🔭 چشم‌انداز فصل: اهداف و جایگاه

تا اینجا برنامه‌های ما همه خط به خط و بدون «فکر کردن» اجرا می‌شدند. یک دستور، بعد دستور بعدی. اما یک برنامه‌ی واقعی باید تصمیم بگیرد: اگر کاربر بزرگسال است این کار را انجام بده، وگرنه آن کار. اگر رمز عبور درست است بگذار وارد شود، وگرنه پیام خطا بده.

این فصل، لحظه‌ای است که برنامه‌های شما «زنده» می‌شوند. ابزار این کار، دستورهای شرطی هستند: if، elif و else. با این‌ها می‌توانید منطق‌های واقعی در برنامه‌تان بسازید — دقیقاً همان کاری که در بازی‌ها، اپلیکیشن‌ها و وب‌سایت‌ها اتفاق می‌افتد.

در پایان این فصل، شما می‌توانید:

  • با if یک شرط ساده را بررسی کنید.
  • با else حالت جایگزین را مشخص کنید.
  • با elif بین چند حالت یکی را انتخاب کنید.
  • شرط‌های تو در تو بسازید (شروطی که داخل شرط دیگرند).
  • با الگوی guard clause از شرط‌های پیچیده جلوگیری کنید.
  • بدانید چه مقدارهایی در پایتون «درست» و چه مقدارهایی «غلط» حساب می‌شوند.
📌 نکته مهم در این فصل، خیلی از مثال‌ها با input() کار می‌کنند. یادتان باشد که input() همیشه متن برمی‌گرداند — برای محاسبه یا مقایسه‌ی عددی، اول با int() یا float() تبدیلش کنید. این نکته از فصل ۳ را در همه‌ی مثال‌ها می‌بینید.

🤔 سوالات محرک ذهنی

قبل از خواندن آموزش، چند لحظه به این سوال‌ها فکر کنید:

🤔 تفاوت elif و یک if جدید چیست؟

خیلی مهم است! وقتی از elif استفاده می‌کنید، یعنی «اگر شرط اول درست نبود، حالا این را امتحان کن». اما اگر یک if جدید بنویسید، پایتون آن را مستقل بررسی می‌کند — حتی اگر شرط اول درست بوده باشد. مثال: اگر if x > 5: ... elif x > 3: ...، وقتی x = 10، فقط شرط اول چک می‌شود و elif نادیده گرفته می‌شود. اما با if x > 5: ... if x > 3: ...، هر دو بررسی می‌شوند.

🤔 چرا تورفتگی در شرط‌ها این‌قدر مهم است؟

چون پایتون با تورفتگی می‌فهمد کدام دستور «داخل شرط» است و کدام نیست. اگر تورفتگی اشتباه باشد، ممکن است دستوری که فکر می‌کنید داخل شرط است، در واقع بیرونش باشد — و همیشه اجرا شود. این دقیقاً همان دلیلی است که در فصل ۲ برایش تورفتگی را یاد گرفتیم.

🤔 آیا می‌توانم چند شرط را با هم بررسی کنم؟

بله! این دقیقاً کاری است که با عملگرهای and و or (که در فصل ۴ یاد گرفتید) انجام می‌شود. مثلاً if age >= 18 and has_license: یعنی «اگر سن بزرگتر یا مساوی ۱۸ بود و گواهینامه هم داشت». ترکیب شرط‌ها به شما قدرت زیادی می‌دهد.

این فصل روی چهار فصل قبل بنا شده. مطمئن شوید این‌ها را انجام داده‌اید:

  • پایتون نصب است و python --version کار می‌کند.
  • پوشه‌ی پروژه را دارید (مثلاً py-learn).

📖 آموزش گام‌به‌گام: شرط و تصمیم‌گیری

۱) اولین شرط — دستور if

کلمه‌ی if در انگلیسی یعنی «اگر». در پایتون هم دقیقاً همین معنی را دارد: اگر شرط برقرار بود، یک کار انجام بده. ساختارش این است:

ساختار کلی ifPython
if شرط:
    # این بلوک اجرا می‌شود اگر شرط True باشد
    دستور1
    دستور2

سه نکته‌ی حیاتی که در ساختار بالا می‌بینید:

  1. بعد از شرط، علامت دو-نقطه : می‌آید.
  2. دستورهایی که داخل شرط هستند، تورفتگی دارند (۴ فاصله).
  3. اگر تورفتگی نباشد، دستور بیرون از شرط حساب می‌شود و همیشه اجرا می‌شود.

بیایید یک مثال ساده ببینیم:

first_if.pyPython
age = 20

if age >= 18:
    print("شما بزرگسال هستید.")

print("پایان برنامه.")

خروجی:

خروجیText
شما بزرگسال هستید.
پایان برنامه.

حالا اگر مقدار age را به ۱۵ تغییر دهید:

خروجی با age = 15Text
پایان برنامه.

دقت کنید: خط «شما بزرگسال هستید» اجرا نشد (چون شرط برقرار نبود)، اما خط «پایان برنامه» همیشه اجرا شد (چون خارج از بلوک if است). این تفاوت، کلید فهمیدن شرط‌هاست.

۲) حالت جایگزین — دستور else

خیلی وقت‌ها فقط یک حالت کافی نیست. می‌خواهید بگویید «اگر شرط درست بود این کار را بکن، وگرنه آن کار». برای این کار از else استفاده می‌کنیم:

if_else.pyPython
age = 15

if age >= 18:
    print("شما بزرگسال هستید.")
else:
    print("شما هنوز کوچک هستید.")

print("پایان برنامه.")

خروجی:

خروجیText
شما هنوز کوچک هستید.
پایان برنامه.

نکته‌های مهم در مورد else:

  • else هیچ شرطی ندارد — چون فقط وقتی اجرا می‌شود که شرط if درست نباشد.
  • در else هم دو-نقطه می‌آید و بدنه‌اش تورفتگی دارد.
  • else همیشه همراه if می‌آید و نمی‌تواند تنها باشد.
  • در هر if/else، فقط یکی از دو بلوک اجرا می‌شود — هرگز هر دو با هم.

۳) چند حالت — دستور elif

حالا فرض کنید بیشتر از دو حالت دارید. مثلاً می‌خواهید نمره‌ی دانشجو را به حروف A، B، C، D، F تبدیل کنید. اینجاست که elif وارد می‌شود (مخفف «else if» یعنی «وگرنه اگر»):

grade.pyPython
score = 85

if score >= 90:
    print("نمره A")
elif score >= 80:
    print("نمره B")
elif score >= 70:
    print("نمره C")
elif score >= 60:
    print("نمره D")
else:
    print("نمره F — نیاز به تلاش بیشتر")

خروجی:

خروجیText
نمره B

چرا؟ چون ۸۵ بزرگ‌تر از ۹۰ نیست (شرط اول رد می‌شود)، اما بزرگ‌تر از ۸۰ است (شرط دوم قبول می‌شود). به‌محض قبول شدن یک شرط، بقیه نادیده گرفته می‌شوند.

⚠️ ترتیب شرط‌ها حیاتی است شرط‌ها را از سخت‌گیرترین به آسان‌ترین بچینید. اگر در مثال بالا اول elif score >= 60 را می‌گذاشتید و بعد elif score >= 90، یک نمره‌ی ۹۵ هم می‌گرفت C — چون شرط اول (>= 60) زودتر قبول می‌شد.

۴) ترکیب شرط‌ها با and و or

گاهی شرط شما بیش از یک چیز را بررسی می‌کند. مثلاً «کاربر بزرگسال است و گواهینامه دارد». اینجا از and استفاده می‌کنیم:

combined_conditions.pyPython
age = 25
has_license = True

if age >= 18 and has_license:
    print("می‌توانید رانندگی کنید.")
else:
    print("اجازه رانندگی ندارید.")

# با or
is_weekend = True
is_holiday = False

if is_weekend or is_holiday:
    print("تعطیل است!")
else:
    print("روز کاری است.")

خروجی:

تعطیل است!

۵) شرط‌های تو در تو (Nested if)

گاهی شرط دوم فقط وقتی معنی دارد که شرط اول درست باشد. مثلاً «اگر کاربر لاگین کرده، بررسی کن که آیا مدیر است یا نه». اینجا می‌توانیم شرط را داخل شرط بگذاریم:

nested_if.pyPython
is_logged_in = True
is_admin = False

if is_logged_in:
    print("خوش آمدید!")
    if is_admin:
        print("شما به پنل مدیریت دسترسی دارید.")
    else:
        print("شما کاربر عادی هستید.")
else:
    print("لطفاً ابتدا وارد شوید.")

خروجی:

خروجیText
خوش آمدید!
شما کاربر عادی هستید.

دقت کنید که if is_admin: یک سطح تورفتگی بیشتر دارد (۸ فاصله)، چون داخل if is_logged_in: قرار گرفته است.

💡 نکته طلایی شرط‌های تو در تو می‌توانند سریع پیچیده شوند. اگر دیدید تورفتگی‌ها ۳ سطح یا بیشتر می‌شوند، بهتر است به فکر ساده‌سازی باشید — با guard clause که در ادامه یاد می‌گیرید.

۶) الگوی Guard Clause — شرط‌های ساده‌تر

فرض کنید می‌خواهید تابعی بنویسید که یک عدد را از ورودی می‌گیرد و جذر آن را حساب کند. باید بررسی کنید که عدد مثبت باشد. یک راه، استفاده از شرط تو در تو:

nested_version.pyPython
number = -4

if number >= 0:
    result = number ** 0.5
    print("جذر:", result)
else:
    print("عدد باید مثبت باشد.")

این کد، برای یک شرط ساده خوب است. اما فرض کنید چند بررسی دارید: عدد باید مثبت باشد، باید عدد باشد، نباید صفر باشد. نوشتن این‌ها داخل همدیگر، کد را پیچیده می‌کند.

راه‌حل: Guard Clause. یعنی «نگهبان» — ابتدا شرط‌های نامطلوب را بررسی می‌کنیم و اگر برقرار بودند، فوراً خارج می‌شویم؛ بعد منطق اصلی را می‌نویسیم:

guard_clause.pyPython
number = -4

# Guard clause — اگر شرط منفی برقرار است، فوراً خارج شو
if number < 0:
    print("عدد باید مثبت باشد.")
else:
    # منطق اصلی، بدون هیچ تورفتگی اضافی
    result = number ** 0.5
    print("جذر:", result)

در این مثال خاص، تفاوت چندانی نمی‌بینید — چون فقط یک شرط داریم. اما در فصل ۸ که توابع را یاد می‌گیرید، خواهید دید که guard clause چطور کدهای پیچیده را ۱۰ خط کوتاه‌تر می‌کند. الان فقط این الگو را به‌خاطر بسپارید: اول شرط‌های منفی، بعد منطق اصلی.

۷) مقدارهای درست و غلط در پایتون (Truthy/Falsy)

در پایتون، شرط‌ها همیشه باید یک مقدار True یا False بدهند. اما یک نکته‌ی زیبا این است که پایتون بعضی مقادیر دیگر را هم «درست» یا «غلط» حساب می‌کند:

truthy_falsy.pyPython
# این مقدارها در پایتون «غلط» حساب می‌شوند:
#   0، 0.0، "" (متن خالی)، None، False

# این مقدارها «درست» حساب می‌شوند:
#   هر عدد غیر صفر، هر متن غیرخالی، True

# مثال واقعی:
name = ""

if name:
    print("سلام", name)
else:
    print("نام شما خالی است!")

خروجی:

خروجیText
نام شما خالی است!

نکته‌ی کلیدی: if name: معادل است با if name != "": یا if len(name) > 0:. یعنی پایتون خودش می‌فهمد که رشته‌ی خالی، «غلط» است. این ویژگی، کد را کوتاه‌تر و خواناتر می‌کند.

💡 نکته طلایی از if name: به‌جای if name != "": استفاده کنید — کوتاه‌تر و پایتونیک‌تر است. همین قاعده برای بررسی لیست خالی یا مقدار None هم صادق است.

۸) یک خطی کردن if — نحو کوتاه

پایتون یک راه بسیار زیبا برای نوشتن شرط‌های کوتاه دارد که در یک خط جا می‌شود:

one_line.pyPython
age = 20

# حالت معمولی
if age >= 18:
    status = "بزرگسال"
else:
    status = "کوچک"

print(status)

# حالت یک‌خطی — دقیقاً همان کار
status = "بزرگسال" if age >= 18 else "کوچک"
print(status)

خروجی هر دو بخش:

خروجیText
بزرگسال
بزرگسال

ساختار این حالت یک‌خطی:

ساختار کلیPython
مقدار_اگر_درست == شرط ? مقدار_درست : مقدار_غلط

# به زبان پایتون:
مقدار_اگر_درست = (result_if_true) if (شرط) else (result_if_false)

یا به شکل ساده:

ساختار واقعیPython
x = "A" if score >= 90 else "B"

یعنی: «x را بگذار A، اگر نمره ۹۰ یا بیشتر بود؛ وگرنه بگذار B». این حالت یک‌خطی را conditional expression یا «عبارت شرطی» می‌گویند.

⚠️ نکته مهم از این حالت فقط برای شرط‌های کوتاه و ساده استفاده کنید. اگر شرط پیچیده است یا باید کارهای زیادی انجام شود، از if/else معمولی استفاده کنید. خوانایی، مهم‌تر از کوتاهی کد است.

۹) کاربرد واقعی: بازی حدس عدد

بیایید همه‌ی آموخته‌ها را در یک برنامه‌ی واقعی به‌کار ببریم. یک بازی ساده که عدد جادویی را در ذهن دارد و از کاربر می‌خواهد حدس بزند:

guess_game.pyPython
# بازی حدس عدد

secret = 7

print("=" * 40)
print("        بازی حدس عدد")
print("=" * 40)
print()

guess_text = input("حدس بزنید (عدد بین 1 تا 10): ")
guess = int(guess_text)

# بررسی حدس کاربر
if guess == secret:
    print("🎉 آفرین! درست حدس زدید.")
elif guess > secret:
    print("❄️ عدد شما بزرگ‌تر از حدس من است.")
elif guess > 10 or guess < 1:
    print("⚠️ عدد باید بین 1 تا 10 باشد.")
else:
    print("🔥 عدد شما کوچک‌تر از حدس من است.")

print()
print("پایان بازی.")

چند نکته:

  • ترتیب شرط‌ها مهم است: ابتدا بررسی می‌کنیم که آیا مساوی است. اگر نبود، بزرگ‌تر بودن. اگر آن هم نبود، کوچک‌تر.
  • شرط guess > 10 or guess < 1 نشان می‌دهد که چطور می‌توانیم شرط‌ها را با or ترکیب کنیم.
  • در مثال واقعی، شما می‌خواهید این بازی را چند بار تکرار کنید — که با حلقه‌ها (فصل ۶) این کار را می‌کنیم. فعلاً یک بار بازی کافی است.

💻 مثال عملی

یک مثال کامل که همه‌ی مفاهیم این فصل را نشان می‌دهد — سیستم ورود ساده:

login_system.pyPython
# سیستم ورود ساده — تمرین شرط‌ها

# اطلاعات ذخیره‌شده (در دنیای واقعی، از دیتابیس می‌آید)
CORRECT_USERNAME = "ali"
CORRECT_PASSWORD = "secret123"
ADMIN_USERNAME = "admin"
ADMIN_PASSWORD = "admin_password"

print("=" * 40)
print("       سیستم ورود")
print("=" * 40)
print()

username = input("نام کاربری: ")
password = input("رمز عبور: ")

print()
print("-" * 40)

# بررسی نام کاربری
if username != CORRECT_USERNAME and username != ADMIN_USERNAME:
    print("❌ نام کاربری اشتباه است.")

# بررسی رمز عبور مدیر

🐞 خطاهای رایج و رفع آن‌ها

این خطاها را در تمرین‌ها زیاد می‌بینید. هر کدام را خوب بشناسید:

❌ SyntaxError: expected ':'

معنی: «بعد از شرط، باید دو-نقطه بیاید».

علت: نوشته‌اید if age >= 18 بدون : در آخر.

راه‌حل: در پایان هر خط if، elif، else باید : باشد: if age >= 18:.

❌ IndentationError: expected an indented block

معنی: «بعد از شرط باید یک بلوک تورفته بیاید».

علت: نوشته‌اید if x > 5: و در خط بعد مستقیماً به دستور بعدی رفته‌اید بدون تورفتگی.

راه‌حل: خط بعد از if باید ۴ فاصله تورفتگی داشته باشد. اگر می‌خواهید شرط هیچ کاری نکند، از pass استفاده کنید.

❌ استفاده از = به‌جای == در شرط

معنی: پایتون فکر می‌کند شما می‌خواهید انتساب انجام دهید، نه مقایسه.

علت: نوشته‌اید if x = 5:.

راه‌حل: برای مقایسه، همیشه از == استفاده کنید: if x == 5:. علامت = فقط برای انتساب است.

❌ ترتیب اشتباه شرط‌ها

معنی: خروجی برنامه درست نیست، ولی خطایی هم نمی‌دهد.

علت: شرط‌های سخت‌گیرانه را بعد از شرط‌های آسان گذاشته‌اید. مثلاً اول if score >= 60: و بعد elif score >= 90:. نمره‌ی ۹۵ می‌شود D، نه A.

راه‌حل: شرط‌ها را از سخت‌گیرترین به آسان‌ترین بچینید. همیشه با >= 90 شروع کنید و به ترتیب پایین بیایید.

❌ پیام نهایی داخل شرط قرار گرفته

معنی: پیامی که باید همیشه چاپ شود، فقط در بعضی موارد چاپ می‌شود.

علت: خط print("پایان") را با تورفتگی نوشته‌اید، پس داخل بلوک آخر است.

راه‌حل: اگر می‌خواهید پیام همیشه چاپ شود، آن را بدون تورفتگی بنویسید — یعنی در سطح اصلی برنامه.

❌ TypeError هنگام مقایسه‌ی int و str

معنی: نمی‌توانید عدد را با متن مقایسه کنید.

علت: از input() بدون تبدیل استفاده کرده‌اید. age = input("سن: ") باعث می‌شود age یک متن باشد؛ بعد if age >= 18: خطا می‌دهد.

راه‌حل: بلافاصله بعد از input()، تبدیل کنید: age = int(input("سن: ")).

❌ فراموشی else در انتهای زنجیره

معنی: اگر هیچ‌کدام از شرط‌ها برقرار نشود، هیچ پیامی چاپ نمی‌شود.

علت: زنجیره‌ی if/elif را بدون else تمام کرده‌اید.

راه‌حل: اگر می‌خواهید حالت «هیچ‌کدام» را هم مدیریت کنید، یک else در انتها اضافه کنید. اما اگر عمداً می‌خواهید در آن حالت هیچ کاری انجام نشود، گذاشتن else اختیاری است.

🏋️ تمرین توسعه — تشخیص زوج و فرد

برنامه‌ای بنویسید که عددی از کاربر بگیرد و مشخص کند زوج است، فرد است، یا صفر است. راه‌حل را با if/elif/else بنویسید:

even_odd_zero.pyPython
number = int(input("یک عدد وارد کنید: "))

if number == 0:
    print("عدد صفر است.")
elif number % 2 == 0:
    print(f"عدد {number} زوج است.")
else:
    print(f"عدد {number} فرد است.")

نکته: ترتیب شرط‌ها مهم است — ابتدا صفر، بعد زوج، بعد فرد. اگر number == 0 را حذف می‌کردیم، صفر به‌عنوان زوج شناخته می‌شد (که از نظر ریاضی درست است، اما اگر بخواهیم صفر پیام جداگانه داشته باشد، باید اول بررسی کنیم).

📝 آزمون تعاملی فصل

پرسش‌های چهارگزینه‌ای زیر را پاسخ دهید؛ بلافاصله بعد از انتخاب، پاسخ درست و توضیحش را می‌بینید. حد نصاب قبولی ۶۰٪ است و بهترین نمره‌تان ذخیره می‌شود.

۱) علامت انتهای شرط if چیست؟

💡 در پایتون، انتهای هر بلوک شرطی باید با دو-نقطه (:) بیاید. بعد از آن، بدنه با تورفتگی شروع می‌شود.

    print("A")

۳) تفاوت elif و if جدید چیست؟

💡 وقتی از elif استفاده می‌کنید، پایتون به‌محض قبول شدن یک شرط، بقیه را نادیده می‌گیرد. اما اگر if جدید بنویسید، همه‌ی شرط‌ها مستقل بررسی می‌شوند.

۴) خروجی این کد چیست؟

    print("سلام")

💡 در پایتون، رشته‌ی خالی ("") یک مقدار «غلط» (falsy) است. پس شرط if name: رد می‌شود و else اجرا می‌شود.

۵) چرا input() قبل از مقایسه با عدد، نیاز به int() دارد؟

💡 input() همیشه رشته (str) برمی‌گرداند. اگر بخواهید با عدد مقایسه کنید (مثل if age >= 18)، اول باید با int() یا float() تبدیلش کنید.

۶) در یک زنجیره‌ی if/elif/else، حداکثر چند بلوک اجرا می‌شود؟

💡 در یک زنجیره‌ی if/elif/else، به‌محض اینکه یک شرط قبول شود، بقیه نادیده گرفته می‌شوند. پس فقط یکی از بلوک‌ها (یا if، یا یکی از elifها، یا else) اجرا می‌شود.

  • با if یک شرط ساده را بررسی کنید.
  • با else حالت جایگزین را برای شرطی که رد شده، تعریف کنید.
  • با elif چند حالت را به‌ترتیب بررسی کنید.
  • تفاوت elif با if جدید: در اولی، بقیه نادیده گرفته می‌شوند؛ در دومی، همه مستقل بررسی می‌شوند.
  • شرط‌های تو در تو بسازید و بدانید چرا معمولاً از guard clause بهتر است.
  • با and و or شرط‌ها را ترکیب کنید.
  • بدانید پایتون چه مقدارهایی را «درست» و چه مقدارهایی را «غلط» حساب می‌کند (truthy/falsy).
  • از حالت یک‌خطی A if شرط else B برای شرط‌های کوتاه استفاده کنید.
💡 ✨ یک‌جمله‌ای که باید یادتان بماند «شرط‌ها به برنامه‌تان شخصیت می‌دهند — بدون آن‌ها، برنامه فقط یک سری دستور پشت سر هم است.»
بخش ۱۴

❓ سوالات متداول و گام بعدی

چرا بعد از if باید حتماً دو-نقطه بگذاریم؟

چون پایتون اینطور طراحی شده. دو-نقطه به پایتون می‌گوید «از خط بعدی، یک بلوک تورفته شروع می‌شود». بدون آن، پایتون نمی‌فهمد که کد بعدی داخل شرط است یا نه.

آیا می‌شود if را در یک خط نوشت؟

بله! پایتون اجازه می‌دهد: if x > 5: print("بزرگ"). اما برای شرط‌های پیچیده یا کارهای بیشتر، خوانایی کم می‌شود. برای شرط‌های ساده و بدنه‌ی یک‌خطی، مشکلی ندارد.

چند تا elif می‌توانم داشته باشم؟

تا هر تعداد که بخواهید. اما اگر بیشتر از ۴-۵ تا شد، بهتر است ساختار کد را بازبینی کنید. در فصل‌های بعدی یاد می‌گیرید که گاهی دیکشنری یا تابع، راه‌حل بهتری است.

آیا else اجباری است؟

خیر، اجباری نیست. اگر بخواهید در حالت «هیچ‌کدام» هیچ کاری انجام نشود، می‌توانید else را حذف کنید. اما در بیشتر اوقات، مدیریت همه‌ی حالت‌ها (شامل حالت هیچ‌کدام) نشانه‌ی کد خوب است.

تفاوت elif x == 5 و elif 5 == x چیست؟

در نتیجه، هیچ تفاوتی. اما بعضی برنامه‌نویس‌ها ترجیح می‌دهند مقدار ثابت را اول بنویسند (5 == x) چون اگر اشتباهاً یکی از مساوی‌ها را فراموش کنند، 5 = x خطای فوری می‌دهد (چون نمی‌شود عدد را مقداردهی کرد)، در حالی که x = 5 بدون خطا اجرا می‌شود ولی کار اشتباهی می‌کند.

📌 🧭 گام بعدی در فصل ۶ با حلقه‌ها آشنا می‌شوید: for و while. این‌ها به شما اجازه می‌دهند یک قطعه کد را چند بار تکرار کنید — بدون نیاز به کپی-پیست. ترکیب شرط‌ها با حلقه‌ها، قدرتمندترین ابزار برنامه‌نویسی است که در فصل‌های بعدی بارها به‌کار می‌برید.
