🔭 چشم‌انداز فصل: اهداف و جایگاه

تا اینجا برنامه‌هایمان یک سری دستور پشت سر هم بودند که از بالا به پایین اجرا می‌شدند. اما وقتی برنامه‌ها بزرگ‌تر می‌شوند، این روش جواب نمی‌دهد. کد طولانی می‌شود، تکرار زیاد می‌شود، و پیدا کردن اشتباهات سخت می‌شود.

راه‌حل حرفه‌ای‌ها، توابع است. تابع یعنی یک قطعه‌ی کوچک از کد که یک کار مشخص انجام می‌دهد و می‌توانید هر وقت لازم شد صدایش بزنید — بدون کپی-پیست کردن. این فصل، شما را از سطح «نوشتن اسکریپت» به سطح «طراحی برنامه» می‌برد.

در پایان این فصل، شما می‌توانید:

  • با def یک تابع جدید بسازید.
  • با پارامتر اطلاعاتی به تابع بفرستید.
  • با return نتیجه‌ای از تابع بگیرید.
  • با پارامتر پیش‌فرض تابع‌های انعطاف‌پذیر بسازید.
  • با scope (دامنه) متغیرها آشنا شوید و تفاوت local و global را بفهمید.
  • برای تابع‌هایتان مستند (docstring) بنویسید.
  • از الگوی if __name__ == "__main__": استفاده کنید.
📌 نکته مهم توابع، پایه‌ی همه چیز در برنامه‌نویسی است. از این فصل به بعد، تقریباً هر کد جدی که می‌نویسید، حداقل یک تابع خواهد داشت. پس این فصل را با دقت بخوانید و هر مثال را خودتان تایپ و اجرا کنید.

🤔 سوالات محرک ذهنی

قبل از خواندن آموزش، چند لحظه به این سوال‌ها فکر کنید:

🤔 چرا از تابع استفاده کنیم؟ مگر نمی‌شود همه‌چیز را یکجا نوشت؟

تصور کنید یک برنامه‌ی ۱۰۰۰ خطی دارید که در ۲۰ جای مختلف، یک محاسبه‌ی تکراری انجام می‌دهد. اگر بخواهید آن محاسبه را تغییر دهید، باید ۲۰ جا را اصلاح کنید. اما اگر آن محاسبه در یک تابع باشد، فقط یک جا عوض می‌کنید و همه‌جا اعمال می‌شود. تابع‌ها به شما کمک می‌کنند: (۱) کد را یک‌بار بنویسید و بارها استفاده کنید، (۲) برنامه را به قطعه‌های منطقی تقسیم کنید، (۳) پیدا کردن اشتباهات را آسان‌تر کنید.

🤔 تفاوت پارامتر و آرگومان چیست؟

این یک سوال کلاسیک است. پارامتر متغیری است که در تعریف تابع می‌نویسید: def greet(name): — اینجا name پارامتر است. آرگومان مقداری است که در زمان صدا زدن تابع می‌فرستید: greet("علی") — اینجا «علی» آرگومان است. در فارسی روزمره، بیشتر اوقات هر دو را «پارامتر» می‌گویند و مشکلی هم پیش نمی‌آید. اما دانستن این تفاوت، در مصاحبه‌های فنی به‌کار می‌آید.

🤔 تفاوت return و print چیست؟ هر دو که یک چیز چاپ می‌کنند!

سوال بسیار مهمی است. print فقط چیزی نشان می‌دهد — بعد از چاپ، آن مقدار از بین می‌رود و نمی‌توانید از آن استفاده کنید. اما return مقدار را برمی‌گرداند به کدی که تابع را صدا زده — می‌توانید آن را در متغیری ذخیره کنید، به تابع دیگری بفرستید یا داخل محاسبه‌ی دیگر به‌کار ببرید. به‌عبارتی: print برای کاربر است، return برای برنامه.

اگر این پیش‌نیازها را ندارید، لطفاً ابتدا فصل‌های قبلی را مرور کنید. توابع، از این پایه‌ها استفاده می‌کنند.

📖 آموزش گام‌به‌گام: توابع

۱) تابع چیست؟ — یک قطعه‌ی کد با اسم

تابع (function) قطعه‌ای از کد است که یک کار مشخص انجام می‌دهد و اسمی دارد. وقتی این اسم را صدا می‌زنید، کدی که داخلش نوشته‌اید، اجرا می‌شود. تابع مثل یک دکمه است: شما می‌دانید وقتی این دکمه را بزنید چه اتفاقی می‌افتد، ولی نیازی نیست از درونش خبر داشته باشید.

فرض کنید می‌خواهید در چند جای مختلف برنامه، یک پیام خوش‌آمد چاپ کنید. بدون تابع، این می‌شود:

بدون تابع — تکراریPython
print("=" * 30)
print("خوش آمدید!")
print("=" * 30)

name = "علی"
print(f"سلام {name}!")
print("=" * 30)

# این الگو را دوباره و دوباره می‌نویسیم...

با تابع، یک‌بار می‌نویسیم، چند بار استفاده می‌کنیم:

با تابع — یک‌بار بنویس، چند بار استفاده کنPython
def show_welcome():
    print("=" * 30)
    print("خوش آمدید!")
    print("=" * 30)

# حالا هر وقت خواستیم، صدا می‌زنیم
show_welcome()
show_welcome()
show_welcome()

خروجی:

۲) def — ساخت اولین تابع

برای ساختن تابع از کلمه‌ی def (مخفف define یعنی «تعریف کن») استفاده می‌کنیم. ساختار:

ساختار defPython
def نام_تابع():
    # بدنه‌ی تابع (با تورفتگی 4 فاصله)
    دستور1
    دستور2

چهار نکته‌ی مهم در ساختار بالا:

  1. بعد از اسم تابع، پرانتز می‌آید.
  2. بعد از پرانتز، علامت دو-نقطه :.
  3. بدنه‌ی تابع با تورفتگی (۴ فاصله) نوشته می‌شود.
  4. اگر تابع را صدا نزنید، هیچ اتفاقی نمی‌افتد. تعریف تابع به‌تنهایی کاری انجام نمی‌دهد.

مهم‌ترین نکته‌ی عملی: یک تابع، فقط یک کار انجام دهد. اگر اسم تابع شما شامل «و» است (مثلاً «محاسبه و چاپ کن»)، بهتر است به دو تابع جدا تقسیم شود.

۳) پارامتر — فرستادن اطلاعات به تابع

تابع show_welcome() همیشه یک چیز می‌گفت. اما بیشتر اوقات می‌خواهیم تابع با اطلاعات مختلف کار کند. مثلاً بخواهیم به هر کس با اسم خودش سلام کند. برای این کار از پارامتر استفاده می‌کنیم:

تابع با پارامترPython
def greet(name):
    print(f"سلام {name}!")

greet("علی")
greet("رضا")
greet("سارا")

خروجی:

خروجیText
سلام علی!
سلام رضا!
سلام سارا!

بخوانیدش: «یک تابع به نام greet بساز که یک پارامتر به نام name می‌گیرد. هر وقت این تابع را با یک متن صدا زدی، همان متن جای name می‌نشیند و پیام چاپ می‌شود.»

تابع با چند پارامتر

تابع می‌تواند چند پارامتر بگیرد:

multiple_params.pyPython
def introduce(name, age, city):
    print(f"من {name} هستم، {age} ساله و ساکن {city}.")

introduce("علی", 25, "تهران")
introduce("رضا", 30, "شیراز")

خروجی:

خروجیText
من علی هستم، 25 ساله و ساکن تهران.
من رضا هستم، 30 ساله و ساکن شیراز.
⚠️ دقت کنید ترتیب پارامترها مهم است. وقتی تابع را صدا می‌زنید، پایتون مقادیر را به ترتیب جای پارامترها می‌گذارد. یعنی introduce("علی", 25, "تهران") یعنی name = "علی"، age = 25، city = "تهران". اگر ترتیب را عوض کنید، خروجی عجیب می‌شود.

۴) return — گرفتن نتیجه از تابع

تا اینجا تابع‌هایمان فقط چیزی چاپ می‌کردند. اما بیشتر اوقات می‌خواهیم تابع یک نتیجه بدهد تا در جای دیگر استفاده کنیم. برای این کار از return استفاده می‌کنیم:

with_return.pyPython
def add(a, b):
    return a + b

# نتیجه تابع را در متغیر ذخیره می‌کنیم
result = add(5, 3)
print(result)             # 8

# یا داخل محاسبه‌ی دیگر
total = add(10, 20) + add(1, 2)
print(total)              # 33

# یا داخل f-string
print(f"جمع: {add(7, 8)}")  # جمع: 15

تفاوت print و return

این یکی از مهم‌ترین تفاوت‌هاست و خیلی از تازه‌کارها با آن اشتباه می‌کنند:

print_vs_return.pyPython
def add_with_print(a, b):
    print(a + b)

def add_with_return(a, b):
    return a + b

# با print
x = add_with_print(5, 3)
# چاپ می‌شود 8، اما x مقدار None دارد!
print("مقدار x:", x)      # مقدار x: None

# با return
y = add_with_return(5, 3)
# چیزی چاپ نمی‌شود، اما y مقدار دارد
print("مقدار y:", y)      # مقدار y: 8

پس وقتی می‌خواهید فقط چیزی نشان دهید، از print استفاده کنید. وقتی می‌خواهید نتیجه را برای استفاده‌ی بعدی برگردانید، از return. و اغلب، بهترین کار این است که تابع شما return کند و چاپ کردن را به عهده‌ی کدی بگذارید که تابع را صدا زده.

return تابع را تمام می‌کند

وقتی به return می‌رسید، تابع فوراً تمام می‌شود. کد بعد از return اجرا نمی‌شود:

return_ends.pyPython
def check_number(x):
    if x > 0:
        return "مثبت"
    if x < 0:
        return "منفی"
    return "صفر"

print(check_number(5))     # مثبت
print(check_number(-3))    # منفی
print(check_number(0))     # صفر

در این تابع، اگر x بزرگ‌تر از صفر باشد، همان‌جا return «مثبت» اجرا می‌شود و تابع تمام می‌شود. کدهای بعدی نادیده گرفته می‌شوند.

۵) پارامتر پیش‌فرض — تابع‌های انعطاف‌پذیر

گاهی می‌خواهید یک پارامتر اختیاری باشد و اگر کاربر آن را نداد، یک مقدار پیش‌فرض استفاده شود:

default_params.pyPython
def greet(name, greeting="سلام"):
    print(f"{greeting} {name}!")

# بدون greeting — از پیش‌فرض استفاده می‌شود
greet("علی")                     # سلام علی!

# با greeting — جای پیش‌فرض را می‌گیرد
greet("رضا", "درود")             # درود رضا!
greet("سارا", "خوش آمدی")         # خوش آمدی سارا!
💡 قاعده مهم پارامترهای پیش‌فرض، باید بعد از پارامترهای اجباری بیایند. یعنی این خطا است: def f(a=1, b):. اما این درست است: def f(a, b=1):. دلیلش این است که پایتون نمی‌تواند تشخیص دهد کدام مقدار برای کدام پارامتر است.

۶) Scope — دامنه‌ی متغیرها

یک نکته‌ی مهم درباره‌ی متغیرها: متغیری که داخل تابع تعریف می‌کنید، خارج از تابع وجود ندارد. به این «دامنه» یا scope می‌گویند:

scope_demo.pyPython
def my_function():
    local_var = "من داخل تابع هستم"
    print(local_var)

my_function()
# print(local_var)   ← خطا می‌دهد: NameError

# اما متغیرهای سراسری (بیرون) در تابع دیده می‌شوند
global_var = "من بیرون هستم"

def show_global():
    print(global_var)     # این کار می‌کند

show_global()             # من بیرون هستم

سه نکته‌ی مهم:

  • متغیر محلی (local): داخل تابع تعریف می‌شود، فقط داخل تابع دیده می‌شود.
  • متغیر سراسری (global): بیرون تابع تعریف می‌شود، داخل تابع خوانده می‌شود ولی نباید تغییرش داد.
  • قاعده‌ی طلایی: تا می‌توانید، از متغیرهای سراسری استفاده نکنید. تابع باید خودکفا باشد. این باعث می‌شود باگ‌های پنهان کمتر پیش بیایند.
⚠️ هشدار اگر داخل تابع بنویسید global x و بعد x = 5، می‌توانید متغیر سراسری را تغییر دهید. اما این کار تقریباً همیشه نشانه‌ی طراحی ضعیف است. به‌جای این کار، از پارامتر و return استفاده کنید.

مثال عملی scope — چرا مهم است؟

scope_why.pyPython
counter = 0

def increment():
    counter = counter + 1     # ← خطا!
    return counter

# UnboundLocalError: local variable 'counter'
# referenced before assignment

این کد خطا می‌دهد چون پایتون فکر می‌کند counter یک متغیر محلی است (چون داخل تابع به آن مقدار می‌دهید)، اما قبل از اینکه تعریفش کنید، می‌خواهید از آن استفاده کنید. راه‌حل درست:

scope_fixed.pyPython
def increment(counter):
    counter = counter + 1
    return counter

count = 0
count = increment(count)
count = increment(count)
print(count)     # 2

به‌جای اینکه تابع بخواهد متغیر بیرونی را تغییر دهد، مقدار را به‌عنوان پارامتر می‌گیرد و نتیجه را برمی‌گرداند. این الگو، استاندارد طلایی توابع خوب است.

۷) Docstring — مستندسازی تابع

حتماً شنیده‌اید که کد خوب باید مستند باشد. برای تابع‌ها، بهترین روش مستندسازی docstring است — یک متن چندخطی که بعد از خط def نوشته می‌شود و با سه گیومه """ مشخص می‌شود:

with_docstring.pyPython
def calculate_average(numbers):
    """میانگین یک لیست از اعداد را حساب می‌کند.

    ورودی:
        numbers: یک لیست از اعداد

    خروجی:
        میانگین به‌صورت یک عدد اعشاری
    """
    return sum(numbers) / len(numbers)

# استفاده
scores = [18, 15, 20, 17]
print(calculate_average(scores))   # 17.5

# دیدن مستندات تابع
help(calculate_average)

وقتی help(calculate_average) را اجرا کنید، متن داخل docstring نمایش داده می‌شود. همچنین در VS Code وقتی موس را روی اسم تابع نگه دارید، همان متن به‌عنوان راهنما نشان داده می‌شود.

یک docstring خوب، سه چیز را توضیح می‌دهد:

  • تابع چه کاری انجام می‌دهد (یک خط خلاصه)
  • چه پارامترهایی می‌گیرد
  • چه چیزی برمی‌گرداند

۸) ساختار حرفه‌ای — main , if __name__

یک الگوی حرفه‌ای که در همه‌ی برنامه‌های جدی پایتون می‌بینید:

professional_structure.pyPython
"""برنامه نمونه با ساختار حرفه‌ای."""


def greet(name):
    """به کاربر سلام می‌کند."""
    return f"سلام {name}!"


def farewell(name):
    """به کاربر خداحافظی می‌کند."""
    return f"خداحافظ {name}!"


def main():
    """نقطه‌ی ورود برنامه."""
    print(greet("علی"))
    print("در حال انجام کارها...")
    print(farewell("علی"))


if __name__ == "__main__":
    main()

این ساختار چه فایده‌ای دارد؟

  • همه‌ی منطق برنامه داخل main() قرار دارد — نقطه‌ی ورود مشخص.
  • توابع کوچک، هر کدام یک کار مشخص انجام می‌دهند.
  • if __name__ == "__main__": یعنی «اگر این فایل مستقیماً اجرا شد، main را صدا بزن». اگر این فایل در فایل دیگری import شود، main اجرا نمی‌شود — فقط توابع در دسترس قرار می‌گیرند.
💡 این چرا مهم است؟ وقتی برنامه‌تان بزرگ‌تر می‌شود و به چند فایل تقسیم می‌شود، این الگو حیاتی می‌شود. اگر نداشته باشید، import کردن یک فایل، کل کد آن را اجرا می‌کند — که معمولاً چیزی نیست که می‌خواهید.

۹) کاربرد واقعی — همه‌چیز در کنار هم

بیایید یک برنامه‌ی کامل با توابع بنویسیم — یک ماشین‌حساب BMI که با توابع سازماندهی شده:

bmi_calculator.pyPython
"""محاسبه‌گر BMI — با ساختار حرفه‌ای."""


def get_positive_float(prompt):
    """یک عدد اعشاری مثبت از کاربر می‌گیرد.

    تا زمانی که کاربر عدد معتبر وارد نکند، ادامه می‌دهد.
    """
    while True:
        try:
            value = float(input(prompt))
            if value > 0:
                return value
            print("⚠️ لطفاً یک عدد مثبت وارد کنید.")
        except ValueError:
            print("⚠️ لطفاً یک عدد معتبر وارد کنید.")


def calculate_bmi(weight, height):
    """شاخص توده‌ی بدنی را حساب می‌کند.

    پارامترها:
        weight: وزن به کیلوگرم
        height: قد به متر

    خروجی:
        مقدار BMI به‌صورت یک عدد اعشاری
    """
    return weight / (height ** 2)


def classify_bmi(bmi):
    """دسته‌بندی BMI را برمی‌گرداند."""
    if bmi < 18.5:
        return "کمبود وزن"
    if bmi < 25:
        return "وزن نرمال"
    if bmi < 30:
        return "اضافه وزن"
    return "چاقی"


def main():
    """نقطه‌ی ورود برنامه."""
    print("=" * 40)
    print("        محاسبه‌گر BMI")
    print("=" * 40)
    print()

    weight = get_positive_float("وزن شما (کیلوگرم): ")
    height = get_positive_float("قد شما (متر): ")

    bmi = calculate_bmi(weight, height)
    category = classify_bmi(bmi)

    print()
    print("-" * 40)
    print(f"  BMI شما: {bmi:.2f}")
    print(f"  دسته‌بندی: {category}")
    print("-" * 40)


if __name__ == "__main__":
    main()

در این برنامه، هر تابع یک مسئولیت مشخص دارد:

  • get_positive_float: گرفتن ورودی معتبر از کاربر.
  • calculate_bmi: محاسبه‌ی BMI — بدون هیچ چاپ یا ورودی.
  • classify_bmi: تشخیص دسته‌بندی — فقط یک مقدار را به یک متن تبدیل می‌کند.
  • main: هماهنگ‌کننده — توابع را به ترتیب صدا می‌زند.

هر تابع را می‌توانید مستقل تست کنید. این، قدرت واقعی توابع است.

"""دستیار متن — چند تابع کاربردی برای متن."""


def count_words(text):
    """تعداد کلمات یک متن را برمی‌گرداند."""
    return len(text.split())


def count_chars(text, ignore_spaces=True):
    """تعداد کاراکترهای متن را می‌شمارد.

    پارامتر اختیاری ignore_spaces: اگر True باشد، فاصله‌ها شمرده نمی‌شوند.
    """
    if ignore_spaces:
        text = text.replace(" ", "")
    return len(text)


def reverse_text(text):
    """متن را برعکس می‌کند."""
    return text[::-1]


def title_case(text):
    """اولین حرف هر کلمه را بزرگ می‌کند (در انگلیسی)."""
    return text.title()


def show_report(text):
    """گزارش کاملی از یک متن نمایش می‌دهد."""
    print("=" * 45)
    print("       تحلیل متن")
    print("=" * 45)
    print(f"  متن اصلی      : {text}")
    print(f"  تعداد کلمات   : {count_words(text)}")
    print(f"  تعداد کاراکتر : {count_chars(text)}")
    print(f"  با فاصله      : {count_chars(text, ignore_spaces=False)}")
    print(f"  معکوس         : {reverse_text(text)}")
    print("=" * 45)


def main():
    """نقطه‌ی ورود برنامه."""
    text = input("یک متن بنویسید: ").strip()

    if not text:
        print("⚠️ متن خالی است.")
        return

    show_report(text)


if __name__ == "__main__":
    main()

"""مدیر حقوق — محاسبه‌ی مالیات و حقوق خالص."""


def get_number(prompt):
    """یک عدد معتبر از کاربر می‌گیرد."""
    while True:
        try:
            value = float(input(prompt))
            return value
        except ValueError:
            print("⚠️ لطفاً یک عدد معتبر وارد کنید.")


def calculate_tax(salary):
    """مالیات را بر اساس حقوق محاسبه می‌کند."""
    if salary < 10_000_000:
        return 0
    if salary < 30_000_000:
        return salary * 0.10
    return salary * 0.20


def calculate_net(salary, tax):
    """حقوق خالص را برمی‌گرداند."""
    return salary - tax


def show_payslip(name, salary, tax, net):
    """فیش حقوقی را چاپ می‌کند."""
    print()
    print("=" * 45)
    print("           فیش حقوقی ماهانه")
    print("=" * 45)
    print(f"  نام کارمند    : {name}")
    print(f"  حقوق پایه     : {salary:,.0f} تومان")
    print(f"  مالیات        : {tax:,.0f} تومان")
    print(f"  حقوق خالص     : {net:,.0f} تومان")
    print("=" * 45)


def main():
    """نقطه‌ی ورود برنامه."""
    name = input("نام کارمند: ").strip() or "ناشناس"
    salary = get_number("حقوق ماهانه (تومان): ")

    tax = calculate_tax(salary)
    net = calculate_net(salary, tax)

    show_payslip(name, salary, tax, net)


if __name__ == "__main__":
    main()

🐞 خطاهای رایج و رفع آن‌ها

این خطاها را در تمرین‌ها زیاد می‌بینید:

❌ فراموش کردن فراخوانی تابع

معنی: تابع را تعریف کرده‌اید، اما صدا نزده‌اید، پس هیچ اتفاقی نمی‌افتد.

علت: نوشته‌اید def my_function(): اما هرگز my_function() را صدا نزده‌اید.

راه‌حل: تعریف تابع، کاری انجام نمی‌دهد — فقط به پایتون می‌گوید «این تابع وجود دارد». برای اجرا، باید صدا بزنید: my_function().

❌ NameError: name 'x' is not defined (در scope)

معنی: متغیری که در تابع تعریف شده، بیرون از آن قابل دسترسی نیست.

علت: متغیر محلی است و در دامنه‌ی بیرونی وجود ندارد.

راه‌حل: اگر می‌خواهید مقدار را بیرون داشته باشید، با return برگردانید: result = my_function().

❌ TypeError: my_function() missing 1 required positional argument

معنی: تابع انتظار پارامتر دارد، اما شما هیچ‌کدام را نفرستادید.

علت: تابعی که def greet(name) است را به‌صورت greet() صدا زده‌اید.

راه‌حل: همه‌ی پارامترهای اجباری را بفرستید: greet("علی").

❌ SyntaxError: non-default argument follows default argument

معنی: پارامتر پیش‌فرض قبل از پارامتر اجباری آمده.

علت: def f(a=1, b): — این خطا است.

راه‌حل: اول پارامترهای اجباری، بعد پیش‌فرض: def f(a, b=1):.

❌ UnboundLocalError

معنی: می‌خواهید از یک متغیر سراسری داخل تابع استفاده کنید، اما پایتون فکر می‌کند محلی است.

علت: مثلاً نوشته‌اید counter = counter + 1 بدون اینکه counter پارامتر باشد.

راه‌حل: counter را به‌عنوان پارامتر بگیرید و با return برگردانید. هرگز از global استفاده نکنید.

❌ فراموش کردن return

معنی: تابع مقداری برمی‌گرداند، اما مقدار None است.

علت: تابعی که باید return بدهد، فقط print دارد.

راه‌حل: اگر تابع باید نتیجه بدهد، حتماً از return استفاده کنید. اگر می‌خواهید چیزی چاپ کنید، از print استفاده کنید. بهترین کار: تابع return کند، و کد بیرونی چاپ کند.

❌ کد بعد از return اجرا نمی‌شود

معنی: دستورهای بعد از return، هیچ‌وقت اجرا نمی‌شوند.

علت: return تابع را کاملاً تمام می‌کند.

راه‌حل: کدهایی که بعد از return نوشته‌اید را حذف کنید یا به قبل از return منتقل کنید. VS Code این کدها را خاکستری نشان می‌دهد.

۵) اگر یک تابع داخلش return نداشته باشد، چه چیزی برمی‌گرداند؟

💡 در پایتون، هر تابعی که به‌طور صریح return نکند، به‌طور پیش‌فرض مقدار None برمی‌گرداند.

۶) متغیری که داخل تابع تعریف می‌شود، از بیرون قابل دسترسی است؟

💡 متغیرهای محلی (local) فقط داخل تابع دیده می‌شوند. برای دسترسی از بیرون، باید مقدار را با return برگردانید.
بخش ۱۲

🏗️ پروژه عملی فصل

پروژه: «دستیار دانشجو» — یک برنامه‌ی منویی که با توابع ساخته شده و چند ابزار مفید برای دانشجو دارد.

نیازمندی‌ها:

  • فایل در پوشه‌ی پروژه به نام student_helper.py ذخیره شود.
  • برنامه شامل این توابع باشد:
    • show_menu() — منوی گزینه‌ها را چاپ کند.
    • calculate_average(grades) — میانگین یک لیست نمره را برگرداند.
    • find_max(grades) — بالاترین نمره را برگرداند.
    • find_min(grades) — پایین‌ترین نمره را برگرداند.
    • get_grades() — از کاربر بخواهد چند نمره وارد کند و یک لیست برگرداند.
    • show_report(grades) — با استفاده از توابع قبلی، یک گزارش کامل نمایش دهد.
  • تابع main() یک حلقه‌ی منو داشته باشد که تا کاربر «خروج» را انتخاب نکند ادامه یابد.
  • هر تابع یک docstring داشته باشد.
  • اگر لیست نمرات خالی بود، تابع‌ها پیام مناسب بدهند (یا مقدار None برگردانند).
  • از f-string و قالب‌بندی اعداد استفاده شود.
  • در پایان، الگوی if __name__ == "__main__": اضافه شود.

🎯 جمع‌بندی و دستاوردها

در این فصل یاد گرفتید:

  • تابع چیست و چرا برای برنامه‌نویسی ضروری است.
  • با def تابع تعریف کنید.
  • پارامتر برای فرستادن اطلاعات به تابع.
  • return برای برگرداندن نتیجه — و تفاوتش با print.
  • پارامترهای پیش‌فرض و قاعده‌ی ترتیبشان.
  • Scope یا دامنه‌ی متغیرها (local و global).
  • چرا از متغیرهای سراسری باید پرهیز کرد و راه‌حل جایگزین.
  • Docstring برای مستندسازی تابع.
  • الگوی main() و if __name__ == "__main__":.
  • هر تابع باید یک کار مشخص انجام دهد (اصل Single Responsibility).
💡 ✨ یک‌جمله‌ای که باید یادتان بماند «توابع، ستون فقرات برنامه‌نویسی حرفه‌ای هستند. کد خوب، مجموعه‌ای از توابع کوچک است که هر کدام یک کار را خوب انجام می‌دهند — نه یک بلوک بزرگ و درهم.»

❓ سوالات متداول و گام بعدی

آیا حتماً باید تابع تعریف کنم یا می‌توانم همه‌چیز را یکجا بنویسم؟

برای برنامه‌های کوچک (زیر ۳۰ خط)، می‌توانید یکجا بنویسید. اما از همان ابتدا به توابع عادت کنید. برنامه‌های واقعی معمولاً صدها یا هزاران خط هستند و بدون توابع غیرقابل مدیریت می‌شوند.

چه زمانی از return استفاده کنم و چه زمانی از print؟

قاعده‌ی ساده: تابعی که محاسبه انجام می‌دهد، return کند. تابعی که نمایش می‌دهد، print کند. این تفکیک باعث می‌شود تابع‌هایتان قابل تست باشند و در جای مختلف به‌کار بروند.

آیا می‌توانم تابعی بنویسم که تابع دیگری را صدا بزند؟

بله، این کار کاملاً رایج است. در همین فصل دیدید که show_report از count_words و count_chars استفاده می‌کرد. این کار باعث می‌شود کد شما به قطعه‌های کوچک و قابل تست تقسیم شود.

تفاوت پارامتر و آرگومان چیست؟

پارامتر در تعریف تابع می‌آید: def greet(name) — name پارامتر است. آرگومان در زمان فراخوانی می‌آید: greet("علی") — «علی» آرگومان است. در گفتگوی روزمره، معمولاً هر دو را پارامتر می‌گویند.

آیا برای هر تابع کوچک باید docstring بنویسم؟

برای تابع‌های خیلی ساده مثل def add(a, b): return a+b، docstring اضافی است — اسم تابع خودش همه‌چیز را می‌گوید. اما برای تابع‌های پیچیده‌تر یا هر تابعی که ممکن است در آینده فراموشش کنید، docstring یک خطی کافی است.

📌 🧭 گام بعدی در فصل ۹ با لیست‌ها و تاپل‌ها آشنا می‌شوید: چطور چند مقدار را در یک متغیر نگه دارید، چطور در آن‌ها جست‌وجو کنید، اضافه و حذف کنید. تا اینجا فقط با یک مقدار در هر متغیر کار می‌کردیم. از فصل بعد، با مجموعه‌ها کار می‌کنیم — و اینجاست که قدرت واقعی پایتون را می‌بینید.
