Bridge در RouterOS نقش سوئیچ نرم‌افزاری را بازی می‌کند. با Bridge می‌توانی چند Interface فیزیکی را در لایه ۲ به هم وصل کنی، Wireless را به Ethernet پل کنی، و شبکه‌ی داخلی یکپارچه بسازی.

📘 بدنه‌ی آموزشی

۳.۱ مفهوم Bridge و تفاوت با Switch

در RouterOS، Bridge یک سوئیچ نرم‌افزاری است که Interfaceهای مختلف را در لایه ۲ به هم وصل می‌کند.

Bridge چه چیزی را در بر می‌گیرد:

  • Interfaceهای Ethernet
  • Interfaceهای Wireless
  • Interfaceهای مجازی (VLAN، EoIP، VPLS)
  • Interfaceهای Tunnel

تفاوت Bridge و Switch:

ویژگی Bridge Switch (Hardware Chip)
نوعنرم‌افزاری (CPU)سخت‌افزاری (ASIC)
Performanceمتوسطبالا (Wire-speed)
انعطاف✅ بالا — VLAN، Filter، NAT❌ محدود
پشتیبانی VLAN✅ (با Filtering)✅
کاربردانعطاف، سناریوهای پیچیدهSwitching ساده و پرسرعت
💡 نکته
در RouterBOARDهای جدید، Bridge می‌تواند از Hardware Offload استفاده کند — یعنی همان Bridge نرم‌افزاری، روی Chip سخت‌افزاری اجرا می‌شود و Performance را بالا می‌برد.

۳.۲ سناریوهای کاربرد Bridge

کاربردهای اصلی Bridge:

  • Router + Switch در یک دستگاه: چهار پورت Ethernet را به یک Bridge اضافه کن → سوئیچ ۴ پورت بساز
  • Wireless Access Point: Wireless را با Ethernet پل کن → کاربران WiFi در همان Subnet سیمی قرار می‌گیرند
  • CPE (Customer Premises Equipment): Wireless Client را با Ethernet LAN پل کن
  • VLAN Switching: با Bridge VLAN Filtering، سوئیچ با VLAN بساز
  • EoIP / VPLS: Bridge چند Interface در دو نقطه‌ی جغرافیایی را
  • Bonding: چند لینک فیزیکی را در یک Bond و سپس Bridge کن
# ===== سناریو: سوئیچ ۴ پورت با Bridge =====
/interface bridge add name=bridge-lan

/interface bridge port
add bridge=bridge-lan interface=ether2
add bridge=bridge-lan interface=ether3
add bridge=bridge-lan interface=ether4
add bridge=bridge-lan interface=ether5

/ip address add address=192.168.88.1/24 interface=bridge-lan
# حالا IP روتر روی bridge است، نه روی یک Interface خاص

# نتیجه: ether2 تا ether5 یک شبکه‌ی داخلی واحد با Gateway 192.168.88.1

۳.۳ ایجاد Bridge در RouterOS

# ===== ایجاد Bridge پایه =====
[admin@MikroTik] > /interface bridge add name=bridge1

# ===== با تنظیمات بیشتر =====
[admin@MikroTik] > /interface bridge add \
    name=bridge1 \
    protocol-mode=rstp \
    comment="LAN Bridge"

# ===== مشاهده =====
[admin@MikroTik] > /interface bridge print
# Flags: X - disabled, R - running
# 0 R name="bridge1" mtu=auto

# ===== حالت‌های Protocol-Mode =====
# none  → بدون STP (پیشنهاد برای شبکه‌های ساده)
# rstp  → Rapid Spanning Tree
# mstp  → Multiple Spanning Tree (پیشرفته)
# stp   → Spanning Tree کلاسیک

پارامترهای مهم Bridge:

پارامتر توضیح
nameنام Bridge
protocol-modenone/rstp/mstp/stp
mtuحداکثر اندازه‌ی بسته (auto یا مقدار مشخص)
mac-addressMAC آدرس Bridge
vlan-filteringفعال‌سازی VLAN Filtering (yes/no)
priorityاولویت STP
arpenabled/disabled/proxy-arp/reply-only

۳.۴ افزودن پورت به Bridge

# ===== افزودن یک پورت =====
[admin@MikroTik] > /interface bridge port add \
    bridge=bridge1 \
    interface=ether2

# ===== افزودن چند پورت =====
[admin@MikroTik] > /interface bridge port add bridge=bridge1 interface=ether3
[admin@MikroTik] > /interface bridge port add bridge=bridge1 interface=ether4
[admin@MikroTik] > /interface bridge port add bridge=bridge1 interface=ether5

# ===== مشاهده =====
[admin@MikroTik] > /interface bridge port print
# Flags: I - inactive, X - disabled, R - running
# 0   bridge=bridge1 interface=ether2
# 1 R bridge=bridge1 interface=ether3
# 2 R bridge=bridge1 interface=ether4
# 3 R bridge=bridge1 interface=ether5

# ===== نکات مهم =====
# - یک Interface فقط می‌تواند عضو یک Bridge باشد
# - پورت‌های Bridge خودشان IP نمی‌گیرند — IP روی Bridge است
# - برای حذف پورت:
[admin@MikroTik] > /interface bridge port remove [find interface=ether2]
⚠️ هشدار
اگر پورت Ethernet قبلاً IP یا DHCP Client داشته، با افزودن به Bridge آن IP غیرفعال می‌شود. همیشه IP روی خود Bridge بگذار.

۳.۵ Bridge و IP Addressing

قانون طلایی: IP روی Bridge، نه روی پورت‌های عضو. 

# ===== اشتباه ❌ =====
[admin@MikroTik] > /ip address add address=192.168.1.1/24 interface=ether2
[admin@MikroTik] > /interface bridge port add bridge=bridge1 interface=ether2
# نتیجه: IP ether2 از کار می‌افتد چون در Bridge قرار گرفته

# ===== درست ✅ =====
[admin@MikroTik] > /interface bridge add name=bridge1
[admin@MikroTik] > /interface bridge port add bridge=bridge1 interface=ether2
[admin@MikroTik] > /interface bridge port add bridge=bridge1 interface=ether3
[admin@MikroTik] > /ip address add address=192.168.1.1/24 interface=bridge1

# ===== چرا؟ =====
# Bridge = یک Interface مجازی در لایه ۲
# IP روی Interface لایه ۳ داده می‌شود
# پورت‌های فیزیکی عضو Bridge، لایه ۲ هستند

# ===== سناریوی رایج: DHCP Server =====
[admin@MikroTik] > /ip dhcp-server add \
    name=lan-dhcp \
    interface=bridge1 \
    address-pool=lan-pool \
    disabled=no

۳.۶ Bridge VLAN Filtering

Bridge VLAN Filtering یک روش مدرن برای ساخت VLAN روی Bridge است — جایگزین روش قدیمی «یک Bridge جدا برای هر VLAN». 

# ===== فعال‌سازی VLAN Filtering =====
[admin@MikroTik] > /interface bridge set bridge1 vlan-filtering=yes

# ===== تعریف VLANها روی Bridge =====
[admin@MikroTik] > /interface bridge vlan add \
    bridge=bridge1 \
    vlan-ids=10 \
    tagged=bridge1 \
    untagged=ether2,ether3

[admin@MikroTik] > /interface bridge vlan add \
    bridge=bridge1 \
    vlan-ids=20 \
    tagged=bridge1 \
    untagged=ether4,ether5

# ===== تنظیم PVID روی Port =====
[admin@MikroTik] > /interface bridge port set [find interface=ether2] pvid=10
[admin@MikroTik] > /interface bridge port set [find interface=ether3] pvid=10
[admin@MikroTik] > /interface bridge port set [find interface=ether4] pvid=20
[admin@MikroTik] > /interface bridge port set [find interface=ether5] pvid=20

# ===== VLAN Interface روی Bridge برای Routing =====
[admin@MikroTik] > /interface vlan add \
    name=vlan10 \
    interface=bridge1 \
    vlan-id=10

[admin@MikroTik] > /interface vlan add \
    name=vlan20 \
    interface=bridge1 \
    vlan-id=20

# ===== IP روی VLAN =====
[admin@MikroTik] > /ip address add address=192.168.10.1/24 interface=vlan10
[admin@MikroTik] > /ip address add address=192.168.20.1/24 interface=vlan20

# ===== بررسی =====
[admin@MikroTik] > /interface bridge vlan print
[admin@MikroTik] > /interface bridge port print
🏆 نکته‌ی طلایی
در Bridge VLAN Filtering:
  • PVID = VLAN پیش‌فرض پورت (برای Untagged)
  • Tagged = پورت‌هایی که فریم را با Tag می‌فرستند (Trunk)
  • Untagged = پورت‌هایی که فریم بدون Tag می‌گیرند (Access)
  • Bridge خودش به‌عنوان Tagged باید در VLANها ثبت شود

۳.۷ STP و RSTP در Bridge

برای جلوگیری از حلقه (Loop) در Bridge، از STP یا RSTP استفاده می‌کنیم. 

# ===== حالت‌های Protocol-Mode =====
# none → بدون STP (برای شبکه‌های ساده و بدون Loop)
# stp → Spanning Tree کلاسیک (کند)
# rstp → Rapid Spanning Tree (سریع، پیشنهاد)
# mstp → Multiple Spanning Tree (پیشرفته)

# ===== فعال‌سازی RSTP =====
[admin@MikroTik] > /interface bridge set bridge1 protocol-mode=rstp

# ===== تنظیم Priority (کمتر = Root Bridge) =====
[admin@MikroTik] > /interface bridge set bridge1 priority=0x1000
# یا برای Root شدن:
[admin@MikroTik] > /interface bridge set bridge1 priority=0x0000

# ===== بررسی وضعیت STP =====
[admin@MikroTik] > /interface bridge monitor bridge1
# خروجی:
# state: enabled
# current-mac-address: XX:XX:XX:XX:XX:XX
# root-bridge: no
# root-bridge-id: 0x8000.XX:XX:XX:XX:XX:XX
# root-path-cost: 20000
# ...

[admin@MikroTik] > /interface bridge port monitor [find interface=ether2]
# state: forwarding / blocking / learning
# role: root-port / designated-port / alternate-port / disabled

STP Port States:

  • Disabled: پورت خاموش
  • Blocking: فقط BPDU دریافت (در STP کلاسیک)
  • Listening: BPDU رد و بدل (در STP کلاسیک)
  • Learning: MAC Learning فعال
  • Forwarding: کاملاً فعال
💡 نکته
در شبکه‌های Bridge بدون Loop (مثل یک سوئیچ ساده)، می‌توانی protocol-mode=none بگذاری و Performance را بهبود بدهی.

۳.۸ Bridge با Wireless (Station-Bridge)

برای اتصال دو شبکه‌ی Wireless در لایه ۲، از ترکیب Bridge + Wireless Mode استفاده می‌کنیم.

حالت‌های Wireless مرتبط:

  • ap-bridge: Access Point استاندارد — کلاینت‌ها با MAC خودشان در Bridge دیده می‌شوند
  • station: Client ساده — فقط خودش MAC دارد (سایر MACها پشت آن مخفی می‌شوند)
  • station-bridge: Client برای Bridge — MAC تمام دستگاه‌های LAN را منتقل می‌کند ✅
  • station-pseudobridge: نسخه‌ی ناقص — برای حالتی که AP از WDS پشتیبانی نمی‌کند
# ===== سناریو: دو Access Point که LANشان به هم وصل است =====

# ===== AP-1 (Master) =====
[admin@AP1] > /interface wireless set wlan1 \
    mode=ap-bridge \
    ssid=BridgeLink \
    frequency=5180 \
    band=5ghz-a \
    security-profile=default \
    disabled=no

[admin@AP1] > /interface bridge add name=bridge1
[admin@AP1] > /interface bridge port add bridge=bridge1 interface=wlan1
[admin@AP1] > /interface bridge port add bridge=bridge1 interface=ether1
[admin@AP1] > /ip address add address=192.168.1.1/24 interface=bridge1

# ===== AP-2 (Client) =====
[admin@AP2] > /interface wireless set wlan1 \
    mode=station-bridge \
    ssid=BridgeLink \
    frequency=5180 \
    band=5ghz-a \
    security-profile=default \
    disabled=no

[admin@AP2] > /interface bridge add name=bridge1
[admin@AP2] > /interface bridge port add bridge=bridge1 interface=wlan1
[admin@AP2] > /interface bridge port add bridge=bridge1 interface=ether1
[admin@AP2] > /ip address add address=192.168.1.2/24 interface=bridge1

# ===== نتیجه: دو شبکه‌ی LAN کاملاً پل شده =====
# PC1 در AP1 با PC2 در AP2 در یک شبکه L2 است
⚠️ هشدار
station-bridge فقط با APهای MikroTik کار می‌کند (چون از WDS اختصاصی استفاده می‌کند). برای APهای غیر MikroTik، از station-pseudobridge استفاده کن (با محدودیت‌ها).

۳.۹ Bridge Hardware Offload

Hardware Offload یک ویژگی است که Bridge را روی ASIC سوئیچ اجرا می‌کند — نه CPU. نتیجه: Performance Wire-speed. 

# ===== فعال‌سازی Offload (خودکار در بعضی مدل‌ها) =====
[admin@MikroTik] > /interface bridge port print
# در ستون H باید ببینی: H = Hardware Offload فعال

# ===== اگر H نشان داده نمی‌شود: =====
[admin@MikroTik] > /interface bridge port set [find] hw=yes

# ===== بررسی وضعیت Offload =====
[admin@MikroTik] > /interface ethernet switch print
[admin@MikroTik] > /interface bridge port print detail

# ===== چه چیزهایی Offload را مختل می‌کنند؟ =====
# 1. Bridge Firewall فعال
# 2. VLAN Filtering در بعضی مدل‌ها
# 3. استفاده از IP روی پورت (به‌جای Bridge)
# 4. Interface مجازی روی Bridge (VLAN، EoIP)

# ===== بررسی دقیق =====
[admin@MikroTik] > /interface bridge port print where hw=yes
💡 نکته
در RouterBOARDهای جدید (مثل hEX، RB4011، CCR)، اگر تمام شرایط Offload برقرار باشد، Bridge می‌تواند چندین Gbps را بدون فشار CPU عبور دهد.

۳.۱۰ Bridge Port Settings

پارامترهای مهم برای هر پورت Bridge:

پارامتر توضیح
pvidPort VLAN ID — VLAN پیش‌فرض پورت (پیش‌فرض: 1)
ingress-filteringبررسی VLAN تگ روی فریم‌های ورودی (yes/no)
frame-typesadmit-all / admit-only-untagged-and-priority-tagged / admit-only-vlan-tagged
tag-stackingافزودن Tag اضافه (برای QinQ)
horizonجلوگیری از Loop در Bridge بدون STP
hwHardware Offload (yes/no/auto)
edgePortFast — برای پورت‌های Access
point-to-pointنوع لینک STP
bpdu-guardBPDU Guard — غیرفعال کردن پورت در صورت دریافت BPDU
learnMAC Learning (yes/no)
trustedپورت Trusted برای DHCP Snooping
 
# ===== پیکربندی پورت Access =====
[admin@MikroTik] > /interface bridge port set [find interface=ether2] \
    pvid=10 \
    frame-types=admit-only-untagged-and-priority-tagged \
    ingress-filtering=yes \
    edge=yes \
    bpdu-guard=yes

# ===== پیکربندی پورت Trunk =====
[admin@MikroTik] > /interface bridge port set [find interface=ether24] \
    frame-types=admit-only-vlan-tagged \
    ingress-filtering=yes

# ===== Horizon برای جلوگیری از Loop =====
[admin@MikroTik] > /interface bridge port set [find interface=ether2] horizon=1
[admin@MikroTik] > /interface bridge port set [find interface=ether3] horizon=1
# پورت‌هایی با Horizon یکسان، ترافیک را به هم Forward نمی‌کنند

۳.۱۱ Bridge Filters و NAT

Bridge Filters اجازه می‌دهد در لایه ۲ ترافیک را فیلتر یا تغییر دهی. 

# ===== انواع Bridge Filter =====
# 1. Filter — Drop بسته‌های خاص
# 2. NAT — تغییر MAC/IP در لایه 2

# ===== مثال ۱: Block کردن ARP در لایه 2 =====
[admin@MikroTik] > /interface bridge filter add \
    chain=forward \
    protocol=arp \
    action=drop \
    comment="Block ARP"

# ===== مثال ۲: Block MAC خاص =====
[admin@MikroTik] > /interface bridge filter add \
    chain=forward \
    src-mac-address=00:11:22:33:44:55/FF:FF:FF:FF:FF:FF \
    action=drop

# ===== مثال ۳: Rate Limit Broadcast =====
[admin@MikroTik] > /interface bridge filter add \
    chain=forward \
    dst-mac-address=FF:FF:FF:FF:FF:FF/FF:FF:FF:FF:FF:FF \
    action=drop

# ===== Bridge NAT =====
[admin@MikroTik] > /interface bridge nat add \
    chain=srcnat \
    src-mac-address=00:11:22:33:44:55/FF:FF:FF:FF:FF:FF \
    action=src-nat \
    to-src-mac-address=AA:BB:CC:DD:EE:FF

# ===== بررسی =====
[admin@MikroTik] > /interface bridge filter print
[admin@MikroTik] > /interface bridge nat print

۳.۱۲ Bridge Firewall (Layer 2 Firewall)

Bridge Firewall نسخه‌ی پیشرفته‌تر Bridge Filter است که از Connection Tracking هم پشتیبانی می‌کند. 

# ===== فعال‌سازی Bridge Firewall =====
# توجه: باید bridge را با use-ip-firewall=yes تنظیم کنی
[admin@MikroTik] > /interface bridge set bridge1 use-ip-firewall=yes

# حالا Bridge از IP Firewall (filter/nat/mangle) استفاده می‌کند

# ===== کاربرد ۱: اعمال Firewall بین VLANها =====
# با Bridge VLAN Filtering، وقتی Bridge ترافیک بین VLANها را Route می‌کند،
# می‌توانی Firewall IP روی Bridge اعمال کنی

[admin@MikroTik] > /ip firewall filter add \
    chain=forward \
    in-interface=vlan10 \
    out-interface=vlan20 \
    action=drop \
    comment="Block VLAN10 → VLAN20"

# ===== کاربرد ۲: Isolate Wireless Clients =====
# روی وایرلس، Client-to-Client Forwarding
[admin@MikroTik] > /interface bridge port set [find interface=wlan1] horizon=1
# تمام Wireless Clientها در یک Horizon → نمی‌توانند با هم حرف بزنند

# ===== مقایسه Bridge Filter و Bridge Firewall =====
# Bridge Filter → L2 فقط، سریع‌تر
# Bridge Firewall → L3/L4 با Connection Tracking، انعطاف‌پذیرتر

۳.۱۳ DHCP Snooping روی Bridge

DHCP Snooping جلوی DHCP Server جعلی را می‌گیرد. در RouterOS با Bridge Filter پیاده می‌شود. 

# ===== فعال‌سازی DHCP Snooping =====

# گام ۱: تعیین پورت‌های Trusted (به‌سمت DHCP Server واقعی)
[admin@MikroTik] > /interface bridge port set [find interface=ether1] trusted=yes
# پورت Uplink به DHCP Server

# گام ۲: Bridge Filter برای Block کردن DHCP Offer از Untrusted
[admin@MikroTik] > /interface bridge filter add \
    chain=forward \
    protocol=udp \
    dst-port=68 \
    src-port=67 \
    in-bridge-port=!ether1 \
    action=drop \
    comment="DHCP Snooping - Block rogue offers"

# ===== چرا این مهم است؟ =====
# بدون Snooping، یک مهاجم می‌تواند:
# - DHCP Offer جعلی بفرستد
# - خودش را Gateway کند (Man-in-the-Middle)
# - ترافیک کاربران را بدزدد

# ===== بررسی =====
[admin@MikroTik] > /interface bridge filter print
[admin@MikroTik] > /interface bridge port print where trusted=yes

[admin@MikroTik] > /tool mac-telnet AA:BB:CC:DD:EE:FF

# ۷. Torch روی Bridge
[admin@MikroTik] > /tool torch interface=bridge1

# ۸. Packet Sniffer روی Bridge
[admin@MikroTik] > /tool sniffer quick interface=bridge1
[admin@MikroTik] > /tool sniffer start
💡 چک‌لیست عیب‌یابی Bridge
  1. Bridge در حالت R (Running) است؟
  2. پورت‌ها در Bridge به‌درستی اضافه شده‌اند؟
  3. IP روی Bridge است (نه روی پورت)؟
  4. VLAN Filtering با PVID و Tagged/Untagged صحیح؟
  5. STP حلقه‌ها را بسته؟ یا protocol-mode=none بدون Loop؟
  6. MAC Addressها در Host Table دیده می‌شوند؟
  7. Firewall و Bridge Filter جلوی ترافیک را نگرفته؟

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
در Bridge، همیشه IP روی خود Bridge بگذار — نه روی پورت‌های عضو. این قانون ۹۰٪ خطاهای پیکربندی را حل می‌کند.
⚠️ هشدار
Bridge VLAN Filtering را با احتیاط فعال کن. اگر درست تنظیم نشود، خودت را از دستگاه بیرون می‌اندازی. همیشه از Safe Mode استفاده کن.
🏆 نکته‌ی طلایی
برای Wireless که می‌خواهی به Bridge وصل شود، از station-bridge (نه station) استفاده کن — فقط این حالت MAC تمام دستگاه‌های LAN را منتقل می‌کند.
ℹ️ اطلاعات بیشتر
در فصل ۴ MikroTik با Wireless، استانداردهای 802.11 و NV2 آشنا می‌شوی.
🔮 دیدگاه پیشرفته
در MTCWE با WDS، NV2 و Mesh در RouterOS کار می‌کنی.

مثال ۱ — سوئیچ ۵ پورت با Bridge

# ===== سناریو: hEX با ۵ پورت — همه در یک شبکه =====

# ۱. ایجاد Bridge
[admin@MikroTik] > /interface bridge add name=br-lan protocol-mode=none

# ۲. افزودن همه‌ی پورت‌ها
[admin@MikroTik] > /interface bridge port
add bridge=br-lan interface=ether2 hw=yes
add bridge=br-lan interface=ether3 hw=yes
add bridge=br-lan interface=ether4 hw=yes
add bridge=br-lan interface=ether5 hw=yes

مثال ۲ — Bridge با VLAN Filtering (Router + Switch)

# ===== سناریو: یک روتر با VLAN 10، 20 و Trunk =====

# ۱. Bridge
[admin@MikroTik] > /interface bridge add name=br-vlan vlan-filtering=no

# ۲. افزودن پورت‌ها
# ether2 → Access VLAN 10 (HR)
# ether3 → Access VLAN 20 (IT)
# ether4 → Access VLAN 30 (Guest)
# ether5 → Trunk
[admin@MikroTik] > /interface bridge port
add bridge=br-vlan interface=ether2 pvid=10
add bridge=br-vlan interface=ether3 pvid=20
add bridge=br-vlan interface=ether4 pvid=30
add bridge=br-vlan interface=ether5

# ۳. VLAN Table
[admin@MikroTik] > /interface bridge vlan
add bridge=br-vlan vlan-ids=10 untagged=ether2 tagged=ether5,br-vlan
add bridge=br-vlan vlan-ids=20 untagged=ether3 tagged=ether5,br-vlan
add bridge=br-vlan vlan-ids=30 untagged=ether4 tagged=ether5,br-vlan

# ۴. فعال‌سازی VLAN Filtering
[admin@MikroTik] > /interface bridge set br-vlan vlan-filtering=yes

# ۵. VLAN Interfaces برای Routing
[admin@MikroTik] > /interface vlan
add name=vlan10 interface=br-vlan vlan-id=10
add name=vlan20 interface=br-vlan vlan-id=20
add name=vlan30 interface=br-vlan vlan-id=30

# ۶. IP Addresses
[admin@MikroTik] > /ip address
add address=192.168.10.1/24 interface=vlan10
add address=192.168.20.1/24 interface=vlan20
add address=192.168.30.1/24 interface=vlan30

# ۷. بررسی
[admin@MikroTik] > /interface bridge vlan print
[admin@MikroTik] > /interface vlan print
[admin@MikroTik] > /ip address print

مثال ۴ — Bridge با STP و BPDU Guard

# ===== سناریو: شبکه با Loop بالقوه =====

# ۱. Bridge با RSTP
[admin@MikroTik] > /interface bridge add \
    name=br-stp \
    protocol-mode=rstp \
    priority=0x1000

# ۲. افزودن پورت‌ها
[admin@MikroTik] > /interface bridge port
add bridge=br-stp interface=ether2 edge=yes bpdu-guard=yes
add bridge=br-stp interface=ether3 edge=yes bpdu-guard=yes
add bridge=br-stp interface=ether4
add bridge=br-stp interface=ether5

# ۳. تنظیم Root Bridge
[admin@MikroTik] > /interface bridge set br-stp priority=0x0000
# priority کمتر = احتمال Root Bridge بیشتر

# ۴. بررسی وضعیت STP
[admin@MikroTik] > /interface bridge monitor br-stp
# ببین: root-bridge: yes (اگر خودت Root شدی)

[admin@MikroTik] > /interface bridge port monitor [find interface=ether4]
# role: root-port یا designated-port یا alternate-port
# state: forwarding یا blocking

# ۵. بررسی BPDU Guard
[admin@MikroTik] > /log print where topics~"bridge"
# اگر BPDU روی پورت Edge دریافت شود، پیام Log دیده می‌شود

مثال ۵ — Bridge Host Table و عیب‌یابی

# ===== مشاهده MAC Table =====
[admin@MikroTik] > /interface bridge host print

# خروجی:
# MAC-ADDRESS       VID  ON-INTERFACE  BRIDGE  AGE
# 00:11:22:33:44:55   10  ether2        br-lan  5s
# AA:BB:CC:DD:EE:FF   20  ether3        br-lan  12s

# ===== فیلتر MAC Table =====
[admin@MikroTik] > /interface bridge host print where interface=ether2
[admin@MikroTik] > /interface bridge host print where mac-address=00:11:22:33:44:55
[admin@MikroTik] > /interface bridge host print where vid=10
[admin@MikroTik] > /interface bridge host print count-only

# ===== پیدا کردن دستگاه با IP خاص =====
[admin@MikroTik] > /ip arp print where address=192.168.88.10
# MAC را بگیر
[admin@MikroTik] > /interface bridge host print where mac-address=
# Interface را ببین

# ===== پاک کردن MAC Table (اجباری) =====
[admin@MikroTik] > /interface bridge host remove [find where !local]

# ===== تست شنود یک پورت =====

🛠️ کارگاه عملی گام‌به‌گام

  1. در GNS3 یا EVE-NG دو RouterOS (CHR) بساز
  2. به هر RouterOS چند Interface بده (Ethernet و Wireless)
  3. روی R1 یک Bridge بساز و ۳ پورت Ethernet اضافه کن
  4. IP روی Bridge بگذار و DHCP Server راه‌اندازی کن
  5. یک PC به هر پورت وصل کن — همه باید IP بگیرند
  6. Bridge VLAN Filtering را فعال کن — VLAN 10، 20، 30
  7. هر پورت را به یک VLAN اختصاص بده (PVID)
  8. یک VLAN Interface بساز و IP بگذار
  9. RSTP را فعال کن و Priority را برای Root تنظیم کن
  10. BPDU Guard را روی پورت‌های Edge فعال کن
  11. یک Wireless Interface روی R2 را به Bridge وصل کن (station-bridge)
  12. R2 را به R1 از طریق Wireless پل کن
  13. MAC Table را در هر دو طرف بررسی کن
  14. با sniffer یک capture بگیر و بسته‌های Bridge را تحلیل کن

🚫 خطاهای رایج و رفع‌اشکال

  • IP روی پورت، نه Bridge: بعد از افزودن به Bridge، IP پورت غیرفعال می‌شود — IP را روی Bridge بگذار.
  • Bridge بدون STP با Loop: شبکه دچار Broadcast Storm می‌شود — RSTP را فعال کن.
  • VLAN Filtering بدون VLAN Table: تمام ترافیک Drop می‌شود — Table را کامل کن.
  • PVID اشتباه: ترافیک در VLAN نادرست می‌رود — PVID را با VLAN Table هماهنگ کن.
  • station به‌جای station-bridge: فقط MAC خودش منتقل می‌شود — MACهای پشت آن دیده نمی‌شوند.
  • Hardware Offload از کار افتاده: Firewall یا VLAN Filtering باعث CPU-based سوئیچینگ می‌شود.
  • BPDU Guard فعال روی Trunk: پورت Trunk به‌اشتباه Block می‌شود — فقط روی Edge فعال کن.
  • Loop در Bridge بدون STP: ترافیک Broadcast بی‌نهایت می‌شود — horizon یا RSTP بگذار.
  • Bridge با MTU کم: بسته‌های بزرگ Drop می‌شوند — MTU را auto یا 1500 بگذار.
  • Trusted Port اشتباه در DHCP Snooping: سرور DHCP واقعی هم Block می‌شود.
  • MAC Table پر می‌شود: Aging Time پایین — Aging را چک کن.
  • بعد از تغییر VLAN Filtering اتصال قطع شد: از Safe Mode استفاده کن — تغییرات بعد از Logout برمی‌گردند.

🎯 پروژه‌ی پایانی فصل

یک شبکه‌ی لایه ۲ کامل با Bridge بساز:

  • سخت‌افزار: RouterOS روی CHR یا سخت‌افزار
  • Bridge با ۴ پورت Ethernet در یک VLAN
  • VLAN Filtering: VLAN 10، 20، 30، 99 (Management)
  • VLAN Interface برای هر VLAN با IP
  • DHCP Server برای هر VLAN
  • RSTP فعال با Priority مناسب
  • BPDU Guard روی پورت‌های Edge
  • DHCP Snooping با Trusted Port روی Uplink
  • Wireless Interface به Bridge اضافه شود (Station-Bridge)
  • MAC Table روی هر دو طرف بررسی و مستندسازی شود
  • مستندسازی کامل با Export و دیاگرام شبکه
🏆 چالش اضافه
  • یک Loop عمدی بساز و ببین RSTP چطور Block می‌کند.
  • یک BPDU جعلی از یک PC بفرست و BPDU Guard را تست کن.
  • با Bridge Filter، ترافیک ARP یک VLAN را Rate Limit کن.
  • با Bridge NAT، MAC یک دستگاه را تغییر بده و تست کن.

📋 جمع‌بندی و برگه‌تقب

  • Bridge: سوئیچ نرم‌افزاری در RouterOS — L2
  • افزودن پورت: /interface bridge port add
  • IP: همیشه روی Bridge — نه روی پورت‌ها
  • Protocol-Mode: none / stp / rstp / mstp
  • VLAN Filtering: Bridge VLAN Table + PVID + Tagged/Untagged
  • PVID: VLAN پیش‌فرض پورت
  • Tagged: پورت Trunk — Untagged: پورت Access
  • Wireless Bridge: از station-bridge (نه station)
  • Hardware Offload: اجرای Bridge روی ASIC — Wire-speed
  • Bridge Firewall: با use-ip-firewall=yes
  • Horizon: جلوگیری از Loop بدون STP
  • BPDU Guard: روی Edge Ports
  • MAC Table: /interface bridge host print
  • DHCP Snooping: Trusted Port روی Uplink، Block Offer از Untrusted
