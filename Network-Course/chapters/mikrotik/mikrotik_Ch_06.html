📘 بدنه‌ی آموزشی

۶.۱ مفاهیم پایه Firewall در RouterOS

Firewall Filter در RouterOS مجموعه‌ای از Rules است که به‌ترتیب چک می‌شوند و تصمیم می‌گیرند چه ترافیکی عبور کند و چه ترافیکی Drop شود.

سه بخش اصلی فایروال در RouterOS:

  • Filter: Allow/Deny ترافیک
  • NAT: ترجمه آدرس IP و پورت
  • Mangle: علامت‌گذاری بسته‌ها برای QoS، Routing و NAT

مسیر بسته در RouterOS:

Inbound Packet
    ↓
[RAW]   → پیش‌فیلتر (Bypass/Notrack)
    ↓
[MANGLE Prerouting]
    ↓
[DESTINATION NAT]
    ↓
[ROUTING DECISION]
    ↓
[INPUT (به روتر)] یا [FORWARD (عبوری)] یا [OUTPUT (از روتر)]
    ↓
[MANGLE Postrouting]
    ↓
[SOURCE NAT]
    ↓
Outbound Packet

۶.۲ Connection Tracking و Stateful Firewall

RouterOS یک Stateful Firewall است — یعنی وضعیت تمام اتصالات فعال را در جدول Connection Tracking نگه می‌دارد.

حالت‌های Connection:

State توضیح
newشروع یک اتصال جدید (SYN یا اولین بسته)
establishedاتصال قبلاً دیده شده و فعال است
relatedمرتبط با یک اتصال دیگر (مثل ICMP Error یا FTP Data)
invalidبسته‌ی نامعتبر یا خارج از State
untrackedاتصال Notrack شده (از فایروال عبور می‌کند)
 
# ===== مشاهده Connection Tracking =====
[admin@MikroTik] > /ip firewall connection print
[admin@MikroTik] > /ip firewall connection print count-only
[admin@MikroTik] > /ip firewall connection print where protocol=tcp
[admin@MikroTik] > /ip firewall connection print where dst-address~":80"

# ===== پاک کردن Connection Table =====
[admin@MikroTik] > /ip firewall connection remove [find]

# ===== تنظیمات Connection Tracking =====
[admin@MikroTik] > /ip firewall connection tracking print
# tcp-syn-sent-timeout: 5s
# tcp-syn-received-timeout: 5s
# tcp-established-timeout: 1d
# tcp-fin-wait-timeout: 10s
# tcp-close-wait-timeout: 10s
# tcp-last-ack-timeout: 10s
# tcp-time-wait-timeout: 10s
# tcp-close-timeout: 10s
# udp-timeout: 10s
# udp-stream-timeout: 3m
# icmp-timeout: 10s
# generic-timeout: 10m
💡 نکته
Connection Tracking، راز اصلی فایروال Stateful است. با یک Rule ساده روی connection-state=established,related می‌توانی اجازه بدهی تمام پاسخ‌های اتصالات مجاز عبور کنند — بدون نیاز به Rule جداگانه.

۶.۳ Chains — Input، Forward، Output

RouterOS سه Chain اصلی دارد که هرکدام ترافیک متفاوتی را مدیریت می‌کند:

Chain ترافیک کاربرد
input به خود روتر حفاظت از روتر — SSH، Winbox، API، SNMP
forward از یک Interface به Interface دیگر کنترل ترافیک کاربران — فیلتر ترافیک عبوری
output از روتر به بیرون کنترل ترافیک تولیدی خود روتر — کمتر استفاده می‌شود 
# ===== نمونه Rule در هر Chain =====

# Input — اجازه SSH از LAN
[admin@MikroTik] > /ip firewall filter add \
    chain=input \
    protocol=tcp \
    dst-port=22 \
    src-address=192.168.88.0/24 \
    action=accept \
    comment="SSH from LAN"

# Forward — اجازه HTTP از کاربران به اینترنت
[admin@MikroTik] > /ip firewall filter add \
    chain=forward \
    protocol=tcp \
    dst-port=80,443 \
    action=accept \
    comment="Allow HTTP/HTTPS"

# Output — اجازه DNS از روتر
[admin@MikroTik] > /ip firewall filter add \
    chain=output \
    protocol=udp \
    dst-port=53 \
    action=accept \
    comment="Allow DNS"

۶.۴ Actions — Accept، Drop، Reject، Jump، Log

Action توضیح
acceptاجازه عبور — از ادامه Rules صرف‌نظر می‌شود
dropحذف بسته بدون اطلاع به فرستنده (Silent)
rejectرد بسته با ارسال ICMP Error به فرستنده
jumpپرش به Chain دیگر — برای تقسیم منطقی Rules
returnبازگشت از Jump به Chain اصلی
logثبت در Log و ادامه به Rule بعدی
tarpitبه‌دام انداختن اتصال (کند کردن مهاجم)
passthroughفقط Match، بدون Action — ادامه به Rule بعدی
💡 نکته
drop امن‌تر از reject است — چون مهاجم نمی‌فهمد سرویس وجود دارد یا نه. در قواعد Public، همیشه از drop استفاده کن.

۶.۵ ساختار فایروال پایه

یک فایروال حرفه‌ای MikroTik معمولاً از این ساختار استفاده می‌کند: 

# ===== ساختار فایروال پایه (ترتیب مهم است) =====

# ===== INPUT CHAIN — حفاظت از روتر =====

# ۱. اجازه Established و Related
[admin@MikroTik] > /ip firewall filter add \
    chain=input \
    connection-state=established,related \
    action=accept \
    comment="Allow Established/Related"

# ۲. Drop Invalid
[admin@MikroTik] > /ip firewall filter add \
    chain=input \
    connection-state=invalid \
    action=drop \
    comment="Drop Invalid"

# ۳. اجازه ICMP (Ping)
[admin@MikroTik] > /ip firewall filter add \
    chain=input \
    protocol=icmp \
    action=accept \
    comment="Allow ICMP"

# ۴. اجازه SSH/Winbox از LAN
[admin@MikroTik] > /ip firewall filter add \
    chain=input \
    protocol=tcp \
    dst-port=22,8291 \
    src-address=192.168.88.0/24 \
    action=accept \
    comment="Allow SSH/Winbox from LAN"

# ۵. اجازه DHCP از LAN
[admin@MikroTik] > /ip firewall filter add \
    chain=input \
    protocol=udp \
    dst-port=67 \
    action=accept \
    comment="Allow DHCP"

# ۶. Drop همه‌ی بقیه
[admin@MikroTik] > /ip firewall filter add \
    chain=input \
    action=drop \
    comment="Drop All Other Input"

# ===== FORWARD CHAIN — کنترل کاربران =====

# ۱. FastTrack برای Established و Related (اختیاری)
[admin@MikroTik] > /ip firewall filter add \
    chain=forward \
    connection-state=established,related \
    action=fasttrack-connection \
    comment="FastTrack Established"

# ۲. اجازه Established و Related
[admin@MikroTik] > /ip firewall filter add \
    chain=forward \
    connection-state=established,related \
    action=accept \
    comment="Accept Established"

# ۳. Drop Invalid
[admin@MikroTik] > /ip firewall filter add \
    chain=forward \
    connection-state=invalid \
    action=drop \
    comment="Drop Invalid"

# ۴. اجازه ترافیک LAN به WAN
[admin@MikroTik] > /ip firewall filter add \
    chain=forward \
    in-interface=bridge-lan \
    out-interface=ether1 \
    action=accept \
    comment="LAN to WAN"

# ۵. Drop بقیه Forward
[admin@MikroTik] > /ip firewall filter add \
    chain=forward \
    action=drop \
    comment="Drop All Other Forward"
🏆 نکته‌ی طلایی
ترتیب Rules حیاتی است. همیشه:
  1. Established/Related Accept
  2. Invalid Drop
  3. ترافیک‌های خاص (SSH از LAN، ICMP، ...)
  4. LAN به WAN
  5. Drop All در انتها

۶.۶ Firewall Rules برای امنیت روتر

# ===== قوانین مهم امنیتی =====

# ۱. محدود کردن Winbox به IP مدیریتی
[admin@MikroTik] > /ip firewall filter add \

۶.۸ Address-List — مدیریت IPها

Address-List مجموعه‌ای از IPها یا Subnetها با نام مشترک است. با این کار می‌توانی Rules را ساده‌تر کنی. 

# ===== ساخت Address-List =====

# ۱. لیست MGMT-IPS — IPهای مدیریتی
[admin@MikroTik] > /ip firewall address-list add \
    list=MGMT-IPS \
    address=192.168.88.10 \
    comment="Admin Laptop"

[admin@MikroTik] > /ip firewall address-list add \
    list=MGMT-IPS \
    address=192.168.88.11 \
    comment="Admin Desktop"

# ۲. لیست VIP-USERS
[admin@MikroTik] > /ip firewall address-list add \
    list=VIP-USERS \
    address=192.168.88.100-192.168.88.120 \
    comment="VIP Range"

# ۳. لیست BLOCKED — سایت‌ها یا IPهای بلاک
[admin@MikroTik] > /ip firewall address-list add \
    list=BLOCKED \
    address=203.0.113.0/24 \
    comment="Blocked Range"

# ===== استفاده در فایروال =====
[admin@MikroTik] > /ip firewall filter add \
    chain=input \
    src-address-list=MGMT-IPS \
    action=accept \
    comment="Allow from MGMT"

[admin@MikroTik] > /ip firewall filter add \
    chain=forward \
    dst-address-list=BLOCKED \
    action=drop \
    comment="Block by list"

# ===== Dynamic Address-List (خودکار) =====
[admin@MikroTik] > /ip firewall filter add \
    chain=forward \
    protocol=tcp \
    tcp-flags=syn \
    dst-port=80 \
    action=add-src-to-address-list \
    address-list=WEB-USERS \
    address-list-timeout=1h \
    comment="Add to list dynamically"

# ===== مشاهده =====
[admin@MikroTik] > /ip firewall address-list print
[admin@MikroTik] > /ip firewall address-list print where list=MGMT-IPS
[admin@MikroTik] > /ip firewall address-list print count-only

۶.۹ NAT — مفهوم و انواع

NAT (Network Address Translation) ترجمه‌ی آدرس IP مبدأ یا مقصد است. در RouterOS، NAT در /ip firewall nat پیکربندی می‌شود.

دو نوع اصلی NAT:

  • Source NAT (srcnat): تغییر IP مبدأ — برای دسترسی چند دستگاه به اینترنت
  • Destination NAT (dstnat): تغییر IP مقصد — برای Port Forwarding

Chains در NAT:

  • srcnat: بعد از تصمیم Routing، قبل از خروج
  • dstnat: قبل از تصمیم Routing

۶.۱۰ Source NAT — Masquerade و Src-NAT

# ===== Masquerade (رایج‌ترین) =====
[admin@MikroTik] > /ip firewall nat add \
    chain=srcnat \
    out-interface=ether1 \
    action=masquerade \
    comment="NAT to Internet"

# مزیت: خودکار IP اینترفیس خروجی را استفاده می‌کند

# ===== Src-NAT با IP مشخص =====
[admin@MikroTik] > /ip firewall nat add \
    chain=srcnat \
    src-address=192.168.88.0/24 \
    out-interface=ether1 \
    action=src-nat \
    to-addresses=203.0.113.5 \
    comment="NAT to specific IP"

# فرق با Masquerade:
# - Masquerade: IP خودکار از Interface
# - Src-NAT: IP مشخص و ثابت

# ===== NAT برای یک IP خاص =====
[admin@MikroTik] > /ip firewall nat add \
    chain=srcnat \
    src-address=192.168.88.10 \
    action=src-nat \
    to-addresses=203.0.113.10 \
    comment="Server Public IP"

# ===== NAT فقط برای یک مقصد خاص =====
[admin@MikroTik] > /ip firewall nat add \
    chain=srcnat \
    dst-address=8.8.8.8 \
    action=src-nat \
    to-addresses=203.0.113.20

# ===== مشاهده =====
[admin@MikroTik] > /ip firewall nat print
[admin@MikroTik] > /ip firewall nat print stats

۶.۱۱ Destination NAT — Port Forwarding

با Destination NAT می‌توانی ترافیک ورودی به یک پورت را به یک سرور داخلی هدایت کنی — مثلاً وب‌سرور داخلی روی پورت 80 از اینترنت. 

# ===== Port Forwarding ساده =====
# ترافیک پورت 8080 روی IP عمومی روتر → پورت 80 سرور داخلی
[admin@MikroTik] > /ip firewall nat add \
    chain=dstnat \
    protocol=tcp \
    dst-port=8080 \
    in-interface=ether1 \
    action=dst-nat \
    to-addresses=192.168.88.10 \
    to-ports=80 \
    comment="Forward 8080 → Web Server 80"

# ===== Port Forwarding با شرط IP مبدأ =====
# فقط از یک IP خاص
[admin@MikroTik] > /ip firewall nat add \
    chain=dstnat \
    protocol=tcp \
    dst-port=22 \
    src-address=203.0.113.100 \
    action=dst-nat \
    to-addresses=192.168.88.5 \
    to-ports=22 \
    comment="SSH only from admin IP"

# ===== Forward یک Range پورت =====
[admin@MikroTik] > /ip firewall nat add \
    chain=dstnat \
    protocol=tcp \
    dst-port=8000-8100 \
    action=dst-nat \
    to-addresses=192.168.88.20 \
    comment="Forward range to server"

# ===== RDP Forward =====
[admin@MikroTik] > /ip firewall nat add \
    chain=dstnat \
    protocol=tcp \
    dst-port=3389 \
    action=dst-nat \
    to-addresses=192.168.88.30 \
    to-ports=3389 \
    comment="RDP to Windows Server"

# ===== مشاهده =====
[admin@MikroTik] > /ip firewall nat print
[admin@MikroTik] > /ip firewall nat print where chain=dstnat
⚠️ هشدار
بعد از Port Forwarding، حتماً در Firewall Filter اجازه‌ی ورود آن پورت را بده: 
/ip firewall filter add chain=forward protocol=tcp dst-port=8080 \
  dst-address=192.168.88.10 action=accept

۶.۱۲ Hairpin NAT — دسترسی داخلی به سرور عمومی

Hairpin NAT (Loopback NAT یا NAT Reflection) مشکل زیر را حل می‌کند: اگر یک سرور داخلی داری که با Port Forwarding از اینترنت قابل دسترس است، کاربران داخلی چطور می‌توانند با IP عمومی به آن دسترسی داشته باشند؟ 

# ===== سناریو =====
# IP عمومی روتر: 203.0.113.5
# سرور داخلی: 192.168.88.10 (پورت 80)
# از اینترنت: 203.0.113.5:80 → 192.168.88.10:80
# از داخل: 192.168.88.50 → می‌خواهد به 203.0.113.5:80 وصل شود

# ===== پیکربندی Hairpin NAT =====

# ۱. Destination NAT
[admin@MikroTik] > /ip firewall nat add \
    chain=dstnat \
    protocol=tcp \
    dst-port=80 \
    dst-address=203.0.113.5 \
    action=dst-nat \
    to-addresses=192.168.88.10 \
    to-ports=80 \
    comment="Web Server DNAT"

# ۲. Source NAT برای ترافیک داخلی به سرور داخلی
[admin@MikroTik] > /ip firewall nat add \
    chain=srcnat \
    src-address=192.168.88.0/24 \
    dst-address=192.168.88.10 \
    protocol=tcp \
    dst-port=80 \
    action=src-nat \
    to-addresses=192.168.88.1 \
    comment="Hairpin NAT"

# ===== نتیجه =====
# کاربر داخلی → 203.0.113.5:80 → ترجمه به 192.168.88.10:80
# پاسخ از سرور → روتر → ترجمه برگشت
# کاربر فکر می‌کند با سرور خارجی حرف زده

۶.۱۳ Netmap — تغییر کامل Subnet

Netmap یک نوع NAT است که کل Subnet را به Subnet دیگر ترجمه می‌کند. مفید برای سناریوهای ISP یا زمانی که شبکه‌ی داخلی با Subnet دیگری تداخل دارد. 

# ===== Netmap =====
# ترجمه 10.0.0.0/24 به 192.168.1.0/24
# یعنی 10.0.0.5 → 192.168.1.5

[admin@MikroTik] > /ip firewall nat add \
    chain=srcnat \
    src-address=10.0.0.0/24 \
    action=netmap \
    to-addresses=192.168.1.0/24 \
    comment="Netmap 10.x to 192.168.1.x"

# در جهت مخالف (اگر لازم باشد)
[admin@MikroTik] > /ip firewall nat add \
    chain=dstnat \
    dst-address=192.168.1.0/24 \
    action=netmap \
    to-addresses=10.0.0.0/24

# ===== کاربرد =====
# دو شرکت با Subnet یکسان 192.168.1.0/24 در یک VPN ادغام می‌شوند
# یکی از آن‌ها با Netmap به 10.0.0.0/24 نگاشت می‌شود

۶.۱۴ FastTrack — عبور سریع ترافیک

FastTrack یک ویژگی مهم MikroTik است که ترافیک Established را از بخش‌های سنگین RouterOS (Firewall، Queue، Mangle) عبور می‌دهد و مستقیم به Forwarding می‌فرستد.

مزایا:

  • Performance بسیار بالاتر (تا چند برابر)
  • کاهش CPU Usage
  • Throughput بالاتر

معایب:

  • ترافیک FastTrack شده از Queue و Mangle عبور نمی‌کند
  • QoS روی ترافیک FastTrack شده کار نمی‌کند
  • اگر QoS یا Queue مهم است، FastTrack را غیرفعال کن
# ===== فعال‌سازی FastTrack =====
[admin@MikroTik] > /ip firewall filter add \
    chain=forward \
    connection-state=established,related \
    action=fasttrack-connection \
    comment="FastTrack Established" \
    place-before=0

# نکته: Rule FastTrack باید بالاتر از Rule Accept باشد

# ===== ترافیک‌های مستثنی از FastTrack =====
# اگر می‌خواهی QoS روی ترافیک خاصی کار کند، آن را از FastTrack خارج کن

# مثلاً VoIP را از FastTrack مستثنی کن
[admin@MikroTik] > /ip firewall filter add \
    chain=forward \
    protocol=udp \
    dst-port=5060,10000-20000 \
    action=accept \
    comment="VoIP - bypass FastTrack" \
    place-before=0
# این Rule باید قبل از FastTrack باشد

# ===== بررسی =====
[admin@MikroTik] > /ip firewall filter print where action=fasttrack-connection
[admin@MikroTik] > /ip firewall filter print stats
# ببین تعداد بسته‌های FastTrack شده
🏆 نکته‌ی طلایی
FastTrack فوق‌العاده است برای شبکه‌های معمولی، ولی اگر QoS یا Queue دقیق داری، یا آن را غیرفعال کن یا ترافیک‌های حساس را مستثنی کن.

۶.۱۵ Raw Firewall و Bypass

Raw Firewall قبل از Connection Tracking اجرا می‌شود — برای Drop کردن ترافیک‌های خطرناک بدون اشغال منابع Connection Table. 

# ===== Raw Rules =====

# ۱. Drop سریع IPهای مهاجم
[admin@MikroTik] > /ip firewall raw add \
    chain=prerouting \
    src-address-list=BLACKLIST \
    action=drop \
    comment="Drop blacklisted IPs"

# ۲. Drop Invalid در Raw (سریع‌تر از Filter)
[admin@MikroTik] > /ip firewall raw add \
    chain=prerouting \
    connection-state=invalid \
    action=drop \
    comment="Drop invalid fast"

# ۳. Notrack برای ترافیک خاص
[admin@MikroTik] > /ip firewall raw add \
    chain=prerouting \
    src-address=192.168.88.0/24 \
    action=notrack \
    comment="Notrack LAN"

# ۴. Raw Drop برای محافظت از CPU
[admin@MikroTik] > /ip firewall raw add \
    chain=prerouting \
    protocol=tcp \
    dst-port=22,8291 \
    src-address-list=NOT-MGMT \
    action=drop
💡 نکته
Raw Firewall ترافیک را قبل از Connection Tracking Drop می‌کند — سریع‌تر و کم‌هزینه‌تر. برای جلوگیری از DDoS ساده بسیار مفید است.

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
همیشه اول Established,Related → Accept بگذار، بعد Invalid → Drop. این دو Rule، ۹۰٪ ترافیک مشروع را پوشش می‌دهند و بقیه Rules فقط برای ترافیک New هستند.
⚠️ خطر بزرگ
هرگز در Production، یک Drop نهایی برای Chain=input بدون Rule قبلی برای SSH/Winbox نگذار. در غیر این صورت خودت را از روتر بیرون می‌اندازی. از Safe Mode استفاده کن.
🏆 نکته‌ی طلایی
Masquerade vs Src-NAT:
  • Masquerade: IP خودکار اینترفیس — برای لینک‌های DHCP/PPPoE
  • Src-NAT: IP ثابت — وقتی IP عمومی مشخص داری و می‌خواهی خاص باشی
ℹ️ اطلاعات بیشتر
در فصل ۷ با Queue، QoS و مدیریت پهنای باند (PCQ، Simple Queue، Queue Tree) آشنا می‌شوی.
🔮 دیدگاه پیشرفته
در MTCSE با Mangle پیشرفته، Connection Mark و Policy Routing در سطح حرفه‌ای کار می‌کنی.

💻 مثال‌های عملی

مثال ۱ — فایروال کامل روتر خانگی

# ===== ساختار فایروال روتر خانگی =====

# INPUT — حفاظت از روتر
/ip firewall filter
add chain=input connection-state=established,related action=accept comment="Est/Rel"
add chain=input connection-state=invalid action=drop comment="Invalid"
add chain=input protocol=icmp action=accept comment="ICMP"
add chain=input protocol=udp dst-port=67 action=accept comment="DHCP"
add chain=input in-interface=bridge-lan action=accept comment="LAN full access"
add chain=input action=drop comment="Drop all WAN input"

# FORWARD — کنترل کاربران
add chain=forward connection-state=established,related action=fasttrack-connection comment="FastTrack"
add chain=forward connection-state=established,related action=accept comment="Est/Rel"
add chain=forward connection-state=invalid action=drop comment="Invalid"
add chain=forward in-interface=bridge-lan out-interface=ether1 action=accept comment="LAN to WAN"
add chain=forward action=drop comment="Drop all"

# NAT
/ip firewall nat
add chain=srcnat out-interface=ether1 action=masquerade comment="NAT"

# ===== نتیجه =====
# - کاربران LAN به اینترنت دسترسی دارند
# - از WAN هیچ‌کس نمی‌تواند به روتر وصل شود
# - Performance بالا با FastTrack

مثال ۲ — Port Forwarding چند سرویس

# ===== سناریو: چند سرویس داخلی =====
# سرور وب: 192.168.88.10 (پورت 80، 443)
# RDP: 192.168.88.20 (پورت 3389)
# SSH: 192.168.88.30 (پورت 22)

# ===== Destination NAT =====
/ip firewall nat
add chain=dstnat protocol=tcp dst-port=80,443 in-interface=ether1 \
    action=dst-nat to-addresses=192.168.88.10 comment="Web Server"
add chain=dstnat protocol=tcp dst-port=3389 in-interface=ether1 \
    action=dst-nat to-addresses=192.168.88.20 comment="RDP"
add chain=dstnat protocol=tcp dst-port=2222 in-interface=ether1 \
    action=dst-nat to-addresses=192.168.88.30 to-ports=22 \
    comment="SSH via 2222"

# ===== اجازه در Firewall =====
/ip firewall filter
add chain=forward protocol=tcp dst-port=80,443 dst-address=192.168.88.10 \
    action=accept comment="Allow Web"
add chain=forward protocol=tcp dst-port=3389 dst-address=192.168.88.20 \
    action=accept comment="Allow RDP"
add chain=forward protocol=tcp dst-port=22 dst-address=192.168.88.30 \
    action=accept comment="Allow SSH"

مثال ۳ — Hairpin NAT برای سرور وب

# ===== پیکربندی Hairpin NAT =====

# ۱. Destination NAT
[admin@MikroTik] > /ip firewall nat add \
    chain=dstnat \
    protocol=tcp \
    dst-port=80 \
    dst-address=203.0.113.5 \
    action=dst-nat \
    to-addresses=192.168.88.10 \
    to-ports=80 \
    comment="Web Server DNAT"

# ۲. Source NAT برای ترافیک داخلی
[admin@MikroTik] > /ip firewall nat add \
    chain=srcnat \
    src-address=192.168.88.0/24 \
    dst-address=192.168.88.10 \
    protocol=tcp \
    dst-port=80 \
    action=src-nat \
    to-addresses=192.168.88.1 \
    comment="Hairpin NAT"

# ===== تست =====
# از یک PC داخلی: browse به 203.0.113.5:80
# باید وب‌سرور داخلی باز شود

# از PC خارجی: browse به 203.0.113.5:80
# باید همان وب‌سرور باز شود

# ===== نکته =====
# IP داخلی روتر (192.168.88.1) در to-addresses استفاده می‌شود
# تا پاسخ از روتر به کاربر برگردد

مثال ۴ — Brute Force Protection

# ===== محافظت از SSH و Winbox با Address-List =====

# ۱. Stage 1 — اولین تلاش
/ip firewall filter
add chain=input protocol=tcp dst-port=22,8291 connection-state=new \
    src-address-list=ssh_stage1 \
    action=add-src-to-address-list \
    address-list=ssh_stage2 \
    address-list-timeout=1m \
    comment="Stage 1 → 2"

# ۲. Stage 2
add chain=input protocol=tcp dst-port=22,8291 connection-state=new \
    src-address-list=ssh_stage2 \
    action=add-src-to-address-list \
    address-list=ssh_stage3 \
    address-list-timeout=1m \
    comment="Stage 2 → 3"

# ۳. Stage 3 → Blacklist
add chain=input protocol=tcp dst-port=22,8291 connection-state=new \
    src-address-list=ssh_stage3 \
    action=add-src-to-address-list \
    address-list=ssh_blacklist \
    address-list-timeout=1d \
    comment="Stage 3 → Blacklist"

# ۴. Drop blacklist
add chain=input protocol=tcp dst-port=22,8291 \
    src-address-list=ssh_blacklist \
    action=drop \
    comment="Drop blacklisted"

# ۵. اولین Rule — شروع Stage 1
add chain=input protocol=tcp dst-port=22,8291 connection-state=new \
    action=add-src-to-address-list \
    address-list=ssh_stage1 \
    address-list-timeout=1m \
    comment="Start Stage 1" \
    place-before=0

# ===== نتیجه =====
# - بعد از ۳ تلاش ناموفق، IP در Blacklist قرار می‌گیرد
# - به مدت ۲۴ ساعت بلاک می‌شود

مثال ۵ — Netmap برای ISP

# ===== سناریو: ISP کوچک با مشتری =====
# مشتری: 100 مشتری با IP خصوصی 10.0.0.1-10.0.0.100
# می‌خواهی این‌ها با IP عمومی 203.0.113.0/24 دیده شوند

# Netmap از 10.0.0.0/24 به 203.0.113.0/24
[admin@MikroTik] > /ip firewall nat add \
    chain=srcnat \
    src-address=10.0.0.0/24 \
    action=netmap \
    to-addresses=203.0.113.0/24 \
    comment="Netmap to public"

# نتیجه:
# 10.0.0.1 → 203.0.113.1
# 10.0.0.5 → 203.0.113.5
# 10.0.0.100 → 203.0.113.100

# ===== در جهت برگشت =====
[admin@MikroTik] > /ip firewall nat add \
    chain=dstnat \
    dst-address=203.0.113.0/24 \
    action=netmap \
    to-addresses=10.0.0.0/24 \
    comment="Reverse netmap"

# ===== نکته =====
# Netmap برای ISPها و ادغام شبکه‌های Overlapping عالی است
# هر IP داخلی به یک IP عمومی نگاشت می‌شود

🛠️ کارگاه عملی گام‌به‌گام

  1. RouterOS با دو Interface (WAN و LAN) راه‌اندازی کن
  2. WAN را با DHCP Client از ISP بگیر
  3. LAN را با Bridge و IP تنظیم کن
  4. فایروال پایه Input بساز (Est، Invalid، ICMP، LAN، Drop)
  5. فایروال پایه Forward بساز (FastTrack، Est، Invalid، LAN to WAN، Drop)
  6. NAT Masquerade روی WAN فعال کن
  7. یک وب‌سرور داخلی راه‌اندازی کن (192.168.88.10:80)
  8. Port Forwarding از WAN:8080 → سرور:80
  9. Hairpin NAT برای دسترسی داخلی از طریق IP عمومی
  10. Brute Force Protection برای SSH
  11. Address-List MGMT-IPS با IP مدیریتی بساز
  12. Winbox را فقط از MGMT-IPS اجازه بده
  13. یک Address-List BLOCKED برای بلاک سایت بساز
  14. با Sniffer ترافیک را تحلیل کن و Ruleها را عیب‌یابی کن
  15. Log را برای Drop نهایی فعال کن و ببین چه چیزی Drop می‌شود

🚫 خطاهای رایج و رفع‌اشکال

  • خودت را از روتر بیرون انداختی: Drop نهایی جلوی SSH/Winbox را گرفته — از Safe Mode استفاده کن.
  • اینترنت کاربران قطع شد: Rule Est/Rel در Forward نیست یا ترتیب اشتباه.
  • NAT کار نمی‌کند: Chain اشتباه، out-interface غلط، یا Rule قبل از آن Drop می‌کند.
  • Port Forwarding کار نمی‌کند: Rule Forward برای اجازه پورت نیست، یا NAT Wrong.
  • Hairpin NAT کار نمی‌کند: Src-Address داخلی و to-addresses باید IP داخلی روتر باشد.
  • FastTrack جلوی QoS را می‌گیرد: ترافیک حساس را قبل از FastTrack Accept کن.
  • Connection Table پر می‌شود: Raw Firewall برای Drop Invalid یا Notrack استفاده کن.
  • Counterها افزایش نمی‌یابند: Rule اشتباه یا ترتیب اشتباه — با place-before جابه‌جا کن.
  • Rule شماره‌ی اشتباه را Delete کردم: همیشه با find comment="..." استفاده کن.
  • بعد از تغییرات Firewall قطعی موقت: از Safe Mode یا یک Session دوم برای برگشت استفاده کن.
  • Drop همه ترافیک: احتمالاً Rule Drop نهایی بدون Rules Accept قبل از آن است.
  • Address-List داینامیک پاک می‌شود: address-list-timeout را تنظیم کن.
  • Masquerade با IP اشتباه: out-interface باید دقیقاً همان Interface خروجی باشد.
  • Netmap پاسخ برنمی‌گردد: باید Reverse Netmap هم داشته باشی.
  • Log Firewall خیلی بزرگ می‌شود: فقط Ruleهای مهم را Log کن — نه همه.

🎯 پروژه‌ی پایانی فصل

یک فایروال کامل برای یک دفتر کوچک بساز:

  • RouterOS با WAN (DHCP) و LAN (Bridge)
  • فایروال Input با قوانین: Est/Rel Accept، Invalid Drop، ICMP Accept، DHCP Accept، LAN Access، Drop All
  • فایروال Forward با FastTrack، Est/Rel Accept، Invalid Drop، LAN to WAN، Drop All

  • Port Forwarding برای یک وب‌سرور داخلی (پورت 8080 → 80)

  • Address-List BLOCKED برای بلاک یک وب‌سایت
  • فقط ساعات کاری برای SSH از بیرون (با Time)
  • مستندسازی کامل با Export و دیاگرام
🏆 چالش اضافه
  • یک Rule بنویس که ترافیک P2P را بلاک کند.
  • یک Rate Limit روی پورت 80 برای کاربر خاص پیاده کن.
  • با Mangle، ترافیک SSH را اولویت‌بندی کن.
  • از Safe Mode استفاده کن و یک تغییر خطرناک بزن — ببین چطور برمی‌گردد.

📋 جمع‌بندی و برگه‌تقب

  • Stateful Firewall: با Connection Tracking — ۵ state
  • Chains: input، forward، output
  • Actions: accept، drop، reject، jump، return، log
  • ترتیب مهم: Est/Rel → Invalid → Rules خاص → LAN to WAN → Drop
  • Source NAT: masquerade (IP خودکار) یا src-nat (IP مشخص)
  • Destination NAT: Port Forwarding — با dstnat
  • Hairpin NAT: برای دسترسی داخلی به سرور با IP عمومی
  • Netmap: ترجمه کل Subnet به Subnet دیگر
  • FastTrack: عبور سریع Established — ولی QoS را دور می‌زند
  • Raw Firewall: قبل از Connection Tracking — سریع‌تر
  • Address-List: مجموعه IPها با نام مشترک — استاتیک یا داینامیک
  • Brute Force Protection: با Address-List داینامیک چند مرحله‌ای
  • Safe Mode: همیشه قبل از تغییرات حساس Firewall فعال کن
