۲.۱ مفاهیم Routing Overview

Routing فرآیند انتخاب مسیر برای بسته‌های IP از یک شبکه به شبکه‌ی دیگر است. RouterOS از سه روش مسیریابی پشتیبانی می‌کند:

  • Connected: شبکه‌هایی که مستقیم به Interfaceهای روتر وصل هستند
  • Static: مسیرهایی که دستی تعریف می‌کنیم
  • Dynamic: مسیرهایی که با پروتکل‌های داینامیک (OSPF، BGP، RIP) یادگرفته می‌شوند

RouterOS چطور مسیر را انتخاب می‌کند؟

  1. بهترین تطبیق مقصد (Longest Prefix Match)
  2. کمترین Distance (مشابه Administrative Distance)
  3. در صورت مساوی بودن Distance، همه را در جدول می‌گذارد (ECMP یا Backup)
💡 نکته‌ی کلیدی
در RouterOS، برخلاف Cisco که از اصطلاح AD استفاده می‌شود، معادل آن Distance است — عدد کمتر، اولویت بالاتر.

۲.۲ ساختار جدول مسیریابی در RouterOS

[admin@MikroTik] > /ip route print

# خروجی نمونه:
Flags: X - disabled, A - active, D - dynamic, C - connect,
       S - static, r - rip, b - bgp, o - ospf, m - mme,
       B - blackhole, U - unreachable, P - prohibit

 #      DST-ADDRESS      PREF-SRC        GATEWAY       DISTANCE
 0 A S  0.0.0.0/0                        203.0.113.1   1
 1 ADC  192.168.88.0/24   192.168.88.1    ether2        0
 2 A S  10.10.10.0/24                   192.168.88.2  1
 3 A S  10.20.20.0/24                   192.168.88.3  5
 4 ADC  203.0.113.0/24   203.0.113.2    ether1        0

# ستون‌های مهم:
# DST-ADDRESS → مقصد
# PREF-SRC → Preferred Source (IP مبدأ)
# GATEWAY → Next Hop یا Interface
# DISTANCE → اولویت (کمتر = بهتر)
# Flags → وضعیت مسیر

۲.۳ Route Flags — راهنمای کامل

DDynamicمسیر داینامیک (از DHCP Client و...)

⚠️ نکته‌ی مهم
Flag A (Active) در هر مسیر نشان می‌دهد که آن مسیر واقعاً در حال استفاده است. اگر مسیری Active نباشد، یعنی Next Hop آن قابل دسترس نیست یا مسیر دیگری با Distance کمتر اولویت دارد.

۲.۴ Connected Route (خودکار)

به‌محض دادن IP به یک Interface، RouterOS خودکار دو مسیر اضافه می‌کند: 

[admin@MikroTik] > /ip address add address=192.168.10.1/24 interface=ether3

[admin@MikroTik] > /ip route print where !dynamic
# خروجی:
# 1 ADC  192.168.10.0/24   192.168.10.1   ether3   0

# ADC = Active Dynamic Connected
# Distance = 0 (بالاترین اولویت)
# این مسیر خودکار حذف می‌شود اگر Interface down شود

ویژگی‌های Connected Route:

  • خودکار ایجاد می‌شود (Dynamic)
  • Distance آن 0 است — بالاترین اولویت
  • با حذف IP یا Down شدن Interface، خودش حذف می‌شود
  • قابل ویرایش یا حذف دستی نیست

۲.۵ Static Route — پیکربندی پایه

Static Route یک مسیر دستی است که ما تعریف می‌کنیم. ساختار پایه: 

# ساختار:
/ip route add dst-address=X.X.X.X/Y gateway=Z.Z.Z.Z

# مثال: مسیر به شبکه 10.10.10.0/24 از طریق 192.168.88.2
[admin@MikroTik] > /ip route add \
    dst-address=10.10.10.0/24 \
    gateway=192.168.88.2 \
    comment="Route to Office Branch"

# بررسی
[admin@MikroTik] > /ip route print
# 2 A S  10.10.10.0/24              192.168.88.2  1

# حذف
[admin@MikroTik] > /ip route remove [find dst-address="10.10.10.0/24"]

# غیرفعال کردن (بدون حذف)
[admin@MikroTik] > /ip route disable [find dst-address="10.10.10.0/24"]

سه راه برای مشخص کردن Gateway:

  1. IP آدرس: gateway=192.168.88.2
  2. Interface: gateway=ether2 (فقط برای Point-to-Point)
  3. IP + Interface: gateway=192.168.88.2%ether2

۲.۶ Default Route (0.0.0.0/0)

Default Route مسیری است که اگر هیچ مسیر دیگری برای یک مقصد پیدا نشد، استفاده می‌شود. معمولاً به سمت ISP. 

# ===== روش ۱: Default Route دستی =====
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=203.0.113.1 \
    comment="Default Route to ISP"

# ===== روش ۲: خودکار با DHCP Client =====
[admin@MikroTik] > /ip dhcp-client add \
    interface=ether1 \
    disabled=no \
    add-default-route=yes \
    use-peer-dns=yes \
    use-peer-ntp=yes

# RouterOS خودکار Default Route را با Distance=1 اضافه می‌کند

# ===== روش ۳: با PPPoE Client =====
[admin@MikroTik] > /interface pppoe-client add \
    interface=ether1 \
    user=myuser \
    password=mypass \
    add-default-route=yes \
    use-peer-dns=yes \
    disabled=no

# ===== بررسی =====
[admin@MikroTik] > /ip route print where dst-address="0.0.0.0/0"
# 0 A S  0.0.0.0/0              203.0.113.1   1
# یا
# 0 ADS  0.0.0.0/0              203.0.113.1   1  ← D یعنی Dynamic (از DHCP)
💡 نکته
اگر می‌خواهی Default Route از DHCP نگیری، در DHCP Client add-default-route=no بگذار و خودت مسیر را تعریف کن.

۲.۷ Static Route با Distance (پشتیبان)

Distance در RouterOS معادل Administrative Distance است. عدد کمتر = اولویت بالاتر. اگر دو مسیر به یک مقصد داشته باشیم، مسیر با Distance کمتر در جدول Active می‌شود.

مقادیر پیش‌فرض Distance:

منبع Distance
Connected0
Static1
eBGP20
OSPF110
RIP120
iBGP200
 
# ===== دو ISP با اولویت =====
# ISP اصلی (Distance پیش‌فرض 1)
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=203.0.113.1 \
    distance=1 \
    comment="Primary ISP"

# ISP پشتیبان (Distance بالاتر — فقط در صورت قطع اولی)
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=198.51.100.1 \
    distance=10 \
    comment="Backup ISP"

# حالا اگر ISP اصلی قطع شود و Interface down شود،
# مسیر Backup به‌طور خودکار فعال می‌شود
⚠️ مهم
برای اینکه Backup Route واقعاً فعال شود، Interface مسیر اصلی باید Down شود. اگر لینک Up بماند ولی ترافیک رد نشود، باید Check Gateway فعال کنی.

۲.۸ Gateway — IP یا Interface؟

در RouterOS Gateway می‌تواند سه شکل داشته باشد:

# ===== ۱. IP Address =====
# استانداردترین روش — نیاز به Next Hop IP
[admin@MikroTik] > /ip route add \
    dst-address=10.10.10.0/24 \
    gateway=192.168.88.2

# ===== ۲. Interface =====
# فقط برای Interfaceهای Point-to-Point (مثل PPPoE، Tunnel، PtP Wireless)
[admin@MikroTik] > /ip route add \
    dst-address=10.10.10.0/24 \
    gateway=pppoe-out1

# ===== ۳. IP + Interface (Recommended) =====
# وقتی می‌خواهی صریحاً بگویی Next Hop از کدام Interface است
[admin@MikroTik] > /ip route add \
    dst-address=10.10.10.0/24 \
    gateway=192.168.88.2%ether2

# چرا این مهم است؟
# در سناریوهای Multi-Access، RouterOS بدون Interface نمی‌داند
# Next Hop از کدام Subnet است — با %interface مشخص می‌کنیم

۲.۹ Scope و Target-Scope

Scope و Target-Scope در RouterOS برای کنترل Recursive Routing و اعتبار مسیرها استفاده می‌شوند.

نوع Route Scope Target-Scope
Connected1010
Static3010
Default Static (0.0.0.0/0)3010
VPN/Route Marked3030
eBGP4040
OSPF11010

قانون طلایی: Next Hop یک مسیر فقط زمانی می‌تواند به عنوان Gateway استفاده شود که Target-Scope آن ≤ Scope مسیر فعلی باشد.

💡 مثال ساده
یک Static Route با Scope=30 نمی‌تواند به‌عنوان Gateway برای مسیر دیگری استفاده شود مگر Target-Scope آن مسیر دیگر ≤ 30 باشد. این قانون جلوی Loop در Recursive Routing را می‌گیرد.

۲.۱۰ Check Gateway (Ping/ARP)

Check Gateway یک ویژگی مهم است که RouterOS با آن به‌طور دوره‌ای وضعیت Gateway را بررسی می‌کند — حتی اگر Interface Up باشد.

دو حالت Check Gateway:

  • ping: ارسال ICMP Echo به Gateway — مناسب Gatewayهای IP
  • arp: بررسی ARP Table — سریع‌تر از ping ولی فقط برای L2
# ===== فعال‌سازی Check Gateway روی یک Route =====
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=203.0.113.1 \
    check-gateway=ping \
    comment="Primary ISP with health check"

# اگر Gateway به‌مدت ~10 ثانیه پاسخ ندهد، Route غیرفعال می‌شود

# ===== Cisco-like Tracking با Recursive Route =====
# یک Route به IP خاص با Check Gateway
[admin@MikroTik] > /ip route add \
    dst-address=8.8.8.8/32 \
    gateway=203.0.113.1 \
    scope=10 \
    target-scope=10 \
    check-gateway=ping \
    comment="Track ISP reachability"

# بعد Default Route با آن به‌عنوان Gateway
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=8.8.8.8 \
    distance=1

# حالا اگر 8.8.8.8 از طریق ISP1 قطع شود، Default Route هم غیرفعال می‌شود
🏆 نکته‌ی طلایی
در سناریوهای Dual-ISP، حتماً از Check Gateway + Recursive Route استفاده کن. بدون این، اگر لینک ISP Up باشد ولی ترافیک رد نکند، شبکه‌ات به‌هم می‌ریزد.

۲.۱۱ Route با چند Gateway (ECMP)

اگر دو مسیر با Distance یکسان به یک مقصد داشته باشیم، RouterOS هر دو را در جدول نگه می‌دارد و ترافیک را بین آن‌ها توزیع می‌کند (Equal Cost Multi-Path). 

# ===== ECMP با دو ISP =====
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=203.0.113.1 \
    distance=1 \
    check-gateway=ping

[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=198.51.100.1 \
    distance=1 \
    check-gateway=ping

# حالا RouterOS ترافیک را بین دو ISP توزیع می‌کند
# Load Balancing بر اساس Connection (5-tuple)

# بررسی
[admin@MikroTik] > /ip route print where dst-address="0.0.0.0/0"
# 0 A S  0.0.0.0/0   203.0.113.1   1
# 1 A S  0.0.0.0/0   198.51.100.1  1  ← هر دو Active

معایب ECMP خالص:

  • Sessionهای خاص (مثل بانکی) ممکن است قطع شوند چون IP مبدأ عوض می‌شود
  • Load Balancing بر اساس 5-tuple است — نه Source IP
  • برای Load Balancing بهتر، باید از Mangle + Route Mark استفاده کنی

۲.۱۲ Recursive Route

Recursive Route یعنی Next Hop یک مسیر، خودش از طریق یک مسیر دیگر قابل دسترس است. RouterOS خودکار این را حل می‌کند — ولی برای سناریوهای پیچیده، باید Scope را دستی تنظیم کنی. 

# ===== سناریو: Default Route از طریق Gateway که خودش از ISP دیگر میاد =====

# مسیر اول: به شبکه ISP1
[admin@MikroTik] > /ip route add \
    dst-address=203.0.113.0/24 \
    gateway=ether1 \
    scope=10 \
    target-scope=10 \
    comment="ISP1 Network"

# مسیر دوم: به IP خاص در ISP1
[admin@MikroTik] > /ip route add \
    dst-address=8.8.8.8/32 \
    gateway=203.0.113.1 \
    scope=10 \
    target-scope=10 \
    check-gateway=ping

# مسیر سوم: Default Route با Gateway IP خاص
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=8.8.8.8 \
    scope=30 \
    target-scope=10

# اگر 8.8.8.8 پاسخ نده، هر سه مسیر به‌ترتیب غیرفعال می‌شوند

۲.۱۳ Route Mark و Mangle

برای Load Balancing هوشمند بین چند ISP (مثلاً تقسیم ترافیک بر اساس Source IP یا نوع ترافیک)، از Mangle + Route Mark استفاده می‌کنیم. 

# ===== سناریو: PC1 از ISP1، PC2 از ISP2 =====

# گام ۱: تعریف Route Mark روی مسیرها
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=203.0.113.1 \
    routing-mark=ISP1 \
    comment="For PC1 via ISP1"

[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=198.51.100.1 \
    routing-mark=ISP2 \
    comment="For PC2 via ISP2"

# Default Route اصلی (اگر Mark نخورد)
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=203.0.113.1 \
    distance=2 \
    comment="Default fallback"

# گام ۲: Mangle برای Mark کردن ترافیک
[admin@MikroTik] > /ip firewall mangle add \
    chain=prerouting \
    src-address=192.168.88.10 \
    action=mark-routing \
    new-routing-mark=ISP1 \
    comment="PC1 → ISP1"

[admin@MikroTik] > /ip firewall mangle add \
    chain=prerouting \
    src-address=192.168.88.11 \
    action=mark-routing \
    new-routing-mark=ISP2 \
    comment="PC2 → ISP2"

# حالا PC1 از ISP1 و PC2 از ISP2 می‌رود
ℹ️ کاربردهای Route Mark
  • Load Balancing بر اساس Source IP
  • Force VoIP از یک ISP خاص
  • Policy-Based Routing (PBR)
  • جداسازی ترافیک مشتریان مختلف

۲.۱۴ عیب‌یابی مسیریابی

# ===== ابزارهای عیب‌یابی =====

# ۱. مشاهده جدول کامل مسیریابی
[admin@MikroTik] > /ip route print
[admin@MikroTik] > /ip route print detail
[admin@MikroTik] > /ip route print where active
[admin@MikroTik] > /ip route print where static
[admin@MikroTik] > /ip route print where dst-address="0.0.0.0/0"

# ۲. بررسی Active/Inactive
[admin@MikroTik] > /ip route print where !active
# مسیرهای غیرفعال را نشان می‌دهد

# ۳. Ping و Traceroute
[admin@MikroTik] > /ping 8.8.8.8
[admin@MikroTik] > /ping 8.8.8.8 count=5 interface=ether1
[admin@MikroTik] > /tool traceroute 8.8.8.8

# ۴. بررسی Interface و IP
[admin@MikroTik] > /ip address print
[admin@MikroTik] > /interface print

# ۵. ARP Table
[admin@MikroTik] > /ip arp print

# ۶. بررسی Firewall
[admin@MikroTik] > /ip firewall filter print
[admin@MikroTik] > /ip firewall nat print

# ۷. Torch — تحلیل ترافیک یک Interface
[admin@MikroTik] > /tool torch interface=ether1

# ۸. Packet Sniffer
[admin@MikroTik] > /tool sniffer quick interface=ether1
[admin@MikroTik] > /tool sniffer start

# ۹. IP Scan — کشف دستگاه‌های شبکه
[admin@MikroTik] > /tool ip-scan 192.168.88.0/24
[admin@MikroTik] > /tool ip-scan address-range=192.168.88.1-254

# ۱۰. بررسی Log
[admin@MikroTik] > /log print
[admin@MikroTik] > /log print where topics~"route"
💡 چک‌لیست عیب‌یابی
  1. Interface Up است؟ (/interface print)
  2. IP درست دارد؟ (/ip address print)
  3. Connected Route فعال است؟ (/ip route print where connected)
  4. Static Route تعریف شده؟ Active است؟
  5. Gateway قابل ping است؟ (/ping X.X.X.X)
  6. Firewall جلوی ترافیک را گرفته؟
  7. NAT درست پیکربندی شده؟

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
همیشه Gateway را با IP + Interface تعریف کن: gateway=192.168.1.1%ether2 — این کار جلوی خیلی از مشکلات مسیریابی در سناریوهای Multi-Access را می‌گیرد.
⚠️ هشدار
وقتی Connected Route خودکار ساخته می‌شود، Distance آن 0 است. هر Static Route با Distance=1 هم قبل از آن قرار نمی‌گیرد مگر مقصد متفاوت باشد. همیشه مراقب Overlapping Networks باش.
🏆 نکته‌ی طلایی
برای Failover خودکار بین دو ISP، از ترکیب Recursive Route + Check Gateway + Distance استفاده کن. این روش، مشکل «لینک Up است ولی ترافیک رد نمی‌شود» را حل می‌کند.
ℹ️ اطلاعات بیشتر
در فصل ۳ با Bridge و Switch در RouterOS آشنا می‌شوی.
🔮 دیدگاه پیشرفته
در MTCRE و MTCINE با OSPF، BGP و MPLS در RouterOS کار می‌کنی.

مثال ۱ — مسیریابی بین دو شبکه

# سناریو: روتر با دو Interface — هرکدام یک شبکه

[admin@MikroTik] > /ip address add address=192.168.1.1/24 interface=ether2
[admin@MikroTik] > /ip address add address=192.168.2.1/24 interface=ether3

# Connected Routes خودکار ساخته می‌شوند:
# 192.168.1.0/24 via ether2
# 192.168.2.0/24 via ether3

# حالا PC در شبکه 1 می‌تواند PC در شبکه 2 را Ping کند
# هیچ Static Route اضافی نیاز نیست!

# بررسی
[admin@MikroTik] > /ip route print where dst-address~"192.168"
# ADC  192.168.1.0/24  ether2  0
# ADC  192.168.2.0/24  ether3  0

مثال ۲ — Default Route از ISP + پشتیبان

# ===== ISP اصلی با Check Gateway =====
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=203.0.113.1 \
    distance=1 \
    check-gateway=ping \
    comment="Primary ISP - ping check"

# ===== ISP پشتیبان =====
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=198.51.100.1 \
    distance=5 \
    check-gateway=ping \
    comment="Backup ISP"

# حالا:
# - اگر ISP1 Up باشد → ترافیک از ISP1
# - اگر ISP1 Down شود → ISP2 در 10 ثانیه فعال می‌شود
# - وقتی ISP1 برگردد → دوباره ISP1 فعال می‌شود

مثال ۳ — Static Route به چند Branch

# ===== Header Office Network =====
[admin@MikroTik] > /ip address add address=192.168.88.1/24 interface=ether2

# ===== مسیرها به Branchهای مختلف =====
# Branch 1
[admin@MikroTik] > /ip route add \
    dst-address=10.10.10.0/24 \
    gateway=192.168.88.10 \
    comment="Branch Tehran"

# Branch 2
[admin@MikroTik] > /ip route add \
    dst-address=10.20.20.0/24 \
    gateway=192.168.88.20 \
    comment="Branch Isfahan"

# Branch 3
[admin@MikroTik] > /ip route add \
    dst-address=10.30.30.0/24 \
    gateway=192.168.88.30 \
    comment="Branch Shiraz"

# ===== بررسی وضعیت =====
[admin@MikroTik] > /ip route print detail where static

# حالا می‌توانی به هر Branch Ping بزنی
[admin@MikroTik] > /ping 10.10.10.1
[admin@MikroTik] > /tool traceroute 10.30.30.5

مثال ۴ — Load Balancing ECMP بین دو ISP

# ===== دو ISP با Distance یکسان =====
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=203.0.113.1 \
    distance=1 \
    check-gateway=ping

[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=198.51.100.1 \
    distance=1 \
    check-gateway=ping

# ===== NAT برای هر دو ISP =====
[admin@MikroTik] > /ip firewall nat add \
    chain=srcnat \
    out-interface=ether1 \
    action=masquerade

[admin@MikroTik] > /ip firewall nat add \
    chain=srcnat \
    out-interface=ether2 \
    action=masquerade

# ===== نتیجه: Load Balancing =====
# RouterOS ترافیک را بین دو ISP توزیع می‌کند (5-tuple hash)

# ===== بررسی =====
[admin@MikroTik] > /tool torch interface=ether1
[admin@MikroTik] > /tool torch interface=ether2

مثال ۵ — Route Mark برای Policy-Based Routing

# ===== سناریو: ترافیک VoIP از ISP-A، ترافیک Data از ISP-B =====

# گام ۱: Route Mark روی مسیرها
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=203.0.113.1 \
    routing-mark=VOIP \
    comment="VoIP via ISP-A"

[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=198.51.100.1 \
    routing-mark=DATA \
    comment="Data via ISP-B"

# گام ۲: Mangle برای Mark
# اول: Connection Mark
[admin@MikroTik] > /ip firewall mangle add \
    chain=prerouting \
    protocol=udp \
    dst-port=5060,10000-20000 \
    action=mark-connection \
    new-connection-mark=voip-conn \
    comment="Mark VoIP connections"

[admin@MikroTik] > /ip firewall mangle add \
    chain=prerouting \
    connection-mark=!voip-conn \
    action=mark-connection \
    new-connection-mark=data-conn \
    comment="Mark Data connections"

# دوم: Route Mark
[admin@MikroTik] > /ip firewall mangle add \
    chain=prerouting \
    connection-mark=voip-conn \
    action=mark-routing \
    new-routing-mark=VOIP

[admin@MikroTik] > /ip firewall mangle add \
    chain=prerouting \
    connection-mark=data-conn \
    action=mark-routing \
    new-routing-mark=DATA

# ===== نتیجه: VoIP از ISP-A، Data از ISP-B =====
[admin@MikroTik] > /ip firewall mangle print

🛠️ کارگاه عملی گام‌به‌گام

  1. در GNS3 یا EVE-NG سه RouterOS (CHR) بساز
  2. به هر RouterOS دو Interface بده
  3. R1 و R2 را با شبکه 10.0.0.0/30 به هم وصل کن
  4. R2 و R3 را با شبکه 10.0.1.0/30 به هم وصل کن
  5. به R1 یک LAN 192.168.1.0/24 بده
  6. به R3 یک LAN 192.168.3.0/24 بده
  7. روی R1 و R3 مسیرهای Static تعریف کن تا به هم دسترسی داشته باشند
  8. روی R1 یک Default Route بگذار به سمت R2
  9. از R1 به LAN پشت R3 Ping بزن
  10. روی R2 یک Loopback 8.8.8.8/32 اضافه کن
  11. از R1 مسیر 8.8.8.8/32 را با Check Gateway تعریف کن
  12. Default Route را از طریق 8.8.8.8 با Recursive Route تعریف کن
  13. یک Default Route پشتیبان با Distance بالاتر به R3 اضافه کن
  14. Interface R2 را Down کن و ببین Backup فعال می‌شود

🚫 خطاهای رایج و رفع‌اشکال

  • Route Active نمی‌شود: Gateway قابل دسترس نیست یا Interface Down است.
  • Ping به LAN دور نمی‌رسد: Static Route به Subnet مقصد نداری.
  • Failover بین ISPها کار نمی‌کند: Interface ISP Down نمی‌شود ولی ترافیک رد نمی‌شود — Check Gateway فعال کن.
  • ECMP ترافیک را نامتعادل تقسیم می‌کند: 5-tuple hash است — برای کنترل دقیق از Mangle استفاده کن.
  • بعد از Route Mark، ترافیک قطع می‌شود: مسیر Default بدون Mark نداری — یک مسیر Fallback بگذار.
  • Route Loop: دو مسیر با Scope/Target-Scope اشتباه — قانون Scope را رعایت کن.
  • Recursive Route کار نمی‌کند: Scope مسیر پایه باید کمتر از Target-Scope مسیر وابسته باشد.
  • بعد از تعریف Static Route، Connected Route حذف شد: اشتباه در Subnet Mask — Overlap را چک کن.
  • Gateway با %interface کار نمی‌کند: Interface اسم اشتباه یا Subnet Gateway اشتباه است.
  • Firewall جلوی ترافیک Routing را می‌گیرد: Filter Rule در Chain=Forward با Action=Drop.
  • Connection Mark برای همه ترافیک اعمال می‌شود: ترتیب Mangle Rules — اول VoIP، بعد Data.
  • بعد از تغییر Distance، Route قطع شد: Distance را یادت رفته که نسبت به Backup کمتر بگذاری.

🎯 پروژه‌ی پایانی فصل

یک شبکه‌ی سازمانی کوچک با دو ISP و Branchهای مختلف بساز:

  • دفتر مرکزی: یک RouterOS با LAN 192.168.10.0/24
  • دو ISP: ISP-A با Distance=1 و ISP-B با Distance=5
  • دو Branch: شعب در شبکه‌های 10.10.10.0/24 و 10.20.20.0/24
  • Static Route: برای دسترسی به هر Branch
  • Default Route: به ISP-A با Check Gateway=ping
  • Backup Route: به ISP-B با Distance بالاتر
  • Recursive Route: Default Route از طریق یک IP خاص در ISP-A
  • NAT Masquerade: برای هر دو ISP
  • Route Mark: ترافیک VoIP از ISP-A و Data از ISP-B
  • Test: با Down کردن Interface ISP-A، Failover به ISP-B
  • مستندسازی کامل با Export و دیاگرام
🏆 چالش اضافه
  • با Mangle، ترافیک کاربران VIP را از ISP-A و بقیه را از ISP-B بفرست.
  • با Netwatch، اگر Branch 1 قطع شد، یک Email هشدار بفرست.
  • ECMP بین دو ISP را پیاده کن و با Torch تحلیل کن.
  • یک Blackhole Route برای یک IP خاص تعریف کن و تست کن.

📋 جمع‌بندی و برگه‌تقب

  • Connected Route: خودکار با دادن IP، Distance=0
  • Static Route: دستی، Distance پیش‌فرض = 1
  • Default Route: dst-address=0.0.0.0/0
  • Flags: A=Active، S=Static، C=Connect، D=Dynamic، X=Disabled
  • Route Flags پروتکل: r=RIP، o=OSPF، b=BGP، B=Blackhole، U=Unreachable
  • Distance: کمتر = اولویت بالاتر — برای Failover استفاده کن
  • Gateway: IP یا Interface یا IP%Interface
  • Check Gateway: ping یا arp — برای Failover هوشمند
  • Recursive Route: Route از طریق IP که خودش از Route دیگر میاد
  • Scope/Target-Scope: کنترل Recursive Routing
  • ECMP: دو Route با Distance یکسان → Load Balancing
  • Route Mark: Policy-Based Routing با Mangle
  • عیب‌یابی: /ping، /tool traceroute، /tool torch، /tool sniffer
