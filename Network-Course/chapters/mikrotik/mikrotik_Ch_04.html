۴.۱ استانداردهای 802.11

Wireless استانداردهای مختلفی دارد که هرکدام سرعت، فرکانس و ویژگی‌های متفاوتی دارند:

استاندارد باند حداکثر سرعت توضیح
802.11a5GHz54 Mbpsقدیمی، OFDM
802.11b2.4GHz11 Mbpsقدیمی، DSSS
802.11g2.4GHz54 Mbpsسازگار با b
802.11n2.4/5GHz600 MbpsMIMO، HT
802.11ac5GHz6.9 GbpsVHT، MU-MIMO
802.11ax2.4/5/6GHz9.6 GbpsWi-Fi 6، OFDMA
💡 نکته
وقتی می‌خواهی Wireless بپیکربندی کنی، همیشه سعی کن بالاترین استاندارد مشترک بین دو طرف را انتخاب کنی — مثلاً اگر AP از 802.11ac پشتیبانی می‌کند و Client هم، از 802.11ac استفاده کن نه a/n.

۴.۴ پارامترهای RF — Power، Gain، SNR، RSSI

درک این پارامترها برای طراحی Wireless ضروری است:

  • TX Power: توان ارسال (dBm یا mW)
  • Antenna Gain: بهره‌ی آنتن (dBi)
  • EIRP: Effective Isotropic Radiated Power = TX Power + Gain - Cable Loss
  • RSSI: Received Signal Strength Indicator (dBm)
  • SNR: Signal-to-Noise Ratio = Signal - Noise (dB)
  • Noise Floor: سطح نویز محیط (dBm)
کیفیت سیگنال RSSI SNR کیفیت

خوب-50 تا -6025-40✅

۴.۶ پیکربندی Access Point (ap-bridge)

# ===== پیکربندی کامل Access Point =====

# ۱. تنظیم Security Profile
[admin@AP] > /interface wireless security-profiles add \
    name=secure-wpa2 \
    mode=dynamic-keys \
    authentication-types=wpa2-psk \
    wpa2-pre-shared-key=StrongWPA2Pass@2024

# ۲. تنظیم Wireless Interface
[admin@AP] > /interface wireless set wlan1 \
    mode=ap-bridge \
    ssid=MyOffice-WiFi \
    band=2ghz-b/g/n \
    channel-width=20mhz \
    frequency=2437 \
    country=iran \
    installation=indoor \
    security-profile=secure-wpa2 \
    disabled=no

# ۳. اتصال به Bridge
[admin@AP] > /interface bridge port add bridge=bridge1 interface=wlan1

# ۴. بررسی
[admin@AP] > /interface wireless monitor wlan1
[admin@AP] > /interface wireless registration-table print

# ===== SSID مخفی =====
[admin@AP] > /interface wireless set wlan1 hide-ssid=yes
# Client باید SSID را دستی وارد کند

# ===== تنظیم Country =====
[admin@AP] > /interface wireless set wlan1 country=iran
# این تنظیم، فرکانس‌ها و توان مجاز را بر اساس قوانین ایران محدود می‌کند

۴.۸ Station-Bridge برای Wireless Bridge

برای اتصال دو شبکه‌ی LAN از طریق Wireless (مثل کابل به‌جای Wireless)، از station-bridge استفاده می‌کنیم — که MAC تمام دستگاه‌های پشت Client را نیز منتقل می‌کند. 

# ===== سناریو: Bridge بین دو ساختمان =====

# ===== AP (Master) =====
[admin@AP-Master] > /interface wireless set wlan1 \
    mode=ap-bridge \
    ssid=BuildingLink \
    band=5ghz-a/n/ac \
    frequency=5500 \
    channel-width=20/40/80mhz-Ceee \
    security-profile=link-secure \
    disabled=no

[admin@AP-Master] > /interface bridge add name=br-link protocol-mode=none
[admin@AP-Master] > /interface bridge port add bridge=br-link interface=wlan1
[admin@AP-Master] > /interface bridge port add bridge=br-link interface=ether1
[admin@AP-Master] > /ip address add address=10.0.0.1/30 interface=br-link

# ===== Station-Bridge (Client) =====
[admin@AP-Client] > /interface wireless set wlan1 \
    mode=station-bridge \
    ssid=BuildingLink \
    band=5ghz-a/n/ac \
    frequency=5500 \
    security-profile=link-secure \
    disabled=no

[admin@AP-Client] > /interface bridge add name=br-link protocol-mode=none
[admin@AP-Client] > /interface bridge port add bridge=br-link interface=wlan1
[admin@AP-Client] > /interface bridge port add bridge=br-link interface=ether1
[admin@AP-Client] > /ip address add address=10.0.0.2/30 interface=br-link

# ===== نتیجه: هر دو LAN کاملاً پل شده‌اند =====
# هر PC پشت AP-Master می‌تواند با هر PC پشت AP-Client در L2 حرف بزند

# ===== بررسی =====
[admin@AP-Master] > /interface wireless registration-table print
[admin@AP-Master] > /interface bridge host print
⚠️ هشدار
station-bridge فقط با APهای MikroTik کار می‌کند (WDS اختصاصی). برای APهای غیر MikroTik، از station-pseudobridge یا station-pseudobridge-clone استفاده کن.

# ===== WPA2/WPA3 Mixed =====
[admin@AP] > /interface wireless security-profiles set wpa3-secure \
    authentication-types=wpa2-psk,wpa3-psk

۴.۱۰ MAC Filtering با Access List

Access List کنترل می‌کند کدام MAC Addressها اجازه اتصال دارند. 

# ===== حالت‌های Access List =====
# - allow: فقط MACهای لیست اجازه دارند (Whitelist)
# - deny: فقط MACهای لیست ممنوع هستند (Blacklist)

# ===== سناریو: فقط ۳ دستگاه اجازه اتصال =====
# گام ۱: Default را Deny کن
[admin@AP] > /interface wireless access-list add \
    interface=wlan1 \
    mac-address=00:00:00:00:00:00 \
    authentication=no \
    forwarding=no \
    comment="Default deny"

# گام ۲: MACهای مجاز
[admin@AP] > /interface wireless access-list add \
    interface=wlan1 \
    mac-address=AA:BB:CC:DD:EE:01 \
    authentication=yes \
    forwarding=yes \
    comment="Manager Laptop"

[admin@AP] > /interface wireless access-list add \
    interface=wlan1 \
    mac-address=AA:BB:CC:DD:EE:02 \
    authentication=yes \
    forwarding=yes \
    comment="Reception PC"

[admin@AP] > /interface wireless access-list add \
    interface=wlan1 \
    mac-address=AA:BB:CC:DD:EE:03 \
    authentication=yes \
    forwarding=yes \
    comment="Guest Phone"

# ===== بررسی =====
[admin@AP] > /interface wireless access-list print
# خروجی: لیست MACها و وضعیت Allow/Deny

# ===== نکته: ترتیب Rules مهم است =====
# Rules از بالا به پایین چک می‌شوند
# اولین Match اعمال می‌شود
⚠️ محدودیت MAC Filtering
MAC Filtering به‌تنهایی امن نیست — یک مهاجم می‌تواند MAC خود را جعل کند. همیشه با WPA2 ترکیب کن.

۴.۱۱ Connect List — کنترل Client

Connect List از دید Client استفاده می‌شود — کنترل می‌کند Client به کدام APها وصل شود (برعکس Access List).

ویژگی Access List Connect List
رویAPClient
کنترل می‌کندورود Clientاتصال Client به AP
معیارMAC ClientMAC/SSID AP
 
# ===== Client فقط به یک AP خاص وصل شود =====
[admin@Client] > /interface wireless connect-list add \
    interface=wlan1 \
    ssid=MyOffice-WiFi \
    mac-address=AA:BB:CC:DD:EE:FF \
    connect=yes \
    area-prefix=""

# ===== Client فقط به SSID خاص وصل شود =====
[admin@Client] > /interface wireless connect-list add \
    interface=wlan1 \
    ssid=MyOffice-WiFi \
    connect=yes \
    security-profile=client-secure

# ===== Default Deny + Whitelist =====
# گام ۱: Deny all
[admin@Client] > /interface wireless connect-list add \
    interface=wlan1 \
    connect=no \
    comment="Default deny"

# گام ۲: فقط SSID ما
[admin@Client] > /interface wireless connect-list add \
    interface=wlan1 \
    ssid=MyOffice-WiFi \
    connect=yes

# ===== بررسی =====
[admin@Client] > /interface wireless connect-list print

۴.۱۲ NV2 Protocol — مزایا و پیکربندی

NV2 یک پروتکل اختصاصی MikroTik است که روی لایه ۲ کار می‌کند و برای لینک‌های Point-to-Point و Point-to-Multipoint طراحی شده.

مزایای NV2 نسبت به 802.11:

  • TDMA: Time Division Multiple Access — بدون Collision
  • Performance: تا ۲ برابر سرعت بیشتر
  • Latency: تأخیر کمتر و پایدارتر
  • Scalability: پشتیبانی از تعداد Client بیشتر
  • Hidden Node: مشکل گره مخفی حل می‌شود
# ===== پیکربندی NV2 روی AP =====
[admin@AP] > /interface wireless set wlan1 \
    wireless-protocol=nv2 \
    nv2-security=enabled \
    nv2-preshared-key=NV2Secret@2024 \
    nv2-cell-radius=30 \
    mode=ap-bridge \
    ssid=NV2-Link

# ===== روی Client =====
[admin@Client] > /interface wireless set wlan1 \
    wireless-protocol=nv2 \
    nv2-security=enabled \
    nv2-preshared-key=NV2Secret@2024 \
    mode=station-bridge \
    ssid=NV2-Link

# ===== بررسی =====
[admin@AP] > /interface wireless monitor wlan1
# ببین: wireless-protocol: nv2

[admin@AP] > /interface wireless registration-table print
# Client با protocol=nv2 ثبت شده

# ===== تنظیمات پیشرفته NV2 =====
[admin@AP] > /interface wireless set wlan1 \
    nv2-qos=default \
    nv2-cell-radius=30 \
    nv2-security=enabled \
    nv2-preshared-key=NV2Secret

# nv2-qos:
# default  → برای ترافیک معمولی
# frame-priority → برای شبکه‌های با VoIP (احترام به QoS)

# nv2-cell-radius:
# شعاع سلول (ثانیه‌ای که برای Clientهای دور در نظر می‌گیرد)
# 10 → 10km، 30 → 30km، 60 → 60km
🏆 نکته‌ی طلایی
برای لینک‌های Point-to-Point طولانی (بیش از ۵ کیلومتر)، حتماً از NV2 استفاده کن. TDMA مشکل Hidden Node و Collision را حل می‌کند و Performance واقعی را بالا می‌برد.

۴.۱۳ Nstreme Protocol

Nstreme نسل قبلی NV2 است — هنوز در بعضی سناریوها استفاده می‌شود ولی NV2 توصیه می‌شود. 

# ===== فعال‌سازی Nstreme =====
[admin@AP] > /interface wireless set wlan1 \
    wireless-protocol=nstreme \
    nstreme=enabled

# پارامترهای Nstreme:
# - nstreme-dual-slave: برای لینک Dual-Pol
# - nstreme-framer-limit: اندازه فریم
# - nstreme-optimize-ack: بهینه‌سازی ACK

# ===== مقایسه =====
# NV2:
# - جدیدتر، سریع‌تر
# - Latency کمتر
# - فقط MikroTik ↔ MikroTik
#
# Nstreme:
# - قدیمی، سازگارتر
# - در برخی مدل‌های قدیمی بهتر
# - Latency بیشتر

# ===== Auto (پیش‌فرض) =====
[admin@AP] > /interface wireless set wlan1 wireless-protocol=unspecified
# خودش تشخیص می‌دهد

۴.۱۴ Country Regulation

هر کشور مقرراتی برای استفاده از فرکانس‌های Wireless دارد. Country تنظیم می‌کند RouterOS در چه فرکانس‌ها و توان‌هایی می‌تواند کار کند. 

# ===== تنظیم Country =====
[admin@AP] > /interface wireless set wlan1 country=iran

# حالا RouterOS:
# - فرکانس‌های مجاز ایران را فعال می‌کند
# - توان ارسال را به حداکثر قانونی محدود می‌کند
# - کانال‌های مجاز را محدود می‌کند

# ===== بررسی فرکانس‌های مجاز =====
[admin@AP] > /interface wireless info country-info iran
# خروجی: لیست فرکانس‌ها و توان‌های مجاز

# ===== Installation Mode =====
[admin@AP] > /interface wireless set wlan1 installation=outdoor
# outdoor → توان بالاتر برای لینک‌های طولانی

# یا
[admin@AP] > /interface wireless set wlan1 installation=indoor
# indoor → توان کمتر، برای APهای داخل

# ===== تنظیم توان دستی =====
[admin@AP] > /interface wireless set wlan1 tx-power-mode=all-rates-fixed tx-power=20
# tx-power-mode:
# default               → خودکار
# all-rates-fixed       → همه Rateها توان یکسان
# all-rates-unspecified → همه Rateها توان پیش‌فرض
# card-rates            → کارت تصمیم می‌گیرد

# ===== مشاهده‌ی تنظیمات =====
[admin@AP] > /interface wireless print detail
[admin@AP] > /interface wireless info country-info
⚠️ هشدار قانونی

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
در باند 2.4GHz، همیشه از کانال‌های 1، 6 یا 11 استفاده کن. بقیه کانال‌ها با هم همپوشانی دارند و تداخل ایجاد می‌کنند.
⚠️ هشدار امنیتی
هرگز از WEP یا Open استفاده نکن. حتی WPA/TKIP قدیمی است. حداقل WPA2-PSK با AES و ایده‌آل WPA3.
🏆 نکته‌ی طلایی
برای لینک‌های Point-to-Point طولانی (بیش از ۵ کیلومتر)، همیشه از NV2 استفاده کن — TDMA مزیت بزرگی در Latency و Performance دارد.
ℹ️ اطلاعات بیشتر
در فصل ۵ با DHCP Server، DHCP Relay، ARP Modes و Netwatch آشنا می‌شوی.
🔮 دیدگاه پیشرفته
در MTCWE با WDS، Nstreme Dual و CAPsMAN (مدیریت متمرکز APها) کار می‌کنی.

# Guest فقط به اینترنت
# Staff به منابع داخلی

[admin@AP] > /ip firewall filter add \

    comment="Block Guest → Staff"

🛠️ کارگاه عملی گام‌به‌گام

  1. دو RouterOS با Wireless (یا یک روتر + یک Client سیمی)
  2. روی RouterOS اول: Wireless را به ap-bridge تبدیل کن
  3. SSID و Country (iran) را تنظیم کن
  4. Security Profile با WPA2-PSK بساز و اعمال کن
  5. Wireless را به Bridge اضافه کن
  6. روی RouterOS دوم: Wireless را به station-bridge تبدیل کن
  7. به همان SSID و Security وصل شو
  8. هر دو را با یک شبکه IP تنظیم کن
  9. از یک PC در یک سمت به PC در سمت دیگر Ping بزن
  10. Registration Table را در AP بررسی کن
  11. Signal Strength و CCQ را مشاهده کن
  12. NV2 را فعال کن و Performance را مقایسه کن
  13. Access List برای محدودسازی MAC یک Client اضافه کن
  14. با Wireless Scan، کانال‌های اشغال اطراف را ببین
  15. کانال را به یک کانال خلوت تغییر بده
  16. عیب‌یابی: با Sniffer ترافیک Wireless را تحلیل کن

🚫 خطاهای رایج و رفع‌اشکال

  • Client وصل نمی‌شود: Security Profile مطابق نیست، Frequency/Band متفاوت، یا MAC در Access List نیست.
  • Signal ضعیف: آنتن اشتباه، جهت اشتباه، مانع فیزیکی، یا فرکانس نامناسب.
  • CCQ پایین (زیر 50%): تداخل، Hidden Node، یا NV2 فعال نیست.
  • Throughput پایین: Channel Width کم، Rate محدود، یا CCQ پایین.
  • Latency بالا: NV2 فعال نیست، کانال شلوغ، یا Client دور.
  • AP Country ندارد: بدون Country، بعضی فرکانس‌ها کار نمی‌کنند — حتماً تنظیم کن.
  • 2.4GHz خیلی شلوغ: از 5GHz استفاده کن یا کانال 1/6/11 را با Scan انتخاب کن.
  • station-bridge با AP غیر MikroTik: استفاده کن از station-pseudobridge یا station معمولی.
  • MAC Filtering کار نمی‌کند: Rule Default Deny اولین Rule نباشد، یا ترتیب اشتباه.
  • Hidden SSID پیدا نمی‌شود: در Client دستی SSID را وارد کن، چون Scan نشان نمی‌دهد.
  • بعد از آپدیت، Wireless کار نمی‌کند: Country را مجدد تنظیم کن یا Firmware را بررسی کن.
  • Clientهای زیاد کند می‌شوند: ظرفیت Radio محدود است — به چند AP با CAPsMAN مهاجرت کن.
  • Virtual AP کار نمی‌کند: master-interface باید ap-bridge باشد (نه station).
  • NV2 فقط با MikroTik: برای Clientهای عمومی، 802.11 استفاده کن.
  • Snooper کند می‌شود: فقط در لحظه نیاز، فعال کن و بعد خاموش کن.

🎯 پروژه‌ی پایانی فصل

یک شبکه‌ی Wireless کامل بساز:

  • سخت‌افزار: دو RouterOS با Wireless (یک AP، یک Client)
  • SSID و Country: نام مناسب + country=iran
  • Security: WPA2-PSK با پسورد قوی
  • Mode: AP به ap-bridge، Client به station-bridge
  • Bridge: Wireless + Ethernet در Bridge
  • IP: هر طرف در یک Subnet جداگانه
  • NV2: فعال روی هر دو طرف
  • Access List: MAC Client را Whitelist کن
  • Hidden SSID: فعال کن (اختیاری)
  • Monitor: Registration Table، Signal، CCQ را بررسی کن
  • عیب‌یابی: با Sniffer یک Capture بگیر
  • مستندسازی کامل با دیاگرام، تنظیمات و Script
🏆 چالش اضافه
  • با CAPsMAN، مدیریت متمرکز ۲ AP را راه‌اندازی کن.
  • یک Virtual AP روی همان Radio بساز برای Guest Network.
  • با Spectral Scan (در صورت پشتیبانی)، کانال‌های شلوغ را تحلیل کن.
  • با Wireless Sniffer ترافیک را Capture و در Wireshark تحلیل کن.

📋 جمع‌بندی و برگه‌تقب

  • استانداردها: 802.11a/b/g/n/ac/ax
  • 2.4GHz: برد بیشتر، تداخل بیشتر، فقط ۳ کانال غیرهمپوشان (1،6،11)
  • 5GHz: سرعت بیشتر، تداخل کمتر، کانال‌های بیشتر
  • حالت‌ها: ap-bridge، station، station-bridge، station-pseudobridge
  • Security: حداقل WPA2-PSK، ایده‌آل WPA3 یا WPA2-EAP
  • NV2: TDMA، فقط MikroTik↔MikroTik، سریع‌تر و پایدارتر
  • Access List: روی AP — کنترل ورود Client
  • Connect List: روی Client — کنترل اتصال به AP
  • Country: همیشه iran — تنظیم فرکانس و توان مجاز
  • Installation: indoor یا outdoor — تأثیر روی توان
  • Signal: بیش از -60dBm خوب، کمتر از -75dBm ضعیف
  • CCQ: بیش از 80% خوب، کمتر از 50% مشکل
  • Virtual AP: master-interface باید ap-bridge باشد
  • Scan: برای کشف SSIDهای اطراف
  • Snooper: برای تحلیل ترافیک Wireless اطراف
