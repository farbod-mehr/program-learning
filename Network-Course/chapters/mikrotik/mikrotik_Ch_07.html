📘 بدنه‌ی آموزشی

۷.۱ مفاهیم پایه QoS

QoS (Quality of Service) مجموعه‌ای از تکنیک‌هاست که ترافیک شبکه را در شرایط کمبود پهنای باند مدیریت می‌کند.

چرا QoS لازم است؟

  • کمبود پهنای باند: پهنای باند اینترنت محدود است
  • ترافیک‌های حساس: VoIP، Gaming، Video Conference نیاز به Latency کم دارند
  • عدالت: یک کاربر نباید تمام پهنای باند را بخورد
  • کنترل هزینه: کاهش نیاز به افزایش پهنای باند
  • تجربه‌ی کاربری: مرور وب روان‌تر، تماس VoIP با کیفیت بالاتر

سه عنصر اصلی QoS:

  • Classification: شناسایی و دسته‌بندی ترافیک (با Mangle)
  • Marking: علامت‌گذاری بسته‌ها (با Mangle)
  • Queuing: صف‌بندی و ارسال بر اساس اولویت (با Queue)
💡 نکته
QoS در RouterOS فقط روی ترافیک خروجی اعمال می‌شود — چون فقط روی Interface خروجی می‌توان ترافیک را کنترل کرد. برای کنترل ورودی، از Queue Tree + Global استفاده کن.

۷.۳ Simple Queue — ساده و سریع

# ===== محدود کردن یک IP ساده =====
[admin@MikroTik] > /queue simple add \
    name=limit-user1 \
    target=192.168.88.10/32 \
    max-limit=5M/10M \
    comment="User1: 5M Up, 10M Down"

# max-limit فرمت: upload/download
# 5M/10M = 5Mbps آپلود، 10Mbps دانلود

# ===== محدود کردن یک Subnet =====
[admin@MikroTik] > /queue simple add \
    name=limit-lan \
    target=192.168.88.0/24 \
    max-limit=50M/100M \
    comment="LAN: 50M Up, 100M Down"

# ===== محدود کردن ترافیک از یک Interface =====
[admin@MikroTik] > /queue simple add \
    name=limit-wan \
    target=ether1 \
    max-limit=100M/100M

# ===== مشاهده وضعیت =====
[admin@MikroTik] > /queue simple print
[admin@MikroTik] > /queue simple print stats
# ستون‌ها:
# rate: نرخ فعلی (up/down)
# packet-rate: نرخ بسته
# queued-bytes: بسته‌های در صف
# dropped: بسته‌های Drop شده
# total-rate: نرخ کل
# total-bytes: بایت کل

۷.۴ Simple Queue با Target و Limit

# ===== Target — چه چیزی محدود شود =====

# ۱. یک IP
target=192.168.88.10/32

# ۲. یک Subnet
target=192.168.88.0/24

# ۳. Range
target=192.168.88.10-192.168.88.20

# ۴. Interface
target=ether1

# ۵. ترکیبی (دو طرف)
target=192.168.88.10/32,ether1

# ===== فرمت max-limit =====

# max-limit=UPLOAD/DOWNLOAD

# نمونه‌ها:
max-limit=1M/2M         # 1Mbps آپلود، 2Mbps دانلود
max-limit=512k/2M       # 512kbps آپلود، 2Mbps دانلود
max-limit=10M/10M       # 10Mbps هر دو جهت

# واحدها:
# k = Kilobit (1000 bit)
# M = Megabit (1,000,000 bit)
# G = Gigabit

# ===== Limit-at (حداقل تضمینی) =====
[admin@MikroTik] > /queue simple add \
    name=guaranteed \
    target=192.168.88.0/24 \
    max-limit=100M/100M \
    limit-at=10M/10M
# limit-at: حداقل پهنای باند تضمینی
# max-limit: حداکثر پهنای باند مجاز

# ===== Priority =====
[admin@MikroTik] > /queue simple set [find name=limit-user1] priority=1/1
# priority: 1 (بالاترین) تا 8 (پایین‌ترین)
# فرمت: upload/download

# ===== Queue Type =====
[admin@MikroTik] > /queue simple set [find name=limit-user1] queue=default/default
# انواع: default، ethernet-default، wireless-default، pcq-upload-default، pcq-download-default

۷.۵ Simple Queue با Burst

Burst یعنی اجازه دادن به کاربر که به‌طور موقت بیش از حد مجاز پهنای باند بگیرد — به شرط آنکه میانگین مصرف زیر حد تعیین‌شده باشد. 

# ===== پیکربندی Burst =====
[admin@MikroTik] > /queue simple add \
    name=burst-user \
    target=192.168.88.10/32 \
    max-limit=5M/10M \
    burst-limit=10M/20M \
    burst-threshold=3M/5M \
    burst-time=10s/10s

# توضیح:
# max-limit: پهنای باند عادی (5M/10M)
# burst-limit: پهنای باند Burst (10M/20M)
# burst-threshold: آستانه برای فعال شدن Burst (3M/5M)
# burst-time: بازه‌ی میانگین (10s)

# ===== نحوه‌ی کار =====
# 1. کاربر شروع به دانلود می‌کند
# 2. اگر میانگین مصرف زیر burst-threshold باشد → burst-limit اعمال می‌شود
# 3. اگر میانگین بالای threshold برود → به max-limit برمی‌گردد

# ===== مثال کاربردی =====
# کاربر عادی: 5M/10M
# Burst در هنگام بارگذاری سریع: 10M/20M
# اگر مداوم دانلود کند: به 5M/10M برمی‌گردد

# ===== نکته =====
# Burst برای تجربه‌ی بهتر کاربر است — صفحه‌ها سریع‌تر باز می‌شوند
# ولی اگر همیشه در حالت Burst باشد، عملاً بی‌فایده است

# ===== غیرفعال کردن Burst =====
[admin@MikroTik] > /queue simple set [find name=burst-user] burst-limit=0/0
💡 نکته
Burst را برای وایبر، اینستاگرام، مرور وب فعال کن — تجربه‌ی کاربر خیلی بهتر می‌شود. برای دانلود مداوم و P2P غیرفعال کن.

۷.۶ Queue Types — FQ_Codel، RED، SFQ، HTB

RouterOS چند نوع الگوریتم صف‌بندی دارد. هرکدام رفتار متفاوتی در شرایط ازدحام دارند.

نوع توضیح کاربرد
default صف پایه FIFO عمومی
ethernet-default مشابه default با تنظیمات Ethernet Interfaceهای Ethernet
pcq-upload-default PCQ آماده برای Upload توزیع عادلانه
pcq-download-default PCQ آماده برای Download توزیع عادلانه
fq-codel Fair Queue CoDel — مدرن، Latency پایین VoIP، Gaming
sfq Stochastic Fair Queue توزیع عادلانه قدیمی
red Random Early Detection جلوگیری از ازدحام
codel Controlled Delay Latency پایین 
# ===== مشاهده Queue Types موجود =====
[admin@MikroTik] > /queue type print

# ===== ساخت Queue Type سفارشی =====
[admin@MikroTik] > /queue type add \
    name=my-pcq-upload \
    kind=pcq \
    pcq-rate=0 \
    pcq-limit=50 \
    pcq-classifier=src-address \
    pcq-total-limit=2000

[admin@MikroTik] > /queue type add \
    name=my-pcq-download \
    kind=pcq \
    pcq-rate=0 \
    pcq-limit=50 \
    pcq-classifier=dst-address \
    pcq-total-limit=2000

# پارامترهای PCQ:
# pcq-rate          → نرخ برای هر کاربر (0 = خودکار)
# pcq-limit         → حداکثر بسته در صف هر کاربر
# pcq-classifier    → معیار تفکیک کاربران
# pcq-total-limit   → حداکثر بسته در صف کل

# ===== FQ_Codel =====
[admin@MikroTik] > /queue type add \
    name=fq-codel-voip \
    kind=fq-codel \
    fq-codel-limit=10240 \
    fq-codel-interval=100ms

۷.۷ PCQ — Per Connection Queue

PCQ یکی از مفیدترین ویژگی‌های RouterOS است — پهنای باند را به‌طور عادلانه بین کاربران تقسیم می‌کند.

چطور کار می‌کند؟

  • RouterOS ترافیک را بر اساس pcq-classifier تفکیک می‌کند
  • برای هر گروه یک صف جداگانه می‌سازد
  • پهنای باند را به‌طور مساوی تقسیم می‌کند

pcq-classifier:

  • src-address: برای Upload — هر IP یک صف
  • dst-address: برای Download — هر IP یک صف
  • src-address,dst-address: ترکیبی
# ===== سناریو: 100 کاربر، 100Mbps اینترنت =====
# هر کاربر باید 1Mbps بگیرد — ولی اگر بقیه بیکار باشند، بیشتر بگیرد

# ۱. ساخت Queue Type برای Upload
[admin@MikroTik] > /queue type add \
    name=pcq-up \
    kind=pcq \
    pcq-rate=0 \
    pcq-limit=50 \
    pcq-classifier=src-address \
    pcq-total-limit=5000

# ۲. برای Download
[admin@MikroTik] > /queue type add \
    name=pcq-down \
    kind=pcq \
    pcq-rate=0 \
    pcq-limit=50 \
    pcq-classifier=dst-address \
    pcq-total-limit=5000

# ۳. اعمال در Simple Queue
[admin@MikroTik] > /queue simple add \
    name=LAN-PCQ \
    target=192.168.88.0/24 \
    max-limit=100M/100M \
    queue=pcq-up/pcq-down \
    comment="PCQ for LAN"

# ===== نتیجه =====
# - اگر 1 کاربر آنلاین: 100Mbps می‌گیرد
# - اگر 10 کاربر: هرکدام 10Mbps
# - اگر 100 کاربر: هرکدام 1Mbps
# - توزیع کاملاً عادلانه!

# ===== محدود کردن هر کاربر به حداکثر X =====
[admin@MikroTik] > /queue type set pcq-up pcq-rate=10M
[admin@MikroTik] > /queue type set pcq-down pcq-rate=20M
# حالا هر کاربر حداکثر 10Mbps آپلود و 20Mbps دانلود
# ولی اگر تنها باشد، حداکثر 10/20 می‌گیرد (نه بیشتر)
🏆 نکته‌ی طلایی
PCQ بهترین روش برای توزیع عادلانه پهنای باند بین صدها کاربر است — بدون نیاز به Queue جداگانه برای هر کاربر. این ویژگی MikroTik را از سایر روترها متمایز می‌کند.

۷.۸ Queue Tree — پیکربندی درختی

Queue Tree یک صف سلسله‌مراتبی است که از Mangle استفاده می‌کند و انعطاف بسیار بالاتری نسبت به Simple Queue دارد.

مفاهیم اصلی:

  • Parent: والد صف — Interface یا Global
  • Packet Mark: علامت بسته از Mangle
  • Global: برای کل روتر — نیازمند HTB در Mangle
# ===== پیکربندی Queue Tree =====

# گام ۱: Mark کردن ترافیک با Mangle
[admin@MikroTik] > /ip firewall mangle add \
    chain=postrouting \
    out-interface=ether1 \
    action=mark-packet \
    new-packet-mark=upload-all \
    passthrough=no \
    comment="Mark all upload"

[admin@MikroTik] > /ip firewall mangle add \
    chain=prerouting \
    in-interface=ether1 \
    action=mark-packet \
    new-packet-mark=download-all \
    passthrough=no \
    comment="Mark all download"

# گام ۲: Queue Tree
[admin@MikroTik] > /queue tree add \
    name=upload \
    parent=ether1 \
    max-limit=50M \
    packet-mark=upload-all \
    comment="Upload Queue"

[admin@MikroTik] > /queue tree add \
    name=download \
    parent=global \
    max-limit=100M \
    packet-mark=download-all \
    comment="Download Queue"

# ===== مشاهده =====
[admin@MikroTik] > /queue tree print
[admin@MikroTik] > /queue tree print stats

۷.۹ Mangle — Mark کردن ترافیک

Mangle ابزار اصلی برای علامت‌گذاری بسته‌هاست — پیش‌نیاز Queue Tree و بسیاری از سناریوهای QoS.

Chains در Mangle:

  • prerouting: قبل از تصمیم Routing — برای Download
  • postrouting: بعد از تصمیم Routing — برای Upload
  • forward: برای ترافیک عبوری
  • input/output: برای ترافیک خود روتر
# ===== Mark کردن ساده =====

# ۱. Mark تمام Upload
[admin@MikroTik] > /ip firewall mangle add \
    chain=postrouting \
    out-interface=ether1 \
    action=mark-packet \
    new-packet-mark=all-upload \
    passthrough=no

# ۲. Mark تمام Download
[admin@MikroTik] > /ip firewall mangle add \
    chain=prerouting \
    in-interface=ether1 \
    action=mark-packet \
    new-packet-mark=all-download \
    passthrough=no

# ۳. Mark فقط ترافیک کاربر خاص
[admin@MikroTik] > /ip firewall mangle add \
    chain=prerouting \
    src-address=192.168.88.10 \
    in-interface=bridge-lan \
    action=mark-packet \
    new-packet-mark=user1-upload \
    passthrough=no

# ۴. Mark بر اساس Protocol
[admin@MikroTik] > /ip firewall mangle add \
    chain=forward \
    protocol=udp \
    dst-port=5060,10000-20000 \
    action=mark-packet \
    new-packet-mark=voip \
    passthrough=no

# ===== مشاهده =====
[admin@MikroTik] > /ip firewall mangle print
[admin@MikroTik] > /ip firewall mangle print stats

۷.۱۰ Connection Mark و Packet Mark

Connection Mark برای علامت‌گذاری کل اتصال و Packet Mark برای علامت‌گذاری هر بسته استفاده می‌شود.

چرا Connection Mark بهتر است؟

  • یک بار در ابتدای Connection اعمال می‌شود
  • Packetهای بعدی به‌صورت خودکار همان Mark را می‌گیرند
  • مصرف CPU کمتر
# ===== سناریو: علامت‌گذاری VoIP =====

# گام ۱: Connection Mark
[admin@MikroTik] > /ip firewall mangle add \
    chain=prerouting \
    protocol=udp \
    dst-port=5060,10000-20000 \
    action=mark-connection \
    new-connection-mark=voip-conn \
    passthrough=yes \
    comment="Mark VoIP connections"

# گام ۲: Packet Mark بر اساس Connection Mark
[admin@MikroTik] > /ip firewall mangle add \
    chain=prerouting \
    connection-mark=voip-conn \
    action=mark-packet \
    new-packet-mark=voip-down \
    passthrough=no \
    comment="VoIP download packets"

[admin@MikroTik] > /ip firewall mangle add \
    chain=postrouting \
    connection-mark=voip-conn \
    action=mark-packet \
    new-packet-mark=voip-up \
    passthrough=no \
    comment="VoIP upload packets"

# ===== ترتیب مهم است =====
# 1. Connection Mark اول
# 2. بعد Packet Mark

# ===== مشاهده =====
[admin@MikroTik] > /ip firewall mangle print stats
[admin@MikroTik] > /ip firewall connection print where connection-mark=voip-conn

۷.۱۱ ترکیب Mangle و Queue Tree

# ===== سناریو کامل: تفکیک ترافیک =====

# ===== بخش ۱: Mangle =====

# ۱. Mark Connection برای VoIP
/ip firewall mangle
add chain=prerouting protocol=udp dst-port=5060,10000-20000 \
    action=mark-connection new-connection-mark=voip-conn \
    passthrough=yes comment="VoIP connection"

add chain=prerouting connection-mark=voip-conn \
    action=mark-packet new-packet-mark=voip-down \
    passthrough=no

add chain=postrouting connection-mark=voip-conn \
    action=mark-packet new-packet-mark=voip-up \
    passthrough=no

# ۲. Mark ترافیک HTTP/HTTPS
add chain=prerouting protocol=tcp dst-port=80,443 \
    action=mark-packet new-packet-mark=http-down \
    passthrough=no

add chain=postrouting protocol=tcp src-port=80,443 \
    action=mark-packet new-packet-mark=http-up \
    passthrough=no

# ۳. Mark ترافیک Other (بقیه)
add chain=prerouting in-interface=ether1 \
    action=mark-packet new-packet-mark=other-down \
    passthrough=no

# ===== بخش ۲: Queue Tree =====

# والد اصلی برای Download
/queue tree add name=download-main parent=global max-limit=100M

# VoIP — بالاترین اولویت
/queue tree add name=voip-down parent=download-main \
    packet-mark=voip-down priority=1 limit-at=5M max-limit=10M

# HTTP — اولویت متوسط
/queue tree add name=http-down parent=download-main \
    packet-mark=http-down priority=4 limit-at=30M max-limit=80M

# Other — اولویت پایین
/queue tree add name=other-down parent=download-main \
    packet-mark=other-down priority=6 limit-at=10M max-limit=100M

# ===== نتیجه =====
# - VoIP همیشه 5M تضمین + حداکثر 10M
# - HTTP حداقل 30M تضمین + حداکثر 80M
# - Other بقیه پهنای باند را می‌گیرد
# - در صورت ازدحام، VoIP هیچ‌وقت قطع نمی‌شود
💡 ساختار HTB
Queue Tree در RouterOS از HTB (Hierarchical Token Bucket) استفاده می‌کند:
  • limit-at: پهنای باند تضمینی (CIR)
  • max-limit: پهنای باند مجاز (PIR)
  • priority: اولویت در زمان ازدحام

۷.۱۲ Priority و اولویت‌بندی VoIP

Priority تعیین می‌کند در زمان ازدحام، کدام ترافیک اول برود. عدد کمتر = اولویت بالاتر (1 بهترین، 8 بدترین). 

# ===== سناریو: VoIP اولویت اول =====

# ساختار:
# 1. VoIP (priority 1)
# 2. DNS (priority 2)
# 3. HTTP/HTTPS (priority 4)
# 4. Email (priority 5)
# 5. FTP/P2P (priority 7)
# 6. Other (priority 8)

# ===== Mangle =====
/ip firewall mangle
# VoIP
add chain=prerouting protocol=udp dst-port=5060,10000-20000 \
    action=mark-connection new-connection-mark=voip-conn
add chain=prerouting connection-mark=voip-conn \
    action=mark-packet new-packet-mark=voip

# DNS
add chain=prerouting protocol=udp dst-port=53 \

۷.۱۵ Burst برای پهنای باند پویا

# ===== سناریو: کاربر 5M/10M با Burst =====

[admin@MikroTik] > /queue simple add \
    name=user-burst \
    target=192.168.88.10 \
    max-limit=5M/10M \
    burst-limit=10M/20M \
    burst-threshold=3M/6M \
    burst-time=8s/8s \
    priority=4/4

# ===== منطق Burst =====
# 1. کاربر شروع می‌کند به دانلود
# 2. اگر میانگین 8 ثانیه‌ی گذشته کمتر از 3M/6M باشد:
#    → به جای 5M/10M، 10M/20M می‌گیرد
# 3. اگر میانگین بالای 3M/6M رفت:
#    → به حالت 5M/10M برمی‌گردد

# ===== تنظیم دقیق =====
# burst-time: بازه‌ی میانگین‌گیری
#   کوتاه (3s): پاسخ سریع، ولی نوسان بیشتر
#   بلند (30s): پایدار، ولی کندتر

# burst-threshold: آستانه
#   معمولاً 50-70% max-limit

# burst-limit: پیک پهنای باند
#   معمولاً 2 برابر max-limit

# ===== غیرفعال کردن Burst =====
[admin@MikroTik] > /queue simple set [find name=user-burst] burst-limit=0/0

# 1. Target درست است؟
# 2. max-limit درست تنظیم شده؟

# یا ترافیک حساس را قبل از FastTrack علامت‌گذاری کن

[admin@MikroTik] > /ip firewall filter print where action=fasttrack-connection
# اگر می‌خواهی QoS کار کند:
[admin@MikroTik] > /ip firewall filter disable [find action=fasttrack-connection]
⚠️ هشدار مهم
FastTrack و Queue با هم کار نمی‌کنند! FastTrack ترافیک Established را دور فایروال می‌زند — یعنی Queue هم دور می‌خورد. اگر می‌خواهی QoS دقیق داشته باشی، FastTrack را غیرفعال کن.

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
برای ۹۰٪ سناریوها، Simple Queue + PCQ کافی است — ساده، سریع، عادلانه. فقط برای سناریوهای پیچیده (اولویت VoIP، تفکیک ترافیک) از Queue Tree + Mangle استفاده کن.
⚠️ FastTrack vs Queue
FastTrack را غیرفعال کن اگر QoS دقیق می‌خواهی. یا ترافیک حساس را قبل از FastTrack علامت‌گذاری کن و از آن مستثنی کن.
🏆 نکته‌ی طلایی
PCQ = عدالت. یک Queue با PCQ روی کل LAN، بدون نیاز به صدها Queue جداگانه، پهنای باند را بین همه کاربران عادلانه تقسیم می‌کند.
ℹ️ اطلاعات بیشتر
در فصل ۸ با Tunnel، PPP، PPTP، L2TP و OpenVPN آشنا می‌شوی.
🔮 دیدگاه پیشرفته
در MTCSE با HTB پیشرفته، L7 Matcher و PCQ Multi-Level در سطح حرفه‌ای کار می‌کنی.

🛠️ کارگاه عملی گام‌به‌گام

  1. RouterOS با WAN و LAN راه‌اندازی کن
  2. یک Simple Queue برای LAN بساز با max-limit=50M/100M
  3. PCQ را فعال کن (queue=pcq-up/pcq-down)
  4. Queue Typeهای PCQ را با classifier درست بساز
  5. یک کاربر خاص را با max-limit=10M/20M محدود کن
  6. برای این کاربر Burst فعال کن
  7. FastTrack را غیرفعال کن (برای QoS دقیق)
  8. Mangle برای VoIP پیاده کن (mark-connection + mark-packet)
  9. Mangle برای HTTP پیاده کن
  10. Queue Tree بساز با VoIP priority=1 و HTTP priority=4
  11. یک تماس VoIP برقرار کن و در همان لحظه دانلود شدید انجام بده
  12. ببین VoIP بدون قطعی کار می‌کند
  13. Priority HTTP را به 6 تغییر بده و تفاوت را ببین
  14. با Queue Stats تحلیل کن کدام Queue چه ترافیکی را عبور می‌دهد
  15. تمام پیکربندی را Export بگیر

🚫 خطاهای رایج و رفع‌اشکال

  • Queue اعمال نمی‌شود: FastTrack فعال است یا Target اشتباه.
  • Queue Tree کار نمی‌کند: Mangle Mark نمی‌کند یا packet-mark در Queue Tree اشتباه است.
  • PCQ توزیع نمی‌کند: pcq-classifier اشتباه (برای Upload باید src-address باشد).
  • Burst کار نمی‌کند: burst-limit=0/0 است یا burst-threshold اشتباه است.
  • Priority اعمال نمی‌شود: همه Queueها priority یکسان دارند.
  • Upload محدود نمی‌شود: Target باید کل Subnet باشد نه فقط یک IP.
  • Limit-at باعث محدودیت می‌شود: limit-at حداکثر نیست، حداقل تضمینی است.
  • Simple Queue با Queue Tree تداخل: هر دو را همزمان روی یک Interface نداشته باش.
  • VoIP قطع می‌شود: priority=1 و limit-at کافی برای VoIP تنظیم نشده.
  • Trafic P2P از Queue فرار می‌کند: P2P معمولاً از پورت‌های تصادفی استفاده می‌کند — L7 Matcher لازم است.
  • Mangle CPU بالا: Rules زیاد و بدون ترتیب بهینه — با passthrough=no بهینه کن.
  • Queue سریع پر می‌شود: pcq-limit و pcq-total-limit را افزایش بده.
  • Burst باعث نوسان می‌شود: burst-time را بلندتر کن (15s به‌جای 8s).
  • Limit-at روی LAN اعمال نمی‌شود: فقط روی WAN معنا دارد — Target را به WAN تغییر بده.
  • بعد از تغییر Priority، ترافیک اشتباه اولویت می‌گیرد: ترتیب Mangle Rules را چک کن — ترتیب مهم است.

۱۶) پهنای باند به چه واحدی در RouterOS داده می‌شود؟
۱۷) در Queue Tree، یک Queue با priority=1 و limit-at=5M و max-limit=10M چه رفتاری دارد؟
۱۸) کدام بهتر است برای توزیع عادلانه بین 100 کاربر؟

🎯 پروژه‌ی پایانی فصل

یک سیستم QoS کامل برای یک ISP کوچک بساز:

  • RouterOS با WAN ۱۰۰Mbps و LAN با ۵۰ کاربر
  • PCQ برای توزیع عادلانه بین همه کاربران (Queue Type سفارشی)
  • Simple Queue اصلی روی WAN با PCQ
  • گروه VIP با priority=1 و max-limit=20M/20M
  • گروه عادی با priority=4 و PCQ
  • گروه Guest با priority=7 و max-limit=5M/10M
  • Mangle برای VoIP (mark-connection + mark-packet)
  • Mangle برای HTTP/HTTPS
  • Queue Tree با VoIP priority=1، HTTP priority=4، Other priority=8
  • FastTrack غیرفعال (چون QoS دقیق می‌خواهیم)
  • Burst برای گروه عادی فعال
  • مستندسازی کامل با Export و دیاگرام QoS
🏆 چالش اضافه
  • QoS بر اساس زمان روز پیاده کن (با Time).
  • یک L7 Matcher برای P2P بساز.
  • با Queue Stats تحلیل کن کدام ترافیک بیشترین مصرف را دارد.
  • یک Dashboard گرافیکی با The Dude یا SNMP برای نمایش Queue بساز.

📋 جمع‌بندی و برگه‌تقب

  • QoS: مدیریت ترافیک در شرایط کمبود پهنای باند
  • Simple Queue: صف ساده، بدون Mangle — برای ۹۰٪ سناریوها
  • Queue Tree: صف درختی، نیاز به Mangle — انعطاف بالا
  • max-limit فرمت: upload/download
  • limit-at: حداقل تضمینی | max-limit: حداکثر مجاز
  • Priority: 1 (بالاترین) تا 8 (پایین‌ترین)
  • Burst: اجازه‌ی موقت پهنای باند بیشتر
  • PCQ: توزیع عادلانه — src-address برای Upload، dst-address برای Download
  • pcq-rate=0: نرخ خودکار بر اساس تعداد کاربران
  • Mangle: Mark کردن ترافیک — پیش‌نیاز Queue Tree
  • Connection Mark: برای کل اتصال — بهینه‌تر از Packet Mark
  • Chain Mangle: prerouting (Download)، postrouting (Upload)
  • FastTrack با Queue تداخل دارد — غیرفعال کن اگر QoS دقیق می‌خواهی
  • Queue Types: default، pcq، fq-codel، sfq، red، codel
  • VoIP: Priority=1، limit-at کافی
  • P2P: Priority=8، محدودیت سختگیرانه
