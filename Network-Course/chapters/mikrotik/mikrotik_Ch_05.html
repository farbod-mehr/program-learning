ARP و DHCP دو سرویس پایه‌ای هستند که بدون آن‌ها هیچ شبکه‌ای کار نمی‌کند. ARP ترجمه‌ی IP به MAC را انجام می‌دهد و DHCP توزیع خودکار آدرس را.

در این فصل یاد می‌گیری این دو سرویس را در RouterOS پیکربندی و عیب‌یابی کنی، از ARP Modes (proxy-arp، local-proxy-arp) تا DHCP Relay، Netwatch، و ابزارهای عیب‌یابی مثل Ping، Traceroute و Profiler.

۵.۱ مفهوم ARP و نقش آن

ARP (Address Resolution Protocol) پروتکلی است که آدرس IP را به آدرس MAC ترجمه می‌کند. بدون ARP، دستگاه‌های داخل یک شبکه‌ی LAN نمی‌توانند با هم حرف بزنند.

فرآیند ARP:

  1. دستگاه A می‌خواهد به IP دستگاه B بسته بفرستد
  2. ARP Request به‌صورت Broadcast می‌فرستد: «چه کسی IP 192.168.1.10 را دارد؟»
  3. دستگاه B با IP مربوطه، ARP Reply (Unicast) پاسخ می‌دهد: «من، با MAC AA:BB:CC:DD:EE:FF»
  4. دستگاه A MAC را در ARP Cache ذخیره و بسته را می‌فرستد
! ===== مشاهده ARP Table در RouterOS =====
[admin@MikroTik] > /ip arp print

# خروجی:
# Flags: X - disabled, I - invalid, H - DHCP, D - dynamic, P - published, C - complete
# #   ADDRESS         MAC-ADDRESS         INTERFACE   
# 0 D 192.168.88.10   AA:BB:CC:DD:EE:01   bridge-lan
# 1 D 192.168.88.11   AA:BB:CC:DD:EE:02   bridge-lan
# 2 DC 192.168.88.20  00:11:22:33:44:55   bridge-lan
# 3 H 192.168.88.50   AA:BB:CC:DD:EE:03   bridge-lan

# ستون‌ها:
# ADDRESS: IP دستگاه
# MAC-ADDRESS: MAC دستگاه
# INTERFACE: اینترفیسی که دستگاه از آن دیده می‌شود

# Flags:
# D = Dynamic (خودکار یاد گرفته شده)
# H = DHCP (از DHCP Server)
# C = Complete (تأیید شده)
# P = Published (برای Proxy ARP)

۵.۲ ARP Table در RouterOS

# ===== مشاهده و مدیریت ARP Table =====

# مشاهده کامل
[admin@MikroTik] > /ip arp print

# فقط Entryهای Dynamic
[admin@MikroTik] > /ip arp print where dynamic

# فقط Entryهای Static
[admin@MikroTik] > /ip arp print where !dynamic

# فیلتر بر اساس Interface
[admin@MikroTik] > /ip arp print where interface=ether2

# جستجو با IP مشخص
[admin@MikroTik] > /ip arp print where address=192.168.1.10

# ===== پاک کردن ARP Table =====
[admin@MikroTik] > /ip arp remove [find where dynamic]

# یا فقط یک Entry خاص
[admin@MikroTik] > /ip arp remove [find address=192.168.1.10]

# ===== Static ARP Entry =====
[admin@MikroTik] > /ip arp add \
    address=192.168.1.10 \
    mac-address=AA:BB:CC:DD:EE:FF \
    interface=ether2 \
    comment="Server Static ARP"

# ===== بررسی =====
[admin@MikroTik] > /ip arp print where !dynamic

۵.۳ ARP Modes

RouterOS پنج ARP Mode پشتیبانی می‌کند:

Mode توضیح کاربرد
enabled پاسخ به همه‌ی ARP Requestها برای IP خودش پیش‌فرض — LAN عادی
disabled به هیچ ARP Requestی پاسخ نمی‌دهد سناریوهای خاص
proxy-arp برای IPهای خارج از Subnet هم پاسخ می‌دهد (با MAC خودش) وقتی کلاینت‌ها Gateway اشتباه دارند
local-proxy-arp فقط برای IPهای داخل همان Subnet، Proxy ARP می‌کند Split-Subnet، Proxy ARP داخلی
reply-only فقط به IPهایی که در ARP Table Static هستند پاسخ می‌دهد امنیت — جلوگیری از ARP Spoofing 
# ===== تنظیم ARP Mode روی Interface =====
[admin@MikroTik] > /interface ethernet set ether2 arp=enabled

# یا در Bridge
[admin@MikroTik] > /interface bridge set bridge-lan arp=proxy-arp

# یا در VLAN
[admin@MikroTik] > /interface vlan set vlan10 arp=enabled

# ===== مشاهده وضعیت =====
[admin@MikroTik] > /interface ethernet print where name=ether2
# ببین ستون ARP

۵.۴ proxy-arp و local-proxy-arp — کاربردها

Proxy ARP یعنی RouterOS به ARP Requestی که برای IP خارج از Subnet خودش است هم پاسخ می‌دهد — با MAC خودش. این کار در سناریوهای خاص بسیار مفید است. 

# ===== سناریو ۱: Split Subnet با Proxy ARP =====
# شبکه‌ی 192.168.1.0/24 بین دو Ethernet تقسیم شده

# ether2: 192.168.1.1/25 (نیمه اول)
# ether3: 192.168.1.129/25 (نیمه دوم)

# کلاینت‌ها فکر می‌کنند در یک /24 هستند
# ولی در دو Subnet جدا هستند

[admin@MikroTik] > /interface ethernet set ether2 arp=proxy-arp
[admin@MikroTik] > /interface ethernet set ether3 arp=proxy-arp

# حالا PC در ether2 (مثلاً 192.168.1.10) که می‌خواهد
# با PC در ether3 (مثلاً 192.168.1.150) حرف بزند:
# - ARP Request برای 192.168.1.150 می‌فرستد
# - RouterOS با MAC ether3 پاسخ می‌دهد
# - ترافیک از روتر عبور می‌کند

# ===== سناریو ۲: local-proxy-arp برای Inside Subnet =====
[admin@MikroTik] > /interface bridge set bridge-lan arp=local-proxy-arp

# فقط برای IPهای همان Subnet پاسخ می‌دهد — مفید برای:
# - Hotspot
# - PPPoE
# - جداسازی بدون تغییر Subnet
⚠️ هشدار امنیتی
Proxy ARP در شبکه‌های Production باید با احتیاط استفاده شود — می‌تواند به حمله‌های MITM کمک کند. از آن فقط در سناریوهای مشخص و کنترل‌شده استفاده کن.

۵.۵ reply-only — جلوگیری از ARP Spoofing

حالت reply-only بسیار مفید است: RouterOS فقط به IPهایی که در ARP Table Static ثبت شده‌اند پاسخ می‌دهد. این جلوی ARP Spoofing و MAC جعلی را می‌گیرد. 

# ===== سناریو: فقط دستگاه‌های ثبت‌شده اجازه ارتباط =====

# گام ۱: Static ARP Entry برای هر دستگاه مجاز
[admin@MikroTik] > /ip arp add \
    address=192.168.1.10 \
    mac-address=AA:BB:CC:DD:EE:01 \
    interface=ether2

[admin@MikroTik] > /ip arp add \
    address=192.168.1.11 \
    mac-address=AA:BB:CC:DD:EE:02 \
    interface=ether2

# گام ۲: ARP Mode را reply-only کن
[admin@MikroTik] > /interface ethernet set ether2 arp=reply-only

# ===== نتیجه =====
# دستگاه‌های ثبت‌شده: ارتباط کامل
# دستگاه‌های غیرثبت‌شده: ARP Reply نمی‌گیرند → ارتباط قطع

# ===== بررسی =====
[admin@MikroTik] > /ip arp print where !dynamic
[admin@MikroTik] > /interface ethernet print where name=ether2

۵.۶ DHCP Server — پیکربندی کامل

DHCP (Dynamic Host Configuration Protocol) آدرس IP، Gateway، DNS و سایر پارامترها را به‌صورت خودکار به کلاینت‌ها می‌دهد.

سه جزء اصلی DHCP در RouterOS:

  1. IP Pool: محدوده‌ی IPهای قابل تخصیص
  2. DHCP Network: تنظیمات هر Subnet (Gateway، DNS)
  3. DHCP Server: سرویس روی یک Interface
# ===== پیکربندی کامل DHCP Server =====

# گام ۱: IP Pool
[admin@MikroTik] > /ip pool add \
    name=lan-pool \
    ranges=192.168.88.10-192.168.88.254 \
    comment="LAN DHCP Range"

# گام ۲: DHCP Network (تنظیمات Subnet)
[admin@MikroTik] > /ip dhcp-server network add \
    address=192.168.88.0/24 \
    gateway=192.168.88.1 \
    dns-server=192.168.88.1 \
    netmask=24 \
    comment="LAN Network"

# گام ۳: DHCP Server
[admin@MikroTik] > /ip dhcp-server add \
    name=lan-dhcp \
    interface=bridge-lan \
    address-pool=lan-pool \
    lease-time=1d \
    disabled=no \
    comment="LAN DHCP Server"

# ===== بررسی =====
[admin@MikroTik] > /ip dhcp-server print
[admin@MikroTik] > /ip dhcp-server lease print
[admin@MikroTik] > /ip dhcp-server lease print detail

۵.۷ DHCP Pool و Network

انواع Pool:

  • Range مشخص: ranges=192.168.1.10-192.168.1.200
  • چند Range: ranges=192.168.1.10-100,192.168.1.150-200
  • کل Subnet: ranges=192.168.1.0/24
# ===== Pool با چند Range =====
[admin@MikroTik] > /ip pool add \
    name=multi-range \
    ranges=192.168.1.10-100,192.168.1.150-200

# ===== Pool با Next-Pool (Pool بعدی بعد از اتمام این) =====
[admin@MikroTik] > /ip pool add \
    name=pool1 \
    ranges=192.168.1.10-100 \
    next-pool=pool2

[admin@MikroTik] > /ip pool add \
    name=pool2 \
    ranges=192.168.2.10-100

# ===== مشاهده Poolها =====
[admin@MikroTik] > /ip pool print
[admin@MikroTik] > /ip pool print detail

# ===== Network — تنظیمات Subnet =====
# چند Subnet در یک Pool می‌توانند باشند
[admin@MikroTik] > /ip dhcp-server network add \
    address=192.168.1.0/24 \
    gateway=192.168.1.1 \
    dns-server=8.8.8.8,1.1.1.1

[admin@MikroTik] > /ip dhcp-server network add \
    address=192.168.2.0/24 \
    gateway=192.168.2.1 \
    dns-server=192.168.2.1

۵.۸ DHCP Lease Time و Reservations

Lease Time مدت زمانی است که یک Client می‌تواند از IP استفاده کند. بعد از اتمام، باید تمدید کند. 

# ===== تنظیم Lease Time =====
[admin@MikroTik] > /ip dhcp-server set lan-dhcp lease-time=1d

# فرمت‌های مختلف:
# 1d      → 1 روز
# 12h     → 12 ساعت
# 1h30m   → 1 ساعت و 30 دقیقه
# 30m     → 30 دقیقه
# 1w      → 1 هفته
# 00:30:00 → 30 دقیقه

# ===== Static Lease (IP Reservation) =====
# یک دستگاه همیشه یک IP ثابت بگیرد (بر اساس MAC)

[admin@MikroTik] > /ip dhcp-server lease add \
    address=192.168.88.100 \
    mac-address=AA:BB:CC:DD:EE:FF \
    server=lan-dhcp \
    comment="Manager Laptop"

# یا اجازه بده IP خودش را از Pool بگیرد
[admin@MikroTik] > /ip dhcp-server lease add \
    mac-address=AA:BB:CC:DD:EE:FE \
    server=lan-dhcp \
    comment="Reception PC"

# ===== مشاهده Leaseها =====
[admin@MikroTik] > /ip dhcp-server lease print
# Flags: X - disabled, R - radius, D - dynamic, W - waiting
#       H - hotspot, B - blocked

# ===== تبدیل Lease داینامیک به Static =====
[admin@MikroTik] > /ip dhcp-server lease make-static 0

# ===== حذف Lease =====
[admin@MikroTik] > /ip dhcp-server lease remove 0

# ===== Block کردن یک Client =====
[admin@MikroTik] > /ip dhcp-server lease set 0 blocked=yes
# یا
[admin@MikroTik] > /ip dhcp-server lease disable 0

۵.۹ DHCP Client — پیکربندی

DHCP Client برای دریافت IP از ISP یا سرور DHCP دیگر استفاده می‌شود. 

# ===== پیکربندی DHCP Client =====
[admin@MikroTik] > /ip dhcp-client add \
    interface=ether1 \
    disabled=no \
    comment="WAN from ISP"

# ===== با تنظیمات پیشرفته =====
[admin@MikroTik] > /ip dhcp-client add \
    interface=ether1 \
    use-peer-dns=yes \
    use-peer-ntp=yes \
    add-default-route=yes \
    disabled=no

# پارامترها:
# use-peer-dns      → استفاده از DNS ISP
# use-peer-ntp      → استفاده از NTP ISP
# add-default-route → اضافه کردن Default Route خودکار
# dhcp-options      → دریافت Optionهای خاص

# ===== مشاهده وضعیت =====
[admin@MikroTik] > /ip dhcp-client print
[admin@MikroTik] > /ip dhcp-client print detail
# ببین: status=bound، address، gateway، dns

# ===== Renew کردن =====
[admin@MikroTik] > /ip dhcp-client renew 0

# ===== Release کردن =====
[admin@MikroTik] > /ip dhcp-client release 0

# ===== Client ID =====
# برخی ISPها به Client ID وابسته هستند
[admin@MikroTik] > /ip dhcp-client set 0 client-id=my-client-id
# یا MAC خود Interface را بفرست
[admin@MikroTik] > /ip dhcp-client set 0 client-id=00:11:22:33:44:55

۵.۱۰ DHCP Relay (Relay Agent)

اگر سرور DHCP در یک Subnet دیگر باشد، روتر نمی‌تواند Broadcast کلاینت را به آن برساند. راه‌حل: DHCP Relay. 

# ===== سناریو =====
# سرور DHCP در شبکه‌ی 10.0.0.0/24 (جایی در شبکه)
# کلاینت‌ها در شبکه‌ی 192.168.1.0/24

# RouterOS با DHCP Relay درخواست کلاینت را به سرور می‌فرستد

[admin@MikroTik] > /ip dhcp-relay add \
    name=relay-lan \
    interface=ether2 \
    dhcp-server=10.0.0.5 \
    local-address=192.168.1.1 \
    disabled=no

# پارامترها:
# interface       → Interface سمت کلاینت
# dhcp-server     → IP سرور DHCP
# local-address   → آدرس روتر در Subnet کلاینت
# delay           → تأخیر در ارسال (ثانیه)

# ===== بررسی =====
[admin@MikroTik] > /ip dhcp-relay print
[admin@MikroTik] > /ip dhcp-relay print detail

# ===== نکات مهم =====
# - روی Interface سمت کلاینت، DHCP Server نباید فعال باشد
# - local-address باید در Subnet کلاینت باشد
# - در سرور DHCP باید Subnet کلاینت تعریف شده باشد
💡 نکته
DHCP Relay در Cisco معادل ip helper-address است. در MikroTik به‌صورت یک سرویس جداگانه پیکربندی می‌شود.

۵.۱۱ DHCP Options — تنظیمات پیشرفته

# ===== DHCP Optionهای رایج =====
# Option 1   → Subnet Mask
# Option 3   → Router (Gateway)
# Option 6   → DNS Server
# Option 15  → Domain Name
# Option 42  → NTP Server
# Option 66  → TFTP Server
# Option 67  → Bootfile Name
# Option 119 → Domain Search List
# Option 121 → Classless Static Routes
# Option 150 → TFTP Server (Cisco)
# Option 252 → WPAD (Proxy)

# ===== ارسال NTP Server به کلاینت‌ها =====
[admin@MikroTik] > /ip dhcp-server network set 0 \
    ntp-server=192.168.88.1

# ===== ارسال Domain Name =====
[admin@MikroTik] > /ip dhcp-server network set 0 \
    domain=company.local

# ===== ارسال Custom Option =====
[admin@MikroTik] > /ip dhcp-server option add \
    name=ntp-server \
    code=42 \
    value="'192.168.88.1'"

[admin@MikroTik] > /ip dhcp-server option add \
    name=tftp-boot \
    code=66 \
    value="'192.168.88.5'"

[admin@MikroTik] > /ip dhcp-server option add \
    name=cisco-phone-tftp \
    code=150 \
    value="'192.168.88.10'"

# ===== اعمال Option روی Network =====
[admin@MikroTik] > /ip dhcp-server network set 0 \
    dhcp-option=ntp-server,tftp-boot

# ===== بررسی =====
[admin@MikroTik] > /ip dhcp-server option print
[admin@MikroTik] > /ip dhcp-server network print detail

۵.۱۲ Netwatch — پایش و اسکریپت

Netwatch ابزاری برای پایش یک IP یا Host است. اگر Host پاسخ ندهد، می‌تواند اسکریپت اجرا کند. 

# ===== پیکربندی پایه Netwatch =====
[admin@MikroTik] > /tool netwatch add \
    host=8.8.8.8 \
    interval=10s \
    timeout=1s \
    comment="Monitor Google DNS"

# پارامترها:
# host      → IP یا Hostname
# interval  → فاصله بین چک‌ها
# timeout   → مدت انتظار برای پاسخ

# ===== با اسکریپت =====
[admin@MikroTik] > /tool netwatch add \
    host=8.8.8.8 \
    interval=30s \
    timeout=1s \
    up-script="/log info \"Internet is UP\"" \
    down-script="/log warning \"Internet is DOWN\""

# ===== با نوع پروتکل =====
[admin@MikroTik] > /tool netwatch add \
    host=192.168.1.100 \
    type=tcp-conn \
    port=443 \
    interval=10s \
    comment="Monitor HTTPS Server"

# انواع:
# icmp      → Ping (پیش‌فرض)
# tcp-conn  → TCP Connection
# http-get  → HTTP GET Request
# simple    → TCP Connect + Close
# udp       → UDP Packet

# ===== مشاهده وضعیت =====
[admin@MikroTik] > /tool netwatch print
# ستون status: up یا down

[admin@MikroTik] > /tool netwatch print detail
# اطلاعات کامل شامل since، status، comment
# ===== مثال: Failover خودکار با Netwatch =====

# ۱. Netwatch روی ISP-A
[admin@MikroTik] > /tool netwatch add \
    host=8.8.8.8 \
    interval=10s \
    down-script="/ip route disable [find comment=\"Primary ISP\"]" \
    up-script="/ip route enable [find comment=\"Primary ISP\"]"

# ۲. روی ISP-B هم مشابه
[admin@MikroTik] > /tool netwatch add \
    host=1.1.1.1 \
    interval=10s \
    down-script="/ip route disable [find comment=\"Backup ISP\"]" \
    up-script="/ip route enable [find comment=\"Backup ISP\"]"

# ===== نتیجه =====
# - اگر ISP-A قطع شود، Default Route آن غیرفعال می‌شود
# - Backup ISP خودکار فعال می‌شود
# - وقتی ISP-A برگردد، دوباره فعال می‌شود

# ===== مثال پیشرفته: اعلان با Email =====
[admin@MikroTik] > /tool netwatch add \
    host=192.168.1.100 \
    interval=1m \
    down-script="
        /tool e-mail send \
            to=admin@company.ir \
            subject=\"Alert: 192.168.1.100 is DOWN\" \
            body=\"Critical server unreachable\" \
            server=smtp.gmail.com
    "

۵.۱۳ Ping و Traceroute پیشرفته

# ===== Ping پیشرفته =====
[admin@MikroTik] > /ping 8.8.8.8

# با تنظیمات:
[admin@MikroTik] > /ping 8.8.8.8 \
    count=10 \
    interval=1s \
    size=1500 \
    src-address=192.168.1.1

# پارامترها:
# count      → تعداد Ping
# interval   → فاصله بین Pingها
# size       → اندازه Payload
# src-address → آدرس مبدأ
# interface  → Interface خروجی
# routing-table → جدول مسیریابی

# ===== Ping از یک Interface خاص =====
[admin@MikroTik] > /ping 8.8.8.8 interface=ether1

# ===== Ping با Don't Fragment (تست MTU) =====

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
همیشه در DHCP Network، Gateway و DNS را درست تنظیم کن — این دو، بیشترین تأثیر روی تجربه‌ی کاربر را دارند.
⚠️ هشدار امنیتی
در شبکه‌های حساس، از reply-only برای ARP استفاده کن و Static ARP برای هر دستگاه مجاز اضافه کن. این جلوی ARP Spoofing را می‌گیرد.
🏆 نکته‌ی طلایی
Netwatch + اسکریپت = Failover خودکار. اگر Default Route به ISP-A قطع شود، Netwatch می‌تواند خودکار به ISP-B سوییچ کند — بدون دخالت انسان.
ℹ️ اطلاعات بیشتر
در فصل ۶ با Firewall، NAT، Connection Tracking و Address-List آشنا می‌شوی.
🔮 دیدگاه پیشرفته
با DHCP Option 82 (Relay Agent Information) می‌توانی DHCP را در محیط‌های پیچیده‌ی ISP کنترل کنی.

مثال ۲ — DHCP Relay برای شبکه‌ی Remote

# ===== سناریو =====
# شبکه‌ی مرکزی: 10.0.0.0/24 (سرور DHCP: 10.0.0.5)
# شبکه‌ی شعبه: 192.168.5.0/24 (روتر: 192.168.5.1)

# در شعبه:
[admin@Branch] > /ip address add address=192.168.5.1/24 interface=ether2

[admin@Branch] > /ip dhcp-relay add \
    name=relay-branch \
    interface=ether2 \
    dhcp-server=10.0.0.5 \
    local-address=192.168.5.1 \
    disabled=no

# در مرکزی (سرور DHCP):
[admin@Central] > /ip dhcp-server network add \
    address=192.168.5.0/24 \
    gateway=192.168.5.1 \
    dns-server=10.0.0.5

[admin@Central] > /ip pool add \
    name=branch-pool \
    ranges=192.168.5.50-192.168.5.200

[admin@Central] > /ip dhcp-server add \
    name=central-dhcp \
    interface=ether2 \
    address-pool=branch-pool,branch-pool2 \
    disabled=no

# ===== نتیجه =====
# کلاینت در شعبه، درخواست DHCP می‌فرستد
# Branch Router آن را به 10.0.0.5 Relay می‌کند
# سرور IP از branch-pool می‌دهد

مثال ۳ — Netwatch برای Failover بین دو ISP

# ===== پیکربندی دو ISP =====
[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=203.0.113.1 \
    distance=1 \
    comment="Primary ISP"

[admin@MikroTik] > /ip route add \
    dst-address=0.0.0.0/0 \
    gateway=198.51.100.1 \
    distance=5 \
    comment="Backup ISP"

# ===== Netwatch برای ISP-A =====
[admin@MikroTik] > /tool netwatch add \
    host=8.8.8.8 \
    interval=10s \
    timeout=2s \
    down-script="{
        /ip route disable [find comment=\"Primary ISP\"];
        /log warning \"ISP-A DOWN - Switching to backup\"
    }" \
    up-script="{
        /ip route enable [find comment=\"Primary ISP\"];
        /log info \"ISP-A UP - Switching back\"
    }"

# ===== نتیجه =====
# اگر 8.8.8.8 پاسخ ندهد:
# - Primary ISP غیرفعال می‌شود
# - Backup ISP فعال می‌شود
# - وقتی 8.8.8.8 پاسخ داد، Primary دوباره فعال می‌شود

# ===== بررسی =====
[admin@MikroTik] > /tool netwatch print
[admin@MikroTik] > /ip route print where dst-address="0.0.0.0/0"

مثال ۴ — امنیت ARP با reply-only

# ===== سناریو: فقط دستگاه‌های مجاز به شبکه دسترسی دارند =====

🚫 خطاهای رایج و رفع‌اشکال

  • DHCP IP نمی‌دهد: Pool خالی، Network اشتباه، یا Server روی Interface غلط.
  • DHCP Pool تمام شده: Pool را گسترده‌تر کن یا Lease Time را کاهش بده.
  • DHCP Relay کار نمی‌کند: local-address باید در Subnet کلاینت باشد.
  • ARP Cache پر می‌شود: ARP Spoofing یا اسکن شبکه — بررسی کن.
  • reply-only روی Bridge: ARP Mode باید روی خود Bridge تنظیم شود، نه پورت‌های عضو.
  • Proxy ARP مشکل می‌سازد: با reply-only ترکیب نکن — Conflict.
  • Netwatch همیشه Down: Host قابل دسترس نیست یا Interval کوتاه است.
  • اسکریپت Netwatch خطا می‌دهد: مسیرها و کوتیشن‌ها را چک کن — خطای Syntax باعث شکست می‌شود.
  • DHCP Option اعمال نمی‌شود: Option باید در Network اضافه شود، نه فقط تعریف شود.
  • کلاینت IP اشتباه می‌گیرد (169.254.x.x): DHCP Server پاسخ نمی‌دهد — Firewall یا Interface را چک کن.
  • Static Lease با MAC اشتباه: MAC باید دقیقاً مطابق دستگاه باشد.
  • بعد از تغییر ARP Mode، اتصال قطع شد: از Safe Mode استفاده کن — تغییرات بعد از Logout برمی‌گردند.
  • DHCP Client از ISP IP نمی‌گیرد: MAC در ISP باید Register شده باشد یا Client ID درست باشد.
  • Netwatch Script اجرا نمی‌شود: در ستون Run باید فعال باشد — Policy کاربر را چک کن.
  • Profiler کند است: فقط در زمان نیاز فعال کن — Performance را پایین می‌آورد.

🎯 پروژه‌ی پایانی فصل

یک شبکه‌ی کامل با DHCP، ARP و Netwatch بساز:

  • روتر اصلی با Bridge LAN و IP Gateway
  • DHCP Server با Pool مناسب و Lease Time ۱ روز
  • Static Lease برای حداقل ۳ دستگاه (سرور، چاپگر، مدیریت)
  • DHCP Options — NTP Server و Domain Name به کلاینت‌ها
  • DHCP Client روی Interface WAN برای دریافت از ISP
  • DHCP Relay برای یک Subnet دوم
  • ARP Mode روی Bridge — reply-only برای امنیت
  • Static ARP برای دستگاه‌های حساس
  • Netwatch روی 8.8.8.8 برای پایش اینترنت
  • Netwatch Script برای Failover بین دو ISP
  • Syslog به سرور مرکزی برای لاگ DHCP و ARP
  • مستندسازی کامل با Export و دیاگرام شبکه
🏆 چالش اضافه
  • یک Script بنویس که وقتی Pool DHCP نزدیک به اتمام شد، هشدار بفرستد.
  • یک ARP Spoofing ساده از PC بساز و ببین reply-only چطور جلوی آن را می‌گیرد.
  • با Packet Sniffer، فرآیند DORA را در سطح بسته تحلیل کن.
  • Netwatch را با Email Alert ترکیب کن.

📋 جمع‌بندی و برگه‌تقب

  • ARP: ترجمه IP به MAC با Broadcast/Reply
  • ARP Modes: enabled، disabled، proxy-arp، local-proxy-arp، reply-only
  • reply-only: فقط به IPهای Static ARP پاسخ می‌دهد — امنیت بالاتر
  • DHCP Server: سه جزء — Pool، Network، Server
  • DHCP Pool: محدوده IPهای قابل تخصیص
  • DHCP Network: تنظیمات Subnet (Gateway، DNS، NTP، Domain)
  • Lease Time: فرمت 1d، 12h، 30m، 1w
  • Static Lease: IP ثابت بر اساس MAC
  • DHCP Client: دریافت IP از ISP یا سرور دیگر
  • DHCP Relay: برای سرور DHCP در Subnet دیگر
  • DHCP Options: 3=Gateway، 6=DNS، 42=NTP، 66=TFTP، 150=Cisco TFTP
  • Netwatch: پایش Host با اسکریپت Up/Down — Failover خودکار
  • Ping پیشرفته: count، size، src-address، interface، do-not-fragment
  • Traceroute: icmp/udp/tcp — تحلیل مسیر
  • Profiler: تحلیل CPU به تفکیک سرویس
  • Logging: Topics مختلف — dhcp، arp، wireless، error
