۸.۱ مفاهیم پایه VPN

VPN (Virtual Private Network) یک تونل امن بین دو نقطه روی اینترنت عمومی می‌سازد.

مزایای VPN:

  • رمزنگاری: ترافیک روی اینترنت امن می‌شود
  • اتصال امن: کاربران Remote با شبکه‌ی اصلی در ارتباط‌اند
  • کاهش هزینه: نیاز به لینک اختصاصی نیست
  • انعطاف: هر اتصال اینترنتی می‌تواند VPN باشد
  • مخفی‌سازی: IP واقعی مشتری مخفی می‌ماند

انواع VPN از نظر معماری:

نوع توضیح مثال
Site-to-Site اتصال دو شبکه‌ی LAN دفتر مرکزی ↔ شعبه
Remote Access اتصال یک کاربر به شبکه کارمند از خانه
Client-to-Site کلاینت به یک شبکه Laptop به VPN سازمانی

۸.۲ PPP Settings — پایه‌ی VPN در RouterOS

تمام VPNهای Point-to-Point در RouterOS زیر چتر /interface ppp (یا در نسخه‌های جدیدتر /interface ppp-client و /ppp) مدیریت می‌شوند. 

# ===== ساختار PPP =====
/ppp
├── aaa          → Authentication, Authorization, Accounting
├── profile      → تنظیمات پیش‌فرض برای کلاینت‌ها
├── secret       → کاربران PPP
└── active       → اتصالات فعال

# ===== مشاهده =====
[admin@MikroTik] > /ppp profile print
[admin@MikroTik] > /ppp secret print
[admin@MikroTik] > /ppp active print

# ===== مشاهده Interfaceهای VPN =====
[admin@MikroTik] > /interface print where type=ppp
[admin@MikroTik] > /interface print where type=ovpn
[admin@MikroTik] > /interface print where type=l2tp
[admin@MikroTik] > /interface print where type=sstp
[admin@MikroTik] > /interface print where type=pptp

۸.۳ IP Pool برای VPN Users

# ===== ساخت IP Pool برای VPN =====
[admin@MikroTik] > /ip pool add \
    name=vpn-pool \
    ranges=10.10.10.10-10.10.10.254 \
    comment="VPN User IP Range"

# ===== مشاهده =====
[admin@MikroTik] > /ip pool print
[admin@MikroTik] > /ip pool print where name=vpn-pool

# ===== استفاده در PPP Profile =====
[admin@MikroTik] > /ppp profile set default remote-address=vpn-pool

# نکته:
# - VPN Userها IP از این Pool می‌گیرند
# - معمولاً از Subnet جداگانه مثل 10.10.10.0/24 استفاده کن
# - این Subnet نباید با شبکه‌ی داخلی تداخل داشته باشد

۸.۴ PPP Secrets و Profiles

PPP Profile تنظیمات پیش‌فرض برای گروهی از کاربران است و PPP Secret یک کاربر مشخص. 

# ===== PPP Profile =====
[admin@MikroTik] > /ppp profile add \
    name=vpn-users \
    local-address=10.10.10.1 \
    remote-address=vpn-pool \
    dns-server=10.10.10.1,8.8.8.8 \
    use-encryption=required \
    comment="VPN User Profile"

# پارامترها:
# local-address    → IP سمت Server
# remote-address   → Pool یا IP برای Client
# dns-server       → DNS برای Client
# use-encryption   → required/preferred/no

# ===== PPP Secret — کاربران =====
[admin@MikroTik] > /ppp secret add \
    name=user1 \
    password=StrongPass1 \
    service=any \
    profile=vpn-users \
    comment="First VPN User"

[admin@MikroTik] > /ppp secret add \
    name=user2 \
    password=StrongPass2 \
    service=l2tp \
    profile=vpn-users \
    remote-address=10.10.10.50 \
    comment="Static IP for user2"

# پارامترها:
# name             → نام کاربری
# password         → رمز عبور
# service          → any، pptp، l2tp، ovpn، sstp
# profile          → PPP Profile
# remote-address   → IP ثابت برای این کاربر (اختیاری)

# ===== مشاهده =====
[admin@MikroTik] > /ppp secret print
[admin@MikroTik] > /ppp secret print detail
[admin@MikroTik] > /ppp active print
# active: کاربران آنلاین

۸.۵ PPTP — پروتکل کلاسیک (توصیه نمی‌شود)

⚠️ هشدار امنیتی
PPTP امن نیست! رمزنگاری آن (MS-CHAPv2) از سال‌ها قبل شکسته شده است. NSA قادر به رمزگشایی آن در چند ساعت است. فقط برای موارد غیرحساس یا سازگاری با دستگاه‌های قدیمی استفاده کن. 
# ===== PPTP Server =====
[admin@MikroTik] > /interface pptp-server server set \
    enabled=yes \
    authentication=mschap2 \
    default-profile=vpn-users \
    keepalive-timeout=60

# مشاهده وضعیت
[admin@MikroTik] > /interface pptp-server server print

# ===== PPTP Client =====
[admin@MikroTik] > /interface pptp-client add \
    name=pptp-out1 \
    connect-to=203.0.113.5 \
    user=user1 \
    password=StrongPass1 \
    disabled=no \
    profile=default-encryption \
    add-default-route=no

# بررسی
[admin@MikroTik] > /interface pptp-client print
[admin@MikroTik] > /interface print where type=pptp

# ===== نکته =====
# PPTP از پورت TCP/1723 استفاده می‌کند
# در نسخه‌های جدید RouterOS، PPTP نیاز به پکیج جداگانه ندارد

۸.۶ L2TP — Layer 2 Tunneling Protocol

L2TP خودش رمزنگاری ندارد، ولی معمولاً با IPsec ترکیب می‌شود (L2TP/IPsec) که امنیت خوبی می‌دهد. 

# ===== L2TP Server (بدون IPsec — توصیه نمی‌شود) =====
[admin@MikroTik] > /interface l2tp-server server set \
    enabled=yes \
    authentication=mschap2 \
    default-profile=vpn-users

# ===== L2TP Server با IPsec (توصیه‌شده) =====
[admin@MikroTik] > /interface l2tp-server server set \
    enabled=yes \
    use-ipsec=yes \
    ipsec-secret=IPsecSecret@2024 \
    authentication=mschap2 \
    default-profile=vpn-users

# پارامترها:
# use-ipsec        → فعال‌سازی IPsec
# ipsec-secret     → کلید مشترک IPsec

# ===== L2TP Client =====
[admin@MikroTik] > /interface l2tp-client add \
    name=l2tp-out1 \
    connect-to=203.0.113.5 \
    user=user1 \
    password=StrongPass1 \
    profile=default-encryption \
    use-ipsec=yes \
    ipsec-secret=IPsecSecret@2024 \
    disabled=no \
    add-default-route=no

# ===== نکات مهم =====
# 1. L2TP از UDP/1701 استفاده می‌کند
# 2. IPsec از UDP/500 و UDP/4500 استفاده می‌کند
# 3. در Firewall باید این پورت‌ها باز باشند

# ===== Firewall برای L2TP/IPsec =====
[admin@MikroTik] > /ip firewall filter add \
    chain=input \
    protocol=udp \
    dst-port=500,1701,4500 \
    action=accept \
    comment="Allow L2TP/IPsec"

[admin@MikroTik] > /ip firewall filter add \
    chain=input \
    protocol=ipsec-esp \
    action=accept \
    comment="Allow IPsec-ESP"

[admin@MikroTik] > /ip firewall filter add \
    chain=input \
    protocol=ipsec-ah \
    action=accept \
    comment="Allow IPsec-AH"

۸.۷ SSTP — Secure Socket Tunneling Protocol

SSTP یک VPN مدرن مایکروسافت است که روی HTTPS (TCP/443) کار می‌کند — به‌راحتی از فایروال‌ها و پروکسی‌ها عبور می‌کند. 

# ===== SSTP Server =====
[admin@MikroTik] > /interface sstp-server server set \
    enabled=yes \
    default-profile=vpn-users \
    authentication=mschap2 \
    certificate=server-cert

# نکته: SSTP نیاز به Certificate دارد
# اگر Certificate نداری، باید بسازی یا از Let's Encrypt استفاده کنی

# ===== ساخت Certificate خودامضا =====
[admin@MikroTik] > /certificate add \
    name=server-cert \
    common-name=vpn.example.com \
    key-usage=tls-server \
    days-valid=3650

[admin@MikroTik] > /certificate sign server-cert

# ===== SSTP Client =====
[admin@MikroTik] > /interface sstp-client add \
    name=sstp-out1 \
    connect-to=203.0.113.5 \
    user=user1 \
    password=StrongPass1 \
    profile=default-encryption \
    disabled=no

# ===== مزایای SSTP =====
# - از TCP/443 عبور می‌کند (معمولاً باز است)
# - رمزنگاری SSL/TLS
# - سازگاری با Windows بدون نصب نرم‌افزار

# ===== عیب =====
# - Performance پایین‌تر از L2TP یا OpenVPN
# - فقط روی Windows (و RouterOS) بومی پشتیبانی می‌شود

۸.۸ OpenVPN — VPN متن‌باز محبوب

# ===== OpenVPN Server =====
# گام ۱: Certificate
[admin@MikroTik] > /certificate add \
    name=ca \
    common-name=my-ca \
    key-usage=key-cert-sign,crl-sign \
    days-valid=3650

[admin@MikroTik] > /certificate sign ca

[admin@MikroTik] > /certificate add \
    name=server-cert \
    common-name=server \
    days-valid=3650

[admin@MikroTik] > /certificate sign server-cert ca=ca

# گام ۲: OpenVPN Server
[admin@MikroTik] > /interface ovpn-server server set \
    enabled=yes \
    port=1194 \
    mode=ip \
    netmask=24 \
    default-profile=vpn-users \
    certificate=server-cert \
    auth=sha1,md5 \
    cipher=aes256,aes192,aes128 \
    require-client-certificate=no

# گام ۳: Firewall
[admin@MikroTik] > /ip firewall filter add \
    chain=input \
    protocol=tcp \
    dst-port=1194 \
    action=accept \
    comment="Allow OpenVPN"

# ===== OpenVPN Client =====
[admin@MikroTik] > /interface ovpn-client add \
    name=ovpn-out1 \
    connect-to=203.0.113.5 \
    port=1194 \
    user=user1 \
    password=StrongPass1 \
    profile=default-encryption \
    certificate=client-cert \
    auth=sha1 \
    cipher=aes256 \
    disabled=no

# ===== مزایا =====
# - Open Source
# - امنیت بالا با SSL/TLS
# - سازگار با اکثر سیستم‌عامل‌ها
# - انعطاف‌پذیری زیاد

# ===== عیب =====
# - Performance کمتر از WireGuard
# - تنظیمات پیچیده‌تر

۸.۹ EoIP — Ethernet over IP

EoIP یک تونل لایه ۲ است که فریم‌های Ethernet را در IP کپسوله می‌کند. برای اتصال دو شبکه‌ی L2 از راه دور. 

# ===== EoIP Tunnel =====
[admin@R1] > /interface eoip add \
    name=eoip-tunnel1 \
    remote-address=203.0.113.5 \
    tunnel-id=100 \
    local-address=203.0.113.1 \
    disabled=no

# پارامترها:
# remote-address   → IP طرف مقابل
# tunnel-id        → شناسه تونل (یکتا، 0-65535)
# local-address    → IP محلی (معمولاً خودکار)

# ===== طرف مقابل =====
[admin@R2] > /interface eoip add \
    name=eoip-tunnel1 \
    remote-address=203.0.113.1 \
    tunnel-id=100 \
    disabled=no

# ===== استفاده: اضافه کردن به Bridge =====
[admin@R1] > /interface bridge add name=br-eoip
[admin@R1] > /interface bridge port add bridge=br-eoip interface=eoip-tunnel1
[admin@R1] > /interface bridge port add bridge=br-eoip interface=ether2

# ===== نکات مهم =====
# 1. EoIP رمزنگاری ندارد — با IPsec ترکیب کن
# 2. tunnel-id باید در دو طرف یکسان باشد
# 3. برای شبکه‌های Multi-Branch عالی است
# 4. روی MTU حساس است — MTU را کم کن اگر مشکل داشتی

# ===== EoIP با IPsec =====
# در EoIP، گزینه ipsec-secret را بگذار
[admin@R1] > /interface eoip set eoip-tunnel1 \
    ipsec-secret=MyIPsecSecret

# حالا ترافیک تونل رمزنگاری می‌شود

۸.۱۰ IPIP Tunnel

# ===== IPIP Tunnel =====
[admin@R1] > /interface ipip add \
    name=ipip-tunnel1 \
    remote-address=203.0.113.5 \
    local-address=203.0.113.1

[admin@R2] > /interface ipip add \
    name=ipip-tunnel1 \

# IPIP: فقط IP (L3) را کپسوله می‌کند
# EoIP: فریم Ethernet (L2) را کپسوله می‌کند
# IPIP سریع‌تر، EoIP انعطاف‌پذیرتر

۸.۱۱ GRE Tunnel در RouterOS

# ===== GRE Tunnel =====
[admin@R1] > /interface gre add \
    name=gre-tunnel1 \
    remote-address=203.0.113.5 \
    local-address=203.0.113.1 \
    ipsec-secret=MyIPsecSecret \

[admin@R2] > /interface gre add \
    name=gre-tunnel1 \

# مناسب برای OSPF روی تونل

[admin@R1] > /interface print where type=gre

۸.۱۲ WireGuard — VPN مدرن (RouterOS 7+)

WireGuard یک پروتکل VPN مدرن و سبک است که در RouterOS 7.x اضافه شده است. سریع، ساده، و امن.

مزایای WireGuard:

  • Performance: بسیار سریع‌تر از OpenVPN و L2TP
  • سادگی: تنظیمات مینیمال
  • امنیت: رمزنگاری مدرن (ChaCha20، Curve25519)
  • Kernel-based: در Linux — بسیار سریع
  • Roaming: پشتیبانی از تغییر شبکه کلاینت
# ===== WireGuard Server (RouterOS 7+) =====
# گام ۱: ساخت Interface
[admin@MikroTik] > /interface wireguard add \
    name=wg-server \
    listen-port=13231 \
    comment="WireGuard Server"

# گام ۲: مشاهده Public Key
[admin@MikroTik] > /interface wireguard print detail
# خروجی شامل: private-key (که باید مخفی بماند)
# public-key (که باید به کلاینت‌ها بدهی)

[admin@MikroTik] > /interface wireguard print
# یا اگر خواستی Public Key را ببینی:
[admin@MikroTik] > /interface wireguard print where name=wg-server

# گام ۳: IP روی Interface
[admin@MikroTik] > /ip address add \
    address=10.30.30.1/24 \
    interface=wg-server

# گام ۴: اضافه کردن Peer (کلاینت)
[admin@MikroTik] > /interface wireguard peers add \
    interface=wg-server \
    public-key="ClientPublicKeyHere" \
    allowed-address=10.30.30.2/32 \
    comment="Client 1"

# ===== WireGuard Client =====
[admin@Client] > /interface wireguard add \
    name=wg-client \
    private-key="ClientPrivateKeyHere" \
    comment="WireGuard Client"

[admin@Client] > /interface wireguard peers add \
    interface=wg-client \
    public-key="ServerPublicKeyHere" \
    endpoint-address=203.0.113.5 \
    endpoint-port=13231 \
    allowed-address=10.30.30.0/24 \
    persistent-keepalive=25s

[admin@Client] > /ip address add \
    address=10.30.30.2/24 \
    interface=wg-client

# ===== نکته =====
# persistent-keepalive: برای عبور از NAT ضروری است (25s توصیه‌شده)

# ===== Firewall =====
[admin@MikroTik] > /ip firewall filter add \
    chain=input \
    protocol=udp \
    dst-port=13231 \
    action=accept \
    comment="WireGuard"

۸.۱۴ Routing روی Tunnel

# ===== بعد از ساخت تونل، Routing =====

# روش ۱: Static Route
[admin@R1] > /ip route add \
    dst-address=192.168.2.0/24 \
    gateway=10.10.10.2 \
    comment="Remote LAN via Tunnel"

# روش ۲: OSPF روی تونل
[admin@R1] > /routing ospf instance add name=ospf1
[admin@R1] > /routing ospf area add name=backbone area-id=0.0.0.0 instance=ospf1

[admin@R1] > /routing ospf interface-template add \
    interfaces=ipip-tunnel1 \
    area=backbone

# روش ۳: BGP روی تونل
[admin@R1] > /routing bgp connection add \
    name=to-r2 \
    remote.address=10.10.10.2 \
    remote.as=65002 \
    local.as=65001 \
    as=65001

# ===== NAT برای ترافیک VPN =====
# اگر VPN Users می‌خواهند به اینترنت بروند:
[admin@MikroTik] > /ip firewall nat add \
    chain=srcnat \
    src-address=10.10.10.0/24 \
    out-interface=ether1 \
    action=masquerade \
    comment="NAT for VPN users"

۸.۱۵ Firewall برای Tunnelها

# ===== پورت‌های مورد نیاز =====

# PPTP: TCP/1723 + Protocol 47 (GRE)
# L2TP: UDP/1701
# L2TP/IPsec: UDP/500، UDP/1701، UDP/4500 + ESP
# SSTP: TCP/443
# OpenVPN: TCP/1194 (یا UDP/1194)
# WireGuard: UDP/13231 (قابل تغییر)
# EoIP: Protocol 47 (GRE)
# IPIP: Protocol 4
# GRE: Protocol 47

# ===== Firewall Rules =====
/ip firewall filter
# PPTP
add chain=input protocol=tcp dst-port=1723 action=accept comment="PPTP"
add chain=input protocol=gre action=accept comment="GRE for PPTP"

# L2TP
add chain=input protocol=udp dst-port=1701 action=accept comment="L2TP"

# IPsec
add chain=input protocol=udp dst-port=500,4500 action=accept comment="IPsec"
add chain=input protocol=ipsec-esp action=accept comment="IPsec-ESP"

# SSTP
add chain=input protocol=tcp dst-port=443 action=accept comment="SSTP"

# OpenVPN
add chain=input protocol=tcp dst-port=1194 action=accept comment="OpenVPN"

# WireGuard
add chain=input protocol=udp dst-port=13231 action=accept comment="WireGuard"

⚠️ نکته‌ی مهم
برخی ISPها پورت‌های VPN (خصوصاً PPTP و L2TP) را بلاک می‌کنند. اگر تونل کار نمی‌کند، از SSTP (TCP/443) یا WireGuard (UDP) استفاده کن که معمولاً بلاک نمی‌شوند.

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
در RouterOS 7+، WireGuard بهترین گزینه برای VPN است — سریع، ساده، امن. اگر نسخه‌ی قدیمی داری، L2TP/IPsec یا SSTP گزینه‌های خوبی هستند.
⚠️ امنیت
هرگز از PPTP استفاده نکن — شکسته است. حتی در سناریوهای غیرحساس، از L2TP/IPsec یا WireGuard استفاده کن.
🏆 نکته‌ی طلایی
برای اتصال بین دو دفتر بدون IP Static، از ZeroTier یا Cloud VPN استفاده کن — نیازی به Forward کردن پورت روی روتر نداری.
ℹ️ اطلاعات بیشتر
با این فصل، دوره MTCNA کامل شد! 🎉 حالا آماده‌ای برای MTCRE، MTCWE و دوره‌های تخصصی‌تر MikroTik.

در MTCINE با BGP و OSPF در سطح ISP، و MTCSE با امنیت پیشرفته کار می‌کنی.

💻 مثال‌های عملی

مثال ۱ — L2TP/IPsec Server کامل

# ===== گام ۱: IP Pool =====
/ip pool add name=vpn-pool ranges=10.99.99.10-10.99.99.254

# ===== گام ۲: PPP Profile =====
/ppp profile add \
    name=vpn-profile \
    local-address=10.99.99.1 \
    remote-address=vpn-pool \
    dns-server=8.8.8.8,1.1.1.1 \
    use-encryption=required

# ===== گام ۳: PPP Secret =====
/ppp secret add \
    name=alice \
    password=AlicePass@2024 \
    service=l2tp \
    profile=vpn-profile \
    comment="Alice - Sales"

/ppp secret add \
    name=bob \
    password=BobPass@2024 \
    service=l2tp \
    profile=vpn-profile \
    comment="Bob - Tech"

# ===== گام ۴: L2TP Server =====
/interface l2tp-server server set \
    enabled=yes \
    use-ipsec=yes \
    ipsec-secret=L2TPIPsec@2024 \
    authentication=mschap2 \
    default-profile=vpn-profile

# ===== گام ۵: Firewall =====
/ip firewall filter
add chain=input protocol=udp dst-port=500,1701,4500 action=accept \
    comment="L2TP/IPsec"
add chain=input protocol=ipsec-esp action=accept comment="IPsec-ESP"
add chain=input protocol=ipsec-ah action=accept comment="IPsec-AH"

# ===== گام ۶: NAT برای VPN Users =====
/ip firewall nat add chain=srcnat src-address=10.99.99.0/24 \
    out-interface=ether1 action=masquerade comment="NAT VPN users"

# ===== تست از Windows =====
# 1. Settings → VPN → Add
# 2. Provider: Windows (built-in)
# 3. Server name: your-public-ip
# 4. VPN type: L2TP/IPsec with pre-shared key
# 5. Pre-shared key: L2TPIPsec@2024
# 6. Username: alice، Password: AlicePass@2024

مثال ۲ — WireGuard بین دو سایت

# ===== Server (Site A) =====

# ۱. Interface
/interface wireguard add name=wg-site name=wg-site listen-port=13231

# ۲. IP
/ip address add address=10.50.50.1/30 interface=wg-site

# ۳. Peer (Site B) - نیاز به Public Key طرف مقابل
# Public Key را از Site B بگیر
/interface wireguard peers add \
    interface=wg-site \
    public-key="SITE_B_PUBLIC_KEY" \
    allowed-address=10.50.50.2/32,192.168.20.0/24 \
    comment="Site B"

# ۴. Route به شبکه‌ی Site B
/ip route add dst-address=192.168.20.0/24 gateway=10.50.50.2

# ۵. Firewall
/ip firewall filter add chain=input protocol=udp dst-port=13231 \
    action=accept comment="WireGuard"

# ===== Client (Site B) =====

# ۱. Interface
/interface wireguard add name=wg-site

# ۲. IP
/ip address add address=10.50.50.2/30 interface=wg-site

# ۳. Peer (Site A)
/interface wireguard peers add \
    interface=wg-site \
    public-key="SITE_A_PUBLIC_KEY" \
    endpoint-address=203.0.113.1 \
    endpoint-port=13231 \
    allowed-address=10.50.50.1/32,192.168.10.0/24 \
    persistent-keepalive=25s \
    comment="Site A"

# ۴. Route به شبکه‌ی Site A
/ip route add dst-address=192.168.10.0/24 gateway=10.50.50.1

# ===== نتیجه =====
# Site A: 192.168.10.0/24 ↔ Site B: 192.168.20.0/24
# اتصال رمزنگاری‌شده با WireGuard

مثال ۳ — EoIP Tunnel با Bridge

# ===== سناریو: Bridge L2 بین دو دفتر =====

# ===== Router 1 =====
# ۱. EoIP Interface
/interface eoip add \

/interface bridge add name=br-remote

/interface bridge port add bridge=br-remote interface=ether2

# ۳. IP روتر روی Bridge
/ip address add address=192.168.100.2/24 interface=br-remote

# ۱. ساخت Certificate

    name=ca-cert \

    key-usage=tls-server \

/certificate sign sstp-server ca=ca-cert

    enabled=yes \
    default-profile=sstp-profile \
    authentication=mschap2 \
    certificate=sstp-server

# ۵. Firewall
/ip firewall filter add chain=input protocol=tcp dst-port=443 \
    action=accept comment="SSTP on 443"

# 2. Provider: Windows (built-in)

🛠️ کارگاه عملی گام‌به‌گام

  1. دو RouterOS در GNS3 یا EVE-NG با IP عمومی شبیه‌سازی‌شده
  2. IP Pool برای VPN با Subnet 10.99.99.0/24 بساز
  3. PPP Profile با local-address و remote-address بساز
  4. دو PPP Secret بساز: user1 و user2
  5. L2TP Server با IPsec فعال کن
  6. Firewall را برای پورت‌های L2TP/IPsec باز کن
  7. با یک RouterOS Client یا Windows به L2TP وصل شو
  8. با /ppp active print کاربران آنلاین را ببین
  9. SSTP را با Certificate راه‌اندازی کن
  10. با Windows به SSTP وصل شو (بدون نرم‌افزار اضافه)
  11. یک EoIP Tunnel بین دو RouterOS بساز
  12. EoIP را به Bridge اضافه کن و شبکه L2 بساز
  13. WireGuard را روی هر دو RouterOS راه‌اندازی کن
  14. با WireGuard یک Site-to-Site VPN راه بینداز
  15. بین دو شبکه Ping و Traceroute بزن
  16. تمام تونل‌ها را با /interface print ببین
  17. هر پیکربندی را با Export ذخیره کن

🚫 خطاهای رایج و رفع‌اشکال

  • PPP Secret وجود ندارد: کاربر در /ppp secret تعریف نشده.
  • IP Pool تمام شده: Range را افزایش بده یا کاربران بیکار را قطع کن.
  • Authentication Failed: نام کاربری یا رمز اشتباه — حساس به بزرگی و کوچکی.
  • IPsec Secret mismatch: کلید مشترک باید در Server و Client یکسان باشد.
  • Certificate نامعتبر: SSTP و OpenVPN نیاز به Certificate معتبر دارند.
  • Ping روی Tunnel کار نمی‌کند: Route به Subnet مقابل تعریف نشده.
  • MTU مشکل: در تونل‌ها MSS را کم کن: ip firewall mangle.
  • ISP پورت را بلاک می‌کند: از SSTP (TCP/443) یا WireGuard (UDP) استفاده کن.
  • NAT برای VPN Users: VPN Userها بدون NAT به اینترنت نمی‌رسند.
  • WireGuard Peer Up نمی‌شود: Public Key اشتباه یا Endpoint غلط.
  • ZeroTier Authorize نمی‌شود: در ZeroTier Central دستگاه را Authorize کن.
  • L2TP/IPsec با Windows کار نمی‌کند: Registry Fix لازم است — AssumeUDPEncapsulationContextOnSendRule=2.
  • EoIP Tunnel Up نمی‌شود: tunnel-id باید در دو طرف یکسان باشد.
  • GRE با NAT عبور نمی‌کند: از GRE/IPsec استفاده کن یا NAT-T را فعال کن.
  • بعد از Restart تونل قطع می‌شود: Interface را disabled=no بگذار و Route را Static کن.

  • NAT: Masquerade برای VPN Users به اینترنت

  • با OSPF روی تونل، Subnetهای دو طرف را خودکار یاد بگیر.

  • یک Netwatch روی Tunnel بگذار که اگر قطع شد، هشدار بفرستد.

📋 جمع‌بندی و برگه‌تقب

  • VPN: تونل امن بین دو نقطه روی اینترنت عمومی
  • Site-to-Site: اتصال دو LAN — Remote Access: اتصال کاربر
  • PPP: پایه‌ی تمام VPNها — Pool + Profile + Secret
  • PPTP: ناامن — استفاده نکن (TCP/1723 + GRE)
  • L2TP: با IPsec امن — UDP/500، 1701، 4500 + ESP
  • SSTP: روی TCP/443 — از فایروال‌ها عبور می‌کند، نیاز به Certificate
  • OpenVPN: متن‌باز، TCP/1194، نیاز به Certificate
  • EoIP: تونل L2 روی IP — با tunnel-id یکتا، نیاز به IPsec برای امنیت
  • IPIP: تونل L3 ساده و سریع
  • GRE: تونل L3 با پشتیبانی Multicast، با ipsec-secret امن
  • WireGuard: مدرن، سریع، Kernel-based — UDP/13231، persistent-keepalive
  • ZeroTier: بدون IP عمومی، از CGNAT عبور می‌کند
  • Firewall: باز کردن پورت‌های VPN قبل از Drop نهایی
  • NAT: Masquerade برای دسترسی VPN Users به اینترنت
  • Routing: Static Route یا OSPF/BGP روی تونل
  • عیب‌یابی: /ppp active، /log، /interface print، /tool sniffer
