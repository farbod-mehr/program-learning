📘 بدنه‌ی آموزشی

۶.۱ چرا اتوماسیون شبکه؟

شبکه‌های مدرن با چالش‌های جدیدی روبرو هستند:

  • مقیاس: هزاران دستگاه، دستی پیکربندی کردن غیرممکن است
  • سرعت تغییر: کسب‌وکار انتظار تغییرات سریع دارد
  • خطای انسانی: ۷۰٪ از Outageها ناشی از خطای انسانی است
  • یکنواختی: پیکربندی باید بین همه‌ی دستگاه‌ها یکسان باشد
  • هزینه: کار دستی پرهزینه و کند است
💡 مثال واقعی
تغییر یک ACL روی ۲۰۰ روتر با CLI: ۱۰ روز کاری. با Ansible: ۱۰ دقیقه + صفر خطای انسانی.

۶.۳ معماری SDN — سه لایه

SDN (Software-Defined Networking) معماری شبکه را به سه لایه تقسیم می‌کند و Control Plane را از Data Plane جدا می‌سازد:

📱 Application Layer

اپلیکیشن‌های شبکه — Cisco DNA Center، Firewall Management، Load Balancer Controller

↕ از طریق Northbound API (NBI) با Controller صحبت می‌کند

🧠 Control Layer

SDN Controller — مغز شبکه؛ تصمیم‌های مسیریابی و سیاست‌ها

↕ از طریق Southbound API (SBI) با زیرساخت صحبت می‌کند

🔌 Infrastructure Layer

دستگاه‌های فیزیکی و مجازی — روترها، سوئیچ‌ها، فایروال‌ها

دو API کلیدی:

  • Northbound API (NBI): بین Application و Controller — REST API رایج‌ترین. با این API برنامه‌نویس‌ها با شبکه حرف می‌زنند.
  • Southbound API (SBI): بین Controller و دستگاه‌ها — OpenFlow، NETCONF، RESTCONF، SNMP.
┌─────────────────────────────────────────┐
│   Application Layer (DNA Center, etc.)  │
└────────────────┬────────────────────────┘
                 │ Northbound API (REST)
┌────────────────▼────────────────────────┐
│   Control Layer (SDN Controller)        │
└────────────────┬────────────────────────┘
                 │ Southbound API
                 │ (OpenFlow, NETCONF, RESTCONF)
┌────────────────▼────────────────────────┐
│   Infrastructure (Routers, Switches)    │
└─────────────────────────────────────────┘

۶.۴ Control Plane و Data Plane

تفکیک Planeها، پایه‌ی SDN است:

  • Control Plane: تصمیم می‌گیرد بسته کجا برود — پروتکل‌های مسیریابی، جدول‌های مسیریابی
  • Data Plane (Forwarding Plane): بسته را واقعاً ارسال می‌کند — ASIC، جدول Forwarding

در شبکه‌ی سنتی، این دو در یک دستگاه هستند. در SDN، Control Plane از دستگاه جدا می‌شود و در Controller مرکزی قرار می‌گیرد.

۶.۵ Overlay، Underlay و Fabric

  • Underlay: شبکه‌ی فیزیکی زیرین — IP routing، OSPF، BGP
  • Overlay: تونل‌های منطقی روی Underlay — VXLAN، GRE، LISP
  • Fabric: معماری کامل Underlay + Overlay + Control Plane — مثال: SD-Access
ℹ️ مثال ساده
Underlay مثل جاده‌های بین‌شهری است. Overlay مثل اتوبان‌های اختصاصی که روی آن جاده‌ها ساخته می‌شوند. Fabric یعنی کل سیستم حمل و نقل با کنترل مرکزی.

۶.۶ مدل‌های مدیریتی: CLI، SNMP، NETCONF، RESTCONF

NETCONF پروتکلی برای مدیریت دستگاه‌های شبکه با ساختار درختی داده است و از YANG برای مدل‌سازی داده استفاده می‌کند. تراکنشی است (همه یا هیچ).

RESTCONF یک نسخه‌ی ساده‌تر از NETCONF روی HTTP است — مثل REST API کار می‌کند و برای برنامه‌نویس‌ها آسان‌تر است.

۶.۷ REST API — مفاهیم پایه

REST API امروزه محبوب‌ترین روش ارتباط برنامه‌ها با شبکه است. REST یعنی Representational State Transfer.

اصول REST:

  • Stateless: هر درخواست مستقل است
  • Client-Server: جداسازی کامل
  • Cacheable: قابلیت Cache کردن پاسخ‌ها
  • Uniform Interface: رابط یکسان با HTTP Verbs

HTTP Verbs (CRUD):

Verb CRUD توضیح
GETReadخواندن اطلاعات
POSTCreateایجاد منبع جدید
PUTUpdate/Replaceجایگزینی کامل
PATCHUpdateبروزرسانی جزئی
DELETEDeleteحذف منبع

HTTP Status Codes مهم:

  • 200 OK: موفق
  • 201 Created: منبع جدید ساخته شد
  • 400 Bad Request: درخواست اشتباه
  • 401 Unauthorized: احراز هویت لازم
  • 403 Forbidden: دسترسی رد شد
  • 404 Not Found: منبع پیدا نشد
  • 500 Internal Server Error: خطای سرور

۶.۸ فرمت داده‌ها: JSON، XML، YAML

JSON (JavaScript Object Notation): سبک، خوانا، رایج‌ترین در REST API.

{
  "hostname": "R1",
  "interfaces": [
    {
      "name": "Gi0/0",
      "ip": "192.168.1.1",
      "status": "up"
    },
    {
      "name": "Gi0/1",
      "ip": "10.0.0.1",
      "status": "up"
    }
  ]
}

XML: قدیمی‌تر، پرجزئیات‌تر، در NETCONF استفاده می‌شود.

<device>
  <hostname>R1</hostname>
  <interfaces>
    <interface>
      <name>Gi0/0</name>
      <ip>192.168.1.1</ip>
      <status>up</status>
    </interface>
  </interfaces>
</device>

YAML: فوق‌العاده خوانا، در Ansible و Terraform استفاده می‌شود.

device:
  hostname: R1
  interfaces:
    - name: Gi0/0
      ip: 192.168.1.1
      status: up
    - name: Gi0/1
      ip: 10.0.0.1
      status: up
💡 نکته
تفاوت JSON و YAML؟ YAML با Indentation کار می‌کند و برای انسان‌ها خواناتر است. JSON با براکت و آکولاد و برای ماشین‌ها دقیق‌تر. هر دو معادل هستند.

نمونه‌ی اتصال به روتر سیسکو با Netmiko:

from netmiko import ConnectHandler

device = {
    "device_type": "cisco_ios",
    "host": "192.168.1.1",
    "username": "admin",
    "password": "secret",
    "secret": "enable-secret"
}

connection = ConnectHandler(**device)
connection.enable()

output = connection.send_command("show ip interface brief")
print(output)

config_commands = [
    "vlan 10",
    "name HR",
    "exit",
    "interface Gi0/1",
    "switchport mode access",
    "switchport access vlan 10"
]
connection.send_config_set(config_commands)
connection.save_config()

connection.disconnect()

۶.۱۱ IaC — Infrastructure as Code

Infrastructure as Code (IaC) یعنی تعریف زیرساخت به‌صورت کد، به‌جای پیکربندی دستی. مزایا:

  • تکرارپذیری: همان کد، همان نتیجه — همیشه
  • کنترل نسخه: با Git همه‌ی تغییرات قابل ردیابی است
  • همکاری: تیم‌ها روی یک مخزن مشترک کار می‌کنند
  • تست: کد را می‌توان قبل از اعمال، تست کرد
  • مستندسازی: کد، خودش مستند است
🏆 نکته‌ی طلایی
تفاوت IaC با پیکربندی دستی، مثل تفاوت برنامه‌نویسی با کپی‌پیست است. یک بار نوشتن کد درست، هزاران بار اجرای بدون خطا.

۶.۱۲ Cisco DNA Center و SD-Access/SD-WAN

Cisco DNA Center (که حالا به نام Catalyst Center شناخته می‌شود) پلتفرم مرکزی سیسکو برای مدیریت، اتوماسیون و تضمین شبکه است. چهار بخش اصلی:

🎨 Design

طراحی سایت‌ها، تنظیمات شبکه (Network Settings)، Templates

📦 Policy

تعریف سیاست‌ها بر اساس Group (مثلاً Employees، Guests، IoT)

🚀 Provision

پیکربندی خودکار دستگاه‌ها با Template، Plug-and-Play (PnP)

📊 Assurance

پایش Health، عیب‌یابی هوشمند، AI/ML برای پیش‌بینی مشکلات

SD-Access: معماری Campus مدرن سیسکو که بر پایه‌ی LISP و VXLAN ساخته شده و Fabric مرکزی ایجاد می‌کند.

SD-WAN: معماری مدرن WAN که Control Plane و Data Plane را جدا می‌کند. مزایا نسبت به WAN سنتی:

  • مدیریت متمرکز از یک Controller
  • انتخاب بهترین لینک (Broadband، MPLS، LTE) به‌صورت خودکار
  • رمزنگاری End-to-End بدون پیچیدگی DMVPN
  • Zero Touch Provisioning (ZTP)

۶.۱۳ هوش مصنوعی در شبکه

AI و ML در عملیات شبکه (AIOps) کاربردهای جدیدی دارند:

  • Predictive AI: پیش‌بینی خرابی دستگاه قبل از وقوع
  • Generative AI: نوشتن پیکربندی از روی توضیحات متنی (Natural Language)
  • Anomaly Detection: تشخیص ترافیک غیرعادی
  • Automated Remediation: رفع خودکار مشکلات شناخته‌شده

مثال ۲ — Python Script برای پیکربندی چند روتر

from netmiko import ConnectHandler

routers = [
    {"host": "192.168.1.1", "username": "admin", "password": "pass"},
    {"host": "192.168.1.2", "username": "admin", "password": "pass"},
    {"host": "192.168.1.3", "username": "admin", "password": "pass"}
]

config = [
    "interface Loopback0",
    "ip address 10.255.255.1 255.255.255.255",
    "description Managed by Automation",
    "exit"
]

for router in routers:
    conn = ConnectHandler(
        device_type="cisco_ios",
        host=router["host"],
        username=router["username"],
        password=router["password"]
    )
    conn.send_config_set(config)
    conn.save_config()
    print(f"✅ {router['host']} configured")
    conn.disconnect()

مثال ۳ — Ansible Playbook برای Backup خودکار

---
- name: Daily Backup of Cisco Devices
  hosts: cisco_devices
  gather_facts: no
  tasks:
    - name: Get running config
      ios_command:
        commands:
          - show running-config
      register: config_output

    - name: Save to file
      copy:
        content: "{{ config_output.stdout[0] }}"
        dest: "/backups/{{ inventory_hostname }}_{{ ansible_date_time.date }}.cfg"

🛠️ کارگاه عملی گام‌به‌گام

  1. Python 3 را روی سیستم نصب کن (python.org)
  2. با pip install netmiko requests کتابخانه‌ها را نصب کن
  3. در GNS3 یا Packet Tracer سه روتر بساز و SSH را روی آن‌ها فعال کن
  4. یک اسکریپت Python بنویس که به هر سه روتر وصل شود و show ip interface brief بگیرد
  5. نتیجه را در یک فایل متنی ذخیره کن
  6. اسکریپت را توسعه بده که روی هر روتر Loopback0 پیکربندی کند
  7. Ansible را نصب کن (pip install ansible)
  8. یک Inventory file با آی‌پی روترها بساز
  9. یک Playbook ساده بنویس که روی همه‌ی روترها VLAN 100 ایجاد کند
  10. Playbook را اجرا کن و خروجی را بررسی کن
  11. یک اسکریپت Python بنویس که با REST API، اطلاعات دستگاه‌ها را از یک Controller شبیه‌سازی‌شده (یا DevNet Sandbox) بگیرد
  12. پاسخ JSON را Parse کن و در Console گزارش بده
  13. همه‌ی کدها را در یک Git Repository قرار بده (GitHub یا GitLab)
  14. یک README.md برای مستندسازی پروژه بنویس

🚫 خطاهای رایج و رفع‌اشکال

  • اتصال SSH در Netmiko نمی‌گیرد: چک کن SSH روی روتر فعال است و device_type درست انتخاب شده.
  • Python Script کند اجرا می‌شود: از paramiko بدون Pool استفاده می‌کنی — Nornir یا Thread Pool بگذار.
  • REST API خطای 401 می‌دهد: Token منقضی شده — دوباره احراز هویت کن.
  • JSON Parse Error: داده‌ی دریافتی کامل نیست یا ساختار متفاوت است — print(response.text) بزن و ببین.
  • Ansible به روتر وصل نمی‌شود: Inventory و Credential را چک کن، روی روتر SSH فعال باشد.
  • YAML Syntax Error: Indentation با Space (نه Tab) باشد.
  • پیکربندی اشتباه اتوماسیون همه‌ی دستگاه‌ها را خراب می‌کند: همیشه اول روی یک دستگاه تست کن، سپس Roll Out کن.
  • Backupها Overwrite می‌شوند: از timestamp در نام فایل استفاده کن (مثلاً Date).

📋 جمع‌بندی و برگه‌تقب

  • SDN: جدا کردن Control Plane از Data Plane
  • سه لایه SDN: Application، Control، Infrastructure
  • NBI: بین Application و Controller (معمولاً REST)
  • SBI: بین Controller و دستگاه‌ها (OpenFlow، NETCONF، RESTCONF)
  • Overlay vs Underlay: تونل‌های منطقی vs شبکه‌ی فیزیکی
  • REST API: Stateless، مبتنی بر HTTP Verbs
  • HTTP Verbs: GET (Read)، POST (Create)، PUT (Update)، DELETE (Delete)
  • Status Codes: 200 OK، 201 Created، 401 Unauthorized، 404 Not Found، 500 Server Error
  • JSON/YAML/XML: فرمت‌های داده؛ JSON و YAML رایج‌ترند
  • NETCONF: SSH/830، XML، تراکنشی — RESTCONF: HTTPS، JSON/XML
  • Ansible: Push، Agentless، YAML Playbook — Puppet/Chef: Pull، Agent-based
  • Python + Netmiko: ساده‌ترین راه ورود به اتوماسیون
  • IaC: تعریف زیرساخت به‌صورت کد، با Git و CI/CD
  • Cisco DNA Center: Design، Policy، Provision، Assurance
  • SD-Access: بر پایه LISP + VXLAN — SD-WAN: Control/Data Plane جدا
  • AIOps: Predictive، Generative، Anomaly Detection، Remediation
