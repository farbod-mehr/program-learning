📘 بدنه‌ی آموزشی

۵.۱ مفاهیم پایه امنیت — CIA Triad

امنیت اطلاعات بر پایه‌ی سه اصل است که به آن CIA Triad می‌گویند:

اصل توضیح تهدید نمونه
Confidentiality اطلاعات فقط برای افراد مجاز قابل دسترسی باشد Eavesdropping، Sniffing
Integrity داده‌ها بدون اجازه تغییر نکنند MITM، Tampering
Availability سرویس همیشه در دسترس باشد DoS، DDoS، Ransomware

۵.۲ انواع تهدیدات و حملات رایج

دسته‌بندی حملات:

  • Reconnaissance: جمع‌آوری اطلاعات (Ping Sweep، Port Scan)
  • Access Attacks: دسترسی غیرمجاز (Password Attack، Trust Exploitation)
  • DoS/DDoS: از کار انداختن سرویس
  • Malware: ویروس، Worm، Trojan، Ransomware
  • Social Engineering: فریب کاربر (Phishing، Pretexting)

حملات خاص لایه ۲:

حمله توضیح دفاع
MAC Flooding پر کردن جدول CAM → سوئیچ Flood می‌کند Port Security
MAC Spoofing جعل MAC خود به‌عنوان MAC مجاز Port Security Sticky
VLAN Hopping دسترسی به VLANهای دیگر از طریق Trunk Native VLAN اختصاصی + switchport mode access
DHCP Spoofing راه‌اندازی DHCP سرور جعلی → دستکاری Gateway DHCP Snooping
ARP Spoofing جعل ARP → MITM Dynamic ARP Inspection
STP Attack ارسال BPDU جعلی → تغییر Root Bridge BPDU Guard، Root Guard
CDP/LLDP Recon افشای اطلاعات دستگاه از طریق CDP غیرفعال روی پورت‌های Edge

۵.۳ سه Plane امنیتی

در Cisco IOS، سه Planes داریم که هرکدام سطح حمله جداگانه‌ای دارند:

🧠 Management Plane

مدیریت دستگاه — SSH، SNMP، Syslog، AAA. اگر این لایه امن نباشد، کل دستگاه در خطر است.

⚙️ Control Plane

پروتکل‌های مسیریابی و سوئیچینگ — OSPF، EIGRP، BGP، STP. حمله به این لایه همگرایی شبکه را می‌شکند. دفاع: CoPP.

📦 Data Plane

ترافیک کاربران. حمله: سیل بسته. دفاع: ACL، uRPF، QoS.

۵.۴ Hardening پایه دستگاه‌ها

حداقل‌های امن‌سازی هر روتر/سوئیچ سیسکو:

! ۱. تنظیم Hostname
Router(config)# hostname R1

! ۲. رمز Enable (بدون رمز، دستگاه کاملاً بی‌دفاع است)
Router(config)# enable secret StrongP@ss123
! enable secret از MD5/SHA استفاده می‌کند، بهتر از enable password

! ۳. رمز خطوط Console و VTY
Router(config)# line console 0
Router(config-line)# password ConsoleP@ss
Router(config-line)# login
Router(config-line)# exec-timeout 5 0
Router(config-line)# logging synchronous
Router(config-line)# exit

Router(config)# line vty 0 4
Router(config-line)# password VtyP@ss
Router(config-line)# login
Router(config-line)# exec-timeout 5 0
Router(config-line)# transport input ssh
Router(config-line)# exit

! ۴. رمزنگاری رمزهای Plain-text
Router(config)# service password-encryption

! ۵. Banner هشدار
Router(config)# banner motd ^
*********************************************************
*  Unauthorized access is prohibited!                  *
*  All activity is monitored and logged.               *
*********************************************************
^

! ۶. رمزگذاری در Config
Router(config)# service password-encryption
Router(config)# security passwords min-length 8

! ۷. جلوگیری از تلاش‌های Brute Force
Router(config)# login block-for 120 attempts 3 within 60

! ۸. غیرفعال کردن سرویس‌های بی‌استفاده
Router(config)# no ip http server
Router(config)# no ip http secure-server
Router(config)# no cdp run
Router(config)# no ip source-route
Router(config)# no ip finger
Router(config)# no service tcp-small-servers
Router(config)# no service udp-small-servers

! ۹. همگام‌سازی زمان (برای لاگ دقیق)
Router(config)# clock timezone IRST +3 30
Router(config)# ntp server pool.ntp.org

! ۱۰. ذخیره
Router# write memory
🏆 نکته‌ی طلایی
همیشه از enable secret استفاده کن — نه enable password. چون enable password در Config به‌صورت Plain-text یا با رمزنگاری ضعیف Type 7 ذخیره می‌شود.

۵.۵ پیکربندی SSH (جایگزین Telnet)

SSH ترافیک مدیریتی را رمزنگاری می‌کند، درحالی‌که Telnet تمام داده (شامل رمز) را Plain-text ارسال می‌کند. 

! ===== پیکربندی کامل SSH =====

! ۱. Hostname و Domain Name (الزامی برای RSA Key)
Router(config)# hostname R1
Router(config)# ip domain-name example.local

! ۲. تولید کلید RSA (حداقل 1024 بیت، توصیه 2048)
Router(config)# crypto key generate rsa modulus 2048
! پیام تأیید: How many bits in the modulus [512]: 2048

! ۳. تعریف کاربر محلی
Router(config)# username admin privilege 15 secret AdminP@ss123

! ۴. تعیین SSH Version 2
Router(config)# ip ssh version 2

! ۵. تنظیم Timeout و Authentication Retries
Router(config)# ip ssh time-out 60
Router(config)# ip ssh authentication-retries 3

! ۶. محدود کردن VTY به SSH
Router(config)# line vty 0 4
Router(config-line)# transport input ssh
Router(config-line)# login local
Router(config-line)# exec-timeout 5 0
Router(config-line)# exit

! ۷. (اختیاری) دسترسی SSH فقط از یک Subnet خاص
Router(config)# access-list 50 permit 192.168.1.0 0.0.0.255
Router(config)# line vty 0 4
Router(config-line)# access-class 50 in

! بررسی
Router# show ip ssh
Router# show ssh
Router# show crypto key mypubkey rsa

! تست از PC
C:\> ssh -l admin 192.168.1.1
⚠️ هشدار
اگر transport input ssh را روی VTY ست کنی و SSH به‌درستی پیکربندی نشده باشد، دسترسی از راه دور را برای همیشه از دست می‌دهی! حتماً قبل از این کار SSH را تست کن.

۵.۶ AAA — Authentication, Authorization, Accounting

AAA یک چارچوب مدیریت دسترسی است که سه بخش دارد:

  • Authentication: «تو کی هستی؟» — تأیید هویت
  • Authorization: «چه کاری می‌تونی بکنی؟» — تعیین سطح دسترسی
  • Accounting: «چه کاری کردی؟» — ثبت فعالیت‌ها

روش‌های پیاده‌سازی:

  • Local: روی خود دستگاه (username/password محلی)
  • TACACS+: سرور اختصاصی سیسکو — کل بسته رمزنگاری می‌شود، TCP/49
  • RADIUS: استاندارد باز — فقط Password رمزنگاری می‌شود، UDP/1645 یا 1812
ویژگی TACACS+ RADIUS
استانداردCiscoIETF / RFC
TransportTCP/49UDP/1812, 1813
رمزنگاریکل بستهفقط Password
AAA جدا✅ Auth، Authz، Acct جداAuth و Authz با هم
کاربرد اصلیمدیریت دستگاه‌های سیسکودسترسی کاربران شبکه (802.1X)
 
! پیکربندی AAA با TACACS+
Router(config)# aaa new-model
Router(config)# tacacs-server host 192.168.1.100 key SharedSecret123
Router(config)# aaa authentication login default group tacacs+ local
Router(config)# aaa authorization exec default group tacacs+ local
Router(config)# aaa accounting exec default start-stop group tacacs+
Router(config)# username fallback privilege 15 secret FallbackP@ss
! fallback local: اگر سرور TACACS از دسترس خارج شد، از یوزر محلی استفاده می‌شود

! بررسی
Router# show aaa servers
Router# show aaa authentication
Router# test aaa group tacacs+ admin Pass123 new-code

۵.۷ انواع ACL

ACL (Access Control List) یک لیست ترتیبی از قوانین Permit/Deny است که ترافیک را فیلتر می‌کند. بدون ACL، هیچ کنترلی روی عبور ترافیک نداریم.

سه نوع اصلی:

📌 Standard ACL

فقط Source IP را فیلتر می‌کند. شماره: 1-99 و 1300-1999. باید نزدیک به Destination اعمال شود.

access-list 10 permit 192.168.1.0 0.0.0.255
access-list 10 deny any
📌 Extended ACL

فیلتر کامل: Source، Destination، Protocol، Port. شماره: 100-199 و 2000-2699. باید نزدیک به Source اعمال شود.

access-list 100 permit tcp 192.168.1.0 0.0.0.255 any eq 80
access-list 100 permit tcp 192.168.1.0 0.0.0.255 any eq 443
access-list 100 deny ip any any log
📌 Named ACL

ACL با اسم توصیفی، ویرایش ساده‌تر (می‌توانی خطی حذف/اضافه کنی).

ip access-list extended WEB-ACCESS
 permit tcp 192.168.1.0 0.0.0.255 any eq 80
 permit tcp 192.168.1.0 0.0.0.255 any eq 443
 deny   ip any any log
⚠️ قواعد حیاتی ACL
  • در انتهای هر ACL، Deny Any به‌صورت نامرئی وجود دارد
  • ترتیب قوانین بسیار مهم است — از خاص به عام
  • هر ACL جدید باید حداقل یک Permit داشته باشد، وگرنه همه چیز Block می‌شود
  • ویرایش ACL شماره‌دار سخت است — از Named استفاده کن

۵.۸ اعمال ACL روی اینترفیس

! اعمال روی اینترفیس (In یا Out)
Router(config)# interface Gi0/0
Router(config-if)# ip access-group 100 in
Router(config-if)# exit

! Standard ACL نزدیک Destination اعمال می‌شود
Router(config)# interface Gi0/1
Router(config-if)# ip access-group 10 out

! بررسی
Router# show access-lists
Router# show ip access-lists
Router# show ip interface Gi0/0
Router# show ip interface Gi0/0 | include access list

In vs Out:

  • In: ترافیک ورودی به اینترفیس را فیلتر می‌کند — بهینه‌تر است (قبل از پردازش مسیریابی)
  • Out: ترافیک خروجی از اینترفیس را فیلتر می‌کند
! مثال: اجازه HTTP/HTTPS به اینترنت، بلاک بقیه
Router(config)# ip access-list extended INTERNET-ACCESS
Router(config-ext-nacl)# permit tcp 192.168.1.0 0.0.0.255 any eq 80
Router(config-ext-nacl)# permit tcp 192.168.1.0 0.0.0.255 any eq 443
Router(config-ext-nacl)# permit udp 192.168.1.0 0.0.0.255 any eq 53
Router(config-ext-nacl)# deny   ip any any log
Router(config-ext-nacl)# exit

Router(config)# interface Gi0/1
Router(config-if)# ip access-group INTERNET-ACCESS in

۵.۹ Wildcard Mask — قلب ACL

Wildcard Mask برعکس Subnet Mask است: 0 = باید دقیقاً مطابقت داشته باشد، 1 = مهم نیست (Don't Care).

Subnet Mask Wildcard Mask توضیح
255.255.255.2550.0.0.0یک هاست مشخص
255.255.255.00.0.0.255/24
255.255.0.00.0.255.255/16
—255.255.255.255هر آدرسی (any)
 
! معادل‌ها
access-list 10 permit 192.168.1.5 0.0.0.0
! = فقط 192.168.1.5
! می‌توانی بنویسی: access-list 10 permit host 192.168.1.5

access-list 10 permit 0.0.0.0 255.255.255.255
! = هر آدرسی
! می‌توانی بنویسی: access-list 10 permit any

! مثال دقیق‌تر — فقط رنج 192.168.1.0 تا 192.168.1.15
access-list 10 permit 192.168.1.0 0.0.0.15
💡 محاسبه‌ی سریع Wildcard
Wildcard = 255.255.255.255 منهای Subnet Mask. مثال: /26 → Mask 255.255.255.192 → Wildcard 0.0.0.63

۵.۱۰ Port Security پیشرفته

۵.۱۱ DHCP Snooping

DHCP Snooping جلوی حملات Rogue DHCP Server را می‌گیرد. سوئیچ پورت‌ها را به دو دسته تقسیم می‌کند:

  • Trusted Port: پورت به سرور DHCP یا Uplink (اجازه DHCP Offer)
  • Untrusted Port: پورت‌های Edge (فقط DHCP Discover/Request)
! فعال‌سازی سراسری
Switch(config)# ip dhcp snooping
Switch(config)# ip dhcp snooping vlan 10,20,30

! تعیین پورت‌های Trusted (به سمت سرور DHCP یا Uplink)
Switch(config)# interface Gi0/24
Switch(config-if)# ip dhcp snooping trust
Switch(config-if)# exit

! (اختیاری) Rate Limiting روی پورت‌های Untrusted
Switch(config)# interface range Gi0/1-23
Switch(config-if-range)# ip dhcp snooping limit rate 10
Switch(config-if-range)# exit

! بررسی
Switch# show ip dhcp snooping
Switch# show ip dhcp snooping binding
Switch# show ip dhcp snooping statistics

! نکته: DHCP Snooping خودش جدول MAC-to-IP می‌سازد که DAI از آن استفاده می‌کند

۵.۱۲ Dynamic ARP Inspection (DAI)

DAI جلوی ARP Spoofing را می‌گیرد. از جدول DHCP Snooping استفاده می‌کند تا بفهمد کدام MAC به کدام IP مجاز است. 

! پیش‌نیاز: DHCP Snooping فعال باشد
Switch(config)# ip dhcp snooping
Switch(config)# ip dhcp snooping vlan 10,20

! فعال‌سازی DAI روی VLANها
Switch(config)# ip arp inspection vlan 10,20

! تعیین پورت‌های Trusted
Switch(config)# interface Gi0/24
Switch(config-if)# ip arp inspection trust
Switch(config-if)# exit

! (اختیاری) Rate Limiting
Switch(config)# interface range Gi0/1-23
Switch(config-if-range)# ip arp inspection limit rate 15
Switch(config-if-range)# exit

! (اختیاری) ARP ACL برای هاست‌های Static
Switch(config)# arp access-list STATIC-HOSTS
Switch(config-arp-nacl)# permit ip host 192.168.10.5 mac host 0050.7966.6801
Switch(config-arp-nacl)# exit
Switch(config)# ip arp inspection filter STATIC-HOSTS vlan 10

! بررسی
Switch# show ip arp inspection
Switch# show ip arp inspection statistics
Switch# show ip arp inspection interfaces

۵.۱۳ 802.1X — کنترل دسترسی به پورت

802.1X یک استاندارد IEEE است که احراز هویت را قبل از دسترسی به شبکه انجام می‌دهد. سه مؤلفه دارد:

  • Supplicant: کلاینت (PC با نرم‌افزار 802.1X)
  • Authenticator: سوئیچ
  • Authentication Server: معمولاً RADIUS
! پیکربندی 802.1X روی سوئیچ
Switch(config)# aaa new-model
Switch(config)# aaa authentication dot1x default group radius
Switch(config)# radius-server host 192.168.1.100 key RadiusSecret

Switch(config)# dot1x system-auth-control

Switch(config)# interface Gi0/5
Switch(config-if)# switchport mode access
Switch(config-if)# authentication port-control auto
Switch(config-if)# dot1x pae authenticator
Switch(config-if)# exit

! بررسی
Switch# show dot1x all
Switch# show authentication sessions

۵.۱۴ لایه‌های امنیتی اضافی

uRPF (Unicast Reverse Path Forwarding):

! جلوگیری از IP Spoofing روی اینترفیس خارجی
Router(config)# interface Gi0/1
Router(config-if)# ip verify unicast source reachable-via rx
! rx = Strict Mode (مسیر برگشت باید از همان اینترفیس باشد)
! any = Loose Mode

CoPP (Control Plane Policing):

! محافظت از CPU روتر در برابر حملات DoS
Router(config)# class-map match-all CRITICAL
Router(config-cmap)# match access-group 100
Router(config-cmap)# exit

Router(config)# policy-map CoPP-POLICY
Router(config-pmap)# class CRITICAL
Router(config-pmap-c)# police 8000 conform-action transmit exceed-action drop
Router(config-pmap)# exit

Router(config)# control-plane
Router(config-cp)# service-policy input CoPP-POLICY

IP Source Guard:

! فقط به IPهایی که در جدول DHCP Snooping هستند اجازه ترافیک می‌دهد
Switch(config)# interface Gi0/5
Switch(config-if)# ip verify source
! بررسی
Switch# show ip verify source

💡 نکته‌ی کاربردی

ℹ️ اطلاعات بیشتر
در فصل ۶ با SDN، REST API و اتوماسیون شبکه آشنا می‌شوی.
🔮 دیدگاه پیشرفته
در CCNP با CoPP، uRPF و IPv6 First Hop Security سطح امنیت را حرفه‌ای‌تر می‌کنی.

🛠️ کارگاه عملی گام‌به‌گام

  1. در Packet Tracer یک روتر 4331 + یک سوئیچ 2960 + ۳ PC اضافه کن
  2. روتر Hostname = EDGE-R1، سوئیچ Hostname = SW1
  3. روی هر دو دستگاه: enable secret، username admin، service password-encryption
  4. روی هر دو: Banner MOTD با هشدار
  5. روی هر دو: SSH فعال کن (RSA 2048، SSH v2، login local، transport input ssh)
  6. روی هر دو: exec-timeout 5 0 برای Console و VTY
  7. روی روتر: no ip http server، no cdp run، no ip source-route
  8. روی سوئیچ: روی پورت‌های Edge، no cdp enable
  9. یک ACL Extended بنویس که: PC1 به HTTP/HTTPS اجازه داشته باشد ولی PC2 به Telnet نداشته باشد
  10. ACL را روی اینترفیس Gi0/0 روتر اعمال کن (in)
  11. روی سوئیچ: Port Security روی پورت PC2 با max=1، sticky، violation=shutdown
  12. DHCP Snooping روی VLAN 10 با Gi0/24 به‌عنوان Trusted فعال کن
  13. DAI روی VLAN 10 با همان Trusted فعال کن
  14. از PC1 با SSH به روتر وصل شو، ACL و Port Security را تست کن

🚫 خطاهای رایج و رفع‌اشکال

  • SSH کار نمی‌کند: Hostname و Domain Name ست شده؟ RSA Key تولید شده؟ ip ssh version 2 فعال است؟
  • بعد از transport input ssh قفل شدی: از Console وارد شو و transport input all بزن.
  • ACL همه ترافیک را Drop می‌کند: فراموش کردی permit بگذاری یا Order اشتباه است.
  • ACL اعمال نمی‌شود: چک کن ip access-group روی اینترفیس درست با جهت (in/out) صحیح.
  • Wildcard Mask اشتباه: اشتباه رایج — 0.0.0.0 یعنی یک IP، نه هر IP.
  • Port Security پورت را err-disable کرده: با shutdown/no shutdown بازیابی یا با errdisable recovery خودکار.
  • DHCP Snooping ترافیک را می‌بندد: اگر Uplink Trusted نباشد، DHCP Clientها IP نمی‌گیرند.
  • DAI ترافیک را Drop می‌کند: پیش‌نیاز آن DHCP Snooping است و باید Binding داشته باشد.
  • TACACS+ کار نمی‌کند: Shared Secret دو طرف یکسان باشد، پورت TCP/49 باز باشد.

🎯 پروژه‌ی پایانی فصل

یک شبکه‌ی سازمانی کوچک امن بساز:

  • یک روتر Edge + یک سوئیچ L2 + ۳ PC + یک سرور RADIUS (شبیه‌سازی)
  • روی روتر: Hardening کامل (enable secret، SSH v2، Banner، exec-timeout، login block-for)
  • روی روتر: غیرفعال کردن سرویس‌های بی‌استفاده (HTTP، CDP، Finger، Source-Route)
  • روی روتر: ACL Extended که فقط HTTP/HTTPS/DNS را اجازه می‌دهد
  • روی روتر: ACL روی VTY برای محدود کردن SSH به یک Subnet مدیریتی
  • روی سوئیچ: Port Security روی همه‌ی پورت‌های Access (max=2، sticky، restrict)
  • روی سوئیچ: DHCP Snooping فعال روی VLAN 10
  • روی سوئیچ: Dynamic ARP Inspection روی VLAN 10
  • روی سوئیچ: IP Source Guard روی پورت‌های Edge
  • روی روتر: uRPF روی اینترفیس خارجی (Strict Mode)
  • تست: SSH از PC به روتر، بررسی لاگ‌ها، تست ACL
🏆 چالش اضافه
  • یک حمله Rogue DHCP Server را شبیه‌سازی کن و ببین DHCP Snooping چطور آن را بلاک می‌کند.
  • یک ARP Spoofing از PC مهاجم انجام بده و ببین DAI چطور Drop می‌کند.
  • یک Banner زیبا با نام سازمان و اطلاعات تماس امنیتی طراحی کن.

📋 جمع‌بندی و برگه‌تقب

  • CIA Triad: Confidentiality، Integrity، Availability
  • سه Plane: Management، Control، Data — هرکدام دفاع متفاوتی دارند
  • Hardening حداقلی: enable secret، SSH، Banner، exec-timeout، service password-encryption
  • SSH لازم دارد: Hostname + Domain + RSA Key + SSH v2 + login local
  • AAA: Authentication + Authorization + Accounting
  • TACACS+: TCP/49، کل بسته رمزنگاری — RADIUS: UDP/1812، فقط Password
  • Standard ACL: 1-99، فقط Source، نزدیک Destination
  • Extended ACL: 100-199، کامل، نزدیک Source
  • ACL Implicit Deny: در انتهای هر ACL وجود دارد
  • Wildcard: 0 = Exact، 1 = Don't Care، 255.255.255.255 = any
  • Port Security: Protect (Drop)، Restrict (Drop+Log)، Shutdown (err-disable)
  • DHCP Snooping: فقط Trusted اجازه DHCP Offer
  • DAI: از Binding DHCP Snooping استفاده می‌کند
  • uRPF: Strict (مسیر برگشت از همان اینترفیس)، Loose (فقط در جدول باشد)
  • CoPP: محافظت از CPU روتر در برابر DoS
