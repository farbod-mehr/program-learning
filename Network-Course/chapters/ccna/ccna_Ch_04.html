📘 بدنه‌ی آموزشی

۴.۱ مفهوم NAT و چرا به آن نیاز داریم

NAT (Network Address Translation) یک تکنیک است که آدرس‌های خصوصی (RFC 1918) را در مرز شبکه به آدرس عمومی ترجمه می‌کند و برعکس.

دلایل نیاز به NAT:

  • کمبود IPv4: 4.3 میلیارد آدرس برای ~۲۰ میلیارد دستگاه کافی نیست
  • صرفه‌جویی: هزاران دستگاه داخلی با یک IP عمومی کار می‌کنند
  • امنیت: آدرس‌های داخلی از دید بیرون مخفی می‌مانند
  • انعطاف: تغییر شبکه‌ی داخلی نیازی به تغییر IP عمومی ندارد
⚠️ محدودیت‌های NAT
  • پروتکل‌هایی که IP را داخل Payload جا می‌دهند (مثل FTP Active و SIP) ممکن است مشکل بخورند.
  • End-to-End Connectivity از بین می‌رود — دستگاه بیرونی نمی‌تواند مستقیم با داخلی حرف بزند.
  • Overhead پردازشی روی روتر بالاتر می‌رود.
  • لاگ‌گیری و Trace سخت‌تر می‌شود.

اصطلاحات مهم NAT:

  • Inside Local: آدرس واقعی دستگاه داخلی (مثلاً 192.168.1.10)
  • Inside Global: آدرس عمومی که دستگاه داخلی به بیرون نشان داده می‌شود
  • Outside Local: آدرس دستگاه بیرونی از دید داخل (معمولاً یکسان)
  • Outside Global: آدرس واقعی دستگاه بیرونی روی اینترنت

۴.۲ انواع NAT

🔒 Static NAT (1-to-1)

یک IP داخلی ↔ یک IP عمومی. برای سرورهای عمومی (Web، Mail) کاربرد دارد.

Router(config)# ip nat inside source static 192.168.1.10 203.0.113.10
♻️ Dynamic NAT (Many-to-Many)

مجموعه‌ای از IPهای داخلی با مجموعه‌ای از IPهای عمومی ترجمه می‌شوند. اول Pool تمام شود، دستگاه‌های بعدی NAT نمی‌شوند.

Router(config)# ip nat pool PUB 203.0.113.1 203.0.113.10 netmask 255.255.255.0
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255
Router(config)# ip nat inside source list 1 pool PUB
🏆 PAT / NAT Overload (Many-to-One)

همه‌ی دستگاه‌های داخلی از یک IP عمومی با پورت‌های متفاوت استفاده می‌کنند — رایج‌ترین نوع NAT.

Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255
Router(config)# ip nat inside source list 1 interface Gi0/1 overload
نوع نگاشت کاربرد
Static NAT1:1سرورهای عمومی
Dynamic NATN:Nشبکه‌های متوسط
PAT / OverloadN:1شبکه‌های خانگی و سازمانی

۴.۳ پیکربندی NAT/PAT — گام به گام

هر پیکربندی NAT سه بخش دارد: مشخص کردن Inside، مشخص کردن Outside، و تعریف قانون NAT.

! ===== پیکربندی PAT (رایج‌ترین) =====

! گام ۱: تعیین اینترفیس‌های داخل و خارج
Router(config)# interface Gi0/0
Router(config-if)# ip nat inside
Router(config-if)# exit

Router(config)# interface Gi0/1
Router(config-if)# ip nat outside
Router(config-if)# exit

! گام ۲: تعریف ACL برای شبکه‌ی داخلی
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255

! گام ۳: فعال‌سازی NAT با Overload
Router(config)# ip nat inside source list 1 interface Gi0/1 overload

! بررسی
Router# show ip nat translations
Router# show ip nat statistics
Router# show ip nat translations verbose
Router# clear ip nat translation *
💡 نکته
کلمه‌ی overload در انتهای دستور، همان PAT است. بدون آن، فقط Dynamic NAT ساده داری.

⚠️ اشکالات رایج NAT
  • فراموش کردن ip nat inside یا ip nat outside روی اینترفیس‌ها
  • ACL اشتباه — هیچ ترافیکی اجازه ندارد
  • Interface اشتباه برای Overload — باید Outside باشد
  • Overlapping بین شبکه‌ی داخلی و خارجی — نیاز به NAT روی هر دو طرف

۴.۵ DHCP Server در سیسکو

DHCP به‌طور خودکار IP، Gateway، DNS و سایر پارامترها را به کلاینت‌ها می‌دهد. یک سرور DHCP در سیسکو شامل: 

! گام ۱: حذف پیکربندی‌های پیش‌فرض (مثلاً DHCP Pool پیش‌فرض)
Router(config)# no ip dhcp pool LAN

! گام ۲: ایجاد Pool و تعریف شبکه
Router(config)# ip dhcp pool LAN
Router(dhcp-config)# network 192.168.1.0 255.255.255.0
Router(dhcp-config)# default-router 192.168.1.1
Router(dhcp-config)# dns-server 8.8.8.8 1.1.1.1
Router(dhcp-config)# domain-name example.local
Router(dhcp-config)# lease 7
Router(dhcp-config)# exit

! گام ۳: حذف آدرس‌هایی که نباید توزیع شوند
Router(config)# ip dhcp excluded-address 192.168.1.1 192.168.1.20
Router(config)# ip dhcp excluded-address 192.168.1.254

! بررسی
Router# show ip dhcp binding
Router# show ip dhcp pool
Router# show ip dhcp server statistics

۴.۶ DHCP Relay (IP Helper-Address)

اگر سرور DHCP در یک Subnet دیگر باشد، روتر نمی‌تواند Broadcast کلاینت را به آن برساند. راه‌حل: DHCP Relay Agent. 

! روی اینترفیس نزدیک به کلاینت (Subnet کلاینت)
Router(config)# interface Gi0/0
Router(config-if)# ip helper-address 192.168.100.5
! آدرس سرور DHCP در Subnet دیگر

! بررسی
Router# show ip interface Gi0/0 | include helper
ℹ️ نکته‌ی کاربردی
دستور ip helper-address به‌طور پیش‌فرض چند UDP Port را Forward می‌کند: DHCP، TFTP، DNS، NetBIOS، TACACS و... فقط برای DHCP می‌خواهی؟ با no ip forward-protocol udp سایر سرویس‌ها را حذف کن.

۴.۷ DNS و تنظیمات Client

DNS نام دامنه را به IP ترجمه می‌کند. روتر سیسکو می‌تواند به‌عنوان DNS Client یا DNS Server کار کند. 

! تنظیم روتر به‌عنوان DNS Client
Router(config)# ip domain-lookup
Router(config)# ip name-server 8.8.8.8
Router(config)# ip name-server 1.1.1.1

! تست
Router# ping google.com
Router# show hosts

! غیرفعال کردن DNS Lookup (برای جلوگیری از تایپ اشتباه)
Router(config)# no ip domain-lookup
💡 نکته
وقتی در CLI سیسکو یک دستور اشتباه تایپ کنی، روتر تلاش می‌کند آن را به‌عنوان نام DNS ترجمه کند و چند ثانیه معطل می‌شود. با no ip domain-lookup این معطلی را حل کن.

۴.۸ NTP — همگام‌سازی زمان

NTP (Network Time Protocol) زمان همه‌ی دستگاه‌ها را هماهنگ می‌کند. زمان دقیق برای لاگ‌ها، گواهی‌های SSL، Kerberos و پایش شبکه حیاتی است. 

! روتر به‌عنوان NTP Client
Router(config)# ntp server 216.239.35.0
Router(config)# ntp server time.google.com
Router(config)# ntp master 5      ! اگر خودت سرور زمانی، با Stratum 5

! تعیین Timezone و Daylight Saving
Router(config)# clock timezone IRST +3 30
Router(config)# clock summer-time IRDT recurring

! بررسی
Router# show ntp status
Router# show ntp associations
Router# show clock
Router# show clock detail
Stratum توضیح
0دستگاه مرجع مثل ساعت اتمی
1مستقیم به Stratum 0 وصل است
2از Stratum 1 می‌گیرد
15حداکثر فاصله از منبع اصلی
16همگام نیست

۴.۱۰ SNMP و Syslog

SNMP برای پایش و مدیریت متمرکز دستگاه‌های شبکه استفاده می‌شود.

! SNMPv2c (ساده ولی ناامن)
Router(config)# snmp-server community PUBLIC ro
Router(config)# snmp-server community PRIVATE rw
Router(config)# snmp-server host 192.168.1.100 version 2c PUBLIC
Router(config)# snmp-server location Tehran-DC1
Router(config)# snmp-server contact admin@example.com

! SNMPv3 (امن - توصیه‌شده)
Router(config)# snmp-server group ADMINS v3 priv
Router(config)# snmp-server user admin ADMINS v3 auth sha AuthPass123 priv aes 128 PrivPass123

! بررسی
Router# show snmp
Router# show snmp community

Syslog برای ارسال لاگ‌ها به سرور مرکزی:

Router(config)# logging host 192.168.1.100
Router(config)# logging trap informational
Router(config)# logging source-interface Gi0/0
Router(config)# service timestamps log datetime msec localtime show-timezone

۴.۱۱ QoS — مفاهیم پایه

QoS (Quality of Service) مجموعه‌ای از تکنیک‌هاست برای مدیریت ترافیک و اولویت‌بندی آن — مخصوصاً در لینک‌های اشباع.

سه مدل QoS:

  • Best Effort: بدون تضمین — پیش‌فرض اینترنت
  • Integrated Services (IntServ): رزرو منابع End-to-End — مقیاس‌ناپذیر
  • Differentiated Services (DiffServ): دسته‌بندی ترافیک بر اساس DSCP — مقیاس‌پذیر و رایج

مفاهیم کلیدی:

  • Classification: شناسایی نوع ترافیک (VoIP، Video، Data)
  • Marking: علامت‌گذاری بسته‌ها (DSCP یا CoS)
  • Queuing: صف‌بندی در اینترفیس خروجی
  • Policing: محدود کردن نرخ ترافیک (Drop یا Remark)
  • Shaping: تأخیر و صاف کردن ترافیک (Buffer)

DSCP (Differentiated Services Code Point): ۶ بیت در هدر IP که نوع سرویس را مشخص می‌کند. مقادیر مهم:

DSCP نام کاربرد
46 (EF)Expedited ForwardingVoIP (بحرانی)
34 (AF41)Assured Forwardingویدیو کنفرانس
26 (AF31)Assured ForwardingStreaming ویدیو
0 (BE)Best Effortترافیک عمومی
 
! نمونه: Marking VoIP روی روتر
Router(config)# class-map match-any VOICE
Router(config-cmap)# match protocol rtp audio
Router(config-cmap)# match access-group name VOICE-ACL

Router(config)# policy-map QoS-POLICY
Router(config-pmap)# class VOICE
Router(config-pmap-c)# priority percent 30
Router(config-pmap)# class class-default
Router(config-pmap-c)# fair-queue

Router(config)# interface Gi0/1
Router(config-if)# service-policy output QoS-POLICY

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
برای PAT، فقط کافیه یه ACL ساده بسازی. همیشه مطمئن شو ip nat inside و ip nat outside روی اینترفیس‌های درست باشه.
⚠️ هشدار
در SNMPv2c، Community String به‌صورت Plain-text ارسال می‌شود. در محیط‌های واقعی همیشه از SNMPv3 با Authentication و Encryption استفاده کن.
🏆 نکته‌ی طلایی
برای DHCP، همیشه ابتدا ip dhcp excluded-address تعریف کن — آدرس‌های زیرساخت (Router، Switch، Server) نباید توسط DHCP توزیع شوند.
ℹ️ اطلاعات بیشتر
در فصل ۵ با ACL، Port Security و امنیت مدیریتی آشنا می‌شوی.
🔮 دیدگاه پیشرفته
در CCNP با NAT در سناریوهای پیشرفته (NAT-T، Twice NAT) و QoS حرفه‌ای (MQC، NBAR) کار می‌کنی.

🛠️ کارگاه عملی گام‌به‌گام

  1. در Packet Tracer یک روتر 4331 + یک سوئیچ 2960 + ۳ PC اضافه کن
  2. روتر به سوئیچ وصل شود (اینترفیس LAN) و به یک Cloud/Internet شبیه‌سازی (اینترفیس WAN)
  3. روی روتر: LAN = 192.168.10.1/24، WAN = 203.0.113.2/24
  4. روی روتر DHCP Pool بساز (شبکه 192.168.10.0/24، Gateway 192.168.10.1)
  5. Excluded-Address برای .1 تا .20 تنظیم کن
  6. PCها را روی DHCP تنظیم کن و IP بگیر
  7. روی اینترفیس LAN: ip nat inside
  8. روی اینترفیس WAN: ip nat outside
  9. یک ACL ساده برای 192.168.10.0/24 بساز و PAT را فعال کن
  10. از PC به یک IP اینترنتی (مثلاً 8.8.8.8) ping بزن
  11. با show ip nat translations ترجمه‌ها را ببین
  12. روی روتر NTP Server تنظیم کن و با show clock بررسی کن
  13. Syslog را به یک سرور شبیه‌سازی‌شده در شبکه بفرست
  14. SNMP Community برای پایشگر (مثلاً 192.168.10.100) تعریف کن

🚫 خطاهای رایج و رفع‌اشکال

  • NAT کار نمی‌کند: چک کن ip nat inside/outside روی اینترفیس‌هاست؟ ACL درست تعریف شده؟
  • DHCP IP نمی‌دهد: Excluded Address ممکن است کل Range را پوشش داده باشد؛ show ip dhcp pool و show ip dhcp binding را چک کن.
  • DHCP Relay کار نمی‌کند: IP Helper Address باید روی اینترفیس نزدیک کلاینت باشد، نه سمت سرور.
  • NTP Sync نمی‌شود: پورت UDP/123 در Firewall باز باشد، Timezone درست تنظیم شده باشد.
  • SNMP Response نمی‌دهد: Community String مطابق باشد، ACL مانع نباشد.
  • Syslog نمی‌رسد: logging host درست؟ Trap Level اجازه می‌دهد؟
  • QoS اثر ندارد: Policy باید روی اینترفیس خروجی اعمال شود (Output)، نه ورودی.
  • Static NAT برای سرور: مطمئن شو ACL داخل به سرور اجازه بدهد (به‌خصوص Deny any).

🎯 پروژه‌ی پایانی فصل

یک شبکه‌ی سازمانی کوچک با سرویس‌های کامل IP راه‌اندازی کن:

  • یک روتر Edge (اتصال به اینترنت شبیه‌سازی‌شده)
  • یک سوئیچ 2960 با ۴ PC در شبکه‌ی داخلی
  • شبکه‌ی داخلی: 192.168.10.0/24
  • DHCP Server روی روتر Edge با Pool مناسب
  • Excluded-Address برای IPهای زیرساخت
  • NAT/PAT روی روتر Edge
  • Static NAT برای یک وب‌سرور داخلی (192.168.10.100 → 203.0.113.100)
  • NTP Server روی روتر + تنظیم Timezone تهران
  • Syslog Server (192.168.10.100) + Trap Level Informational
  • SNMPv2c روی روتر با Community مناسب
  • QoS: اولویت‌بندی ترافیک RTP/صوت
  • Ping از PC به 8.8.8.8 و تست ترجمه‌ی NAT
🏆 چالش اضافه
  • SNMPv3 با Authentication و Encryption راه‌اندازی کن.
  • با debug ip nat ترافیک NAT را در CLI تماشا کن.
  • یک DHCP Pool دوم برای VLAN دیگر بساز و از Router با ip helper-address به آن Relay کن.

📋 جمع‌بندی و برگه‌تقب

  • NAT انواع: Static (1:1)، Dynamic (N:N)، PAT/Overload (N:1)
  • NAT گام‌ها: inside + outside + ACL + ip nat inside source
  • مشاهده‌ی NAT: show ip nat translations
  • DHCP: Pool + Excluded-Address + default-router
  • DHCP Relay: ip helper-address [server-ip]
  • DORA: Discover → Offer → Request → Acknowledge
  • DNS Client: ip name-server + no ip domain-lookup
  • NTP: ntp server [ip] + clock timezone
  • TFTP: UDP/69 (بدون رمزنگاری) | SCP: TCP/22 (امن)
  • SNMP Levels: v1/v2c (Plain)، v3 (Auth+Encrypt)
  • Syslog Levels: 0 Emergency تا 7 Debugging
  • QoS: Classification + Marking (DSCP) + Queuing + Policing/Shaping
  • DSCP مهم: EF=46 (VoIP)، AF41=34 (ویدیو کنفرانس)، BE=0
