۸.۱ مرور معماری SDN و Controller-based

در CCNP، SDN را در سطح معماری می‌بینیم. سه ستون SDN:

🧠 Centralized Control Plane

تصمیم‌گیری متمرکز در Controller — نه در هر دستگاه.

🔌 Programmable Interfaces

APIهای برنامه‌پذیر برای ارتباط با Controller و دستگاه‌ها.

📊 Abstraction

لایه انتزاع — برنامه‌نویس نیاز به دانستن جزئیات سخت‌افزار ندارد.

سه مدل Controller-based SDN:

  • Open SDN (OpenFlow): Controller کل Control Plane را در دست دارد — دستگاه‌ها فقط Forwarding انجام می‌دهند
  • API-based SDN: Controller از APIهای موجود دستگاه استفاده می‌کند (NETCONF، RESTCONF) — رایج‌ترین مدل امروز
  • Overlay SDN: Controller فقط Overlay را مدیریت می‌کند — Underlay مستقل است (VXLAN، LISP)

۸.۳ YANG — زبان مدل‌سازی داده

YANG (Yet Another Next Generation) زبان استاندارد (RFC 6020) برای توصیف مدل داده در NETCONF و RESTCONF است. YANG مشخص می‌کند هر دستگاه چه پارامترهایی دارد، ساختار آن‌ها چیست، و چه عملیاتی مجاز است.

ساختار YANG:

  • Module: یک فایل YANG شامل چند Container و List
  • Container: گروهی از Nodeهای مرتبط (مثل Interface)
  • List: مجموعه‌ای از عناصر با کلید یکتا
  • Leaf: یک مقدار (مثل IP Address)
  • Leaf-list: لیست مقادیر
// نمونه‌ی ساده YANG — تعریف Interface
module ietf-interfaces {
  namespace "urn:ietf:params:xml:ns:yang:ietf-interfaces";
  prefix if;

  container interfaces {
    list interface {
      key "name";
      leaf name {
        type string;
      }
      leaf description {
        type string;
      }
      leaf enabled {
        type boolean;
      }
      leaf type {
        type identityref {
          base interface-type;
        }
      }
    }
  }
}

YANG Models استاندارد مهم:

  • ietf-interfaces: Interfaceها
  • ietf-ip: IPv4 و IPv6
  • ietf-routing: Routing Table
  • ietf-system: Hostname، NTP، Users
  • Cisco-IOS-XE-*: مدل‌های اختصاصی سیسکو
  • openconfig-*: مدل‌های OpenConfig — Multi-Vendor

۸.۴ NETCONF — RPC، Datastore، Capabilities

NETCONF (RFC 6241) پروتکل مدیریت شبکه روی SSH/830 است که از YANG برای مدل داده استفاده می‌کند. تراکنشی و Atomic است.

ساختار NETCONF:

  • Transport: SSH/830
  • Messages: RPC و RPC-Reply — با XML
  • Operations: get، get-config، edit-config، copy-config، delete-config، lock، unlock، close-session، kill-session
  • Datastores: running، candidate، startup، intended
Datastore توضیح
runningپیکربندی فعال — همیشه موجود
candidateمحیط موقت — قبل از اعمال، تست
startupپیکربندی ذخیره‌شده — بعد از Reboot
intendedپیکربندی هدف در IOS-XE (اختصاصی)

نمونه‌ی NETCONF RPC — خواندن Interface:

<rpc message-id="101" xmlns="urn:ietf:params:xml:ns:netconf:base:1.0">
  <get-config>
    <source>
      <running/>
    </source>
    <filter>
      <interfaces xmlns="urn:ietf:params:xml:ns:yang:ietf-interfaces">
        <interface>
          <name>GigabitEthernet0/0</name>
        </interface>
      </interfaces>
    </filter>
  </get-config>
</rpc>

نمونه‌ی NETCONF RPC — تغییر Description:

<rpc message-id="102" xmlns="urn:ietf:params:xml:ns:netconf:base:1.0">
  <edit-config>
    <target>
      <running/>
    </target>
    <config>
      <interfaces xmlns="urn:ietf:params:xml:ns:yang:ietf-interfaces">
        <interface>
          <name>GigabitEthernet0/0</name>
          <description>WAN-to-ISP</description>
        </interface>
      </interfaces>
    </config>
  </edit-config>
</rpc>

۸.۶ gNMI و Model-Driven Telemetry

gNMI (gRPC Network Management Interface) یک پروتکل مدرن گوگل است که بر پایه gRPC کار می‌کند و جایگزین سریع‌تر و مقیاس‌پذیرتر NETCONF/RESTCONF برای Telemetry است.

Model-Driven Telemetry (MDT): جایگزین SNMP Polling با:

  • Push Model: دستگاه خودش داده را می‌فرستد (نه NMS بپرسد)
  • Streaming: جریان مداوم داده
  • Structured Data: با YANG Model — JSON، Protobuf
  • مقیاس‌پذیر: gRPC از HTTP/2 استفاده می‌کند — مناسب هزاران دستگاه

دو نوع Subscription:

  • Dial-in: Collector به دستگاه وصل می‌شود
  • Dial-out: دستگاه به Collector وصل می‌شود (برای NAT مناسب‌تر)

! ===== Dial-in از Python با gNMI =====
# pip install pygnmi
from pygnmi.client import gNMIclient
import json

with gNMIclient(target=("192.168.1.1", 57400),
                username="admin", password="pass",
                insecure=True) as gc:
    # Subscribe
    sub = {
        "subscription": [
            {
                "path": "interfaces/interface/state/counters",
                "mode": "sample",
                "sample_interval": 10000000000  # nanoseconds
            }
        ],
        "mode": "stream",
        "encoding": "json_ietf"
    }
    for response in gc.subscribe2(sub):
        print(json.dumps(response, indent=2))

۸.۷ Python پیشرفته — Netmiko، NAPALM، Nornir

Netmiko: کتابخانه SSH برای دستگاه‌های شبکه — ساده، محبوب، ولی Single-Vendor.

NAPALM: کتابخانه Multi-Vendor با API یکسان — برای شبکه‌های چندبرندی.

Nornir: فریم‌ورک Python برای اجرای موازی روی صدها دستگاه.

# ===== Netmiko =====
from netmiko import ConnectHandler

device = {
    "device_type": "cisco_ios",
    "host": "192.168.1.1",
    "username": "admin",
    "password": "pass",
    "secret": "enable-secret"
}

with ConnectHandler(**device) as conn:
    conn.enable()
    output = conn.send_command("show ip interface brief")
    print(output)

    config = [
        "interface Loopback10",
        "ip address 10.10.10.1 255.255.255.255",
        "description Managed by Automation"
    ]
    conn.send_config_set(config)
    conn.save_config()

# ===== NAPALM (Multi-Vendor) =====
from napalm import get_network_driver

driver = get_network_driver("ios")
device = driver(
    hostname="192.168.1.1",
    username="admin",
    password="pass"
)

device.open()
print(device.get_facts())
print(device.get_interfaces())
print(device.get_environment())

config = """
interface GigabitEthernet0/2
 description Managed by NAPALM
 no shutdown
"""
device.load_merge_candidate(config=config)
print(device.compare_config())
device.commit_config()
device.close()

# ===== Nornir (Parallel) =====
from nornir import InitNornir
from nornir_netmiko.tasks import netmiko_send_command
from nornir_utils.plugins.functions import print_result

nr = InitNornir(config_file="config.yaml")

result = nr.run(
    task=netmiko_send_command,
    command_string="show version"
)
print_result(result)

۸.۹ Terraform و Infrastructure as Code

Terraform (HashiCorp) ابزار IaC با زبان HCL است. برای Cloud، SD-WAN و زیرساخت‌های API-driven. 

# ===== Terraform — Provider =====
terraform {
  required_providers {
    dnacenter = {
      source = "cisco-en-programmability/dnacenter"
      version = "1.0.0"
    }
    iosxe = {
      source = "CiscoDevNet/iosxe"
    }
  }
}

provider "iosxe" {
  username = var.username
  password = var.password
  host     = var.device_host
}

# ===== Resource — Interface =====
resource "iosxe_interface_loopback" "loopback10" {
  name        = 10
  description = "Managed by Terraform"
  ipv4_address = "10.10.10.1"
  ipv4_address_mask = "255.255.255.255"
}

# ===== Variables =====
variable "username" {
  type      = string
  sensitive = true
}
variable "password" {
  type      = string
  sensitive = true
}
variable "device_host" {
  type = string
}
# ===== Terraform Workflow =====
terraform init          # نصب Providerها
terraform plan          # نمایش تغییرات
terraform apply         # اعمال تغییرات
terraform destroy       # حذف Resourceها
terraform state list    # لیست Resourceهای مدیریت‌شده
terraform fmt           # فرمت‌دهی HCL

مزایای Terraform:

  • State مدیریت‌شده — می‌داند چه چیزی deploy کرده
  • Idempotent — اجرای دوباره، نتیجه یکسان
  • Plan/Apply — مشاهده پیش از اعمال
  • Multi-Provider — Cloud + Network در یک فایل

۸.۱۰ CI/CD Pipeline برای شبکه

CI/CD (Continuous Integration / Continuous Deployment) یک رویکرد DevOps است که تغییرات را به‌صورت خودکار Test و Deploy می‌کند.

مزایای CI/CD در شبکه:

  • کاهش خطای انسانی
  • Rollback سریع در صورت مشکل
  • Version Control تمام تغییرات
  • Peer Review قبل از اعمال
  • Test خودکار روی محیط Shakedown

ابزارهای CI/CD محبوب:

  • Git: مخزن کد و Config
  • GitLab CI/CD: Pipeline کامل با Runner
  • GitHub Actions: CI/CD رایگان برای Open Source
  • Jenkins: ابزار Classic با Pluginهای زیاد
  • Drone CI: سبک و Container-based
# ===== نمونه .gitlab-ci.yml =====

stages:
  - lint
  - build
  - test
  - deploy

variables:
  ANSIBLE_HOST_KEY_CHECKING: "False"

lint:
  stage: lint
  script:
    - ansible-lint playbooks/
    - yamllint .

build_config:
  stage: build
  script:
    - python render_templates.py
  artifacts:
    paths:
      - generated_configs/

test_config:
  stage: test
  script:
    - python validate_configs.py
    - ansible-playbook -i inventory/test playbooks/deploy.yml --check

deploy:
  stage: deploy
  only:
    - main
  script:
    - ansible-playbook -i inventory/prod playbooks/deploy.yml
  when: manual

💡 نکته‌ی کاربردی
در RESTCONF، همیشه اول با /restconf/data/ietf-yang-library:modules-state لیست YANG Moduleها را بگیر. سپس /restconf/data/<module-name>:<path> را برای خواندن استفاده کن.
⚠️ هشدار
هرگز از RESTCONF/NETCONF در Production استفاده نکن بدون احراز هویت HTTPS. حتماً از Certificate یا Basic Auth با HTTPS استفاده کن — هرگز HTTP ساده.
🏆 نکته‌ی طلایی
در CI/CD شبکه، همیشه در Pipeline یک Stage Validate داشته باش که Config را با pyATS یا Batfish تست کند — قبل از Deploy روی Production. این تنها راه جلوگیری از فاجعه است.

import requests
import json
requests.packages.urllib3.disable_warnings()

def configure_interface(host, username, password, interface, description, ip):
    url = f"https://{host}/restconf/data/ietf-interfaces:interfaces/interface={interface.replace('/', '%2F')}"
    headers = {
        "Content-Type": "application/yang-data+json",
        "Accept": "application/yang-data+json"
    }
    payload = {
        "ietf-interfaces:interface": {
            "name": interface,
            "description": description,
            "type": "iana-if-type:ethernetCsmacd",
            "enabled": True,
            "ietf-ip:ipv4": {
                "address": [{
                    "ip": ip,
                    "netmask": "255.255.255.0"
                }]
            }
        }
    }
    response = requests.put(
        url,
        headers=headers,
        json=payload,
        auth=(username, password),
        verify=False
    )
    print(f"[{host}] {interface}: HTTP {response.status_code}")
    return response.status_code == 204

# استفاده

مثال ۳ — Nornir + NAPALM برای Multi-Vendor

from nornir import InitNornir
from nornir_utils.plugins.functions import print_result
from nornir_napalm.plugins.tasks import napalm_get, napalm_configure

def get_facts(task):
    result = task.run(task=napalm_get, getters=["facts", "interfaces"])
    facts = result.result["facts"]
    task.host["vendor"] = facts["vendor"]
    task.host["model"] = facts["model"]
    task.host["uptime"] = facts["uptime"]

def deploy_config(task):
    if task.host["vendor"] == "Cisco":
        config = "hostname " + task.host.name
    elif task.host["vendor"] == "Juniper":
        config = "set system host-name " + task.host.name
    else:
        return

    task.run(task=napalm_configure, configuration=config, replace=False)

nr = InitNornir(config_file="config.yaml")

print("=== Gathering Facts ===")
result = nr.run(task=get_facts)
print_result(result)

print("\n=== Deploying Config ===")
result = nr.run(task=deploy_config)
print_result(result)

🚫 خطاهای رایج و رفع‌اشکال

  • RESTCONF 401: Authentication Basic را در HTTP Header تنظیم کن یا از Token استفاده کن.
  • RESTCONF 404: مسیر YANG اشتباه — با /ietf-yang-library:modules-state چک کن.
  • NETCONF Session باز نمی‌شود: SSH/830 باز، User Privilege 15، و netconf-yang فعال.
  • YANG Path اشتباه: Namespace و Module Name را دقیق بنویس.
  • gNMI Auth Error: Certificate یا Username/Password اشتباه — Insecure را برای Lab فعال کن.
  • Telemetry Stream قطعه‌قطعه: UDP بر DNS یا Network از دست می‌رود — از gRPC/TCP استفاده کن.
  • Netmiko Timeout: device_type درست نیست یا SSH v1/2 مشکل دارد.
  • NAPALM با Device ناسازگار: Driver مناسب را انتخاب کن (ios، iosxr، junos، eos).
  • Ansible Playbook کند: از serial و strategy: free برای موازی‌سازی استفاده کن.
  • Ansible Vault باز نمی‌شود: --vault-password-file را ست کن یا رمز را یادت رفته.
  • Terraform State Conflict: از Remote Backend (S3، GitLab) استفاده کن و State را Lock کن.
  • CI/CD خطا در Deploy: Credentialها در CI/CD به‌صورت Secret تعریف شوند، نه در Repo.
  • pyATS Learn Error: OS Version پشتیبانی نمی‌شود — pyATS را آپدیت کن.
  • Batfish Snapshot خالی: Config فایل‌ها در فرمت صحیح نبودند.
  • DNA Center Token Expire: Token را با Refresh هر ۵۰ دقیقه تازه کن.
