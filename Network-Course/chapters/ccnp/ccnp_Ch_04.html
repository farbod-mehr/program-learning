Autonomous System (AS): یک دامنه‌ی مدیریتی واحد که با یک شماره ASN مشخص می‌شود — IGPها درون AS و EGP (BGP) بین ASها کار می‌کنند.

۴.۲ EIGRP — متریک و K-Values

EIGRP (Enhanced Interior Gateway Routing Protocol) یک پروتکل پیشرفته‌ی Distance Vector است که سیسکو آن را به‌عنوان Advanced Distance Vector یا Hybrid معرفی می‌کند.

متریک ترکیبی EIGRP بر پایه‌ی ۵ پارامتر است:

  • Bandwidth: پهنای باند کمترین لینک در مسیر
  • Delay: مجموع تأخیر لینک‌ها
  • Reliability: قابلیت اطمینان (K4)
  • Load: بار لینک (K2)
  • MTU: حداکثر اندازه بسته (استفاده نمی‌شود)

K-Values پیش‌فرض:

K1=1 (Bandwidth)   → فعال
K2=0 (Load)        → غیرفعال
K3=1 (Delay)       → فعال
K4=0 (Reliability) → غیرفعال
K5=0 (MTU)         → غیرفعال

فرمول ساده‌شده:
Metric = 256 × [(10^7 / Bandwidth_min) + (Delay_sum / 10)]
! تغییر K-Values (به‌ندرت پیشنهاد می‌شود)
Router(config)# router eigrp 100
Router(config-router)# metric weights 0 1 0 1 0 0

! بررسی
Router# show ip protocols
Router# show ip eigrp topology
Router# show interface Gi0/0
! ببین: BW, DLY, reliability, load, MTU
⚠️ هشدار
K-Values باید در همه‌ی روترهای EIGRP یکسان باشد. اگر متفاوت باشد، همسایگی EIGRP تشکیل نمی‌شود و در Log پیام %DUAL-5-NBRCHANGE: K-value mismatch می‌آید.

۴.۳ EIGRP — DUAL، FD و FS

قلب EIGRP الگوریتم DUAL (Diffusing Update Algorithm) است که مسیرهای Loop-Free را تضمین می‌کند.

مفاهیم کلیدی:

  • FD (Feasible Distance): بهترین متریک تا مقصد (Metric محلی)
  • RD (Reported Distance): متریکی که همسایه اعلان می‌کند
  • Successor: بهترین Next Hop به مقصد (در جدول مسیریابی نصب می‌شود)
  • Feasible Successor (FS): Next Hop پشتیبان که شرط Feasibility Condition را دارد
  • FC (Feasibility Condition): RD از همسایه < FD محلی → مسیر Loop-Free

جدول Topology EIGRP:

  • مسیرهای Successor در Routing Table نصب می‌شوند
  • مسیرهای Feasible Successor در Topology Table نگه داشته می‌شوند
  • اگر Successor از بین برود، FS بلافاصله جایگزین می‌شود (بدون Query)
  • اگر FS نباشد، Router وارد حالت Active می‌شود و Query می‌فرستد (SIA = Stuck in Active)
! بررسی جدول Topology EIGRP
Router# show ip eigrp topology
! P = Passive (پایدار) — A = Active (در حال Query)

Router# show ip eigrp topology 10.0.0.0/24
! خروجی:
!   P 10.0.0.0/24, 1 successors, FD is 28160
!     via 10.1.1.2 (28160/21760), Gi0/1
!         ↑FD  ↑RD
!   P 10.0.0.0/24, 1 successors, FD is 28160
!     via 10.1.2.2 (30720/28160), Gi0/2  ← Feasible Successor
!         ↑FD   ↑RD (28160 < FD اصلی 28160 → شرط FC برقرار؟ باید RD < FD اصلی)

! مشاهده فقط Successorها (Routing Table)
Router# show ip route eigrp

! مشاهده فقط Feasible Successorها
Router# show ip eigrp topology all-links
🏆 نکته‌ی طلایی
شرط FC می‌گوید: RD همسایه < FD محلی. یعنی همسایه‌ای که مسیرش بهتر از خودم است، حتماً Loop-Free است. این قانون، نیاز به محاسبه‌ی پیچیده را در ۹۰٪ سناریوها از بین می‌برد.

۴.۴ EIGRP — Classic Mode vs Named Mode

EIGRP دو شکل پیکربندی دارد:

📜 Classic Mode (قدیمی)

پیکربندی با router eigrp [AS] — همه‌ی تنظیمات در سطح Router Process.

Router(config)# router eigrp 100
Router(config-router)# network 10.0.0.0 0.0.0.255
Router(config-router)# no auto-summary
Router(config-router)# passive-interface Gi0/0
Router(config-router)# variance 2
📦 Named Mode (مدرن)

پیکربندی با router eigrp [NAME] و Address Families — استاندارد امروز و پیشنهاد CCNP.

Router(config)# router eigrp COMPANY
Router(config-router)# address-family ipv4 unicast autonomous-system 100
Router(config-router-af)# network 10.0.0.0 0.0.0.255
Router(config-router-af)# af-interface Gi0/0
Router(config-router-af-interface)# passive-interface
Router(config-router-af-interface)# exit
Router(config-router-af)# topology base
Router(config-router-af-topology)# variance 2
Router(config-router-af-topology)# exit

مزایای Named Mode:

  • پشتیبانی از IPv4 و IPv6 در یک Process
  • پیکربندی Interface-level (AF-Interface)
  • پشتیبانی از VRF و Multi-Topology
  • ساختار سلسله‌مراتبی و مرتب

۴.۵ EIGRP — Stub، Summarization، Load Balancing

EIGRP Stub: اگر روتری فقط یک مسیر خروجی دارد (مثل شعبه)، می‌توانی آن را Stub کنی. با این کار روتر به Hub اعلام می‌کند که برای شبکه‌های دیگر Query نپذیرد.

! EIGRP Stub
Router(config)# router eigrp 100
Router(config-router)# eigrp stub connected summary
! گزینه‌ها: connected، static، summary، redistributed، receive-only

! بررسی
Router# show ip eigrp neighbors detail
! ببین: Stub Peer Status

Summarization در EIGRP: روی Interface یا در AF-Interface:

! Classic Mode — روی Interface
Router(config)# interface Gi0/1
Router(config-if)# ip summary-address eigrp 100 10.0.0.0 255.255.0.0

! Named Mode — در AF-Interface
Router(config-router-af)# af-interface Gi0/1
Router(config-router-af-interface)# summary-address 10.0.0.0 255.255.0.0

Load Balancing EIGRP:

  • Equal Cost (پیش‌فرض): تا ۴ مسیر هم‌متریک — با maximum-paths تا ۱۶
  • Unequal Cost (Variance): با variance X — مسیرهایی که متریک آن‌ها تا X برابر بهترین باشد، Load Balancing می‌شوند
! Equal Cost LB
Router(config-router)# maximum-paths 8

! Unequal Cost LB
Router(config-router)# variance 2
! هر مسیری که متریکش ≤ 2 × FD باشد، در Load Balancing شرکت می‌کند
! شرط FC همچنان باید برقرار باشد

! بررسی
Router# show ip route 10.0.0.0
! ببین: 2 subnets, ...
Router# show ip protocols
! ببین: Number of routes in AS

۴.۶ OSPF — Link State، LSA Types، Area Types

OSPF با ساختن LSDB (Link State Database) یکسان در همه‌ی روترهای یک Area، و اجرای الگوریتم Dijkstra، درخت کوتاه‌ترین مسیر (SPF Tree) را می‌سازد.

انواع LSA در OSPF:

Type نام منتشرکننده محدوده
1Router LSAهر روترداخل Area
2Network LSADRداخل Area
3Summary LSAABRبین Area
4ASBR SummaryABRبین Area
5External LSAASBRکل OSPF Domain
7NSSA ExternalASBR در NSSAداخل NSSA

انواع Area در OSPF:

  • Backbone (Area 0): اجباری — همه‌ی Areaهای دیگر باید به آن متصل باشند
  • Standard Area: Area معمولی با LSA 1, 2, 3, 4, 5
  • Stub Area: بدون LSA 5 (External) — Default Route جایگزین
  • Totally Stubby: فقط Default Route — بدون LSA 3, 4, 5 (فقط Cisco)
  • NSSA (Not-So-Stubby Area): مثل Stub ولی می‌تواند External بفرستد (LSA 7)
  • Totally NSSA: مثل Totally Stubby + LSA 7
! پیکربندی Area Types
! Stub
Router(config-router)# area 10 stub

! Totally Stubby (روی ABR)
Router(config-router)# area 10 stub no-summary

! NSSA
Router(config-router)# area 10 nssa

! Totally NSSA (روی ABR)
Router(config-router)# area 10 nssa no-summary

! بررسی
Router# show ip ospf database
Router# show ip ospf
Router# show ip ospf border-routers

۴.۷ OSPF — ABR، ASBR، Virtual Link

ABR (Area Border Router): روتری که در دو یا چند Area عضویت دارد. خلاصه‌سازی (Summarization) بین Areaها و توزیع LSA Type 3 انجام می‌دهد.

ASBR (Autonomous System Boundary Router): روتری که Redistribution (تزریق مسیر خارجی) انجام می‌دهد. LSA Type 5 منتشر می‌کند.

Backbone Router: روتری که حداقل یک اینترفیس در Area 0 دارد.

Internal Router: همه‌ی اینترفیس‌هایش در یک Area غیر از 0.

Virtual Link: زمانی استفاده می‌شود که یک Area به Area 0 مستقیم متصل نیست. Virtual Link یک تونل منطقی بین دو ABR می‌سازد که از یک Transit Area عبور می‌کند.

! Virtual Link — بین R1 و R2 که هر دو ABR هستند
! سناریو: Area 20 به Area 0 وصل نیست، از Area 10 عبور می‌کند

! روی R1 (نزدیک Area 0)
R1(config)# router ospf 1
R1(config-router)# area 10 virtual-link 2.2.2.2
! 2.2.2.2 = Router ID روتر R2

! روی R2 (نزدیک Area 20)
R2(config)# router ospf 1
R2(config-router)# area 10 virtual-link 1.1.1.1
! 1.1.1.1 = Router ID روتر R1

! بررسی
Router# show ip ospf virtual-links
Router# show ip ospf neighbor

۴.۸ OSPF — Network Types و Neighbor States

انواع Network در OSPF:

نوع DR/BDR Hello/Dead کاربرد
Broadcast✅10s / 40sEthernet
Point-to-Point❌10s / 40sSerial، GRE
Non-Broadcast (NBMA)✅30s / 120sFrame Relay
Point-to-Multipoint❌30s / 120sHub-Spoke
Point-to-Multipoint NBMA❌30s / 120sLegacy
 
! تعیین Network Type دستی
Router(config)# interface Gi0/0
Router(config-if)# ip ospf network point-to-point
! یا broadcast، non-broadcast، point-to-multipoint

! نکته: در نقطه‌به‌نقطه واقعی (Serial)، OSPF خودکار Point-to-Point می‌شود
! در Ethernet خودکار Broadcast می‌شود

Neighbor States (۷ مرحله):

  1. Down: هیچ Hello دریافت نشده
  2. Init: Hello دریافت شده ولی Router ID ما در آن نیست
  3. 2-Way: Hello تبادل کامل — وضعیت پایدار در DROther↔DROther
  4. ExStart: انتخاب Master/Slave (بالاترین Router ID = Master)
  5. Exchange: تبادل DBD (Database Description)
  6. Loading: تبادل LSR/LSU برای اطلاعات کامل
  7. Full: همسایگی کامل — LSDB یکسان

۴.۹ OSPF — Summarization و Path Preference

Summarization (Inter-Area) — فقط روی ABR:

Router(config)# router ospf 1
Router(config-router)# area 10 range 10.0.0.0 255.0.0.0
! خلاصه‌سازی 10.0.0.0/8 از Area 10 به Area 0

! External Summarization (روی ASBR)
Router(config-router)# summary-address 192.168.0.0 255.255.0.0

Path Preference در OSPF — ترتیب انتخاب مسیر:

  1. Intra-Area (O): مسیر داخل همان Area — بالاترین اولویت
  2. Inter-Area (O IA): مسیر از Area دیگر
  3. External Type 1 (E1): متریک = Cost داخلی + Cost خارجی
  4. External Type 2 (E2 — پیش‌فرض): فقط متریک خارجی — Cost داخلی نادیده
! Redistribution به OSPF با E1 به‌جای E2
Router(config)# router ospf 1
Router(config-router)# redistribute static subnets metric-type 1

! تنظیم متریک External
Router(config-router)# redistribute eigrp 100 subnets metric 100 metric-type 2

! بررسی
Router# show ip route ospf
! ببین: O، O IA، O E1، O E2

۴.۱۰ BGP — eBGP vs iBGP، AS، Path Attributes

BGP (Border Gateway Protocol) یک پروتکل Path Vector است که بین Autonomous Systemها کار می‌کند و بر پایه‌ی TCP/179 اجرا می‌شود.

تفاوت eBGP و iBGP:

ویژگی eBGP iBGP
ASمتفاوتیکسان
AD پیش‌فرض20200
TTL1 (پیش‌فرض)نامحدود منطقی (بدون TTL=1)
AS_PATHقبل از ارسال، AS خود را اضافه می‌کندبدون تغییر
Next Hopخودش را می‌گذاردNext Hop را حفظ می‌کند
Loop PreventionAS_PATHSplit Horizon (بدون RR)

چهار دسته‌ی Path Attributes:

  • Well-Known Mandatory: باید در همه‌ی Updateها باشند — AS_PATH، NEXT_HOP، ORIGIN
  • Well-Known Discretionary: باید شناخته شوند ولی اجباری نیستند — LOCAL_PREF، ATOMIC_AGGREGATE
  • Optional Transitive: می‌توانند منتقل شوند — AGGREGATOR، COMMUNITY
  • Optional Non-Transitive: منتقل نمی‌شوند — MED، ORIGINATOR_ID، CLUSTER_LIST
! پیکربندی eBGP
Router(config)# router bgp 65001
Router(config-router)# neighbor 203.0.113.2 remote-as 65002
Router(config-router)# network 10.0.0.0 mask 255.255.255.0

! پیکربندی iBGP (داخل AS)
Router(config)# router bgp 65001
Router(config-router)# neighbor 10.1.1.2 remote-as 65001
Router(config-router)# neighbor 10.1.1.2 update-source Loopback0
Router(config-router)# neighbor 10.1.1.2 next-hop-self
! next-hop-self برای iBGP ضروری است — وگرنه Next Hop خارجی می‌شود

! بررسی
Router# show ip bgp summary
Router# show ip bgp neighbors
Router# show ip bgp

۴.۱۱ BGP — Best Path Selection Algorithm

BGP برای انتخاب بهترین مسیر، ۱۱ مرحله را به ترتیب چک می‌کند. هر مرحله اگر مسیر برنده مشخص کند، بررسی متوقف می‌شود:

1Weight (Cisco Only)بالاتر = بهتر
2Local Preferenceبالاتر = بهتر
3Locally OriginatedNetwork/Redistribute/Static
4AS_PATH Lengthکوتاه‌تر = بهتر
5OriginIGP > EGP > Incomplete
6MED (Multi-Exit Discriminator)پایین‌تر = بهتر
7eBGP > iBGPeBGP ترجیح دارد
8IGP Metric به Next Hopکمتر = بهتر
9Oldest Path (eBGP)قدیمی‌تر = بهتر
10Lowest Router IDپایین‌تر = بهتر
11Lowest Neighbor IPپایین‌تر = بهتر

(Weight، Local Pref، Originate، AS Path، Origin، MED، eBGP، IGP، Oldest، Router ID، Neighbor IP) 
! تنظیم Weight روی یک روتر

Router(config-router)# neighbor 203.0.113.2 weight 200

! تنظیم Local Preference (معمولاً روی ASBR)
Router(config)# route-map SET-LP permit 10
Router(config-route-map)# set local-preference 150
Router(config-router)# neighbor 203.0.113.2 route-map SET-LP in

Router# show ip bgp
! ببین: Weight, Local Pref, Metric, AS Path, Origin

۴.۱۲ BGP — Route Reflector و Confederation

مشکل iBGP Full-Mesh: در iBGP، هر روتر باید با همه‌ی روترهای دیگر iBGP Peer باشد (چون مسیرهای iBGP یادگرفته‌شده به iBGP دیگر Forward نمی‌شوند). این باعث می‌شود N×(N-1)/2 Session لازم باشد.

راه‌حل ۱: Route Reflector (RR)

  • یک یا چند روتر به‌عنوان RR — روترهای دیگر Client آن
  • RR مسیرهای یک Client را به Clientهای دیگر بازتاب می‌دهد (Reflect)
  • Loop Prevention با ORIGINATOR_ID و CLUSTER_LIST
! Route Reflector
Router(config)# router bgp 65001
Router(config-router)# neighbor 10.1.1.2 route-reflector-client
Router(config-router)# neighbor 10.1.1.3 route-reflector-client
Router(config-router)# neighbor 10.1.1.4 route-reflector-client

! بررسی
Router# show ip bgp neighbors 10.1.1.2 | include Route-Reflector
! ببین: Route-Reflector Client: yes

راه‌حل ۲: Confederation

  • تقسیم یک AS بزرگ به چند Sub-AS (خصوصی: 64512-65535)
  • داخل هر Sub-AS، Full-Mesh iBGP
  • بین Sub-ASها، eBGP Session (ولی از دید بیرون یک AS هستند)
! Confederation
Router(config)# router bgp 65001
Router(config-router)# bgp confederation identifier 100
Router(config-router)# bgp confederation peers 65002 65003
Router(config-router)# neighbor 10.1.1.2 remote-as 65002

۴.۱۳ Redistribution و Route Filtering

Redistribution: تزریق مسیرهای یک پروتکل به پروتکل دیگر. مثال: OSPF به EIGRP، Static به BGP.

خطرات Redistribution بدون Filtering:

  • Route Loops — مسیر از A به B و برگردانده شود
  • Suboptimal Routing
  • افزایش جدول مسیریابی (بدون کنترل)
! Redistribution OSPF → EIGRP
Router(config)# router eigrp 100
Router(config-router)# redistribute ospf 1 metric 10000 100 255 1 1500
! metric bandwidth delay reliability load MTU

! Redistribution EIGRP → OSPF
Router(config)# router ospf 1
Router(config-router)# redistribute eigrp 100 subnets metric 100 metric-type 2

! Redistribution با Route Map
Router(config)# route-map OSPF-TO-EIGRP permit 10
Router(config-route-map)# match ip address prefix-list ALLOWED
Router(config-route-map)# set metric 10000 100 255 1 1500
Router(config-route-map)# set tag 100

Router(config)# router eigrp 100
Router(config-router)# redistribute ospf 1 route-map OSPF-TO-EIGRP

! Route Filtering با Prefix-List
Router(config)# ip prefix-list ALLOWED seq 10 permit 10.0.0.0/8 le 24
Router(config)# ip prefix-list ALLOWED seq 20 permit 172.16.0.0/12 le 24
Router(config)# ip prefix-list ALLOWED seq 100 deny 0.0.0.0/0 le 32

! Filtering OSPF
Router(config)# router ospf 1
Router(config-router)# distribute-list prefix ALLOWED in

! Filtering BGP
Router(config)# router bgp 65001
Router(config-router)# neighbor 203.0.113.2 prefix-list ALLOWED in
! یا
Router(config-router)# neighbor 203.0.113.2 route-map FILTER in

۴.۱۴ Policy-Based Routing (PBR)

PBR یا Policy-Based Routing به شما اجازه می‌دهد بر اساس سیاست (نه جدول مسیریابی معمولی) تصمیم بگیرید بسته از کدام مسیر برود.

کاربردهای PBR:

  • هدایت ترافیک خاص از یک لینک مشخص (مثلاً ترافیک HTTP از ISP A، بقیه از ISP B)
  • Marking برای QoS (Next Hop بر اساس DSCP)
  • Force Route به یک روتر خاص برای Inspection
  • Load Balancing در Dual-Homed
! ===== PBR نمونه: هدایت ترافیک HTTP از یک لینک =====

! گام ۱: تعریف ACL یا Prefix-List برای Match
Router(config)# ip access-list extended HTTP-TRAFFIC
Router(config-ext-nacl)# permit tcp 10.1.0.0 0.0.255.255 any eq 80
Router(config-ext-nacl)# permit tcp 10.1.0.0 0.0.255.255 any eq 443
Router(config-ext-nacl)# exit

! گام ۲: تعریف Route Map
Router(config)# route-map PBR-HTTP permit 10
Router(config-route-map)# match ip address HTTP-TRAFFIC
Router(config-route-map)# set ip next-hop 203.0.113.2
Router(config-route-map)# exit

! گام ۳: اعمال روی اینترفیس (In)
Router(config)# interface Gi0/0
Router(config-if)# ip policy route-map PBR-HTTP

! بررسی
Router# show route-map PBR-HTTP
Router# show ip policy
Router# debug ip policy

! ===== PBR برای Locally-Generated Traffic =====
Router(config)# ip local policy route-map PBR-HTTP
! ترافیک تولیدشده توسط خود روتر هم از PBR پیروی می‌کند
💡 نکته
PBR فقط روی ترافیک Inbound اعمال می‌شود — یعنی بسته‌ای که وارد اینترفیس می‌شود. برای ترافیک Outbound، باید روی اینترفیس مقابل اعمال کنی.

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
در EIGRP، همیشه show ip eigrp topology را با show ip route eigrp مقایسه کن. تفاوت این دو، تعداد Feasible Successorهای ذخیره‌شده را نشان می‌دهد.
⚠️ هشدار Redistribution
هرگز Redistribution را بدون Route Filtering انجام نده. حداقل با یک Prefix-List کنترل کن چه چیزی تزریق می‌شود. استفاده از Tag هم توصیه می‌شود.
🏆 نکته‌ی طلایی
در BGP، Weight و Local Preference را همه‌جا نمی‌توان تغییر داد:
  • Weight: فقط روی همان روتر محلی تأثیر دارد — از آن برای ترجیح یک ISP استفاده کن
  • Local Pref: در کل AS منتشر می‌شود — از آن برای Policy کل AS استفاده کن
ℹ️ اطلاعات بیشتر
در فصل ۵ CCNP وارد MPLS و DMVPN می‌شوی.
🔮 دیدگاه پیشرفته
در ENARSI عیب‌یابی EIGRP Stuck-in-Active، OSPF Virtual Link و BGP Policy در سناریوهای واقعی ISP بررسی می‌شود.

🚫 خطاهای رایج و رفع‌اشکال

  • EIGRP همسایه نمی‌شود: AS Number، K-Values، Authentication، Network Statement یا Passive-Interface اشتباه.
  • EIGRP SIA (Stuck in Active): Query پاسخ نمی‌گیرد — Stub Config یا Filtering اضافه کن.
  • EIGRP Variance کار نمی‌کند: Feasibility Condition برقرار نیست — حتی با Variance بالا، FS لازم است.
  • OSPF همسایه نمی‌شود: Area ID، Hello/Dead، Authentication، MTU، Network Type یکسان نیست.
  • OSPF Router ID تکراری: پیام %OSPF-4-DUP_RTRID_NBR — Router ID دستی و یکتا تعریف کن.
  • OSPF Virtual Link کار نمی‌کند: Router ID باید یکتا و در Transit Area باشد.
  • BGP Session Up نمی‌شود: TCP/179 باز، Remote AS درست، Update-Source و TTL Check.
  • BGP Route اعلان نمی‌شود: Network Statement با Mask، Redistribute یا Aggregate.
  • iBGP Loop Prevention: بدون Route Reflector، iBGP مسیر را به iBGP دیگر Forward نمی‌کند — Full-Mesh یا RR لازم است.
  • BGP Best Path اشتباه: ترتیب Weight → Local Pref → Origin → AS Path → Origin → MED را چک کن.
  • Redistribution Loop: بدون Tag و Route Map، مسیرها بین دو پروتکل Loop می‌شوند.
  • PBR کار نمی‌کند: روی اینترفیس Inbound اعمال شده؟ ACL Match دقیق است؟ Local Policy برای ترافیک روتر فعال است؟

یک شبکه‌ی چندپروتکلی با Redistribution و Policy طراحی کن:

  • داخل AS 65001: ۳ روتر با EIGRP Named Mode
  • ASBR (R3): Redistribution دوطرفه با Route Map و Tag بین EIGRP و OSPF
  • داخل AS 65002: ۳ روتر OSPF چندناحیه‌ای (Area 0 و Area 10)
  • ABR (R4): Summarization برای Area 10 و Totally Stubby
  • iBGP: Full-Mesh داخل AS 65001 با Route Reflector
  • eBGP: با یک ISP شبیه‌سازی‌شده (AS 65010) روی R1
  • Policy: ترجیح یک ISP با Weight روی R1
  • Prefix-List: فقط Prefixهای خودی به ISP اعلان شود
  • PBR: ترافیک HTTP از ISP-A، VoIP از ISP-B
  • Variance EIGRP: Load Balancing بین دو مسیر
  • مستندسازی کامل با Diagram، IP Plan و Policy Matrix
🏆 چالش اضافه
  • یک Routing Loop عمدی در Redistribution بساز و با Route Map حل کن.
  • یک BGP Policy برای جلوگیری از Transit Traffic پیاده کن.
  • OSPF Virtual Link ایجاد کن تا یک Area بدون اتصال مستقیم به Area 0 متصل شود.
  • EIGRP SIA عمدی بساز و با Stub حل کن.

📋 جمع‌بندی و برگه‌تقب

  • EIGRP متریک: BW + Delay (K1، K3) با Weight 256
  • EIGRP FD vs RD: FD محلی، RD از همسایه — شرط FC: RD < FD
  • EIGRP State: Passive (پایدار) — Active (Query در جریان)
  • EIGRP Stub: برای شعبه‌های تک‌لینکی — جلوگیری از SIA
  • EIGRP Variance: Unequal Cost Load Balancing (با شرط FC)
  • OSPF LSA: Type 1 (Router)، 2 (Network)، 3 (Summary)، 5 (External)، 7 (NSSA)
  • OSPF Areas: Backbone، Stub، Totally Stubby، NSSA، Totally NSSA
  • ABR: بین Areaها — ASBR: تزریق External
  • OSPF States: Down → Init → 2-Way → ExStart → Exchange → Loading → Full
  • OSPF Path Preference: Intra > Inter > E1 > E2
  • BGP: TCP/179، Path Vector، eBGP AD=20، iBGP AD=200
  • BGP Best Path: Weight > Local Pref > Originate > AS Path > Origin > MED > eBGP > IGP Metric > Oldest > Router ID
  • BGP Attributes: Well-Known (Mandatory/Discretionary)، Optional (Transitive/Non-Transitive)
  • Route Reflector: کاهش iBGP Full-Mesh با ORIGINATOR_ID و CLUSTER_LIST
  • Redistribution: همیشه با Route Map + Tag + Prefix-List
  • PBR: Inbound Only، با Route Map و Local Policy برای ترافیک روتر
