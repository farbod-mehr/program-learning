۱.۱ مدل‌های طراحی سلسله‌مراتبی

طراحی شبکه‌های سازمانی بر پایه‌ی سه لایه بنا شده که هرکدام نقش مشخصی دارند. انتخاب تعداد لایه‌ها (۲ یا ۳) به اندازه‌ی سازمان و بودجه بستگی دارد.

سه لایه در طراحی سنتی:

  • Access Layer: اتصال دستگاه‌های کاربر نهایی (PC، IP Phone، AP، دوربین). تمرکز روی Port Density، PoE و امنیت پورت.
  • Distribution Layer: Aggregation، اعمال Policy (ACL، QoS)، Inter-VLAN Routing و مرز بین Access و Core.
  • Core Layer: ستون فقرات شبکه با پهنای باند بالا، Latency کم و بدون هیچ Policy پیچیده.
🏢 Three-Tier (سنتی):

مناسب سازمان‌های بزرگ با چند ساختمان. Core، Distribution و Access جدا.

[Core] ← ستون فقرات
   ↑↓
[Distribution] ← Policy & Routing
   ↑↓
[Access] ← Endpoints
🏢 Two-Tier (Collapsed Core):

مناسب سازمان‌های متوسط. Core و Distribution در یک لایه ادغام می‌شوند.

[Collapsed Core/Distribution]
   ↑↓
[Access]

۱.۲ معماری Fabric و Spine-Leaf

Fabric یک معماری مدرن است که به‌جای سلسله‌مراتب سنتی، از یک توپولوژی Full-Mesh بین دو لایه استفاده می‌کند.

مشخصات Spine-Leaf:

  • هر Leaf به همه‌ی Spineها وصل می‌شود
  • Leafها به هم وصل نمی‌شوند
  • Spineها به هم وصل نمی‌شوند
  • پهنای باند یکنواخت — هر Leaf فقط یک Hop از هر Leaf دیگر فاصله دارد
  • مقیاس‌پذیری افقی: با اضافه کردن Spine یا Leaf جدید، شبکه بزرگ‌تر می‌شود
  • Overlay معمولاً با VXLAN ساخته می‌شود
[Spine1]  [Spine2]  [Spine3]
   │  ╲    ╱  │  ╲    ╱  │
   │   ╲  ╱   │   ╲  ╱   │
   │    ╳    │    ╳    │
   │   ╱  ╲   │   ╱  ╲   │
   ↓  ╱    ╲  ↓  ╱    ╲  ↓
[Leaf1]  [Leaf2]  [Leaf3]
   │        │        │
[Server] [Server] [Server]
💡 نکته
برای همگرایی سریع و پایداری در Fabric، معمولاً از BGP بین Spine و Leaf استفاده می‌شود (eBGP در Underlay) یا OSPF در سناریوهای ساده‌تر.

۱.۳ High Availability — Redundancy، FHRP و SSO

در شبکه‌های سازمانی، هیچ نقطه‌ی شکستی (Single Point of Failure) نباید وجود داشته باشد. HA از سه بخش تشکیل می‌شود:

  • Physical Redundancy: دو لینک، دو سوئیچ، دو مسیر برق
  • Protocol Redundancy: پروتکل‌های مسیریابی و سوئیچینگ با همگرایی خودکار
  • Gateway Redundancy: FHRP برای Gateway کاربران

FHRP در CCNP:

  • HSRP: اختصاصی سیسکو، Active/Standby، Virtual MAC = 0000.0c07.acXX
  • VRRP: استاندارد باز، Master/Backup، Virtual MAC = 0000.5e00.01XX
  • GLBP: اختصاصی سیسکو با قابلیت Load Balancing بین روترها
! HSRP پیشرفته با Tracking
R1(config)# interface Gi0/0
R1(config-if)# ip address 192.168.10.2 255.255.255.0
R1(config-if)# standby 1 ip 192.168.10.1
R1(config-if)# standby 1 priority 150
R1(config-if)# standby 1 preempt delay minimum 30
R1(config-if)# standby 1 track Gi0/1 30
R1(config-if)# standby 1 track 5 decrement 20
! اگر Gi0/1 قطع شد، ۳۰ واحد از Priority کم می‌شود
! اگر Track List 5 خطا داد، ۲۰ واحد کم می‌شود

SSO (Stateful Switchover): در روترها و سوئیچ‌های Dual-Supervisor، Supervisor فعال State را به Supervisor Standby منتقل می‌کند تا در صورت Failover، جلسات (مثل OSPF Adjacency یا NAT Sessions) حفظ شوند.

NSF (Non-Stop Forwarding) + SSO = تجربه‌ی Failover بدون قطعی در پلن Control.

۱.۴ مکانیزم‌های سوئیچینگ: CAM، TCAM و CEF

CAM (Content Addressable Memory): جدول MAC سوئیچ. برای Lookup در لایه ۲ — سرعت جستجو در یک Clock Cycle.

TCAM (Ternary Content Addressable Memory): جدول مورد استفاده برای ACL، QoS Classification و Routing در سوئیچ‌های L3. با پشتیبانی از Wildcard و Mask — سرعت بسیار بالا ولی گران‌قیمت.

CEF (Cisco Express Forwarding): مکانیزم سوئیچینگ مدرن سیسکو که بر پایه‌ی دو جدول کار می‌کند:

  • FIB (Forwarding Information Base): کپی سخت‌افزاری از جدول مسیریابی، در TCAM. برای Lookup سریع.
  • Adjacency Table: اطلاعات لایه ۲ Next-Hop (MAC و Encapsulation).

ترکیب FIB + Adjacency → Forwarding سریع بدون پردازش هر بسته در CPU.

۱.۵ مقایسه Process، Fast و CEF Switching

روش Lookup Performance وضعیت
Process Switching هر بسته → CPU 🐌 خیلی کند قدیمی
Fast Switching Cache Flow 🐢 متوسط قدیمی
CEF FIB + Adjacency در TCAM 🚀 بسیار سریع استاندارد فعلی

۱.۶ SD-WAN — معماری و اجزا

SD-WAN (Software-Defined WAN) یک معماری مدرن برای اتصال شعب سازمان است که جایگزین WAN سنتی (MPLS) می‌شود. مزیت اصلی: استفاده از لینک‌های Broadband ارزان در کنار MPLS.

سه جزء اصلی Cisco SD-WAN (Viptela):

  • vManage: رابط مدیریت گرافیکی (NMS) — Provision، Monitor، Troubleshoot
  • vBond: Orchestrator — احراز هویت اولیه دستگاه‌ها و معرفی آن‌ها به Controller
  • vSmart: Controller — توزیع Policy و Routing Information به vEdgeها

دستگاه‌های Edge:

  • vEdge / cEdge: روترهای SD-WAN که در شعب سازمان قرار می‌گیرند
  • Control Plane از Data Plane جدا شده است
Control Plane:
   vBond ←→ vSmart ←→ vManage
       │
       ↓ (توزیع Policy و Routes)
Data Plane:
   vEdge ←(IPsec/DTLS)→ vEdge
   (Overlay روی هر لینک فیزیکی — MPLS، Broadband، LTE)
ℹ️ مزایای کلیدی SD-WAN
  • Zero Touch Provisioning (ZTP): نصب و راه‌اندازی با یک بار تایپ کردن
  • Application-Aware Routing: انتخاب بهترین لینک بر اساس نوع ترافیک (VoIP vs Bulk)
  • Segmentation: جداسازی ترافیک مشتریان با VPN ID
  • End-to-End Encryption: IPsec خودکار بین همه‌ی سایت‌ها

۱.۷ SD-Access — Fabric Campus

SD-Access معماری مدرن سیسکو برای شبکه‌های Campus است که بر پایه‌ی LISP (Control Plane) و VXLAN (Data Plane) ساخته می‌شود.

اجزای اصلی SD-Access:

  • DNA Center: مدیریت متمرکز و Provision خودکار
  • Identity Services Engine (ISE): احراز هویت و اعمال Policy
  • Control Plane Node: نگه‌داری Database از تمام Endpointها (LISP Map-Server)
  • Edge Node: سوئیچ‌هایی که Endpointها به آن‌ها وصل می‌شوند
  • Border Node: مرز Fabric با شبکه‌های خارجی (مثل WAN یا DC)
  • Intermediate Node: سوئیچ‌های میانی که فقط Forward می‌کنند

مزایای SD-Access:

  • Segmentation با VXLAN: میلیون‌ها Segment (VNI) در مقابل 4096 VLAN
  • Policy متمرکز: مشابه Firewall ولی روی کل Fabric
  • Mobility: Endpoint هر جای شبکه وصل شود، همان Policy اعمال می‌شود
  • Automation: Provision با یک کلیک در DNA Center

۱.۸ VXLAN و LISP

VXLAN (Virtual Extensible LAN): یک تکنولوژی MAC-in-UDP است که فریم‌های L2 را داخل بسته‌های UDP (پورت 4789) کپسوله می‌کند.

  • شناسه‌ی VXLAN: VNI (VXLAN Network Identifier) — ۲۴ بیت، حدود ۱۶ میلیون Segment
  • VTEP (VXLAN Tunnel Endpoint): دستگاهی که Encapsulation/Decapsulation را انجام می‌دهد
  • Overlay روی Underlay IP — نیازی به Trunk بین Data Centerها نیست

LISP (Locator/ID Separation Protocol): پروتکل جداسازی هویت از مکان:

  • EID (Endpoint ID): آدرس هویت — مثلاً IP هاست
  • RLOC (Routing Locator): آدرس مکان — مثلاً IP روتر
  • Map-Server: نگه‌داری Database EID → RLOC
  • Map-Resolver: پاسخ به درخواست‌های Lookup
! نمونه‌ی Mapping در LISP
EID: 192.168.10.5 (Host IP)
  ↓
RLOC: 10.10.10.1 (Edge Node IP)

! وقتی هاست جابه‌جا می‌شود، EID همان می‌ماند ولی RLOC تغییر می‌کند
! نتیجه: Policy ثابت + Mobility

۱.۱۰ VRF، GRE و IPsec

VRF (Virtual Routing and Forwarding): چند جدول مسیریابی مستقل روی یک روتر فیزیکی. هر VRF جدا از دیگری است — حتی اگر IP یکسان داشته باشند.

! پیکربندی VRF
Router(config)# ip vrf CUSTOMER-A
Router(config-vrf)# rd 65000:100
Router(config-vrf)# route-target export 65000:100
Router(config-vrf)# route-target import 65000:100
Router(config-vrf)# exit

Router(config)# interface Gi0/0
Router(config-if)# ip vrf forwarding CUSTOMER-A
Router(config-if)# ip address 192.168.1.1 255.255.255.0

! بررسی
Router# show ip vrf
Router# show ip route vrf CUSTOMER-A

GRE (Generic Routing Encapsulation): تونل ساده‌ی L3 بدون رمزنگاری. پروتکل IP با شماره 47. برای انتقال Multicast و Routing Protocol روی تونل مناسب.

! GRE Tunnel
R1(config)# interface Tunnel0
R1(config-if)# ip address 10.1.1.1 255.255.255.252
R1(config-if)# tunnel source Gi0/0
R1(config-if)# tunnel destination 203.0.113.2

! نکته: GRE رمزنگاری ندارد — با IPsec ترکیب می‌شود
! (GRE over IPsec)

IPsec: چارچوب رمزنگاری L3 با دو پروتکل:

  • AH (Authentication Header): فقط احراز هویت — بدون رمزنگاری
  • ESP (Encapsulating Security Payload): احراز هویت + رمزنگاری

دو حالت IPsec:

  • Transport Mode: فقط Payload رمزنگاری می‌شود — برای End-to-End
  • Tunnel Mode: کل بسته رمزنگاری می‌شود — برای Site-to-Site VPN

۱.۱۱ QoS در شبکه‌های سازمانی

در CCNP، QoS را در سطح معماری می‌بینیم:

  • Trust Boundary: جایی که Marking اعتماد می‌شود — معمولاً در Access Layer یا روی IP Phone
  • Classification & Marking: با NBAR یا ACL — DSCP در L3، CoS در L2
  • Queuing: LLQ (Low Latency Queue) برای VoIP، CBWFQ برای بقیه
  • Congestion Avoidance: WRED برای جلوگیری از Sync Global
  • Policing / Shaping: Policing = Drop، Shaping = Buffer
! نمونه‌ی Policy Map QoS در CCNP
Router(config)# class-map match-any VOICE
Router(config-cmap)# match dscp ef
Router(config-cmap)# match protocol rtp audio

Router(config)# class-map match-any CRITICAL-DATA
Router(config-cmap)# match dscp af31 af41

Router(config)# policy-map WAN-QOS
Router(config-pmap)# class VOICE
Router(config-pmap-c)# priority percent 20
Router(config-pmap)# class CRITICAL-DATA
Router(config-pmap-c)# bandwidth remaining percent 30
Router(config-pmap)# class class-default
Router(config-pmap-c)# fair-queue

Router(config)# interface Gi0/1
Router(config-if)# service-policy output WAN-QOS

۱.۱۲ Multicast — IGMP، PIM و RP

مفاهیم پایه:

  • Unicast: یک به یک | Broadcast: یک به همه | Multicast: یک به گروه
  • کلاس D: 224.0.0.0/4 — بازه‌ی Multicast
  • 224.0.0.0/24 رزرو Local (TTL=1)

IGMP (Internet Group Management Protocol): بین Host و Router محلی:

  • IGMPv2: Join، Leave، Query
  • IGMPv3: SSM (Source-Specific Multicast)
  • IGMP Snooping: سوئیچ Multicast را فقط به پورت‌های عضو می‌فرستد

PIM (Protocol Independent Multicast): بین روترها — دو حالت اصلی:

  • PIM Dense Mode: ابتدا همه‌جا، بعد Prune — مناسب شبکه‌های کوچک
  • PIM Sparse Mode: فقط با درخواست — نیازمند RP (Rendezvous Point)

RP (Rendezvous Point): نقطه‌ی ملاقات در Sparse Mode. گزینه‌ها:

  • Static RP: ساده، دستی
  • Auto-RP: سیسکو اختصاصی
  • BSR (Bootstrap Router): استاندارد باز
  • Anycast RP: مقیاس‌پذیر با MSDP
! پیکربندی PIM Sparse Mode
Router(config)# ip multicast-routing
Router(config)# ip pim rp-address 10.0.0.1
Router(config)# interface Gi0/0
Router(config-if)# ip pim sparse-mode

! بررسی
Router# show ip mroute
Router# show ip pim neighbor
Router# show ip pim rp mapping

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
در Spine-Leaf، هر Leaf دقیقاً یک Hop از هر Leaf دیگر دارد. اگر Latency بین Leafها متفاوت است، یعنی طراحی Spine-Leaf شما به‌درستی پیاده نشده.
⚠️ هشدار طراحی
هرگز روی Core Layer سیاست‌های پیچیده (ACL، NAT، QoS سنگین) اعمال نکن. Core باید سریع و بدون Policy باشد — Policy در Distribution.
🏆 نکته‌ی طلایی
در SD-Access، تفاوت اصلی با VLAN سنتی این است که VXLAN با VNI می‌تواند میلیون‌ها Segment بسازد در مقابل 4096 VLAN. این یعنی بدون محدودیت طراحی کن.
ℹ️ اطلاعات بیشتر
در فصل ۲ CCNP با VRF در سناریوهای Multi-Tenant و VXLAN در SD-Access عمیق‌تر آشنا می‌شوی.
🔮 دیدگاه پیشرفته
در ENARSI با MPLS، DMVPN و BGP معماری‌های پیچیده‌ی WAN و SP می‌سازی.

مثال ۳ — GRE over IPsec

! ===== گام ۱: GRE Tunnel =====
R1(config)# interface Tunnel0
R1(config-if)# ip address 10.1.1.1 255.255.255.252
R1(config-if)# tunnel source Gi0/0
R1(config-if)# tunnel destination 203.0.113.2
R1(config-if)# tunnel mode gre ip

! ===== گام ۲: IPsec روی GRE =====
R1(config)# crypto isakmp policy 10
R1(config-isakmp)# encr aes 256
R1(config-isakmp)# hash sha256
R1(config-isakmp)# authentication pre-share
R1(config-isakmp)# group 14
R1(config-isakmp)# exit

R1(config)# crypto isakmp key SecureKey123 address 203.0.113.2

R1(config)# crypto ipsec transform-set MY-SET esp-aes 256 esp-sha256-hmac

R1(config)# crypto map GRE-MAP 10 ipsec-isakmp

🛠️ کارگاه عملی گام‌به‌گام

  1. در GNS3 یا EVE-NG یک توپولوژی Spine-Leaf با ۲ Spine و ۳ Leaf بساز
  2. Underlay را با OSPF یا eBGP پیکربندی کن
  3. یک Overlay ساده با VXLAN بین Leafها بساز (unicast flood-and-learn)
  4. یک VRF مشترک بساز و روی VTEPها اعمال کن
  5. روی Spine-Leafها IP Multicast PIM Sparse Mode فعال کن
  6. یک سوئیچ L3 با VRF-Lite برای جداسازی دو Tenant پیاده کن
  7. HSRP با Tracking روی دو روتر لبه پیاده‌سازی کن
  8. QoS Policy برای VoIP و داده روی WAN پیاده کن
  9. یک GRE Tunnel بین دو سایت بساز
  10. GRE را با IPsec (Tunnel Mode با ESP-AES-256) امن کن
  11. CEF را روی همه‌ی روترها بررسی کن — FIB و Adjacency
  12. IGMP Snooping روی سوئیچ Access برای Multicast فعال کن
  13. Multicast بین دو سایت از طریق GRE Tunnel تست کن
  14. تأیید نهایی: پینگ و Multicast Ping بین Endpointها

🚫 خطاهای رایج و رفع‌اشکال

  • Spine-Leaf Latency متفاوت: احتمالاً Underlay مسیریابی بهینه ندارد — BGP/OSPF را بررسی کن.
  • VXLAN Tunnel بالا نمی‌آید: VTEP Source IP باید در Underlay قابل دسترسی باشد — Ping VTEPها را چک کن.
  • VRF Route Leak: در Route-Target اشتباه — Export/Import را دو طرف چک کن.
  • HSRP Preempt کار نمی‌کند: Preempt باید روی Active هم فعال باشد.
  • GRE Tunnel Flapping: Source Interface باید Up باشد و Stable — از Loopback برای Source استفاده کن.
  • IPsec SA برقرار نمی‌شود: Pre-Shared Key، Transform-Set و ACL (Match Address) را چک کن.
  • QoS اثری ندارد: Trust Boundary را چک کن — Marking باید در ورودی انجام و Trust شود.
  • Multicast Flooding: IGMP Snooping روی سوئیچ Access فعال باشد.
  • CEF در برخی مسیرها از کار افتاده: ممکن است TCAM Overflow باشد — با show platform tcam بررسی کن.
  • SD-WAN Edge وصل نمی‌شود: vBond IP و Certificate (Chassis/Serial) را چک کن.

🎯 پروژه‌ی پایانی فصل

یک معماری کامل Enterprise با SD-WAN و SD-Access طراحی کن:

  • Fabric Campus: ۲ Spine + ۴ Leaf با VXLAN Overlay و Underlay eBGP
  • VRF: حداقل دو Tenant (مثلاً Corporate و Guest)
  • Border Node: اتصال Fabric به WAN
  • WAN Edge: SD-WAN شبیه‌سازی‌شده (یا DMVPN به‌جای آن)
  • FHRP: HSRP یا VRRP برای Gateway کاربران
  • QoS: LLQ برای VoIP، CBWFQ برای بقیه
  • Multicast: PIM Sparse Mode با RP روی Border
  • HA: تمام لینک‌های حیاتی دوگانه (Dual-Homed)
  • مستندسازی کامل معماری (Diagram + IP Plan + Policy Doc)

📋 جمع‌بندی و برگه‌تقب

  • Three-Tier: Core + Distribution + Access — سازمان‌های بزرگ
  • Two-Tier: Collapsed Core — سازمان‌های متوسط
  • Fabric/Spine-Leaf: Data Center — Latency یکنواخت، مقیاس‌پذیری افقی
  • FHRP: HSRP (سیسکو)، VRRP (استاندارد باز)، GLBP (Load Balancing)
  • SSO + NSF: High Availability در Control Plane
  • CAM: MAC Table — TCAM: ACL/Routing Table
  • CEF: FIB (TCAM) + Adjacency Table → Forwarding سریع
  • SD-WAN اجزا: vManage (مدیریت) + vBond (Orchestrator) + vSmart (Controller)
  • SD-Access اجزا: Control Plane Node + Edge Node + Border Node + Intermediate Node
  • VXLAN: MAC-in-UDP، VNI ۲۴ بیت، ~۱۶M Segment
  • LISP: جدا کردن EID (هویت) از RLOC (مکان)
  • VRF: چند جدول مسیریابی مستقل — Multi-Tenant
  • GRE: تونل L3 بدون رمزنگاری (پروتکل IP/47)
  • IPsec: AH (Auth) + ESP (Auth+Encrypt) — Transport یا Tunnel Mode
  • QoS: LLQ برای VoIP، CBWFQ برای داده، WRED برای Congestion Avoidance
  • Multicast: IGMP (Host↔Router)، PIM (Router↔Router)، RP در Sparse Mode
