۷.۱ مفاهیم پایه‌ی Network Assurance

Network Assurance یعنی اطمینان از این‌که شبکه در حال کارکردن طبق طراحی است. سه ستون اصلی:

  • Monitoring (پایش): دیدن وضعیت لحظه‌ای — SNMP، Syslog، NetFlow
  • Baseline (خط پایه): ثبت وضعیت عادی — برای مقایسه با زمان مشکل
  • Analytics (تحلیل): پیش‌بینی و کشف الگو — DNA Center، AIOps
💡 نکته‌ی کاربردی
قبل از هر عیب‌یابی، Baseline داشته باش. بدون آن، نمی‌دانی «عادی» چه شکلی است.

۷.۲ Syslog — سطوح، ساختار، سرور مرکزی

Syslog استاندارد ارسال پیام‌های سیستمی به سرور مرکزی است (RFC 5424). هر دستگاه سیسکو پیام‌های خود را با Priority مشخص به سرور Syslog می‌فرستد.

۸ سطح Syslog (Severity Level):

Level نام توضیح
0Emergencyسیستم از کار افتاده
1Alertاقدام فوری لازم
2Criticalشرایط بحرانی
3Errorخطا
4Warningهشدار
5Notificationاطلاع‌رسانی عادی
6Informationalاطلاعات عمومی
7Debuggingپیام‌های Debug

ساختار پیام Syslog:

%FACILITY-SEVERITY-MNEMONIC: Message text

مثال:
%LINK-3-UPDOWN: Interface Gi0/1, changed state to up
%OSPF-5-ADJCHG: Process 1, Nbr 2.2.2.2 on Gi0/0 from LOADING to FULL

Facility: نوع سرویس (LINK, OSPF, SYS, ...)
Severity: عدد 0-7
Mnemonic: کد پیام
! پیکربندی Syslog Client
Router(config)# logging host 192.168.1.100
Router(config)# logging trap informational
! trap = حداکثر سطحی که ارسال می‌شود (5 = Notification، 6 = Informational)

Router(config)# logging source-interface Loopback0
Router(config)# logging buffered 16384 debugging
! Buffered: نگه‌داری در حافظه محلی
! 16384 = حجم Buffer

Router(config)# service timestamps log datetime msec localtime show-timezone
Router(config)# service sequence-numbers
! اضافه کردن شماره ترتیبی به هر پیام

! بررسی
Router# show logging
Router# show logging | include ERROR
Router# show logging | include OSPF
Router# show logging history

! ارسال به چند سرور
Router(config)# logging host 192.168.1.100
Router(config)# logging host 192.168.1.101 transport tcp port 514
! می‌توانی از TCP یا UDP استفاده کنی — TCP مطمئن‌تر

۷.۳ SNMP — نسخه‌ها، MIB، OID، Trap vs Inform

SNMP (Simple Network Management Protocol) پروتکل استاندارد پایش و مدیریت دستگاه‌های شبکه است.

سه نسخه‌ی اصلی:

ویژگی SNMPv1 SNMPv2c SNMPv3
AuthenticationCommunityCommunityUser + Auth
Encryption❌❌✅ (AES/DES)
Bulk Retrieval❌✅ GetBulk✅ GetBulk
امنیت🔴 ضعیف🟡 متوسط🟢 قوی

مفاهیم کلیدی SNMP:

  • MIB (Management Information Base): دیتابیس سلسله‌مراتبی اطلاعات دستگاه
  • OID (Object Identifier): آدرس هر مقدار در MIB — مثل 1.3.6.1.2.1.1.5 (نام دستگاه)
  • Agent: نرم‌افزار روی دستگاه که به NMS پاسخ می‌دهد
  • NMS (Network Management Station): سرور پایش (SolarWinds، PRTG، Zabbix)
  • Polling: NMS به دستگاه درخواست می‌فرستد (Get، GetNext، GetBulk)
  • Trap: دستگاه خودش به NMS خبر می‌دهد (بدون ACK)
  • Inform: مثل Trap ولی با ACK — مطمئن‌تر
! ===== SNMPv2c =====
Router(config)# snmp-server community PUBLIC-RO ro
! RO = فقط خواندن
Router(config)# snmp-server community PRIVATE-RW rw
! RW = خواندن و نوشتن (توصیه نمی‌شود)

Router(config)# snmp-server location Tehran-DC1
Router(config)# snmp-server contact admin@company.ir
Router(config)# snmp-server host 192.168.1.100 version 2c PUBLIC-RO
Router(config)# snmp-server enable traps
Router(config)# snmp-server enable traps ospf
! محدودسازی Trapها

! بررسی
Router# show snmp
Router# show snmp community
Router# show snmp host

! ===== SNMPv3 =====
Router(config)# snmp-server group ADMINS v3 priv
! priv = Auth + Encryption

Router(config)# snmp-server user admin ADMINS v3 auth sha AuthPass@2024 priv aes 128 PrivPass@2024

Router(config)# snmp-server host 192.168.1.100 version 3 priv admin

! بررسی
Router# show snmp user
Router# show snmp group

۷.۴ SNMPv3 — Authentication و Encryption

SNMPv3 سه سطح امنیتی دارد:

  • noAuthNoPriv: بدون Authentication و رمزنگاری (مثل v1/v2c)
  • authNoPriv: با Authentication ولی بدون رمزنگاری
  • authPriv: با هر دو — امن‌ترین

الگوریتم‌های Authentication:

  • MD5 (قدیمی، 128-bit)
  • SHA (Secure Hash Algorithm، 160-bit)
  • SHA-256 (مدرن، توصیه‌شده)

الگوریتم‌های Encryption:

  • DES (56-bit — ضعیف)
  • 3DES (168-bit)
  • AES-128 (استاندارد فعلی)
  • AES-256 (قوی‌ترین)
! SNMPv3 پیشرفته با AES-256
Router(config)# snmp-server group SECURE-ADMIN v3 priv

Router(config)# snmp-server user secureadmin SECURE-ADMIN v3 \
    auth sha AuthKey@2024 \
    priv aes 256 PrivKey@2024

! Trap به NMS
Router(config)# snmp-server host 192.168.1.100 version 3 priv secureadmin

! بررسی
Router# show snmp user secureadmin
Router# show snmp group SECURE-ADMIN

! تست از NMS با snmpwalk:
! snmpwalk -v3 -l authPriv -u secureadmin -a SHA -A AuthKey@2024 \
!          -x AES -X PrivKey@2024 192.168.1.1 1.3.6.1.2.1.1

۷.۵ NetFlow — Flexible NetFlow و تحلیل ترافیک

NetFlow یک تکنولوژی سیسکو است که اطلاعات جریان‌های ترافیکی را جمع‌آوری می‌کند. هر «Flow» با ۷ کلید تعریف می‌شود:

  • Source IP
  • Destination IP
  • Source Port
  • Destination Port
  • Protocol (TCP، UDP، ICMP)
  • Type of Service (ToS)
  • Input Interface

دو نسخه‌ی NetFlow:

  • Traditional NetFlow: ثابت با ۷ کلید
  • Flexible NetFlow: قابل تنظیم — می‌توانی کلیدها و فیلدهای خروجی را خودت تعریف کنی
! ===== Flexible NetFlow =====

! گام ۱: Flow Record — تعریف چه چیزی جمع‌آوری شود
Router(config)# flow record MY-RECORD
Router(config-flow-record)# match ipv4 source address
Router(config-flow-record)# match ipv4 destination address
Router(config-flow-record)# match ipv4 protocol
Router(config-flow-record)# match transport source-port
Router(config-flow-record)# match transport destination-port
Router(config-flow-record)# collect counter bytes
Router(config-flow-record)# collect counter packets
Router(config-flow-record)# collect timestamp sys-uptime first
Router(config-flow-record)# collect timestamp sys-uptime last
Router(config-flow-record)# exit

! گام ۲: Flow Exporter — تعریف سرور مقصد
Router(config)# flow exporter NETFLOW-SRV
Router(config-flow-exporter)# destination 192.168.1.100
Router(config-flow-exporter)# source Loopback0
Router(config-flow-exporter)# transport udp 2055
Router(config-flow-exporter)# template data timeout 60
Router(config-flow-exporter)# exit

! گام ۳: Flow Monitor — ترکیب Record و Exporter
Router(config)# flow monitor MY-MONITOR
Router(config-flow-monitor)# record MY-RECORD
Router(config-flow-monitor)# exporter NETFLOW-SRV
Router(config-flow-monitor)# cache timeout active 60
Router(config-flow-monitor)# cache timeout inactive 15
Router(config-flow-monitor)# exit

! گام ۴: اعمال روی Interface
Router(config)# interface Gi0/0
Router(config-if)# ip flow monitor MY-MONITOR input
Router(config-if)# ip flow monitor MY-MONITOR output
Router(config-if)# exit

! بررسی
Router# show flow record MY-RECORD
Router# show flow exporter NETFLOW-SRV
Router# show flow monitor MY-MONITOR
Router# show flow monitor MY-MONITOR cache format table
Router# show flow interface Gi0/0
💡 NetFlow در برابر SNMP
  • SNMP: چه مقدار ترافیک عبور می‌کند؟ (byte counters)
  • NetFlow: چه نوع ترافیکی از کجا به کجا می‌رود؟ (source/destination)

۷.۶ IP SLA — پایش Latency، Jitter، Reachability

IP SLA یک ابزار فعال (Active) است که از یک روتر ترافیک مصنوعی می‌فرستد و پاسخ را اندازه می‌گیرد:

چیزهایی که IP SLA اندازه می‌گیرد:

  • RTT (Round Trip Time)
  • Jitter (تغییرات تأخیر)
  • Packet Loss
  • Connectivity (ICMP Echo، TCP Connect، HTTP Get)
  • VoIP Quality (MOS Score)
! ===== IP SLA Operation =====
Router(config)# ip sla 1
Router(config-ip-sla)# icmp-echo 8.8.8.8 source-interface Loopback0
Router(config-ip-sla)# frequency 30
Router(config-ip-sla)# timeout 5000
Router(config-ip-sla)# threshold 500
Router(config-ip-sla)# exit

! زمان‌بندی
Router(config)# ip sla schedule 1 life forever start-time now

! بررسی
Router# show ip sla configuration 1
Router# show ip sla statistics 1
Router# show ip sla summary

! ===== IP SLA با Object Tracking =====
Router(config)# track 1 ip sla 1 reachability
! اگر IP SLA شکست خورد، Track Down می‌شود

! استفاده در HSRP
Router(config)# interface Gi0/0
Router(config-if)# standby 1 ip 192.168.1.1
Router(config-if)# standby 1 priority 110
Router(config-if)# standby 1 track 1 decrement 30
! اگر Track Down شد، Priority ۳۰ کم می‌شود

! استفاده در Static Route
Router(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1 track 1

! بررسی
Router# show track
Router# show track 1

۷.۷ BFD — تشخیص سریع قطعی لینک

BFD (Bidirectional Forwarding Detection) یک پروتکل سبک است که در چند صد میلی‌ثانیه قطعی لینک را تشخیص می‌دهد — در مقابل OSPF که چند ثانیه طول می‌کشد.

مزایای BFD:

  • همگرایی سریع (sub-second)
  • مستقل از Routing Protocol — روی OSPF، BGP، EIGRP، HSRP کار می‌کند
  • Overhead کم (UDP/3784)
  • Echo Mode با UDP/3785
! ===== BFD با OSPF =====
Router(config)# interface Gi0/0
Router(config-if)# bfd interval 100 min_rx 100 multiplier 3
! interval: هر ۱۰۰ms یک Hello BFD
! multiplier: ۳ بار Hello دریافت نشد → Down
! زمان تشخیص: 100 × 3 = 300ms

Router(config)# router ospf 1
Router(config-router)# bfd all-interfaces
! یا روی Interface خاص:
Router(config)# interface Gi0/0
Router(config-if)# ip ospf bfd

! ===== BFD با BGP =====
Router(config)# router bgp 65001
Router(config-router)# neighbor 203.0.113.2 fall-over bfd

! ===== BFD با EIGRP =====
Router(config)# router eigrp 100
Router(config-router)# bfd all-interfaces

! ===== BFD با HSRP =====
Router(config)# interface Gi0/0
Router(config-if)# standby 1 ip 192.168.1.1
Router(config-if)# standby 1 bfd

! بررسی
Router# show bfd neighbors
Router# show bfd neighbors details
Router# show bfd interface Gi0/0
Router# show bfd summary
🏆 نکته‌ی طلایی
BFD برای لینک‌های حیاتی (بین Data Centerها، ISPهای چندگانه) ضروری است. با BFD، همگرایی OSPF از ۴۰ ثانیه به زیر ۱ ثانیه می‌رسد.

۷.۸ SPAN/RSPAN/ERSPAN — تحلیل ترافیک

SPAN (Switched Port Analyzer) مکانیزم کپی کردن ترافیک یک یا چند پورت به یک پورت مقصد است برای تحلیل با Wireshark یا IDS.

سه نوع SPAN:

نوع محدوده کاربرد
SPANیک سوئیچتحلیل محلی
RSPANچند سوئیچارسال به سوئیچ دیگر
ERSPANبین سایت‌هاارسال روی L3 با GRE
 
! ===== SPAN Local =====
Switch(config)# monitor session 1 source interface Gi0/1 both
! both = هر دو جهت — یا rx / tx

Switch(config)# monitor session 1 destination interface Gi0/10
! یا:
Switch(config)# monitor session 1 destination interface Gi0/10 encapsulation replicate
! replicate = حفظ VLAN Tag اصلی

! چند Source
Switch(config)# monitor session 1 source interface Gi0/1-5 both
! یا با VLAN:
Switch(config)# monitor session 1 source vlan 10 both

! بررسی
Switch# show monitor session 1
Switch# show monitor session all

! حذف
Switch(config)# no monitor session 1

! ===== RSPAN =====
! روی سوئیچ مبدأ
Source(config)# vlan 999
Source(config-vlan)# remote-span

Source(config)# monitor session 1 source interface Gi0/1 both
Source(config)# monitor session 1 destination remote vlan 999

! روی سوئیچ مقصد
Dest(config)# vlan 999
Dest(config-vlan)# remote-span

Dest(config)# monitor session 1 source remote vlan 999
Dest(config)# monitor session 1 destination interface Gi0/10

! ===== ERSPAN =====
Router(config)# monitor session 1 type erspan-source
Router(config-mon-erspan-src)# source interface Gi0/1 both
Router(config-mon-erspan-src)# no shutdown
Router(config-mon-erspan-src)# destination
Router(config-mon-erspan-src-dst)# erspan-id 10
Router(config-mon-erspan-src-dst)# ip address 192.168.1.100
Router(config-mon-erspan-src-dst)# origin ip address 192.168.1.1
Router(config-mon-erspan-src-dst)# exit

۷.۱۰ Cisco DNA Center — Assurance و Health Score

Cisco DNA Center (الان Catalyst Center) پلتفرم مرکزی سیسکو است. بخش Assurance آن قوی‌ترین ابزار AIOps در شبکه‌های سازمانی است.

اجزای Assurance:

  • Health Score: نمره‌ی ۰-۱۰۰ برای هر دستگاه، Client، Application
  • 360° View: نمای کامل یک Client یا Device
  • Issue Detection: کشف خودکار مشکلات (Onboarding، Connectivity، Performance)
  • Guided Troubleshooting: راهنمای گام‌به‌گام عیب‌یابی
  • Path Trace: نمایش مسیر بسته بین دو Endpoint
  • Network Time Travel: بررسی وضعیت گذشته (Snapshot)
  • AI/ML: پیش‌بینی مشکلات، Anomaly Detection

۷.۱۱ NETCONF و RESTCONF — مدیریت قابل برنامه‌ریزی

NETCONF و RESTCONF پروتکل‌های مدرن مدیریت دستگاه‌های شبکه به‌صورت برنامه‌ریزی‌شده هستند.

ویژگی NETCONF RESTCONF
TransportSSH/830HTTPS/443
Data FormatXMLJSON یا XML
Data ModelYANGYANG
InterfaceRPCRESTful (GET/POST/PUT/DELETE)
 
! ===== فعال‌سازی NETCONF/RESTCONF روی سیسکو =====
Router(config)# netconf-yang
Router(config)# restconf
! HTTP/HTTPS
Router(config)# ip http secure-server
Router(config)# ip http authentication local

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
همیشه Syslog Server مرکزی داشته باش. بدون آن، بعد از Reboot روتر، لاگ‌ها از بین می‌روند. Syslog + NTP دقیق = عیب‌یابی حرفه‌ای.
⚠️ هشدار
SNMPv1 و v2c امن نیستند — Community String به‌صورت Plain-text ارسال می‌شود. روی همه‌ی دستگاه‌ها به SNMPv3 با authPriv مهاجرت کن.
🏆 نکته‌ی طلایی
BFD + IP SLA + Object Tracking یک ترکیب قدرتمند برای High Availability است. BFD لینک قطع را در ۳۰۰ms تشخیص می‌دهد، IP SLA مسیر را پایش می‌کند، و Tracking به HSRP/Static Route می‌گوید چه کاری کند.
ℹ️ اطلاعات بیشتر
در فصل ۸ CCNP وارد Automation پیشرفته با REST API، Python و Ansible می‌شویم.
🔮 دیدگاه پیشرفته
با AIOps و Predictive Analytics در DNA Center، می‌توانی مشکلات را قبل از رخ دادن پیش‌بینی کنی — در CCIE Enterprise Infrastructure.

🛠️ کارگاه عملی گام‌به‌گام

  1. در GNS3/EVE-NG چهار روتر + یک Syslog Server (Linux) بساز
  2. NTP روی همه‌ی روترها با Timezone IRST پیاده کن
  3. Syslog Client روی همه با ارسال به Server مرکزی
  4. SNMPv3 با authPriv راه‌اندازی کن و با snmpwalk تست کن
  5. NetFlow Flexible روی Interface WAN پیاده کن
  6. با یک ترافیک FTP از سرور، Flow را در NMS شبیه‌سازی‌شده ببین
  7. IP SLA برای پایش ISP-A و ISP-B بساز
  8. Object Tracking را به HSRP و Static Route وصل کن
  9. یک Link Failure عمدی بساز و ببین Failover چقدر طول می‌کشد
  10. BFD را فعال کن و مجدداً Link Failure بساز
  11. زمان Failover را با BFD و بدون BFD مقایسه کن (زیر ۱ ثانیه)
  12. SPAN Local روی یک Interface راه‌اندازی کن و با Wireshark تحلیل کن
  13. RESTCONF را روی یک روتر فعال کن و با curl لیست Interfaceها را بگیر
  14. عیب‌یابی: با Debug Conditional یک مشکل OSPF را پیدا کن

🚫 خطاهای رایج و رفع‌اشکال

  • Syslog نمی‌رسد: پورت UDP/514 باز، Trap Level اشتباه، یا Source-Interface مشخص نشده.
  • Syslog Message Timestamp اشتباه: NTP پیکربندی نشده یا Timezone اشتباه.
  • SNMPv3 کار نمی‌کند: Group، User و Host باید با هم هماهنگ باشند — Auth Pass و Priv Pass یکسان در دو طرف.
  • NetFlow داده نمی‌فرستد: Exporter، Monitor و اعمال روی Interface — هر سه مورد چک شود.
  • IP SLA همیشه Down: Source Interface پایدار نیست یا Target بلاک ICMP است.
  • BFD Up نمی‌شود: Interval و Multiplier باید در دو طرف یکسان باشد.
  • BFD با OSPF کار نمی‌کند: bfd all-interfaces یا ip ospf bfd فراموش شده.
  • SPAN ترافیک را Drop می‌کند: پورت Destination بیش از حد بار می‌گیرد — از RSPAN یا Filter استفاده کن.
  • Debug CPU را ۱۰۰٪ می‌کند: همیشه Conditional Debug و Console Logging Off.
  • DNA Center Device را نمی‌بیند: SNMP، NETCONF، SSH باید روی Device فعال باشد.
  • RESTCONF خطای 401: Authentication اشتباه یا HTTP Basic Auth غیرفعال.
  • RESTCONF خطای 404: مسیر YANG اشتباه — از /restconf/data/ietf-yang-library:modules-state لیست را بگیر.

📋 جمع‌بندی و برگه‌تقب

  • Syslog Levels: 0 Emergency تا 7 Debugging
  • Syslog Structure: %FACILITY-SEVERITY-MNEMONIC: Message
  • SNMPv1/v2c: Community String (Plain-text) — SNMPv3: User + Auth + Priv
  • SNMPv3 Levels: noAuthNoPriv، authNoPriv، authPriv
  • Auth: MD5، SHA، SHA-256 | Priv: DES، 3DES، AES-128، AES-256
  • MIB: دیتابیس سلسله‌مراتبی | OID: آدرس هر مقدار
  • Trap: بدون ACK | Inform: با ACK (مطمئن‌تر)
  • NetFlow: ۷ کلید (Src/Dst IP/Port، Protocol، ToS، Input Intf)
  • Flexible NetFlow: Record + Exporter + Monitor
  • IP SLA: Active Monitoring — RTT، Jitter، Packet Loss، MOS
  • Object Tracking: اتصال IP SLA به HSRP/Static Route
  • BFD: UDP/3784 (Echo 3785)، همگرایی Sub-second
  • BFD با: OSPF، BGP، EIGRP، HSRP، Static Route
  • SPAN: Local — RSPAN: بین سوئیچ‌ها — ERSPAN: روی L3 با GRE
  • Debug: همیشه Conditional + terminal monitor + no logging console
  • DNA Center Assurance: Health Score، 360° View، Path Trace، AI/ML
  • NETCONF: SSH/830، XML، RPC — RESTCONF: HTTPS/443، JSON/XML، RESTful
  • YANG: زبان مدل‌سازی داده برای NETCONF/RESTCONF
