۳.۱ مرور سریع VLAN و Trunk

در CCNA پایه‌ی این مباحث را دیدی. در اینجا نکات پیشرفته و تفاوت‌های سطح CCNP را می‌بینیم:

  • VLAN Range: Normal (1-1005) و Extended (1006-4094)
  • VLAN 1: Default — هیچ‌وقت برای Data استفاده نکن
  • VLAN 1002-1005: رزرو FDDI/Token Ring (Legacy)
  • Trunk: از 802.1Q روی همه‌ی پورت‌های Uplink
  • Native VLAN: فریم‌های بدون Tag — همیشه با VLAN اختصاصی (مثل 999) عوض کن
  • Allowed VLANs: فقط VLANهای موردنیاز را روی Trunk مجاز کن
! پیکربندی Trunk بهینه
Switch(config)# interface Gi0/24
Switch(config-if)# switchport trunk encapsulation dot1q
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk native vlan 999
Switch(config-if)# switchport trunk allowed vlan 10,20,30,999
Switch(config-if)# switchport nonegotiate
! nonegotiate: DTP را خاموش می‌کند (امنیت)

! بررسی
Switch# show interfaces trunk
Switch# show interfaces Gi0/24 switchport

۳.۲ VTP — Vlan Trunking Protocol

VTP یک پروتکل سیسکو است که اطلاعات VLAN را بین سوئیچ‌ها همگام می‌کند. مزیت: مدیریت متمرکز VLANها. عیب: اگر اشتباه پیکربندی شود، می‌تواند کل VLAN Database را پاک کند.

سه Mode اصلی VTP:

Mode ایجاد/تغییر VLAN Forward VTP Sync با دیگران
Server✅✅✅
Client❌✅✅
Transparent✅ (فقط محلی)✅ (بدون اعمال)❌

سه نسخه VTP:

  • VTPv1: فقط Normal VLANs (1-1005)
  • VTPv2: پشتیبانی از Token Ring + Versionهای بهتر (پیش‌فرض سیسکو)
  • VTPv3: Extended VLANs، Primary Server، Authentication قوی، Mode Off
! پیکربندی VTP Server
Switch(config)# vtp domain COMPANY
Switch(config)# vtp mode server
Switch(config)# vtp version 3
Switch(config)# vtp password StrongVTPPass
Switch(config)# vtp pruning
! pruning: VLANهای بی‌استفاده به Trunk فرستاده نمی‌شوند

! بررسی
Switch# show vtp status
Switch# show vtp password
Switch# show vtp counters
⚠️ خطر VTP
اگر یک سوئیچ با Revision Number بالاتر به شبکه اضافه شود، VLAN Database کل شبکه را پاک می‌کند. همیشه:
  • VTP Domain را یکتا و غیرپیش‌فرض بگذار
  • Password قوی تنظیم کن
  • روی سوئیچ‌های Edge از VTP Mode Transparent یا Off استفاده کن
  • قبل از اضافه کردن سوئیچ جدید، Revision آن را ریست کن

۳.۳ DTP — Dynamic Trunking Protocol

DTP پروتکل سیسکو برای مذاکره‌ی خودکار حالت Trunk است. خطر امنیتی جدی دارد — یک مهاجم می‌تواند با ارسال DTP Frame، پورت Access را Trunk کند و به همه‌ی VLANها دسترسی بگیرد.

حالت‌های DTP روی پورت:

Mode توضیح
Accessهمیشه Access — DTP غیرفعال
Trunkهمیشه Trunk — DTP فعال
Dynamic Autoمنتظر DTP از طرف مقابل — پاسخ می‌دهد ولی ابتکار نمی‌کند
Dynamic Desirableابتکار می‌کند و DTP می‌فرستد
NonegotiateDTP کاملاً خاموش — بهترین گزینه امنیتی
 
! غیرفعال کردن DTP روی پورت
Switch(config)# interface Gi0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport nonegotiate

! روی Trunk
Switch(config)# interface Gi0/24
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport nonegotiate

! بررسی
Switch# show dtp interface Gi0/24
! DTP information for GigabitEthernet0/24:
! TOS/TAS/TNS: TRUNK/ON/TRUNK
! TOT/TAT/TNT: 802.1Q/802.1Q/802.1Q
! Neighbor address 1: ...
! Local device ID: ...

۳.۴ Native VLAN و 802.1Q — عمیق

Native VLAN روی Trunk یعنی VLANی که فریم‌های آن بدون Tag فرستاده می‌شوند. اگر Native VLAN دو طرف Trunk یکسان نباشد، پیام CDP Error می‌آید و ترافیک VLANهای دیگر ممکن است دچار مشکل شود.

حملات Native VLAN:

  • VLAN Hopping با Double Tagging: مهاجم فریم با دو Tag 802.1Q می‌فرستد — سوئیچ اول Tag خارجی را (Native) حذف می‌کند و Tag داخلی باقی می‌ماند → دسترسی به VLAN غیرمجاز
  • راه دفاع: Native VLAN = VLAN بی‌استفاده (999)، Trunk کردن Native VLAN روی Access Ports (تگ زدن Native روی پورت کاربر)
! Defense در برابر Double Tagging
Switch(config)# interface range Gi0/1-23
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 10
Switch(config-if-range)# switchport nonegotiate

! Native VLAN اختصاصی
Switch(config)# interface Gi0/24
Switch(config-if)# switchport trunk native vlan 999

! vlan dot1q tag native — تگ زدن Native روی Trunk
Switch(config)# vlan dot1q tag native
! با این دستور، Native VLAN هم Tag می‌شود — Double Tagging نمی‌گیرد

۳.۵ STP — مرور Port Roles و States

STP کلاسیک (802.1D) با ۵ State و ۳ Port Role کار می‌کند و برای همگرایی ۳۰ تا ۵۰ ثانیه زمان می‌برد.

Port Roles در STP کلاسیک:

  • Root Port (RP): بهترین پورت هر سوئیچ غیر Root به سمت Root
  • Designated Port (DP): پورتی که ترافیک را به سمت Root هدایت می‌کند
  • Blocking Port (BP): مسدود برای جلوگیری از Loop

Port States:

State مدت داده MAC Learning
Blocking۲۰s❌❌
Listening۱۵s❌❌
Learning۱۵s❌✅
Forwarding—✅✅
Disabled—❌❌

۳.۶ RSTP — Rapid Spanning Tree Protocol (802.1w)

RSTP (که در سیسکو با نام Rapid PVST+ پیاده می‌شود) همگرایی را به زیر ۱ ثانیه می‌رساند — با سه تغییر اساسی نسبت به STP کلاسیک:

  1. Port Roles جدید: Alternate و Backup جایگزین Blocking شدند
  2. Port States جدید: Discarding جای Blocking، Listening و Disabled
  3. مکانیزم Proposal/Agreement: Handshake بین سوئیچ‌ها برای رسیدن سریع به Forwarding

Port Roles در RSTP:

  • Root Port: مثل STP کلاسیک
  • Designated Port: مثل STP کلاسیک
  • Alternate Port: پورت پشتیبان برای Root — در صورت شکست مسیر اصلی فعال می‌شود (جایگزین Blocking)
  • Backup Port: پورت پشتیبان برای Designated — در سناریوهای Hub (نادر)

Port States در RSTP:

  • Discarding: نه یاد می‌گیرد نه Forward (جایگزین Blocking، Listening، Disabled)
  • Learning: یاد می‌گیرد ولی Forward نمی‌کند
  • Forwarding: کاملاً فعال
! فعال‌سازی RSTP
Switch(config)# spanning-tree mode rapid-pvst

! بررسی
Switch# show spanning-tree
Switch# show spanning-tree vlan 10
Switch# show spanning-tree vlan 10 detail
Switch# show spanning-tree summary

۳.۷ RSTP — Proposal/Agreement و Sync

مکانیزم اصلی سرعت RSTP، Handshake بین سوئیچ‌هاست که از BPDU Flag استفاده می‌کند:

فرآیند:

  1. سوئیچ Root Proposal می‌فرستد (BPDU با Flag Proposal)
  2. سوئیچ دریافت‌کننده، پورت‌های غیرEdge خود را Sync (Block) می‌کند
  3. سوئیچ دریافت‌کننده Agreement برمی‌گرداند (BPDU با Flag Agreement)
  4. پورت به‌سرعت به Forwarding می‌رود
! اجزای کلیدی RSTP
- Sync: فرآیند Block کردن پورت‌های Downstream برای همگرایی سریع
- Proposal: پیشنهاد از سمت Root
- Agreement: تأیید از سمت Downstream
- Edge Port: پورتی که به Endpoint وصل است (مثل PortFast در STP)
- Link Type: Point-to-Point یا Shared (Hub)

! بررسی
Switch# show spanning-tree interface Gi0/1 detail
! ببین: Edge Port: Enabled, Link Type: Point-to-Point
💡 نکته
RSTP نیازمند Full-Duplex Link و Point-to-Point است تا همگرایی سریع داشته باشد. روی Hub یا لینک Half-Duplex، به STP کلاسیک برمی‌گردد.

۳.۸ MSTP — Multiple Spanning Tree Protocol (802.1s)

MSTP یا MST یک نسخه‌ی پیشرفته است که اجازه می‌دهد چند VLAN را به یک Instance نگاشت کنیم. این کار باعث:

  • کاهش بار پردازشی (به‌جای یک STP برای هر VLAN)
  • Load Balancing بین Instanceهای مختلف
  • پشتیبانی از تعداد بالای VLAN

مفاهیم کلیدی MSTP:

  • MST Instance (MSTI): یک توپولوژی STP مجزا — چند VLAN در یک Instance
  • MST Region: گروهی از سوئیچ‌ها با پیکربندی MST یکسان
  • IST (Internal Spanning Tree): Instance 0 — پیش‌فرض، همه‌ی VLANها را در بر می‌گیرد
  • CST (Common Spanning Tree): بین Regionها — مثل STP کلاسیک بین MST و PVST

پارامترهای یکسان‌ساز Region:

  1. Name: نام Region
  2. Revision Number: شماره Revision
  3. VLAN-to-Instance Mapping: جدول نگاشت
! پیکربندی MSTP
Switch(config)# spanning-tree mode mst

Switch(config)# spanning-tree mst configuration
Switch(config-mst)# name COMPANY-MST
Switch(config-mst)# revision 1
Switch(config-mst)# instance 1 vlan 10,20,30
Switch(config-mst)# instance 2 vlan 40,50,60
Switch(config-mst)# exit

! تعیین Root برای هر Instance
Switch(config)# spanning-tree mst 1 root primary
Switch(config)# spanning-tree mst 2 root secondary

! بررسی
Switch# show spanning-tree mst configuration
Switch# show spanning-tree mst 1
Switch# show spanning-tree mst 2
Switch# show spanning-tree mst

۳.۹ MSTP — Load Balancing

با MSTP می‌توان بین چند لینک، تعادل بار ایجاد کرد. مثال: دو سوئیچ با دو لینک متصل — Instance 1 از لینک اول، Instance 2 از لینک دوم عبور کند. 

! سناریو: SW1 و SW2 با دو لینک Gi0/23 و Gi0/24
! SW1: Root برای MSTI 1، Secondary برای MSTI 2
! SW2: Root برای MSTI 2، Secondary برای MSTI 1

! ===== SW1 =====
SW1(config)# spanning-tree mst 1 root primary
SW1(config)# spanning-tree mst 2 root secondary

! ===== SW2 =====
SW2(config)# spanning-tree mst 1 root secondary
SW2(config)# spanning-tree mst 2 root primary

! نتیجه: ترافیک MSTI 1 از یک لینک و MSTI 2 از لینک دیگر
! بررسی
SW1# show spanning-tree mst 1
SW1# show spanning-tree mst 2
🏆 نکته‌ی طلایی
در MSTP، همه‌ی سوئیچ‌های یک Region باید:
  • Name یکسان داشته باشند
  • Revision Number یکسان داشته باشند
  • VLAN-to-Instance Mapping یکسان داشته باشند
اگر یکی از اینها متفاوت باشد، سوئیچ به Region دیگری می‌رود و همگرایی MSTP به STP ساده برمی‌گردد.

۳.۱۰ EtherChannel لایه ۲ — LACP و PAgP

EtherChannel یعنی تجمیع چند لینک فیزیکی به یک لینک منطقی. در CCNP، جزئیات بیشتر و پروتکل‌های مختلف را می‌بینیم.

سه روش ایجاد EtherChannel:

  • LACP (802.3ad): استاندارد باز — حالت‌های Active و Passive
  • PAgP: اختصاصی سیسکو — حالت‌های Desirable و Auto
  • Static (On): بدون مذاکره — توصیه نمی‌شود

قوانین مهم EtherChannel:

  • همه‌ی پورت‌ها باید هم‌سرعت و هم‌Duplex باشند
  • همه در یک VLAN (Access) یا همه Trunk با همان Allowed VLANs
  • همه در یک Mode (Access یا Trunk) — نه مخلوط
  • حداکثر ۸ پورت فعال + ۸ پورت Standby در LACP
  • Load Balancing بر اساس MAC/IP/Port — با port-channel load-balance
! EtherChannel L2 با LACP
Switch(config)# interface range Gi0/23-24
Switch(config-if-range)# shutdown
Switch(config-if-range)# switchport mode trunk
Switch(config-if-range)# switchport trunk native vlan 999
Switch(config-if-range)# switchport trunk allowed vlan 10,20,30,999
Switch(config-if-range)# channel-protocol lacp
Switch(config-if-range)# channel-group 1 mode active
Switch(config-if-range)# no shutdown
Switch(config-if-range)# exit

! پیکربندی Load Balancing
Switch(config)# port-channel load-balance src-dst-ip
! گزینه‌ها: src-mac, dst-mac, src-dst-mac, src-ip, dst-ip, src-dst-ip, src-port, dst-port, src-dst-port

! بررسی
Switch# show etherchannel summary
Switch# show etherchannel 1 port-channel
Switch# show etherchannel load-balance
Switch# show interfaces port-channel 1
⚠️ هشدار
اگر یک EtherChannel به‌درستی Up نشود، احتمالاً:
  • پورت‌ها هم‌سرعت نیستند
  • Duplex متفاوت است
  • VLANهای Allowed متفاوتند
  • حالت Mode یکسان نیست (یک طرف Active، طرف دیگر Passive OK؛ دو طرف Passive نه)

۳.۱۱ EtherChannel لایه ۳ — Routed Port Channel

می‌توان EtherChannel را در لایه ۳ هم ساخت — با no switchport روی پورت‌های فیزیکی، و IP دادن به Port-Channel Interface. 

! EtherChannel L3
Switch(config)# interface range Gi0/23-24
Switch(config-if-range)# no switchport
Switch(config-if-range)# channel-group 1 mode active
Switch(config-if-range)# exit

Switch(config)# interface Port-channel 1
Switch(config-if)# no switchport
Switch(config-if)# ip address 10.1.1.1 255.255.255.252

! بررسی
Switch# show etherchannel summary
Switch# show ip interface brief
Switch# show ip route

! نکته: اینترفیس Port-channel باید no switchport باشد و IP داشته باشد
! اینترفیس‌های فیزیکی داخلش نباید IP داشته باشند

مزیت EtherChannel L3: پهنای باند بالاتر بین دو سوئیچ L3، با Load Balancing بهتر از یک لینک.

۳.۱۲ ابزارهای عیب‌یابی — SPAN، RSPAN، Storm Control

SPAN (Switched Port Analyzer): کپی کردن ترافیک یک پورت به پورت دیگر برای تحلیل با Wireshark.

! SPAN Local
Switch(config)# monitor session 1 source interface Gi0/1 both
! both = در هر دو جهت (rx و tx)
! می‌توانی rx یا tx هم بگذاری

Switch(config)# monitor session 1 destination interface Gi0/10

! بررسی
Switch# show monitor session 1
Switch# show monitor session all

! حذف
Switch(config)# no monitor session 1

RSPAN (Remote SPAN): ارسال ترافیک به یک سوئیچ دیگر در VLAN اختصاصی.

! RSPAN — روی سوئیچ مبدأ
Switch(config)# vlan 999
Switch(config-vlan)# remote-span
Switch(config-vlan)# exit

Switch(config)# monitor session 1 source interface Gi0/1 both
Switch(config)# monitor session 1 destination remote vlan 999

! روی سوئیچ مقصد
Switch(config)# monitor session 1 source remote vlan 999
Switch(config)# monitor session 1 destination interface Gi0/10

! بررسی
Switch# show monitor session all

ERSPAN (Encapsulated RSPAN): ارسال ترافیک در قالب GRE بین سوئیچ‌ها با IP — برای سناریوهای دور و روی L3.

! ERSPAN — فقط روی پلتفرم‌های خاص
Switch(config)# monitor session 1 type erspan-source
Switch(config-mon-erspan-src)# source interface Gi0/1
Switch(config-mon-erspan-src)# destination
Switch(config-mon-erspan-src-dst)# erspan-id 10
Switch(config-mon-erspan-src-dst)# ip address 10.10.10.10
Switch(config-mon-erspan-src-dst)# origin ip address 10.10.10.1

Storm Control: محدودسازی Broadcast/Unknown Unicast/Multicast برای جلوگیری از Broadcast Storm.

! Storm Control
Switch(config)# interface Gi0/1
Switch(config-if)# storm-control broadcast level 20
! 20% = اگر نرخ Broadcast به ۲۰٪ رسید، Drop کن

Switch(config-if)# storm-control multicast level 30
Switch(config-if)# storm-control unicast level 25

! (اختیاری) وقتی از حد گذشت، پورت Shutdown شود
Switch(config-if)# storm-control action shutdown
! یا trap

! بررسی
Switch# show storm-control
Switch# show storm-control broadcast
💡 نکته
Storm Control در محیط‌های Production حتماً فعال باش — یک Broadcast Storm می‌تواند کل شبکه را در چند ثانیه از کار بیندازد.

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
در Trunk، همیشه switchport nonegotiate بزن — DTP را کاملاً خاموش کن. یک مهاجم می‌تواند با DTP Frame پورت Access را Trunk کند و به همه‌ی VLANها دسترسی بگیرد.
⚠️ هشدار VTP
VTP می‌تواند خطرناک باشد. سوئیچ جدید با Revision Number بالاتر، VLAN Database کل شبکه را پاک می‌کند. از VTPv3 با Password و Mode Transparent روی Edgeها استفاده کن.
🏆 نکته‌ی طلایی
در MSTP، قبل از پیکربندی، یک نقشه‌ی کامل از Region و Instanceها بکش. یک تغییر کوچک در Name یا Revision، می‌تواند سوئیچ را به Region دیگری بفرستد.
ℹ️ اطلاعات بیشتر
در فصل ۴ CCNP وارد OSPF چندناحیه‌ای، EIGRP و BGP پیشرفته می‌شوی.
🔮 دیدگاه پیشرفته
در ENARSI، عیب‌یابی STP در محیط‌های Multi-Vendor و VXLAN EVPN را در سطح حرفه‌ای کار می‌کنی.

💻 مثال‌های عملی

مثال ۱ — پیکربندی کامل Trunk بهینه و امن

Switch(config)# interface Gi0/24
Switch(config-if)# switchport trunk encapsulation dot1q
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk native vlan 999
Switch(config-if)# switchport trunk allowed vlan 10,20,30,99,999
Switch(config-if)# switchport nonegotiate
Switch(config-if)# spanning-tree guard root
! Root Guard: اگر سوئیچ مقابل Root Bridge شود، پورت مسدود می‌شود
Switch(config-if)# exit

Switch(config)# interface range Gi0/1-23
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 10
Switch(config-if-range)# switchport nonegotiate
Switch(config-if-range)# spanning-tree portfast
Switch(config-if-range)# spanning-tree bpduguard enable
Switch(config-if-range)# storm-control broadcast level 20
Switch(config-if-range)# exit

! چک نهایی
Switch# show interfaces trunk
Switch# show spanning-tree

مثال ۲ — VTPv3 امن با Primary Server

Switch(config)# vtp domain COMPANY
Switch(config)# vtp version 3
Switch(config)# vtp mode server
Switch(config)# vtp password StrongVTP@2024 secret
Switch(config)# vtp pruning

! تعیین Primary Server (فقط VTPv3)
Switch# vtp primary vlan
! یا vtp primary mst

! بررسی
Switch# show vtp status
! ببین: VTP Operating Mode: Server
!        Configuration Revision: X
!        Primary ID: ...

! روی سوئیچ‌های Edge
Switch(config)# vtp mode transparent
! Transparent: تغییرات VLAN را Forward می‌کند ولی اعمال نمی‌کند
! امن‌تر برای Edgeها

مثال ۳ — RSTP با PortFast و BPDU Guard

! فعال‌سازی RSTP
Switch(config)# spanning-tree mode rapid-pvst

! PortFast سراسری روی پورت‌های Edge
Switch(config)# spanning-tree portfast default
Switch(config)# spanning-tree portfast bpduguard default

! یا روی هر پورت
Switch(config)# interface Gi0/1
Switch(config-if)# spanning-tree portfast
Switch(config-if)# spanning-tree bpduguard enable

! Root Bridge دستی
Switch(config)# spanning-tree vlan 10 root primary
Switch(config)# spanning-tree vlan 20 root secondary

! بررسی
Switch# show spanning-tree
Switch# show spanning-tree interface Gi0/1 detail
! ببین: Edge Port: Enabled, BPDU Guard: Enabled

مثال ۴ — MSTP Load Balancing کامل

! روی همه‌ی سوئیچ‌های Region، همان پیکربندی:
Switch(config)# spanning-tree mode mst
Switch(config)# spanning-tree mst configuration
Switch(config-mst)# name CAMPUS
Switch(config-mst)# revision 1
Switch(config-mst)# instance 1 vlan 10,20,30,40
Switch(config-mst)# instance 2 vlan 50,60,70,80
Switch(config-mst)# exit

! SW1
SW1(config)# spanning-tree mst 1 root primary
SW1(config)# spanning-tree mst 2 root secondary

! SW2
SW2(config)# spanning-tree mst 1 root secondary
SW2(config)# spanning-tree mst 2 root primary

! بررسی
SW1# show spanning-tree mst configuration
SW1# show spanning-tree mst 1
SW1# show spanning-tree mst 2
! در MSTI 1 ببین: Root Bridge خودت
! در MSTI 2 ببین: Alternate در یک لینک

مثال ۵ — RSPAN برای تحلیل ترافیک از راه دور

! ===== سوئیچ مبدأ (ترافیکی که می‌خواهیم) =====
Source_SW(config)# vlan 999
Source_SW(config-vlan)# remote-span
Source_SW(config-vlan)# exit

Source_SW(config)# monitor session 1 source interface Gi0/1 both
Source_SW(config)# monitor session 1 destination remote vlan 999

! Trunk بین دو سوئیچ باید VLAN 999 را حمل کند
Source_SW(config)# interface Gi0/24
Source_SW(config-if)# switchport trunk allowed vlan add 999

! ===== سوئیچ مقصد (تحلیل) =====
Dest_SW(config)# vlan 999
Dest_SW(config-vlan)# remote-span
Dest_SW(config-vlan)# exit

Dest_SW(config)# interface Gi0/24
Dest_SW(config-if)# switchport trunk allowed vlan add 999

Dest_SW(config)# monitor session 1 source remote vlan 999
Dest_SW(config)# monitor session 1 destination interface Gi0/10

! ===== اتصال Wireshark به Gi0/10 سوئیچ مقصد =====
! همه‌ی ترافیک Gi0/1 سوئیچ مبدأ را می‌بینی

🛠️ کارگاه عملی گام‌به‌گام

  1. در GNS3 یا EVE-NG چهار سوئیچ IOS-XE بساز (SW1، SW2، SW3، SW4)
  2. SW1 و SW2 را با دو لینک به هم وصل کن (Gi0/23 و Gi0/24)
  3. روی هر دو، RSTP را فعال کن و Root Bridge برای VLAN 10 و 20 تعیین کن
  4. EtherChannel با LACP روی دو لینک بین SW1 و SW2 بساز
  5. VTPv3 روی SW1 به‌عنوان Primary Server پیکربندی کن
  6. SW3 و SW4 را به‌عنوان VTP Client یا Transparent تنظیم کن
  7. VLAN 10, 20, 30, 99, 999 بساز و روی Trunkها مجاز کن
  8. MSTP با ۲ Instance پیکربندی کن و Load Balancing بین آنها برقرار کن
  9. SW3 و SW4 را با دو لینک به SW1/SW2 وصل کن — MSTP را بررسی کن
  10. روی همه‌ی پورت‌های Access، PortFast + BPDU Guard + Storm Control فعال کن
  11. SPAN Local از یک پورت به یک PC با Wireshark راه‌اندازی کن
  12. RSPAN بین دو سوئیچ راه‌اندازی کن و ترافیک VLAN 10 را از راه دور تحلیل کن
  13. یک Native VLAN Mismatch عمدی بساز و پیام CDP Error را ببین
  14. عیب‌یابی کامل: EtherChannel Down، MSTP Region Mismatch، Trunk Down

🚫 خطاهای رایج و رفع‌اشکال

  • EtherChannel Up نمی‌شود: سرعت، Duplex، Mode، VLAN، Allowed VLANs باید یکسان باشند.
  • Native VLAN Mismatch: در show cdp neighbors detail خودش را نشان می‌دهد.
  • VTP Revision Number بالا: سوئیچ جدید را در حالت Transparent یا با Revision صفر اضافه کن.
  • MSTP Region Mismatch: Name، Revision و Mapping باید یکسان باشند.
  • STP Loop: BPDU Guard و Root Guard باید روی پورت‌های Edge فعال باشند.
  • PortFast روی Trunk: فاجعه — PortFast فقط روی Access، همیشه BPDU Guard فعال.
  • DTP Security: switchport nonegotiate روی همه‌ی پورت‌ها.
  • SPAN ترافیک را Drop می‌کند: ممکن است پورت Destination Overload شده باشد — از RSPAN یا ERSPAN استفاده کن.
  • Storm Control بیش از حد تهاجمی: ممکن است ترافیک مشروع را Drop کند — Threshold را درست تنظیم کن.
  • RSTP کند کار می‌کند: Link Type باید Point-to-Point باشد — روی Hub یا Half-Duplex، به STP برمی‌گردد.
  • VLAN Hopping: Native VLAN اختصاصی + vlan dot1q tag native.
  • STP تغییر Root Bridge ناخواسته: Root Guard روی پورت‌های Downstream فعال کن.

🎯 پروژه‌ی پایانی فصل

یک Campus کامل با MSTP و EtherChannel طراحی کن:

  • ۴ سوئیچ: ۲ Core/Distribution و ۲ Access
  • EtherChannel L2 بین دو Core و بین Core و Access (LACP)
  • MSTP با ۳ Instance: VLAN 10-20 (MSTI 1)، VLAN 30-40 (MSTI 2)، VLAN 50-60 (MSTI 3)
  • Load Balancing: هر Instance روی یک EtherChannel متفاوت Root داشته باشد
  • VTPv3 با Primary Server روی Core1 و Transparent روی Access
  • Trunk روی EtherChannelها با Native VLAN 999
  • Native VLAN Tagging (vlan dot1q tag native) برای جلوگیری از Double Tagging
  • DTP غیرفعال روی همه‌ی پورت‌ها
  • PortFast + BPDU Guard روی همه‌ی پورت‌های Access
  • Storm Control روی پورت‌های Access با محدودیت ۲۰٪
  • SPAN + RSPAN برای تحلیل ترافیک یک VLAN خاص
  • مستندسازی کامل توپولوژی + VLAN Plan + STP Topology
🏆 چالش اضافه
  • یک Loop عمدی بساز (دو کابل بین دو Access) و ببین MSTP چطور Block می‌کند.
  • یک Native VLAN Mismatch عمدی بساز و پیام CDP را در Log ببین.
  • یک EtherChannel اشتباه پیکربندی کن (سرعت متفاوت) و ببین چطور Up نمی‌شود.
  • ارتقاء از PVST+ به MSTP را با Down Time صفر انجام بده.

📋 جمع‌بندی و برگه‌تقب

  • VLAN: Normal (1-1005) + Extended (1006-4094)
  • VTP: Server (ایجاد و Sync)، Client (Sync)، Transparent (فقط محلی)، Off
  • VTPv3: Extended VLANs، Primary Server، Authentication قوی
  • DTP: خطرناک — همیشه switchport nonegotiate
  • Native VLAN: همیشه VLAN اختصاصی (999)، vlan dot1q tag native
  • STP کلاسیک: Blocking (۲۰s) → Listening (۱۵s) → Learning (۱۵s) → Forwarding
  • RSTP: Port Roles جدید (Alternate، Backup)، States جدید (Discarding)، Proposal/Agreement
  • MSTP: Instance برای گروهی از VLANها، Load Balancing، Region با ۳ پارامتر یکسان
  • EtherChannel: LACP (Active/Passive)، PAgP (Desirable/Auto)، Static
  • EtherChannel L3: no switchport + IP روی Port-channel
  • Load Balancing: port-channel load-balance src-dst-ip
  • PortFast: فقط روی Access، همیشه با BPDU Guard
  • Root Guard: روی پورت‌های Downstream برای جلوگیری از Root ناخواسته
  • SPAN: Local — RSPAN: بین سوئیچ‌ها با VLAN اختصاصی — ERSPAN: روی L3 با GRE
  • Storm Control: محدودسازی Broadcast/Unknown Unicast/Multicast
