🔭 چشم‌انداز فصل

در این فصل وارد امنیت سطح حرفه‌ای می‌شویم. مباحث پایه‌ی CCNA (SSH، ACL، Port Security) را رد کرده‌ایم — حالا سراغ ابزارهایی می‌رویم که در شبکه‌های واقعی ISP و Enterprise استفاده می‌شوند: CoPP برای محافظت از CPU روتر، uRPF برای جلوگیری از جعل IP، IPv6 First Hop Security برای خنثی کردن حملات IPv6، و AAA پیشرفته با TACACS+ و RADIUS.

تمرکز این فصل روی سناریوهای حمله واقعی و چگونگی دفاع در برابر آنهاست. در انتها می‌توانی یک روتر مرزی ISP را کاملاً Hardening کنی.

📘 بدنه‌ی آموزشی

۶.۱ مرور سه Plane

در CCNP، امنیت را از دید سه Plane می‌بینیم. هر Plane سطح حمله و مکانیزم دفاعی متفاوتی دارد:

Plane ترافیک حمله رایج دفاع
Management SSH، SNMP، Syslog، AAA Password Attack، SNMP Guess SSH، AAA، VTY ACL
Control OSPF، BGP، EIGRP، STP، ARP، ICMP DoS، Spoofing، Protocol Attack CoPP، CPPr، uRPF
Data کاربران Flood، Malware ACL، QoS، Firewall
💡 نکته‌ی کلیدی
حملات Control Plane خطرناک‌ترین هستند — چون مستقیم روی CPU روتر تأثیر می‌گذارند و کل شبکه را از کار می‌اندازند. CoPP مخصوص دفاع در این لایه است.

۶.۲ حملات رایج به روتر و سوئیچ

حمله توضیح دفاع
Ping Flood سیل ICMP Echo — اشباع CPU CoPP، Rate Limit ICMP
SYN Flood سیل SYN TCP — اشباع Connection Table CoPP، TCP Intercept
Routing Protocol Attack جعل OSPF/BGP Hello — تزریق مسیر جعلی Authentication، TTL Security
IP Spoofing جعل IP مبدأ uRPF
ARP Spoofing جعل ARP — MITM DAI، Port Security
DHCP Starvation مصرف کل Pool آدرس با MAC جعلی DHCP Snooping، Port Security
VLAN Hopping دسترسی غیرمجاز به VLAN دیگر Native VLAN اختصاصی، DTP Off
Rogue DHCP سرور DHCP جعلی DHCP Snooping
RA Attack (IPv6) RA جعلی — تغییر Gateway کلاینت‌ها IPv6 RA Guard
DHCPv6 Spoofing سرور DHCPv6 جعلی DHCPv6 Guard

۶.۳ AAA پیشرفته — TACACS+ و RADIUS

AAA مخفف سه بخش است: Authentication (کیستی؟)، Authorization (چه کاری می‌توانی؟)، Accounting (چه کاری کردی؟).

مقایسه‌ی دقیق TACACS+ و RADIUS:

ویژگی TACACS+ RADIUS
استانداردCisco اختصاصیIETF / RFC 2865
TransportTCP/49UDP/1812 (Auth)، 1813 (Acct)
رمزنگاریکل Payloadفقط Password (با Shared Secret)
AAA جدا✅ جدا برای هر سهAuth + Authz ترکیب
کاربرد اصلیDevice AdminNetwork Access (802.1X)
MultiprotocolIP, IPX, AppleTalkفقط IP
Command Authorization✅ در سطح Command❌ محدود
 
! ===== پیکربندی کامل AAA با TACACS+ =====
Router(config)# aaa new-model

! TACACS+ Server
Router(config)# tacacs server TAC1
Router(config-server-tacacs)# address ipv4 192.168.1.100
Router(config-server-tacacs)# key StrongKey@2024
Router(config-server-tacacs)# exit

! AAA Method Lists
Router(config)# aaa authentication login default group tacacs+ local
Router(config)# aaa authentication enable default group tacacs+ enable
Router(config)# aaa authorization exec default group tacacs+ local if-authenticated
Router(config)# aaa authorization commands 15 default group tacacs+ local
Router(config)# aaa accounting exec default start-stop group tacacs+
Router(config)# aaa accounting commands 15 default start-stop group tacacs+

! Fallback User (اگر سرور از دسترس خارج شد)
Router(config)# username fallback privilege 15 secret FallbackP@ss

! Local Command Authorization (اگر Server نداری)
Router(config)# username admin privilege 15 secret AdminP@ss
Router(config)# username operator privilege 1 secret OperP@ss
Router(config)# username operator autocommand show ip interface brief
! کاربر operator فقط این دستور را می‌تواند اجرا کند

! بررسی
Router# show aaa servers
Router# show aaa method-lists
Router# test aaa group tacacs+ admin Pass123 new-code

! ===== پیکربندی AAA با RADIUS =====
Router(config)# radius server RAD1
Router(config-radius-server)# address ipv4 192.168.1.101 auth-port 1812 acct-port 1813
Router(config-radius-server)# key RadiusKey@2024
Router(config-radius-server)# exit

Router(config)# aaa authentication login default group radius local
Router(config)# aaa authorization network default group radius
🏆 نکته‌ی طلایی
برای مدیریت دستگاه‌های سیسکو، همیشه TACACS+ را ترجیح بده — چون Command Authorization در سطح دستور را پشتیبانی می‌کند (مثلاً «این کاربر نمی‌تواند write erase بزند»). RADIUS این را ندارد.

۶.۵ Control Plane Policing (CoPP)

CoPP یک ویژگی است که ترافیک رسیده به CPU روتر را Rate Limit می‌کند تا در برابر حملات DoS مقاوم شود. بدون CoPP، یک Flood ساده می‌تواند CPU را ۱۰۰٪ اشغال و روتر را از کار بیندازد.

مفهوم کلیدی: ترافیک Control Plane شامل چیست؟

  • Routing Protocols: OSPF، EIGRP، BGP، RIP
  • Management: SSH، Telnet، SNMP، NTP، Syslog
  • ICMP: Echo، TTL-Exceeded، Unreachable
  • ARP، DHCP، HSRP، VRRP
  • Other: IP Options، Fragments، TTL=0/1

سه گام CoPP:

  1. تعریف Class Map برای دسته‌بندی ترافیک
  2. تعریف Policy Map برای Rate Limiting هر کلاس
  3. اعمال روی Control Plane
! ===== گام ۱: ACL برای دسته‌بندی =====
Router(config)# ip access-list extended ICMP-TRAFFIC
Router(config-ext-nacl)# permit icmp any any echo
Router(config-ext-nacl)# permit icmp any any echo-reply
Router(config-ext-nacl)# exit

Router(config)# ip access-list extended ROUTING-TRAFFIC
Router(config-ext-nacl)# permit ospf any any
Router(config-ext-nacl)# permit eigrp any any
Router(config-ext-nacl)# permit tcp any any eq 179
Router(config-ext-nacl)# exit

Router(config)# ip access-list extended MGMT-TRAFFIC
Router(config-ext-nacl)# permit tcp any any eq 22
Router(config-ext-nacl)# permit udp any any eq 161
Router(config-ext-nacl)# permit udp any any eq 123
Router(config-ext-nacl)# exit

! ===== گام ۲: Class Maps =====
Router(config)# class-map match-any CRITICAL-ROUTING
Router(config-cmap)# match access-group name ROUTING-TRAFFIC
Router(config-cmap)# exit

Router(config)# class-map match-any MANAGEMENT
Router(config-cmap)# match access-group name MGMT-TRAFFIC
Router(config-cmap)# exit

Router(config)# class-map match-any ICMP-FLOOD
Router(config-cmap)# match access-group name ICMP-TRAFFIC
Router(config-cmap)# exit

! ===== گام ۳: Policy Map =====
Router(config)# policy-map COPP-POLICY
Router(config-pmap)# class CRITICAL-ROUTING
Router(config-pmap-c)# police 5000000 conform-action transmit exceed-action drop
Router(config-pmap-c)# exit

Router(config-pmap)# class MANAGEMENT
Router(config-pmap-c)# police 2000000 conform-action transmit exceed-action drop
Router(config-pmap-c)# exit

Router(config-pmap)# class ICMP-FLOOD
Router(config-pmap-c)# police 128000 conform-action transmit exceed-action drop
Router(config-pmap-c)# exit

Router(config-pmap)# class class-default
Router(config-pmap-c)# police 1000000 conform-action transmit exceed-action drop
Router(config-pmap-c)# exit

! ===== گام ۴: اعمال روی Control Plane =====
Router(config)# control-plane
Router(config-cp)# service-policy input COPP-POLICY
Router(config-cp)# exit

! بررسی
Router# show policy-map control-plane
Router# show policy-map control-plane input
! خروجی: تعداد بسته‌های Conform و Exceed
⚠️ هشدار مهم
CoPP یک شمشیر دو لبه است. اگر Rate را خیلی پایین بگذاری، پروتکل‌های مسیریابی (OSPF Hello) هم Drop می‌شوند و شبکه از هم می‌پاشد. همیشه اول در Lab تست کن، بعد روی Production.

۶.۶ Control Plane Protection (CPPr)

CPPr یک نسخه‌ی پیشرفته‌تر از CoPP است که اجازه می‌دهد ترافیک Control Plane را به سه Sub-Interface تقسیم کنی:

  • Host Sub-Interface: ترافیک به IPهای خود روتر (SSH، SNMP، ICMP)
  • Transit Sub-Interface: ترافیک عبوری که قرار است توسط Control Plane پردازش شود (TTL=1، IP Options)
  • CEF-Exception Sub-Interface: ترافیک استثناء CEF (Fragments، ARP، Unreachable)
! Policy Map برای CPPr
Router(config)# policy-map CPPr-POLICY
Router(config-pmap)# class HOST-CLASS
Router(config-pmap-c)# police 500000
Router(config-pmap)# class TRANSIT-CLASS
Router(config-pmap-c)# police 200000
Router(config-pmap)# class CEF-EXCEPTION
Router(config-pmap-c)# police 100000

! اعمال روی Sub-Interface
Router(config)# control-plane host
Router(config-cp-host)# service-policy input CPPr-POLICY
Router(config-cp-host)# exit

Router(config)# control-plane transit
Router(config-cp-transit)# service-policy input CPPr-POLICY
Router(config-cp-transit)# exit

Router(config)# control-plane cef-exception
Router(config-cp-cef)# service-policy input CPPr-POLICY

! بررسی
Router# show policy-map control-plane host
Router# show policy-map control-plane transit
Router# show policy-map control-plane cef-exception

۶.۷ uRPF — Unicast Reverse Path Forwarding

uRPF یک ویژگی است که جلوی IP Spoofing را می‌گیرد. وقتی بسته‌ای به Interface می‌رسد، روتر بررسی می‌کند که آیا مسیر برگشت به Source IP وجود دارد یا نه.

دو Mode اصلی:

Mode شرط مزیت عیب
Strict مسیر برگشت باید از همان Interface باشد که بسته آمده امن‌تر در شبکه‌های Asymmetric ممکن است ترافیک مشروع را Drop کند
Loose فقط مسیر برگشت در جدول باشد (از هر Interface) با Asymmetric سازگار کمتر امن 
! uRPF Strict Mode (توصیه‌شده روی لبه ISP)
Router(config)# interface Gi0/1
Router(config-if)# ip verify unicast source reachable-via rx
! rx = Strict Mode

! uRPF Loose Mode (برای محیط‌های Asymmetric)
Router(config)# interface Gi0/1
Router(config-if)# ip verify unicast source reachable-via any
! any = Loose Mode

! uRPF با ACL برای استثناءها
Router(config)# access-list 100 permit ip 10.0.0.0 0.0.0.255 any
Router(config)# interface Gi0/1
Router(config-if)# ip verify unicast source reachable-via rx 100 allow-default

! بررسی
Router# show ip interface Gi0/1
! ببین: Verify source reachable-via rx
Router# show ip traffic | include unicast
Router# show cef interface Gi0/1
Router# show ip verify source
💡 نکته‌ی کاربردی
uRPF را همیشه روی Interfaceهای لبه (به‌سمت اینترنت یا مشتری) فعال کن. روی Interfaceهای داخلی که مسیریابی Asymmetric دارند، ممکن است مشکل بسازد.

۶.۸ IPv4 ACL پیشرفته — Reflexive و Dynamic

Reflexive ACL: ACLهای رفلکتیو اجازه می‌دهند ترافیک خروجی (Outbound) به‌صورت خودکار یک ورودی موقت در ACL ورودی (Inbound) بسازد تا پاسخ‌ها را مجاز کند. مناسب سناریوهایی که Firewall اختصاصی نداریم.

! Reflexive ACL — اجازه HTTP از داخل، ولی بلاک ورودی از بیرون

! گام ۱: ACL Outbound — برای ترافیک خروجی
Router(config)# ip access-list extended OUTBOUND
Router(config-ext-nacl)# permit tcp 10.1.0.0 0.0.255.255 any eq 80 reflect HTTP-TRAFFIC
Router(config-ext-nacl)# permit tcp 10.1.0.0 0.0.255.255 any eq 443 reflect HTTPS-TRAFFIC
Router(config-ext-nacl)# exit

! گام ۲: ACL Inbound — با Reflexive Entry
Router(config)# ip access-list extended INBOUND
Router(config-ext-nacl)# evaluate HTTP-TRAFFIC
Router(config-ext-nacl)# evaluate HTTPS-TRAFFIC
Router(config-ext-nacl)# deny ip any any log
Router(config-ext-nacl)# exit

! اعمال روی Interfaceها
Router(config)# interface Gi0/1
Router(config-if)# ip access-group INBOUND in
Router(config-if)# exit

Router(config)# interface Gi0/0
Router(config-if)# ip access-group OUTBOUND out

! بررسی
Router# show ip access-lists INBOUND
! ببین: Dynamic Entry — ساخته‌شده برای هر Session

۶.۹ IPv6 Traffic Filter

ACLهای IPv6 مشابه IPv4 هستند ولی تفاوت‌های کلیدی دارند:

  • پیشوند ipv6 به‌جای ip
  • Wildcard Mask ندارد — همه‌ی آدرس‌ها با Prefix Length مشخص می‌شوند
  • Implicit Deny در انتها هم وجود دارد
  • پشتیبانی از ICMPv6 و ICMPv6 Message Types
  • Flow Label در IPv6 — برای QoS استفاده می‌شود
! ACL IPv6
Router(config)# ipv6 access-list V6-FILTER
Router(config-ipv6-acl)# permit tcp 2001:db8:1::/64 any eq 443
Router(config-ipv6-acl)# permit udp 2001:db8:1::/64 any eq 53
Router(config-ipv6-acl)# permit icmp 2001:db8:1::/64 any
Router(config-ipv6-acl)# deny ipv6 any any log
Router(config-ipv6-acl)# exit

! اعمال روی Interface
Router(config)# interface Gi0/0
Router(config-if)# ipv6 traffic-filter V6-FILTER in

! ===== IPv6 Routing Filters =====
! CoPP برای IPv6
Router(config)# ipv6 access-list V6-COPP
Router(config-ipv6-acl)# permit icmp any any router-advertisement
Router(config-ipv6-acl)# permit icmp any any router-solicitation
Router(config-ipv6-acl)# permit icmp any any neighbor-advertisement
Router(config-ipv6-acl)# permit icmp any any neighbor-solicitation
Router(config-ipv6-acl)# exit

! بررسی
Router# show ipv6 access-list
Router# show ipv6 interface Gi0/0
Router# show ipv6 traffic

۶.۱۰ IPv6 First Hop Security (FHS)

IPv6 FHS مجموعه‌ای از ویژگی‌هاست که حملات لایه ۲ در IPv6 را خنثی می‌کند. مشابه DHCP Snooping و DAI در IPv4، ولی برای IPv6.

حملات IPv6 خاص:

  • Rogue RA: ارسال Router Advertisement جعلی — تغییر Default Gateway کلاینت‌ها
  • DHCPv6 Spoofing: سرور DHCPv6 جعلی
  • ND Spoofing: جعل Neighbor Discovery — مشابه ARP Spoofing
  • RA Flood: سیل Router Advertisement — اشباع CPU
  • Prefix Hijacking: اعلان Prefix غیرمجاز

اجزای IPv6 FHS:

🛡️ RA Guard

جلوگیری از ارسال RA جعلی — پورت‌های Access به‌عنوان Host علامت‌گذاری می‌شوند.

🛡️ DHCPv6 Guard

جلوگیری از سرور DHCPv6 جعلی — پورت‌ها Trusted/Untrusted.

🛡️ ND Inspection

مشابه DAI — Neighbor Discovery را Inspect می‌کند.

🛡️ IPv6 Source Guard

بررسی منبع IPv6 بر اساس جدول Binding.

🛡️ Destination Guard

Rate Limit ترافیک ND برای مقاصد غیرفعال.

۶.۱۱ RA Guard — محافظت از Router Advertisement

۶.۱۳ IPv6 Source Guard

! IPv6 Source Guard از جدول Binding (DHCPv6 Snooping یا ND) استفاده می‌کند

Switch(config)# interface Gi0/1

۶.۱۴ DMVPN امنیتی و عیب‌یابی

نکات امنیتی DMVPN:

  • همیشه از IPsec Profile + Tunnel Protection استفاده کن
  • PSK را روی Hub به‌صورت Wildcard (0.0.0.0) بگذار
  • در Phase 3، NHRP Shortcut امن است چون IPsec بین Spokeها برقرار می‌شود
  • Routing Protocol روی DMVPN را با Authentication محافظت کن (OSPF MD5، EIGRP MD5)
! OSPF MD5 روی DMVPN
Hub(config)# interface Tunnel0
Hub(config-if)# ip ospf authentication message-digest
Hub(config-if)# ip ospf message-digest-key 1 md5 OSPF-Key@2024

! EIGRP Authentication روی DMVPN
Hub(config)# key chain EIGRP-KEYS
Hub(config-keychain)# key 1
Hub(config-keychain-key)# key-string EIGRP-Key@2024
Hub(config-keychain-key)# exit

Hub(config)# interface Tunnel0
Hub(config-if)# ip authentication mode eigrp 100 md5
Hub(config-if)# ip authentication key-chain eigrp 100 EIGRP-KEYS

! بررسی
Hub# show crypto isakmp sa
Hub# show crypto ipsec sa
Hub# show dmvpn
Hub# show ip nhrp

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
CoPP را همیشه با class class-default ببند — تا هر ترافیک غیرقابل‌طبقه‌بندی هم Rate Limit شود. بدون این، ترافیک ناشناخته می‌تواند CPU را اشباع کند.
⚠️ هشدار
uRPF در شبکه‌های Asymmetric (مثل BGP Multihomed یا DMVPN) ممکن است ترافیک مشروع را Drop کند. همیشه اول Loose Mode را تست کن، بعد به Strict مهاجرت کن.
🏆 نکته‌ی طلایی
در IPv6 FHS، یادت باشه که دستگاه‌های شبکه (Router، Switch) در IPv6 از ICMPv6 استفاده می‌کنند. اگر ICMPv6 را به‌طور کامل بلاک کنی، IPv6 از کار می‌افتد.
ℹ️ اطلاعات بیشتر
در فصل ۷ CCNP وارد SD-WAN و VXLAN در سطح حرفه‌ای می‌شوی.
🔮 دیدگاه پیشرفته
با MACsec (802.1AE) در لایه ۲ و SGT (Security Group Tag) در SD-Access آشنا می‌شوی — در CCIE Security.

🛠️ کارگاه عملی گام‌به‌گام

  1. در GNS3/EVE-NG سه روتر IOS-XE و دو سوئیچ بساز
  2. روی روتر Edge، AAA با TACACS+ و Fallback Local پیاده کن (TACACS+ Server شبیه‌سازی‌شده)
  3. SSH v2 + RSA 4096 + VTY ACL + exec-timeout پیاده کن
  4. یک RBAC View برای کاربر Monitoring بساز
  5. Time-Based ACL برای دسترسی Telnet فقط در ساعات کاری
  6. CoPP با سه کلاس (Critical، Normal، Default) پیاده کن
  7. با یک Ping Flood از یک PC خارجی، پاسخ CoPP را در show policy-map ببین
  8. uRPF Strict روی اینترفیس خارجی فعال کن
  9. یک IP Spoofing ساده (با hping3 یا اسکریپت Python) انجام بده و ببین uRPF Drop می‌کند
  10. Reflexive ACL برای اجازه HTTP از داخل
  11. روی سوئیچ Access، IPv6 Snooping + RA Guard + DHCPv6 Guard پیاده کن
  12. یک RA جعلی از یک Linux با radvd یا scapy بفرست — ببین RA Guard Drop می‌کند
  13. ND Inspection + Source Guard روی پورت‌های Access فعال کن
  14. عیب‌یابی: If CoPP باعث قطعی OSPF شد، Rate را بالا ببر

🚫 خطاهای رایج و رفع‌اشکال

  • CoPP باعث قطعی OSPF/BGP: Rate خیلی پایین است — پهنای باند پروتکل‌ها را در نظر بگیر.
  • uRPF ترافیک مشروع را Drop می‌کند: شبکه Asymmetric است — به Loose Mode سوییچ کن.
  • uRPF با DMVPN کار نمی‌کند: روی Tunnel Interface فعال نکن — فقط روی Physical.
  • Reflexive ACL پاسخ‌ها را نمی‌گیرد: ACL Inbound باید evaluate داشته باشد و ترتیب مهم است.
  • AAA Fallback کار نمی‌کند: کاربر Local باید privilege 15 داشته باشد و Fallback در Method List تعریف شده باشد.
  • TACACS+ Session قطع می‌شود: Shared Secret یکسان نیست یا پورت TCP/49 بسته است.
  • IPv6 FHS ترافیک را Drop می‌کند: پورت Uplink به Router باید Trusted باشد، وگرنه RA نیز بلاک می‌شود.
  • RA Guard روی Uplink فعال است: باید روی Port Access فعال باشد — نه روی Uplink.
  • DHCPv6 Guard سرور را بلاک می‌کند: پورت به Server باید device-role server باشد.
  • ND Inspection پیام‌های مشروع را Drop می‌کند: باید DHCPv6 Snooping Binding Table پر شده باشد.
  • Time-Based ACL همیشه Deny می‌کند: Time Range اشتباه یا Timezone اشتباه — با show time-range چک کن.
  • RBAC View دسترسی نمی‌دهد: دستورات را با commands exec include یکی‌یکی اضافه کن.

🎯 پروژه‌ی پایانی فصل

یک روتر مرزی ISP را کاملاً Hardening کن:

  • AAA: با TACACS+ و Fallback Local — سه کاربر (Admin، Operator، Monitor)
  • SSH v2: RSA 4096، VTY ACL، exec-timeout 5 دقیقه، login block-for
  • Banner: هشدار قانونی، ورژن، تماس امنیتی
  • RBAC: View برای هر نقش کاربری
  • Time-Based ACL: دسترسی مدیریت فقط در ساعات کاری
  • CoPP: سه کلاس (Critical، Normal، Default) — تست با Ping Flood
  • CPPr: جداگانه Host، Transit، CEF-Exception
  • uRPF Strict: روی Interfaceهای خارجی با Exception ACL
  • Reflexive ACL: اجازه HTTP/HTTPS Outbound، بلاک Inbound
  • IPv6 FHS: Snooping + RA Guard + DHCPv6 Guard + ND Inspection + Source Guard
  • DMVPN: با IPsec Profile + OSPF Authentication
  • مستندسازی کامل Security Policy
🏆 چالش اضافه
  • یک Ping Flood واقعی از یک PC مهاجم اجرا کن و آمار CoPP را ببین.
  • با hping3 --spoof یک IP Spoofing انجام بده و uRPF Drop را ببین.
  • با Python یک RA Flood بساز و RA Guard را تست کن.
  • SNMPv3 با Authentication SHA و Encryption AES راه‌اندازی کن.

📋 جمع‌بندی و برگه‌تقب

  • سه Plane: Management، Control (بیشترین ریسک)، Data
  • TACACS+: TCP/49، کل Payload، Command Authorization — RADIUS: UDP/1812-1813، فقط Password
  • AAA Fallback: اگر Server نبود، از Local User استفاده کن
  • CoPP: Rate Limit ترافیک CPU — Class + Policy + Service-Policy Input روی Control-Plane
  • CPPr: سه Sub-Interface: Host، Transit، CEF-Exception
  • uRPF Strict: مسیر برگشت باید از همان Interface — Loose: از هر Interface
  • uRPF در DMVPN: فقط روی Physical، نه روی Tunnel
  • Reflexive ACL: ورودی موقت بر اساس Outbound — با reflect و evaluate
  • Time-Based ACL: با time-range و ترکیب با ACL
  • IPv6 ACL: بدون Wildcard، با /prefix
  • IPv6 FHS: RA Guard + DHCPv6 Guard + ND Inspection + Source Guard
  • RA Guard: روی پورت‌های Access فعال — نه Uplink
  • DHCPv6 Guard: Uplink = Server، Access = Client
  • ND Inspection: مشابه DAI — از Binding Table استفاده می‌کند
  • RBAC: View با دستورات محدود در IOS-XE
  • DMVPN امن: IPsec Profile + Tunnel Protection + OSPF Authentication
