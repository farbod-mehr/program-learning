۲.۱ مرور IPv4 و IPv6 در Windows Server

Windows Server از IPv4 و IPv6 به‌طور موازی پشتیبانی می‌کند. آدرس‌دهی از طریق Network Adapter Settings یا PowerShell پیکربندی می‌شود. 

# ===== مشاهده تنظیمات شبکه =====
Get-NetIPConfiguration
Get-NetIPAddress
Get-NetAdapter | Format-Table Name, Status, LinkSpeed
Get-NetRoute

# ===== تنظیم IP استاتیک =====
New-NetIPAddress -InterfaceAlias "Ethernet" `
    -IPAddress 192.168.1.10 `
    -PrefixLength 24 `
    -DefaultGateway 192.168.1.1

# ===== تنظیم DNS =====
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" `
    -ServerAddresses 192.168.1.5,8.8.8.8

# ===== غیرفعال کردن IPv6 موقتاً (توصیه نمی‌شود) =====
Disable-NetAdapterBinding -Name "Ethernet" -ComponentID ms_tcpip6

# ===== فعال‌سازی مجدد =====
Enable-NetAdapterBinding -Name "Ethernet" -ComponentID ms_tcpip6

# ===== مشاهده تنظیمات کامل =====
ipconfig /all
netsh interface ip show config
💡 نکته
هرگز IPv6 را کامل غیرفعال نکن — حتی اگر از IPv4 استفاده می‌کنی. برخی سرویس‌های ویندوز (مثل DirectAccess) به IPv6 نیاز دارند. در عوض، IPv6 را با Prefix Policy اولویت‌بندی کن.

۲.۲ DNS — نقش و معماری

DNS (Domain Name System) ترجمه‌ی نام دامنه به IP است — پایه‌ی هر شبکه‌ی Active Directory.

مزایای DNS Server در ویندوز:

  • کاملاً با Active Directory یکپارچه است
  • پشتیبانی از Dynamic Update (خودکار ثبت رکوردها)
  • Zone Replication از طریق AD
  • DNSSEC برای امنیت
  • DNS Policies و Response Rate Limiting
  • PowerShell کامل
# ===== نصب DNS Server =====
Install-WindowsFeature -Name DNS -IncludeManagementTools

# ===== بررسی نصب =====
Get-WindowsFeature -Name DNS
Get-Service DNS

# ===== ابزارها =====
dnsmgmt.msc        # GUI
Get-DnsServer      # PowerShell
Resolve-DnsName    # Query DNS
nslookup           # ابزار کلاسیک

۲.۳ DNS Zones — Primary، Secondary، Stub

انواع Zone:

نوع قابل نوشتن ذخیره‌سازی کاربرد
Primary ✅ File یا AD Zone اصلی — یک دامنه
Secondary ❌ (Read-Only) File یا AD کپی از Primary — افزونگی
Stub ❌ File یا AD فقط NS Records — برای Delegation
AD-Integrated ✅ Active Directory Replication از طریق AD

Forward Zone vs Reverse Zone:

  • Forward Lookup Zone: نام → IP (مثل server01.company.local → 192.168.1.10)
  • Reverse Lookup Zone: IP → نام (مثل 192.168.1.10 → server01.company.local)
# ===== ایجاد Forward Zone =====
Add-DnsServerPrimaryZone -Name "company.local" `
    -ReplicationScope "Domain" `
    -DynamicUpdate "Secure"

# یا از فایل:
Add-DnsServerPrimaryZone -Name "company.local" `
    -ZoneFile "company.local.dns"

# ===== ایجاد Reverse Zone =====
Add-DnsServerPrimaryZone -NetworkID "192.168.1.0/24" `
    -ReplicationScope "Domain"

# ===== ایجاد Secondary Zone =====
Add-DnsServerSecondaryZone -Name "company.local" `
    -ZoneFile "company.local.dns" `
    -MasterServers 192.168.1.5

# ===== ایجاد Stub Zone =====
Add-DnsServerStubZone -Name "branch.local" `
    -MasterServers 10.0.0.5 `
    -ReplicationScope "Domain"

# ===== مشاهده Zoneها =====
Get-DnsServerZone
Get-DnsServerZone | Format-Table ZoneName, ZoneType, IsDsIntegrated, DynamicUpdate

۲.۴ Forwarders و Conditional Forwarders

اگر DNS Server شما نمی‌تواند یک نام را Resolve کند، می‌تواند درخواست را به Forwarder بفرستد (مثلاً Google DNS یا DNS ISP). 

# ===== تنظیم Forwarders =====
Add-DnsServerForwarder -IPAddress 8.8.8.8,1.1.1.1

# با Timeout و Prioritization:
Add-DnsServerForwarder -IPAddress 8.8.8.8 -Timeout 3 -EnableReordering

# ===== مشاهده Forwarders =====
Get-DnsServerForwarder

# ===== حذف Forwarder =====
Remove-DnsServerForwarder -IPAddress 8.8.8.8

# ===== Conditional Forwarder برای دامنه خاص =====
# مثلاً برای دامنه‌ی partner.local که DNS Server آن در 10.10.10.5 است
Add-DnsServerConditionalForwarderZone -Name "partner.local" `
    -MasterServers 10.10.10.5 `
    -ReplicationScope "Forest"

# یا برای Forwarder با Port غیر استاندارد (BIND)
Add-DnsServerConditionalForwarderZone -Name "another.local" `
    -MasterServers 10.20.20.5 `
    -ForwarderTimeout 5

# ===== مشاهده =====
Get-DnsServerZone | Where-Object ZoneType -eq "Forwarder"

# ===== Root Hints =====
Get-DnsServerRootHint
# این‌ها همان DNS Serverهای ریشه‌ی اینترنت هستند
# (a.root-servers.net تا m.root-servers.net)

۲.۵ DNS Record Types

Record توضیح مثال
Aنام → IPv4server01 → 192.168.1.10
AAAAنام → IPv6server01 → 2001:db8::10
CNAMEنام → نام (Alias)www → server01
MXMail Server@ → mail.company.local
NSName ServerZone → DNS Server
SOAStart of Authorityاطلاعات Zone
PTRIP → نام (Reverse)Reverse Zone
SRVService Locator_ldap._tcp.company.local
TXTمتن آزادSPF، DKIM
 
# ===== ایجاد Record A =====
Add-DnsServerResourceRecordA -Name "server01" `
    -ZoneName "company.local" `
    -IPv4Address 192.168.1.10

# ===== ایجاد CNAME =====
Add-DnsServerResourceRecordCName -Name "www" `
    -HostNameAlias "server01.company.local" `
    -ZoneName "company.local"

# ===== ایجاد PTR (در Reverse Zone) =====
Add-DnsServerResourceRecordPtr -Name "10" `
    -ZoneName "1.168.192.in-addr.arpa" `
    -PtrDomainName "server01.company.local"

# ===== ایجاد MX =====
Add-DnsServerResourceRecordMX -Name "@" `
    -ZoneName "company.local" `
    -MailExchange "mail.company.local" `
    -Preference 10

# ===== مشاهده Recordها =====
Get-DnsServerResourceRecord -ZoneName "company.local"
Get-DnsServerResourceRecord -ZoneName "company.local" -Name "server01" -RRType A

# ===== Query با PowerShell =====
Resolve-DnsName server01.company.local
Resolve-DnsName server01.company.local -Type A
Resolve-DnsName server01.company.local -Server 192.168.1.5

۲.۶ DNS Integration با Active Directory

وقتی DNS Zone را به AD یکپارچه می‌کنی (AD-Integrated Zone)، مزایای زیر را می‌گیری:

  • Multi-Master Replication: هر DC می‌تواند Zone را تغییر دهد
  • Secure Dynamic Update: فقط دستگاه‌های Authenticated رکورد می‌سازند
  • Replication از طریق AD: بدون نیاز به Zone Transfer جداگانه
  • Application Partitions: برای Zoneهای خاص
# ===== تبدیل Zone معمولی به AD-Integrated =====
Set-DnsServerPrimaryZone -Name "company.local" `
    -ReplicationScope "Domain"

# Scopeها:
# Domain    → همه DCهای همان دامنه
# Forest    → همه DCهای Forest
# Legacy    → DCهای Windows 2000
# Custom    → Application Partition خاص

# ===== تغییر Dynamic Update =====
Set-DnsServerPrimaryZone -Name "company.local" `
    -DynamicUpdate "Secure"
# گزینه‌ها: None، NonsecureAndSecure، Secure

# ===== مشاهده وضعیت =====
Get-DnsServerZone -Name "company.local" | Format-List

# ===== Aging و Scavenging =====
# برای پاک کردن رکوردهای قدیمی
Set-DnsServerZoneAging -Name "company.local" `
    -Aging $true `
    -NoRefreshInterval 7.00:00:00 `
    -RefreshInterval 7.00:00:00

Set-DnsServerScavenging -ScavengingState $true `
    -ScavengingInterval 7.00:00:00 `
    -ApplyOnAllZones

۲.۷ DHCP — نقش و اجزا

DHCP (Dynamic Host Configuration Protocol) IP، Gateway، DNS و سایر پارامترها را به‌طور خودکار به کلاینت‌ها می‌دهد.

اجزای اصلی DHCP در Windows Server:

  • Scope: محدوده‌ی IPهای قابل تخصیص
  • Exclusion: IPهایی که تخصیص داده نمی‌شوند
  • Reservation: IP ثابت بر اساس MAC
  • Lease: مدت زمان اجاره
  • Options: تنظیمات اضافی (DNS، Router، NTP، PXE)
  • Superscope: گروهی از Scopeها
  • Multicast Scope: برای Multicast Addresses
# ===== نصب DHCP =====
Install-WindowsFeature -Name DHCP -IncludeManagementTools

# ===== Authorize در Active Directory =====
# (پیش‌نیاز: DHCP Server باید در دامنه Authorize شود)
Add-DhcpServerInDC -DnsName "dhcp01.company.local" `
    -IPAddress 192.168.1.5

# ===== تنظیم Post-Install =====
# برای سرورهای جدید:
netsh dhcp add securitygroups

# ===== ایجاد Scope =====
Add-DhcpServerv4Scope -Name "LAN-Office" `
    -StartRange 192.168.1.100 `
    -EndRange 192.168.1.200 `
    -SubnetMask 255.255.255.0 `
    -State Active

# ===== Exclusions =====
Add-DhcpServerv4ExclusionRange -ScopeId 192.168.1.0 `
    -StartRange 192.168.1.150 `
    -EndRange 192.168.1.160

# ===== تنظیم Options =====
Set-DhcpServerv4OptionValue -ScopeId 192.168.1.0 `
    -Router 192.168.1.1 `
    -DnsServer 192.168.1.5,8.8.8.8 `
    -DnsDomain "company.local"

# ===== مشاهده =====
Get-DhcpServerv4Scope
Get-DhcpServerv4OptionValue -ScopeId 192.168.1.0
Get-DhcpServerv4Lease -ScopeId 192.168.1.0

۲.۸ DHCP Scope، Reservation، Relay

# ===== Reservation (IP ثابت بر اساس MAC) =====
Add-DhcpServerv4Reservation -ScopeId 192.168.1.0 `
    -IPAddress 192.168.1.50 `
    -ClientId "00-11-22-33-44-55" `
    -Description "Printer Room 201"

# ===== مشاهده Reservationها =====
Get-DhcpServerv4Reservation -ScopeId 192.168.1.0

# ===== Lease Time =====
Set-DhcpServerv4Scope -ScopeId 192.168.1.0 `
    -LeaseDuration 2.00:00:00
# LeaseDuration فرمت: DD.HH:MM:SS

# برای SOHO: 1 روز | سازمانی: 8 روز | Guest: 2-4 ساعت

# ===== DHCP Relay Agent =====
# وقتی سرور DHCP در یک Subnet دیگر است
Install-WindowsFeature -Name RemoteAccess -IncludeManagementTools
Install-WindowsFeature -Name Routing

# راه‌اندازی RRAS
Install-RemoteAccess -VpnType RoutingOnly

# در RRAS Console:
# IPv4 → General → Right Click → New Routing Protocol → DHCP Relay Agent
# بعد: Right Click on DHCP Relay Agent → New Interface
# Interface = کارت سمت کلاینت
# Right Click → Properties → DHCP Server Address را وارد کن

# یا با netsh:
netsh routing ip relay add interface "Ethernet"
netsh routing ip relay add dhcpserver "Ethernet" 192.168.1.5

# ===== Superscope =====
Add-DhcpServerv4Superscope -SuperscopeName "Multi-Site" `
    -ScopeId 192.168.1.0,192.168.2.0,192.168.3.0

۲.۹ DHCP Failover و Split Scope

برای High Availability، DHCP دو روش دارد: Failover و Split Scope.

ویژگی Failover Split Scope
نسخهWindows Server 2012+همه نسخه‌ها
همگام‌سازی✅ خودکار❌ دستی
Scope IDیکسان روی هر دوجداگانه
Load Balancing✅ Active-Active❌ فقط Failover
توصیه✅ مدرنLegacy
 
# ===== راه‌اندازی DHCP Failover =====
Add-DhcpServerv4Failover -ComputerName "dhcp01.company.local" `
    -Name "DHCP-Failover-01" `
    -PartnerServer "dhcp02.company.local" `
    -ScopeId 192.168.1.0 `
    -SharedSecret "MySecret123" `
    -Mode LoadBalance `
    -LoadBalancePercent 50

# Modeها:
# LoadBalance  → Active-Active (توصیه‌شده)
# HotStandby   → Active-Passive

# ===== Hot Standby =====
Add-DhcpServerv4Failover -ComputerName "dhcp01.company.local" `
    -Name "DHCP-HotStandby" `
    -PartnerServer "dhcp02.company.local" `
    -ScopeId 192.168.1.0 `
    -SharedSecret "MySecret456" `
    -Mode HotStandby `
    -ReservePercent 5 `
    -ServerRole Active `
    -State SwitchOverInterval=30min

# ===== Force Replication =====
Invoke-DhcpServerv4FailoverReplication -ComputerName "dhcp01.company.local"

# ===== بررسی وضعیت =====
Get-DhcpServerv4Failover
Get-DhcpServerv4Failover -ComputerName "dhcp01.company.local"

۲.۱۰ IPAM — مدیریت متمرکز IP

IPAM (IP Address Management) یک سرویس ویندوز است که DHCP، DNS و IPها را به‌صورت متمرکز مدیریت می‌کند.

IPAM چه می‌کند؟

  • کشف خودکار DHCP Serverها، DCها و DNS Serverها
  • مدیریت متمرکز Scopeهای DHCP از چند سرور
  • گزارش استفاده از IP Addressها
  • پایش DNS Zoneها
  • Audit و Tracking تغییرات
  • Role-Based Access Control (RBAC)
# ===== نصب IPAM =====
# پیش‌نیاز: Windows Internal Database (WID) یا SQL Server
Install-WindowsFeature -Name IPAM -IncludeManagementTools

# بعد از نصب، Post-Install Configuration
Invoke-IpamGpoProvisioning -Domain "company.local" `
    -GpoPrefixName "IPAM" `
    -IpamServerFqdn "ipam01.company.local" `
    -DelegatedGpoUser "Administrator"

# ===== تنظیمات اولیه =====
# در Server Manager → IPAM → Provision IPAM manually

# ===== روش PowerShell =====
Set-IpamConfiguration -ProvisioningMethod "Manual"

# ===== اجرای Discovery =====
Invoke-IpamServerDiscovery -AddressRange 192.168.0.0/16 -Type "Domain"

# یا
Invoke-IpamServerDiscovery -AddressRange 10.0.0.0/8

# ===== مشاهده سرورهای کشف‌شده =====
Get-IpamServerInventory

# ===== افزودن دستی Server =====
Add-IpamServerInventory -Name "dhcp01.company.local" `
    -ServerType "DHCP" `
    -ServerRole "DC"

# ===== مشاهده IPها =====
Get-IpamIPAddress -AddressFamily IPv4
Get-IpamSubnet
Get-IpamRange

۲.۱۱ VPN — Remote Access Service

Windows Server از چند پروتکل VPN پشتیبانی می‌کند:

پروتکل رمزنگاری وضعیت
PPTPMS-CHAPv2 (شکسته)🔴 توصیه نمی‌شود
L2TP/IPsecAES🟢 استاندارد فعلی
SSTPSSL/TLS🟢 از Firewall عبور می‌کند
IKEv2AES🟢 مدرن، مناسب Mobile
Always On VPNIKEv2/SSTP🟢 جدیدترین (جایگزین DirectAccess)
 
# ===== نصب Remote Access =====
Install-WindowsFeature -Name RemoteAccess -IncludeManagementTools

# ===== نصب NPS (RADIUS Server) =====
Install-WindowsFeature -Name NPAS -IncludeManagementTools

# ===== راه‌اندازی RRAS با PowerShell =====
Install-RemoteAccess -VpnType VpnS2S,Vpn `
    -IPv4AddressRange "192.168.100.0,192.168.100.254" `
    -IPv6Prefix "2001:db8:100::/64"

# پارامترها:
# Vpn       → Remote Access VPN
# VpnS2S    → Site-to-Site VPN
# RoutingOnly → فقط Routing

# ===== مشاهده وضعیت =====
Get-RemoteAccess
Get-VpnS2SInterface
Get-RemoteAccessConnectionStatistics

# ===== فعال‌سازی پروتکل‌ها =====
# در RRAS Console → Properties → Security
# یا با netsh:
netsh ras set vpnprotocol pptp enable
netsh ras set vpnprotocol l2tp enable
netsh ras set vpnprotocol sstp enable

# ===== Firewall برای VPN =====
# PPTP: TCP/1723 + GRE
# L2TP: UDP/500, 1701, 4500 + ESP
# SSTP: TCP/443
# IKEv2: UDP/500, 4500

New-NetFirewallRule -DisplayName "L2TP" `
    -Direction Inbound -Protocol UDP -LocalPort 500,1701,4500 -Action Allow
New-NetFirewallRule -DisplayName "SSTP" `
    -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow

۲.۱۲ DirectAccess vs VPN

ویژگی VPN DirectAccess
اتصالدستی توسط کاربرهمیشه متصل (Always On)
پروتکلPPTP، L2TP، SSTP، IKEv2IPsec + IPv6 (6to4/Teredo)
Requires Client✅❌ Built-in
مدیریتسادهپیچیده
کاربردعمومیEnterprise با Windows Enterprise
وضعیتفعالمنسوخ → Always On VPN
 
# ===== راه‌اندازی DirectAccess =====
# پیش‌نیاز:
# - Windows Server 2012+ (Enterprise یا Datacenter)
# - دو IP عمومی (یکی برای DirectAccess، یکی برای Management)
# - Certificate (CA) یا Kerberos
# - IPv6 یا Transition Technology

Install-WindowsFeature -Name DirectAccess-VPN -IncludeManagementTools

# راه‌اندازی با Wizard:
# Server Manager → Tools → Remote Access Management Console
# Configuration → DirectAccess → Run Getting Started Wizard

# ===== Always On VPN (جایگزین مدرن) =====
# مبتنی بر IKEv2 با Certificate
# نیاز به Certificate Authority + NPS + RRAS
# مزایا: پشتیبانی Windows 10/11، Domain-Joined و Non-Domain
💡 نکته
DirectAccess منسوخ شده است. مایکروسافت توصیه می‌کند به Always On VPN مهاجرت کنی که مبتنی بر IKEv2 است و با Windows 10/11 و Azure AD کار می‌کند.

۲.۱۳ NPS و RADIUS

NPS (Network Policy Server) پیاده‌سازی مایکروسافت از RADIUS است. برای:

  • Authentication و Authorization کاربران VPN
  • 802.1X برای Wi-Fi و Switch
  • Centralized Management دسترسی‌ها
  • Accounting و Logging
# ===== نصب NPS =====
Install-WindowsFeature -Name NPAS -IncludeManagementTools

# ===== ثبت NPS در Active Directory =====
netsh nps add registeredserver domain=company.local server=nps01.company.local

# ===== ایجاد RADIUS Client (مثلاً VPN Server یا Wi-Fi Controller) =====
New-NpsRadiusClient -Name "VPN-Server" `
    -Address "192.168.1.20" `
    -SharedSecret "RadiusSecret@2024" `
    -VendorName "RADIUS Standard"

# ===== Policy برای VPN Users =====
New-NpsRemediationServer
New-NpsRemediationServerGroup

# بهتر است از GUI استفاده کنی:
# NPS Console → Policies → Network Policies → New

# مثال: اجازه به Group "VPN-Users"
# Conditions:
#   - NAS Port Type = Virtual (VPN)
#   - Windows Groups = COMPANY\VPN-Users
# Settings:
#   - Authentication Methods: MS-CHAP v2، EAP
#   - Encryption: Strongest
#   - Idle Timeout: 30 minutes

# ===== مشاهده =====
Get-NpsRadiusClient
Get-NpsNetworkPolicy
Get-NpsAccountingConfiguration

۲.۱۴ DFS — Namespace و Replication

DFS (Distributed File System) دو بخش دارد:

  • DFS Namespace: یک نقطه‌ی دسترسی یکسان برای منابع مختلف
  • DFS Replication: همگام‌سازی خودکار بین سرورها
# ===== نصب =====
Install-WindowsFeature -Name FS-DFS-Namespace, FS-DFS-Replication -IncludeManagementTools

# ===== DFS Namespace =====

# ۱. ایجاد Namespace
New-DfsnRoot -Path "\\company.local\Public" `
    -Type DomainV2 `
    -TargetPath "C:\DFSRoots\Public"

# Type:
# Standalone → یک سرور، بدون AD
# DomainV1   → مبتنی بر AD، فقط NTFS
# DomainV2   → مبتنی بر AD، NTFS + Access-Based Enumeration

# ۲. ایجاد Folder (Target)
New-DfsnFolder -Path "\\company.local\Public\Sales" `
    -TargetPath "\\fileserver01\Sales"

# ۳. افزودن Target دوم (افزونگی)
New-DfsnFolderTarget -Path "\\company.local\Public\Sales" `
    -TargetPath "\\fileserver02\Sales"

# ۴. مشاهده
Get-DfsnRoot
Get-DfsnFolder -Path "\\company.local\Public\*"
Get-DfsnFolderTarget -Path "\\company.local\Public\Sales"

# ===== DFS Replication =====

# ۱. ایجاد Replication Group
New-DfsReplicationGroup -GroupName "RG-Sales"

۲.۱۶ SDN و Network Controller

در Windows Server 2016+، مایکروسافت Software Defined Networking را با Network Controller معرفی کرد که مشابه Cisco DNA Center ولی برای محیط‌های Hyper-V است.

اجزای SDN:

  • Network Controller: کنترلر مرکزی — REST API
  • Hyper-V Network Virtualization (HNV): مجازی‌سازی شبکه با VXLAN/NVGRE
  • Software Load Balancer (SLB): Load Balancer نرم‌افزاری
  • RAS Gateway: Site-to-Site و Remote Access Gateway
  • Datacenter Firewall: فایروال توزیع‌شده
# ===== نصب Network Controller =====
# روی 3 VM یا سرور فیزیکی (Cluster)
Install-WindowsFeature -Name NetworkController -IncludeManagementTools

# ===== ایجاد Network Controller Cluster =====
$nodes = @("nc01.company.local", "nc02.company.local", "nc03.company.local")

New-NetworkControllerNodeObject -Name "nc01" `
    -Server "nc01.company.local" `
    -FaultDomain "fd:/rack1/host1" `
    -RestInterface "Ethernet"

New-NetworkControllerCluster -Node $nodes `
    -ManagementSecurityMode X509 `
    -Credential (Get-Credential) `
    -ClusterAuthentication Kerberos

# ===== نمونه REST API Call =====
# GET https://nc.company.local/networking/v1/LogicalNetworks
# Header: X-NetworkController-Signed...

# - مدیریت متمرکز با REST API

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
همیشه DNS Server روی DC را به‌عنوان DNS اصلی برای همه‌ی Serverها و Clientهای دامنه تنظیم کن. در کلاینت‌های دامنه، DNS ISP را به‌عنوان Secondary نگذار — این باعث کندی در Resolve می‌شود.
⚠️ هشدار
DHCP Failover و Split Scope را با هم استفاده نکن — می‌تواند باعث IP Conflict شود. یکی را انتخاب کن.
🏆 نکته‌ی طلایی
IPAM را در سازمان‌های بزرگ پیاده کن — دیگر نیازی نیست جدول Excel برای IPها داشته باشی. کشف خودکار، گزارش و Audit همه‌چیز را مدیریت می‌کند.
ℹ️ اطلاعات بیشتر
در فصل ۳ MCSA با Active Directory، GPO، FSMO و Trust آشنا می‌شوی.
🔮 دیدگاه پیشرفته
در AZ-800 با Azure Network Adapter و Hybrid DNS (Azure + On-Prem) در سطح حرفه‌ای کار می‌کنی.

🚫 خطاهای رایج و رفع‌اشکال

  • DNS Server رکوردها را Resolve نمی‌کند: Forwarders یا Root Hints اشتباه یا Firewall UDP/53 را بسته.
  • DNS Zone Transfer نمی‌شود: Master Server آدرس اشتباه یا Allow Zone Transfer فعال نیست.
  • Secure Dynamic Update کار نمی‌کند: Kerberos مشکل دارد یا Zone AD-Integrated نیست.
  • DHCP IP نمی‌دهد: Scope Active نیست یا در DC Authorize نشده.
  • DHCP Conflict: IP استاتیک در محدوده‌ی Scope — Exclusion اضافه کن.
  • DHCP Failover قطع می‌شود: Shared Secret یکسان نیست یا پورت‌ها بسته‌اند.
  • IPAM Serverها را نمی‌بیند: Firewall (WMI، RPC)، GPO تنظیم نشده، یا Provisioning Method اشتباه.
  • VPN Client وصل نمی‌شود: Certificate منقضی، Firewall، یا NPS Policy اشتباه.
  • SSTP کار نمی‌کند: Certificate در Certificate Store درست Bind نشده.
  • NPS Authenticate نمی‌کند: RADIUS Client اشتباه یا Shared Secret ناهماهنگ.
  • DFS Replication کند است: Bandwidth Throttling یا Schedule اشتباه.
  • DFS Backlog بالا: Connection بین Memberها مشکل دارد یا فایل قفل است.
  • BranchCache کار نمی‌کند: GPO تنظیم نشده یا Server در SCP Register نشده.
  • DirectAccess Client وصل نمی‌شود: Certificate یا IPv6 Transition مشکل دارد.
  • Network Controller Cluster بالا نمی‌آید: Nodeهای FQDN یا Certificate اشتباه.

📋 جمع‌بندی و برگه‌تقب

  • DNS Zones: Primary، Secondary، Stub، AD-Integrated
  • Forward Lookup: نام → IP | Reverse Lookup: IP → نام
  • DNS Records: A، AAAA، CNAME، MX، NS، SOA، PTR، SRV، TXT
  • Forwarder: برای همه | Conditional Forwarder: برای دامنه‌ی خاص
  • AD-Integrated Zone: Multi-Master، Secure Update، Replication از AD
  • DHCP اجزا: Scope، Exclusion، Reservation، Lease، Options
  • DHCP Failover: LoadBalance یا HotStandby — با Shared Secret
  • DHCP Relay: در RRAS با DHCP Relay Agent
  • IPAM: مدیریت متمرکز DHCP + DNS + IP — با Discovery و گزارش
  • VPNها: PPTP (ناامن)، L2TP/IPsec، SSTP، IKEv2، Always On VPN
  • SSTP: TCP/443، از فایروال‌ها عبور می‌کند
  • DirectAccess منسوخ شده → Always On VPN
  • NPS: پیاده‌سازی RADIUS — برای VPN و 802.1X
  • DFS Namespace: نقطه‌ی دسترسی یکسان با چند Target
  • DFS Replication: همگام‌سازی خودکار بین سرورها
  • BranchCache: Distributed (Client) یا Hosted (Server)
  • SDN: Network Controller + HNV + SLB + RAS Gateway
  • HNV: Multi-Tenant با NVGRE یا VXLAN
