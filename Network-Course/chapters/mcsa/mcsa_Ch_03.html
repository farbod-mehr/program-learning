۳.۱ مفاهیم پایه Active Directory

Active Directory یک دیتابیس توزیع‌شده است که از LDAP برای دسترسی، Kerberos برای Authentication و DNS برای Locate کردن سرویس‌ها استفاده می‌کند.

چهار سرویس اصلی AD:

  • AD DS: Domain Services — دیتابیس هویت‌ها (مهم‌ترین)
  • AD CS: Certificate Services — PKI و Certificate
  • AD FS: Federation Services — Single Sign-On با سیستم‌های خارجی
  • AD LDS: Lightweight Directory Services — LDAP سبک برای Application
  • AD RMS: Rights Management Services — مدیریت دسترسی به اسناد

اجزای منطقی AD:

  • Object: هر چیزی که در AD ثبت می‌شود (User، Group، Computer، Printer)
  • Attribute: خصیصه‌های یک Object (مثل Name، Email، Department)
  • Schema: تعریف ساختار Objectها
  • Global Catalog: کپی Read-Only از همه‌ی Objectهای Forest

۳.۲ Forest، Tree، Domain — سلسله‌مراتب AD

مفهوم توضیح مثال
Forest مجموعه‌ای از Domainها با Schema و Configuration مشترک company.local + partner.local
Tree Domainهایی با Namespace پیوسته company.local، sales.company.local
Domain واحد مدیریتی و امنیتی — مرز Replication company.local
OU ساختار منطقی داخل Domain — برای Delegation و GPO OU=Sales، OU=IT
Site ساختار فیزیکی — بر اساس شبکه Site=Tehran، Site=Isfahan 
# ===== Domain vs Forest =====

# یک Forest می‌تواند شامل چندین Domain باشد
# همه‌ی Domainها در یک Forest، Schema و Configuration مشترک دارند
# همه‌ی Domainها به‌طور خودکار با هم Trust دوسویه دارند

# ===== Child Domain vs Tree Root =====
company.local                 # Tree Root Domain
├── sales.company.local       # Child Domain
├── tech.company.local        # Child Domain
└── asia.company.local        # Child Domain
    └── ir.asia.company.local # Grandchild

# ===== Forest Root =====
# اولین Domain در Forest = Forest Root
# نمی‌توان آن را حذف کرد (به‌راحتی)
# Enterprise Admins و Schema Admins در آن هستند

# ===== New Forest vs New Domain =====
# New Forest → Schema و Configuration جدید
# New Domain in Existing Forest → Schema مشترک

۳.۳ نصب AD DS و Promote به Domain Controller

# ===== پیش‌نیازها =====
# - Windows Server 2016+ (نسخه Standard یا Datacenter)
# - IP Static
# - DNS Server (خود DC یا سرور دیگر)
# - حداقل 20GB فضای دیسک
# - Administrative Privileges

# ===== نصب Role =====
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools

# ===== Promote به Domain Controller =====

# ۱. نصب‌کننده PowerShell (قبل از Promote)
Install-ADDSForest -DomainName "company.local" `
    -DomainNetbiosName "COMPANY" `
    -InstallDns `
    -DomainMode WinThreshold `
    -ForestMode WinThreshold `
    -DatabasePath "C:\Windows\NTDS" `
    -LogPath "C:\Windows\NTDS" `
    -SysvolPath "C:\Windows\SYSVOL" `
    -SafeModeAdministratorPassword (Read-Host -AsSecureString "DSRM Password") `
    -Force

# DomainMode و ForestMode:
# Win2008R2، Win2012، Win2012R2، WinThreshold (2016+)

# ===== نصب Child Domain =====
Install-ADDSDomain -NewDomainName "sales" `
    -ParentDomainName "company.local" `
    -DomainType ChildDomain `
    -Credential (Get-Credential COMPANY\Administrator) `
    -InstallDns `
    -SafeModeAdministratorPassword (Read-Host -AsSecureString "DSRM Password")

# ===== نصب Domain Controller اضافی (Replica) =====
Install-ADDSDomainController -DomainName "company.local" `
    -Credential (Get-Credential COMPANY\Administrator) `
    -SiteName "Tehran" `
    -InstallDns `
    -SafeModeAdministratorPassword (Read-Host -AsSecureString "DSRM Password")

# ===== بررسی بعد از نصب =====
Get-ADDomain
Get-ADForest
Get-ADDomainController -Filter * | Format-Table Name, Site, IPv4Address, OperatingSystem
Get-Service NTDS, DNS, KDC, Netlogon

# ===== ابزارهای مدیریتی =====
dsa.msc               # Active Directory Users and Computers
dssite.msc            # Active Directory Sites and Services
domain.msc            # Active Directory Domains and Trusts
schema.msc            # Active Directory Schema (نیاز به Register)
gpmc.msc              # Group Policy Management Console
adsiedit.msc          # ADSI Edit
dsacls.exe            # ACL Management
repadmin.exe          # Replication
dcdiag.exe            # Diagnostics
⚠️ نکته‌ی مهم
قبل از Promote به DC، حتماً:
  • Hostname را تنظیم کن (بعداً نمی‌توان تغییر داد بدون Demote)
  • IP Static بده
  • DNS درست تنظیم کن
  • از سیستم Snapshot یا Backup بگیر (اگر VM است)

۳.۴ Site و Subnet در AD

Site برای بهینه‌سازی Replication بین مکان‌های جغرافیایی استفاده می‌شود. اگر دو شعبه در دو شهر دارید، Site جداگانه تعریف کنید. 

# ===== ایجاد Site =====
New-ADReplicationSite -Name "Isfahan"
New-ADReplicationSite -Name "Shiraz"

# ===== ایجاد Subnet و اتصال به Site =====
New-ADReplicationSubnet -Name "192.168.1.0/24" -Site "Tehran"
New-ADReplicationSubnet -Name "192.168.10.0/24" -Site "Isfahan"
New-ADReplicationSubnet -Name "192.168.20.0/24" -Site "Shiraz"

# ===== ایجاد Site Link =====
New-ADReplicationSiteLink -Name "Tehran-Isfahan" `
    -SitesIncluded "Tehran","Isfahan" `
    -Cost 100 `
    -ReplicationFrequencyInMinutes 15

# ===== Bridgehead Server =====
# سرور خاصی که Replication بین Siteها را انجام می‌دهد
Set-ADReplicationSiteLinkBridge -Name "Default-First-Site-Name"

# ===== مشاهده =====
Get-ADReplicationSite -Filter *
Get-ADReplicationSubnet -Filter *
Get-ADReplicationSiteLink -Filter *

# ===== بررسی Site فعلی کامپیوتر =====
nltest /dsgetsite

# ===== انتقال DC به Site دیگر =====
Move-ADDirectoryServer -Identity "DC01" -Site "Isfahan"

انواع User Account:

  • Domain User: کاربر عادی
  • Domain Admin: مدیر دامنه — دسترسی کامل

  • Schema Admin: تغییر Schema — بسیار حساس
  • Service Account: برای سرویس‌ها (IIS، SQL)
  • gMSA (Group Managed Service Account): مدرن — رمز خودکار مدیریت می‌شود

# ===== ایجاد gMSA (پیشنهاد مدرن) =====

Add-KdsRootKey -EffectiveImmediately

New-ADGroup -Name "gMSA-WebServers" -GroupScope Global -Path "OU=ServiceAccounts,DC=company,DC=local"

# ۳. ایجاد gMSA
New-ADServiceAccount -Name "svc-web" `
    -DNSHostName "svc-web.company.local" `
    -PrincipalsAllowedToRetrieveManagedPassword "gMSA-WebServers" `

# ۴. نصب روی سرور
Install-ADServiceAccount -Identity "svc-web"
Test-ADServiceAccount -Identity "svc-web"

۳.۶ مدیریت Group — Security و Distribution

دو نوع Group:

  • Security Group: برای Permissions و Email
  • Distribution Group: فقط برای Email (بدون SID)

سه Scope اصلی:

Scope محدوده کاربرد
Domain Localهمان Domain (برای Permission)دسترسی به منابع
Globalکل Forest (برای Member)گروه‌بندی کاربران
Universalکل Forest (در Global Catalog)گروه‌های Cross-Domain

قاعده‌ی AGDLP (استاندارد مایکروسافت):

A → Account (کاربر)
G → Global Group (گروه کاربران)
DL → Domain Local Group (دسترسی به منابع)
P → Permission (مجوزها)

مثال:
1. Account: ali.rezaei
2. Global Group: G-Sales-Users
3. Domain Local Group: DL-Sales-Folder
4. Permission: Modify روی D:\Sales
# ===== ایجاد Group =====
New-ADGroup -Name "G-Sales-Users" `
    -GroupScope Global `
    -GroupCategory Security `
    -Path "OU=Sales,OU=Groups,DC=company,DC=local" `
    -Description "Sales Department Users"

New-ADGroup -Name "DL-Sales-Folder" `
    -GroupScope DomainLocal `
    -GroupCategory Security `
    -Path "OU=Resources,OU=Groups,DC=company,DC=local"

# ===== افزودن Member =====
Add-ADGroupMember -Identity "G-Sales-Users" -Members "ali.rezaei","maryam.h"
Add-ADGroupMember -Identity "DL-Sales-Folder" -Members "G-Sales-Users"

# ===== مشاهده Members =====
Get-ADGroupMember -Identity "G-Sales-Users"
Get-ADGroupMember -Identity "G-Sales-Users" -Recursive

# ===== مشاهده گروه‌های یک کاربر =====
Get-ADUser -Identity "ali.rezaei" -Properties MemberOf | Select -ExpandProperty MemberOf
Get-ADPrincipalGroupMembership -Identity "ali.rezaei"

# ===== حذف Member =====
Remove-ADGroupMember -Identity "G-Sales-Users" -Members "ali.rezaei" -Confirm:$false

# ===== مشاهده همه‌ی Groupها =====
Get-ADGroup -Filter * -Properties GroupScope,GroupCategory | Format-Table Name, GroupScope, GroupCategory

۳.۷ Organizational Unit (OU) و طراحی ساختار

OU یک Container داخل Domain است که برای:

  • سازماندهی Objectها
  • Delegation مدیریت
  • اعمال GPO

سه مدل طراحی OU:

  • Location-based: OU=Tehran، OU=Isfahan
  • Department-based: OU=Sales، OU=IT، OU=HR
  • Function-based: OU=Users، OU=Computers، OU=Servers

مدل ترکیبی (توصیه‌شده):

company.local
└── Company
    ├── Users
    │   ├── Sales
    │   ├── IT
    │   └── HR
    ├── Computers
    │   ├── Sales
    │   ├── IT
    │   └── HR
    ├── Servers
    ├── Groups
    │   ├── Global
    │   └── DomainLocal
    ├── ServiceAccounts
    └── Admins
# ===== ایجاد OU =====
New-ADOrganizationalUnit -Name "Company" `
    -Path "DC=company,DC=local" `
    -ProtectedFromAccidentalDeletion $true

New-ADOrganizationalUnit -Name "Users" -Path "OU=Company,DC=company,DC=local"
New-ADOrganizationalUnit -Name "Sales" -Path "OU=Users,OU=Company,DC=company,DC=local"
New-ADOrganizationalUnit -Name "IT" -Path "OU=Users,OU=Company,DC=company,DC=local"

New-ADOrganizationalUnit -Name "Computers" -Path "OU=Company,DC=company,DC=local"
New-ADOrganizationalUnit -Name "Servers" -Path "OU=Company,DC=company,DC=local"
New-ADOrganizationalUnit -Name "Groups" -Path "OU=Company,DC=company,DC=local"

# ===== مشاهده OU =====
Get-ADOrganizationalUnit -Filter * | Format-Table Name, DistinguishedName

# ===== حذف OU (فقط اگر خالی باشد) =====
Remove-ADOrganizationalUnit -Identity "OU=OldOU,DC=company,DC=local" -Confirm:$false

# ===== Delegation مدیریت =====
# اجازه به یک User برای مدیریت OU
# در dsa.msc: Right-click OU → Delegate Control
# یا با dsacls:
dsacls "OU=Sales,OU=Users,OU=Company,DC=company,DC=local" `
    /I:S /G "COMPANY\sales-admin:CC;user;all"

# ===== محافظت از OU =====
Set-ADOrganizationalUnit -Identity "OU=Sales,OU=Users,OU=Company,DC=company,DC=local" `
    -ProtectedFromAccidentalDeletion $true

۳.۸ Group Policy (GPO) — مفاهیم پایه

GPO (Group Policy Object) مجموعه‌ای از تنظیمات است که روی Users و Computers اعمال می‌شود.

GPO دو بخش دارد:

  • Computer Configuration: قبل از Login اعمال می‌شود (هر ۹۰ دقیقه)
  • User Configuration: هنگام Login اعمال می‌شود (هر ۹۰ دقیقه)

پردازش GPO در سه مرحله:

  • Computer Startup: GPOهای Computer Configuration
  • User Logon: GPOهای User Configuration
  • Background Refresh: هر ۹۰ دقیقه +- ۳۰ دقیقه (Random Offset)
# ===== ایجاد GPO =====
New-GPO -Name "Sales-Password-Policy" -Comment "Password policy for Sales"

# ===== Link GPO به OU =====
New-GPLink -Name "Sales-Password-Policy" `
    -Target "OU=Sales,OU=Users,OU=Company,DC=company,DC=local" `
    -LinkEnabled Yes

# ===== مشاهده GPOها =====
Get-GPO -All | Format-Table DisplayName, GpoStatus, CreationTime
Get-GPOReport -Name "Sales-Password-Policy" -ReportType HTML -Path "C:\gpo.html"

# ===== تغییر تنظیمات GPO =====
Set-GPRegistryValue -Name "Sales-Password-Policy" `
    -Key "HKLM\Software\Policies\Microsoft\Windows\WindowsUpdate\AU" `
    -ValueName "NoAutoUpdate" `
    -Type DWord `
    -Value 1

# ===== Backup GPO =====
Backup-GPO -Name "Sales-Password-Policy" -Path "C:\GPO-Backups"

# ===== Restore GPO =====
Restore-GPO -Name "Sales-Password-Policy" -Path "C:\GPO-Backups"

# ===== Force Update روی یک کامپیوتر =====
gpupdate /force

# ===== مشاهده نتیجه‌ی GPO =====
gpresult /r
gpresult /h C:\gpo-report.html

GPOهای Default:

  • Default Domain Policy: Password Policy، Account Lockout
  • Default Domain Controllers Policy: تنظیمات DCها
⚠️ هشدار
تنظیمات Password Policy و Account Lockout فقط در Default Domain Policy یا در یک GPO Linked به Domain معنی دارند. در OU-level GPO برای Password Policy، فقط روی Userهای همان OU اثر می‌گذارند که رفتار نامطلوبی دارد.

۳.۹ GPO Processing و LSDOU

ترتیب اعمال GPOها را با LSDOU حفظ کنید: 

L → Local (Local Security Policy)
S → Site
D → Domain
O → Organizational Unit
U → OU داخلی‌تر (Nested OU)

ترتیب اعمال: از بالا به پایین
ترتیب اولویت: از پایین به بالا (آخرین برنده است)

مثال:
1. Local Policy
2. Site GPO
3. Domain GPO
4. Parent OU GPO
5. Child OU GPO  ← برنده است (اگر Conflict باشد)

مفاهیم کلیدی:

  • Inheritance: GPOهای والد به فرزندان ارث می‌رسند
  • Block Inheritance: جلوگیری از ارث بردن
  • Enforced (No Override): GPO بالاتر، برنده است
  • WMI Filter: اعمال GPO بر اساس شرط WMI
  • Security Filtering: فقط به گروه خاص اعمال شود
  • Loopback Processing: تنظیمات User Configuration جایگزین User Settings می‌شود
# ===== Block Inheritance =====
Set-GPInheritance -Target "OU=Sales,OU=Users,OU=Company,DC=company,DC=local" `
    -IsBlocked Yes

# ===== Enforced GPO =====
Set-GPLink -Name "Default Domain Policy" `
    -Target "DC=company,DC=local" `
    -Enforced Yes

# ===== Security Filtering =====
Set-GPPermission -Name "Sales-Password-Policy" `
    -TargetName "COMPANY\G-Sales-Users" `
    -TargetType Group `
    -PermissionLevel GpoApply

# پاک کردن Authenticated Users و فقط گروه Sales
Set-GPPermission -Name "Sales-Password-Policy" `
    -TargetName "Authenticated Users" `
    -TargetType Group `
    -PermissionLevel None

# ===== WMI Filter =====
New-GPO -Name "Win11-Only-GPO"
New-WmiFilter -Name "Only-Windows-11" `
    -Query "SELECT * FROM Win32_OperatingSystem WHERE Version LIKE '10.0.2%'" `
    -Description "Windows 11 Only"
Set-GPO -Name "Win11-Only-GPO" -WmiFilter "Only-Windows-11"

# ===== Loopback Processing =====
Set-GPRegistryValue -Name "Loopback-GPO" `
    -Key "HKLM\Software\Policies\Microsoft\Windows\System" `
    -ValueName "UserPolicyMode" `
    -Type DWord -Value 2
# 1 = Merge (ترکیب)
# 2 = Replace (جایگزین)

# ===== Force GPO Update =====
Invoke-GPUpdate -Computer "PC01" -Force

۳.۱۰ GPO پیشرفته — Preferences، Starter GPO

# ===== Group Policy Preferences =====
# تنظیمات غیراجباری (کابر می‌تواند تغییر دهد)
# مثل: Mapping درایو، Shortcut، Printer، Scheduled Task
# در GPMC: Computer/User Configuration → Preferences

# ===== Drive Mapping =====

# یا با GPO Registry:

    -Key "HKCU\Network\S" `
    -ValueName "RemotePath" `
    -Type String `
    -Value "\\fileserver\Sales"

# ===== Starter GPO =====
# قالب آماده برای ساخت GPOهای جدید
New-GPO -Name "Company-Baseline" `
    -StarterGpoName "Enterprise Client"

# ===== Group Policy Modeling =====
# شبیه‌سازی نتیجه‌ی GPO قبل از اعمال
# در GPMC: Group Policy Modeling Wizard

# ===== Group Policy Results =====
# مشاهده‌ی نتیجه‌ی GPO روی یک کلاینت
gpresult /h C:\result.html
Invoke-GPResult -ComputerName "PC01" -Path "C:\report.xml"

۳.۱۱ Trust بین Domain و Forest

انواع Trust:

نوع جهت Transitive کاربرد
Parent-Childدوطرفه✅خودکار
Tree-Rootدوطرفه✅خودکار
Externalیک/دوطرفه❌بین Forest
Forestیک/دوطرفه✅بین Forestها

۳.۱۲ FSMO Roles — پنج نقش کلیدی

FSMO (Flexible Single Master Operations) پنج نقش است که فقط روی یک DC فعال هستند:

نقش محدوده کارکرد
Schema MasterForestتغییرات Schema
Domain Naming MasterForestافزودن/حذف Domain
PDC EmulatorDomainTime Sync، Password Changes، GPO
RID MasterDomainتخصیص RID Pools به DCها
Infrastructure MasterDomainReference Updates بین Domainها
 
# ===== مشاهده FSMO Roles =====
netdom query fsmo

# با PowerShell:
Get-ADForest | Select SchemaMaster, DomainNamingMaster
Get-ADDomain | Select PDCEmulator, RIDMaster, InfrastructureMaster

# ===== انتقال FSMO Role =====
Move-ADDirectoryServerOperationMasterRole -Identity "DC02" `
    -OperationMasterRole SchemaMaster, DomainNamingMaster, PDCEmulator, RIDMaster, InfrastructureMaster

# یا یکی یکی:
Move-ADDirectoryServerOperationMasterRole -Identity "DC02" -OperationMasterRole PDCEmulator

# ===== Seize (اجباری) - اگر DC اصلی از کار افتاده =====
Move-ADDirectoryServerOperationMasterRole -Identity "DC02" `
    -OperationMasterRole PDCEmulator `
    -Force

# ===== نکات مهم =====
# 1. Schema Master و Domain Naming Master روی یک DC در Forest Root
# 2. PDC Emulator مهم‌ترین نقش (Time Sync، Urgent Replication)
# 3. Infrastructure Master نباید روی Global Catalog باشد (اگر چند Domain داری)
# 4. در Forest با یک Domain، می‌توان همه را روی یک DC گذاشت
🏆 نکته‌ی طلایی
اگر DC اصلی PDC Emulator از کار بیفتد:
  • Time Sync در Domain مشکل می‌خورد
  • Password Changes ممکن است کندتر انجام شوند
  • GPO Editing ممکن است مشکل داشته باشد
  • Urgent Replication متوقف می‌شود
بلافاصله با -Force به DC دیگر منتقل کن.

۳.۱۳ RODC (Read-Only Domain Controller)

RODC یک Domain Controller فقط-خواندنی است که برای مکان‌های پرخطر (شعبه‌ها، مکان‌های فیزیکی ناامن) طراحی شده.

مزایای RODC:

  • دیتابیس فقط-خواندنی — تغییرات باید از DC قابل نوشتن بیاید
  • Password Caching محدود — فقط کاربران مجاز
  • امنیت بالا در صورت دزدیده شدن سخت‌افزار
  • کاهش Replication و پهنای باند
  • Filtered Attribute Set — بعضی Attributeها Replicate نمی‌شوند
# ===== نصب RODC =====

# ۱. در Forest، ابتدا Recycle Bin را فعال کن (اختیاری)
Enable-ADOptionalFeature -Identity "Recycle Bin Feature" `
    -Scope ForestOrConfigurationSet `
    -Target "company.local"

# ۲. در DC اصلی، یک Staged Account بساز
Add-ADDSReadOnlyDomainControllerAccount -DomainControllerAccountName "RODC01" `
    -DomainName "company.local" `
    -SiteName "Isfahan" `
    -DelegatedAdministratorAccountName "COMPANY\rodc-admin" `
    -AllowPasswordReplicationAccountName "COMPANY\Allowed RODC Password Replication Group" `
    -DenyPasswordReplicationAccountName "COMPANY\Denied RODC Password Replication Group" `
    -ReplicationSourceDC "DC01.company.local" `
    -InstallDns

# ۳. در سرور جدید (RODC):
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools

Install-ADDSDomainController -DomainName "company.local" `
    -Credential (Get-Credential) `
    -ReadOnlyReplica `
    -SiteName "Isfahan" `
    -InstallDns `
    -SafeModeAdministratorPassword (Read-Host -AsSecureString "DSRM")

# ===== Password Replication Policy =====
# کدام Userها اجازه دارند رمزشان در RODC Cache شود

# در ADUC: Domain Controller OU → RODC → Properties → Password Replication Policy

# با PowerShell:
Get-ADDomainControllerPasswordReplicationPolicy -Identity "RODC01"
Get-ADDomainControllerPasswordReplicationPolicyUsage -Identity "RODC01" `
    -AllowedAccounts

# ===== افزودن User به Allowed List =====
Add-ADDomainControllerPasswordReplicationPolicy -Identity "RODC01" `
    -AllowedList "COMPANY\G-Branch-Users"

# ===== Credential Caching =====
# فقط Userهایی که در Allowed هستند، رمزشان Cache می‌شود
# بقیه باید به DC اصلی برای Authentication وصل شوند
⚠️ نکته‌ی امنیتی
به‌طور پیش‌فرض، اعضای Domain Admins و Enterprise Admins هرگز رمزشان در RODC Cache نمی‌شود. این برای امنیت است — اگر RODC دزدیده شود، رمزهای حساس محافظت می‌شوند.

۳.۱۴ AD CS — Certificate Services

AD CS (Active Directory Certificate Services) پیاده‌سازی PKI مایکروسافت است. برای:

  • 802.1X Authentication (Wi-Fi، Switch)
  • Code Signing
  • Email Encryption (S/MIME)

انواع CA:

  • Standalone CA: مستقل — Manual Approval
  • Root CA: ریشه‌ی PKI — Offline توصیه می‌شود

        -Path "OU=Groups,OU=Company,DC=company,DC=local"
    
    # افزودن Userها به گروه Global
    $members = Get-ADUser -Filter "Department -eq '$dept'" -SearchBase "OU=Users,OU=Company,DC=company,DC=local"
    if ($members) {
        Add-ADGroupMember -Identity "G-$dept-Users" -Members $members
    }
    
    # افزودن Global به Domain Local (AGDLP)
    Add-ADGroupMember -Identity "DL-$dept-Resources" -Members "G-$dept-Users"
}

🚫 خطاهای رایج و رفع‌اشکال

  • Promote DC شکست می‌خورد: Hostname، DNS، یا رمز DSRM اشتباه. Event Log را چک کن.
  • DC همسایه Replicate نمی‌کند: DNS Resolution مشکل دارد یا Firewall بسته است.
  • User Login نمی‌شود: Locked Account، Expired Password، یا Trust Issue.
  • GPO اعمال نمی‌شود: gpresult /r را چک کن — ترتیب LSDOU یا Block Inheritance.
  • GPO با WMI Filter اعمال نمی‌شود: WMI Query اشتباه یا WMI Service غیرفعال روی Client.
  • FSMO Transfer شکست می‌خورد: DC مقصد Offline است یا دسترسی کافی نیست.
  • PDC Emulator از کار افتاد: Time Sync مشکل می‌خورد — سریعاً Seize به DC دیگر.
  • Trust برقرار نمی‌شود: DNS Condition Forwarder تنظیم نشده یا رمز Trust اشتباه.
  • RODC Authentication مشکل دارد: Password Replication Policy اشتباه یا User در Denied List.
  • AD CS Certificate صادر نمی‌کند: Template اشتباه، CRL منقضی، یا Permissions کافی نیست.
  • AD FS SSO کار نمی‌کند: Certificate منقضی یا Claim Rules اشتباه.
  • Backup Restore نمی‌شود: DSRM Password گم شده یا Backup خراب است.
  • Authoritative Restore مشکل می‌سازد: Object را کامل Restore کن — نه کل دیتابیس.
  • AD Recycle Bin غیرفعال است: باید یک بار برای همیشه فعال شود (غیرقابل بازگشت).
  • SYSVOL Replicate نمی‌شود: FRS یا DFSR را چک کن — Event ID 4614 و 4604.

📋 جمع‌بندی و برگه‌تقب

  • Forest: مجموعه‌ای از Domainها با Schema مشترک
  • Domain: واحد مدیریتی و امنیتی — مرز Replication
  • OU: ساختار منطقی داخل Domain — برای Delegation و GPO
  • Site: ساختار فیزیکی — بهینه‌سازی Replication
  • Global Catalog: کپی Read-Only از تمام Forest
  • FSMO: ۵ نقش — Schema Master، Domain Naming، PDC، RID، Infrastructure
  • GPO Processing: LSDOU — Child OU برنده
  • Block Inheritance vs Enforced: Enforced همیشه برنده
  • Loopback Processing: جایگزینی User Settings
  • AGDLP: Account → Global → Domain Local → Permission
  • Trust انواع: Parent-Child، Tree-Root، External، Forest، Realm، Shortcut
  • RODC: DC فقط-خواندنی — با Password Replication Policy
  • AD CS: PKI و Certificate — Enterprise Root CA
  • AD FS: SSO با Cloud و سایر سازمان‌ها
  • AD RMS: محافظت از اسناد Office
  • Backup: System State Backup + DSRM Password + AD Recycle Bin
  • Replication: repadmin + dcdiag — بیشترین مشکل از DNS و Time Sync
  • Time Sync: PDC Emulator از منبع خارجی، بقیه از PDC
  • gMSA: Service Account مدرن با رمز خودکار
  • AD Recycle Bin: بازیابی Objectهای حذف‌شده (یک بار فعال شود)
