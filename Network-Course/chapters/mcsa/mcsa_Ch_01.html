۱.۱ معرفی Windows Server 2025 و نسخه‌ها

Windows Server 2025 جدیدترین نسخه‌ی سرور مایکروسافت است که با تمرکز بر امنیت، Cloud Integration و Hybrid Management ارائه شده است.

نسخه‌های Windows Server 2025:

نسخه حداکثر CPU حداکثر RAM کاربرد
Essentials۲۶۴ GBSMB کوچک
Standard۶۴۴ TBسازمانی
Datacenterنامحدود۲۴ TBمراکز داده

تفاوت Standard و Datacenter: تعداد Virtual Machineهای مجاز (Standard: ۲ VM، Datacenter: نامحدود) و ویژگی‌های پیشرفته مثل Storage Spaces Direct و SDN که فقط در Datacenter موجودند.

ℹ️ توجه به MCSA
مایکروسافت مدرک MCSA را از ۳۱ ژانویه ۲۰۲۱ بازنشسته کرده است. جایگزین رسمی آن Windows Server Hybrid Administrator Associate با آزمون‌های AZ-800 و AZ-801 است. محتوای MCSA هنوز برای یادگیری مفید است و مفاهیم پایه تغییر نکرده‌اند.

۱.۳ MBR vs GPT — پارتیشن‌بندی دیسک

دو روش برای پارتیشن‌بندی دیسک وجود دارد که تفاوت‌های مهمی دارند:

ویژگی MBR GPT
حداکثر پارتیشن۴ Primary۱۲۸
حداکثر اندازه دیسک۲ TB۱۸ EB
Redundancy❌✅ (Backup Table)
CRC❌✅ (Checksum)
پشتیبانی UEFIBIOS LegacyUEFI
Secure Boot❌✅
وضعیتقدیمیمدرن

mbr2gpt /validate /disk:0
mbr2gpt /convert /disk:0

۱.۷ NTFS Permissions و Sharing

NTFS Permissions در سطح فایل و پوشه اعمال می‌شوند و Sharing Permissions در سطح Share. محدودکننده‌ترین حالت بین این دو اعمال می‌شود.

انواع NTFS Permissions:

  • Full Control: کنترل کامل + تغییر Permissions
  • Modify: خواندن، نوشتن، حذف
  • Read & Execute: خواندن + اجرا
  • Read: فقط خواندن
  • Write: فقط نوشتن
# ===== مشاهده NTFS Permissions =====
Get-Acl -Path "C:\Data" | Format-List
(Get-Acl -Path "C:\Data").Access

# ===== اعطای Permission =====
$acl = Get-Acl -Path "C:\Data"

$rule = New-Object System.Security.AccessControl.FileSystemAccessRule(
    "DOMAIN\Username",     # Identity
    "Modify",              # Rights
    "ContainerInherit,ObjectInherit",  # Inheritance
    "None",                # Propagation
    "Allow"                # Type
)

$acl.SetAccessRule($rule)
Set-Acl -Path "C:\Data" -AclObject $acl

# ===== روش ساده‌تر: icacls =====
icacls "C:\Data" /grant "DOMAIN\Username:(OI)(CI)M"

# پارامترها:
# (OI) = Object Inherit
# (CI) = Container Inherit
# M = Modify

# ===== ایجاد Share =====
New-SmbShare -Name "Data" -Path "C:\Data" -FullAccess "DOMAIN\Domain Admins"

# ===== مشاهده Shareها =====
Get-SmbShare

# ===== نکات مهم =====
# - Permission مؤثر = محدودکننده‌ترین بین NTFS و Share
# - همیشه از Groups به‌جای Users مستقیم استفاده کن
# - از Deny فقط در موارد ضروری استفاده کن
# - Principle of Least Privilege را رعایت کن

۱.۸ Storage Spaces — Pool و Virtual Disk

Storage Spaces تکنولوژی مدرن مایکروسافت برای ترکیب چند دیسک فیزیکی در یک استخر (Pool) و ساخت Virtual Disk با قابلیت افزونگی است.

مزایای Storage Spaces نسبت به RAID سنتی:

  • مدیریت آسان‌تر
  • افزودن دیسک بدون قطع سرویس
  • Thin Provisioning
  • Tiering خودکار (SSD + HDD)
  • Integration با ReFS و NTFS
  • Powershell Management کامل
# ===== ایجاد Storage Pool =====

# ۱. مشاهده دیسک‌های موجود
Get-PhysicalDisk

# ۲. ایجاد Pool از دیسک‌های خاص
$disks = Get-PhysicalDisk -CanPool $true |
    Where-Object { $_.MediaType -eq "HDD" }

New-StoragePool -FriendlyName "Pool01" `
    -StorageSubsystemFriendlyName "Windows Storage*" `
    -PhysicalDisks $disks

# ۳. ایجاد Virtual Disk
New-VirtualDisk -StoragePoolFriendlyName "Pool01" `
    -FriendlyName "VDisk01" `
    -Size 500GB `
    -ResiliencySettingName Mirror `
    -NumberOfColumns 2 `
    -Interleave 64KB

# ۴. ایجاد Volume روی Virtual Disk
$vdisk = Get-VirtualDisk -FriendlyName "VDisk01" | Get-Disk
New-Partition -DiskNumber $vdisk.Number -UseMaximumSize -DriveLetter M

# ۵. فرمت
Format-Volume -DriveLetter M -FileSystem NTFS -NewFileSystemLabel "Storage"

# ===== بررسی وضعیت =====
Get-StoragePool
Get-VirtualDisk
Get-PhysicalDisk
Get-StorageJob

# ===== Resiliency Types =====
# Simple       → بدون Redundancy
# Mirror       → مشابه RAID-1
# Parity       → مشابه RAID-5
# Dual Parity  → مشابه RAID-6

۱.۹ Data Deduplication

Data Deduplication (Deduplication) یک ویژگی است که فایل‌های تکراری روی Volume را شناسایی و فقط یک نسخه ذخیره می‌کند — با حفظ دسترسی کاربران به هر نسخه.

مزایا:

  • صرفه‌جویی ۵۰-۹۰٪ فضا
  • بهترین گزینه برای فایل‌های تکراری (مثل Backup، VDI)
  • مدیریت متمرکز

معایب / محدودیت‌ها:

  • مصرف CPU بیشتر
  • مناسب فایل‌های کم‌حجم زیاد، نه فایل‌های بزرگ اندک
  • نمی‌توان روی Volume بوت استفاده کرد
  • روی ReFS کامل نیست
# ===== نصب Feature =====
Install-WindowsFeature -Name FS-Data-Deduplication

# ===== فعال‌سازی روی Volume =====
Enable-DedupVolume -Volume "D:"

# یا با تنظیمات سفارشی
Enable-DedupVolume -Volume "D:" -UsageType HyperV
# Usage Types: Default، HyperV، Backup

# ===== پیکربندی زمان‌بندی =====
Set-DedupSchedule -Name "Optimization" `
    -Days Monday,Tuesday,Wednesday,Thursday,Friday,Saturday `
    -Start 22:00

# ===== مشاهده وضعیت =====
Get-DedupVolume
Get-DedupStatus
Get-DedupJob

# ===== اجرای دستی Optimization =====
Start-DedupJob -Volume "D:" -Type Optimization

# ===== محاسبه صرفه‌جویی =====
Get-DedupStatus | Select Volume, FreeSpace, SavedSpace, OptimizedFilesCount

# ===== غیرفعال کردن =====
Disable-DedupVolume -Volume "D:"
💡 نکته
Data Deduplication عمدتاً برای فایل‌های ثابت (Static) طراحی شده — مثل Backupهای روزانه، VHDxها، یا مخزن‌های فایل. برای فایل‌های مداوم در حال تغییر (مثل Database)، از Dedup استفاده نکن.

۱.۱۰ iSCSI Target و Initiator

iSCSI یک پروتکل است که Storage را روی شبکه IP منتقل می‌کند. Windows Server می‌تواند هم Target (ارائه‌دهنده) و هم Initiator (مصرف‌کننده) باشد. 

# ===== راه‌اندازی iSCSI Target (Server) =====
Install-WindowsFeature FS-iSCSITarget-Server

# ایجاد iSCSI Virtual Disk
New-IscsiVirtualDisk -Path "C:\iSCSI\disk1.vhdx" -Size 100GB

# ایجاد Target
New-IscsiServerTarget -TargetName "Target01" -InitiatorIds "IQN:iqn.1991-05.com.microsoft:client01"

# اتصال VDisk به Target
Add-IscsiVirtualDiskTargetMapping -TargetName "Target01" -DevicePath "C:\iSCSI\disk1.vhdx"

# ===== مشاهده =====
Get-IscsiVirtualDisk
Get-IscsiServerTarget
Get-IscsiServerTarget -TargetName "Target01" | Select -ExpandProperty Sessions

# ===== ======================================================
# ===== سمت Initiator (Client) =====
# ===== ======================================================

# ۱. شروع سرویس iSCSI
Start-Service msiscsi
Set-Service msiscsi -StartupType Automatic

# ۲. کشف Target
New-IscsiTargetPortal -TargetPortalAddress 192.168.1.10
Get-IscsiTarget

# ۳. اتصال به Target
Connect-IscsiTarget -NodeAddress "iqn.1991-05.com.microsoft:target01" `
    -TargetPortalAddress 192.168.1.10 `
    -IsPersistent $true

# ۴. مشاهده دیسک جدید
Get-Disk

# ۵. مقداردهی اولیه دیسک
Initialize-Disk -Number 1 -PartitionStyle GPT
New-Partition -DiskNumber 1 -UseMaximumSize -DriveLetter I
Format-Volume -DriveLetter I -FileSystem NTFS -NewFileSystemLabel "iSCSI-Data"

۱.۱۱ Hyper-V — نصب و پیکربندی

Hyper-V یک Hypervisor Type-1 مایکروسافت است که برای مجازی‌سازی در محیط‌های Enterprise استفاده می‌شود.

پیش‌نیازهای Hyper-V:

  • CPU با پشتیبانی Intel VT-x یا AMD-V
  • SLAT (Second Level Address Translation)
  • حداقل ۴ GB RAM
  • Windows Server 2016+ (یا Windows 10/11 Pro/Enterprise)
  • DEP (Data Execution Prevention) فعال
# ===== بررسی پیش‌نیازها =====
systeminfo
Get-ComputerInfo | Select HyperVRequirement*

# ===== نصب Hyper-V =====
Install-WindowsFeature -Name Hyper-V -IncludeManagementTools -Restart

# یا در Windows Client:
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All

# ===== بررسی نصب =====
Get-WindowsFeature -Name Hyper-V

# ===== تنظیمات اولیه =====
# مسیر پیش‌فرض VHDx
Set-VMHost -VirtualHardDiskPath "D:\Hyper-V\VHDs" `
    -VirtualMachinePath "D:\Hyper-V\VMs"

# ===== مشاهده وضعیت =====
Get-VMHost
Get-VMHost | Select ComputerName, LogicalProcessorCount, MemoryCapacity

۱.۱۲ Virtual Machine، Virtual Switch، Checkpoint

# ===== ایجاد Virtual Switch =====
# External Switch
New-VMSwitch -Name "ExternalSwitch" -NetAdapterName "Ethernet" -AllowManagementOS $true

# Internal Switch
New-VMSwitch -Name "InternalSwitch" -SwitchType Internal

# Private Switch
New-VMSwitch -Name "PrivateSwitch" -SwitchType Private

# مشاهده Switchها
Get-VMSwitch

# ===== ایجاد VM =====
New-VM -Name "WebServer01" `
    -MemoryStartupBytes 4GB `
    -Generation 2 `
    -NewVHDPath "D:\Hyper-V\VMs\WebServer01.vhdx" `
    -NewVHDSizeBytes 60GB `
    -SwitchName "ExternalSwitch"

# ===== پیکربندی VM =====
Set-VMProcessor -VMName "WebServer01" -Count 2
Set-VMMemory -VMName "WebServer01" -DynamicMemoryEnabled $true `
    -MinimumBytes 2GB -MaximumBytes 8GB
Add-VMDvdDrive -VMName "WebServer01" -Path "D:\ISOs\Win2025.iso"

# ===== Dynamic Memory =====
# Min = حداقل | Max = حداکثر | Startup = شروع
Set-VMMemory -VMName "WebServer01" `
    -DynamicMemoryEnabled $true `
    -MinimumBytes 2GB `
    -MaximumBytes 8GB `
    -StartupBytes 4GB

# ===== شروع و اتصال =====
Start-VM -Name "WebServer01"
vmconnect.exe localhost "WebServer01"

# ===== Checkpoint =====
Checkpoint-VM -Name "WebServer01" -SnapshotName "Before-Update"

# مشاهده Checkpointها
Get-VMSnapshot -VMName "WebServer01"

# بازیابی
Restore-VMSnapshot -VMName "WebServer01" -Name "Before-Update" -Confirm:$false

# حذف Checkpoint
Remove-VMSnapshot -VMName "WebServer01" -Name "Before-Update"

# ===== Production Checkpoint vs Standard =====
# Standard: تصویر از حافظه (Snapshot سریع)
# Production: تصویر سازگار با Backup (پیشنهاد)
⚠️ هشدار Checkpoint
Checkpoint فقط برای کوتاه‌مدت است — نه برای Backup. اگر Checkpoint قدیمی روی VM بماند، دیسک AVHDX بزرگ می‌شود و Performance افت می‌کند. برای Backup از Windows Server Backup یا Veeam استفاده کن.

۱.۱۳ Live Migration و Storage Migration

# ===== پیش‌نیاز =====
# - Windows Server با Hyper-V Role
# - Failover Clustering یا Shared Storage (SMB 3.0، iSCSI، Fiber Channel)
# - Live Migration روی هر دو Host فعال باشد
# - CPU Compatibility چک شود (اگر متفاوت است)

# ===== فعال‌سازی Live Migration =====
Enable-VMMigration
Set-VMHost -VirtualMachineMigrationAuthenticationType Kerberos
Set-VMHost -VirtualMachineMigrationPerformanceOption SMB

# ===== Live Migration — انتقال VM بدون قطعی =====
Move-VM -Name "WebServer01" -DestinationHost "Host02" `
    -IncludeStorage -DestinationStoragePath "D:\Hyper-V\VMs"

# فقط انتقال حافظه (بدون تغییر Storage)
Move-VM -Name "WebServer01" -DestinationHost "Host02"

# ===== Storage Migration — انتقال فقط دیسک =====

۱.۱۴ Failover Clustering — Quorum و Witness

Failover Clustering ویژگی‌ای است که چند سرور را در یک Cluster قرار می‌دهد تا در صورت خرابی یکی، بقیه سرویس را ادامه دهند.

مفاهیم اصلی:

  • Node: هر سرور در Cluster
  • Quorum: حداقل تعداد Nodeهای فعال برای Cluster سالم
  • Witness: رای‌دهنده‌ی اضافی (Disk، File Share، Cloud)
  • CSV (Cluster Shared Volume): Volume مشترک بین Nodeها
  • Cluster Role: سرویس یا Application که در Cluster اجرا می‌شود

انواع Quorum Witness:

نوع توضیح کاربرد
Node Majorityفقط رای NodeهاCluster فرد
Node and Disk MajorityNode + دیسک WitnessCluster با Shared Storage
Node and File Share MajorityNode + Share WitnessMulti-Site Cluster
Cloud WitnessAzure Storage Accountمدرن، Multi-Site
No Majorityبدون رای⚠️ خطرناک

# ===== ایجاد Cluster =====

    -Node "Server01","Server02" `
    -StaticAddress 192.168.1.100

    -AccountName "mystorageaccount" `

# File Share Witness

# Disk Witness

🎨 نکات کلیدی این فصل

💡 نکته‌ی کاربردی
در Windows Server 2025، همه‌چیز با PowerShell مدیریت می‌شود. حتی اگر Server Core استفاده نمی‌کنی، عادت کن به PowerShell — اتوماسیون، مقیاس‌پذیری و سرعت بسیار بالاتر.
⚠️ هشدار
تبدیل MBR به GPT بدون Backup، تمام داده را نابود می‌کند. همیشه اول با mbr2gpt /validate بررسی کن، بعد با /convert تبدیل کن.
🏆 نکته‌ی طلایی
در محیط‌های Production مدرن، از Storage Spaces Direct برای Hyper-Converged Infrastructure استفاده کن — دیگر نیازی به SAN گران‌قیمت نداری.
ℹ️ اطلاعات بیشتر
در فصل ۲ با DNS، DHCP، IPAM و VPN آشنا می‌شوی.
🔮 دیدگاه پیشرفته
با Windows Server Hybrid Administrator (AZ-800 + AZ-801)، مدیریت ترکیبی On-Prem + Azure را یاد می‌گیری.

🚫 خطاهای رایج و رفع‌اشکال

  • تبدیل MBR به GPT داده‌ها را پاک می‌کند: از mbr2gpt استفاده کن یا اول Backup بگیر.
  • Storage Pool داده‌ها را نمی‌بیند: دیسک‌ها ممکن است حاوی داده باشند — نیاز به Clean دارند.
  • Deduplication CPU را ۱۰۰٪ می‌کند: زمان‌بندی شبانه بگذار و Usage Type درست را انتخاب کن.
  • iSCSI Target به Client وصل نمی‌شود: IQN یا IP اشتباه، یا Firewall پورت 3260 را بسته است.
  • Hyper-V نصب نمی‌شود: پیش‌نیازهای CPU (VT-x، SLAT) در BIOS فعال نیست.
  • VM شبکه ندارد: Integration Services نصب نشده یا Virtual Switch اشتباه است.
  • Live Migration کار نمی‌کند: CPU Compatibility بین دو Host یکسان نیست یا Kerberos Constrained Delegation تنظیم نشده.
  • Cluster Quorum می‌بازد: تعداد Node فعال کمتر از Quorum است — Witness اضافه کن.
  • Cloud Witness خطا می‌دهد: Storage Account Key یا Network اتصال Azure اشتباه است.
  • CSV مشکل دارد: Antivirus روی Volume فعال است یا Diag نام کاربری اشتباه است.
  • S2D همگرا نمی‌شود: کارت شبکه ۱۰Gbps لازم است یا RDMA غیرفعال است.
  • Checkpoint روی VM می‌ماند: دیسک AVHDX بزرگ می‌شود — Checkpoint را Merge یا حذف کن.
  • Volume از Mount می‌افتد: iSCSI Session قطع است — از Multipath I/O استفاده کن.
  • Pool Performance پایین است: از Tiering (SSD + HDD) استفاده کن یا Column را تغییر بده.
  • Server Core مدیریت نمی‌شود: Remote Management را با sconfig فعال کن و از RSAT یا WAC استفاده کن.
