۴.۱ مفاهیم امنیت در لایه‌های ویندوز

امنیت ویندوز را در چند لایه می‌بینیم. مهاجم برای رسیدن به هدف باید از تمام لایه‌ها عبور کند:

  • Physical Security: دسترسی فیزیکی به سرور
  • Firmware/UEFI: Secure Boot، TPM
  • Boot: BitLocker، Measured Boot
  • OS: Credential Guard، Device Guard، LSA Protection
  • Application: AppLocker، WDAC، Defender
  • Identity: Tier Model، PAW، Protected Users
  • Data: BitLocker، EFS، AD RMS
  • Network: Firewall، IPsec، SMB Signing

مدل Zero Trust:

  • Verify Explicitly: همیشه Authenticate کن — حتی در شبکه‌ی داخلی
  • Least Privilege: حداقل دسترسی لازم
  • Assume Breach: فرض کن مهاجم داخل شبکه است
💡 نکته
امنیت یک محصول نیست — یک فرآیند است. هیچ‌وقت نمی‌گویی «شبکه‌ام امن است»، می‌گویی «شبکه‌ام در حال حاضر امن است».

۴.۲ Server Hardening — اصول و Baseline

اصول Hardening:

  • Remove Unused Services: هر سرویس غیرضروری را حذف کن
  • Least Privilege: حداقل دسترسی به سرویس‌ها و کاربران
  • Patch Management: همیشه به‌روز
  • Attack Surface Reduction: کاهش سطح حمله
  • Defense in Depth: چند لایه دفاعی
  • Monitoring: Log و Alert
# ===== Hardening با PowerShell =====

# ۱. حذف Features غیرضروری
Get-WindowsFeature | Where-Object {$_.Installed -and !$_.BestPracticesModelId} | 
    Select Name, DisplayName

# حذف SMBv1
Disable-WindowsOptionalFeature -Online -FeatureName SMB1Protocol -NoRestart

# غیرفعال کردن PowerShell v2 (کاهش سطح حمله)
Disable-WindowsOptionalFeature -Online -FeatureName MicrosoftWindowsPowerShellV2

# ۲. فعال‌سازی SMB Signing
Set-SmbClientConfiguration -RequireSecuritySignature $true -Force
Set-SmbServerConfiguration -RequireSecuritySignature $true -Force

# ۳. غیرفعال کردن SMB Guest Access
Set-SmbClientConfiguration -EnableInsecureGuestLogons $false -Force

# ۴. NTLM Hardening
# در GPO: Network Security → Restrict NTLM
# یا در Registry:
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" `
    -Name "LmCompatibilityLevel" -Value 5
# 5 = Send NTLMv2 response only, refuse LM & NTLM

# ۵. غیرفعال کردن LLMNR و NetBIOS
# LLMNR (Link-Local Multicast Name Resolution) — خطرناک
# در GPO: Turn off multicast name resolution

# NetBIOS over TCP/IP
Get-WmiObject Win32_NetworkAdapterConfiguration | ForEach-Object {
    $_.SetTcpipNetbios(2)  # 2 = Disable
}

# ۶. Windows Firewall — سه Profile
Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled True `
    -DefaultInboundAction Block `
    -DefaultOutboundAction Allow `
    -NotifyOnListen False

# ۷. Windows Defender
Set-MpPreference -DisableRealtimeMonitoring $false
Set-MpPreference -DisableIOAVProtection $false
Set-MpPreference -MAPSReporting Advanced
Set-MpPreference -SubmitSamplesConsent SendSafeSamples

Update-MpSignature

۴.۳ LAPS — Local Administrator Password Solution

LAPS مشکل «رمز یکسان Local Admin روی همه‌ی سرورها» را حل می‌کند. با LAPS:

  • هر کامپیوتر/سرور رمز Local Admin یکتا دارد
  • رمزها خودکار چرخش می‌کنند
  • رمزها در Active Directory ذخیره می‌شوند (مخفی از کاربران عادی)
  • دسترسی برای خواندن رمز، با Permissions کنترل می‌شود

چرا LAPS مهم است؟

  • اگر یک کامپیوتر Compromise شد، مهاجم نمی‌تواند با رمز Local Admin به سرورهای دیگر برود
  • Pass-the-Hash به‌شدت سخت‌تر می‌شود
  • Lateral Movement محدود می‌شود
# ===== نصب LAPS =====

# ۱. Schema Extension (یک بار برای کل Forest)
Import-Module AdmPwd.PS
Update-AdmPwdADSchema

# ۲. تنظیم Permissions روی OU
# به گروه خاصی اجازه بده رمزها را بخوانند
Set-AdmPwdReadPasswordPermission -OrgUnit "OU=Servers,OU=Company,DC=company,DC=local" `
    -AllowedPrincipals "COMPANY\LAPS-Readers"

# اجازه به سرورها برای به‌روزرسانی رمز خودشان
Set-AdmPwdComputerSelfPermission -OrgUnit "OU=Servers,OU=Company,DC=company,DC=local"

# ۳. تنظیم GPO برای LAPS
New-GPO -Name "LAPS-Settings"
Set-GPRegistryValue -Name "LAPS-Settings" `
    -Key "HKLM\Software\Policies\Microsoft Services\AdmPwd" `
    -ValueName "AdmPwdEnabled" -Type DWord -Value 1

Set-GPRegistryValue -Name "LAPS-Settings" `
    -Key "HKLM\Software\Policies\Microsoft Services\AdmPwd" `
    -ValueName "PasswordComplexity" -Type DWord -Value 4
# 4 = Large letters + small letters + numbers + specials

Set-GPRegistryValue -Name "LAPS-Settings" `
    -Key "HKLM\Software\Policies\Microsoft Services\AdmPwd" `
    -ValueName "PasswordLength" -Type DWord -Value 20

Set-GPRegistryValue -Name "LAPS-Settings" `
    -Key "HKLM\Software\Policies\Microsoft Services\AdmPwd" `
    -ValueName "PasswordAgeDays" -Type DWord -Value 30

Set-GPRegistryValue -Name "LAPS-Settings" `
    -Key "HKLM\Software\Policies\Microsoft Services\AdmPwd" `
    -ValueName "AdminAccountName" -Type String -Value "LocalAdmin"

New-GPLink -Name "LAPS-Settings" `
    -Target "OU=Servers,OU=Company,DC=company,DC=local"

# ۴. نصب Client روی سرورها
# از فایل MSI: LAPS.x64.msi
# نصب در حالت GPO-managed
msiexec /i LAPS.x64.msi /quiet ADDLOCAL=Management,CDrive

# ۵. خواندن رمز
Get-AdmPwdPassword -ComputerName "SERVER01" | Select ComputerName, Password, ExpirationTimestamp

# یا با Find-AdmPwdExtendedRights برای مدیریت

# ===== Windows LAPS (نسخه جدید — Windows Server 2022+) =====
# Built-in در ویندوز، دیگر نیاز به MSI نیست
Update-LapsADSchema
Set-LapsADReadPasswordPermission -Identity "OU=Servers,DC=company,DC=local" `
    -AllowedPrincipals "COMPANY\LAPS-Readers"
Set-LapsADComputerSelfPermission -Identity "OU=Servers,DC=company,DC=local"

# در GPO:
# Computer Configuration → Administrative Templates → System → LAPS
# Configure password backup directory: Active Directory
🏆 نکته‌ی طلایی
در ویندوزهای جدید (Windows 11 + Server 2022/2025)، از Windows LAPS استفاده کن که Built-in است. LAPS قدیمی دیگر نیاز به نصب جداگانه ندارد.

۴.۴ JIT و JEA — Just Enough Administration

JEA یک تکنولوژی PowerShell است که اجازه می‌دهد کاربران فقط دستورات مشخصی را اجرا کنند — بدون دسترسی Admin کامل.

تفاوت JIT و JEA:

ویژگی JIT JEA
رویکرددسترسی موقتدسترسی محدود
مدتچند ساعت (Time-Bound)دائمی ولی محدود
پیاده‌سازیPAM (Privileged Access Management)PowerShell Endpoint
مثالAdmin برای ۴ ساعتفقط Get-Service و Restart-Service
 
# ===== ایجاد JEA Endpoint =====

# ۱. ایجاد Role Capability
New-PSRoleCapabilityFile -Path "C:\JEA\WebAdminRole.psrc"

# ویرایش فایل برای تعریف دستورات مجاز:
# VisibleCmdlets = @(
#     'Get-Service',
#     'Restart-Service',
#     'Get-EventLog',
#     'Get-Process'
# )
# VisibleFunctions = @()
# VisibleProviders = @('FileSystem')

# ۲. ایجاد Session Configuration
New-PSSessionConfigurationFile -Path "C:\JEA\WebAdmin.pssc" `
    -SessionType RestrictedRemoteServer `
    -RunAsVirtualAccount `
    -RoleDefinitions @{
        'COMPANY\Web-Admins' = @{ RoleCapabilities = 'WebAdminRole' }
    }

# ۳. ثبت Session Configuration
Register-PSSessionConfiguration -Path "C:\JEA\WebAdmin.pssc" `
    -Name "WebAdminEndpoint" -Force

# ۴. تست
Enter-PSSession -ComputerName SERVER01 -ConfigurationName WebAdminEndpoint `
    -Credential (Get-Credential)

# بررسی دستورات مجاز
Get-Command

# فقط دستورات تعریف‌شده اجرا می‌شوند
# Get-Service OK، Remove-Item خطا

# ===== نکات امنیتی =====
# - RunAsVirtualAccount: اجرا با حساب مجازی موقت
# - Transcript Directory: ثبت همه‌ی فعالیت‌ها
# - Language Mode: NoLanguage برای محدودیت بیشتر
⚠️ نکته‌ی مهم
JEA در ویندوزهای جدید، نیازمند Language Mode = NoLanguage است برای امنیت بیشتر. این باعث می‌شود کاربر نتواند از Script Blocks یا متغیرهای پیشرفته استفاده کند.

۴.۵ PAW — Privileged Access Workstation

PAW یک کامپیوتر مجزا است که فقط برای کارهای Admin استفاده می‌شود. روی PAW:

  • هیچ Email یا Internet browsing وجود ندارد
  • فقط Admin Tools نصب است
  • دسترسی به اینترنت محدود
  • BitLocker، Credential Guard، Device Guard
  • AppLocker برای فقط برنامه‌های مجاز

چرا PAW مهم است؟

  • اگر Admin با کامپیوتر شخصی کار کند، ممکن است با Malware آلوده شود
  • PAW محیط ایزوله‌ای برای کارهای حساس است
  • کاهش قابل توجه سطح حمله
# ===== راه‌اندازی PAW =====

# ۱. سخت‌افزار: کامپیوتر مجزا یا VM
# ۲. ویندوز Enterprise

# ۳. BitLocker اجباری
Enable-BitLocker -MountPoint "C:" -EncryptionMethod XtsAes256 `
    -UsedSpaceOnly -TpmProtector

# ۴. Credential Guard
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard" `
    -Name "EnableVirtualizationBasedSecurity" -Value 1

Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard" `
    -Name "RequirePlatformSecurityFeatures" -Value 1

Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" `
    -Name "LsaCfgFlags" -Value 1

# ۵. AppLocker — فقط برنامه‌های مجاز
# در GPO: Computer Configuration → Windows Settings → Security Settings → AppLocker

# ۶. Internet Restrictions
# غیرفعال کردن Browser
Set-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\CurrentVersion\Internet Settings" `
    -Name "ProxyServer" -Value "0.0.0.0:1"

۴.۶ Tier Model و ESAE Forest

Tier Model دسترسی‌ها را به سه لایه تقسیم می‌کند:

Tier منابع Admin Accounts
Tier 0 DC، AD، PKI، Backup Tier 0 Admins (فقط روی PAW)
Tier 1 Serverها و Applicationها Tier 1 Admins
Tier 2 Clientها Helpdesk

قانون طلایی: Admin یک Tier بالاتر نمی‌تواند از کامپیوتر Tier پایین‌تر لاگین کند.

ESAE Forest (Enhanced Security Administrative Environment):

  • یک Forest جداگانه برای Admin Accounts
  • One-Way Trust از Production به ESAE
  • Adminها فقط در ESAE Forest وجود دارند
  • Production Forest قابل Compromise است ولی ESAE نه
# ===== پیاده‌سازی Tier Model =====

# ۱. ساختار OU در AD
# OU=Tier0,DC=company,DC=local
# OU=Tier1,DC=company,DC=local
# OU=Tier2,DC=company,DC=local

# ۲. Admin Accounts جدا برای هر Tier
New-ADUser -Name "t0-admin" `
    -SamAccountName "t0-admin" `
    -Path "OU=Admins,OU=Tier0,DC=company,DC=local" `
    -AccountPassword (Read-Host -AsSecureString "Pass") `
    -Enabled $true

# ۳. Deny Logon برای Adminها روی کامپیوترهای Tier پایین
# در GPO: Computer Configuration → Windows Settings → Security Settings
# → Local Policies → User Rights Assignment → Deny log on locally
# Users: COMPANY\Tier0-Admins

# ۴. Protected Users Group
Add-ADGroupMember -Identity "Protected Users" -Members "t0-admin"

# ===== Protected Users Group =====
# اعضای این گروه:
# - NTLM استفاده نمی‌کنند
# - Kerberos با AES اجباری
# - Credential Delegation ممنوع
# - TGT Lifetime کوتاه (4 ساعت)
# - CredSSP ممنوع
# نکته: کاربران با Protected Users نباید برای سرویس‌ها استفاده شوند

۴.۷ Protected Users Group

# ===== افزودن کاربر به Protected Users =====
Add-ADGroupMember -Identity "Protected Users" -Members "DomainAdmin1","DomainAdmin2"

Get-ADGroupMember "Protected Users"

۴.۸ Credential Guard و Device Guard

Credential Guard از Credentialها (مثل NTLM Hash و Kerberos TGT) با Virtualization-Based Security (VBS) محافظت می‌کند. جلوی:

  • Pass-the-Hash
  • Pass-the-Ticket
  • Credential Dumping (Mimikatz)

Device Guard:

  • Configurable Code Integrity (CI): فقط کد امضاشده اجرا شود
  • Virtualization-Based Protection of Code Integrity: با VBS
# ===== پیش‌نیاز Credential Guard =====
# - Windows 10 Enterprise / Windows Server 2016+
# - UEFI + Secure Boot
# - TPM 2.0
# - CPU Virtualization Extensions (VT-x، AMD-V)
# - 64-bit

# ===== فعال‌سازی Credential Guard =====
# در GPO: Computer Configuration → Administrative Templates → System → Device Guard
# Turn On Virtualization Based Security: Enabled
# Select Platform Security Level: Secure Boot and DMA Protection
# Credential Guard Configuration: Enabled with UEFI lock

# با PowerShell (روی خود سیستم):
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard" `
    -Name "EnableVirtualizationBasedSecurity" -Value 1 -Force

Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard" `
    -Name "RequirePlatformSecurityFeatures" -Value 1 -Force

Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" `
    -Name "LsaCfgFlags" -Value 1 -Force

# ===== بررسی =====
Get-CimInstance -ClassName Win32_DeviceGuard -Namespace root\Microsoft\Windows\DeviceGuard

# ===== فعال‌سازی Device Guard =====
# در GPO: Computer Configuration → Administrative Templates → System → Device Guard
# - Deploy Code Integrity Policy: Enabled
# - Policy File: مسیر XML

# ساخت Policy:
New-CIPolicy -Level Publisher -FilePath "C:\Policies\BasePolicy.xml"
ConvertFrom-CIPolicy -XmlFilePath "C:\Policies\BasePolicy.xml" `
    -BinaryFilePath "C:\Policies\BasePolicy.p7b"

# Deploy به %SystemRoot%\System32\CodeIntegrity\CiPolicies\Active\

۴.۹ Shielded VM و Guarded Fabric

Shielded VM یک VM است که حتی Adminهای Hypervisor هم نمی‌توانند به محتوای آن دسترسی داشته باشند.

مشکلات VM معمولی:

  • Admin Hypervisor می‌تواند VHDX را کپی و روی سیستم دیگر اجرا کند
  • می‌تواند Screenshot از Console بگیرد
  • می‌تواند در Memory VM تغییر ایجاد کند

راه‌حل: Guarded Fabric = Shielded VM + Host Guardian Service

# ===== اجزای Shielded VM =====

# 1. HGS (Host Guardian Service)
#    - سرور جداگانه که Hypervisor Hostها را Authorize می‌کند
#    - از Attestation برای تأیید Hostها استفاده می‌کند

# 2. Shielded VM
#    - VHDX با BitLocker رمزنگاری شده
#    - فقط Hostهای تأییدشده می‌توانند اجرا کنند

# 3. Guarded Host
#    - Hypervisor Host که توسط HGS تأیید شده

# ===== نصب HGS =====
Install-WindowsFeature -Name HostGuardianServiceRole -IncludeManagementTools

# راه‌اندازی HGS
Initialize-HgsServer -HgsServiceName "hgs.company.local" `
    -SigningCertificate "hgs-signing-cert" `
    -EncryptionCertificate "hgs-encryption-cert"

# TPM Mode (قوی‌تر)
Initialize-HgsServer -HgsServiceName "hgs.company.local" `
    -UseHostKeyCertificate "host-key-cert" `
    -SigningCertificate "hgs-signing-cert" `
    -EncryptionCertificate "hgs-encryption-cert"

# ===== ساخت Shielded VM Template =====
# ۱. Template Disk با BitLocker
# ۲. Shielded VM Template با Windows PowerShell

New-ShieldingDataFile -ShieldingDataFilePath "C:\Shielded\Template.pdk" `
    -Owner "COMPANY\Administrator" `
    -KeyProtector "BitLockerKeyProtector" `
    -SigningCertificate "hgs-signing-cert"

New-ShieldedVMTemplate -Name "ShieldedTemplate" `
    -TemplateFilePath "C:\Shielded\Template.vhdx" `
    -ShieldingDataFilePath "C:\Shielded\Template.pdk"

# ===== ایجاد Shielded VM =====
New-VM -Name "SHIELDED-VM01" `
    -Generation 2 `
    -MemoryStartupBytes 4GB `
    -Shielded `
    -TemplateFilePath "C:\Shielded\ShieldedTemplate.vhdx" `
    -ShieldingDataFilePath "C:\Shielded\ShieldedData.pdk"

# ===== بررسی =====
Get-VM | Select Name, State, IsShielded, HgsAttestationStatus
Get-HgsServer
Get-HgsAttestationHostGroup
🏆 نکته‌ی طلایی
Shielded VM + Guarded Fabric برای محیط‌هایی است که می‌خواهی از VMها در برابر دسترسی‌های Hypervisor Admin محافظت کنی — مثل ارائه‌دهندگان Cloud یا سازمان‌هایی با محیط Multi-Tenant.

۴.۱۰ Host Guardian Service (HGS)

# ===== دو حالت Attestation =====

# ۱. TPM Mode
# - امن‌تر — نیاز به TPM 2.0 در هر Host
# - Host Certificate از خود TPM
# - پیشنهاد برای Production

# ۲. Admin-Trusted Attestation
# - ساده‌تر، بدون TPM
# - فقط با Kerberos
# - کمتر امن — توصیه نمی‌شود

# ===== نصب HGS Cluster (برای HA) =====
Install-WindowsFeature -Name HostGuardianServiceRole -IncludeManagementTools

# روی هر ۳ سرور HGS:
# ۱. Join Domain
# ۲. نصب Role

# راه‌اندازی Cluster
Initialize-HgsServer -HgsServiceName "hgs.company.local" `
    -SigningCertificate "hgs-signing-cert" `
    -EncryptionCertificate "hgs-encryption-cert"

# ===== Guarded Host Configuration =====
# روی هر Hyper-V Host:

# ۱. فعال‌سازی Isolated User Mode
Enable-WindowsOptionalFeature -Online -FeatureName IsolatedUserMode -NoRestart

# ۲. فعال‌سازی Hyper-V
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All

# ۳. تنظیم HGS Client
Set-HgsClientConfiguration -AttestationServerUrl "https://hgs.company.local/Attestation" `
    -KeyProtectionServerUrl "https://hgs.company.local/KeyProtection"

مثال ۵ — Incident Response با PowerShell

# ===== سناریو: تشخیص Brute Force =====

# ۱. جمع‌آوری Failed Logons
$failedLogons = Get-WinEvent -FilterHashtable @{
    LogName='Security'; Id=4625; StartTime=(Get-Date).AddHours(-1)
} -ErrorAction SilentlyContinue

# ۲. گروه‌بندی بر اساس IP
$suspiciousIPs = $failedLogons | 
    ForEach-Object {
        [PSCustomObject]@{
            Time = $_.TimeCreated
            TargetUser = $_.Properties[5].Value
            SourceIP = $_.Properties[19].Value
            Workstation = $_.Properties[13].Value
        }
    } |
    Group-Object SourceIP |
    Where-Object {$_.Count -gt 10} |
    Sort-Object Count -Descending

# ۳. نمایش
$suspiciousIPs | Format-Table Name, Count

# ۴. Block کردن IP در Firewall
foreach ($ip in $suspiciousIPs) {
    New-NetFirewallRule -DisplayName "Block Brute Force - $($ip.Name)" `
        -Direction Inbound `
        -RemoteAddress $ip.Name `
        -Action Block
    Write-Host "Blocked: $($ip.Name)" -ForegroundColor Red
}

# ۵. بررسی Successful Login بعد از Failed
$successAfterFail = $failedLogons | ForEach-Object {
    $user = $_.Properties[5].Value
    $ip = $_.Properties[19].Value
    $time = $_.TimeCreated
    
    Get-WinEvent -FilterHashtable @{
        LogName='Security'; Id=4624; StartTime=$time
    } | Where-Object {
        $_.Properties[5].Value -eq $user -and
        $_.Properties[18].Value -eq $ip
    }
}

if ($successAfterFail) {
    Write-Warning "Possible Successful Breach!"
    $successAfterFail | Format-List TimeCreated, Message
}

# ۶. گزارش
$report = @{
    ReportTime = Get-Date
    FailedCount = $failedLogons.Count
    SuspiciousIPs = $suspiciousIPs.Count
    TopAttackers = $suspiciousIPs | Select -First 5
}
$report | ConvertTo-Json -Depth 3 | Out-File "C:\Incident\Report-$(Get-Date -Format 'yyyyMMdd-HHmm').json"

# ۷. اعلان
Send-MailMessage -To "security@company.ir" `
    -From "alerts@company.ir" `
    -Subject "Possible Brute Force Attack" `
    -Body "Detected $($suspiciousIPs.Count) suspicious IPs" `
    -SmtpServer "smtp.company.ir"

🚫 خطاهای رایج و رفع‌اشکال

  • LAPS Schema Extension خطا: باید با Schema Admin اجرا شود و در Forest Root.
  • LAPS رمز نمی‌چرخاند: GPO لینک نشده یا Client نصب نشده. Get-LapsADPassword را چک کن.
  • Windows LAPS رمز را نمی‌بیند: Permission روی OU تنظیم نشده یا Encryption Certificate مشکل دارد.
  • JEA User نمی‌تواند Login کند: Role Definition یا Group Membership اشتباه.
  • JEA دستور غیرمجاز اجرا می‌کند: LanguageMode باید NoLanguage باشد.
  • Protected Users مشکل ایجاد کرد: ممکن است سرویس‌ها از NTLM استفاده کنند. فقط Adminهای خالص.
  • Credential Guard فعال نمی‌شود: نیاز به UEFI + Secure Boot + TPM 2.0 + CPU Virtualization.
  • BitLocker روی Server خطا: TPM 2.0 نبوده یا UEFI+Secure Boot ندارد.
  • BitLocker Recovery Key پیدا نمی‌شود: GPO برای Backup به AD فعال نبوده.
  • Network Unlock کار نمی‌کند: WDS یا Certificate اشتباه. DHCP و FQDN صحیح چک کن.
  • Shielded VM Start نمی‌شود: HGS Attestation Failed — Host را در HGS Group اضافه کن.
  • HGS خطای Certificate: Signing و Encryption Certificate از CA معتبر بگیر.
  • AppLocker همه‌چیز را بلاک می‌کند: Default Rules (Allow Admins) را فعال نکردی.
  • WDAC بعد از Reboot سیستم بوت نمی‌شود: Policy را در Audit Mode تست کن قبل از Enforce.
  • ATA/Defender for Identity Alert Flood: Baseline رفتار عادی را تنظیم کن — Not Every Alert a Breach.
