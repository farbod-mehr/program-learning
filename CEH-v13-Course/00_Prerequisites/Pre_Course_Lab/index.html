🔰 معرفی آزمایشگاه Ping و Traceroute

Ping و Traceroute دو ابزار اساسی و حیاتی در عیب‌یابی شبکه و تست نفوذ هستند. این ابزارها از پروتکل ICMP (Internet Control Message Protocol) برای بررسی اتصال و مسیریابی بسته‌ها استفاده می‌کنند.

چرا این آزمایشگاه برای CEH مهم است؟

  • شناسایی میزبان‌های زنده: با Ping می‌توانید تشخیص دهید کدام دستگاه‌ها در شبکه فعال هستند.
  • تشخیص قطعی: اگر پینگ پاسخ ندهد، یعنی مسیر یا دستگاه مقصد مشکل دارد.
  • مسیریابی: Traceroute به شما نشان می‌دهد که بسته‌ها از چه مسیری به مقصد می‌رسند.
  • تحلیل تأخیر: با اندازه‌گیری زمان پاسخ (RTT) می‌توانید کیفیت شبکه را ارزیابی کنید.
  • پایهٔ حملات: بسیاری از حملات مانند Ping of Death و Smurf Attack از ICMP سوءاستفاده می‌کنند.
💡 هدف این آزمایشگاه:
  • راه‌اندازی دو ماشین مجازی در یک شبکه داخلی
  • تست اتصال با ping و تحلیل پاسخ‌ها
  • مشاهدهٔ مسیر بسته‌ها با traceroute
  • آنالیز ترافیک ICMP با Wireshark
  • عیب‌یابی سناریوهای رایج قطعی شبکه

📥 پیش‌نیازهای آزمایشگاه

برای انجام این آزمایشگاه به موارد زیر نیاز دارید:

  • دو ماشین مجازی:
    • یک ماشین Kali Linux (به‌عنوان مهاجم/تستر)
    • یک ماشین Ubuntu یا Windows (به‌عنوان هدف)
  • نرم‌افزار VirtualBox: با قابلیت تنظیم شبکه‌های داخلی (Internal Network).
  • ابزارهای شبکه:
    • ping (در تمام سیستمعامل‌ها موجود است)
    • traceroute (در لینوکس) یا tracert (در ویندوز)
    • Wireshark (برای آنالیز بسته‌ها)
  • دسترسی به اینترنت: برای تست Traceroute به بیرون.
⚠️ توجه: اگر از ویندوز به‌عنوان هدف استفاده می‌کنید، ممکن است فایروال داخلی ویندوز پاسخ‌های ICMP را بلاک کند. برای تست، فایروال را به‌طور موقت غیرفعال کنید یا قانون ورودی برای ICMP اضافه کنید.

🖥️ مرحله ۱: تنظیم شبکه داخلی در VirtualBox

برای اینکه دو ماشین مجازی بتوانند با هم ارتباط برقرار کنند، باید آنها را در یک شبکه داخلی (Internal Network) قرار دهیم.

۱ هر دو ماشین را خاموش کنید
  • در VirtualBox، ماشین‌های Kali و Ubuntu را انتخاب کرده و از منوی Machine → Close → Power Off خاموش کنید.
  • چرا؟ تنظیمات شبکه فقط در حالت خاموش قابل تغییر هستند.
۲ تنظیم آداپتور شبکه روی Internal Network
  • روی هر ماشین، Settings → Network را باز کنید.
  • تب Adapter 1 را انتخاب کنید.
  • گزینهٔ Enable Network Adapter را فعال کنید.
  • در بخش Attached to: گزینهٔ Internal Network را انتخاب کنید.
  • در بخش Name: نام شبکه را intnet (یا هر نام دلخواه) وارد کنید.
  • این کار را برای هر دو ماشین انجام دهید.
  • چرا؟ Internal Network یک شبکهٔ مجازی کاملاً ایزوله است که فقط ماشین‌های داخل آن می‌توانند با هم ارتباط برقرار کنند. این محیط امن‌ترین گزینه برای تمرین تست نفوذ است.
۳ بررسی آداپتورهای شبکه در سیستمعامل مهمان
  • هر دو ماشین را روشن کنید.
  • در ترمینال هر دو، دستور ip a (لینوکس) یا ipconfig (ویندوز) را اجرا کنید.
  • آداپتور eth0 (در لینوکس) یا Ethernet (در ویندوز) را پیدا کنید.
  • اگر آدرسی دریافت نکرده است، نگران نباشید – در مرحلهٔ بعد به‌صورت دستی تنظیم می‌کنیم.
💡 نکته: اگر از VMware استفاده می‌کنید، به‌جای Internal Network از حالت Host‑Only یا Custom Network با محدودهٔ IP دلخواه استفاده کنید.

🔢 مرحله ۲: اختصاص IP ثابت به ماشین‌ها

در شبکه‌های داخلی، معمولاً سرور DHCP وجود ندارد. بنابراین باید IP را به‌صورت دستی (Static) تنظیم کنیم.

📌 تنظیم IP در Kali (ماشین اول)

# اضافه کردن آدرس IP به رابط eth0
sudo ip addr add 192.168.100.10/24 dev eth0

# فعال کردن رابط شبکه
sudo ip link set eth0 up

# بررسی تنظیمات
ip a show eth0

📌 تنظیم IP در Ubuntu (ماشین دوم)

# اضافه کردن آدرس IP به رابط eth0
sudo ip addr add 192.168.100.20/24 dev eth0

# فعال کردن رابط شبکه
sudo ip link set eth0 up

# بررسی تنظیمات
ip a show eth0

چرا این IPها را انتخاب کردیم؟

  • رنج ۱۹۲.۱۶۸.۱۰۰.۰/24 یک محدودهٔ خصوصی است که برای شبکه‌های داخلی استفاده می‌شود.
  • .۱۰ برای Kali و .۲۰ برای Ubuntu – این اختلاف باعث می‌شود به‌راحتی تشخیص داده شوند.
  • ماسک /24 یعنی ۲۵۶ آدرس در این شبکه وجود دارد که برای آزمایشگاه کافی است.
✅ تست اولیه: از Kali، دستور ping -c 2 192.168.100.20 را اجرا کنید. اگر پاسخ دریافت کردید، یعنی شبکه به‌درستی تنظیم شده است.
⚠️ اگر پینگ پاسخ نداد:
  • مطمئن شوید که هر دو ماشین روشن هستند.
  • آدرس IP را دوباره بررسی کنید.
  • فایروال Ubuntu را با sudo ufw disable غیرفعال کنید.

📡 مرحله ۳: تست اتصال با Ping

حالا که شبکه برقرار است، می‌توانیم از Ping برای تست اتصال استفاده کنیم.

📌 پینگ به Ubuntu از Kali

ping -c 4 192.168.100.20

خروجی نمونه: 

PING 192.168.100.20 (192.168.100.20) 56(84) bytes of data.
64 bytes from 192.168.100.20: icmp_seq=1 ttl=64 time=0.456 ms
64 bytes from 192.168.100.20: icmp_seq=2 ttl=64 time=0.389 ms
64 bytes from 192.168.100.20: icmp_seq=3 ttl=64 time=0.412 ms
64 bytes from 192.168.100.20: icmp_seq=4 ttl=64 time=0.401 ms

--- 192.168.100.20 ping statistics ---
4 packets transmitted, 4 received, 0% packet loss, time 3055ms
rtt min/avg/max/mdev = 0.389/0.414/0.456/0.030 ms
🔍 تفسیر خروجی:
  • icmp_seq: شماره دنبالهٔ بسته – نشان می‌دهد چندمین بسته ارسال شده است.
  • ttl (Time To Live): تعداد هاپ‌های باقی‌مانده – در شبکه محلی معمولاً ۶۴ است.
  • time: زمان رفت و برگشت (RTT) به میلی‌ثانیه – هرچه کمتر باشد، شبکه بهتر است.
  • packet loss: درصد بسته‌های از دست‌رفته – اگر بالای ۱٪ باشد، نشانهٔ مشکل است.
  • min/avg/max/mdev: آمار دقیق تأخیر – mdev نشان‌دهندهٔ نوسان است.

📌 پینگ به سرور خارجی (مثل Google)

ping -c 4 8.8.8.8

توجه: اگر Kali به اینترنت دسترسی ندارد (زیرا Internal Network ایزوله است)، این دستور جواب نمی‌دهد. برای تست به بیرون، باید آداپتور دوم را روی NAT تنظیم کنید.

🗺️ مرحله ۴: مشاهده مسیر با Traceroute

Traceroute نشان می‌دهد که بسته‌ها از چه مسیری به مقصد می‌رسند و هر هاپ چقدر تأخیر دارد.

📌 Traceroute به یک سرور خارجی

traceroute -n 8.8.8.8

خروجی نمونه: 

traceroute to 8.8.8.8 (8.8.8.8), 30 hops max, 60 byte packets
 1  192.168.1.1  1.234 ms  1.189 ms  1.155 ms
 2  10.0.0.1  5.678 ms  5.634 ms  5.601 ms
 3  172.16.0.1  10.234 ms  10.189 ms  10.155 ms
 4  8.8.8.8  15.678 ms  15.634 ms  15.601 ms
🔍 تفسیر خروجی:
  • هر سطر یک هاپ (Hop) یا روتر در مسیر را نشان می‌دهد.
  • ستون اول: IP روتر.
  • سه ستون بعدی: زمان رفت و برگشت (RTT) برای هر یک از سه بستهٔ ارسال‌شده.
  • اگر یک هاپ با * * * نمایش داده شود، یعنی آن روتر به بسته‌های ICMP پاسخ نمی‌دهد (ممکن است فایروال آن را بلاک کرده باشد).
  • گزینهٔ -n: از حل معکوس DNS جلوگیری می‌کند و سرعت را افزایش می‌دهد.

📌 Traceroute در ویندوز (tracert)

tracert -d 8.8.8.8

گزینهٔ -d در ویندوز معادل -n در لینوکس است (عدم حل DNS).

💡 کاربرد در هک:
  • با Traceroute می‌توانید تعداد روترهای بین شما و هدف را بشمارید.
  • هاپ‌های با تأخیر بالا نشانهٔ گلوگاه (Bottleneck) در شبکه هستند.
  • اگر Traceroute در یک هاپ خاص متوقف شود، یعنی مسیر در آن نقطه قطع است.

🔍 مرحله ۵: آنالیز ترافیک ICMP با Wireshark

Wireshark به شما اجازه می‌دهد بسته‌های ICMP را در لحظه ببینید و ساختار آنها را تحلیل کنید.

📌 مراحل:

  1. Wireshark را در Kali باز کنید.
  2. رابط eth0 را انتخاب کرده و ضبط را شروع کنید.
  3. فیلتر icmp را در نوار فیلتر وارد کنید.
  4. از ترمینال، یک پینگ به Ubuntu بفرستید: ping -c 4 192.168.100.20.
  5. بسته‌های Echo Request (ارسال) و Echo Reply (دریافت) را در Wireshark مشاهده کنید.
🔍 جزئیات بسته‌های ICMP در Wireshark:
  • Type: 8 برای Echo Request، 0 برای Echo Reply.
  • Code: معمولاً ۰ است.
  • Identifier: یک شمارهٔ منحصربه‌فرد برای تشخیص پینگ‌های مختلف.
  • Sequence Number: شماره دنباله (همان icmp_seq در خروجی پینگ).
  • Data: محتوای بسته (معمولاً شامل حروف و اعداد تصادفی).
💡 تمرین: یک پینگ با اندازهٔ ۱۰۰۰ بایت ارسال کنید: ping -s 1000 -c 2 192.168.100.20. در Wireshark مشاهده کنید که بسته به دو بخش (Fragment) تقسیم می‌شود. این همان مفهوم MTU است.

🛠️ عیب‌یابی مشکلات رایج در Ping و Traceroute

❌ مشکل ۱: پینگ پاسخ نمی‌دهد (Request timed out)
  • دلیل: مقصد خاموش است، فایروال بسته‌ها را بلاک می‌کند، یا شبکه قطع است.
  • راه‌حل:
    • با ping 127.0.0.1 (لوپ‌بک) تست کنید که خود سیستم کار می‌کند.
    • با traceroute ببینید بسته در کدام هاپ متوقف می‌شود.
    • فایروال مقصد را غیرفعال کنید (در Ubuntu: sudo ufw disable).
❌ مشکل ۲: Traceroute فقط * * * نشان می‌دهد
  • دلیل: روترها پاسخ ICMP Time Exceeded را بلاک می‌کنند.
  • راه‌حل:
    • از گزینهٔ -T (TCP) یا -U (UDP) در لینوکس استفاده کنید: traceroute -T -p 80 8.8.8.8.
    • در ویندوز، tracert -d امتحان کنید.
❌ مشکل ۳: پینگ به بیرون (اینترنت) کار نمی‌کند
  • دلیل: ماشین مجازی به اینترنت دسترسی ندارد (Internal Network ایزوله است).
  • راه‌حل:
    • در VirtualBox، یک آداپتور دوم روی NAT اضافه کنید.
    • در Kali، sudo dhclient eth1 را اجرا کنید تا IP دریافت کند.
❌ مشکل ۴: تأخیر (RTT) خیلی بالاست
  • دلیل: شبکه شلوغ است، مسیر طولانی است، یا مشکل سخت‌افزاری وجود دارد.
  • راه‌حل:
    • با traceroute شناسایی کنید کدام هاپ تأخیر دارد.
    • در VirtualBox، منابع (RAM و CPU) ماشین را افزایش دهید.
❌ مشکل ۵: پینگ با خطای «Network is unreachable» مواجه می‌شود
  • دلیل: رابط شبکه بالا نیامده یا IP به‌درستی تنظیم نشده است.
  • راه‌حل:
    • ip a را اجرا کنید و وضعیت eth0 را ببینید.
    • اگر state DOWN بود، sudo ip link set eth0 up را اجرا کنید.
❌ مشکل ۶: پینگ پاسخ می‌دهد اما Traceroute کار نمی‌کند
  • دلیل: ممکن است پروتکل UDP (پیش‌فرض traceroute) توسط فایروال بلاک شود.
  • راه‌حل: از گزینهٔ -I (ICMP) استفاده کنید: traceroute -I 8.8.8.8.

🛡️ نکات امنیتی – استفاده از Ping و Traceroute در تست نفوذ

🔐 ۱. محدود کردن ICMP در فایروال

در شبکه‌های سازمانی، معمولاً ICMP را محدود می‌کنند تا از حملات شناسایی (Reconnaissance) جلوگیری شود. به‌عنوان یک هکر قانونمند، باید بدانید که اگر پینگ جواب نداد، ممکن است هدف هنوز زنده باشد اما ICMP را بلاک کرده باشد.

🔐 ۲. استفاده از Ping Sweep برای شناسایی میزبان‌های زنده

با اسکن کردن کل یک زیرشبکه با پینگ، می‌توانید دستگاه‌های فعال را پیدا کنید: 

for i in {1..254}; do ping -c 1 -W 1 192.168.1.$i | grep "64 bytes" & done

در Nmap، این کار با nmap -sn 192.168.1.0/24 انجام می‌شود.

🔐 ۳. حملات مبتنی بر ICMP
  • Ping of Death: ارسال بسته‌های ICMP بزرگتر از ۶۵۵۳۵ بایت که باعث سرریز شدن بافر می‌شود.
  • Smurf Attack: ارسال پینگ به آدرس Broadcast با IP مبدأ جعلی که باعث می‌شود همه دستگاه‌های شبکه به هدف پاسخ دهند (DDoS).
  • ICMP Tunneling: استفاده از ICMP برای انتقال داده‌های مخفی در شبکه.

توصیه: همیشه ICMP را در شبکه‌های تولیدی محدود کنید و فقط از آن برای عیب‌یابی استفاده کنید.

🔐 ۴. استفاده از Traceroute برای نقشه‌برداری شبکه

Traceroute به شما کمک می‌کند توپولوژی شبکه را شناسایی کنید. در تست نفوذ، این اطلاعات برای برنامه‌ریزی حملات بعدی بسیار ارزشمند است.

⚠️ هشدار: اسکن شبکه و استفاده از ابزارهای ICMP بدون مجوز، در بسیاری از کشورها جرم محسوب می‌شود. فقط در محیط‌های آزمایشگاهی یا با مجوز کتبی از مالک شبکه استفاده کنید.

🧪 تمرینات عملی پیشرفته

برای تسلط کامل بر Ping و Traceroute، این تمرینات را در محیط آزمایشگاهی خود انجام دهید:

  • تمرین ۱ – پینگ با اندازه‌های مختلف: بسته‌هایی با اندازه‌های ۶۴، ۵۱۲، ۱۴۷۲ و ۲۰۰۰ بایت ارسال کنید و رفتار آنها را در Wireshark مشاهده کنید. 
    ping -s 1472 -c 2 192.168.100.20
    نکته: ۱۴۷۲ بایت حداکثر اندازه‌ای است که بدون Fragment در شبکه‌های Ethernet (MTU=1500) ارسال می‌شود.
  • تمرین ۲ – تنظیم TTL در پینگ: با تغییر TTL، ببینید چه اتفاقی می‌افتد. 
    ping -t 1 8.8.8.8   # TTL=1 → بسته در اولین روتر متوقف می‌شود
  • تمرین ۳ – Traceroute با پروتکل‌های مختلف: سه نوع Traceroute را امتحان کنید و تفاوت خروجی را مشاهده کنید: 
    traceroute -I 8.8.8.8   # ICMP
traceroute -T -p 80 8.8.8.8  # TCP به پورت ۸۰
traceroute -U -p 53 8.8.8.8  # UDP به پورت ۵۳
  • تمرین ۴ – اسکن Ping Sweep با Bash: یک اسکریپت بنویسید که تمام IPهای شبکه ۱۹۲.۱۶۸.۱۰۰.۰/24 را پینگ کند و IPهای زنده را گزارش دهد. 
    #!/bin/bash
for i in {1..254}; do
    ping -c 1 -W 1 192.168.100.$i &> /dev/null
    if [ $? -eq 0 ]; then
        echo "192.168.100.$i is alive"
    fi
done
  • تمرین ۵ – آنالیز ترافیک ICMP در Wireshark: یک پینگ با ۱۰۰ بسته ارسال کنید و در Wireshark آمار (Statistics) مربوط به ICMP را بررسی کنید.
💡 پاسخ سوال مطرح‌شده در ابتدای صفحه: «اگر مقصد خاموش باشد، پیغام خطای پینگ چیست؟»
پاسخ: پیغام «Destination Host Unreachable» یا «Request timed out» نمایش داده می‌شود. در لینوکس، اگر مقصد در شبکه محلی نباشد، خطای «Network is unreachable» نیز ممکن است ظاهر شود.

📖 واژه‌نامه تخصصی مرتبط با Ping و Traceroute

واژهتوضیح کامل (معنی، کاربرد، مثال، کارکرد، عملکرد)
ICMP معنی: Internet Control Message Protocol – پروتکل پیام‌های کنترلی اینترنت.
کاربرد: ارسال پیام‌های خطا و اطلاعات عملیاتی در شبکه (مثل پینگ و Traceroute).
مثال: بسته‌های Echo Request و Echo Reply برای تست اتصال.
کارکرد: در لایه شبکه (Internet Layer) قرار دارد و برای گزارش خطاها و تست اتصال استفاده می‌شود.
عملکرد: بسته‌های ICMP شامل نوع، کد و داده هستند و توسط روترها و میزبان‌ها پردازش می‌شوند.
Ping معنی: یک دستور شبکه برای تست اتصال بین دو دستگاه با استفاده از ICMP.
کاربرد: بررسی زنده بودن یک میزبان، اندازه‌گیری تأخیر (RTT) و تشخیص قطعی.
مثال: ping 8.8.8.8 برای تست اتصال به اینترنت.
کارکرد: ارسال بسته‌های Echo Request و دریافت Echo Reply.
عملکرد: اگر پاسخ دریافت نشود، یعنی دستگاه مقصد غیرفعال است یا فایروال آن را بلاک کرده است.
Traceroute معنی: یک دستور شبکه برای نمایش مسیر بسته‌ها از مبدأ به مقصد.
کاربرد: شناسایی روترهای بین مبدأ و مقصد، تشخیص قطعی و اندازه‌گیری تأخیر در هر هاپ.
مثال: traceroute 8.8.8.8 برای مشاهده مسیر به سرور گوگل.
کارکرد: ارسال بسته‌هایی با TTL افزایشی و دریافت خطای Time Exceeded از روترها.
عملکرد: هر روتر TTL را ۱ کم می‌کند؛ وقتی به صفر برسد، خطا را به مبدأ برمی‌گرداند و آدرس خود را نشان می‌دهد.
TTL (Time To Live) معنی: یک فیلد در هدر IP که تعداد هاپ‌های مجاز برای یک بسته را مشخص می‌کند.
کاربرد: جلوگیری از چرخش بی‌نهایت بسته‌ها در شبکه.
مثال: TTL=64 در شبکه محلی، TTL=128 در ویندوز.
کارکرد: هر روتر که بسته را عبور می‌دهد، TTL را ۱ کاهش می‌دهد.
عملکرد: وقتی TTL به صفر می‌رسد، روتر بسته را دور می‌اندازد و خطای ICMP Time Exceeded را به مبدأ برمی‌گرداند.
RTT (Round-Trip Time) معنی: زمان رفت و برگشت – مدت زمان لازم برای ارسال یک بسته به مقصد و دریافت پاسخ آن.
کاربرد: اندازه‌گیری کیفیت شبکه و تشخیص تأخیر.
مثال: در خروجی پینگ، time=0.456 ms نشان‌دهندهٔ RTT است.
کارکرد: زمان بر حسب میلی‌ثانیه (ms) اندازه‌گیری می‌شود.
عملکرد: RTT کمتر = شبکه بهتر و پاسخ‌دهی سریع‌تر.
Packet Loss معنی: درصد بسته‌هایی که به مقصد نمی‌رسند.
کاربرد: تشخیص مشکلات شبکه مانند ترافیک بالا، خرابی کابل یا تنظیمات اشتباه.
مثال: «0% packet loss» یعنی همه بسته‌ها به‌درستی رسیده‌اند.
کارکرد: در خروجی پینگ در انتها نمایش داده می‌شود.
عملکرد: اگر Packet Loss بالای ۱٪ باشد، شبکه نیاز به بررسی دارد.
Internal Network معنی: یک شبکه مجازی ایزوله در VirtualBox که فقط ماشین‌های داخل آن به هم متصل هستند.
کاربرد: ایجاد محیط آزمایشگاهی امن برای تست نفوذ.
مثال: نام شبکه‌های داخلی مثل intnet.
کارکرد: ماشین‌ها فقط با هم ارتباط دارند و به اینترنت یا میزبان دسترسی ندارند.
عملکرد: مناسب برای شبیه‌سازی شبکه‌های محلی بدون خطر تداخل با شبکهٔ واقعی.
Hop معنی: یک گام یا پرش در مسیر یک بسته از مبدأ به مقصد – معمولاً هر روتر یک هاپ محسوب می‌شود.
کاربرد: شمارش تعداد روترهای بین دو دستگاه.
مثال: در خروجی Traceroute، هر سطر یک هاپ را نشان می‌دهد.
کارکرد: هر چه تعداد هاپ بیشتر باشد، مسیر طولانی‌تر است.
عملکرد: در شبکه‌های IPv4، حداکثر TTL ۲۵۵ است که یعنی حداکثر ۲۵۵ هاپ مجاز است.
💡 نکته: این واژه‌نامه یک مرجع سریع برای اصطلاحات کلیدی این آزمایشگاه است. توصیه می‌شود قبل از شروع آزمایشگاه، آنها را مرور کنید.
