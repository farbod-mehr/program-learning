🧠 بدنه اصلی آموزش

۱۳.۱ ماژول چیست و چرا از آن استفاده می‌کنیم؟

ماژول (Module) یک فایل پایتون است که شامل تعاریف، توابع، کلاس‌ها و متغیرهاست. با استفاده از ماژول‌ها می‌توانید کد را به بخش‌های کوچک‌تر و قابل‌مدیریت تقسیم کنید.

  • مزایای استفاده از ماژول‌ها:
    • سازماندهی کد: کد را به بخش‌های منطقی تقسیم می‌کند.
    • قابل استفاده‌ی مجدد: یک ماژول را می‌توانید در چندین برنامه استفاده کنید.
    • کاهش وابستگی: تغییرات در یک ماژول، بقیه‌ی برنامه را تحت تأثیر قرار نمی‌دهد.
    • استفاده از کتابخانه‌های آماده: با import کردن ماژول‌های استاندارد یا شخص ثالث، از کدهای دیگران استفاده می‌کنید.
# ماژول‌های استاندارد پایتون
import math
import random
import datetime
import os
import sys

# استفاده از ماژول math
print(math.sqrt(16))       # 4.0
print(math.pi)             # 3.141592653589793

# استفاده از ماژول random
print(random.randint(1, 10))  # عدد تصادفی بین ۱ تا ۱۰

# استفاده از ماژول datetime
now = datetime.datetime.now()
print(now)                 # 2026-01-15 14:30:00...
➜ 4.0
➜ 3.141592653589793
💡 نکته: پایتون کتابخانه‌ی استاندارد بسیار غنی‌ای دارد که شامل ماژول‌های مفید برای کارهای مختلف (ریاضی، تاریخ، فایل، شبکه و ...) است.
🧪 تمرین: ماژول math را import کنید و از توابع ceil()، floor() و pow() استفاده کنید.

۱۳.۲ روش‌های import: import، from...import و as

سه روش اصلی برای import کردن ماژول‌ها وجود دارد:

📦 import module import کامل ماژول
📋 from module import ... import بخشی از ماژول
🔤 import module as alias import با نام مستعار 
# روش ۱: import کامل
import math
print(math.sqrt(25))  # 5.0

# روش ۲: from...import
from math import sqrt, pi
print(sqrt(36))      # 6.0
print(pi)            # 3.1415

# روش ۳: import با نام مستعار (alias)
import datetime as dt
now = dt.datetime.now()
print(now)

# import همه‌چیز (توصیه نمی‌شود)
from math import *
print(sin(0))        # 0.0 (اما نام‌ها ممکن است تداخل کنند)

# import چندین چیز با کاما
from random import randint, choice
print(randint(1, 100))
print(choice(["a", "b", "c"]))

# import ماژول‌های استاندارد
import os
import sys
print(sys.version)   # نسخه پایتون
➜ 5.0
➜ 6.0
➜ 2026-01-15 14:30:00
💎 نکته طلایی: از from module import * خودداری کنید چون ممکن است نام‌ها تداخل پیدا کنند. بهتر است فقط چیزهایی که نیاز دارید را import کنید یا از نام مستعار استفاده کنید.
🧪 تمرین: ماژول random را import کنید و یک عدد تصادفی بین ۱ تا ۱۰۰ تولید کنید. همچنین با from random import choice یک عنصر تصادفی از یک لیست انتخاب کنید.

۱۳.۳ ساخت ماژول‌های سفارشی

شما می‌توانید ماژول‌های خود را بسازید. کافی است یک فایل .py ایجاد کنید و توابع، کلاس‌ها و متغیرهای خود را در آن بنویسید.

# فایل: mymodule.py
def greet(name):
    return f"سلام {name}!"

def add(a, b):
    return a + b

PI = 3.14159

class Calculator:
    def multiply(self, a, b):
        return a * b

# ============================================

# فایل: main.py (استفاده از ماژول)
import mymodule

print(mymodule.greet("علی"))        # "سلام علی!"
print(mymodule.add(5, 3))           # 8
print(mymodule.PI)                  # 3.14159

calc = mymodule.Calculator()
print(calc.multiply(5, 3))          # 15

# با from...import
from mymodule import greet, PI
print(greet("سارا"))                # "سلام سارا!"
print(PI)                           # 3.14159
➜ سلام علی!
➜ 8
💡 نکته: وقتی یک فایل پایتون را import می‌کنید، پایتون آن را اجرا می‌کند. برای جلوگیری از اجرای کدهای خاص هنگام import، از if __name__ == "__main__" استفاده کنید (بخش بعدی).
🧪 تمرین: یک ماژول به نام utilities.py ایجاد کنید که شامل توابع is_even()، is_odd() و factorial() باشد. سپس آن را در یک فایل دیگر import کنید و از توابع استفاده کنید.

۱۳.۴ if __name__ == "__main__"

این یک الگوی مهم در پایتون است که به ماژول اجازه می‌دهد هم به‌عنوان یک برنامه‌ی مستقل اجرا شود و هم به‌عنوان ماژول import شود.

  • __name__: زمانی که فایل مستقیماً اجرا می‌شود، مقدار "__main__" است.
  • زمانی که فایل import می‌شود، مقدار __name__ برابر با نام ماژول است.
# فایل: mymodule.py
def greet(name):
    return f"سلام {name}!"

def main():
    print("این ماژول به‌صورت مستقیم اجرا شده است.")
    print(greet("علی"))

if __name__ == "__main__":
    main()
    # این کد فقط زمانی اجرا می‌شود که فایل مستقیم اجرا شود
    # اگر import شود، اجرا نمی‌شود

# ============================================

# فایل: main.py (import کردن)
import mymodule

print(mymodule.greet("سارا"))  # "سلام سارا!"
# کدهای داخل if __name__ اجرا نمی‌شوند
➜ (اجرای مستقیم mymodule.py)
➜ این ماژول به‌صورت مستقیم اجرا شده است.
➜ سلام علی!
💎 نکته طلایی: همیشه از if __name__ == "__main__" برای قرار دادن کدهای تست یا اجرای مستقیم ماژول استفاده کنید. این کار باعث می‌شود ماژول شما هم قابل استفاده‌ی مجدد و هم قابل اجرا باشد.
🧪 تمرین: یک ماژول به نام calculator.py با توابع add()، subtract()، multiply() و divide() ایجاد کنید. یک بخش if __name__ == "__main__" اضافه کنید که توابع را تست کند. سپس ماژول را import کنید و از توابع استفاده کنید.

۱۳.۵ پکیج‌ها (Packages) و __init__.py

پکیج (Package) یک دایرکتوری است که شامل چندین ماژول مرتبط است. برای اینکه یک دایرکتوری به‌عنوان پکیج شناخته شود، باید یک فایل __init__.py در آن وجود داشته باشد.

  • __init__.py: می‌تواند خالی باشد یا کدهای اولیه برای پکیج را شامل شود.
  • پکیج‌ها به شما اجازه می‌دهند ماژول‌ها را به‌صورت سلسله‌مراتبی سازماندهی کنید.
# ساختار پکیج
myproject/
├── __init__.py
├── utils/
│   ├── __init__.py
│   ├── strings.py
│   └── numbers.py
└── data/
    ├── __init__.py
    └── database.py

# ============================================

# فایل: utils/strings.py
def reverse(text):
    return text[::-1]

def capitalize_words(text):
    return text.title()

# فایل: utils/numbers.py
def is_even(n):
    return n % 2 == 0

def is_prime(n):
    if n < 2:
        return False
    for i in range(2, int(n**0.5) + 1):
        if n % i == 0:
            return False
    return True

# فایل: data/database.py
class Database:
    def __init__(self):
        self.data = []
    
    def add(self, item):
        self.data.append(item)
    
    def get_all(self):
        return self.data

# ============================================

# فایل: main.py (استفاده از پکیج)
from utils.strings import reverse, capitalize_words
from utils.numbers import is_even, is_prime
from data.database import Database

print(reverse("hello"))           # "olleh"
print(capitalize_words("hello world"))  # "Hello World"
print(is_even(4))                 # True
print(is_prime(7))                # True

db = Database()
db.add("item1")
db.add("item2")
print(db.get_all())               # ['item1', 'item2']
➜ olleh
➜ Hello World
➜ True
💡 نکته: در پایتون ۳، __init__.py برای تعریف پکیج لازم است (اختیاری در نسخه‌های جدیدتر، اما همچنان توصیه می‌شود).
🧪 تمرین: یک پکیج به نام math_utils با دو ماژول basic.py (توابع جمع، تفریق، ضرب، تقسیم) و advanced.py (توابع توان، ریشه، فاکتوریل) ایجاد کنید. سپس در یک فایل اصلی از آنها استفاده کنید.

۱۳.۶ نصب پکیج‌ها با pip

pip مدیر بسته‌های پایتون است و برای نصب پکیج‌های شخص ثالث از PyPI (Python Package Index) استفاده می‌شود.

  • نصب پکیج: pip install package_name
  • نصب نسخه‌ی خاص: pip install package_name==1.2.3
  • به‌روزرسانی: pip install --upgrade package_name
  • حذف: pip uninstall package_name
  • مشاهده‌ی پکیج‌های نصب‌شده: pip list
  • نصب از فایل requirements: pip install -r requirements.txt
# نصب پکیج محبوب requests
pip install requests

# نصب نسخه‌ی خاص
pip install numpy==1.24.0

# نصب چند پکیج
pip install requests pandas matplotlib

# نصب پکیج در محیط مجازی
# (پس از فعال‌سازی محیط)
pip install flask

# ذخیره‌سازی وابستگی‌ها
pip freeze > requirements.txt

# نصب از روی فایل requirements.txt
pip install -r requirements.txt
💎 نکته طلایی: همیشه از محیط مجازی برای نصب پکیج‌ها استفاده کنید تا از تداخل بین پروژه‌های مختلف جلوگیری کنید.
🧪 تمرین: پکیج requests را نصب کنید و یک درخواست ساده به یک API (مثلاً https://api.github.com) ارسال کنید.

۱۳.۷ محیط‌های مجازی و requirements.txt

محیط مجازی (Virtual Environment) یک فضای ایزوله برای پروژه‌های پایتون است که به شما اجازه می‌دهد وابستگی‌های هر پروژه را جداگانه مدیریت کنید.

  • ایجاد محیط مجازی: python -m venv venv
  • فعال‌سازی در Windows: venv\Scripts\activate
  • فعال‌سازی در macOS/Linux: source venv/bin/activate
  • خروج از محیط: deactivate
  • ذخیره‌سازی وابستگی‌ها: pip freeze > requirements.txt
  • نصب وابستگی‌ها: pip install -r requirements.txt
# ایجاد محیط مجازی
python -m venv myenv

# فعال‌سازی (Windows)
myenv\Scripts\activate

# فعال‌سازی (macOS/Linux)
source myenv/bin/activate

# نصب پکیج‌ها در محیط
pip install requests flask pandas

# ذخیره‌سازی وابستگی‌ها
pip freeze > requirements.txt

# محتویات requirements.txt
# requests==2.28.1
# flask==2.2.2
# pandas==1.5.3

# نصب وابستگی‌ها در محیط جدید
pip install -r requirements.txt

# خروج از محیط
deactivate
ویژگی بدون محیط مجازی با محیط مجازی ایزوله بودن ❌ ✅ مدیریت وابستگی‌ها ❌ مشکل ✅ آسان تداخل بین پروژه‌ها ❌ زیاد ✅ کم توصیه ❌ ✅ همیشه
💡 نکته: همیشه برای هر پروژه‌ی پایتونی یک محیط مجازی ایجاد کنید. این کار باعث می‌شود پروژه‌ها از هم مستقل باشند و از مشکلات نسخه‌های مختلف جلوگیری شود.
🧪 تمرین: یک محیط مجازی برای یک پروژه‌ی جدید ایجاد کنید، پکیج‌های requests و flask را نصب کنید، وابستگی‌ها را در requirements.txt ذخیره کنید و سپس محیط را غیرفعال کنید.

🛠️ کارگاه عملی

گام‌به‌گام: ساخت یک پروژه با ماژول‌ها و پکیج‌ها

  1. یک پوشه برای پروژه ایجاد کنید.
  2. یک محیط مجازی ایجاد و فعال کنید.
  3. یک پکیج به نام utils با ماژول‌های زیر بسازید:

  6. وابستگی‌ها (در صورت نیاز) را در requirements.txt ذخیره کنید.
  7. برنامه را اجرا کنید و نتایج را بررسی کنید.

📝 پرسش‌ها و تمرینات

سوالات تشریحی

  1. تفاوت بین ماژول و پکیج چیست؟
  2. سه روش import کردن ماژول را با مثال توضیح دهید.
  3. if __name__ == "__main__" چه کاربردی دارد؟
  4. چرا باید از محیط‌های مجازی استفاده کنیم؟
  5. requirements.txt چه نقشی در پروژه دارد؟

سوالات چهارگزینه‌ای

  1. کدام یک از موارد زیر برای import کردن یک ماژول با نام مستعار استفاده می‌شود؟
    أ) import module as alias ب) from module import alias ج) import alias from module د) alias = import module
  2. برای اینکه یک دایرکتوری به‌عنوان پکیج شناخته شود، چه فایلی باید در آن باشد؟
    أ) __main__.py ب) __init__.py ج) package.py د) setup.py
  3. کدام دستور برای نصب یک پکیج با pip استفاده می‌شود؟
    أ) pip install package ب) pip get package ج) pip add package د) pip download package

📌 جمع‌بندی و خلاصه

نکات طلایی

  • 🔹 ماژول یک فایل .py است که کد را سازماندهی می‌کند.
  • 🔹 پکیج یک دایرکتوری با __init__.py است که ماژول‌ها را گروه‌بندی می‌کند.

  • 🔹 if __name__ == "__main__" برای تشخیص اجرای مستقیم یا import.
  • 🔹 pip مدیر بسته‌های پایتون برای نصب پکیج‌های شخص ثالث.
  • 🔹 محیط‌های مجازی (venv) برای ایزوله کردن وابستگی‌های پروژه.
  • 🔹 requirements.txt برای مدیریت وابستگی‌ها و انتقال آسان پروژه.

📖 واژه‌نامه تخصصی

  • Module (ماژول): فایل پایتون با کدهای قابل استفاده‌ی مجدد.
  • Package (پکیج): مجموعه‌ای از ماژول‌ها در یک دایرکتوری.
  • Import: فراخوانی کد از یک ماژول یا پکیج.
  • __name__: متغیر ویژه که نام ماژول را نگه می‌دارد.
  • pip: مدیر بسته‌های پایتون.
  • Virtual Environment (محیط مجازی): فضای ایزوله برای مدیریت وابستگی‌ها.
  • requirements.txt: فایل لیست وابستگی‌های پروژه.
  • PyPI: مخزن رسمی پکیج‌های پایتون.
  • __init__.py: فایل برای تعریف پکیج.

❓ سوالات محرک (برای درگیری ذهن)

  • ❓ اگر دو ماژول با نام مشابه داشته باشیم، چگونه از تداخل جلوگیری کنیم؟
  • ❓ چرا پایتون از ماژول‌ها برای سازماندهی کد استفاده می‌کند؟
  • ❓ چه تفاوتی بین import کردن یک ماژول و اجرای مستقیم آن وجود دارد؟
  • ❓ چرا باید از محیط‌های مجازی استفاده کنیم و چه مشکلاتی را حل می‌کنند؟
  • ❓ اگر یک پکیج را بدون __init__.py ایجاد کنیم، چه اتفاقی می‌افتد؟

⚠️ خطاهای رایج و عیب‌یابی

  • 🔴 اشتباه: فراموش کردن __init__.py در پکیج که باعث می‌شود پایتون آن را به‌عنوان پکیج تشخیص ندهد.
    🔧 راه حل: یک فایل __init__.py (حتی خالی) در دایرکتوری پکیج ایجاد کنید.
  • 🔴 اشتباه: فراموش کردن فعال‌سازی محیط مجازی قبل از نصب پکیج‌ها که باعث می‌شود پکیج‌ها در سیستم نصب شوند.
    🔧 راه حل: قبل از نصب هر پکیج، محیط مجازی را فعال کنید.
  • 🔴 اشتباه: استفاده از from module import * که باعث تداخل نام‌ها می‌شود.
    🔧 راه حل: فقط چیزهایی که نیاز دارید را import کنید یا از نام مستعار استفاده کنید.
  • 🔴 اشتباه: فراموش کردن if __name__ == "__main__" که باعث می‌شود کدهای تست هنگام import اجرا شوند.
    🔧 راه حل: کدهای تست را در داخل if __name__ == "__main__" قرار دهید.
  • 🔴 اشتباه: استفاده از مسیرهای نسبی نامناسب برای import ماژول‌های داخل پکیج.
    🔧 راه حل: از from . import module (import نسبی) یا ساختار مناسب پکیج استفاده کنید.

🏆 پروژه نهایی این فصل

عنوان پروژه: ساخت یک ابزار خط فرمان با ماژول‌ها و پکیج‌ها

شرح: یک ابزار خط فرمان برای مدیریت وظایف (Task Manager) با استفاده از ماژول‌ها و پکیج‌ها بسازید:

  • ساختار پروژه: 
    task_manager/
├── __init__.py
├── main.py
├── tasks/
│   ├── __init__.py
│   ├── models.py
│   └── storage.py
├── utils/
│   ├── __init__.py
│   ├── validators.py
│   └── formatters.py
└── tests/
    ├── __init__.py
    └── test_tasks.py
  • ماژول‌های پروژه:
    • tasks/models.py: کلاس Task با ویژگی‌های title, description, due_date, status.
    • tasks/storage.py: توابع برای ذخیره‌سازی و بارگذاری وظایف در یک فایل JSON.
    • utils/validators.py: توابع اعتبارسنجی (تاریخ، اولویت و ...).
    • utils/formatters.py: توابع برای نمایش زیبای وظایف (با f-strings و جداول).
    • main.py: منوی اصلی با while و استفاده از پکیج‌ها.
  • از if __name__ == "__main__" در همه‌ی ماژول‌ها برای تست استفاده کنید.
  • یک محیط مجازی ایجاد کنید و requirements.txt برای وابستگی‌ها (در صورت نیاز) تهیه کنید.
  • قابلیت‌های برنامه:
    • افزودن وظیفه (با اعتبارسنجی)
    • نمایش همه‌ی وظایف
    • تغییر وضعیت وظیفه (انجام‌شده/انجام‌نشده)
    • حذف وظیفه
    • جستجوی وظایف بر اساس عنوان
    • ذخیره‌سازی خودکار در فایل
  • همه‌ی توابع را با Docstring مستند کنید و از Type Hints استفاده کنید.
  • یک فایل README.md برای پروژه بنویسید.

کد خود را در VS Code بنویسید و با python3 main.py اجرا کنید.
