🚀 مقدمه و انگیزه‌بخشی

آیا تا به حال برنامه‌ای نوشته‌اید که با ورودی غیرمنتظره کاربر، خطا بدهد و از کار بیفتد؟ یا فایلی که وجود ندارد را باز کرده‌اید و برنامه کرش کرده است؟ اینجاست که مدیریت خطاها و استثناها (Exception Handling) وارد می‌شود.

در پایتون، خطاها به دو دسته تقسیم می‌شوند: خطاهای نحوی (Syntax Errors) که قبل از اجرا شناسایی می‌شوند و استثناها (Exceptions) که در زمان اجرا رخ می‌دهند. با مدیریت صحیح استثناها، می‌توانید برنامه‌های مقاوم و حرفه‌ای بنویسید که به‌جای کرش کردن، خطا را مدیریت کنند و پیام مناسب به کاربر نشان دهند.

در این فصل با همه‌ی مباحث مدیریت خطاها آشنا می‌شوید: try/except، else، finally، raise، استثناهای سفارشی و Context Managers با with.

🧠 بدنه اصلی آموزش

۱۲.۱ آشنایی با انواع خطاها و استثناها

در پایتون، خطاها به دو دسته اصلی تقسیم می‌شوند:

  • خطاهای نحوی (Syntax Errors): قبل از اجرا شناسایی می‌شوند.
  • استثناها (Exceptions): در زمان اجرا رخ می‌دهند.

انواع رایج استثناها:

  • ZeroDivisionError – تقسیم بر صفر
  • TypeError – عملیات با نوع داده‌ی نامناسب
  • ValueError – مقدار نامناسب
  • IndexError – اندیس خارج از محدوده
  • KeyError – کلید ناموجود در دیکشنری
  • FileNotFoundError – فایل وجود ندارد
  • AttributeError – ویژگی یا متد وجود ندارد
  • ImportError – ماژول وجود ندارد
# SyntaxError (خطای نحوی)
# print("Hello"  # ❌ پرانتز بسته نشده

# ZeroDivisionError (تقسیم بر صفر)
# print(10 / 0)  # ❌ ZeroDivisionError

# TypeError (نوع داده نامناسب)
# print("10" + 5)  # ❌ TypeError

# ValueError (مقدار نامناسب)
# int("abc")  # ❌ ValueError

# IndexError (اندیس خارج از محدوده)
# [1, 2, 3][5]  # ❌ IndexError

# KeyError (کلید ناموجود)
# {"a": 1}["b"]  # ❌ KeyError
➜ ZeroDivisionError: division by zero
➜ TypeError: can only concatenate str (not "int") to str
➜ ValueError: invalid literal for int() with base 10: 'abc'
💡 نکته: همه‌ی استثناها از کلاس پایه Exception ارث‌بری می‌کنند. این به شما امکان می‌دهد همه‌ی استثناها را با except Exception بگیرید.
🧪 تمرین: کدهایی که باعث ایجاد هر یک از خطاهای بالا می‌شوند را در محیط تعاملی پایتون اجرا کنید و پیام خطا را مشاهده کنید.

۱۲.۲ try/except – مدیریت استثناها

با استفاده از try/except می‌توانید استثناها را بگیرید و مدیریت کنید.

# try/except ساده
try:
    result = 10 / 0
    print(result)
except ZeroDivisionError:
    print("❌ تقسیم بر صفر مجاز نیست!")

# try/except با چند استثنا
try:
    num = int(input("یک عدد وارد کنید: "))
    result = 10 / num
    print(f"نتیجه: {result}")
except ValueError:
    print("❌ لطفاً یک عدد معتبر وارد کنید!")
except ZeroDivisionError:
    print("❌ عدد صفر مجاز نیست!")

# گرفتن چند استثنا با یک except
try:
    data = [1, 2, 3]
    index = int(input("اندیس: "))
    print(data[index])
except (ValueError, IndexError) as e:
    print(f"❌ خطا: {e}")

# گرفتن همه‌ی استثناها
try:
    risky_code()
except Exception as e:
    print(f"❌ یک خطا رخ داد: {e}")
➜ ❌ تقسیم بر صفر مجاز نیست!
💎 نکته طلایی: از except Exception as e برای گرفتن همه‌ی استثناها استفاده کنید، اما بهتر است تا حد امکان استثناهای خاص را بگیرید تا از پنهان شدن خطاهای غیرمنتظره جلوگیری کنید.
🧪 تمرین: یک برنامه بنویسید که از کاربر یک عدد دریافت کند و تقسیم ۱۰۰ بر آن را محاسبه کند. خطاهای ValueError و ZeroDivisionError را مدیریت کنید.

۱۲.۳ else و finally

  • else: زمانی اجرا می‌شود که هیچ استثنایی رخ ندهد.
  • finally: همیشه اجرا می‌شود، چه خطا رخ دهد و چه ندهد.
# else - اجرا در صورت عدم وجود خطا
try:
    num = int(input("عدد: "))
    result = 10 / num
except ValueError:
    print("❌ عدد معتبر وارد کنید!")
except ZeroDivisionError:
    print("❌ صفر مجاز نیست!")
else:
    print(f"✅ نتیجه: {result}")
    print("✅ عملیات با موفقیت انجام شد!")

# finally - همیشه اجرا می‌شود
try:
    file = open("test.txt", "r")
    content = file.read()
except FileNotFoundError:
    print("❌ فایل وجود ندارد!")
finally:
    print("🧹 پاکسازی منابع...")
    # file.close() اگر فایل باز شده باشد
    print("🧹 بستن فایل (اگر باز بود)")

# کاربرد finally برای بستن منابع
def divide_numbers():
    try:
        a = int(input("عدد اول: "))
        b = int(input("عدد دوم: "))
        return a / b
    except ValueError:
        return "خطا: عدد معتبر وارد کنید!"
    except ZeroDivisionError:
        return "خطا: تقسیم بر صفر!"
    finally:
        print("🧹 عملیات پایان یافت (چه خطا داشته باشد و چه نه)")
➜ ✅ نتیجه: 5.0
➜ ✅ عملیات با موفقیت انجام شد!
➜ 🧹 عملیات پایان یافت (چه خطا داشته باشد و چه نه)
💡 نکته: finally برای پاکسازی منابع (بستن فایل‌ها، اتصالات پایگاه داده و ...) بسیار مفید است، حتی اگر خطا رخ دهد.
🧪 تمرین: یک برنامه بنویسید که یک فایل را باز کند، محتوای آن را بخواند و در صورت خطا پیام مناسب نشان دهد. از finally برای بستن فایل استفاده کنید.

۱۲.۴ raise – ایجاد استثنا

با raise می‌توانید استثناها را به‌صورت دستی ایجاد کنید. این کار برای اعتبارسنجی و کنترل جریان برنامه مفید است.

# raise ساده
def divide(a, b):
    if b == 0:
        raise ValueError("مقسوم‌علیه نمی‌تواند صفر باشد!")
    return a / b

try:
    result = divide(10, 0)
except ValueError as e:
    print(f"❌ خطا: {e}")

# raise با شرط
def get_age(age):
    if age < 0:
        raise ValueError("سن نمی‌تواند منفی باشد!")
    if age > 120:
        raise ValueError("سن معتبر نیست (حداکثر ۱۲۰)!")
    return age

try:
    age = get_age(-5)
except ValueError as e:
    print(f"❌ خطا: {e}")

# raise بدون آرگومان (propagate)
def process_data(data):
    try:
        return int(data)
    except ValueError:
        print("خطا در تبدیل داده!")
        raise  # استثنا را به بالا منتقل می‌کند

try:
    process_data("abc")
except ValueError:
    print("❌ خطا در پردازش داده!")

# raise با استثنای سفارشی (در بخش بعدی)
➜ ❌ خطا: مقسوم‌علیه نمی‌تواند صفر باشد!
➜ ❌ خطا: سن نمی‌تواند منفی باشد!
💎 نکته طلایی: از raise برای اعتبارسنجی ورودی‌ها و گزارش خطاهای منطقی استفاده کنید. این کار باعث می‌شود خطاها زودتر شناسایی شوند.
🧪 تمرین: یک تابع validate_email بنویسید که یک ایمیل دریافت کند و اگر معتبر نبود، با raise یک ValueError ایجاد کند.

۱۲.۵ استثناهای سفارشی (Custom Exceptions)

با ایجاد کلاس‌هایی که از Exception ارث‌بری می‌کنند، می‌توانید استثناهای سفارشی تعریف کنید.

# تعریف استثنای سفارشی
class AgeError(Exception):
    """خطای مربوط به سن"""
    pass

class NegativeAgeError(AgeError):
    """سن نمی‌تواند منفی باشد"""
    pass

class TooOldError(AgeError):
    """سن بیش از حد مجاز است"""
    pass

def validate_age(age):
    if age < 0:
        raise NegativeAgeError(f"سن {age} منفی است!")
    if age > 120:
        raise TooOldError(f"سن {age} بیش از حد مجاز است!")
    return age

# استفاده
try:
    age = validate_age(-5)
except NegativeAgeError as e:
    print(f"❌ خطای سن منفی: {e}")
except TooOldError as e:
    print(f"❌ خطای سن زیاد: {e}")
except AgeError as e:
    print(f"❌ خطای سن: {e}")

# استثنای سفارشی با پیام سفارشی
class InsufficientFundsError(Exception):
    def __init__(self, balance, amount):
        self.balance = balance
        self.amount = amount
        super().__init__(f"موجودی ناکافی! موجودی: {balance}, درخواست: {amount}")

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError(balance, amount)
    return balance - amount

try:
    withdraw(100, 150)
except InsufficientFundsError as e:
    print(f"❌ {e}")
➜ ❌ خطای سن منفی: سن -5 منفی است!
➜ ❌ موجودی ناکافی! موجودی: 100, درخواست: 150
💡 نکته: استثناهای سفارشی به شما امکان می‌دهند خطاهای خاص حوزه‌ی کاری خود را به‌صورت دقیق‌تر مدیریت کنید. نام استثناها باید با حرف بزرگ شروع شود و معمولاً با Error ختم می‌شود.
🧪 تمرین: یک استثنای سفارشی InvalidPasswordError تعریف کنید و یک تابع validate_password بنویسید که اگر رمز عبور کمتر از ۸ کاراکتر بود، این استثنا را ایجاد کند.

۱۲.۶ with و Context Managers

with یک روش ایمن و تمیز برای مدیریت منابع (فایل‌ها، اتصالات، قفل‌ها و ...) است. Context Managers به‌طور خودکار منابع را پس از استفاده پاکسازی می‌کنند.

# استفاده از with برای باز کردن فایل
with open("test.txt", "w") as file:
    file.write("Hello World!")

# معادل با try/finally
file = open("test.txt", "w")
try:
    file.write("Hello World!")
finally:
    file.close()

# چندین منبع با with
with open("input.txt", "r") as infile, open("output.txt", "w") as outfile:
    content = infile.read()
    outfile.write(content.upper())

# ایجاد Context Manager سفارشی با __enter__ و __exit__
class FileManager:
    def __init__(self, filename, mode):
        self.filename = filename
        self.mode = mode
        self.file = None
    
    def __enter__(self):
        self.file = open(self.filename, self.mode)
        return self.file
    
    def __exit__(self, exc_type, exc_val, exc_tb):
        if self.file:
            self.file.close()
        return False  # استثنا را propagate می‌کند

# استفاده
with FileManager("test.txt", "r") as f:
    content = f.read()
    print(content)

# استفاده از contextlib برای ایجاد Context Manager ساده
from contextlib import contextmanager

@contextmanager
def open_file(filename, mode):
    f = open(filename, mode)
    try:
        yield f
    finally:
        f.close()

with open_file("test.txt", "r") as f:
    print(f.read())
💎 نکته طلایی: همیشه برای کار با فایل‌ها، اتصالات پایگاه داده و سایر منابع از with استفاده کنید. این کار از نشت منابع (Resource Leak) جلوگیری می‌کند.
🧪 تمرین: یک Context Manager سفارشی برای یک اتصال پایگاه داده شبیه‌سازی‌شده بنویسید که در __enter__ اتصال را باز کند و در __exit__ آن را ببندد.

۱۲.۷ بهترین شیوه‌های مدیریت خطا

  • استثناهای خاص را بگیرید: به‌جای except Exception، استثناهای خاص را بگیرید.
  • از raise برای اعتبارسنجی استفاده کنید: به‌جای return None یا return False.
  • از finally برای پاکسازی منابع استفاده کنید: یا از with استفاده کنید.
  • استثناهای سفارشی معنادار ایجاد کنید: نام‌های واضح و پیام‌های مفید.
  • به‌جای except: خالی، از except Exception as e استفاده کنید.
  • خطاها را لاگ کنید: در برنامه‌های بزرگ، از ماژول logging استفاده کنید.
  • از else برای کدهایی استفاده کنید که فقط در صورت عدم وجود خطا اجرا می‌شوند.
# الگوی خوب
def safe_divide(a, b):
    try:
        result = a / b
    except ZeroDivisionError:
        print("⚠️ تقسیم بر صفر!")
        return None
    except TypeError:
        print("⚠️ نوع داده نامناسب!")
        return None
    else:
        print("✅ عملیات موفق")
        return result
    finally:
        print("🧹 پایان عملیات")

# الگوی بد (اجتناب کنید)
def bad_divide(a, b):
    try:
        return a / b
    except:  # ❌ همه‌ی خطاها را می‌گیرد
        return None
🧪 تمرین: کدهای خود را بازبینی کنید و ببینید آیا از بهترین شیوه‌های مدیریت خطا استفاده می‌کنید یا خیر.

  • 🔹 استثناهای سفارشی با ارث‌بری از Exception تعریف می‌شوند.
  • 🔹 with و Context Managers منابع را به‌طور خودکار مدیریت می‌کنند.
  • 🔹 همیشه استثناهای خاص را بگیرید، نه Exception.
  • 🔹 از raise برای اعتبارسنجی ورودی‌ها استفاده کنید.

برگه تقلب

# try/except
try:
    risky_code()
except ValueError as e:
    print(f"خطا: {e}")
except ZeroDivisionError:
    print("تقسیم بر صفر!")
else:
    print("موفق")
finally:
    print("پایان")

# raise
raise ValueError("پیام خطا")

# استثنای سفارشی
class MyError(Exception):
    pass

# with
with open("file.txt", "r") as f:
    content = f.read()

📖 واژه‌نامه تخصصی

  • Exception (استثنا): خطایی که در زمان اجرا رخ می‌دهد.
  • try: بلوکی که کد خطرناک در آن قرار می‌گیرد.
  • except: بلوکی که استثناها را مدیریت می‌کند.
  • else: بلوکی که در صورت عدم وجود خطا اجرا می‌شود.
  • finally: بلوکی که همیشه اجرا می‌شود.
  • raise: دستور برای ایجاد استثنا.
  • Custom Exception: استثنای تعریف‌شده توسط برنامه‌نویس.
  • Context Manager: شیءی که منابع را با with مدیریت می‌کند.
  • Resource Leak: نشت منابع (عدم بستن فایل، اتصال و ...).

❓ سوالات محرک (برای درگیری ذهن)

  • ❓ چرا باید استثناها را مدیریت کنیم؟ چه اتفاقی می‌افتد اگر مدیریت نکنیم؟
  • ❓ چه تفاوتی بین except: و except Exception as e: وجود دارد؟
  • ❓ چرا finally برای پاکسازی منابع مهم است؟
  • ❓ چه زمانی باید استثنای سفارشی ایجاد کنیم؟
  • ❓ اگر یک Context Manager بنویسیم، چه مزیتی نسبت به try/finally دارد؟

⚠️ خطاهای رایج و عیب‌یابی

  • 🔴 اشتباه: استفاده از except: خالی که همه‌ی خطاها را می‌گیرد و خطاهای واقعی را پنهان می‌کند.
    🔧 راه حل: از except Exception as e: استفاده کنید یا استثناهای خاص را بگیرید.
  • 🔴 اشتباه: فراموش کردن finally برای بستن منابع که باعث نشت حافظه می‌شود.
    🔧 راه حل: از with برای مدیریت خودکار منابع استفاده کنید.
  • 🔴 اشتباه: استفاده از raise بدون استثنا در خارج از except که باعث خطا می‌شود.
    🔧 راه حل: raise بدون آرگومان فقط در داخل except کار می‌کند.
  • 🔴 اشتباه: ایجاد استثنای سفارشی بدون پیام مفید که دیباگ را سخت می‌کند.
    🔧 راه حل: در __init__ پیام‌های مفید بنویسید.
  • 🔴 اشتباه: استفاده از else برای کدهایی که ممکن است خطا داشته باشند.
    🔧 راه حل: else فقط برای کدهایی استفاده شود که خطا ندارند.
