🔰 مقدمه – رایانش ابری چیست؟

رایانش ابری (Cloud Computing) یک مدل محاسباتی است که دسترسی بر اساس تقاضا و از راه دور به منابع محاسباتی قابل تنظیم (شبکه‌ها، سرورها، ذخیره‌سازی، برنامه‌ها و سرویس‌ها) را فراهم می‌کند. این منابع با حداقل تلاش مدیریتی و تعامل با ارائه‌دهنده سرویس، به سرعت قابل تامین و آزادسازی هستند.

رایانش ابری امروزه به بخش جدایی‌ناپذیر زیرساخت‌های فناوری اطلاعات تبدیل شده است. سازمان‌ها از ابر برای کاهش هزینه‌ها، افزایش مقیاس‌پذیری و بهبود دسترس‌پذیری استفاده می‌کنند. با این حال، این تغییر به معنای ظهور چالش‌های امنیتی جدیدی نیز هست که متخصصان امنیت باید با آنها آشنا باشند.

در این ماژول، با مفاهیم پایه رایانش ابری، مدل‌های خدمات و استقرار، معماری ابری، تهدیدات و آسیب‌پذیری‌ها، امنیت پلتفرم‌های اصلی (AWS، Azure، GCP)، مدیریت هویت و دسترسی (IAM)، امنیت کانتینرها و Kubernetes، و ابزارهای تست نفوذ ابری آشنا خواهید شد.

⚠️ هشدار اخلاقی: حملات به محیط‌های ابری بدون مجوز جرم است. تمام تمرینات این ماژول فقط در محیط‌های آزمایشگاهی با مجوز انجام شوند.

📊 مدل‌های خدمات و استقرار ابری

رایانش ابری بر اساس سه مدل خدمات اصلی و چهار مدل استقرار دسته‌بندی می‌شود:

📌 مدل‌های خدمات (Service Models):

  • IaaS (Infrastructure as a Service): ارائه زیرساخت‌های محاسباتی (سرورها، ذخیره‌سازی، شبکه). کاربر کنترل کامل بر سیستمعامل و برنامه‌ها دارد. مثال: AWS EC2، Azure Virtual Machines.
  • PaaS (Platform as a Service): ارائه پلتفرم توسعه و استقرار برنامه‌ها بدون نیاز به مدیریت زیرساخت. مثال: Google App Engine، AWS Elastic Beanstalk.
  • SaaS (Software as a Service): ارائه نرم‌افزارهای آماده از طریق اینترنت. مثال: Google Workspace، Microsoft 365، Salesforce.

📌 مدل‌های استقرار (Deployment Models):

  • ابر عمومی (Public Cloud): منابع توسط ارائه‌دهنده شخص ثالث مدیریت می‌شوند و از طریق اینترنت در دسترس عموم هستند. (AWS، Azure، GCP).
  • ابر خصوصی (Private Cloud): منابع منحصراً برای یک سازمان خاص استفاده می‌شوند و معمولاً در محل (On-Premise) یا در مرکز داده اختصاصی قرار دارند.
  • ابر ترکیبی (Hybrid Cloud): ترکیبی از ابر عمومی و خصوصی که داده‌ها و برنامه‌ها بین آنها به اشتراک گذاشته می‌شوند.
  • ابر اجتماعی (Community Cloud): منابع بین چندین سازمان با اهداف مشترک (مثل سازمان‌های دولتی) به اشتراک گذاشته می‌شود.
💡 نکته: در CEH v13، تمرکز اصلی بر امنیت ابرهای عمومی (AWS، Azure، GCP) است، زیرا رایج‌ترین محیط‌های ابری مورد استفاده سازمان‌ها هستند.

🏗️ معماری ابری (Cloud Architecture)

معماری ابری شامل اجزای مختلفی است که با هم یک محیط ابری کارآمد و مقیاس‌پذیر را تشکیل می‌دهند.

📌 اجزای اصلی معماری ابری:

  • Frontend (سمت کاربر): رابط‌های کاربری و APIهایی که کاربران برای تعامل با ابر استفاده می‌کنند.
  • Backend (سمت سرور): منابع محاسباتی، ذخیره‌سازی، شبکه و نرم‌افزارهای مدیریت ابر.
  • شبکه (Network): زیرساخت ارتباطی که Frontend و Backend را به هم متصل می‌کند.
  • ذخیره‌سازی (Storage): ذخیره‌سازی داده‌ها به صورت ساختاریافته (پایگاه‌های داده) و غیرساختاریافته (فایل‌ها، اشیاء).
  • مجازی‌سازی (Virtualization): فناوری که منابع فیزیکی را به منابع مجازی تبدیل می‌کند.
  • مدیریت (Management): ابزارهای نظارت، مقیاس‌پذیری و مدیریت منابع.
💡 نکته: درک معماری ابری برای شناسایی نقاط ضعف و حملات مؤثر ضروری است.

🎯 تهدیدات و آسیب‌پذیری‌های ابری

محیط‌های ابری با تهدیدات و آسیب‌پذیری‌های خاصی مواجه هستند که در ادامه به مهم‌ترین آنها اشاره می‌کنیم:

📌 تهدیدات اصلی امنیت ابری (بر اساس CSA Top Threats 2024):

  • پیکربندی اشتباه (Misconfiguration): شایع‌ترین علت نقض امنیت در ابر.
  • کنترل دسترسی ناکافی (Insufficient Access Controls): مدیریت ضعیف IAM.
  • آسیب‌پذیری‌های APIها: APIهای ابری که به درستی امن نشده‌اند.
  • دزدیده شدن اعتبارنامه‌ها (Credential Theft): سرقت کلیدهای API و رمزهای عبور.
  • تهدیدات داخلی (Insider Threats): کارمندان یا پیمانکاران با دسترسی سوءاستفاده‌کننده.
  • حملات انکار سرویس (DoS/DDoS): هدف قرار دادن در دسترس بودن سرویس‌های ابری.
  • نشت داده (Data Breaches): دسترسی غیرمجاز به داده‌های ذخیره‌شده در ابر.
  • کمبود دید و نظارت (Visibility & Monitoring Gaps): عدم توانایی در مشاهده کامل محیط ابری.
  • وابستگی به ارائه‌دهنده (Vendor Lock-in): مشکلات مهاجرت و امنیت بین سرویس‌ها.
  • حملات به کانتینرها و Kubernetes: هدف قرار دادن برنامه‌های کانتینری.
⚠️ هشدار: پیکربندی اشتباه در ابر (مانند باز بودن Bucketها) یکی از اصلی‌ترین دلایل نشت داده در سال‌های اخیر بوده است.

☁️ امنیت AWS (Amazon Web Services)

AWS بزرگترین ارائه‌دهنده خدمات ابری در جهان است و امنیت آن یکی از مهم‌ترین مباحث در هک قانونمند محسوب می‌شود.

📌 اجزای کلیدی امنیت AWS:

  • IAM (Identity and Access Management): مدیریت کاربران، گروه‌ها و دسترسی‌ها.
  • S3 (Simple Storage Service): ذخیره‌سازی اشیاء که به دلیل پیکربندی اشتباه، یکی از منابع اصلی نشت داده است.
  • EC2 (Elastic Compute Cloud): ماشین‌های مجازی که نیاز به مدیریت امنیتی دقیق دارند.
  • VPC (Virtual Private Cloud): شبکه مجازی ایزوله برای منابع AWS.
  • CloudTrail: ثبت و مانیتورینگ فعالیت‌های API.
  • GuardDuty: تشخیص تهدیدات مبتنی بر یادگیری ماشین.
  • Inspector: اسکن خودکار آسیب‌پذیری.
# نصب و پیکربندی AWS CLI
aws configure

# لیست کردن Bucketهای S3 (تست دسترسی)
aws s3 ls

# بررسی تنظیمات امنیتی IAM
aws iam list-users
aws iam list-groups
💡 نکته: S3 Bucketهای عمومی یکی از رایج‌ترین آسیب‌پذیری‌های AWS هستند. همیشه سطح دسترسی Bucketها را بررسی کنید.

☁️ امنیت Azure (Microsoft Azure)

Azure دومین ارائه‌دهنده بزرگ خدمات ابری است که به دلیل یکپارچگی با محصولات مایکروسافت، بسیار محبوب است.

📌 اجزای کلیدی امنیت Azure:

  • Azure AD (Active Directory): مدیریت هویت و دسترسی.
  • Azure Key Vault: ذخیره‌سازی امن کلیدها و رمزها.
  • Azure Security Center: مدیریت یکپارچه امنیت و نظارت.
  • Azure Sentinel: سیستم SIEM ابری.
  • Azure VNet: شبکه‌های مجازی.
  • Azure Blob Storage: ذخیره‌سازی اشیاء (مشابه S3).
# نصب Azure CLI
az login

# لیست کردن منابع
az resource list

# بررسی دسترسی‌ها
az role assignment list
💡 نکته: Azure AD یکی از مهم‌ترین اهداف حملات در محیط‌های Azure است. مدیریت صحیح نقش‌ها و دسترسی‌ها بسیار حیاتی است.

☁️ امنیت GCP (Google Cloud Platform)

GCP سومین ارائه‌دهنده بزرگ خدمات ابری است که به دلیل قدرت در داده‌های بزرگ و یادگیری ماشین شناخته می‌شود.

📌 اجزای کلیدی امنیت GCP:

  • IAM: مدیریت هویت و دسترسی.
  • Cloud Storage: ذخیره‌سازی اشیاء (مشابه S3).
  • Compute Engine: ماشین‌های مجازی.
  • Cloud Armor: محافظت در برابر DDoS و WAF.
  • Security Command Center: مدیریت امنیت و کشف آسیب‌پذیری.
  • VPC Service Controls: جداسازی سرویس‌ها.
# نصب gcloud CLI
gcloud init

# لیست کردن پروژه‌ها
gcloud projects list

# بررسی دسترسی‌ها
gcloud projects get-iam-policy PROJECT_ID
💡 نکته: GCP از Cloud IAM برای مدیریت دسترسی استفاده می‌کند. اصول کمترین دسترسی (Least Privilege) باید به دقت رعایت شود.

🔑 مدیریت هویت و دسترسی (IAM)

IAM (Identity and Access Management) یکی از حیاتی‌ترین اجزای امنیت ابری است که تعیین می‌کند چه کسی (Who) به چه چیزی (What) و چگونه (How) دسترسی دارد.

📌 مفاهیم اصلی IAM:

  • User (کاربر): یک هویت منحصربه‌فرد (معمولاً یک شخص).
  • Group (گروه): مجموعه‌ای از کاربران با مجوزهای مشترک.
  • Role (نقش): مجموعه‌ای از مجوزها که می‌تواند به کاربران یا سرویس‌ها اختصاص داده شود.
  • Policy (سیاست): مجموعه قوانینی که دسترسی را مشخص می‌کند.
  • Permission (مجوز): اجازه انجام یک عمل خاص روی یک منبع خاص.

📌 اصول کلیدی IAM:

  • Least Privilege (کمترین دسترسی): فقط دسترسی‌های لازم برای انجام وظایف را اعطا کنید.
  • Separation of Duties (جدایی وظایف): هیچ کاربری نباید تمام مجوزهای یک فرآیند حساس را داشته باشد.
  • MFA (Multi-Factor Authentication): برای کاربران با دسترسی بالا الزامی است.
  • بررسی منظم دسترسی‌ها: به‌طور دوره‌ای مجوزهای کاربران را بررسی و اصلاح کنید.
# AWS IAM: ایجاد یک کاربر جدید
aws iam create-user --user-name newuser

# AWS IAM: متصل کردن یک سیاست به کاربر
aws iam attach-user-policy --user-name newuser --policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess

# Azure: ایجاد یک نقش
az role assignment create --assignee user@domain.com --role Contributor
⚠️ هشدار: یکی از بزرگترین ریسک‌های امنیتی، اعطای دسترسی‌های بیش از حد به کاربران است. همیشه از اصل کمترین دسترسی پیروی کنید.

🐳 امنیت کانتینرها و Kubernetes

کانتینرها (مانند Docker) و Kubernetes به عنوان استانداردهای استقرار برنامه‌های مدرن، نیازمند توجه ویژه به امنیت هستند.

📌 آسیب‌پذیری‌های رایج کانتینرها:

  • تصاویر ناامن (Insecure Images): استفاده از تصاویر پایه با آسیب‌پذیری‌های شناخته‌شده.
  • رمزهای پیش‌فرض: وجود رمزهای پیش‌فرض در تصاویر.
  • دسترسی root: اجرای کانتینر با دسترسی root.
  • متغیرهای محیطی حساس: ذخیره کلیدهای API در متغیرهای محیطی.

📌 آسیب‌پذیری‌های رایج Kubernetes:

  • پیکربندی ضعیف RBAC: مدیریت نادرست نقش‌ها و دسترسی‌ها.
  • API Server بدون احراز هویت: دسترسی عمومی به API Server.
  • ثبت‌های (Secrets) ضعیف: ذخیره‌سازی ناامن اطلاعات حساس.
  • پهنه‌های شبکه (Network Policies): عدم محدودیت در ارتباطات بین Podها.
# اسکن تصاویر Docker با Trivy
trivy image myapp:latest

# بررسی تنظیمات امنیتی Kubernetes با kube-hunter
kube-hunter --pod

# بررسی دسترسی‌ها در Kubernetes
kubectl auth can-i list pods --as=system:serviceaccount:default:myuser
💡 نکته: استفاده از ابزارهایی مانند Trivy، Clair و Aqua Security برای اسکن آسیب‌پذیری تصاویر کانتینری ضروری است.

💾 امنیت ذخیره‌سازی ابری (Cloud Storage Security)

ذخیره‌سازی ابری (S3، Blob Storage، Cloud Storage) یکی از پرکاربردترین سرویس‌های ابری است که به دلیل سادگی، اغلب پیکربندی اشتباه دارد.

📌 تهدیدات مرتبط با ذخیره‌سازی ابری:

  • دسترسی عمومی (Public Access): باز بودن Bucketها به روی عموم.
  • فایل‌های حساس غیررمزنگاری‌شده: ذخیره داده‌های حساس بدون رمزنگاری.
  • مدیریت ضعیف کلید: کلیدهای دسترسی به سرقت رفته.
  • نسخه‌سازی غیرفعال: عدم امکان بازیابی فایل‌های حذف‌شده.
  • گزارش‌دهی ضعیف: عدم مانیتورینگ دسترسی‌ها.
# AWS S3: بررسی سطح دسترسی یک Bucket
aws s3api get-bucket-acl --bucket my-bucket

# AWS S3: فعال‌سازی رمزنگاری
aws s3api put-bucket-encryption --bucket my-bucket --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'

# Azure: بررسی دسترسی Blob Storage
az storage container show --name mycontainer --account-name myaccount
⚠️ هشدار: باز بودن غیرعمدی Bucketهای ذخیره‌سازی یکی از بزرگترین علل نشت داده در سال‌های اخیر بوده است. همیشه تنظیمات دسترسی را بررسی کنید.

⚡ حملات به محیط‌های ابری

حملات به محیط‌های ابری شامل مجموعه‌ای از تکنیک‌ها برای نفوذ، سرقت داده و ایجاد اختلال در سرویس‌های ابری است.

📌 حملات رایج ابری:

  • حملات به S3/Blob Storage: جستجوی Bucketهای عمومی و استخراج داده.
  • جعل هویت IAM: سرقت کلیدهای API و دسترسی به منابع.
  • حملات به EC2/VM: اسکن آسیب‌پذیری و نفوذ به ماشین‌های مجازی.
  • حملات DoS/DDoS: هدف قرار دادن سرویس‌های ابری.
  • حملات به Kubernetes: نفوذ به خوشه‌های Kubernetes.
  • حملات Supply Chain: آلوده کردن تصاویر کانتینری.
  • SSRF (Server-Side Request Forgery): دسترسی به متادیتای ابری (AWS Metadata API).
# حمله به AWS Metadata API (SSRF)
curl http://169.254.169.254/latest/meta-data/iam/security-credentials/admin

# جستجوی Bucketهای عمومی با AWS CLI
aws s3 ls s3:// --recursive | grep "public"

# اسکن آسیب‌پذیری EC2 با Nmap
nmap -sV -p 22,80,443 192.168.1.101
💡 نکته: حملات به Metadata API یکی از رایج‌ترین روش‌های به دست آوردن اعتبارنامه‌های IAM در AWS است.

🛠️ ابزارهای تست نفوذ ابری

ابزارهای متعددی برای تست نفوذ و ارزیابی امنیت محیط‌های ابری وجود دارند که در این بخش مهم‌ترین آنها را معرفی می‌کنیم:

ابزارپلتفرمکاربرد اصلی
Pacu AWS چارچوب تست نفوذ AWS
ScoutSuite AWS, Azure, GCP ارزیابی امنیت چندپلتفرمی
CloudBrute AWS, Azure, GCP, DigitalOcean جستجوی ذخیره‌سازی‌های عمومی
Stormspotter Azure نقشه‌برداری و تحلیل امنیتی Azure
Cartography AWS, Azure, GCP نقشه‌برداری زیرساخت ابری
CloudSploit AWS, Azure, GCP اسکن خودکار پیکربندی امنیتی
kube-hunter Kubernetes اسکن امنیتی Kubernetes
Trivy کانتینرها اسکن آسیب‌پذیری تصاویر
CloudMapper AWS نقشه‌برداری و تحلیل امنیتی AWS 
# استفاده از Pacu برای تست AWS
git clone https://github.com/RhinoSecurityLabs/pacu.git
cd pacu
python3 pacu.py
# سپس کلیدهای AWS را وارد کنید

# استفاده از ScoutSuite
scout --help

# استفاده از CloudBrute برای جستجوی Bucketهای عمومی
cloudbrute -d company.com -k aws
💡 نکته: Pacu یکی از قدرتمندترین ابزارهای تست نفوذ اختصاصی AWS است که توسط Rhino Security Labs توسعه یافته است.

CEH v13 به عنوان اولین نسخه‌ای که هوش مصنوعی را در تمام مراحل هک قانونمند ادغام کرده، به نقش هوش مصنوعی در امنیت ابری نیز می‌پردازد.

📌 نقش هوش مصنوعی در امنیت ابری:

  • تشخیص خودکار پیکربندی اشتباه: AI می‌تواند تنظیمات ناامن را در محیط‌های ابری شناسایی کند.
  • شناسایی فعالیت‌های غیرعادی: AI می‌تواند رفتارهای مشکوک در IAM و APIها را تشخیص دهد.
  • پیش‌بینی حملات: AI می‌تواند حملات به سرویس‌های ابری را پیش‌بینی کند.
  • اتوماسیون پاسخ به حوادث: AI می‌تواند به‌صورت خودکار به تهدیدات پاسخ دهد.
  • تحلیل تصاویر کانتینری: AI می‌تواند آسیب‌پذیری‌های تصاویر را شناسایی کند.

📌 ابزارهای AI-Powered Cloud Security:

  • AWS GuardDuty: تشخیص تهدیدات مبتنی بر یادگیری ماشین.
  • Azure Security Center: با قابلیت‌های AI برای تشخیص تهدیدات.
  • Google Cloud Security Command Center: با قابلیت تحلیل هوشمند.
  • Lacework: پلتفرم امنیت ابری مبتنی بر AI.
💡 چرا هوش مصنوعی در امنیت ابری مهم است؟

هوش مصنوعی می‌تواند حجم عظیم داده‌های ابری را تحلیل کرده و حملات پیچیده را سریع‌تر از روش‌های سنتی شناسایی کند.

🛡️ راه‌های مقابله با حملات ابری

برای محافظت از محیط‌های ابری در برابر حملات، سازمان‌ها باید اقدامات زیر را انجام دهند:

📌 اقدامات کلی:

  • مدیریت صحیح IAM: استفاده از اصل کمترین دسترسی، فعال‌سازی MFA.
  • رمزنگاری داده‌ها: رمزنگاری داده‌ها در حالت ذخیره‌سازی و انتقال.
  • پیکربندی امن: بررسی منظم تنظیمات امنیتی با ابزارهایی مانند ScoutSuite.
  • مونیتورینگ و لاگ‌گیری: فعال‌سازی CloudTrail، Azure Monitor، و Stackdriver Logging.
  • استفاده از WAF و فایروال: محافظت از برنامه‌ها و APIها.
  • به‌روزرسانی تصاویر کانتینری: اسکن و به‌روزرسانی منظم تصاویر.
  • آموزش کارکنان: آگاهی‌بخشی درباره امنیت ابری.

📌 اقدامات خاص برای هر پلتفرم:

  • AWS: استفاده از AWS Config، AWS Shield، Amazon Inspector.
  • Azure: استفاده از Azure Policy، Azure Firewall، Azure DDoS Protection.
  • GCP: استفاده از Cloud Armor، Security Command Center، VPC Service Controls.
  • Kubernetes: استفاده از Network Policies، Pod Security Policies، RBAC صحیح.
💡 نکته: بهترین دفاع در برابر حملات ابری، ترکیبی از پیکربندی صحیح، مونیتورینگ مداوم و استفاده از ابزارهای خودکار است.

🧪 کارگاه عملی – تست نفوذ ابری

در این کارگاه، شما با ابزارهای تست نفوذ ابری آشنا خواهید شد و یک سناریوی کامل از ارزیابی امنیت یک محیط ابری را پیاده‌سازی می‌کنید.

🎯 هدف کارگاه:

  • آشنایی با ابزارهای Pacu و ScoutSuite.
  • شناسایی پیکربندی‌های اشتباه در محیط AWS.
  • اجرای حمله به Metadata API.
  • اسکن آسیب‌پذیری کانتینرها.
  • مقابله با آسیب‌پذیری‌های شناسایی‌شده.

🖥️ محیط مورد نیاز:

  • حمله‌کننده: Kali Linux
  • هدف: یک محیط AWS آزمایشگاهی (با مجوز) یا یک شبیه‌ساز محلی (مانند LocalStack).
  • ابزارها: AWS CLI, Pacu, ScoutSuite, Trivy, Nmap

📝 سناریوی گام‌به‌گام:

مرحله ۱: نصب و پیکربندی ابزارها

# نصب AWS CLI
sudo apt install awscli

# نصب Pacu
git clone https://github.com/RhinoSecurityLabs/pacu.git
cd pacu
pip3 install -r requirements.txt

# نصب ScoutSuite
pip3 install scoutsuite

# نصب Trivy
sudo apt install trivy

مرحله ۲: اسکن با ScoutSuite

# اسکن کامل AWS
scout aws --report-dir ./reports

مرحله ۳: تست با Pacu

# اجرای Pacu
python3 pacu.py
# وارد کردن کلیدهای AWS
# اجرای ماژول‌ها برای کشف آسیب‌پذیری‌ها

مرحله ۴: جستجوی دسترسی‌های عمومی

# جستجوی S3 Bucketهای عمومی
aws s3 ls s3:// --recursive | grep "public"

# با CloudBrute
cloudbrute -d example.com -k aws

مرحله ۵: اسکن کانتینرها با Trivy

# اسکن یک تصویر Docker
trivy image nginx:latest
⏳ تکلیف: تمام مراحل بالا را در محیط آزمایشگاهی خود (با مجوز) اجرا کنید و یک گزارش کامل از فرآیند تست نفوذ ابری، یافته‌ها و راهکارهای رفع تهیه کنید.

📝 تمرین‌های عملی

این تمرینات به شما کمک می‌کنند تا مهارت‌های خود در زمینه امنیت ابری را تقویت کنید.

  • تمرین ۱ – ScoutSuite:
    با استفاده از ScoutSuite، یک محیط AWS آزمایشگاهی را اسکن کنید و پیکربندی‌های اشتباه را شناسایی کنید.
  • تمرین ۲ – Pacu:
    با استفاده از Pacu، ماژول‌های مختلف را روی یک محیط AWS آزمایشگاهی اجرا کنید و نتایج را تحلیل کنید.
  • تمرین ۳ – Metadata API:
    روی یک EC2 آزمایشگاهی، دسترسی به Metadata API را شبیه‌سازی کنید و اعتبارنامه‌های IAM را استخراج کنید.
  • تمرین ۴ – امنیت کانتینرها:
    یک تصویر Docker (مثل nginx) را با Trivy اسکن کنید و آسیب‌پذیری‌های آن را شناسایی کنید.
  • تمرین ۵ – ارائه راهکارهای امنیتی:
    برای یک سازمان با محیط AWS، یک برنامه امنیتی جامع (شامل IAM، رمزنگاری، مونیتورینگ، WAF) تهیه کنید.

📖 واژه‌نامه تخصصی (Glossary)

در این بخش، تمام واژه‌های تخصصی این ماژول، همراه با ساختار (ریشه یا مخفف)، تعریف ساده، کاربرد در هک، و یک مثال روزمره توضیح داده شده است.

واژه ساختار / مخفف تعریف ساده کاربرد در هک مثال
IaaS Infrastructure as a Service زیرساخت به عنوان سرویس هدف حملات به سرورها و شبکه AWS EC2, Azure VMs
PaaS Platform as a Service پلتفرم به عنوان سرویس هدف حملات به برنامه‌ها Google App Engine
SaaS Software as a Service نرم‌افزار به عنوان سرویس هدف حملات فیشینگ و سرقت داده Google Workspace, Office 365
IAM Identity and Access Management مدیریت هویت و دسترسی مدیریت مجوزها و دسترسی‌ها AWS IAM, Azure AD
S3 Simple Storage Service سرویس ذخیره‌سازی AWS دسترسی به Bucketهای عمومی aws s3 ls
EC2 Elastic Compute Cloud ماشین‌های مجازی AWS اسکن آسیب‌پذیری VMها nmap EC2_IP
Container — کانتینر (مثل Docker) اسکن آسیب‌پذیری تصاویر Docker, Trivy
Kubernetes K8s سیستم ارکستراسیون کانتینر نفوذ به خوشه‌ها kubectl, kube-hunter
Pacu — چارچوب تست نفوذ AWS ارزیابی امنیت AWS python3 pacu.py
ScoutSuite — ابزار ارزیابی امنیت چندپلتفرمی اسکن پیکربندی ابری scout aws
Metadata API — API متادیتای AWS استخراج اعتبارنامه‌های IAM curl 169.254.169.254
Serverless — محاسبات بدون سرور حملات به توابع Lambda AWS Lambda, Azure Functions

💡 جمع‌بندی ماژول ۱۹:

در این ماژول با یکی از مهم‌ترین حوزه‌های امنیت سایبری مدرن، یعنی امنیت رایانش ابری آشنا شدید:

  • مفاهیم پایه: IaaS, PaaS, SaaS و مدل‌های استقرار.
  • معماری ابری: اجزا و نحوه عملکرد محیط‌های ابری.
  • تهدیدات ابری: پیکربندی اشتباه، IAM ضعیف، حملات DDoS و …

  • IAM: مدیریت هویت و دسترسی با اصل کمترین دسترسی.
  • امنیت کانتینرها و Kubernetes: آسیب‌پذیری‌ها و ابزارهای اسکن.
  • حملات ابری: SSRF, S3 Public Access, Metadata API.
  • ابزارهای تست نفوذ: Pacu, ScoutSuite, CloudBrute, Trivy.
  • نقش هوش مصنوعی: تشخیص تهدیدات و اتوماسیون امنیتی.
  • راه‌های مقابله: پیکربندی صحیح، مونیتورینگ، به‌روزرسانی.
