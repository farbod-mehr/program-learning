🎯 اهداف کلان این فصل:
  1. درک تفاوت انواع شبکه در VMware (NAT، Bridged، Host-Only) و انتخاب صحیح برای هر سناریو.

  • Django روی Windows هدف اجرا می‌شود و از Kali با مرورگر قابل دسترسی است.
  • DVWA در Ubuntu/Kali به‌عنوان هدف اضافه راه‌اندازی شده.
  • حداقل ۳ Snapshot از حالت‌های مختلف (clean-install، tools-installed، dvwa-ready) گرفته‌اید.

  • ابزارهای پایه (Nmap، Burp، sqlmap، Wireshark) روی Kali نصب و تست شده‌اند.
⚠️ هشدار اخلاقی (تکرار می‌کنیم چون حیاتی است): این آزمایشگاه فقط و فقط برای تمرین قانونی طراحی شده است. هیچ‌گاه VM هدف را به اینترنت یا شبکه سازمانی وصل نکنید — حتی لحظه‌ای. اگر می‌خواهید درک کنید چرا: آسیب‌پذیری‌های DVWA (مثل Command Injection) به‌صورت خودکار روی هر سروری که به آن متصل شود، اجرا می‌شود و می‌تواند فاجعه بیافریند.

۴. مقدمه: چرا آزمایشگاه ایزوله؟

📖 یک داستان واقعی که در بسیاری از کلاس‌ها اتفاق افتاده:

دانشجویی مشتاق، پس از یادگیری SQL Injection، تصمیم گرفت «کمی آزمایش» کند. او یک VM با Damn Vulnerable Web Application (DVWA) نصب کرد و بدون ایزوله‌سازی، آن را روی حالت Bridged اجرا کرد. پس از چند دقیقه، یک ربات اسکنر اینترنتی که به‌طور مداوم کل فضای IP را اسکن می‌کند، آن را کشف کرد و از آسیب‌پذیری Command Injection برای اجرای یک Crypto Miner استفاده کرد. در عرض ۴۸ ساعت:

  • دانشجو پیام اخطار از ISP گرفت (استفاده ۹۸٪ CPU)
  • بخش اداری دانشگاه پیگیر «ترافیک شبکه مشکوک» شد
  • حساب کاربری‌اش در شبکه دانشگاه مسدود شد
  • و بدتر: تمام اطلاعات دانشجویان دیگر روی شبکه دانشگاه در معرض خطر قرار گرفت

درس: آزمایشگاه امنیت، ایزوله بودن را از قبل می‌طلبد، نه بعد از فاجعه. این فصل، دقیقاً همان «قبل از فاجعه» است.

🎯 سه دلیل بنیادی برای ایزوله‌سازی:
🔒 دلیل ۱: ایمنی حقوقی

اگر DVWA روی شبکه واقعی شما آسیب‌پذیر باشد و کسی از آن سواستفاده کند، شما مسئول قانونی هستید — نه مهاجم. ایزوله‌سازی، شما را از این مسئولیت محافظت می‌کند.

🛡️ دلیل ۲: ایمنی فنی

جدایی کامل از اینترنت یعنی هیچ رباتی نمی‌تواند به VM هدف شما برسد. حتی اگر آسیب‌پذیری خطرناکی مثل RCE را فعال کنید، مهاجم راهی به آن ندارد.

📚 دلیل ۳: تمرکز آموزشی

در شبکه ایزوله، می‌توانید آزادانه آزمایش کنید، خراب کنید، بازسازی کنید. هیچ ترسی از خرابی ندارید و همین آزادی، سرعت یادگیری را چند برابر می‌کند.

📜 تاریخچه کوتاه — چطور به «آزمایشگاه ایزوله» رسیدیم؟
  • ۲۰۰۵ — VMware Workstation 5.5 قابلیت Snapshot را فراگیر کرد.
  • ۲۰۱۰ — Metasploitable 1 به‌عنوان اولین هدف آموزشی استاندارد منتشر شد.
  • ۲۰۱۴ — DVWA نسخه ۱.۹ با درجه‌بندی سطح امنیت (Low/Medium/High).
  • ۲۰۱۷ — VirtualBox رایگان به رقیب جدی VMware تبدیل شد.
  • ۲۰۲۰ — عصر WSL2 و Docker در ویندوز: آزمایشگاه‌های سبک.
  • ۲۰۲۳+ — Kali Linux Purple و Metasploitable3 برای تمرین دفاع و حمله.

۱ نصب VMware Workstation

  1. از سایت رسمی vmware.com/products/workstation-pro نسخه Pro را دانلود کنید (از ۲۰۲۴ برای استفاده شخصی رایگان شده).
  2. نصب‌کننده را اجرا کنید و مسیر پیش‌فرض را بپذیرید.
  3. در پایان، لایسنس Personal Use را انتخاب کنید.
  4. بررسی کنید: Help → About نسخه ۱۷.۵ به بالا را نشان دهد.
  5. در BIOS، VT-x/AMD-V فعال باشد. تست: در Windows با Task Manager → Performance → CPU، در گوشه پایین باید Virtualization: Enabled دیده شود.

۲ ساخت شبکه Host-Only (VMnet1)

این مرحله مهم‌ترین مرحله ایزوله‌سازی است. دقیقاً دنبال کنید:

  1. VMware Workstation را باز کنید.
  2. منوی Edit → Virtual Network Editor.
  3. روی Change Settings (پایین) کلیک کنید و تأیید Administrator بدهید.
  4. روی Add Network کلیک کنید و VMnet1 را انتخاب کنید.
  5. در بخش تنظیمات VMnet1، این موارد را اعمال کنید:
    • Type: Host-Only
    • Subnet IP: 192.168.56.0
    • Subnet Mask: 255.255.255.0
    • ✅ Connect a host virtual adapter to this network
    • ❌ Use local DHCP service — تیک را بردارید
    • ❌ Connect a host virtual adapter to this network — اگر ناخواسته اینترنت میزبان را به VM می‌دهد، تیکش را بردارید.
  6. روی Apply و OK بزنید.
💡 چرا DHCP را خاموش می‌کنیم؟ چون IPهای ثابت (Static) می‌خواهیم. با IP ثابت:
  • دستورهای nmap/sqlmap همیشه کار می‌کنند
  • لینک‌های کالی به Django همیشه یکسان است
  • اسکریپت‌ها و گزارش‌های شما قابل تکرار می‌شوند

مرحله ۳.۳ — تنظیم IP استاتیک روی Kali:

پس از ورود به Kali، یک ترمینال باز کنید و دستورات زیر را اجرا کنید:

# ۱) پیدا کردن نام اینترفیس شبکه

# انتظار می‌رود خروجی مثل: eth0 یا ens33 یا ens160 باشد
# فرض: eth0

# ۲) تنظیم IP استاتیک (موقت — برای تست سریع)
sudo ip addr add 192.168.56.10/24 dev eth0
sudo ip link set eth0 up

# ۳) بررسی
ip addr show eth0
# باید ببینید: inet 192.168.56.10/24

# ۴) تنظیم دائمی با nmcli (روش مدرن — پیشنهادی)
sudo nmcli con add type ethernet \
    con-name "kali-lab" ifname eth0 \
    ipv4.method manual \
    ipv4.addresses 192.168.56.10/24 \
    ipv4.gateway "" \
    ipv4.dns ""

# ۵) فعال کردن اتصال
sudo nmcli con up kali-lab

# ۶) تست نهایی
ip addr show eth0
# باید IP 192.168.56.10 را نشان دهد

🔐 مباحث دفاعی که در این فصل یاد می‌گیرید:
🔹 لایه ۱: Host-Only Network — جدایی از اینترنت

نمایش دقیق: تفاوت Subnet شما با شبکه واقعی:

شبکه واقعی شما:  192.168.1.x  (روتر خانگی، اینترنت)
شبکه آزمایشگاه:  192.168.56.x (فقط میزبان، بدون اینترنت)

اگر مهاجمی از بیرون بخواهد به VM هدف شما برسد:
- باید از روتر خانگی شما عبور کند (که IP خصوصی است و پورت‌فوروارد ندارد)
- باید Subnet 192.168.56.0/24 را کشف کند (که فقط در حافظه میزبان شماست)
- باید به VMnet1 برسد (که VMware فقط برای میزبان ایجاد کرده)

نتیجه: عملاً غیرممکن.
🔹 لایه ۲: Snapshot — جدایی زمانی
قبل از هر آزمایش:
  [VM] ──── Snapshot ────► [نسخه مهرشده]

حین آزمایش:
  [VM] ──── آلوده شد ────► ⚠️ به نسخه مهرشده دست نمی‌زند

بعد از آزمایش:
  [VM] ── Revert ──► [نسخه مهرشده، سالم و تمیز]

مزیت: همیشه می‌توانید به «قبل از آزمایش» برگردید — در ثانیه‌ها، نه ساعت‌ها.
🔹 لایه ۳: Firewall میزبان — جدایی از سیستم‌عامل
# در Windows Firewall (میزبان):
# هدف: جلوگیری از دسترسی VM هدف به فایل‌های میزبان

# ۱) در Windows Defender Firewall → Advanced Settings
# ۲) روی Outbound Rules → New Rule
# ۳) Rule Type: Port → TCP → Local port: 445 (SMB)
# ۴) Action: Block the connection
# ۵) Profile: Domain + Private + Public
# ۶) Name: Block VM-SMB-outbound

# این کار جلوی یکی از رایج‌ترین سناریوها را می‌گیرد:
# اگر VM آلوده به باج‌گیر شود، نمی‌تواند فایل‌های میزبان را رمزنگاری کند.
💡 قاعده «۳ چک قبل از هر Session»: قبل از اینکه هر تست نفوذی را شروع کنید، همیشه این سه چک را انجام دهید:
  1. چک شبکه: VM هدف روی Host-Only است؟
  2. چک Snapshot: Snapshot تازه دارید؟
  3. چک هدف: مطمئن هستید که VM هدف درست است (نه یک VM دیگر)؟
این ۳۰ ثانیه چک، شما را از فاجعه‌های چندساعته نجات می‌دهد.

۱۰. پرسش و پاسخ و رفع اشکال

❓ سوالات متداول این فصل:
آیا می‌توانم از VirtualBox به‌جای VMware استفاده کنم؟

بله، کاملاً. VirtualBox رایگان است و بیشتر قابلیت‌های موردنیاز ما را دارد. تفاوت‌ها: VMware کمی سریع‌تر و پایدارتر است، VirtualBox کمی سبک‌تر و رایگان‌تر. مفاهیم شبکه در VirtualBox متفاوت است: به‌جای VMnet1، از Host-Only Adapter استفاده می‌کنید. IP را در File → Host Network Manager تنظیم می‌کنید.

RAM من فقط ۸GB است. می‌توانم این دوره را ادامه دهم؟

بله، با تنظیمات زیر:
• Kali: 2GB RAM به‌جای 4GB
• Windows: 3GB RAM به‌جای 6GB (کمی کند ولی کار می‌کند)
• میزبان: 3GB برای ویندوز/لینوکس
یا از Kali در WSL2 استفاده کنید (نیاز به RAM کمتری دارد).

چرا VM هدف به اینترنت وصل نمی‌شود؟

این ویژگی است، نه باگ. Host-Only به‌طور عمد اینترنت را قطع می‌کند تا VM ایزوله بماند. اگر واقعاً برای نصب پکیج نیاز دارید:
۱) موقتاً VM را به NAT تغییر دهید
۲) آپدیت‌ها را انجام دهید
۳) بلافاصله به VMnet1 برگردانید
۴) Snapshot جدید بگیرید
هرگز VM را روی Bridged نگه ندارید، حتی برای لحظه!

IP استاتیک کار نمی‌کند، پینگ نمی‌شود

چک‌لیست سه‌مرحله‌ای:
۱) در VMware: هر دو VM روی VMnet1 هستند؟
۲) در terminal: ip addr show روی Kali، ipconfig روی Windows — IPها درست هستند؟
۳) در Kali: sudo iptables -L — هیچ rule مسدودکننده‌ای نیست؟
۴) در Windows: Get-NetFirewallProfile — فایروال روی Block نیست؟
اگر همه درست است ولی هنوز کار نمی‌کند: VMware را ری‌استارت کنید (نه فقط VM، خود VMware).

آیا می‌توانم Kali و هدف را روی یک VM داشته باشم؟

بله — از Docker استفاده کنید:
• Kali را به‌عنوان VM میزبان داشته باشید
• DVWA یا Django را در Docker Container اجرا کنید
• با docker run -p 8000:8000 vulhub/django شروع کنید
مزیت: سبک‌تر، سریع‌تر. عیب: پیچیدگی Docker یادگیری بیشتری می‌خواهد.

DVWA چرا خطای «Could not connect to database» می‌دهد؟

این خطا ۹۰٪ مواقع به دلیل تنظیمات config است:
۱) فایل config.inc.php وجود دارد؟
۲) نام کاربری/رمز MySQL درست است؟
۳) دیتابیس DVWA ساخته شده؟
دستور تعمیر: sudo mysql -e "SHOW DATABASES;" — باید dvwa را ببینید. اگر نیست: sudo mysql -e "CREATE DATABASE dvwa;".

🐛 خطاهای رایج و رفع آن‌ها:
خطا / مشکلعلت محتملراه‌حل
VT-x is disabled in BIOS مجازی‌سازی سخت‌افزاری خاموش BIOS → Advanced → CPU Config → Intel VT-x: Enabled
Hyper-V is enabled and conflicts with VMware Hyper-V تداخل دارد PowerShell admin: Disable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All
پینگ از Kali به Windows: Request Timeout فایروال Windows ICMP را می‌بندد New-NetFirewallRule -DisplayName "Allow ICMP" -Protocol ICMPv4 -IcmpType 8 -Direction Inbound -Action Allow
curl: Connection refused Django روی 127.0.0.1 اجرا شده، نه 0.0.0.0 از runserver 0.0.0.0:8000 استفاده کنید
DisallowedHost at / ALLOWED_HOSTS خالی است در settings.py: ALLOWED_HOSTS = ['*'] (فقط lab)
Address already in use پورت 8000 مشغول است netstat -ano | findstr :8000 سپس taskkill /PID <PID> /F
VMware Tools روی Kali نصب نمی‌شود Kali خودش open-vm-tools دارد sudo apt install open-vm-tools open-vm-tools-desktop
رزولوشن صفحه Kali کوچک است VMware Tools نصب نیست بعد از نصب open-vm-tools: xrandr --auto و ری‌استارت
Clipboard کار نمی‌کند (کپی/پیست بین Kali و میزبان) Guest Isolation فعال است VM Settings → Options → Guest Isolation → غیرفعال کنید (امن‌تر)
Snapshotها فضای زیادی می‌گیرند Snapshotهای انباشته Snapshot Manager → Delete All (Commit به دیسک اصلی)

📝 آزمونک فصل (۵ سؤال، بدون نگاه به متن بالا):
۱. برای VM هدف در آزمایشگاه امنیت، کدام نوع شبکه مناسب‌تر است؟
  • الف) Bridged (VMnet0)
  • ب) NAT (VMnet8)
  • ج) Host-Only (VMnet1)
  • د) Custom
۲. در شبکه Host-Only، DHCP را چرا خاموش می‌کنیم؟
  • الف) برای افزایش سرعت
  • ب) برای داشتن IPهای ثابت و قابل تکرار
  • ج) چون VMware پشتیبانی نمی‌کند
  • د) برای کاهش مصرف حافظه
۳. تفاوت اصلی Snapshot با Clone چیست؟
  • الف) هیچ تفاوتی ندارند
  • ب) Snapshot سریع است، Clone کند
  • ج) Snapshot از وضعیت فعلی نگه می‌دارد ولی Clone یک VM کامل جدید می‌سازد
  • د) فقط Clone قابل بازگشت است
۴. در Django، ALLOWED_HOSTS = ['*'] چه می‌کند؟
  • الف) به همه دامنه‌ها اجازه دسترسی می‌دهد
  • ب) پورت را باز می‌کند
  • ج) فایروال را غیرفعال می‌کند
  • د) HTTPS را فعال می‌کند
۵. چرا هرگز نباید VM هدف را روی Bridged بگذاریم؟
  • الف) کند می‌شود
  • ب) چون از شبکه واقعی و اینترنت قابل دسترسی می‌شود و ربات‌ها می‌توانند به آن حمله کنند
  • ج) VMware پشتیبانی نمی‌کند
  • د) IP نمی‌گیرد
✅ نمایش پاسخ‌های صحیح

۱. ج — Host-Only ایزوله‌ترین حالت است و هیچ رباتی از اینترنت به آن دسترسی ندارد.

۲. ب — IP ثابت باعث تکرارپذیری می‌شود؛ دستورهای nmap/sqlmap همیشه یکسان کار می‌کنند.

۳. ج — Snapshot مثل «Ctrl+S» موقت است؛ Clone یک VM مستقل می‌سازد.

۴. الف — به Django می‌گوید هر هدر Host را بپذیر (خطرناک در تولید، مجاز در lab).

۵. ب — Bridged یعنی اتصال مستقیم به شبکه واقعی؛ فاجعه حقوقی و فنی.

🏆 پروژه هفتگی: «آزمایشگاه سه‌سطحی پیشرفته»
