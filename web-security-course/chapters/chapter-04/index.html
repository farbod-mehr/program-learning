۱. جعبه عنوان و هویت

📖 عنوان کامل فصل: شناسایی و اسکن وب (Scanning & Enumeration) — تبدیل اطلاعات خام Recon به پروفایل دقیق آسیب‌پذیری و اولویت‌بندی حمله.

🎓 سطح دشواری: متوسط. این فصل بیشترین حجم ابزار را در دوره دارد و شلوغ‌ترین فاز تست نفوذ را پوشش می‌دهد.

⏱ زمان مطالعه: ۹۰ تا ۱۲۰ دقیقه (اجرای واقعی ابزارها ۲-۴ ساعت زمان می‌برد).

🛠 پیش‌نیاز فنی: فصل‌های ۱ تا ۳ کامل + Burp Suite Community نصب‌شده روی Kali + آشنایی با HTTP Response/Request.

🎯 اهداف کلان این فصل:
  1. اجرای Nikto به‌عنوان اسکنر کلاسیک وب‌سرور و تفسیر خروجی.
  2. تسلط بر Nuclei — سریع‌ترین و مدرن‌ترین اسکنر آسیب‌پذیری (YAML-based).
  3. پیکربندی Burp Suite به‌عنوان پروکسی و اجرای Spider برای کشف مسیرها.
  4. استفاده از OWASP ZAP برای اسکن خودکار و پویا.
  5. تحلیل SSL/TLS با testssl.sh و شناسایی پیکربندی ضعیف.
  6. کشف API endpoints و شناسایی نقاط ورود داده.
  7. ساخت گزارش اولویت‌بندی‌شده آسیب‌پذیری با امتیاز CVSS.
📚 خروجی قابل اندازه‌گیری (پس از این فصل):
  • یک Nikto scan کامل از هدف Django lab با گزارش خروجی.
  • یک Nuclei scan با حداقل ۵ نوع Template مختلف.
  • Burp Spider فعال با Sitemap کامل هدف.
  • OWASP ZAP Automated Scan با گزارش HTML.
  • گزارش SSL/TLS با testssl.sh و تست هدرهای امنیتی.
  • فایل vulnerability-report.md با جدول اولویت‌بندی (CVSS).
⚠️ هشدار حقوقی — تفاوت Recon با Scanning: در فصل ۳ (Recon)، بیشتر ابزارها Passive بودند یا با درخواست‌های محدود کار می‌کردند. ولی در این فصل، همه ابزارها (Nikto، Nuclei، ZAP، Spider) هزاران درخواست Active می‌فرستند که:
  • در لاگ سرور هدف ثبت می‌شود
  • ممکن است WAF/IPS را فعال کند
  • ممکن است سرویس‌های آسیب‌پذیر را از کار بیندازد
  • اگر بدون مجوز باشد، اثبات قانونی جرم است (ماده ۱ و ۲ قانون جرایم رایانه‌ای)
فقط روی VMهای آزمایشگاه خودتان یا سرویس‌های آموزشی معتبر اجرا کنید.

۴. مقدمه: چرا Scanning فراتر از Recon است؟

📖 داستان واقعی — نقض Capital One (۲۰۱۹):

مهاجم سابقاً کارمند AWS بود. تیم امنیت Capital One می‌دانست که سرورهای AWS دارند و به‌طور منظم تست نفوذ انجام می‌داد. اما یک نقطه از Scanning را نادیده گرفته بودند: Server-Side Request Forgery (SSRF) در یکی از WAFهای اجاره‌ای AWS.

مراحل حمله در این سناریو:

  • مهاجم یک Scan کامل پورت روی IP عمومی Capital One انجام داد و SSRF endpoint را کشف کرد
  • با Nikto + Nuclei متوجه نسخه آسیب‌پذیر WAF شد
  • با Burp Suite پیکربندی SSRF را کشف کرد
  • به AWS Metadata (169.254.169.254) دسترسی گرفت
  • نتیجه: افشای ۱۰۶ میلیون رکورد کاربران، جریمه ۱۹۰ میلیون دلاری

اگر Capital One در فاز Scanning، SSRF را شناسایی کرده بود، این فاجعه رخ نمی‌داد. Scanning دقیق = جلوگیری از فاجعه.

🛠 ابزار ۱: Nikto (اسکنر کلاسیک وب)

کاربرد: اسکن سریع ۶۵۰۰+ آسیب‌پذیری شناخته‌شده، فایل‌های حساس، پیکربندی نادرست

اسکن پایه:
# اسکن ساده
nikto -h http://192.168.56.20:8000

# ذخیره در فرمت‌های مختلف
nikto -h http://192.168.56.20:8000 -o nikto_report.html -Format html
nikto -h http://192.168.56.20:8000 -o nikto_report.xml -Format xml
nikto -h http://192.168.56.20:8000 -o nikto_report.txt -Format txt

# اسکن سریع‌تر (بدون تست همه)
nikto -h http://192.168.56.20:8000 -Tuning 123bde

# اسکن با پروکسی (از طریق Burp)
nikto -h http://192.168.56.20:8000 -useproxy http://127.0.0.1:8080

# اسکن با Header دلخواه (دور زدن WAF ساده)
nikto -h http://192.168.56.20:8000 -useragent "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"

# اجرای موازی (سریع‌تر)
nikto -h http://192.168.56.20:8000 -maxtime 10m -Pause 0

🛠 ابزار ۲: Nuclei (اسکنر مدرن YAML-based)

کاربرد: سریع‌ترین اسکنر آسیب‌پذیری با ۵۰۰۰+ Template آماده

۱) راه‌اندازی اولیه:
# به‌روزرسانی Templateها (بسیار مهم — روزانه اجرا کنید)
nuclei -update-templates

# بررسی نسخه
nuclei -version

# فهرست Templateها
nuclei -tl

# شمارش کل Templateها
nuclei -tl | wc -l
# خروجی: حدود 5000+ Template
۲) اسکن‌های پایه:
# اسکن ساده یک هدف
nuclei -u http://192.168.56.20:8000

# اسکن با شدت بالا (Critical + High)
nuclei -u http://192.168.56.20:8000 -severity critical,high

# اسکن همه شدت‌ها
nuclei -u http://192.168.56.20:8000 -severity critical,high,medium,low,info

# ذخیره نتایج در چند فرمت
nuclei -u http://192.168.56.20:8000 \
    -o nuclei_results.txt \
    -json-export nuclei_results.json \
    -markdown-export nuclei_md/

# اسکن با HTML report
nuclei -u http://192.168.56.20:8000 -html-export nuclei_report.html

# /etc/nginx/nginx.conf
http {
    server_tokens off;  # حذف نسخه Nginx
    
    # Rate Limiting برای جلوگیری از Scannerها
    limit_req_zone $binary_remote_addr zone=scan_limit:10m rate=10r/s;
    limit_req_zone $binary_remote_addr zone=api_limit:10m rate=30r/s;
    
    # مسدودسازی User-Agentهای اسکنرها
    map $http_user_agent $block_scanner {
        default 0;
        ~*nikto 1;
        ~*nuclei 1;
        ~*nmap 1;
        ~*sqlmap 1;
        ~*dirbuster 1;
        ~*gobuster 1;
        ~*zap 1;
        ~*burpsuite 1;
    }
    
    server {
        listen 443 ssl http2;
        server_name target.local;
        
        # مسدودسازی اسکنرها
        if ($block_scanner) {
            return 403;
        }
        
        # Rate Limiting
        location / {
            limit_req zone=scan_limit burst=20 nodelay;
            limit_req_status 429;
            proxy_pass http://127.0.0.1:8000;
        }

۱۰. پرسش و پاسخ و رفع اشکال

❓ سوالات متداول این فصل:
تفاوت Nikto و Nuclei چیست؟ کدام را انتخاب کنم؟

Nikto: قدیمی، کند، پر سروصدا، ولی جامع — ۶۵۰۰+ چک آماده روی سرور.
Nuclei: مدرن، سریع، کم سروصدا، با ۵۰۰۰+ Template پویا و قابل سفارشی‌سازی.
توصیه: اول Nuclei (سریع و دقیق)، بعد Nikto (برای چک‌های سرور).

چرا Nuclei خطا «no templates found» می‌دهد؟

چک‌لیست:
۱) nuclei -update-templates اجرا شده؟
۲) به اینترنت دسترسی دارید؟ (برای دانلود اولیه)
۳) پوشه templates کجاست؟ ls ~/nuclei-templates/
۴) اگر پشت Proxy هستید، -update-templates -proxy.
۵) گاهی دسترسی مستقیم به GitHub مشکل است — از -t با Templates محلی استفاده کنید.

Burp به‌عنوان Proxy روی Kali کار نمی‌کند. مشکل چیست؟

چک‌لیست:
۱) Burp روی 8080 گوش می‌دهد؟ (Proxy → Options)
۲) Firefox تنظیم شده؟ (Manual proxy → 127.0.0.1:8080)
۳) CA Certificate نصب شده؟ (برای HTTPS)
۴) فایروال Kali جلو را گرفته؟ sudo ufw status
۵) در Burp: Intercept is off (راست‌کلیک روی دکمه Intercept).

ZAP Automated Scan روی هدف ما هیچ چیزی پیدا نمی‌کند!

دلایل احتمالی:
۱) Django lab ما خیلی امن است (احتمال کم)
۲) ZAP فقط سطح اول را اسکن کرده (باید Spider هم انجام دهد)
۳) Authentication لازم است و ZAP لاگین نیست
۴) Input Validation سمت Django، Payloadها را رد می‌کند

چرا testssl.sh زمان اجرا این‌قدر طول می‌کشد؟
