۱. جعبه عنوان و هویت

📖 عنوان کامل فصل: جمع‌آوری اطلاعات (Reconnaissance) — فاز اول هر تست نفوذ که در آن مهاجم، پروفایل کامل هدف را از منابع عمومی و تعاملی می‌سازد.

🎓 سطح دشواری: متوسط. این فصل اولین فصلی است که به‌طور جدی از ترمینال Kali و ابزارهای حرفه‌ای استفاده می‌کنید.

⏱ زمان مطالعه: ۹۰ تا ۱۲۰ دقیقه (بدون احتساب زمان دانلود ابزارها).

🛠 پیش‌نیاز فنی: فصل ۱ و ۲ کامل + آشنایی با ترمینال Linux + مفهوم DNS/HTTP/پورت.

🎯 اهداف کلان این فصل:
  1. تمایز کامل Passive Recon (بدون تماس با هدف) از Active Recon (با تماس).
  2. اجرای OSINT حرفه‌ای با Google Dorks، Shodan، Censys، Wayback Machine.
  3. تسلط بر Nmap با تمام سوئیچ‌های کلیدی: -sS, -sV, -A, -O, NSE Scripts.
  4. Directory Brute-forcing با Gobuster و FFUF.
  5. Subdomain Enumeration با Subfinder و Amass.
  6. Technology Fingerprinting با Wappalyzer و WhatWeb.
  7. ساخت پروفایل هدف در قالب یک فایل Markdown قابل ارائه.
📚 خروجی قابل اندازه‌گیری (پس از این فصل):
  • یک پروفایل کامل از هدف (IP، پورت‌ها، سرویس‌ها، نسخه‌ها، تکنولوژی، مسیرها).
  • Nmap scan با گزارش خروجی (قابل ارائه در مصاحبه).
  • حداقل ۳ Directory کشف‌شده با Gobuster روی Django lab.
  • تسلط بر ۲۰+ Dork برای Passive Recon.
  • فایل target-profile.md که به پورتفولیوی امنیتی شما افزوده می‌شود.
⚠️ هشدار قانونی — این فصل پرخطرترین فصل از نظر قانونی است: Passive Recon روی سایت‌های عمومی (خواندن، جستجو در موتورها) از نظر قانونی ساده است، ولی حتی برای Passive، شما نباید سایت‌های حساس (بانک، دولتی) را هدف بگیرید. و Active Recon (Nmap، Gobuster، FFUF) روی هر سیستم بدون مجوز کتبی، جرم کیفری است. تمام تمرین‌های این فصل فقط روی VMهای خودتان (192.168.56.x) یا سرویس‌های آموزشی معتبر (مثل scanme.nmap.org) مجاز است.

۴. مقدمه: چرا Recon اولویت اول است؟

📖 داستان واقعی — عملیات Aurora (۲۰۰۹):

مهاجمان یک عملیات APT پیشرفته را علیه گوگل و چند شرکت بزرگ شروع کردند. اما جالب‌ترین بخش ماجرا این است: قبل از هر خط کد مخرب، تیم مهاجم بیش از ۶ ماه را صرف Reconnaissance کرد:

  • شناسایی کارمندان کلیدی از LinkedIn و شبکه‌های اجتماعی
  • کشف معماری شبکه گوگل از مستندات عمومی و جستجوی Google Dorks
  • یافتن زیردامنه‌های فراموش‌شده و سرورهای تست
  • شناسایی نسخه‌های نرم‌افزاری از پاسخ‌های Server Header
  • تحلیل چرخه‌های انتشار نرم‌افزار از بلاگ‌های مهندسی گوگل

نتیجه: حمله Aurora آن‌قدر دقیق بود که حتی مهندسان ارشد گوگل هم ۳ هفته متوجه نشدند. اگر Recon درست انجام نشود، حمله شکست می‌خورد. اما با Recon درست، حمله تقریباً اجتناب‌ناپذیر می‌شود.

🎯 سه دلیل بنیادی برای اهمیت Recon:
🎯 دقت حمله

بدون Recon، حمله شما کورکورانه است — نمی‌دانید چه پورت‌هایی بازند، چه نسخه‌ای، چه تکنولوژی. با Recon، هر حمله به هدف دقیقی می‌خورد.

🕵️ پیشگیری از شناسایی

Recon خوب، شما را از اسکن‌های بیهوده و پر سروصدا نجات می‌دهد. مهاجم حرفه‌ای اول ۸۰٪ اطلاعات را Passive جمع می‌کند، بعد فقط ۲۰٪ آخر را Active.

📋 سطح حمله وسیع‌تر

Recon نشان می‌دهد هدف شما فقط یک دامنه نیست: زیردامنه‌ها، سرویس‌های فراموش‌شده، ایمیل‌های لو رفته، اسناد PDF — همه این‌ها سطح حمله را بزرگ‌تر می‌کنند.

  • ۲۰۰۴ — انتشار The Art of Scanning (Johnny Long) — مرجع اولیه Active Recon.
  • ۲۰۰۹ — Shodan تاسیس شد: موتور جستجوی دستگاه‌های متصل به اینترنت.
  • ۲۰۱۲ — Recon-ng: اولین ابزار چارچوبی برای Recon خودکار.
  • ۲۰۱۵ — Amass، Subfinder و ابزارهای Subdomain Enumeration ظهور کردند.
  • ۲۰۲۰+ — عصر OSINT حرفه‌ای با Censys، SecurityTrails، VirusTotal API.
  • ۲۰۲۳+ — AI در Recon: تحلیل خودکار اطلاعات با GPT و Claude.

🛠 ابزار ۵: Nmap (Active) — پادشاه Recon

کاربرد: اسکن پورت، شناسایی سرویس، تشخیص سیستم‌عامل، اسکریپت‌های NSE

۱) اسکن‌های پایه:
# سریع‌ترین اسکن (بدون سرویس)
nmap 192.168.56.20

# اسکن پرسرعت چند پورت
nmap -F 192.168.56.20
# فقط 100 پورت رایج

# اسکن همه ۶۵,۵۳۵ پورت
nmap -p- 192.168.56.20

# اسکن پورت‌های خاص
nmap -p 80,443,8000,8080 192.168.56.20
۲) شناسایی سرویس و نسخه:
# تشخیص نسخه سرویس (Service Detection)
nmap -sV 192.168.56.20
# خروجی: port 8000: WSGIServer 0.2 (Django)

# تشخیص سیستم‌عامل
nmap -O 192.168.56.20
# نیاز به sudo

# ترکیب همه چیز (Aggressive)
sudo nmap -A 192.168.56.20
# -O + -sV + default scripts + traceroute

# اسکن سریع با ۴-سطح تهاجم
sudo nmap -A -T4 192.168.56.20
۳) تکنیک‌های اسکن پیشرفته:
# TCP SYN Scan (نیاز به root — پیش‌فرض با sudo)
sudo nmap -sS 192.168.56.20

# TCP Connect Scan (بدون root)
nmap -sT 192.168.56.20

# UDP Scan (کند ولی مهم برای DNS/NTP/SNMP)
sudo nmap -sU 192.168.56.20

# ترکیب TCP + UDP
sudo nmap -sS -sU 192.168.56.20

# اسکن مخفیانه (کند)
sudo nmap -sS -T1 -f 192.168.56.20

# اسکن از طریق FTP bounce یا idle host (پیشرفته)
sudo nmap -sI <idle_host> 192.168.56.20
۴) Nmap Scripting Engine (NSE) — قدرتمندترین بخش Nmap:
# بررسی آسیب‌پذیری‌های رایج (Vulnerability Scan)
sudo nmap --script=vuln 192.168.56.20

# بررسی رایج‌ترین ضعف‌های وب
sudo nmap --script=http-vuln* 192.168.56.20

# استخراج اطلاعات HTTP (عنوان، Server Header، روش‌های مجاز)
sudo nmap --script=http-title,http-headers,http-methods -p 8000 192.168.56.20

# بررسی دایرکتوری‌های پیش‌فرض
sudo nmap --script=http-enum -p 8000 192.168.56.20

# اسکن SMB
sudo nmap --script=smb-vuln* -p 445 192.168.56.20

# بررسی SSH Weak Algorithms
sudo nmap --script=ssh2-enum-algos -p 22 192.168.56.20
۵) خروجی‌گیری حرفه‌ای:
# ذخیره در فرمت‌های مختلف
sudo nmap -A -oN scan.txt 192.168.56.20       # متن ساده
sudo nmap -A -oX scan.xml 192.168.56.20       # XML (برای ابزارهای دیگر)
sudo nmap -A -oG scan.gnmap 192.168.56.20     # Grepable
sudo nmap -A -oA scan_all 192.168.56.20       # همه فرمت‌ها

# تبدیل XML به HTML
xsltproc scan.xml -o scan.html
# سپس در مرورگر باز کنید
💡 ترکیب استاندارد Nmap برای پنتست: sudo nmap -sS -sV -sC -O -p- -T4 -oA target_full_scan 192.168.56.20
  • -sS: SYN Scan (سریع)
  • -sV: Service Detection
  • -sC: Default Scripts
  • -O: OS Detection
  • -p-: همه پورت‌ها
  • -T4: سرعت بالا (اجتناب از T5 که نویز می‌کند)

۱۰. پرسش و پاسخ و رفع اشکال

❓ سوالات متداول این فصل:
تفاوت Gobuster با FFUF چیست؟ کدام را انتخاب کنم؟

Gobuster: ساده‌تر، سریع‌تر برای سناریوهای استاندارد (dir, dns, vhost), زبان Go (تک فایل).
FFUF: انعطاف‌پذیرتر، پشتیبانی از FUZZ در URL/Header/Body، فیلتر پیشرفته (اندازه، کلمه، خط)، مناسب برای fuzzing پیچیده.
توصیه: Gobuster برای شروع، FFUF برای موارد پیشرفته.

Nmap -T5 چرا خطرناک است؟

T5 (Insane) پکت‌ها را آن‌قدر سریع می‌فرستد که:
• ممکن است سرویس‌های قدیمی را از کار بیندازد
• Firewall/IDS شما را به‌عنوان DoS بلاک کند
• پکت‌ها گم شوند → نتایج اشتباه
• در محیط قانونی، شبیه حمله دیده می‌شود
همیشه با T2 یا T3 شروع کنید، فقط در شبکه داخلی و با مجوز T4.

چرا Passive Subdomain Enumeration نتایج دقیق نمی‌دهد؟

چون Passive فقط از منابع ثالث استفاده می‌کند:
• Subfinder/Censys → ممکن است دیر آپدیت شوند
• crt.sh → فقط زیردامنه‌های SSL دارند
• Wayback → فقط زیردامنه‌های آرشیوشده
راه‌حل: ترکیب چند منبع + مقایسه + تأیید با Active (DNS lookup).

۱۲. خودارزیابی و آزمونک

⭐ چک‌لیست خودارزیابی (صادق باشید):
  • می‌توانم تفاوت Passive و Active Recon را توضیح دهم.
  • حداقل ۲۰ Google Dork حرفه‌ای را می‌شناسم.
  • Nmap را با سوئیچ‌های -sS, -sV, -sC, -O, -p- اجرا می‌کنم.
  • NSE Scripts را برای تشخیص آسیب‌پذیری استفاده می‌کنم.
  • Gobuster را با Wordlist مناسب اجرا می‌کنم و نتایج را فیلتر می‌کنم.
  • Subfinder و Amass را برای کشف زیردامنه استفاده می‌کنم.
  • Wappalyzer/WhatWeb تکنولوژی هدف را تشخیص می‌دهد.
  • یک پروفایل کامل از هدف (target-profile.md) ساخته‌ام.
  • می‌دانم چرا Passive قبل از Active است.
  • Rate Limiting را در ابزارها تنظیم می‌کنم.
📝 آزمونک فصل (۵ سؤال):
۱. کدام گزینه Passive Recon است؟
  • الف) Nmap Port Scan
  • ب) Gobuster Directory Busting
  • ج) Shodan Search
  • د) Nikto Vulnerability Scan
۲. در Nmap، کدام سوئیچ نسخه سرویس را تشخیص می‌دهد؟
  • الف) -sS
  • ب) -sV
  • ج) -O
  • د) -p-
۳. کدام ابزار برای Subdomain Enumeration بهتر است؟
  • الف) Gobuster
  • ب) Subfinder
  • ج) Nmap
  • د) WhatWeb
۴. چرا Nmap -T5 خطرناک است؟
  • الف) کد را اجرا نمی‌کند
  • ب) ممکن است سرویس‌های هدف را از کار بیندازد و به‌عنوان DoS شناسایی شود
  • ج) نتایج دقیق‌تری می‌دهد
  • د) با sudo کار نمی‌کند
۵. بهترین دفاع در برابر Shodan و OSINT روی سازمان چیست؟
  • الف) فعال کردن WAF
  • ب) کاهش Attack Surface (حذف سرویس‌های غیرضروری و اطلاعات افشاگر)
  • ج) نصب آنتی‌ویروس
  • د) تغییر رمز عبور
✅ نمایش پاسخ‌های صحیح

۱. ج — Shodan بدون تماس با هدف کار می‌کند → Passive.

۲. ب — -sV = Service Version Detection.

۳. ب — Subfinder تخصصی برای این کار است (Gobuster برای مسیرها، Nmap برای پورت‌ها).

۴. ب — T5 پکت‌ها را آن‌قدر سریع می‌فرستد که ممکن است سرویس‌ها crash کنند یا شما را بلاک کنند.

۵. ب — Attack Surface Reduction یکی از مهم‌ترین استراتژی‌های دفاعی است.
