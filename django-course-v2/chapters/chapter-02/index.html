🔭 چشم‌انداز فصل: اهداف و جایگاه

این فصل اولین برخورد عملی شما با ابزارهاست. تا پایان فصل، محیط توسعه‌تان کامل آماده است و صفحه خوش‌آمدگویی جنگو را در مرورگر می‌بینید — یکی از لذت‌بخش‌ترین لحظات دوره! 🙂

اهداف یادگیری — پس از این فصل شما می‌توانید:

  • پایتون را نصب و نسخه‌اش را در ترمینال بررسی کنید.
  • محیط مجازی بسازید و فعال کنید و بدانید چرا ضروری است.
  • جنگو را با pip نصب کنید.
  • با startproject اولین پروژه را بسازید و نقش هر فایل را بگویید.
  • سرور توسعه را با runserver اجرا و صفحه را در مرورگر ببینید.

جایگاه فصل: پیش‌نیاز تمام فصل‌های عملی دوره. اگر جایی از نصب گیر کردید، بخش ۹ (خطاهای رایج) را حتماً ببینید — ۹۰٪ مشکلات نصب آنجاست.

🤔 سوالات محرک ذهنی

قبل از خواندن آموزش، چند لحظه به این سوال‌ها فکر کنید؛ حتی اگر جواب را نمی‌دانید، ذهنتان آماده دریافت آن می‌شود:

🤔 چرا نباید بسته‌های پایتون را مستقیم روی پایتونِ اصلی سیستم نصب کرد؟

چون پروژه‌های مختلف به نسخه‌های متفاوت یک بسته نیاز دارند و نصب سراسری باعث تداخل می‌شود. محیط مجازی برای هر پروژه یک «اتاق ایزوله» می‌سازد تا بسته‌ها و نسخه‌هایشان قاطی نشوند.

🤔 وقتی در مرورگر 127.0.0.1:8000 را باز می‌کنید، درخواست به کجا می‌رود؟

به همان کامپیوتر خودتان! عدد 127.0.0.1 یعنی «خودم» (localhost). سرور توسعه جنگو روی کامپیوتر شما اجرا شده و درخواست مرورگر را locally پاسخ می‌دهد. به اینترنت هم نیازی نیست.

🤔 فایل manage.py با django-admin چه فرقی دارد؟

هر دو فرمان اجرا می‌کنند؛ اما manage.py به پروژه شما و فایل settings.pyاش وصل است (فرمان‌هایی مثل runserver و migrate)، در حالی که django-admin عمومی است و بیشتر برای startproject استفاده می‌شود.

بخش ۵

📖 آموزش گام‌به‌گام: مفاهیم

۵.۱ نصب پایتون

جنگو با پایتون کار می‌کند، پس اول پایتون لازم است (نسخه ۳.۱۰ به بالا؛ پیشنهاد ما ۳.۱۲). پایتون ۲ سال‌هاست منسوخ شده — حتماً نسخه ۳ را نصب کنید.

  • ویندوز: از python.org/downloads نصب‌کننده را بگیرید. در صفحه اول نصب، تیک «Add python.exe to PATH» را حتماً بزنید (مهم‌ترین قدم!).
  • مک: پایتون معمولاً هست، ولی برای به‌روز بودن با brew install python نصبش کنید.
  • لینوکس (اوبونتو/دبیان): sudo apt install python3 python3-venv python3-pip

حالا در ترمینال (ویندوز: PowerShell یا CMD) بررسی کنید:

بررسی نصب پایتونBash
python --version
# یا در برخی سیستم‌ها:
python3 --version
# خروجی نمونه: Python 3.12.4

۵.۲ ترمینال و محیط مجازی (venv)

ترمینال محیط متنی اجرای دستورات است. برای هر پروژه یک پوشه بسازید و داخلش محیط مجازی ایجاد کنید:

ساخت و فعال‌سازی محیط مجازیBash
mkdir django-course && cd django-course

# ساخت محیط مجازی (پوشه .venv ساخته می‌شود)
python -m venv .venv

# فعال‌سازی در ویندوز (PowerShell):
.venv\Scripts\Activate.ps1
# فعال‌سازی در ویندوز (CMD):
.venv\Scripts\activate.bat
# فعال‌سازی در مک/لینوکس:
source .venv/bin/activate

بعد از فعال‌سازی، اول خط فرمان (.venv) ظاهر می‌شود؛ یعنی از این به بعد هر نصبی فقط داخل همین محیط انجام می‌شود. برای خروج: deactivate.

⚠️ قانون طلایی هر بار که ترمینال جدید باز می‌کنید، اول venv را فعال کنید بعد دستور جنگو بزنید. نیمی از خطاهای «django-admin is not recognized» همین است!

۵.۳ نصب جنگو

با venv فعال، جنگو را با pip (نصب‌کننده بسته‌های پایتون) نصب کنید:

نصب جنگوBash
pip install "django>=5.2,<6.0"

# بررسی نصب:
django-admin --version
# خروجی نمونه: 5.2.4

python -m django --version   # روش جایگزین

پیشنهاد ما نصب نسخه 5.2 (LTS) است — نسخهٔ پشتیبانی بلندمدت که تا ۲۰۲۸ به‌روزرسانی امنیتی می‌گیرد. جزئیات نسخه‌ها در فصل ۲۹.

۵.۴ ساخت اولین پروژه و آناتومی فایل‌ها

با دستور زیر اسکلت پروژه ساخته می‌شود:

ساخت پروژهBash
django-admin startproject mysite .
# نقطه آخر مهم است: پروژه در همین پوشه ساخته شود، نه زیرپوشه تو در تو

ساختار حاصل:

ساختار پروژهمتن
django-course/
├── .venv/            ← محیط مجازی (به مخزن کد اضافه نمی‌شود)
├── manage.py         ← رابط فرمان پروژه
└── mysite/
    ├── __init__.py
    ├── settings.py   ← تنظیمات مرکزی پروژه
    ├── urls.py       ← ریشه مسیریابی URLها
    ├── asgi.py       ← ورودی سرور ناهمگام (فصل ۲۶)
    └── wsgi.py       ← ورودی سرور تولید (فصل ۲۶)

نگاه سریع به چند تنظیم مهم settings.py:

  • SECRET_KEY — کلید مخفی امضای رمزنگاری؛ هرگز لو نرود.
  • DEBUG = True — حالت اشکال‌زدایی؛ در تولید باید False شود.
  • ALLOWED_HOSTS = [] — دامنه‌های مجاز؛ با DEBUG=True سخت‌گیری نمی‌شود.
  • INSTALLED_APPS — فهرست اپ‌ها؛ فصل ۳ اضافه می‌کنیم.
  • DATABASES — به‌صورت پیش‌فرض SQLite (فایل db.sqlite3).

۵.۵ اجرای سرور توسعه

لحظه دیدن نتیجه! با runserver سرور توسعه را اجرا کنید:

اجرای سرورBash
python manage.py runserver

# خروجی نمونه:
# Starting development server at http://127.0.0.1:8000/
# Quit the server with CTRL-BREAK.

مرورگر را باز کنید و به http://127.0.0.1:8000/ بروید: 🎉 صفحه خوش‌آمدگویی موشک جنگو! سرور با Ctrl+C متوقف می‌شود و با ذخیره هر فایل، خودش reload می‌کند.

📌 این سرور چیست؟ runserver یک سرور سبک مخصوص توسعه است. مرورگر شما کلاینت است و یک درخواست می‌فرستد و پاسخ می‌گیرد — دقیقاً همان مفهومی که در فصل ۱ یاد گرفتید، حالا روی کامپیوتر خودتان. برای تولید هرگز از runserver استفاده نمی‌شود (فصل ۲۶).
بخش ۶

💻 مثال عملی

یک دور کامل از صفر تا سرورِ در حال اجرا — همین توالی را عملاً انجام دهید:

دور کامل راه‌اندازی (مک/لینوکس؛ ویندوز مشابه)Bash
mkdir blog-project && cd blog-project
python3 -m venv .venv
source .venv/bin/activate
pip install "django>=5.2,<6.0"
django-admin startproject config .
python manage.py runserver

تحلیل هر خط:

  1. پوشه پروژه ساخته و واردش شدیم.
  2. محیط مجازی .venv ساخته شد.
  3. فعالش کردیم — حالا pip و python این محیط‌اند.
  4. جنگو فقط داخل .venv نصب شد.
  5. پروژه‌ای به نام config در همین پوشه ساخته شد (نام config یک قرارداد حرفه‌ای است).
  6. سرور توسعه بالا آمد → 127.0.0.1:8000 را ببینید!
💡 نکته طلاییکدهای بالا را خودتان تایپ و اجرا کنید؛ تایپ کردن رمز یادگیری است!

🛠️ کارگاه عملی

حالا نوبت شماست (حدود ۲۰ دقیقه). اگر جایی خطا گرفتید، اول بخش ۹ را ببینید:

  1. کارگاه ۱: پوشه‌ای به نام my-first-site بسازید، داخلش venv بسازید و فعال کنید و جنگو نصب کنید. با pip list مطمئن شوید django در فهرست است.
  2. کارگاه ۲: پروژه‌ای به نام config در همان پوشه بسازید و سرور را روی پورت ۹۰۰۰ اجرا کنید (راهنما: runserver یک آرگومان پورت هم می‌گیرد).
  3. کارگاه ۳: در فایل settings.py مقدار DEBUG را موقتاً False کنید، صفحه را رفرش کنید و تفاوت را ببینید. بعد برگردانید True. چه نتیجه‌ای گرفتید؟
بخش ۸

✅ پاسخ کامل کارگاه عملی

✅ پاسخ کارگاه ۱ — محیط و نصب
دستورات کاملBash
mkdir my-first-site && cd my-first-site
python -m venv .venv
source .venv/bin/activate   # ویندوز: .venv\\Scripts\\activate
pip install "django>=5.2,<6.0"
pip list   # باید: django  5.2.x

اگر pip list جنگو را نشان نداد، یعنی venv فعال نبوده؛ فعال کنید و دوباره نصب کنید.

✅ پاسخ کارگاه ۲ — پروژه و پورت ۹۰۰۰
دستوراتBash
django-admin startproject config .
python manage.py runserver 9000

حالا در مرورگر: http://127.0.0.1:9000/. پورت فقط عدد درگاه شبکه است؛ ۸۰۰۰ پیش‌فرض است و اجباری نیست.

✅ پاسخ کارگاه ۳ — نتیجه DEBUG=False

با DEBUG=False و ALLOWED_HOSTS خالی، جنگو صفحه خطای «DisallowedHost» نشان می‌دهد و حتی خطاهای دیگر را هم بدون جزئیات نمایش می‌دهد. درس: DEBUG=False یعنی «هیچ جزئیاتی از خطا به کاربر غریبه نشان نده» — دقیقاً چیزی که در تولید می‌خواهیم (به‌همراه تنظیم صحیح ALLOWED_HOSTS و یک صفحه خطای ۵۰۰ مناسب). DEBUG را برای ادامه دوره True بگذارید.

بخش ۹

🐞 خطاهای رایج و رفع آن‌ها

اشتباهات و خطاهای رایج این فصل را بشناسید تا سریع‌تر رفعشان کنید:

❌ خطای 'django-admin' is not recognized یا command not found

سه علت رایج: ① جنگو نصب نیست → pip install django. ② venv فعال نیست → فعالش کنید. ③ در ویندوز، پایتون با تیک PATH نصب نشده → دوباره نصب کنید و «Add to PATH» را بزنید (یا از python -m django استفاده کنید).

❌ خطای 'python' is not recognized

پایتون نصب نیست یا در PATH نیست. در مک/لینوکس ممکن است دستور python3 باشد نه python. در ویندوز نصب‌کننده را با گزینه PATH دوباره اجرا کنید.

❌ خطای Port 8000 is already in use

سرور قبلی هنوز باز است (شاید در ترمینالی دیگر). آن را با Ctrl+C ببندید یا پورت دیگری بدهید: python manage.py runserver 8080.

❌ اجرای Activate.ps1 در PowerShell خطا می‌دهد

سیاست اجرایی PowerShell محدود است. با PowerShell به‌عنوان مدیر: Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser یا از activate.bat در CMD استفاده کنید.

🚨 هرگز این کار را نکنید pip install django را بیرون از venv اجرا نکنید (مگر عمداً). نصب سراسری، ریشه اکثر تداخل‌های عجیب‌وغریب نسخه‌هاست.

🏋️ تمرین‌های تثبیت

پاسخ‌ها را اول خودتان بنویسید، بعد باز کنید:

🏋️ تمرین ۱ — فرمان درست را انتخاب کنید

سوال: برای هر کار کدام فرمان؟ (الف) ساخت محیط مجازی (ب) نصب جنگو (ج) ساخت پروژه (د) اجرای سرور

پاسخ: الف → python -m venv .venv • ب → pip install django • ج → django-admin startproject NAME . • د → python manage.py runserver

🏋️ تمرین ۲ — نقش فایل‌ها

سوال: نقش هر فایل چیست؟ settings.py، urls.py، manage.py، wsgi.py

پاسخ: settings → تنظیمات مرکزی (پایگاه داده، اپ‌ها، امنیت) • urls → ریشه مسیریابی نشانی‌ها • manage.py → رابط فرمان‌های پروژه • wsgi.py → نقطه اتصال سرورهای تولید مثل Gunicorn (فصل ۲۶).

🏋️ تمرین ۳ — عیب‌یابی

سناریو: هم‌اتاقی‌تان می‌گوید «دیروز همه‌چیز کار می‌کرد، امروز django-admin کار نمی‌کند!». محتمل‌ترین علت چیست؟

پاسخ: ترمینال جدید باز کرده و venv را فعال نکرده. راه‌حل: cd به پوشه پروژه + فعال‌سازی venv. به او بگویید نشانه فعال بودن، پیشوند (.venv) است.

بخش ۱۱

📝 آزمون تعاملی فصل

پرسش‌های چهارگزینه‌ای زیر را پاسخ دهید؛ بلافاصله بعد از انتخاب، پاسخ درست و توضیحش را می‌بینید. حد نصاب قبولی ۶۰٪ است و بهترین نمره‌تان ذخیره می‌شود.

۱) چرا برای هر پروژه یک محیط مجازی (venv) می‌سازیم؟

💡 محیط مجازی ایزوله‌سازی می‌کند: هر پروژه بسته‌ها و نسخه‌های خودش را دارد و به بقیه سیستم کاری ندارد.

۲) کدام گزینه یک پروژه جدید جنگو می‌سازد؟

💡 برای ساخت پروژه از django-admin استفاده می‌شود؛ manage.py بعد از ساخت پروژه وجود دارد (مرغ و تخم‌مرغ!).

۳) سرور توسعه جنگو با کدام دستور اجرا می‌شود؟

💡 runserver فرمان مخصوص manage.py است؛ آدرس پیش‌فرض http://127.0.0.1:8000/.

۴) در مرحله تولید (سایت واقعی روی اینترنت) کدام تنظیم درست است؟

💡 DEBUG=True در تولید، جزئیات حساس (کلیدها، مسیرها، کوئری‌ها) را به غریبه‌ها لو می‌دهد؛ پس False + ALLOWED_HOSTS مشخص.

۵) نقش فایل settings.py چیست؟

💡 settings.py مرکز پیکربندی پروژه است؛ مسیریابی در urls.py و قالب‌ها در پوشه templatesاند.

۶) نشانه فعال بودن محیط مجازی در خط فرمان چیست؟

💡 بعد از activate، نام محیط (معمولاً .venv) ابتدای prompt اضافه می‌شود؛ دیدن آن یعنی نصب‌ها ایزوله‌اند.

  • پوشه پروژه + venv فعال + جنگو 5.2 نصب‌شده.
  • پروژه‌ای به نام config ساخته و سرور روی ۱۲۷.۰.۰.۱:۸۰۰۰ اجرا شود.
  • در settings.py، مقادیر SECRET_KEY، DEBUG، ALLOWED_HOSTS، INSTALLED_APPS و DATABASES را پیدا کنید و نقش هرکدام را در یک خط در بخش یادداشت‌ها بنویسید.
  • با pip freeze > requirements.txt فایل وابستگی پروژه را بسازید.
  • یک بار ترمینال را ببندید، دوباره باز کنید و کل توالی «cd + فعال‌سازی venv + runserver» را از حفظ انجام دهید. 🙂
💡 چرا این پروژه مهم است؟ همین محیط، پایه همه فصل‌های بعد است. عادت «اول venv، بعد دستور» از همین‌جا شکل می‌گیرد.
بخش ۱۳

🎯 جمع‌بندی و دستاوردها

در این فصل یاد گرفتید:

  • پایتون ۳ را نصب و در ترمینال بررسی کردیم.
  • با venv محیط ایزوله ساختیم؛ قانون طلایی: اول فعال‌سازی، بعد هر دستور.
  • جنگو را با pip نصب کردیم (نسخه پیشنهادی: 5.2 LTS).
  • پروژه را با startproject ساختیم و نقش manage.py، settings.py، urls.py و wsgi.py را شناختیم.
  • سرور توسعه را با runserver اجرا و صفحه خوش‌آمدگویی را دیدیم.
💡 ✨ یک‌جمله‌ای که باید یادتان بماند «هر پروژه = یک پوشه + یک venv + یک startproject + یک runserver؛ به همین سادگی.»

❓ سوالات متداول و گام بعدی

آیا باید حتماً VS Code داشته باشم؟

خیر. PyCharm Community، Sublime یا هر ویرایشگر دیگری هم کار می‌کند. VS Code به‌خاطر سبکی، رایگان بودن و افزونه عالی Python پیشنهاد اول ماست.

پایتون ۳.۱۳ نصب کردم؛ مشکلی ندارد؟

نه! جنگو 5.2 از پایتون 3.10 تا 3.13 پشتیبانی می‌کند. فقط پایتون ۲ یا نسخه‌های خیلی قدیمی (زیر 3.10) مشکل‌سازند.

سرور را بگذارم باز بماند اشکالی دارد؟

برای توسعه خیر؛ ولی موقع بستن لپ‌تاپ یا تمام‌شدن کار با Ctrl+C ببندیدش. مصرف منابع runserver ناچیز است.

📌 🧭 گام بعدی محیط آماده است! در فصل ۳ اولین اپلیکیشن را می‌سازیم و اولین کد واقعی جنگو (ویو و URL) را می‌نویسیم.
