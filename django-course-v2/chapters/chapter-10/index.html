🔭 چشم‌انداز فصل: اهداف و جایگاه

قالب لایه «ظاهر» در MTV است. با ارث‌بری قالب‌ها، یک اسکلت مشترک (هدر/فوتر) می‌سازید و هر صفحه فقط محتوای خودش را پر می‌کند — بدون حتی یک خط HTML تکراری.

اهداف یادگیری — پس از این فصل شما می‌توانید:

  • متغیرها {{ }} و فیلترها | را به کار ببرید.
  • با تگ‌های {% if %}، {% for %} منطق نمایشی بنویسید.
  • با extends/block یک base.html حرفه‌ای بسازید.
  • قطعه‌های تکراری را با include جدا کنید.
  • Auto-escaping و امنیت XSS را توضیح دهید.

جایگاه فصل: مکمل فصل‌های ۸ و ۹؛ فایل‌های ایستا (CSS) در فصل ۱۴ و صفحه‌بندی پیشرفته در فصل ۹ دیدید.

بخش ۳

🤔 سوالات محرک ذهنی

قبل از خواندن آموزش، چند لحظه به این سوال‌ها فکر کنید؛ حتی اگر جواب را نمی‌دانید، ذهنتان آماده دریافت آن می‌شود:

🤔 چرا نباید منطق پیچیده (کوئری، محاسبه) را در قالب نوشت؟

قالب فقط برای نمایش است؛ زبان قالب عمداً محدود ساخته شده. منطق در ویو/مدل بماند تا قابل تست و استفاده مجدد باشد. «قالب احمق، ویوی باهوش».

🤔 با extends چه اتفاقی برای blockهای تعریف‌نشده می‌افتد؟

محتوای پیش‌فرض base (اگر داشته باشد) نمایش داده می‌شود یا خالی می‌ماند. این یعنی صفحه فقط blockهایی را override می‌کند که لازم دارد.

🤔 اگر کاربر در کامنتش <script> بنویسد چه می‌شود؟

جنگو به‌طور پیش‌فرض escape می‌کند: به‌جای اجرای اسکریپت، متنش نمایش داده می‌شود. این محافظ خودکار XSS است؛ با فیلتر |safe خودتان می‌توانید بازش کنید — با احتیاط!

۵.۱ متغیرها، جست‌وجوی نقطه‌ای و فیلترها

متغیرها در قالبHTML
{{ post.title }}            ← کلید دیکشنری یا ویژگی شیء
{{ post.author.name }}      ← پیمایش رابطه با نقطه
{{ post.tags.all|length }}  ← فیلتر
{{ post.created_at|date:"Y/m/d H:i" }}
{{ post.body|truncatewords:30 }}
{{ missing_var|default:"—" }}

فیلترهای پرکاربرد: date، length، truncatewords/chars، default، upper/lower، join، linebreaks، slugify، add. فیلترها با | زنجیر می‌شوند.

۵.۲ تگ‌ها: if و for

شرط و مقایسهHTML
{% if user.is_authenticated %}
  <a href="{% url 'blog:post_create' %}">نوشته جدید</a>
{% elif perms.blog.change_post %}
  <p>شما فقط ویرایش‌کارید.</p>
{% else %}
  <a href="{% url 'login' %}">ورود</a>
{% endif %}
حلقه و متغیرهای forloopHTML
{% for post in posts %}
  <article>
    <h2>{{ forloop.counter }}. {{ post.title }}</h2>
    <p>{{ post.body|truncatewords:25 }}</p>
    {% if not forloop.last %}<hr>{% endif %}
  </article>
{% empty %}
  <p>هنوز نوشته‌ای منتشر نشده است.</p>
{% endfor %}

درون حلقه: forloop.counter (از ۱)، counter0، first/last، revcounter. شاخه {% empty %} برای فهرست خالی است.

۵.۳ ارث‌بری قالب: base.html

templates/base.htmlHTML
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head>
  <meta charset="utf-8">
  <title>{% block title %}وبلاگ من{% endblock %}</title>
</head>
<body>
  {% include "partials/navbar.html" %}

  <main class="container">
    {% block content %}{% endblock %}
  </main>

  {% include "partials/footer.html" %}
  {% block scripts %}{% endblock %}
</body>
</html>
templates/blog/post_list.htmlHTML
{% extends "base.html" %}

{% block title %}نوشته‌ها | وبلاگ من{% endblock %}

{% block content %}
  <h1>همه نوشته‌ها</h1>
  {% for post in posts %}
    <h2><a href="{{ post.get_absolute_url }}">{{ post.title }}</a></h2>
  {% endfor %}
{% endblock %}
📌 قانون طلایی extends فایل فرزند فقط می‌تواند block تعریف کند؛ هر متن/تگی بیرون از block در فرزند نادیده گرفته می‌شود. extends هم باید اولین تگ فایل باشد.

۵.۵ امنیت: Auto-escaping و XSS

هر {{ ... }} به‌طور خودکار escape می‌شود: < به &lt; تبدیل می‌شود تا HTML تزریق‌شده اجرا نشود (دفاع اصلی در برابر XSS).

استثناها — با احتیاط!HTML
{{ post.body_html|safe }}        ← escape نکن (فقط برای محتوای اعتمادشده)
{% autoescape off %} ... {% endautoescape %}
🚨 هرگز |safe روی ورودی کاربر اگر کاربر می‌تواند آن محتوا را بنویسد، |safe یعنی دعوت‌نامه XSS! برای متن غنی کاربر از پاک‌سازی‌کننده‌هایی مثل bleach یا django-bleach استفاده کنید.

💻 مثال عملی

قالب کامل صفحه جزئیات پست با همه اجزا:

templates/blog/post_detail.htmlHTML
{% extends "base.html" %}

{% block title %}{{ post.title }} | وبلاگ من{% endblock %}

{% block content %}
<article>
  <h1>{{ post.title }}</h1>
  <p class="meta">
    ✍️ {{ post.author.name }} •
    📅 {{ post.created_at|date:"j F Y" }} •
    👁 {{ post.views_count }} بازدید
  </p>

  {% for tag in post.tags.all %}
    <a class="badge" href="{% url 'blog:tag_posts' tag.slug %}">#{{ tag.name }}</a>
  {% endfor %}

  <div class="body">{{ post.body|linebreaks }}</div>
</article>

<section>
  <h3>نظرات ({{ post.comments.count }})</h3>
  {% for comment in post.comments.all %}
    <div class="comment">
      <b>{{ comment.name }}</b> <small>{{ comment.created_at|date:"Y/m/d" }}</small>
      <p>{{ comment.text|linebreaks }}</p>
    </div>
  {% empty %}
    <p>اولین نفری باشید که نظر می‌دهد!</p>
  {% endfor %}
  <a href="{% url 'blog:add_comment' post.slug %}">➕ ثبت نظر</a>
</section>

{% if related_posts %}
<section>
  <h3>مطالب مرتبط</h3>
  <ul>
    {% for rp in related_posts %}
      <li><a href="{{ rp.get_absolute_url }}">{{ rp.title }}</a></li>
    {% endfor %}
  </ul>
</section>
{% endif %}
{% endblock %}

به post.comments.count دقت کنید: دسترسی معکوس related_name + متد بدون پرانتز (قالب خودش صدا می‌زند). خطاها هم با escape خودکار، امن نمایش داده می‌شوند.

💡 نکته طلاییکدهای بالا را خودتان تایپ و اجرا کنید؛ تایپ کردن رمز یادگیری است!

🛠️ کارگاه عملی

ظاهر وبلاگ را کامل کنید:

  1. کارگاه ۱: base.html با سه block (title، content، scripts) و دو partial (navbar, footer) بسازید و همه قالب‌های موجود را به آن وصل کنید.
  2. کارگاه ۲: در navbar، وضعیت ورود کاربر را نشان دهید: اگر وارد شده «خوش آمدید، {{ user.username }} + خروج»، وگرنه لینک ورود/ثبت‌نام.
  3. کارگاه ۳: صفحه آرشیو بسازید که پست‌ها را گروه‌بندی‌شده بر اساس سال نمایش دهد (راهنما: از ویو یک دیکشنری {سال: [پست‌ها]} پاس دهید و در قالب دو حلقه تودرتو بزنید).

def archive(request):
    grouped = {}
    for post in Post.objects.filter(published=True).order_by("-created_at"):
        grouped.setdefault(post.created_at.year, []).append(post)
    return render(request, "blog/archive.html", {"grouped": grouped})
قالب — حلقه تودرتوHTML
{% for year, posts in grouped.items %}
  <h2>{{ year }} ({{ posts|length }})</h2>
  <ul>{% for post in posts %}<li><a href="{{ post.get_absolute_url }}">{{ post.title }}</a></li>{% endfor %}</ul>
{% endfor %}

🐞 خطاهای رایج و رفع آن‌ها

اشتباهات و خطاهای رایج این فصل را بشناسید تا سریع‌تر رفعشان کنید:

❌ خطای TemplateSyntaxError: Invalid block tag

تگی را بسته‌اید جا افتاده ({% endif %} یا {% endfor %}) یا نام تگ غلط است. خطای جنگو شماره خط را نشان می‌دهد — از همان‌جا شروع کنید.

❌ TemplateDoesNotExist برای base.html

پوشه templates ریشه در DIRS تنظیمات نیست: "DIRS": [BASE_DIR / "templates"] را در TEMPLATES اضافه کنید.

❌ متغیر چیزی چاپ نمی‌کند (خالی است)

قالب بی‌صداست: متغیر اشتباه/جای‌نیفتاده خطا نمی‌دهد! نام را در context ویو چک کنید. برای دیباگ، موقتاً {{ posts }} را چاپ کنید تا مقدارش را ببینید.

❌ HTML در خروجی به‌صورت متن دیده می‌شود (<p>)

escape خودکار کارش را کرده. اگر محتوا واقعاً HTML امن است: |safe یا linebreaks برای متن ساده با enter.

❌ extends کار نمی‌کند و کل صفحه خالی است

extends باید اولین تگ باشد و همه محتوا داخل blockها. متن بیرون block در فرزند نادیده گرفته می‌شود.

بخش ۱۰

🏋️ تمرین‌های تثبیت

پاسخ‌ها را اول خودتان بنویسید، بعد باز کنید:

🏋️ تمرین ۱ — فیلتر درست

سوال: کدام فیلتر برای هر نیاز؟ (الف) «۱۴۰۵/۰۴/۲۱» از DateTimeField (ب) ۳۰ حرف اول متن (ج) تبدیل enterها به پاراگراف (د) مقدار جایگزین برای None

پاسخ: الف → |date:"Y/m/d" • ب → |truncatechars:30 • ج → |linebreaks • د → |default:"—"

🏋️ تمرین ۲ — block یا include؟

سوال: برای (الف) هدر مشترک همه صفحات (ب) بخشی که هر صفحه محتوای متفاوتش را دارد، کدام مکانیزم؟

پاسخ: الف → include (قطعه ثابت مشترک) • ب → block (جای خالی که فرزند پر می‌کند). قاعده: «تکراری ثابت = include، متغیر = block».

🏋️ تمرین ۳ — امنیت

سناریو: کاربری در فیلد «بیوگرافی» پروفایلش می‌نویسد: <script>alert(1)</script>. در صفحه پروفایل چه می‌بینیم؟ اگر |safe گذاشته باشیم چه؟

پاسخ: حالت عادی: خودِ متن به‌صورت escape‌شده (بی‌خطر) نمایش داده می‌شود. با |safe: اسکریپت اجرا می‌شود = حمله XSS موفق. نتیجه: روی داده کاربر هرگز |safe نزنید.

بخش ۱۱

📝 آزمون تعاملی فصل

پرسش‌های چهارگزینه‌ای زیر را پاسخ دهید؛ بلافاصله بعد از انتخاب، پاسخ درست و توضیحش را می‌بینید. حد نصاب قبولی ۶۰٪ است و بهترین نمره‌تان ذخیره می‌شود.

۱) کدام نوشته در قالب جنگو یک «فیلتر» است؟

💡 فیلترها با | بعد از متغیر می‌آیند؛ فراخوانی متد با پرانتز در زبان قالب مجاز نیست.

۲) تگ extends چه محدودیتی برای فایل فرزند می‌سازد؟

💡 در فرزندِ extends، هر چیزی بیرون از {% block %} نادیده گرفته می‌شود؛ ساختار کلی از والد می‌آید.

۳) Auto-escaping از چه حمله‌ای جلوگیری می‌کند؟

💡 escape کردن < > & باعث می‌شود HTML/JS تزریق‌شده در داده کاربر اجرا نشود، فقط نمایش داده شود.

۴) در حلقه for، برای حالت «فهرست خالی» از چه استفاده می‌شود؟

💡 شاخه {% empty %}...{% endfor %} وقتی فهرست خالی باشد رندر می‌شود.

۵) forloop.counter از چه عددی شروع می‌شود؟

💡 counter از ۱ و counter0 از ۰ شروع می‌شود؛ first/last هم بولی‌اند.

۶) چرا {{ post.comments.count }} پرانتز ندارد؟

💡 جست‌وجوی نقطه‌ای قالب، ویژگی/متد/کلید/ایندکس را امتحان و متدهای بدون آرگومان را خودکار فراخوانی می‌کند.
بخش ۱۲

🏗️ پروژه عملی فصل

پروژه: «قالب کامل وبلاگ» — مجموعه قالب‌های وبلاگ را با ارث‌بری و اجزای مشترک بازنویسی کنید.

  • base.html با blockهای title/content/scripts + navbar و footer به‌صورت include.
  • post_list با کارت پست‌ها + pagination partial + حالت خالی.
  • post_detail با متا، برچسب‌ها، نظرات و مطالب مرتبط.
  • صفحه‌های خطای سفارشی 404.html و 500.html در templates ریشه.
  • یک CSS ساده برای مرتب‌سازی ظاهر (فصل ۱۴ حرفه‌ای‌اش می‌کند).
💡 بازاستفاده‌پذیری هر قطعه‌ای که دو بار تکرار شد (کارت پست، پیام خطا، دکمه) را به partial تبدیل کنید. نام‌گذاری: templates/partials/post_card.html.

🎯 جمع‌بندی و دستاوردها

در این فصل یاد گرفتید:

  • {{ }} متغیر و فیلتر، {% %} تگ و منطق — زبان قالب عمداً ساده است.
  • فیلترهای پرکاربرد: date، truncatewords، linebreaks، default، length.
  • ارث‌بری: base.html + block؛ قطعه‌های مشترک با include.
  • page_obj همه امکانات صفحه‌بندی را در قالب می‌دهد.
  • Auto-escape سپر اصلی XSS است؛ |safe فقط برای محتوای اعتمادشده.
💡 ✨ یک‌جمله‌ای که باید یادتان بماند «قالب خوب = اسکلت مشترک (extends) + قطعه‌های کوچک (include) + صفر منطق تجاری.»

❓ سوالات متداول و گام بعدی

می‌توانم از Jinja2 استفاده کنم؟

بله؛ جنگو از چند موتور قالب پشتیبانی می‌کند و Jinja2 قابل فعال‌سازی است. ولی DTL برای بیشتر پروژه‌ها کافی و یکپارچه‌تر است (تگ csrf، url و... داخلی).

کجا قالب بگذارم: templates اپ یا ریشه؟

قالب‌های مخصوص اپ داخل app/templates/app/ (برای استفاده مجدد) و base/صفحات خطا/partials مشترک در templates/ ریشه. DIRS قبل از APP_DIRS جست‌وجو می‌شود — برای override قالب اپ‌های ثالث عالی است.

رندر قالب کند است؟

معمولاً خیر؛ گلوگاه واقعی تقریباً همیشه کوئری‌های دیتابیس است. برای قطعات پرهزینه، تگ {% cache %} در فصل ۱۹ معرفی می‌شود.
