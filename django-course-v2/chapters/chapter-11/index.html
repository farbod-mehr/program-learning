🔭 چشم‌انداز فصل: اهداف و جایگاه

در فصل ۸ فرم را دستی با request.POST خواندیم؛ حالا ابزار حرفه‌ای جنگو را یاد می‌گیریم که هم HTML فرم را می‌سازد، هم اعتبارسنجی می‌کند و هم داده تمیز (clean) تحویل می‌دهد.

اهداف یادگیری — پس از این فصل شما می‌توانید:

  • با forms.Form فیلد، ویجت و اعتبارسنج تعریف کنید.
  • الگوی استاندارد فرم در ویو (Bound/Unbound) را بنویسید.
  • متد clean_<field> و clean() برای اعتبارسنجی سفارشی بنویسید.
  • با ModelForm فرم را مستقیم از مدل بسازید و save() کنید.
  • خطاهای فرم را زیبا در قالب نمایش دهید.

جایگاه فصل: پایهٔ ثبت‌نام (فصل ۱۲)، CRUDهای CreateView (فصل ۹) و فرم‌های DRF (فصل ۲۲).

بخش ۳

🤔 سوالات محرک ذهنی

قبل از خواندن آموزش، چند لحظه به این سوال‌ها فکر کنید؛ حتی اگر جواب را نمی‌دانید، ذهنتان آماده دریافت آن می‌شود:

🤔 چرا اعتبارسنجی فقط در مرورگر (جاوااسکریپت) کافی نیست؟

چون کاربر می‌تواند جاوااسکریپت را خاموش کند یا با ابزارهایی مثل curl مستقیم به سرور درخواست بفرستد. اعتبارسنجی مرورگر برای تجربه کاربری است؛ اعتبارسنجی سرور برای امنیت و صحت داده — همیشه هر دو.

🤔 فرم Bound و Unbound یعنی چه؟

Unbound: فرم خالی برای اولین نمایش (بدون داده). Bound: فرمی که با داده (معمولاً POST) ساخته شده؛ می‌تواند is_valid شود و در صورت خطا، داده‌های قبلی و خطاها را نشان دهد.

🤔 ModelForm چه چیزی را از مدل «ارث» می‌برد؟

فیلدها، محدودیت‌ها (max_length و...)، اعتبارسنج‌های سطح مدل (مثل unique) و help_text. یعنی یک تعریف، دو جا استفاده: دیتابیس و فرم.

۵.۱ ساخت فرم با forms.Form

blog/forms.pyPython
from django import forms


class CommentForm(forms.Form):
    name = forms.CharField(
        label="نام شما", max_length=50,
        widget=forms.TextInput(attrs={"class": "form-control", "placeholder": "نام"}),
    )
    email = forms.EmailField(label="ایمیل", required=False)
    text = forms.CharField(
        label="متن نظر",
        widget=forms.Textarea(attrs={"rows": 4, "maxlength": 500}),
    )
    agree = forms.BooleanField(label="قوانین را پذیرفته‌ام")

فیلدهای رایج: CharField، EmailField، IntegerField، BooleanField، ChoiceField، DateField، FileField. هر فیلد هم ویجت (ظاهر HTML) دارد هم اعتبارسنج (منطق).

۵.۲ الگوی استاندارد فرم در ویو

ویوی فرم‌دارPython
from django.contrib import messages
from django.shortcuts import get_object_or_404, redirect, render

from .forms import CommentForm
from .models import Post


def add_comment(request, slug):
    post = get_object_or_404(Post, slug=slug)

    if request.method == "POST":
        form = CommentForm(request.POST)          # Bound
        if form.is_valid():
            data = form.cleaned_data               # داده تمیز و تبدیل‌شده
            post.comments.create(
                name=data["name"], text=data["text"],
            )
            messages.success(request, "نظر شما ثبت شد!")
            return redirect(post.get_absolute_url())  # PRG
    else:
        form = CommentForm()                       # Unbound

    return render(request, "blog/add_comment.html", {"form": form, "post": post})
📌 cleaned_data چیست؟ خروجی اعتبارسنجی: همه فیلدها به نوع درست تبدیل شده‌اند («۵» شده 5، رشته‌ها trim شده). هرگز مستقیم از request.POST برای ذخیره استفاده نکنید؛ فقط cleaned_data.

۵.۴ اعتبارسنجی سفارشی: clean_

فرم با منطق اختصاصیPython
from django import forms
from django.core.exceptions import ValidationError


class CommentForm(forms.Form):
    name = forms.CharField(max_length=50)
    text = forms.CharField(widget=forms.Textarea)
    website = forms.URLField(required=False)

    def clean_name(self):
        name = self.cleaned_data["name"].strip()
        if name.lower() in ("admin", "مدیر"):
            raise ValidationError("این نام رزرو شده است.")
        return name                        # حتماً مقدار را برگردانید!

    def clean(self):
        cleaned = super().clean()
        text = cleaned.get("text", "")
        if "http" in text and not cleaned.get("website"):
            self.add_error("website", "اگر لینک دارید، در فیلد سایت بنویسید.")
        return cleaned
  • clean_<field> — اعتبارسنجی یک فیلد.
  • clean() — منطق چندفیلدی (مقایسه رمز و تکرارش، تاریخ شروع/پایان).
  • اعتبارسنج‌های آماده: MinLengthValidator، RegexValidator و... در validators=[...].

۵.۵ ModelForm: فرم مستقیم از مدل

فرم ساخت/ویرایش پستPython
from django import forms

from .models import Post


class PostForm(forms.ModelForm):
    class Meta:
        model = Post
        fields = ("title", "slug", "body", "tags")   # یا exclude
        widgets = {
            "body": forms.Textarea(attrs={"rows": 10}),
        }
        labels = {"slug": "نشانی (انگلیسی)"}
        help_texts = {"slug": "مثلاً: hello-django"}

    def clean_title(self):
        title = self.cleaned_data["title"]
        if len(title) < 5:
            raise forms.ValidationError("عنوان حداقل ۵ نویسه باشد.")
        return title
ویو — یک فرم برای ساخت و ویرایشPython
def post_create(request):
    if request.method == "POST":
        form = PostForm(request.POST)
        if form.is_valid():
            post = form.save(commit=False)   # ذخیره نکن؛ اول تکمیل
            post.author = request.user
            post.save()
            form.save_m2m()                  # روابط چندبه‌چند حالا
            return redirect(post.get_absolute_url())
    else:
        form = PostForm()
    return render(request, "blog/post_form.html", {"form": form})


def post_edit(request, pk):
    post = get_object_or_404(Post, pk=pk, author=request.user)
    if request.method == "POST":
        form = PostForm(request.POST, instance=post)   # ← instance!
        if form.is_valid():
            form.save()
            return redirect(post.get_absolute_url())
    else:
        form = PostForm(instance=post)
    return render(request, "blog/post_form.html", {"form": form, "post": post})
⚠️ commit=False را بشناسید form.save(commit=False) شیء را می‌سازد ولی ذخیره نمی‌کند — فرصت می‌دهد فیلدهایی مثل author را از request.user ست کنید. اگر فرم M2M دارد، بعد از save() حتماً form.save_m2m() را صدا بزنید.

💻 مثال عملی

یک فرم تماس کامل با اعتبارسنجی چندفیلدی و ذخیره در مدل:

models و formsPython
class ContactMessage(models.Model):
    name = models.CharField(max_length=80)
    email = models.EmailField()
    subject = models.CharField(max_length=120)
    body = models.TextField()
    created_at = models.DateTimeField(auto_now_add=True)


class ContactForm(forms.ModelForm):
    confirm_email = forms.EmailField(label="تکرار ایمیل")

    class Meta:
        model = ContactMessage
        fields = ("name", "email", "subject", "body")

    def clean(self):
        cleaned = super().clean()
        if cleaned.get("email") != cleaned.get("confirm_email"):
            self.add_error("confirm_email", "ایمیل و تکرار آن یکی نیستند.")
        return cleaned
ویو و قالبPython
def contact(request):
    if request.method == "POST":
        form = ContactForm(request.POST)
        if form.is_valid():
            form.save()
            messages.success(request, "پیام شما ارسال شد 🌿")
            return redirect("pages:contact")
    else:
        form = ContactForm()
    return render(request, "pages/contact.html", {"form": form})

نکته امنیتی: ایمیل در مدل ذخیره می‌شود ولی confirm_email فیلد فرم-only است (در Meta.fields نیست) — مقایسه‌اش صرفاً اعتبارسنجی است.

💡 نکته طلاییکدهای بالا را خودتان تایپ و اجرا کنید؛ تایپ کردن رمز یادگیری است!

✅ پاسخ کارگاه ۲
clean_text ضد تبلیغPython
BANNED = ("تبلیغ", "خرید اینترنتی", "bit.ly")


def clean_text(self):
    text = self.cleaned_data["text"]
    lowered = text.lower()
    if any(word in text or word in lowered for word in BANNED):
        raise forms.ValidationError("نظر شما شامل محتوای تبلیغاتی است.")
    if "http://" in lowered or "https://" in lowered:
        raise forms.ValidationError("درج لینک در نظر مجاز نیست.")
    return text

این «فیلتر محتوای» ساده است؛ در پروژه‌های جدی، پاک‌سازی و بررسی دقیق‌تر (یا تأیید دستی توسط مدیر — فیلد approved فصل ۶) توصیه می‌شود.

✅ پاسخ کارگاه ۳
PostForm با slug خودکارPython
from django.utils.text import slugify


class PostForm(forms.ModelForm):
    class Meta:
        model = Post
        fields = ("title", "body", "tags")   # slug را از کاربر نگیریم!

    def save(self, commit=True):
        post = super().save(commit=False)
        if not post.slug:
            base = slugify(post.title, allow_unicode=True)
            slug, i = base, 1
            while Post.objects.filter(slug=slug).exists():
                i += 1
                slug = f"{base}-{i}"
            post.slug = slug
        if commit:
            post.save()
            self.save_m2m()
        return post

slugify با allow_unicode=True اسلاگ فارسی می‌سازد؛ حلقه، یکتایی را با افزودن شماره تضمین می‌کند.

بخش ۹

🐞 خطاهای رایج و رفع آن‌ها

اشتباهات و خطاهای رایج این فصل را بشناسید تا سریع‌تر رفعشان کنید:

❌ فرم همیشه نامعتبر است ولی نمی‌فهمم چرا

خطاها را ببینید! در قالب {{ form.errors }} یا در شل/دیباگ: form.errors.as_data(). رایج‌ترین علت: نام فیلد فرم با name ورودی HTML نمی‌خواند.

❌ خطای The 'post' field is required در ModelForm

فیلدی که در مدل null=False و بدون default است در فرم اجباری می‌شود. برای فیلدهای سیستمی (author، created_at) آن‌ها را از Meta.fields حذف یا با commit=False پر کنید.

❌ cleaned_data KeyError

در clean() به cleaned_data["field"] دسترسی مستقیم کرده‌اید ولی فیلد قبلاً رد شده. از cleaned.get("field") استفاده کنید.

❌ فرم با فایل (تصویر) آپلود نمی‌شود

دو نکته: ① در تگ form: enctype="multipart/form-data" ② در ویو: Form(request.POST, request.FILES). فایل‌ها در request.FILES جدا می‌آیند.

❌ پیام خطاها انگلیسی است

در settings: LANGUAGE_CODE = "fa" و USE_I18N=True. پیام‌های داخلی جنگو ترجمه فارسی دارند (فصل ۲۵).

🏋️ تمرین‌های تثبیت

پاسخ‌ها را اول خودتان بنویسید، بعد باز کنید:

🏋️ تمرین ۱ — انتخاب نوع فرم

سوال: برای هر مورد forms.Form یا ModelForm؟ (الف) فرم تماس (ذخیره در مدل) (ب) فرم جست‌وجو (ج) فرم ورود (د) فرم ثبت پست

پاسخ: الف → ModelForm (مدل ContactMessage) • ب → Form ساده (یا حتی GET دستی) • ج → فرم آماده AuthenticationForm (فصل ۱۲) • د → ModelForm.

🏋️ تمرین ۲ — clean یا clean_field؟

سوال: بررسی «تاریخ پایان باید بعد از تاریخ شروع باشد» در کدام متد؟

پاسخ: در clean() — چون به دو فیلد نیاز دارد. با self.add_error("end_date", ...) خطا را به فیلد درست نسبت دهید.

🏋️ تمرین ۳ — widget در برابر field

سوال: تفاوت forms.ChoiceField و forms.Select چیست؟

پاسخ: ChoiceField منطق است (اعتبارسنجی یکی از گزینه‌ها)؛ Select ویجت است (نمایش dropdown). ChoiceField به‌طور پیش‌فرض ویجت Select دارد؛ می‌توان به RadioSelect عوضش کرد.

بخش ۱۱

📝 آزمون تعاملی فصل

پرسش‌های چهارگزینه‌ای زیر را پاسخ دهید؛ بلافاصله بعد از انتخاب، پاسخ درست و توضیحش را می‌بینید. حد نصاب قبولی ۶۰٪ است و بهترین نمره‌تان ذخیره می‌شود.

۱) form.is_valid() چه می‌کند؟

💡 is_valid تمام اعتبارسنج‌ها (و clean_های سفارشی) را اجرا می‌کند؛ اگر همه قبول شدند cleaned_data آماده است.

۲) فرم Bound چه زمانی ساخته می‌شود؟

💡 دادن data به سازنده، فرم را Bound می‌کند؛ فرم Bound داده و خطاها را در رندر نگه می‌دارد.

۳) خروجی تمیز و تبدیل‌شده فرم کجاست؟

💡 cleaned_data فقط بعد از is_valid موفق وجود دارد؛ form.data همان ورودی خام (و نامطمئن) است.

۴) در ModelForm، نقش instance در فرم ویرایش چیست؟

💡 PostForm(request.POST, instance=post) یعنی همین رکورد را با داده جدید به‌روزرسانی کن؛ بدون instance، رکورد جدید ساخته می‌شود.

۵) form.save(commit=False) چه وقتی لازم است؟

💡 commit=False شیء ذخیره‌نشده برمی‌گرداند؛ پس از تکمیل فیلدها save() و در صورت M2M، save_m2m() صدا زده می‌شود.

۶) کدام گزینه درباره اعتبارسنجی سمت مرورگر درست است؟

💡 کلاینت قابل اعتماد نیست؛ forms جنگو لایه اطمینان سمت سرور است.

🏗️ پروژه عملی فصل

پروژه: «سامانه نظرات با فرم حرفه‌ای» — سیستم نظردهی وبلاگ را کاملاً فرم‌محور بازنویسی کنید.

  • CommentForm با اعتبارسنج‌های طول و ایمیل اختیاری.
  • clean_text ضد لینک/تبلیغ + پیام‌های فارسی.
  • ویوی PRG با messages.success/error.
  • نمایش field-by-field با classهای Bootstrapمانند و highlight خطاها.
  • فرم پست (ModelForm) با ساخت/ویرایش و slug خودکار.
💡 تست دستی فرم هر بار: یک‌بار خالی، یک‌بار داده غلط، یک‌بار داده درست submit کنید. سه مسیر ویو (GET، POST ناموفق، POST موفق) همه باید کار کنند.
بخش ۱۳

🎯 جمع‌بندی و دستاوردها

در این فصل یاد گرفتید:

  • فرم جنگو = تعریف فیلدها + اعتبارسنجی + رندر HTML در یک کلاس.
  • الگوی ویو: POST → Bound → is_valid → cleaned_data → PRG؛ GET → Unbound.
  • clean_<field> برای تک‌فیلد و clean() برای منطق چندفیلدی.
  • ModelForm فرم را از مدل مشتق می‌کند؛ instance برای ویرایش، commit=False برای تکمیل دستی.
  • فایل‌ها: request.FILES + enctype="multipart/form-data".
💡 ✨ یک‌جمله‌ای که باید یادتان بماند «هرگز به ورودی کاربر اعتماد نکن؛ forms جنگو همان لایه‌ای است که اعتماد را «اعتبارسنجی» می‌کند.»
بخش ۱۴

❓ سوالات متداول و گام بعدی

کریسپی‌فرم‌ها (crispy-forms) چیست؟

بسته django-crispy-forms رندر فرم را به قالب Bootstrap/Tailwind واگذار می‌کند و کد قالب را تمیزتر می‌سازد. برای شروع، حلقه {% for field in form %} کافی است.

Formset برای چه زمانی است؟

مجموعه فرم وقتی لازم است که تعداد نمونه‌ها پویا باشد: مثل «افزودن چند تصویر به یک محصول». مدیریت پیشوندهای فیلد و فرم‌های خالی/اضافی را خودش انجام می‌دهد.

چطور فیلد را فقط در ویرایش نشان دهم نه ایجاد؟

دو فرم مجزا (PostCreateForm/PostUpdateForm) یا حذف فیلد در __init__ بر اساس self.instance.pk. دو فرم صریح‌تر و خواناتر است.

📌 🧭 گام بعدی فرم‌ها آماده‌اند؛ حالا در فصل ۱۲ مهم‌ترین فرم‌های هر سایت را می‌سازیم: ثبت‌نام، ورود و خروج با سیستم احراز هویت داخلی جنگو.
