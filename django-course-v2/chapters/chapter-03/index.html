🔭 چشم‌انداز فصل: اهداف و جایگاه

تا الان فقط «اسکلت» داشتیم؛ از این فصل کد واقعی می‌نویسیم. اپ‌ها قلب سازمان‌دهی کد در جنگو هستند و هر ویو یک قدم به سمت ساختن سایت واقعی است.

اهداف یادگیری — پس از این فصل شما می‌توانید:

  • تفاوت پروژه و اپلیکیشن را توضیح دهید.
  • با startapp اپ بسازید و فایل‌هایش را بشناسید.
  • اپ را در INSTALLED_APPS ثبت کنید.
  • اولین ویوی تابعی را بنویسید و به یک URL وصل کنید.
  • صفحه «سلام دنیا»ی خودتان را در مرورگر ببینید!

🤔 سوالات محرک ذهنی

قبل از خواندن آموزش، چند لحظه به این سوال‌ها فکر کنید؛ حتی اگر جواب را نمی‌دانید، ذهنتان آماده دریافت آن می‌شود:

🤔 اگر سایتی «وبلاگ»، «فروشگاه» و «تماس با ما» دارد، چند اپ باید بسازیم؟

به‌طور کلاسیک سه اپ: blog، shop و pages. قاعده سرانگشتی: هر مسئولیت مستقل = یک اپ. مدل‌ها، ویوها و قالب‌های هر بخش داخل اپ خودش می‌ماند.

🤔 چرا جنگو اصرار دارد ویو یک «درخواست» بگیرد و «پاسخ» برگرداند؟

چون وب همین است! هر ویو در واقع کارخانه تبدیل درخواست به پاسخ است. این قرارداد ساده باعث می‌شود همه چیز (صفحه HTML، فایل، JSON) یک‌شکل مدیریت شود.

🤔 بدون ثبت اپ در INSTALLED_APPS چه می‌شود؟

جنگو اصلاً نمی‌فهمد اپ شما وجود دارد: مدل‌هایش مهاجرت نمی‌گیرند، قالب‌هایش پیدا نمی‌شوند و فرمان‌های مدیریتی‌اش کار نمی‌کنند.

بخش ۵

📖 آموزش گام‌به‌گام: مفاهیم

۵.۱ پروژه در برابر اپلیکیشن

پروژه = کل وب‌سایت: تنظیمات مشترک، پایگاه داده و ریشه URLها. اپ = یک ماژول با مسئولیت مشخص داخل پروژه: مثل اپ «وبلاگ» یا «نظرسنجی».

  • یک پروژه می‌تواند چند اپ داشته باشد.
  • یک اپ می‌تواند در چند پروژه استفاده مجدد شود (فلسفه اصلی اپ!).
  • اپ‌ها کنار هم در پوشه apps/ یا ریشه پروژه قرار می‌گیرند؛ در دوره ما کنار manage.py.

۵.۲ ساخت اپ و آناتومی آن

ساخت اپ وبلاگBash
python manage.py startapp blog
ساختار اپمتن
blog/
├── __init__.py
├── admin.py       ← ثبت مدل‌ها در پنل مدیریت (فصل ۶)
├── apps.py        ← کلاس پیکربندی اپ
├── migrations/    ← مهاجرت‌های پایگاه داده (فصل ۵)
├── models.py      ← مدل‌های داده (فصل ۴)
├── tests.py       ← تست‌ها (فصل ۲۰)
└── views.py       ← ویوها (منطق صفحه‌ها)

دو فایل دیگر را خودمان اضافه می‌کنیم چون جنگو به‌صورت پیش‌فرض نمی‌سازدشان: urls.py (مسیرهای مخصوص اپ) و پوشه templates/blog/ (قالب‌ها).

۵.۳ ثبت اپ در INSTALLED_APPS

در settings.py نام اپ را اضافه کنید:

config/settings.pyPython
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",
    # اپ‌های خودمان:
    "blog",
]

آن شش مورد اول، اپ‌های آماده خود جنگو هستند (پنل ادمین، احراز هویت، نشست‌ها و...). حالا اپ blog برای جنگو «وجود دارد».

۵.۴ اولین ویو و اتصال به URL

ویو تابعی ساده‌ترین شکل منطق صفحه است: یک درخواست می‌گیرد، یک پاسخ برمی‌گرداند:

blog/views.pyPython
from django.http import HttpResponse


def home(request):
    return HttpResponse("<h1>سلام از اولین ویوی من! 🌿</h1>")


def about(request):
    return HttpResponse("اینجا صفحه درباره ماست.")

حالا مسیریابی. اول در اپ، فایل blog/urls.py:

blog/urls.pyPython
from django.urls import path

from . import views

urlpatterns = [
    path("", views.home, name="home"),
    path("about/", views.about, name="about"),
]

و در ریشه پروژه، مسیرهای اپ را با include وصل می‌کنیم:

config/urls.pyPython
from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("", include("blog.urls")),
]
📌 جریان کار درخواست /about/ → از config/urls.py به blog.urls می‌رود (include) → با الگوی about/ مطابقت می‌کند → ویوی about اجرا و پاسخ برگردانده می‌شود. جزئیات کامل include و نام‌گذاری در فصل ۷.

۵.۵ از متن خام به صفحه HTML: render

HttpResponse برای متن ساده خوب است، ولی صفحه واقعی یعنی HTML. فعلاً یک نمونه سریع (فصل ۱۰ کامل توضیح می‌دهد):

blog/views.py — استفاده از قالبPython
from django.shortcuts import render


def home(request):
    context = {"title": "وبلاگ من", "posts_count": 3}
    return render(request, "blog/home.html", context)

فایل blog/templates/blog/home.html را بسازید:

blog/templates/blog/home.htmlHTML
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head><meta charset="utf-8"><title>{{ title }}</title></head>
<body>
  <h1>به {{ title }} خوش آمدید!</h1>
  <p>تعداد نوشته‌ها: {{ posts_count }}</p>
</body>
</html>

تابع render، قالب و بافت (دیکشنری داده) را ترکیب و HTML نهایی می‌سازد.

بخش ۶

💻 مثال عملی

یک اپ کامل «pages» با دو صفحه — مرحله‌به‌مرحله:

۱) ساخت و ثبت اپBash
python manage.py startapp pages
# سپس "pages" را به INSTALLED_APPS اضافه کنید
۲) ویوها — pages/views.pyPython
from django.shortcuts import render


def home(request):
    return render(request, "pages/home.html", {"name": "دنیای جنگو"})


def about(request):
    return render(request, "pages/about.html")
۳) مسیرها — pages/urls.py و اتصال در config/urls.pyPython
# pages/urls.py
from django.urls import path
from . import views

urlpatterns = [
    path("", views.home, name="home"),
    path("about/", views.about, name="about"),
]

# config/urls.py
urlpatterns = [
    path("admin/", admin.site.urls),
    path("", include("pages.urls")),
]
۴) قالب‌ها — pages/templates/pages/home.htmlHTML
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<head><meta charset="utf-8"><title>خانه</title></head>
<body>
  <h1>سلام {{ name }}! 🌿</h1>
  <a href="/about/">درباره ما</a>
</body>
</html>

سرور را اجرا کنید و / و /about/ را ببینید. اولین سایت دو صفحه‌ای شما ساخته شد! 🎉

💡 نکته طلاییکدهای بالا را خودتان تایپ و اجرا کنید؛ تایپ کردن رمز یادگیری است!
بخش ۷

🛠️ کارگاه عملی

۲۰ دقیقه وقت بگذارید و خودتان بسازید:

  1. کارگاه ۱: اپی به نام shop بسازید، ثبتش کنید و ویویی بنویسید که با HttpResponse متن «به فروشگاه خوش آمدید» را در مسیر /shop/ نشان دهد.
  2. کارگاه ۲: در همان اپ، ویوی product با render و یک قالب بسازید که نام محصول را از بافت بگیرد و نمایش دهد (مسیر: /shop/product/).
  3. کارگاه ۳: عمداً نام اپ را از INSTALLED_APPS حذف کنید و ببینید چه خطایی می‌بینید. سپس برگردانید.
بخش ۸

✅ پاسخ کامل کارگاه عملی

✅ پاسخ کارگاه ۱ — اپ shop
shop/views.pyPython
from django.http import HttpResponse


def shop_home(request):
    return HttpResponse("به فروشگاه خوش آمدید 🛍️")
shop/urls.pyPython
from django.urls import path
from . import views

urlpatterns = [
    path("", views.shop_home, name="shop_home"),
]

و در config/urls.py: path("shop/", include("shop.urls")), + ثبت "shop" در INSTALLED_APPS.

✅ پاسخ کارگاه ۲ — ویو با render
shop/views.pyPython
from django.shortcuts import render


def product(request):
    context = {"product_name": "لپ‌تاپ جنگویی"}
    return render(request, "shop/product.html", context)

قالب در shop/templates/shop/product.html با {{ product_name }}. مسیر: path("product/", views.product) داخل shop/urls.py.

✅ پاسخ کارگاه ۳ — نتیجه حذف از INSTALLED_APPS

با حذف نام اپ، قالب‌هایش پیدا نمی‌شوند: خطای TemplateDoesNotExist (برای کارگاه ۲) — چون جنگو پوشه templates اپ‌های ثبت‌نشده را جست‌وجو نمی‌کند. ویوهای HttpResponse-only ممکن است هنوز کار کنند (چون import مستقیم‌اند) ولی مدل‌ها و مهاجرت‌ها قطعاً از کار می‌افتند. درس: ثبت در INSTALLED_APPS یعنی «جنگو، این اپ را بشناس».

بخش ۹

🐞 خطاهای رایج و رفع آن‌ها

اشتباهات و خطاهای رایج این فصل را بشناسید تا سریع‌تر رفعشان کنید:

❌ خطای TemplateDoesNotExist

سه علت: ① اپ در INSTALLED_APPS ثبت نشده. ② مسیر قالب غلط است — ساختار درست: blog/templates/blog/home.html و در ویو: "blog/home.html" (پوشه templates دوبرابر ندارد!). ③ نام فایل اشتباه تایپ شده.

❌ صفحه 404 برای مسیری که نوشته‌ام

معمولاً include درست وصل نشده یا الگوی path اشتباه است. ترتیب مهم است: جنگو urlpatterns را از بالا به پایین امتحان می‌کند. همچنین اسلش انتهایی را چک کنید (about/ با about فرق دارد).

❌ خطای ModuleNotFoundError: No module named 'blog'

پوشه اپ هم‌سطح manage.py نیست (جایی دیگر ساخته‌اید) یا نام را اشتباه نوشته‌اید. manage.py را پیدا کنید و ببینید پوشه اپ کنارش هست یا نه.

❌ فراموشی کاما یا براکت در urlpatterns

SyntaxError با پیام روشن می‌دهد. هر path(...) را با کاما جدا کنید و آخرین ] را ببندید.

بخش ۱۰

🏋️ تمرین‌های تثبیت

پاسخ‌ها را اول خودتان بنویسید، بعد باز کنید:

🏋️ تمرین ۱ — مرز پروژه و اپ

سوال: برای سایتی با بخش‌های «خبر»، «ویدیو» و «کاربران»، ساختار پروژه/اپ را طراحی کنید.

پاسخ نمونه: یک پروژه (config) با سه اپ: news، video و accounts. تنظیمات و پایگاه داده مشترک در پروژه؛ هر بخش مدل/ویو/قالب خودش را در اپ خودش دارد.

🏋️ تمرین ۲ — ترتیب اجرا

سوال: مراحل ساخت یک صفحه جدید را مرتب کنید: نوشتن قالب / ساخت ویو / افزودن path / ثبت اپ.

پاسخ: ① ثبت اپ در INSTALLED_APPS → ② نوشتن ویو در views.py → ③ افزودن path در urls → ④ ساخت قالب و اتصالش به ویو با render. (ترتیب ۲ و ۴ قابل جابه‌جایی است.)

🏋️ تمرین ۳ — نام‌گذاری

سوال: چرا پیشنهاد می‌شود قالب‌ها را در templates/blog/ بگذاریم نه مستقیم templates/؟

پاسخ: چون جست‌وجوی قالب جنگو در همه اپ‌ها مشترک است؛ اگر دو اپ هر دو home.html داشته باشند، تداخل پیش می‌آید. پوشه همنام با اپ (namespace) از برخورد جلوگیری می‌کند.

بخش ۱۱

📝 آزمون تعاملی فصل

پرسش‌های چهارگزینه‌ای زیر را پاسخ دهید؛ بلافاصله بعد از انتخاب، پاسخ درست و توضیحش را می‌بینید. حد نصاب قبولی ۶۰٪ است و بهترین نمره‌تان ذخیره می‌شود.

۱) رابطه پروژه و اپلیکیشن در جنگو کدام است؟

💡 پروژه تنظیمات و اسکلت کل سایت را دارد؛ اپ‌ها اجزای مستقل و قابل استفاده مجدد داخل آن‌اند.

۲) کدام فایل را جنگو در startapp نمی‌سازد و معمولاً خودمان اضافه می‌کنیم؟

💡 urls.py مخصوص اپ (و پوشه templates) را خودمان می‌سازیم؛ بقیه با startapp ایجاد می‌شوند.

۳) یک ویوی تابعی در جنگو چه چیزی دریافت و چه چیزی برمی‌گرداند؟

💡 قرارداد ثابت جنگو: ویو = تابعی که HttpRequest می‌گیرد و HttpResponse (یا نتیجه render/redirect) برمی‌گرداند.

۴) اگر اپ در INSTALLED_APPS ثبت نشود، کدام مورد از کار می‌افتد؟

💡 جنگو اپ‌های ثبت‌نشده را نمی‌شناسد: مهاجرت مدل‌ها ساخته نمی‌شود و قالب‌هایش در جست‌وجو پیدا نمی‌شوند.

۵) تابع render چه ترکیبی را به پاسخ HTML تبدیل می‌کند؟

💡 render(request, template, context) قالب را با داده‌های بافت پر و پاسخ HTML می‌سازد.

۶) در config/urls.py، تابع include چه کاری می‌کند؟

💡 include("blog.urls") یعنی «بقیه مسیرها را از فایل urls همان اپ بخوان»؛ یعنی مسیریابی تکه‌تکه و منظم.
بخش ۱۲

🏗️ پروژه عملی فصل

پروژه: «سایت دو بخشی من» — یک پروژه با دو اپ واقعی بسازید: pages (صفحه‌های عمومی) و blog (مقالات).

  • اپ pages با صفحه‌های خانه و درباره (با render و قالب).
  • اپ blog با ویوی فهرست مقالات که فعلاً یک لیست پایتونی ساختگی (hardcode) را به قالب می‌دهد و با حلقه نمایش می‌دهد.
  • هر دو اپ در INSTALLED_APPS ثبت و با include به ریشه وصل شوند.
  • در همه قالب‌ها یک لینک مشترک بین صفحه‌ها بگذارید.
  • ساختار پوشه‌ها را در یادداشت‌ها رسم کنید.
💡 نگاه به آینده فهرست «ساختگی» مقالات در فصل ۴ جای خودش را به مدل و پایگاه داده واقعی می‌دهد — صبور باشید!
بخش ۱۳

🎯 جمع‌بندی و دستاوردها

در این فصل یاد گرفتید:

  • پروژه = کل سایت؛ اپ = ماژول مستقل با مسئولیت مشخص.
  • با startapp اپ ساختیم و نقش models.py، views.py، admin.py و migrations را شناختیم.
  • اپ را در INSTALLED_APPS ثبت کردیم.
  • اولین ویوهای تابعی با HttpResponse و render نوشتیم.
  • با path و include، ویوها را به URLها وصل کردیم.
💡 ✨ یک‌جمله‌ای که باید یادتان بماند «اپ = واحد سازمان‌دهی کد؛ ویو = تابعی که درخواست را به پاسخ تبدیل می‌کند؛ urls = نقشهٔ اتصال این دو.»
بخش ۱۴

❓ سوالات متداول و گام بعدی

نام اپ را فارسی یا با حرف بزرگ بگذارم؟

خیر! نام اپ باید شناسه معتبر پایتون باشد: حروف کوچک انگلیسی، بدون فاصله (مثل blog، shop، accounts). عنوان نمایشی فارسی را در قالب و پنل ادمین بگذارید.

چند اپ زیاد است؟

قاعده سفت‌وسختی ندارد. یک سایت کوچک با ۲ تا ۵ اپ نرمال است. وقتی دو اپ همیشه با هم تغییر می‌کنند، شاید باید یکی باشند؛ وقتی یک اپ دو مسئولیت مستقل دارد، شاید باید تقسیم شود.

می‌توانم همه چیز را در یک اپ بگذارم؟

فنی بله، ولی ساختار به‌هم می‌ریزد و استفاده مجدد از بین می‌رود. در پروژه‌های کوچکِ تمرینی اشکالی ندارد؛ برای پروژه جدی، تفکیک کنید.

📌 🧭 گام بعدی صفحه‌ها ساخته شدند ولی داده‌هایشان ساختگی است. در فصل ۴ با مدل‌ها و ORM، داده‌های واقعی را در پایگاه داده ذخیره و مدیریت می‌کنیم.
