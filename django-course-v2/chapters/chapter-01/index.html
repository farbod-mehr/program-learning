🤔 سوالات محرک ذهنی

قبل از خواندن آموزش، ۳۰ ثانیه به این سوال‌ها فکر کنید؛ حتی اگر جواب را نمی‌دانید، ذهنتان آماده دریافت آن می‌شود:

وقتی آدرس digikala.com را در مرورگر می‌زنید و Enter را فشار می‌دهید، تا دیدن صفحه چه اتفاقاتی می‌افتد؟

مرورگر یک درخواست HTTP به سرور دیجی‌کالا می‌فرستد؛ سرور (که احتمالاً با فریم‌ورکی مثل جنگو نوشته شده) درخواست را پردازش می‌کند، داده‌ها را از پایگاه داده می‌گیرد، صفحه HTML را می‌سازد و به‌عنوان پاسخ برمی‌گرداند. مرورگر هم آن را نمایش می‌دهد. کل این رفت‌وبرگشت معمولاً زیر یک ثانیه طول می‌کشد!

چرا اینستاگرام، اسپاتیفای و پینترست برای بک‌اندشان پایتون/جنگو را انتخاب کردند؟

چون جنگو سرعت توسعه فوق‌العاده‌ای دارد: احراز هویت، پنل مدیریت، امنیت و کار با پایگاه داده آماده است و تیم می‌تواند به‌جای چرخ‌اختراع‌های تکراری، روی منطق تجاری محصول تمرکز کند. مقیاس‌پذیری خوب و اکوسیستم غنی پایتون هم دلایل بعدی‌اند.

به نظر شما «پروژه» و «اپلیکیشن» در جنگو چه فرقی دارند؟

پروژه (Project) کل وب‌سایت با تنظیمات مشترک است؛ اپلیکیشن (App) یک جزء مستقل داخل پروژه با یک مسئولیت مشخص (مثل بخش وبلاگ یا فروشگاه). یک پروژه می‌تواند چند اپ داشته باشد و هر اپ می‌تواند در چند پروژه استفاده شود. جزئیات کامل در فصل ۳.

📖 آموزش گام‌به‌گام: مفاهیم

۵.۱ وب چطور کار می‌کند؟ (مدل درخواست و پاسخ)

وب بر پایه یک گفت‌وگوی ساده ساخته شده: «درخواست بده، پاسخ بگیر». برنامه‌ای که شما استفاده می‌کنید (مرورگر، اپ موبایل و...) کلاینت نام دارد و رایانه‌ای که سایت روی آن اجرا می‌شود سرور. زبان مشترک این دو، پروتکل HTTP است.

  1. شما نشانی‌ای مثل example.com/blog/ (یک URL) را وارد می‌کنید.
  2. مرورگر یک درخواست (Request) به سرور می‌فرستد.
  3. سرور درخواست را بررسی می‌کند، داده لازم را از پایگاه داده می‌گیرد و صفحه را می‌سازد.
  4. سرور یک پاسخ (Response) برمی‌گرداند که شامل کد وضعیت و محتوای HTML است.
  5. مرورگر HTML را رندر می‌کند و شما صفحه را می‌بینید. 🎉
📌 کدهای وضعیت پرکاربرد را همین‌جا حفظ کنید 200 = موفق • 301/302 = انتقال (Redirect) • 404 = پیدا نشد • 403 = دسترسی مجاز نیست • 500 = خطای داخلی سرور. در فصل ۸ عملاً با همه‌شان کار می‌کنید.

۵.۲ فریم‌ورک چیست و چرا جنگو؟

ساختن یک وب‌سایت واقعی یعنی هزاران کار تکراری: مدیریت URLها، اتصال به پایگاه داده، ساخت فرم‌ها، جلوگیری از حملات امنیتی، مدیریت ورود کاربران، پنل مدیریت و... فریم‌ورک تمام این کارهای مشترک را یک‌بار و به‌صورت استاندارد انجام داده و شما فقط منطق مخصوص سایت خودتان را می‌نویسید.

جنگو یک فریم‌ورک سطح‌بالا بر پایه پایتون است؛ یعنی با کمترین کد، بیشترین امکانات را می‌دهد. شعار رسمی‌اش هم همین است: «فریم‌ورکی برای کمال‌گراها با مهلت تحویل فوری».

جمع‌بندی مقایسه: برای APIهای خیلی سبک یا میکروسرویس‌ها، Flask و FastAPI عالی‌اند؛ اما برای یک وب‌سایت کامل (وبلاگ، فروشگاه، پلتفرم آموزشی...) جنگو با اختلاف سریع‌ترین و امن‌ترین مسیر است — چون «باتری‌ها همراهش هست» (Batteries Included).

۵.۳ معماری MTV: نقشهٔ ذهنی جنگو

جنگو کد شما را به سه لایه تقسیم می‌کند تا هر بخش یک مسئولیت مشخص داشته باشد:

  • 🗄️ مدل (Model) — داده: ساختار جدول‌ها و ارتباطشان با پایگاه داده (فایل models.py).
  • 🎨 قالب (Template) — ظاهر: فایل‌های HTML با جای‌خالی‌های پویا.
  • 🎯 ویو (View) — منطق: درخواست را می‌گیرد، از مدل داده می‌گیرد و با قالب، پاسخ می‌سازد.
🧩 MTV در برابر MVC احتمالاً الگوی معروف MVC (مدل-ویو-کنترلر) را شنیده‌اید. در جنگو، «ویو»یِ MVC نقش کنترلر را دارد و «قالب» نقش ویو را؛ برای همین نامش را MTV گذاشته‌اند. مفهوم یکی است، فقط نام‌گذاری جنگویی است.

جریان یک درخواست در جنگو:

جریان درخواست: از مرورگر تا پاسخمفهومی
مرورگر (کلاینت)
   │  ۱. درخواست: GET /blog/5/
   ▼
urls.py ── ۲. مسیریابی: این URL مال کدام ویو است؟
   ▼
views.py ── ۳. منطق: ویو اجرا می‌شود
   │        ۴. داده: از مدل (پایگاه داده) پست شماره ۵ را می‌گیرد
   ▼
template ── ۵. نمایش: داده داخل قالب HTML قرار می‌گیرد
   ▼
پاسخ (Response) ── ۶. HTML نهایی به مرورگر برمی‌گردد 🎉

۵.۴ نگاهی به کد: یک ویو چقدر ساده است؟

هنوز چیزی نصب نکرده‌ایم، ولی ببینید ساده‌ترین ویوی دنیا در جنگو چه شکلی است (فصل ۳ عملاً می‌سازیمش):

views.py — ساده‌ترین ویوی جنگوPython
from django.http import HttpResponse

def hello(request):
    """یک درخواست می‌گیرد و یک پاسخ متنی برمی‌گرداند."""
    return HttpResponse("سلام جنگو! 🌿")

و اتصالش به یک نشانی، در فایل مسیرها:

urls.py — مسیریابیPython
from django.urls import path
from . import views

urlpatterns = [
    path("", views.hello, name="hello"),  # نشانی اصلی → ویوی hello
]
⚠️ توجه کدهای بالا فقط برای آشنایی‌اند؛ قبل از فصل ۲ (نصب) اجراشان نکنید. هدف این است که ببینید هر صفحه = یک URL + یک ویو + (معمولاً) یک قالب.

۵.۵ اکوسیستم و تاریخچه جنگو

جنگو در سال ۲۰۰۳ در روزنامه Lawrence Journal-World برای ساخت سریع سایت خبری متولد شد و ۲۰۰۵ متن‌باز منتشر شد. از آن روز، اینستاگرام، پینترست، اسپاتیفای (بخش‌هایی)، موزیلا و هزاران سایت ایرانی رویش ساخته شده‌اند. اجزای اصلی اکوسیستم:

  • ORM — کار با پایگاه داده به‌جای SQL، با کد پایتون.
  • Admin Panel — پنل مدیریت آماده، ساخته‌شده از روی مدل‌های شما.
  • Migration — نسخه‌بندی و اعمال خودکار تغییرات ساختار پایگاه داده.
  • سیستم احراز هویت داخلی — کاربر، گروه، مجوز، ورود/خروج.
  • DRF — ساخت API حرفه‌ای (فصل‌های ۲۲ و ۲۳).
  • SQLite — پایگاه داده پیش‌فرض برای توسعه؛ در تولید معمولاً PostgreSQL.

مفاهیم پروژه و اپلیکیشن را هم همین‌جا گوشه ذهن داشته باشید: پروژه = کل سایت (تنظیمات در settings.py)، اپ = یک ماژول مستقل داخلش. فصل ۳ کامل می‌سازیمشان.

💻 مثال عملی

چون هنوز نصب نکرده‌ایم، مثال عملی این فصل «پیش‌نمایش دستورات» است؛ همین ۴ قدم در فصل ۲ واقعاً اجرا می‌شوند. الان فقط ببینید مسیر چقدر کوتاه است:

گام ۱ — نصب جنگو داخل محیط مجازیBash
python -m venv .venv            # ساخت محیط مجازی
source .venv/bin/activate       # فعال‌سازی (لینوکس/مک)
pip install django              # نصب جنگو
گام ۲ — ساخت پروژه و اجرای سرورBash
django-admin startproject mysite   # ساخت پروژه
cd mysite
python manage.py runserver         # اجرای سرور توسعه
گام ۳ — مشاهده نتیجهمرورگر
http://127.0.0.1:8000/   # 🎉 صفحه خوش‌آمدگویی جنگو

تحلیل آنچه دیدید (با دانش همین فصل):

  • pip install django → با pip بسته جنگو را از مخزن پایتون گرفتیم.
  • startproject → اسکلت پروژه شامل settings.py و manage.py ساخته شد.
  • runserver → سرور توسعه بالا آمد؛ حالا مرورگر شما کلاینت است و یک درخواست به این سرور می‌فرستد و پاسخ می‌گیرد.
💡 نکته طلاییدر فصل ۲ این دستورات را خودتان تایپ و اجرا کنید؛ تایپ کردن رمز یادگیری است!

🛠️ کارگاه عملی

بدون نصب و کدنویسی — فقط با فکر و کاغذ (یا بخش یادداشت‌ها). حداقل ۱۰ دقیقه خودتان تلاش کنید و بعد سراغ بخش ۸ بروید:

  1. کارگاه ۱: فرض کنید کاربر در سایت فروشگاهی روی «افزودن به سبد خرید» کلیک می‌کند. جریان کامل را در ۵ مرحله بنویسید: چه کسی درخواست می‌فرستد؟ سرور چه می‌کند؟ پاسخ چیست؟
  2. کارگاه ۲: برای یک «سایت وبلاگ شخصی»، مشخص کنید کدام قسمت مدل است، کدام قالب و کدام ویو: (الف) جدول پست‌ها در پایگاه داده، (ب) صفحه HTML فهرست پست‌ها، (ج) کدی که پست‌ها را می‌گیرد و صفحه را می‌سازد.
  3. کارگاه ۳: سه دلیل بنویسید که چرا یک استارتاپ برای ساخت MVP محصولش، جنگو را به «نوشتن از صفر با پایتون خالص» ترجیح می‌دهد.
بخش ۸

✅ پاسخ کامل کارگاه عملی

پاسخ کارگاه ۱ — جریان «افزودن به سبد خرید»
  1. مرورگر (کلاینت) با کلیک روی دکمه، یک درخواست (معمولاً POST) به URL مربوطه مثل /cart/add/7/ می‌فرستد.
  2. سرور جنگو از روی فایل urls.py می‌فهمد این نشانی به کدام ویو وصل است (مسیریابی).
  3. ویو اجرا می‌شود: محصول شماره ۷ را از مدل/پایگاه داده پیدا می‌کند و به سبد خرید کاربر (در نشست او) اضافه می‌کند.
  4. ویو یک پاسخ می‌سازد: یا صفحه سبد خرید را رندر می‌کند یا کاربر را به صفحه سبد هدایت (Redirect) می‌کند.
  5. مرورگر پاسخ را نمایش می‌دهد و کاربر سبد به‌روز‌شده را می‌بیند؛ کد وضعیت ۲۰۰ یا ۳۰۲.
پاسخ کارگاه ۲ — اجزای MTV در سایت وبلاگ
  • (الف) جدول پست‌ها در پایگاه داده ← مدل (Model): ساختار داده (عنوان، متن، تاریخ، نویسنده) را نگه می‌دارد.
  • (ب) صفحه HTML فهرست پست‌ها ← قالب (Template): فقط ظاهر و جای‌خالی داده‌ها.
  • (ج) کدی که پست‌ها را می‌گیرد و صفحه را می‌سازد ← ویو (View): منطق اتصال مدل به قالب.
پاسخ کارگاه ۳ — چرا جنگو برای MVP؟
  1. سرعت توسعه: احراز هویت، پنل ادمین، فرم‌ها و کار با پایگاه داده آماده‌اند؛ MVP در هفته‌ها ساخته می‌شود نه ماه‌ها.
  2. امنیت پیش‌فرض: محافظت داخلی در برابر CSRF، XSS، تزریق SQL — چیزی که در کدنویسی از صفر، تازه‌کارها معمولاً فراموش می‌کنند.
  3. ساختار و نگهداری: معماری MTV و مستندات عالی یعنی کد تمیز، قابل توسعه و استخدام نیروی آشنا به جنگو راحت‌تر.

🐞 خطاهای رایج و رفع آن‌ها

اشتباهات رایج تازه‌کاران در همین مرحله مفهومی (و اولین قدم‌های فصل بعد):

❌ اشتباه ۱: «جنگو یک زبان برنامه‌نویسی است!»

جنگو فریم‌ورک است، نه زبان؛ زبانش پایتون است. اگر پایتون بلد نیستید، هم‌زمان با دوره کمی مبانی پایتون هم تمرین کنید.

❌ اشتباه ۲: قاطی کردن «پروژه» و «اپ»

پروژه کل سایت است و اپ بخشی از آن. startproject یک‌بار برای کل سایت اجرا می‌شود، ولی startapp به تعداد بخش‌های سایت (وبلاگ، فروشگاه و...).

❌ خطای 'django-admin' is not recognized (فصل بعد)

یعنی جنگو نصب نیست یا محیط مجازی فعال نشده. راه‌حل: pip install django داخل venv فعال. جزئیات کامل در فصل ۲.

❌ خطای Port 8000 is already in use (فصل بعد)

یک سرور دیگر روی پورت ۸۰۰۰ در حال اجراست. یا ببندیدش، یا پورت دیگری بدهید: python manage.py runserver 8080.

🚨 هشدار مهم برای آینده runserver فقط برای توسعه است. در مرحله استقرار (فصل ۲۶) حتماً از Gunicorn پشت Nginx استفاده می‌شود — الان فقط بدانید که چنین چیزی هست.
بخش ۱۰

🏋️ تمرین‌های تثبیت

پاسخ‌ها را اول خودتان بنویسید، بعد باز کنید:

تمرین ۱ — هر واژه را به تعریفش وصل کنید

سوال: (۱) ORM   (۲) Template   (۳) View   (۴) URL   →  (الف) منطق پردازش درخواست   (ب) نشانی هر صفحه   (ج) ظاهر HTML صفحه   (د) کار با پایگاه داده با کد پایتون

پاسخ: ۱→د، ۲→ج، ۳→الف، ۴→ب

تمرین ۲ — کد وضعیت مناسب را انتخاب کنید

سوال: (الف) صفحه با موفقیت نمایش داده شد (ب) کاربر رمز عبور را اشتباه زد و به صفحه ورود برگشت (ج) پستی که دنبالش بودیم وجود ندارد (د) باگ در کد ویو باعث خرابی شد

پاسخ: الف→200، ب→302 (انتقال به صفحه ورود)، ج→404، د→500

تمرین ۳ — معماری MTV را به رستوران تشبیه کنید

پاسخ نمونه: مدل = آشپزخانه و مواد اولیه (داده)، ویو = گارسون (سفارش/درخواست را می‌گیرد، به آشپزخانه می‌برد و نتیجه را برمی‌گرداند)، قالب = چیدمان و تزیین بشقاب (نمایش). مشتری (مرورگر) فقط بشقاب نهایی را می‌بیند!

بخش ۱۱

📝 آزمون تعاملی فصل

۶ پرسش چهارگزینه‌ای؛ بلافاصله بعد از انتخاب، پاسخ درست و توضیحش را می‌بینید. حد نصاب قبولی ۶۰٪ است و بهترین نمره‌تان ذخیره می‌شود. پرسش‌های شک‌برانگیز را با 🚩 نشان کنید تا بعداً مرورشان کنید.

۱) جنگو (Django) دقیقاً چیست؟

💡 جنگو یک فریم‌ورک وب است که با پایتون نوشته می‌شود؛ یعنی ابزارهایی آماده برای ساخت سریع وب‌سایت فراهم می‌کند، نه زبان یا پایگاه داده.

۲) در معماری MTV، وظیفهٔ اصلی «مدل» (Model) چیست؟

💡 مدل = لایهٔ داده: ساختار جدول‌ها، فیلدها و روابط را تعریف و از طریق ORM با پایگاه داده گفت‌وگو می‌کند. ظاهر کارِ قالب و منطق کارِ ویو است.

۳) در مدل ارتباط وب، مرورگر شما چه نقشی دارد و چه چیزی به سرور می‌فرستد؟

💡 مرورگر کلاینت است: درخواست می‌فرستد و پاسخ را دریافت و نمایش می‌دهد. سرور هم برعکس.

۴) کد وضعیت HTTP شمارهٔ 404 یعنی چه؟

💡 404 = پیدا نشد. موفقیت 200، خطای سرور 500 و انتقال 301/302 است. در فصل ۸ با get_object_or_404 عملاً می‌سازیمش.

۵) رابطهٔ «پروژه» و «اپلیکیشن» در جنگو کدام است؟

💡 یک پروژه (با settings مشترک) می‌تواند چند اپ داشته باشد؛ مثلاً اپ «وبلاگ» و اپ «فروشگاه» در یک سایت. هر اپ هم می‌تواند در پروژه‌های دیگر استفاده مجدد شود.

۶) برای ساخت Web API (مثلاً برای اپ موبایل) روی جنگو، ابزار استاندارد اکوسیستم کدام است؟

💡 DRF جعبه‌ابزار رسمی ساخت API در جنگوست (فصل‌های ۲۲ و ۲۳). سلری برای کارهای پس‌زمینه، Nginx وب‌سرور و Redis حافظه نهان/بروکر است.
بخش ۱۲

🏗️ پروژه عملی فصل

پروژه: «نقشهٔ معماری وب‌سایت رؤیاها» — یک سایت که دوست دارید بسازید (وبلاگ، فروشگاه، پلتفرم آموزشی...) را انتخاب کنید و روی کاغذ طراحی‌اش کنید:

  • نام سایت و هدفش را در یک جمله بنویسید.
  • ۳ صفحه اصلی‌اش را فهرست کنید (مثلاً: خانه، فهرست محصولات، صفحه محصول).
  • برای هر صفحه یک URL پیشنهادی بنویسید (مثلاً /products/7/).
  • مشخص کنید در هر صفحه چه داده‌ای لازم است (→ مدل‌های آینده) و چه چیزی نمایش داده می‌شود (→ قالب‌های آینده).
  • بنویسید کدام بخش‌ها می‌توانند اپهای جدا باشند (مثلاً اپ «فروشگاه» و اپ «وبلاگ»).
🎯 چرا این پروژه مهم است؟ این نقشه، دقیقاً همان چیزی است که از فصل ۳ به بعد واقعاً می‌سازید؛ در فصل‌های ۴ (مدل)، ۷ (URL) و ۱۰ (قالب) اجزای همین نقشه یکی‌یکی پیاده می‌شوند. آن را در بخش یادداشت‌ها (بخش ۱۶) ذخیره کنید!
بخش ۱۳

🎯 جمع‌بندی و دستاوردها

در این فصل یاد گرفتید:

  • وب = گفت‌وگوی کلاینت و سرور با پروتکل HTTP در قالب درخواست/پاسخ.
  • فریم‌ورک یعنی ابزار آمادهٔ کارهای تکراری؛ جنگو «فریم‌ورک کامل» (Batteries Included) دنیای پایتون است.
  • معماری MTV: مدل (داده) + قالب (ظاهر) + ویو (منطق)؛ جریان هر درخواست: URL → ویو → مدل → قالب → پاسخ.
  • اکوسیستم جنگو: ORM، Admin، مهاجرتها، احراز هویت داخلی و DRF.
  • تفاوت پروژه و اپ و کدهای مهم وضعیت HTTP.
✨ یک‌جمله‌ای که باید یادتان بماند «جنگو = پایتون + ساختار آماده؛ هر صفحه یعنی یک URL که به یک ویو وصل است و ویو با مدل و قالب، پاسخ می‌سازد.»
بخش ۱۴

❓ سوالات متداول و گام بعدی

برای این دوره چقدر پایتون بلد باشم کافی است؟

در حد متغیر، شرط، حلقه، تابع و لیست/دیکشنری. هر جای دوره که به مفهوم پایتونی برخورید، همان‌جا در حد نیاز توضیح داده می‌شود. فصل ۲ هم یک مرور فشرده دارد.

جنگو قدیمی نشده؟ هنوز بازار کار دارد؟

اتفاقاً برعکس! جنگو با نسخه‌های ۵.x و ۶.0 فعال‌تر از همیشه است و در ایران و جهان تقاضای استخدام بالایی دارد (اینستاگرام و اسپاتیفای هنوز رویش می‌سازند). فصل ۲۹ ویژگی‌های جدید و فصل ۳۰ نقشه راه بازار کار را دارد.

با موبایل هم می‌شود دوره را خواند؟

بله، قالب کاملاً واکنش‌گراست. فقط برای «مثال عملی» و کارگاه‌های کدنویسی به کامپیوتر نیاز دارید؛ بخش‌های مفهومی را می‌توانید با موبایل هم پیش بروید.

🧭 گام بعدی حالا که نقشه راه را در دست دارید، وقت نصب و راه‌اندازی است: در فصل ۲ پایتون و جنگو را نصب می‌کنیم، اولین پروژه را می‌سازیم و سرور توسعه را اجرا می‌کنیم. قبلش، آزمون این فصل را بدهید و دکمه «این فصل را تمام کردم» را بزنید!
