🧭 URLها و مسیریابی (Routing)

کامل‌ترین آموزش مسیریابی: تابع path و تبدیل‌کننده‌های نوع، پارامترهای پویا، include، نام‌گذاری و reverse، فضای نام و re_path — با مثال‌های واقعی وبلاگ.

بخش ۱

🔭 چشم‌انداز فصل: اهداف و جایگاه

URLها دروازه ورود به سایت شما هستند. در این فصل از «/» ساده به مسیرهای پویا و حرفه‌ای مثل /blog/2026/hello-django/ می‌رسیم و الگوهای نام‌گذاری استاندارد صنعت را یاد می‌گیریم.

اهداف یادگیری — پس از این فصل شما می‌توانید:

  • با تابع path() و تبدیل‌کننده‌های int، str، slug و uuid مسیر پویا بسازید.
  • پارامتر مسیر را در ویو دریافت کنید.
  • مسیریابی را با include() بین اپ‌ها تقسیم کنید.
  • با name و reverse، URLها را از کد و قالب ارجاع دهید.
  • با re_path الگویregex بنویسید و بدانید کجا لازم است.

جایگاه فصل: پایهٔ همه فصل‌های ویو (۸ و ۹) و API (۲۲ و ۲۳). الگوهای این فصل در تمام پروژه‌های دوره تکرار می‌شود.

بخش ۳

🤔 سوالات محرک ذهنی

قبل از خواندن آموزش، چند لحظه به این سوال‌ها فکر کنید؛ حتی اگر جواب را نمی‌دانید، ذهنتان آماده دریافت آن می‌شود:

🤔 چرا /blog/7/ بهتر از /blog/post.php?id=7 است؟

خوانایی برای کاربر، سئو بهتر برای موتورهای جست‌وجو و انعطاف برای ما: جنگو پشت همین URL تمیز، شناسه را به ویو می‌دهد. به این‌ها «URLهای زیبا» (Pretty URLs) می‌گویند.

🤔 اگر دو الگوی مسیر با یک URL مطابقت کنند، کدام برنده است؟

اولین الگو در ترتیب urlpatterns. جنگو از بالا به پایین امتحان می‌کند و به اولین تطبیق، ویو را صدا می‌زند. برای همین الگوهای خاص‌تر را بالاتر می‌گذارند.

🤔 چرا باید به مسیرها name بدهیم و در قالب از {% url %} استفاده کنیم؟

تا اگر روزی نشانی را عوض کردید (مثلاً /blog/ شد /articles/)، فقط urls.py عوض شود؛ همه لینک‌های قالب‌ها و کدها خودکار به‌روز می‌مانند. Hardcode کردن URL بدهی فنی است.

بخش ۵

📖 آموزش گام‌به‌گام: مفاهیم

۵.۱ تابع path و تبدیل‌کننده‌های نوع

هر الگو سه جزء دارد: رشته مسیر، ویو و نام اختیاری. داخل رشته مسیر می‌توان «گرفتنی» (capture) با تبدیل‌کننده نوع گذاشت:

blog/urls.pyPython
from django.urls import path

from . import views

urlpatterns = [
    path("", views.post_list, name="post_list"),
    path("post/<int:pk>/", views.post_detail, name="post_detail"),
    path("post/<slug:slug>/", views.post_by_slug, name="post_by_slug"),
    path("author/<int:pk>/", views.author_detail, name="author_detail"),
]

تبدیل‌کننده‌های داخلی:

  • str — هر متن بدون اسلش (پیش‌فرض).
  • int — فقط عدد صحیح مثبت؛ به ویو int می‌دهد.
  • slug — حروف، رقم، خط تیره و زیرخط.
  • uuid — شناسه یکتای استاندارد.
  • path — هر متنی با اسلش (برای مسیر فایل).

۵.۲ دریافت پارامتر در ویو

هر چه در <...> گرفته شود، به‌عنوان آرگومان کلیدواژه‌ای به ویو پاس می‌شود — نام‌ها باید یکی باشند:

blog/views.pyPython
from django.shortcuts import get_object_or_404, render

from .models import Post


def post_detail(request, pk):
    post = get_object_or_404(Post, pk=pk, published=True)
    return render(request, "blog/post_detail.html", {"post": post})


def post_by_slug(request, slug):
    post = get_object_or_404(Post, slug=slug, published=True)
    return render(request, "blog/post_detail.html", {"post": post})
📌 get_object_or_404 یعنی چه؟ رکورد را پیدا کن؛ اگر نبود، به‌جای خطای ۵۰۰، صفحه 404 استاندارد نشان بده. تقریباً همیشه در ویوهای جزئیات از آن استفاده می‌شود.

۵.۳ include و سازمان‌دهی چند اپی

هر اپ urls.py خودش را دارد و ریشه پروژه آن‌ها را با include زیر «پیشوندهای مسیر» می‌چسباند:

config/urls.pyPython
from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("blog/", include("blog.urls")),
    path("shop/", include("shop.urls")),
    path("", include("pages.urls")),
]

نتیجه: /blog/post/5/ = پیشوند blog/ از ریشه + الگوی post/<int:pk>/ از اپ. با این تقسیم، هر تیم/اپ مسیرهای خودش را مستقل مدیریت می‌کند.

۵.۴ name، reverse و تگ url

به هر مسیر نام بدهید و هیچ‌جا URL را hardcode نکنید:

ارجاع نام‌ها در پایتون و قالبPython
# در پایتون:
from django.urls import reverse
from django.shortcuts import redirect

url = reverse("post_detail", args=[post.pk])       # "/blog/post/5/"
url = reverse("post_by_slug", kwargs={"slug": "hello"})
return redirect("post_list")                        # redirect با نام!
در قالب‌ها (فصل ۱۰ کامل‌تر)HTML
<a href="{% url 'post_list' %}">همه نوشته‌ها</a>
<a href="{% url 'post_by_slug' post.slug %}">{{ post.title }}</a>
⚠️ نام یکتا نام‌ها در کل پروژه باید یکتا باشند، وگرنه reverse گیج می‌شود. قرارداد حرفه‌ای: استفاده از فضای نام اپ — در ادامه.

۵.۵ فضای نام (namespace) و re_path

app_name در blog/urls.pyPython
app_name = "blog"

urlpatterns = [
    path("", views.post_list, name="list"),
    path("post/<slug:slug>/", views.detail, name="detail"),
]
ارجاع با فضای نامPython
reverse("blog:detail", args=["hello-django"])
در قالبHTML
<a href="{% url 'blog:detail' post.slug %}">{{ post.title }}</a>

و در موارد خاص که تبدیل‌کننده‌ها کافی نیستند، regex:

re_path — فقط وقتی لازم استPython
from django.urls import re_path

urlpatterns = [
    # آرشیو سالانه: /blog/archive/2026/
    re_path(r"^archive/(?P<year>[0-9]{4})/$", views.year_archive, name="year_archive"),
]

در re_path نام گرفتنی به شکل (?P<name>pattern) است. تا وقتی path کارتان را راه می‌اندازد، سراغ regex نروید!

بخش ۶

💻 مثال عملی

ساخت مسیرهای کامل یک وبلاگ حرفه‌ای با آرشیو زمانی:

blog/urls.py نهاییPython
from django.urls import path, re_path

from . import views

app_name = "blog"

urlpatterns = [
    path("", views.post_list, name="list"),
    path("archive/<int:year>/", views.year_archive, name="year_archive"),
    path("tag/<slug:tag>/", views.tag_posts, name="tag_posts"),
    path("<slug:slug>/", views.post_detail, name="detail"),   # خاص‌ترها بالا؛ این عمومی‌ترین، آخر
]
blog/views.pyPython
from django.shortcuts import get_object_or_404, render

from .models import Post, Tag


def post_list(request):
    posts = Post.objects.filter(published=True)
    return render(request, "blog/post_list.html", {"posts": posts})


def year_archive(request, year):
    posts = Post.objects.filter(published=True, created_at__year=year)
    return render(request, "blog/post_list.html", {"posts": posts, "year": year})


def tag_posts(request, tag):
    t = get_object_or_404(Tag, slug=tag)
    posts = t.posts.filter(published=True)
    return render(request, "blog/post_list.html", {"posts": posts, "tag": t})


def post_detail(request, slug):
    post = get_object_or_404(Post, slug=slug, published=True)
    return render(request, "blog/post_detail.html", {"post": post})

به ترتیب دقت کنید: اگر <slug:slug> را اول می‌گذاشتیم، «archive» و «tag» هم به‌عنوان slug تفسیر می‌شدند!

💡 نکته طلاییکدهای بالا را خودتان تایپ و اجرا کنید؛ تایپ کردن رمز یادگیری است!
بخش ۷

🛠️ کارگاه عملی

مسیریابی یک فروشگاه را کامل کنید:

  1. کارگاه ۱: برای اپ shop مسیرهای زیر را بسازید: فهرست محصولات /shop/، دسته‌بندی /shop/category/<slug>/، محصول /shop/product/<int:pk>/<slug>/ (هر دو پارامتر!).
  2. کارگاه ۲: به همه مسیرها name با فضای نام shop: بدهید و در ویوی محصول، بعد از ثبت نظر کاربر با redirect("shop:product", ...) به همان صفحه برگردید.
  3. کارگاه ۳: مسیری /shop/archive/<year>/ بسازید که سال فقط ۴ رقم معتبر باشد (با re_path).
بخش ۸

✅ پاسخ کامل کارگاه عملی

✅ پاسخ کارگاه ۱ و ۲
shop/urls.pyPython
from django.urls import path, re_path
from . import views

app_name = "shop"

urlpatterns = [
    path("", views.product_list, name="list"),
    path("category/<slug:slug>/", views.category_detail, name="category"),
    path("product/<int:pk>/<slug:slug>/", views.product_detail, name="product"),
]
ویو با دو پارامتر و redirectPython
def product_detail(request, pk, slug):
    product = get_object_or_404(Product, pk=pk, slug=slug)
    if request.method == "POST":
        ...  # ثبت نظر
        return redirect("shop:product", pk=pk, slug=slug)
    return render(request, "shop/product_detail.html", {"product": product})

نکته: آوردن slug کنار pk هم سئو را بهتر می‌کند هم از حدس زدن pk جلوگیری می‌کند.

✅ پاسخ کارگاه ۳
re_path برای سالPython
re_path(r"^archive/(?P<year>[0-9]{4})/$", views.year_archive, name="archive"),

با path معمولی هم archive/<int:year>/ ممکن است، ولی int هر طول عددی را می‌پذیرد (مثل ۲۶!)؛ اگر اعتبار ۴ رقم مهم است، یا re_path یا بررسی دستی در ویو.

بخش ۹

🐞 خطاهای رایج و رفع آن‌ها

اشتباهات و خطاهای رایج این فصل را بشناسید تا سریع‌تر رفعشان کنید:

❌ صفحه 404 می‌گیرم ولی ویو را نوشته‌ام

چک کنید: ① include درست وصل است؟ ② اسلش ابتدا/انتهای مسیر دقیق است؟ ③ ترتیب الگوها — شاید الگوی عمومی‌تر بالاتر است و درخواست را می‌رباید. صفحه 404 جنگو با DEBUG=True همه الگوهای امتحان‌شده را نشان می‌دهد؛ بخوانیدش!

❌ خطای NoReverseMatch

نام مسیر اشتباه است، یا فضای نام جا افتاده (blog:list نه list)، یا args/kwargs لازم را به {% url %} نداده‌اید.

❌ خطای post_detail() missing 1 required positional argument: 'pk'

نام گرفتنی در URL با نام پارامتر ویو نمی‌خواند. <int:pk> باید به def post_detail(request, pk) وصل شود.

❌ /about کار می‌کند ولی /about/ نه (یا برعکس)

تنظیم APPEND_SLASH (پیش‌فرض True) فقط برای redirect به نسخه اسلش‌دار کار می‌کند و آن هم وقتی که مسیر بی‌اسلش هیچ‌جا تعریف نشده باشد. عادت حرفه‌ای: همه مسیرها با اسلش انتهایی.

بخش ۱۰

🏋️ تمرین‌های تثبیت

پاسخ‌ها را اول خودتان بنویسید، بعد باز کنید:

🏋️ تمرین ۱ — تطبیق الگو

سوال: الگوی path("post/<int:pk>/", ...) با کدام‌ها مطابقت می‌کند؟ الف) /post/5/ ب) /post/hello/ ج) /post/5 د) /blog/post/5/

پاسخ: فقط الف. ب → int نیست؛ ج → اسلش انتهایی ندارد؛ د → پیشوند blog باید با include اضافه شود.

🏋️ تمرین ۲ — reverse

سوال: خروجی reverse("blog:detail", kwargs={"slug": "my-post"}) با include روی "blog/" چیست؟

پاسخ: /blog/my-post/ — reverse پیشوند include + الگو + آرگومان‌ها را سرهم می‌کند.

🏋️ تمرین ۳ — طراحی URL

سوال: برای «ویرایش پست شماره ۳ در پنل کاربری» یک URL استاندارد طراحی کنید.

پاسخ نمونه: /accounts/posts/3/edit/ با name="accounts:post_edit". الگوهای رایج RESTمانند: منبع جمع، شناسه، سپس فعل.

بخش ۱۱

📝 آزمون تعاملی فصل

پرسش‌های چهارگزینه‌ای زیر را پاسخ دهید؛ بلافاصله بعد از انتخاب، پاسخ درست و توضیحش را می‌بینید. حد نصاب قبولی ۶۰٪ است و بهترین نمره‌تان ذخیره می‌شود.

۱) تبدیل‌کننده <slug:...> کدام ورودی را می‌پذیرد؟

💡 slug برای شناسه‌های خوانای URL طراحی شده؛ مثال: hello-django یا post_1.

۲) اگر دو الگو با یک درخواست مطابقت کنند، کدام اجرا می‌شود؟

💡 جنگو از بالا به پایین می‌رود و به اولین تطبیق بسنده می‌کند؛ پس الگوهای خاص‌تر را بالاتر بگذارید.

۳) فایده اصلی name در path چیست؟

💡 با نام‌گذاری، تغییر ساختار URL فقط در urls.py انجام می‌شود و همه لینک‌ها خودکار درست می‌مانند.

۴) کار include("blog.urls") در ریشه پروژه چیست؟

💡 include یعنی «ادامه مسیریابی را از فایل اپ بخوان»؛ با پیشوند path("blog/", ...) همه مسیرهای اپ زیر /blog/ می‌نشینند.

۵) app_name = "blog" چه چیزی می‌سازد؟

💡 فضای نام از برخورد نام مسیرها بین اپ‌ها جلوگیری می‌کند: {% url "blog:list" %}.

۶) کجا واقعاً به re_path نیاز داریم؟

💡 اولویت با path ساده و خواناست؛ regex فقط برای قواعد پیچیده مثل ^archive/(?P<year>[0-9]{4})/$.
بخش ۱۲

🏗️ پروژه عملی فصل

پروژه: «نقشه URL سایت چندبخشی» — مسیریابی کامل یک سایت «مجله آنلاین» را طراحی و پیاده‌سازی کنید.

  • صفحات ثابت (pages): /، /about/، /contact/.
  • وبلاگ با فضای نام: فهرست، جزئیات با slug، آرشیو سال/ماه، برچسب.
  • فروشگاه با فضای نام: فهرست، دسته (تودرتو با دو slug)، محصول.
  • همه لینک‌های قالب‌ها فقط با {% url %} — هیچ URL دستی!
  • جدول «URL → name → ویو» را در یادداشت‌ها مستند کنید.
💡 الگوی طلایی نام‌گذاری نام‌ها را فعلی و کوتاه انتخاب کنید: list، detail، create، update، delete، archive. با فضای نام اپ، تکراری‌ها مشکل‌ساز نمی‌شوند.
بخش ۱۳

🎯 جمع‌بندی و دستاوردها

در این فصل یاد گرفتید:

  • تابع path با تبدیل‌کننده‌های str/int/slug/uuid/path مسیر پویا می‌سازد.
  • پارامترهای مسیر با نام یکسان به ویو پاس می‌شوند.
  • include مسیریابی را بین اپ‌ها تقسیم و سازمان‌دهی می‌کند.
  • name + reverse + {% url %} = خداحافظی با URL هاردکد.
  • app_name فضای نام می‌سازد؛ re_path برای regexهای خاص؛ ترتیب الگوها حیاتی است.
💡 ✨ یک‌جمله‌ای که باید یادتان بماند «هر URL یک قرارداد عمومی است: خوانا برای کاربر، نام‌دار برای کد، خاص‌ترها بالاتر.»
بخش ۱۴

❓ سوالات متداول و گام بعدی

URL فارسی (مثل /مقالات/) اشکالی دارد؟

فنی کار می‌کند (با re_path یا تبدیل‌کننده str و allow_unicode در SlugField) ولی برای سئو و اشتراک‌گذاری، اسلاگ انگلیسی-فینگلیش یا ترجمه کوتاه رایج‌تر است. تصمیم پروژه‌ای است.

چطور صفحه خطای ۴۰۴ سفارشی بسازم؟

فایل templates/404.html بسازید؛ با DEBUG=False خودکار استفاده می‌شود. برای handler سفارشی‌تر: handler404 = "mysite.views.my_404" در urls ریشه. در فصل ۲۱ بیشتر می‌بینیم.
